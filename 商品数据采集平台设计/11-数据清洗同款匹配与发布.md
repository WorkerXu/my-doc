## 7. 数据模型、清洗匹配和最终发布（保持原约束）

### 7.1 建议持久化实体

| 实体 | 主要信息 |
|---|---|
| `factory_job` / `analysis_evidence` | 上传 APK、需求版本、AI 阶段、发现证据、错误诊断 |
| `connector_build` / `connector_release` | 产物/依赖哈希、SDK 版本、审查和发布时间、前后版本关系 |
| `validation_run` / `validation_case_result` | 测试环境、构建哈希、强制/来源测试、断言证据、结果 |
| `source_schedule` / `collection_run` / `collection_task` | 触发规则、任务图、租约、任务状态、重试与固定产物版本 |
| `run_checkpoint` / `outbox_event` | 游标、提交点、下游任务补投、重复运行幂等 |
| `raw_source_product` / `raw_listing` / `raw_sku` | 原始数据、来源身份、详情状态、采集证据及唯一约束 |
| `standard_dictionary` / `matching_rule` / `review_record` | 分类、品牌、属性标准、匹配规则版本与人工审核 |
| `canonical_product` / `product_version` / `change_event` | 标准商品、不可变发布版本与同步游标 |

### 7.2 原始数据与清洗

后台管理分类、品牌、属性类型、标准值、别名、单位和格式，支持 XLSX/CSV 导入和校验预览。保留来源原值、清洗值、转换依据及标准版本；确定性解析优先，本地轻量模型辅助不规则文本。缺单位、语义含糊、数值不能核实时进入待确认，绝不以示范格式替换真实值。标准更新仅影响后续新增数据，历史版本不被隐式改写。

### 7.3 同款匹配和审核

- 标准商品与来源在售商品分表关联；来源商品、商家在售记录和 SKU 不得在 Connector 层错误合并。
- 规则按“分类 × 品牌”维护；品牌专属规则覆盖“全部品牌”规则。一条规则的必需属性全部满足才通过，多条规则满足任意一条即可判定。
- 候选召回模型仅提供辅助：初期使用字典与确定性转换、BGE-small-zh-v1.5、Qwen2.5-1.5B 量化模型；推理预算最多 4 核、4 GB，生成模型单并发。清洗与同款识别均在服务器本地完成，不自动调用云模型。
- 完整且无疑似冲突的新商品可自动建档；身份不确定、必需属性缺失、跨来源属性冲突进入人工审核。人工确认后发布，审核期间对外保留最新已发布版本。
- 商品最终版本不可变，新增已确认属性或人工修订生成下一版本，相同内容不重复生成版本；图片保留来源链接并按需缓存预览，缓存有容量限制与访问时间清理机制。
