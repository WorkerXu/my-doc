# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站与公开 Newsletter** 的长期采集、清洗、版本化和检索平台，可平滑扩展到数千站点、百万到千万级文章。

平台必须满足：

1. **全历史回填**：尽可能完整发现每个已批准 Source 的历史文章，并能解释发现通道、覆盖率、缺口、停止原因与证据；
2. **持续增量同步**：发现新文章、正文修改、元数据变化、URL 迁移、重定向、删除与重发布；
3. **动态归档覆盖**：支持静态分页、Load More、Infinite Append、Virtual Replace/窗口化列表以及反向滚动归档；
4. **Markdown 稳定可重放**：不可变 Raw Artifact 经版本化 Cleaner、Extractor、Canonical IR、Renderer 生成最终 Markdown；
5. **技术内容保真**：代码块、表格、公式、Mermaid、列表、引用、脚注、图片说明、链接不能被降噪算法静默删除；
6. **多语言安全**：中文、日文及中英混排正文、标题、链接身份不能因 ASCII 假设或文本归一化而被错误合并；
7. **低成本扩站**：新增站点优先通过 Source Profile、Provider、SelectorBundle、Recipe、Traversal Policy 配置完成，不维护 1000 份独立爬虫脚本；
8. **Web 可运营**：支持接入、审批、Backfill、Incremental、Coverage、Frontier、Dynamic Archive、质量、成本、暂停、恢复、重跑、灰度与审计；
9. **任务可恢复**：Provider Run、Archive Run/Step、Task、Attempt、URL、Artifact、Document、Version 全链路持久化，Worker/Runtime 崩溃可恢复；
10. **可搜索/RAG**：支持 BM25、向量和混合检索，并能回溯 Source、原文、版本、抓取证据与处理 Release；
11. **主链不依赖 LLM**：LLM 只用于可选 Repair/Enrichment，不参与 Coverage、URL 身份、版本真相、Freshness、权限边界的最终判定。

### 1.1 核心 SLO

- **Coverage**：每 Source 可查看 Provider Inventory、Completion Attestation、Known Gap、Backfill Stop Reason；
- **Freshness**：新文章/更新从发布或发现到 PASS Markdown 的 P50/P95/P99 延迟；
- **TTFM**：URL 首次发现到首个可用 Markdown 的时间；
- **Extraction Quality**：标题、正文、代码、表格、列表、链接、图片说明、公式召回率与噪声率；
- **Protected Structure Recall**：受保护技术结构的保留率；
- **Multilingual Retention**：CJK/混排正文和链接身份保留率；
- **Replayability**：相同 Raw Artifact + 相同 Release 得到相同派生结果；
- **Provider Integrity**：HTTP 200、Runtime success、cache hit、滚到底、预算耗尽都不能被误报为完整枚举；
- **Validator Integrity**：业务 ETag/Last-Modified 必须绑定具体 authoritative Artifact/body hash；
- **Dynamic Archive Integrity**：每次滚动的 actual delta、stable item identity、wait/progress、cursor、停止原因可审计；
- **Browser Efficiency**：HTTP Fast Lane 命中率、Browser avoided、Browser minutes/新 URL；
- **Fairness**：大型 Backfill/Dynamic Archive 不得长期饿死 Incremental、Revalidation、小站与 Repair；
- **Recipe Stability**：selector 命中率、歧义率、mutation survival、deterministic replay 成功率；
- **Agentic Safety**：越界导航、Prompt Injection、Secret 泄露、动作循环与成本超限可监控、可硬终止。

## 2. 核心设计原则

1. **Coverage First**：先建立可解释 URL Inventory，再抓正文；
2. **Authoritative First**：CMS/API、Sitemap、Feed、静态归档优先，浏览器只做必要慢路径；
3. **Observation Before Selection**：发现事实先落库，再 Normalize、Scope、Classify、Dedup；
4. **Successful Return != Provider Complete**：Runtime 返回成功只是证据，不是完整性真相；
5. **Completion Must Be Attested**：只有协议级结束条件才可声明 `ATTESTED_COMPLETE`；
6. **Runtime Is Executor, Platform Owns Truth**：Crawl4AI/Playwright/Browser Use 不拥有 Coverage、Version、Freshness、Markdown 真值；
7. **Per-step Identity Before Synthetic Merge**：动态列表每个真实步骤先采稳定文章身份，再允许 Runtime 合并 DOM；
8. **Dynamic DOM Is Derived Evidence**：Virtual Scroll 合成 HTML、合成后截图不得覆盖原始网络/真实步骤证据；
9. **Unicode-safe Identity**：URL/稳定 ID 优先，绝不使用 ASCII-only 文本归一化作为主身份；
10. **Stable Item Identity Before Text Dedup**：文本 hash 仅弱辅助；
11. **Actual Progress, Not Requested Action**：判断滚动进展必须观察 actual scroll delta、新 stable key、Mutation/Network/Cursor，而不是“执行过 scroll”；
12. **Discovery / Revalidation / Fetch / Clean / Extract / Quality / Canonicalize / Projection 分离**；
13. **HTTP First, Browser Slow Lane**；
14. **Snapshot First**：Raw/Provider Evidence 先保存，再产生派生物；
15. **Candidate Portfolio, Not Single Extractor**；
16. **Protected Structures Are First-Class**；
17. **Canonical IR First, Markdown as Projection**；
18. **Recipe, Not 1000 Site Scripts**；
19. **Persistent Frontier, Not In-Memory Traversal**；
20. **Semantic Checkpoint, Not Browser Session**；
21. **Idempotent + Recoverable**：幂等键、Lease、Fencing Token、Checkpoint、Inbox/Outbox；
22. **Fair by Default**：Incremental/Revalidation 预留容量；
23. **Bounded Concurrency Everywhere**；
24. **No Silent Degradation**：partial、cache fallback、过滤、截断、早停、碰撞、降级都有 typed reason；
25. **Config Is Capability**：高能力配置必须经过 Capability Firewall；
26. **Runtime Cache Is Disposable**；
27. **Derived Artifact Never Overwrites Evidence**；
28. **Weak Freshness Signal Cannot Close Truth**；
29. **Validator Must Bind To Artifact**；
30. **Same URL Does Not Imply Same Representation**：locale/Cookie/UA/Proxy/session/device 使用 `fetch_variant_key` 隔离；
31. **Offline Means No Network**：离线 Replay 由平台 Artifact + egress deny 保证；
32. **Agentic Repair Is Proposal, Not Truth**；
33. **Ephemeral Element Identity**：Browser highlight index/CDP node id 只属于单次观测；
34. **Web Content Is Untrusted Prompt Input**；
35. **Hard Limits Outside Model**：循环、停滞、wall-time/token/cost 由平台硬终止。

- 网页内容、模型输出不能扩大能力边界。

## 6. 全历史 URL 发现与 Coverage

### 6.1 Provider 顺序

1. CMS/API；
2. Sitemap/Sitemap Index；
3. RSS/Atom；
4. Static Archive/Pagination/Tag/Category；
5. Dynamic Archive；
6. 静态链接图；
7. Common Crawl Index；
8. Wayback；
9. Crawl4AI URL Seeder/Domain Mapping/Deep/Adaptive 作为补洞与加速。

任何单一 Provider 都不能自动证明“全历史完整”。

### 6.2 Observation 与 Inventory

发现先写：

```text
url_observation(
  observation_id,
  source_id,
  provider_id,
  provider_run_id,
  provider_step_id,
  observed_url,
  stable_item_key,
  observed_at,
  provider_timestamp,
  provider_metadata,
  provider_evidence_uri
)
```

再统一：

```text
Normalize -> Scope Check -> MIME Hint -> URL Identity -> Dedup -> Frontier Upsert
```

### 6.3 Provider Completion Attestation

Provider Run 保存 cursor/shard/checkpoint、items_seen、unique_urls、status、completion_type、stop_reason、truncated、budget_exhausted、known_gap、provider_release。

统一状态：

```text
ATTESTED_COMPLETE
HEURISTIC_EXHAUSTED
PARTIAL
FAILED
BLOCKED
```

只有协议级结束条件允许 `ATTESTED_COMPLETE`。HTTP 200、非空结果、达到 limit、cache hit、浏览器正常退出、LLM 表示完成、`scroll_count` 用尽、scroll geometry 到底都不算。

### 6.4 Sitemap / Common Crawl / Wayback

- Sitemap Index 拆 durable shard；
- Sitemap 增量用 Conditional GET，`lastmod` 只是变化线索；
- Common Crawl/Wayback 固定 index/release，保存查询 Evidence，流式处理；
- Archive 出现不代表当前仍有效，Archive 缺失也不能证明历史上不存在。

## 7. DynamicArchiveProvider 与 Virtual Scroll

### 7.1 模式

```text
STATIC_PAGINATION
LOAD_MORE
INFINITE_APPEND
VIRTUAL_REPLACE
```

`scroll_direction=up|down` 独立于模式，以覆盖反向/向上加载的窗口化归档。

Onboarding 用小预算 Probe：比较初始/动作后的 stable item key、child count、scrollHeight、next link、XHR/fetch/cursor。若能识别权威 JSON/API，升级为 API Provider，避免长期依赖 Browser。

### 7.2 平台自有 VirtualArchiveExecutor 为主路径

对 `VIRTUAL_REPLACE`，生产 Coverage 主路径不是直接相信 Crawl4AI 最终合成 HTML，而是平台通过 Playwright/确定性浏览器执行逐步采集：

```text
1. 验证 container/item selector 和 scope
2. 采集当前真实 DOM 中 stable item keys + href + metadata
3. 保存 PRE_SCROLL Evidence
4. 执行一次受控 scroll/click
5. 等待 meaningful progress
6. 采 actual scroll delta / Mutation / Network / Cursor / item keys
7. 保存 POST_SCROLL Evidence
8. 新 URL 写 url_observation
9. 判断 protocol end / heuristic stop / budget
10. 保存 semantic checkpoint
11. 继续下一步
```

`meaningful progress` 优先级：

```text
new stable item key
> cursor/has_more 变化
> relevant XHR/fetch 完成
> MutationObserver 后 DOM quiet
> network quiet
> fixed sleep fallback
```

### 7.3 Crawl4AI 原生 Virtual Scroll 的边界

Crawl4AI 原生实现适合生成 Derived Merged HTML，但不能拥有 Coverage 真相，原因包括：

1. 通过 `currentHTML == previousHTML` / `startsWith(previousHTML)` / else 判断 no-change/append/replace，对 DOM 抖动敏感；
2. 固定 `wait_after_scroll` 不证明数据加载完成；
3. `scroll_count` 是预算，不是完整性证明；
4. 几何触底不等于服务端 cursor 耗尽；
5. replace 时遍历 chunk 的直接子元素，嵌套卡片可能丢失正确语义；
6. 最终按 `innerText.toLowerCase().replace(/[\s\W]/g, '')` 去重，可把相同可见文本不同 href 合并；
7. JavaScript 传统 `\w` 近似 ASCII 范围，纯中文/日文文本可能被归一化为空键，产生严重碰撞；
8. 发生 replace 后会重写 `container.innerHTML`，得到的是 Synthetic/Derived DOM，原节点事件监听与框架绑定可能失效；
9. Virtual Scroll 异常后外层普通 crawl 仍可能继续成功，Runtime success 不能推进 Provider Completion；
10. 内部滚动结果不提供平台所需的逐步 durable Observation。

因此：

```text
Crawl4AI VirtualScrollConfig = Derived HTML Recovery / Candidate / Probe
Platform VirtualArchiveExecutor = Inventory / Evidence / Completion / Checkpoint Authority
```

### 7.4 稳定条目身份

优先：

```text
normalized_article_url
> source-specific item id / data-id / API id
> canonical target
> title + published_at + author composite
> stable structural fingerprint
> Unicode-aware text fingerprint（弱辅助）
```

纯文本 hash 不得作为 URL Inventory 主键。

### 7.5 Unicode/CJK Merge Guard

若 Source 为中文、日文或混排，或 Runtime normalized-text 空键/碰撞率异常：

- 禁止把 Crawl4AI merged unique count 推进 Coverage；
- URL Inventory 只接受平台 stable item key Observation；
- Merged HTML 可以进入 Extraction Candidate，但标记 `DERIVED_MERGED`；
- 对 merged href 数与平台 unique item 数做差异检查；
- 超阈值进入 `RUNTIME_MERGE_UNSAFE`，触发 REVIEW/平台执行器。

## 8. URL Identity 与 Persistent Frontier

### 8.1 URL 三层身份

```text
observed_url
normalized_url
canonical_url
```

`rel=canonical` 不是绝对真相。Query、path 大小写、www/apex、HTTP/HTTPS 合并必须 Source-specific。

### 8.2 去重关系

```text
exact URL
-> redirect/canonical alias
-> stable archive item id
-> raw body hash
-> semantic hash
-> SimHash/MinHash relation
```

近重复只建立关系，不静默删版本。

### 8.3 Frontier

```text
url_id, source_id, normalized_url, canonical_url, fetch_variant_key,
state, priority, next_action_at, last_discovered_at,
last_fetch_at, last_verified_at, retry_count,
lease_owner, lease_until, fencing_token
```

状态：DISCOVERED、DUE_FOR_REVALIDATION、FETCH_REQUIRED、FETCHING、FETCHED、EXTRACT_PENDING、PASS、REPAIR、REVIEW、DELETED、BLOCKED、DEAD。

## 9. 增量同步与 Revalidation Engine

### 9.1 增量入口

CMS revision、Sitemap `lastmod`、RSS `updated`、Webhook、Archive 新链接、Dynamic Archive head scan、定时 Revalidation、强制完整刷新、人工重抓、Provider Reconcile。

### 9.2 Revalidation Ledger

保存：

```text
last_fetch_at / last_verified_at / last_changed_at
ETag / Last-Modified
raw_hash / semantic_hash / head_fingerprint
validator_strength
validator_artifact_id / validator_body_sha256
binding_state
validation_method / result / reason
runtime_cache_status
consecutive_304
forced_refresh_due_at
false_negative_count
source_validator_trust_score
```

### 9.3 证据强度

- **STRONG**：CMS revision；与 authoritative Artifact 绑定的 validator 得到标准 304；完整 GET 后 body hash 一致；
- **MEDIUM**：validator 变化、Sitemap/RSS 更新时间变化；
- **WEAK**：head fingerprint、长度、列表卡片、局部 metadata、LLM 判断。

只有 Source Policy 接受的强证据推进 `last_verified_at`。

### 9.4 Validator Binding Invariant

1. 只有与完整网络响应一起得到的 validator 才绑定 Raw Artifact；
2. HEAD/弱校验得到的新 validator 只能记 `UNBOUND_HINT`；
3. 304 只有在请求 validator 已绑定当前 authoritative Artifact/body hash 时才是 STRONG；
4. Runtime cache weak match 更新的 validator 不直接导入业务真相；
5. Artifact 替代后旧绑定进入历史；
6. 定期完整 GET 抽样检测 false negative，并动态调 trust score。

### 9.5 Dynamic Archive 增量高水位

保存：

```text
newest_known_article_key
newest_known_published_at
archive_head_fingerprint
recent_known_item_keys
last_incremental_archive_run
last_forced_deep_scan
```

从归档头部开始；连续出现 `K` 个已知稳定 item key 且排序单调性政策满足时 early stop。

防漏：

- 置顶文章单独识别；
- 定期 forced deep scan；
- Sitemap/CMS/RSS 多 Provider Reconcile；
- 历史插入/乱序严重则关闭 aggressive early-stop；
- forced deep scan 持续发现漏 URL 时自动降低 Dynamic Archive trust；
- reverse/upward list 使用方向对应高水位；
- 正文变化始终交给 Revalidation Engine。

## 10. HTTP、Browser 与 Runtime Cache

### 10.1 HTTP Fast Lane

普通文章优先 `httpx/aiohttp`，保存 redirect、response headers、Content-Type、encoding、validator、原始字节。正文质量满足即不启 Browser。

### 10.2 Browser Slow Lane

仅 HTTP 空壳、JS 渲染、有限交互、Shadow DOM/iframe、动态归档或 Recipe 指定时升级。

资源池隔离：

```text
archive-browser-dynamic
fetch-browser-article
agentic-repair
```

大型归档滚动不能拖垮正文 Freshness。

### 10.3 Runtime Cache Policy

业务层只暴露：

```text
AUTHORITATIVE_FETCH
VALIDATE_THEN_FETCH
REPLAY_FROM_ARTIFACT
RUNTIME_CACHE_WARMUP
```

Runtime cache 只是性能层，不能直接推进 `last_verified_at`、Coverage 或 Version 真相。

## 11. Agentic Browser Repair / Recipe Studio

只在确定性路径失败、新 Source onboarding 探索、REPAIR/REVIEW 或 Operator 诊断时启用 Browser Use。

```text
Deterministic path failed
        |
        v
Agentic Browser Repair Sandbox
        |
        +-- bounded BrowserState / actions
        +-- Browser Gateway policy enforcement
        +-- Agentic Progress Guard
        +-- immutable trace/evidence
        v
Selector Compiler + Recipe Compiler
        v
Recipe Candidate
        v
Fixture Replay -> Live Sample -> Shadow -> Canary -> Approval
        v
recipe_release
```

硬预算：max steps/actions/page/tab/wall-time/token/cost/artifact bytes。

平台 Progress Guard 对重复动作、停滞状态、state revisit、连续无新 Observation、wall-time/token/cost 硬终止。模型内部 loop/replan 提示仅 advisory。

临时 highlight index/CDP node id 不能进入 Production Recipe。必须编译成稳定 `selector_bundle`：semantic role、accessible name、稳定属性、CSS/XPath 候选、ancestor/frame 约束、cardinality、fallback、fixture/live match rate、ambiguity rate、mutation survival rate。

若仍需 LLM 实时决策，则不能晋升无监督生产 Recipe。

## 12. Raw Artifact、清洗、提取与 Markdown

### 12.1 Raw First

每次网络/浏览器 authoritative fetch 保存不可变 Raw Artifact：

```text

fetch_variant_key
status / headers
content_type / encoding
body_sha256
raw_uri
fetched_at
runtime_release
browser_build
attempt_id
```

Derived HTML、Cleaned HTML、IR、Markdown 都引用 Raw Artifact，不覆盖它。

### 12.2 Versioned Cleaner

Cleaner 只做确定性、可重放变换：

- 去 nav/footer/广告/推荐；
- 规范相对 URL；
- 保留代码、表格、公式、Mermaid、引用、figure/figcaption、脚注；
- 保护语言特定标点与 Unicode；
- 每个删除规则可输出 reason/统计。

### 12.3 Protected Structure Manifest

在强降噪前建立：

```text
pre/code/table/blockquote/figure/figcaption
mermaid/math/katex
technical lists
inline code
important links/images
```

质量门验证 Candidate/IR 没有异常丢失这些结构。

### 12.4 Extraction Portfolio

并行或按成本逐级生成候选：

1. Source Recipe；
2. JSON-LD/Microdata；
3. Trafilatura；
4. DOM article/main heuristic；
5. Crawl4AI Raw/Fit Markdown candidate；
6. Browser-rendered candidate；
7. LLM repair 仅在 REVIEW/REPAIR。

候选按正文密度、结构保留、噪声、标题/日期一致性、链接/代码保留、语言保留评分。

### 12.5 Canonical IR

最终先写稳定 IR，再渲染 Markdown：

```text
Document
  metadata
  blocks[]:
    heading
    paragraph
    code
    list
    table
    quote
    image
    math
    mermaid
    footnote
```

IR 包含 source span/provenance，Renderer 版本化。换 Markdown 格式不需要重抓网站。

### 12.6 Markdown 文件组织

建议：

```text

  <source_slug>/
    <yyyy>/
      <canonical_slug>--<short_id>.md
```

Front Matter：source_id、canonical_url、title、author、published_at、updated_at、fetched_at、document_version、content_hash、language、license_hint、provenance。

图片默认保留原 URL 与 alt/caption；需要归档时单独进入 media artifact pipeline。

## 13. 任务、幂等与可恢复性

任务类型：

```text

DYNAMIC_ARCHIVE_STEP
REVALIDATE
FETCH
CLEAN
EXTRACT
QUALITY
CANONICALIZE
RENDER_MD
INDEX
```

每 Task 有业务幂等键；Worker 获取 Lease + Fencing Token；超时 Lease 可回收；写数据库与发消息使用 Transactional Outbox；消费侧 Inbox 去重。

## 21. 验收标准

平台上线前至少满足：

1. 1000 个 Source 可批量导入并独立配置 Scope/Profile；
2. 静态站优先无需 Browser 完成全历史回填；
3. 动态归档每步拥有 stable item identity、actual scroll delta、Evidence、typed stop reason；
4. 中文/日文 Virtual Scroll fixture 不因原生文本去重静默丢文章；
5. 任何 `SCROLL_BUDGET_EXHAUSTED`、几何触底、Runtime success 都不会被标成 `ATTESTED_COMPLETE`；
6. Worker/Browser crash 后从 semantic checkpoint 恢复且无重复业务结果；
7. ETag/304 必须满足 Validator Binding Invariant；
8. 相同 Raw + 相同 Release 离线重放得到一致 Markdown；
9. 技术结构与多语言 Golden Set 达到预设 Recall/Retention 阈值；
10. Web Admin 能解释 Source 的 Coverage、Freshness、质量、成本和失败原因；
11. Incremental/Revalidation 在大 Backfill 下仍满足 Freshness SLO；
12. Search/RAG 可追溯到 Document Version、Raw Artifact 与原始 URL；
13. Agentic Repair 不可绕过 Scope/Capability/预算，且不能直接写生产真相。

## 22. 最终方案结论

整体采用 **“Provider-first URL Inventory + Persistent Frontier + HTTP Fast Lane + Browser Slow Lane + Immutable Raw Artifact + Versioned Extraction/IR/Markdown + Incremental Revalidation + Web Control Plane”**。

对于最容易造成历史漏采的 Virtual Scroll，明确采用 **平台自有 `VirtualArchiveExecutor` 负责真实步骤的文章身份、Evidence、Completion、Checkpoint；Crawl4AI 原生 Virtual Scroll 只作为 Derived HTML 恢复与抽取 Candidate**。该边界同时解决窗口化 DOM 回收、Runtime 启发式误判、固定等待、滚动几何假完成、Synthetic DOM、CJK 文本去重碰撞与崩溃恢复问题。

这样新增网站时主要增加配置、Provider/Recipe 与 SelectorBundle，而不是复制爬虫代码；全历史抓取、增量同步、Markdown 清洗、动态归档、Web 管理、质量控制与可审计证据链能够在同一平台模型下持续扩展。
