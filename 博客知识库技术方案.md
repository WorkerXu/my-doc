# 博客知识库技术方案

## 1. 目标与规模

建设一个长期运行、可横向扩展、可审计、可重放的技术博客知识库平台：首期接入约 1000 个技术博客、工程博客、技术文档站和公开 Newsletter，尽可能抓取完整历史文章并清洗为稳定 Markdown；后续持续新增站点，支持增量同步、版本追踪、全文/向量/图谱检索、Web 管理、质量审计、单 URL 手工摄取、离线重处理和 AI 派生分析。

设计规模：

- 1000+ Source，后续扩展到数千；
- 百万级 Document；
- 数百万到千万级 URL Observation；
- 千万级 Chunk / Embedding；
- HTML、PDF、Markdown、TXT、JSON/API、RSS/Atom/JSON Feed；
- 中英日韩等多语言；
- HTTP 为默认抓取路线，Browser 为受控 fallback；
- CMS API、Sitemap、Feed、Archive、Docs TOC、Common Crawl、Deep Crawl 等多入口历史发现；
- PostgreSQL + Object Storage 保存事实，Markdown、Structured Record、Chunk、Embedding、全文索引、向量索引、Graph、AI Insight、Dashboard Read Model 均为可重建 Projection。

系统必须能回答：

1. 一个站点理论上有哪些历史文章，为什么认为历史已基本覆盖；
2. URL 从哪里被发现、如何规范化、为何被过滤或放行、经过哪些跳转、最终抓了什么；
3. 为什么走 HTTP、API、PDF、Browser 或其他抓取路线；
4. 一个 Markdown 来自哪个 Snapshot、Extractor、Schema、Release 和 Document Version；
5. 源站变化后哪些内容真的变化，哪些派生物需要重建；
6. Worker 崩溃或批任务部分失败后如何恢复且不丢成功项；
7. 新增站点、规则、模型、索引、图谱策略时如何灰度、回放、回滚；
8. Web 管理中的暂停、重跑、重新分析、切 Release 等操作由谁发起、是否幂等、是否经过 RBAC；
9. 查询某站点/文章/版本时，BM25、Vector、Graph 三条召回链路是否都严格遵守 Scope/ACL；
10. Dashboard 指标处理到什么 watermark，覆盖多少 Source，使用哪一版指标定义。

## 2. 核心原则

1. **Config First**：普通站点靠 Source / Site Profile / Release 接入，不改核心代码。
2. **Coverage First**：历史完整性由 Provider Evidence、cursor 和 exhaustion reason 证明，队列为空不等于完整。
3. **Authoritative First**：CMS/API、Sitemap、Feed、Archive 优先，Deep Crawl/Common Crawl 用于补洞。
4. **Discovery Before Fetch**：先发现、规范化、过滤、分类、去重 URL，再抓正文。
5. **Filter With Evidence**：URL Filter 允许 HARD/SOFT，但任何过滤都保留 Observation 和 reason。
6. **URL Is Locator**：资源类型由响应 MIME、签名、跳转和规则综合判断，不只看后缀。
7. **HTTP First, Browser Last**：Browser 仅处理动态发现、动态正文或质量 fallback。
8. **Recipe, Not Site Code**：动态交互、URL Filter、结构化抽取均声明式、版本化、可回放。
9. **Bounded Crawl**：Deep Crawl、Browser、LLM Extraction、Graph Expansion 都有预算和终止条件。
10. **Snapshot First**：先保存不可变网络事实，再做抽取、清洗、Schema、Graph、AI。
11. **IR First, Markdown as Projection**：Canonical IR / Document Version 是内容事实层，Markdown 可重建。
12. **Structured Record Is Projection**：CSS/XPath/Regex/LLM 结构化抽取不覆盖 canonical 内容。
13. **Graph Is Projection**：实体、关系、社区、GraphRAG 都来自 Document Version，不能成为唯一事实源。
14. **LLM Is Projection, Not Truth**：LLM Extraction/Analysis 失败不阻塞 Source Sync。
15. **Stable Identity**：Document、Version、Chunk、Embedding、Graph Entity/Relation、Analysis 身份稳定且 release-aware。
16. **Release Everything**：影响结果的 Filter、Recipe、Schema、Extractor、Model、Prompt、Graph、Metric、Index、Runtime 全部版本化。
17. **Idempotent + Recoverable**：任务有幂等键、lease、fencing、checkpoint、retry、partial success。
18. **Stream and Commit Per URL**：批任务按 URL 独立提交，一个失败项不回滚其他成功项。
19. **One Durable Task System**：PostgreSQL durable state + Transactional Outbox + Redis Streams 是唯一业务任务体系。
20. **Async Command API**：抓取、解析、Embedding、Graph、AI、重建等长任务使用 202 + durable command ID。
21. **Projection Readiness Explicit**：Canonical、Markdown、Structured、Chunk、Embedding、Graph、AI、Index、Dashboard 状态分别表达。
22. **Hybrid Retrieval by Default**：BM25 + Vector 是基线，Graph 是第三召回通道，Reranker 可降级。
23. **Hard Scope Filter**：SOURCE/DOCUMENT/VERSION/ACL Scope 必须下推到所有召回通道。
24. **Generation Instead of Destructive Rebuild**：全文、向量、Graph 新版本后台构建、验证、原子切换。
25. **Dashboard Is Read Model**：Dashboard 读取可重建聚合，不把缓存、WebSocket 或 Worker 内存当真相。
26. **Security on Every Hop**：起始 URL、Redirect、Browser navigation 每跳重新做 SSRF/Egress/Scope 校验。
27. **Benchmark Before Switch**：Filter、Extractor、Analyzer、Embedding、Graph、Retrieval、Metric 等升级先固定回归再激活。

## 4. 技术选型

### 4.1 控制面

- FastAPI + Pydantic：REST/Command API、Schema 校验、内部服务接口；
- PostgreSQL：Source、Profile、Run、Task、Coverage、Observation、Snapshot、Document、Version、Release、Audit、Outbox、Graph metadata；
- Transactional Outbox：数据库事务与异步消息发布一致；
- Redis Streams：consumer group、retry、backpressure，只做任务运输；
- React/Vue + TypeScript：生产 Web 管理台；
- Docker/Kubernetes：隔离 Worker 类型并弹性扩缩容。

### 4.2 抓取与解析

- HTTPX/aiohttp：静态 HTML、Feed、Sitemap、API、Conditional GET、Range GET；
- Crawl4AI：Deep Crawl、URL Seeding、Browser Interaction、Markdown/Structured Extraction Adapter；
- Playwright：复杂 JS 页面和特殊交互 fallback；
- lxml/BeautifulSoup/CSS/XPath/Regex：确定性抽取；
- Trafilatura/Readability：正文候选；
- PDF Parser + OCR fallback；
- S3/MinIO：raw response、HTML、Rendered DOM、PDF、WARC、Canonical IR、Markdown、Structured JSON、Graph artifact、AI artifact、fixture。

### 4.3 检索与图谱

- OpenSearch：生产 BM25、过滤、聚合、Alias/Generation；
- pgvector/OpenSearch kNN：首期向量；规模增长可替换 Qdrant/Milvus；
- RRF：BM25 + Vector 默认融合；
- Graph：首期 PostgreSQL entity/relation 表即可验证价值，成熟后可增加 Neo4j/Memgraph/其他图引擎 Adapter；
- R2R/其他 GraphRAG 平台：可作为可替换 Graph/RAG Adapter 或实验后端，不接管平台 Truth；
- Cross Encoder Reranker：可选精排。

### 4.4 运营分析

- Prometheus + Grafana + OpenTelemetry：低基数指标和 Trace；
- PostgreSQL Materialized/Incremental Read Model：首期运营聚合；
- 规模增长后可引入 ClickHouse 等分析引擎；
- SSE/WebSocket：仅做数据失效通知。

## 7. 全量历史发现、Filter 与 Coverage

### 7.1 Provider Contract

```text
probe(source, profile) -> capability
discover(cursor, budget) -> candidates + evidence + next_cursor
checkpoint() -> durable_cursor
exhaustion() -> explicit_reason
```

Provider：

```text
CMS_API
SITEMAP
FEED
ARCHIVE
CATEGORY_TAG_AUTHOR
DOCS_TOC
DISCOVERY_SURFACE
BROWSER_DISCOVERY_SURFACE
COMMON_CRAWL_URL_INDEX
SITE_SEARCH
DEEP_CRAWL_BFS
DEEP_CRAWL_DFS
DEEP_CRAWL_BEST_FIRST
```

### 7.2 历史发现顺序

```text
CMS/API
 -> Sitemap
 -> Historical Feed
 -> Archive year/month
 -> Category/Tag/Author
 -> Blog Index / Docs TOC
 -> Common Crawl
 -> HTTP/Browsed Discovery Surface
 -> Best-First/BFS gap filling
 -> Site Search supplement
```

Deep Crawl 是 gap discovery，不是 Coverage 真相。

### 7.3 URL Filter Chain

```text
url_filter_release
- rules[]
- action: HARD_REJECT / SOFT_REJECT / DEPRIORITIZE / ACCEPT
- reason_code
- fixture_refs
```

HARD_FILTER 仅用于明确禁止域、robots/policy、后台/登录、静态资产等；路径模式、相关性、category/tag 推测默认属于 SOFT_FILTER。

每次 decision 都保存：

```text
url_id
filter_release_id
matched_rule
result
reason_code
score nullable
evidence_ref
observed_at
```

SOFT_FILTER 只影响调度优先级/是否抓取，不删除 Observation。新 Filter Release 上线前必须对已知文章 URL fixture 做 recall 回归。

### 7.4 Coverage

```text
coverage_provider_run
- run_id
- provider_type
- provider_release_id
- cursor_before/after
- status
- exhaustion_reason
- candidate_count
- completed_count
- failed_count
- known_gap
- blocker
```

预算耗尽只能标记：

```text
known_gap = true
exhaustion_reason = BUDGET_EXCEEDED
```

只有主要权威 Provider exhausted，或剩余缺口均成为可解释 known gap，FULL_BACKFILL 才能结束。

Common Crawl 只能证明 URL 曾被观察/抓取，不能证明站点历史完整。

## 8. URL Normalization、Resolution、Probe 与 Fetch

### 8.1 Normalization

lowercase host、default port removal、fragment removal、path slash、安全 percent-encoding、query key ordering、tracking param removal、站点 semantic param allowlist。

禁止全局删除 query；`?id=123`、`?p=456`、`?page=7` 可能有业务语义。

### 8.2 Classification

```text
ARTICLE_CANDIDATE
DISCOVERY_SURFACE
ASSET
NAVIGATION
EXTERNAL_REFERENCE
IGNORE_BY_POLICY
UNKNOWN
```

### 8.3 Resolution

```text
Observed URL
 -> Normalized Candidate
 -> HTTP Redirect
 -> Wrapper Param / HTML Target
 -> Meta Refresh
 -> Browser Navigation Fallback
 -> Resolved Target
```

每一跳重新执行 DNS/IP/SSRF/domain scope。`canonical`/`og:url` 属于 Identity Evidence，不等同 redirect。

### 8.4 Resource Probe

综合：最终 Content-Type、Content-Disposition、magic bytes、Content-Length、HTML 壳、Range GET、redirect 和 Site Profile。

资源类型：

```text
HTML_PAGE
PDF_DOCUMENT
MARKDOWN_TEXT
PLAIN_TEXT
JSON_API
XML_FEED
IMAGE
ARCHIVE
UNKNOWN_BINARY
```

### 8.5 Fetch Route

```text
HTTP_STATIC
 -> HTTP_ALT_HEADERS
 -> HTTP_PLATFORM_API
 -> FILE_STREAM_FETCH
 -> BROWSER_CRAWL4AI_RECIPE
 -> BROWSER_PLAYWRIGHT_CUSTOM
 -> SITE_CUSTOM_EXTRACTOR
```

Browser 不与 API 服务共享 Playwright event loop，独立 Worker 部署。

## 10. Snapshot、Extraction、Canonical IR 与 Markdown

### 10.1 Snapshot First

```text
snapshot_id
fetch_attempt_id
snapshot_origin
content_type
body_hash
object_ref
headers_hash
rendered_dom_ref
captured_at
```

Extractor/Filter/Graph/AI 升级优先对旧 Snapshot/Document Version 离线 replay，不重新访问源站。

### 10.2 Extraction Candidate

同一 Snapshot 可产生：

- CMS/API body；
- Site Selector；
- CSS/XPath/Regex；
- JSON-LD；
- Trafilatura/Readability；
- Crawl4AI cleaned HTML/raw Markdown；
- Rendered DOM；
- Feed Content；
- PDF Text/OCR；
- Markdown/TXT native parse。

### 10.3 Canonical IR

```text
DocumentIR
  metadata: title/authors/published_at/updated_at/language/canonical_url/tags
  blocks: heading/paragraph/list/quote/code/table/image/figure/formula
  assets[]
  outbound_links[]
  source_evidence[]
```

HTML/PDF/MD/TXT 最终统一进入 IR。

### 10.4 Quality

至少检查：正文长度、标题一致、link density、boilerplate、code/table 保留、语言、published_at confidence、truncation、selector match、required field 缺失、DOM drift。

低质量候选进入 quarantine，Web 可比较不同 Extractor。

### 10.5 Canonical Markdown

从 IR 确定性生成：去导航/广告/推荐/评论；保留标题层级、代码、列表、引用、表格、图片 alt/caption、重要链接；解析相对链接；不做 query-dependent 删减。

BM25/Pruning/LLM Filter 只能生成 `FILTERED_MARKDOWN`，不能覆盖 canonical Markdown。


## 12. Document Identity、版本与增量同步

### 12.1 Identity

综合 platform stable ID、canonical/og:url、redirect evidence、Feed GUID、平台 article ID、normalized URL、exact/near duplicate、title + published time。

URL Alias、Document Identity、Document Version 分离。

Document Version 仅在 Canonical IR 或关键元数据变化时创建。304、重复抓取、Markdown/Chunk/Embedding/Graph/AI 策略升级不创建正文版本。

### 12.2 增量信号

```text
Feed/API cursor
 -> Sitemap lastmod
 -> High-yield Surface
 -> Conditional GET
 -> Metadata/Resource Probe
 -> Full HTTP
 -> Browser fallback
```

保存 ETag、Last-Modified、previous_body_hash、content_length、content_kind。

304：不重复保存 body、不抽取、不建 Version、不重做 Projection。

### 12.3 调度分层

```text
Tier 0 Feed/API            分钟级
Tier 1 Sitemap/Blog Index  10~60 分钟
Tier 2 Category/Archive    1~6 小时
Tier 3 Deep Reconcile      每周/每月
Tier 4 Common Crawl        新 collection/按月
```

Feed/API 使用 overlap window，周期 Reconcile 防止迟到、排序变化、Feed 窗口外遗漏、URL 迁移、删除和结构漂移。

## 16. Chunk、Embedding、Index 与 Hybrid Retrieval

### 16.1 Chunk

Structure-aware：Heading/Section 优先；段落、列表、引用尽量完整；code/table 默认不拆；保存 heading path/page/block range；超长 section 才 recursive fallback；长度按目标 Embedding tokenizer 计数。

```text
chunk_id = hash(document_version_id + chunk_release_id + logical_block_range + normalized_text_hash)
```

禁止只依赖 file path + chunk_index。

### 16.2 Embedding

```text
embedding_id = hash(chunk_id + embedding_release_id)
```

Worker 支持 batch token 上限、OOM 自动缩 batch、lease、retry、partial success、backpressure。写向量前校验 dimension、finite value、normalization、release 和 payload schema。

### 16.3 Index Generation

全文、向量、Graph 都使用 Generation：后台构建、固定 judgment set 验证、canary、Alias/逻辑指针原子切换。RECHUNK/REEMBED/REINDEX/REGRAPH 不重新抓源站。

### 16.4 Hybrid Retrieval

默认：

```text
BM25
 + Vector
 + optional Graph linked chunks
 -> hard metadata scope
 -> RRF/controlled fusion
 -> optional reranker
 -> context assembly
```

BM25 保护技术 token：ClassName、snake_case、camelCase、package.module、版本号、C++、.NET、Node.js 等。

Scope：ALL、SOURCE、DOCUMENT、DOCUMENT_VERSION、URL Alias、TAG、LANGUAGE、ACL/tenant。

URL Scope 先在本地映射内部 Document/Version；Query Plane 禁止为查询去访问远程 URL。

Retrieval Trace 记录 BM25/VECTOR/GRAPH/RRF/RERANK 各阶段候选、rank、score、scope、latency 和来源证据。

## 17. AI Analysis Plane

AI Analysis 与 Source Sync 解耦：

```text
Document Version
 -> Analysis Input Manifest
 -> Model/Agent Adapter
 -> Schema Validation
 -> AI Analysis Record
```

Analysis Manifest 固定 input projection/hash、filter、analysis/model/prompt/schema release。

## 24. 测试、Replay 与发布门禁

### 24.1 Coverage

Sitemap/API cursor/Archive pagination exhaustion、known gap、Budget exceeded 不得 COMPLETE。

### 24.2 Filter Recall

固定已知文章 URL fixture，评估 article_url_recall、non_article_reject_rate、soft_filter_false_negative_rate。新 Filter Release recall 不得无解释下降。

### 24.3 Snapshot Replay

新 Extractor/Quality/Markdown/Structured/Graph 在旧 Snapshot/Document Version 离线重放，不访问源站。

### 24.4 Resource Probe

无扩展名 PDF、`.pdf` 跳 HTML、错误 Content-Type、HEAD 405、超大文件、签名冲突。

### 24.5 Crash / Idempotency

重复 Command/message 不重复 Version；Worker 退出后 lease 恢复；fencing 阻止旧 Worker 覆盖；batch partial success 不丢失。

### 24.6 Structured Extraction

required field/type/null/multi-item/DOM drift/LLM invalid JSON/timeout/chunk boundary；比较 deterministic engine 与 LLM engine 的准确率和成本。

### 24.7 Graph

- ACTIVE Entity/Relation 必须有 provenance；
- entity merge/split 固定回归；
- 新 Graph Release 离线重建并比较关系漂移；
- Graph ScopeLeakRate 接近 0；
- max_hops/max_nodes/max_edges 生效；
- 图谱模型故障不影响 canonical readiness。

### 24.8 Retrieval

中英文、技术 token、同义词、长问题、HTML/PDF/MD、SOURCE/DOCUMENT/VERSION/URL/ACL Scope 固定 judgment set。

指标：Recall@K、MRR、nDCG、HitRate、ScopeLeakRate、Latency、Cost；Graph channel 还评估 multi-hop answer hit rate。

### 24.9 Dashboard

watermark、Read Model 一致性、高基数、UI rerun 不触发 Crawl/LLM、Command Audit、Metric Release diff。

发布流程：

```text
fixture/offline replay
 -> benchmark
 -> shadow
 -> canary sources
 -> observe
 -> staged rollout
 -> active
```

Coverage/Quality/Scope/Cost/Graph provenance/Metric consistency 回归时停止扩大并回滚。

## 26. 验收标准

### Coverage

- 每个 Source 有可解释 Provider；
- FULL_BACKFILL 有 exhaustion evidence；
- known gap 可枚举/可重跑；
- Deep Crawl 队列为空不能冒充完整；
- Common Crawl 不作为完整性证明。

### Incremental

- Feed/API/Sitemap 新文章在目标 SLA 内入库；
- 304 不重复抽取/建版/投影；
- Reconcile 能发现 Feed 窗口外遗漏和结构漂移。

### Filter / Crawl

- URL Filter 有 release/evidence；
- HARD/SOFT 明确；
- 新 Filter Release 有文章 recall fixture；
- Browser 不是默认路线；
- Deep Crawl/Interaction 有预算；
- 批处理按 URL 独立提交。

### Markdown / Structured

- Markdown 可从 IR 确定性重建；
- 正文 heading/code/list/table/image/link 有质量验证；
- Structured Schema 有 fixture 和 validation；
- LLM Extraction 失败不影响 canonical；
- token/cost 可按 Source/Schema 查询。

### Chunk / Search

- HTML/PDF/MD/TXT 使用统一 Chunk Release；
- Chunk ID 不依赖 chunk_index；
- RECHUNK/REEMBED 不访问源站；
- BM25 + Vector + optional Graph 可解释；
- Scope 不召回范围外 Chunk；
- 新 Generation 验证后才能 ACTIVE。

### Graph

- Graph 是 Projection，不是 Truth；
- Entity/Relation 有 Document/Chunk provenance；
- Entity Resolution 可回放、可 diff；
- REGRAPH 不重新抓源站；
- Graph 失败不阻塞 Source Sync；
- Graph Retrieval 有 hop/node/edge budget；
- Graph ScopeLeakRate 接近 0；
- R2R/图数据库可替换，不承担 Source/Version/Task 真相。

### Web / Ops

- Fleet Overview 不实时扫描所有事实表；
- 每个趋势图显示 watermark/coverage；
- Filter/Schema/Graph/Release 可调试、diff、回滚；
- UI 刷新不触发 Crawl/LLM；
- Prometheus 无 URL/Document/Task 高基数 label；
- Dashboard Command 全部经过幂等、RBAC、Audit。

### Reliability / Security

- Worker crash 后 lease 可恢复；
- fencing 防止旧 Worker 覆盖；
- fan-out 保留 partial success；
- Embedding/Graph/AI/Search/Dashboard 故障不阻塞 Source Sync；
- Query Plane 无任意公网 URL 访问权限；
- Runtime/Model/Graph/Metric Artifact 可复现、可回滚。

## 27. 最终技术路线

平台的主链路是：

```text
Coverage-driven Discovery
 -> Evidence-preserving URL Filter
 -> Normalize / Resolve / Probe
 -> HTTP-first Fetch
 -> Immutable Snapshot
 -> Deterministic Canonical IR
 -> Stable Markdown + Document Version
 -> Async Projections
      ├─ Structured Record
      ├─ Chunk / BM25 / Vector
      ├─ Graph Entity / Relation
      └─ AI Insight / Ops Analytics
 -> BM25 + Vector + optional Graph Retrieval
 -> Web-operable Release / Generation / Audit
```

这条路线保证：新增站点靠配置扩展；全量历史有 Coverage 证据；增量同步低成本；Browser 和 LLM 只处理必要长尾；Markdown 是稳定可重建知识资产；结构化数据和知识图谱作为可选派生能力持续增强检索，而不会绑架事实同步；所有策略均可版本化、回放、灰度和回滚，满足 1000+ 技术博客长期运营。
