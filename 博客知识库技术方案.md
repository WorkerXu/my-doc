# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站和公开 Newsletter** 的长期采集与知识库平台，可平滑扩展到数千站点、百万到千万级文章。

平台必须满足：

1. **全历史回填**：尽可能完整发现每个已批准 Source 的历史文章，并能解释发现通道、覆盖率、缺口、截断和停止原因；
2. **持续增量同步**：发现新文章、正文修改、元数据变化、URL 迁移、重定向、删除和重发布；
3. **Markdown 稳定可重放**：保存不可变 Raw Artifact，经版本化 Cleaner、Extractor、Canonical IR、Renderer 生成最终 Markdown；
4. **技术内容保真**：代码块、表格、公式、Mermaid、列表、引用、脚注、图片说明不能被通用降噪算法静默删除；
5. **低成本扩站**：新增站点优先通过 Source Profile、Provider、Recipe、Traversal Policy 配置完成，不维护 1000 份独立爬虫脚本；
6. **Web 可运营**：支持站点接入、审批、Backfill、Incremental、Coverage、Frontier、质量、成本、诊断、暂停、恢复、重跑、灰度和审计；
7. **任务可恢复**：Provider Run、Task、Attempt、URL、Artifact、Candidate、Document、Version 全链路有持久状态，Worker/Runtime 崩溃可恢复；
8. **可搜索/RAG**：支持 BM25、向量和混合检索，并能回溯原文、版本、Source、抓取证据和处理 Release；
9. **主链不依赖 LLM**：LLM 只做可选 Repair/Enrichment，不参与历史完整性、URL 身份、正文存在性、版本真相和权限边界的最终判定。

### 1.1 核心 SLO

- **Coverage**：每个 Source 可查看 Provider Inventory、Completion Attestation、Known Gap、Backfill Stop Reason；
- **Freshness**：新文章/更新从发布或发现到 PASS Markdown 的 P50/P95/P99 延迟；
- **TTFM**：URL 首次发现到首个可用 Markdown 的时间；
- **Extraction Quality**：标题、正文、代码、表格、列表、链接、图片说明、公式的召回率与噪声率；
- **Protected Structure Recall**：受保护技术节点在 Candidate/IR 中的保留率；
- **Multilingual Retention**：中文、日文及中英混排正文保留率；
- **Reliability**：Task 成功率、Retry、DLQ、Queue Age、Lease Recovery；
- **Replayability**：相同 Raw Artifact + 相同 Release 必须得到相同派生结果；
- **Provider Integrity**：部分返回、cache hit、预算耗尽不能被误报为“已完整枚举”；
- **Artifact Durability**：需要保留的 Runtime/Provider Artifact 必须晋升平台对象存储；
- **Browser Efficiency**：HTTP Fast Lane 命中率、Browser avoided、Browser 单文档成本；
- **Revalidation Integrity**：强验证成功率、弱验证漏检率、`hit_fallback` 数量、强制刷新抽样命中变化率；
- **Validator Integrity**：业务 validator 必须能追溯到具体 Raw Artifact/body hash，不允许弱信号把新 validator 绑定到旧正文；
- **Fairness**：大型 Backfill 不得长期饿死 Incremental、小站、Repair 和 Reconcile；
- **Agentic Safety**：Agent 越界导航、Policy Deny、Prompt Injection 阻断、Secret 泄露必须可监控、可审计；
- **Recipe Stability**：Production Recipe 的 selector 多样本命中率、歧义率、mutation survival 与 deterministic replay 成功率必须可量化。

## 2. 核心设计原则

1. **Coverage First**：先构建可解释 URL Inventory，再抓正文；
2. **Authoritative First**：官方 CMS/API、Sitemap、Feed、Archive 优先；
3. **Observation Before Selection**：先保存发现事实，再 Normalize、Scope、Classify、Dedup；
4. **Successful Return != Provider Complete**：HTTP 200、非空结果、`success=true`、cache hit 均不能自动代表 Provider 完成；
5. **Completion Must Be Attested**：只有具备可验证结束语义的 Provider Adapter 才能声明完成；
6. **Discovery / Revalidation / Fetch / Clean / Extract / Quality / Canonicalize / Projection 分离**；
7. **HTTP First, Browser Slow Lane**；
8. **Snapshot First**：先保存 Provider Evidence / Raw Artifact，再生成派生物；
9. **Candidate Portfolio, Not Single Extractor**：多个确定性候选互相校验；
10. **Protected Structures Are First-Class**：代码、表格、公式等先识别，再验证召回；
11. **Language Assumptions Must Be Explicit**：word/token threshold 必须声明适用语言；
12. **Canonical IR First, Markdown as Projection**；
13. **Recipe, Not 1000 Site Scripts**；
14. **Persistent Frontier, Not In-Memory Traversal**；
15. **Idempotent + Recoverable**：幂等键、Lease、Fencing Token、Checkpoint、Inbox/Outbox；
16. **Fair by Default**：Incremental、Revalidation、Repair 必须预留容量；
17. **Bounded Concurrency Everywhere**：任务数、在途请求、结果集合、Browser、进程生命周期都有硬边界；
18. **No Silent Degradation**：过滤、截断、partial result、预算耗尽、cache fallback、降级必须有 typed reason；
19. **Correlate by Identity, Never by Position**；
20. **Config Is Capability**：高能力配置必须经过 Capability Firewall；
21. **Runtime Is Execution Plane**：第三方 Runtime 不拥有 Coverage、Identity、Document、Version、Freshness 或 Markdown 真值；
22. **Behavior Beats Naming**：生产语义以 pinned release + Contract Test 为准，而不是 enum 名称或某一页文档；
23. **Runtime Cache Is Disposable**：本地 cache 可丢弃，不得推进业务版本真值；
24. **Derived Artifact Never Overwrites Evidence**：Cleaned HTML、Candidate、IR、Markdown 均是可重放派生物；
25. **Weak Freshness Signal Cannot Close Truth**：head fingerprint、长度相近等弱信号不能单独证明正文未变化；
26. **Validator Must Bind To Artifact**：ETag/Last-Modified 等业务 validator 必须绑定到具体 Raw Artifact/body hash；
27. **Same URL Does Not Imply Same Representation**：locale、Cookie、UA、Proxy、session、JS、Browser Profile 等不同上下文必须有 `fetch_variant_key`；
28. **Offline Means No Network**：离线 Replay 必须由平台 Artifact + egress deny 保证，不能依赖 `READ_ONLY` 之类的 Runtime 名称；
29. **Explicit Runtime Config**：生产 Attempt 必须显式记录 cache_mode、freshness 开关和 effective config，不能依赖 Runtime 默认值；
30. **Agentic Repair Is Proposal, Not Truth**：LLM 浏览器 Agent 只用于复杂站点诊断、URL Observation 补充和 Recipe Candidate 生成；未经确定性 Replay、Shadow、Canary 与审批门禁，不得成为生产 Recipe，更不能推进 Coverage、Freshness、Document Version 或 canonical Markdown；
31. **Ephemeral Element Identity**：Browser Agent 的 highlight index、CDP node id、backend node id 只属于当前观测/Run，禁止直接持久化为 Production Recipe selector；必须编译成稳定、可验证的 `SelectorBundle`；
32. **Agent Replay Is Diagnostic**：Browser Use history replay 属于启发式元素重定位与诊断能力，不等价于确定性 Recipe Replay，更不等价于平台 Task Recovery；
33. **One Mutating Action, One State Boundary**：任何可能改变 URL、focus target 或 DOM 的动作后都必须重新采样页面状态；Agent 一次返回的多动作不是平台事务边界；
34. **Web Content Is Untrusted Prompt Input**：网页文本、DOM、Accessibility Tree、截图和隐藏内容均是不可信输入，永远不能修改 Tool Policy、Source Scope、Secret Policy 或运行权限；
35. **Agentic Runtime Is Hermetic**：Agentic Browser 必须使用显式的 Source allowlist、IP/私网阻断、容器 egress、最小 Tool Set、临时 Profile 与最小权限，不能把第三方库默认值当安全边界。

### 3.1 业务真相边界

**PostgreSQL + S3/MinIO 是业务真相。**

- PostgreSQL：Source、Scope、Provider、Provider Run/Checkpoint、Observation、URL Identity、Frontier、Task、Attempt、Revalidation Ledger、Validator Binding、Coverage、Candidate Manifest、Quality、Document、Version、Release、Audit；
- S3/MinIO：Provider Evidence、Raw HTML/PDF、Cleaned HTML、Protected Structure Manifest、Candidate、Canonical IR、Markdown、Checkpoint、诊断 Artifact；
- Redis Streams：任务运输与 Backpressure，可重建；
- Redis Lua：跨 Worker Token Bucket/Semaphore；
- Prometheus/TSDB：运行指标；
- OpenSearch/pgvector：Serving Projection，可重建；
- Crawl4AI queue/cache/browser/session/seen/results：Runtime 临时状态，不是业务真相；
- Browser Use AgentState/History/EventBus/Watchdog/browser profile：Agentic Runtime 临时状态，只能产生诊断 Evidence，不是 Coverage、Freshness、Task checkpoint 或 Document Version 真相。

## 4. 技术选型

### 4.1 控制面

- **FastAPI + Pydantic**：REST API、Command、Webhook Inbox、配置编译；
- **PostgreSQL**：Truth Store、Task、Frontier、Coverage、Version、Revalidation Ledger、Validator Binding、Audit；
- **Redis Streams**：Durable Task Transport；
- **Redis Lua**：host/domain/source/browser 全局限流与并发控制；
- **React/Next.js + TypeScript**：Web 管理后台；
- **S3/MinIO**：不可变对象存储；
- **OpenTelemetry + Prometheus + Grafana + Structured Logging**；
- **Vault/KMS/Secret Manager**：secret 引用；
- **Nginx/Envoy/API Gateway**：TLS、Rate Limit、请求体限制、Correlation ID。

### 4.2 Discovery / Fetch

- **httpx/aiohttp**：CMS API、robots、Sitemap、Feed、Conditional GET、普通网页；
- **RFC 9309 Robots Engine**；
- **平台原生 SitemapProvider**：显式 Sitemap、robots Sitemap、Sitemap Index durable shard；
- **平台原生 CommonCrawlIndexProvider**：固定 index release、流式查询、Evidence、Checkpoint；
- **Crawl4AI AsyncUrlSeeder pinned release**：Sitemap/CC URL 发现加速器；
- **Crawl4AI pinned package/image**：复杂页面、JS Render、Deep/Adaptive gap discovery、Browser Runtime、Markdown Candidate；
- **Playwright**：确定性 Browser Recipe Executor 与必要的受控慢路径；
- **Browser Use pinned release（可选）**：只用于 Agentic Browser Repair / Recipe Studio；负责少量复杂交互站点的诊断和 Recipe Candidate 生成，不进入默认批量抓取主链，产物必须经过 Selector/Recipe Compiler 与确定性 Promotion Gate；
- **Wayback Adapter**：历史缺口证据；
- **PyMuPDF/pdftotext**：PDF；扫描件进入独立 OCR 慢路径。

### 4.3 Extraction / Search

- **Trafilatura**：Generic Candidate；
- **lxml/BeautifulSoup**：DOM/XPath、Metadata、Repair、Protected Structure Fingerprint；
- **JSON-LD/OpenGraph/Microdata**；
- **CSS/XPath/Regex Recipe**；
- **Crawl4AI DefaultMarkdownGenerator / ContentFilter**：Markdown Candidate，不直接作为 canonical；
- **SimHash/MinHash**：近重复；
- **OpenSearch BM25 + pgvector + RRF**；
- embedding、reranker、LLM 只做增强。

### 5.3 Fetch Variant

同一个 URL 在不同上下文中可能得到不同表示。平台必须生成稳定的 `fetch_variant_key`，输入至少考虑：

```text
source_id
browser_profile_class
locale / timezone
user_agent_class
auth/cookie class
proxy/region class
session class
render_js / interaction class
accepted representation / device class
runtime_security_profile_release
```

`fetch_variant_key` 用于：

- 判断某次 Raw Artifact 是否可复用；
- 隔离 Runtime cache namespace；
- 避免同 URL 在不同 locale、Cookie、UA、Proxy、session 下交叉污染；
- 诊断“同 URL 不同正文”的来源；
- 约束 Agentic Run、确定性 Replay、Shadow、Canary 必须在兼容表示上下文内比较。

Extractor/Markdown 配置变化不应通过复用 Runtime 已派生的 `cleaned_html/markdown/extracted_content` 解决，而应从平台 Raw Artifact 重放新的处理 Release。

### 5.4 Capability Firewall

高风险能力必须单独授权：

- 自定义 JS；
- LLM 驱动浏览器交互 / Agentic Repair；
- 任意 Header/Cookie；
- Proxy；
- Browser CDP；
- 文件下载/上传；
- 文件系统读写；
- iframe/Shadow DOM；
- 剪贴板、通知或其他 Browser Permission；
- 任意外部回调；
- 高并发/长超时；
- 跨 host 跳转。

未经审批的 Source 配置只能使用安全 allowlist。网页内容、模型输出或 Agent tool result 不得动态扩大 Capability。

## 6. 全历史 URL 发现与 Coverage

### 6.1 Provider 优先级

每个 Source 的历史发现按以下优先级执行：

1. 官方 CMS/API；
2. Sitemap / Sitemap Index；
3. RSS / Atom；
4. Archive / Pagination / Tag / Category；
5. 静态链接图；
6. Common Crawl Index；
7. Wayback；
8. Crawl4AI URL Seeder、Domain Mapping、Deep/Adaptive Crawl 作为补洞和加速。

任何单一 Provider 都不能自动证明“全历史完整”。Agentic Browser 只能补充 Observation 或发现“可能存在的新入口”，不能担任 Completion Authority。

### 6.2 Observation 模型

Provider 返回的每一条 URL 先写 `url_observation`：

```text
observation_id
source_id
provider_id
provider_run_id
observed_url
observed_at
provider_timestamp
provider_metadata
provider_evidence_uri
```

随后统一执行：

```text
Normalize -> Scope Check -> MIME Hint -> URL Identity -> Dedup -> Frontier Upsert
```

不允许 Provider 内部去重结果直接成为平台最终 Inventory。Agentic Repair 新发现的 URL 同样必须先形成 Observation，再经过相同 Scope/Identity 管线。

### 6.3 Provider Completion Attestation

每次 Provider Run 保存：

```text
started_at / finished_at
checkpoint / cursor / shard
items_seen / unique_urls
status
completion_type
stop_reason
truncated
budget_exhausted
known_gap
provider_release
```

只有满足 Adapter 的明确完成条件时，`completion_type=ATTESTED_COMPLETE`。

以下情况一律不能标完整：

- 返回非空列表；
- HTTP 200；
- `success=true`；
- 达到 limit；
- cache hit；
- 搜索结果不再增加但没有协议级结束条件；
- Deep Crawl 达到配置深度/页面预算；
- Agentic Repair 停止继续点击或暂时未发现新 URL；
- Agent/LLM 报告“任务完成”。

### 6.4 SitemapProvider

Sitemap Index 必须拆成 durable shard：

```text
sitemap_index_run
  -> sitemap_shard_1
  -> sitemap_shard_2
  -> ...
```

每个 shard 单独保存 URL、ETag/Last-Modified、fetch time、parse result、child count、checkpoint、completion attestation。

增量阶段对 Sitemap 使用 Conditional GET；`lastmod` 只做变化线索，不直接代表正文已变化。

### 6.5 Common Crawl / Wayback

只作为历史缺口补洞：

- 固定 index/release；
- 保存查询条件和返回证据；
- 流式读取，避免一次性加载大结果；
- URL 仍进入 Observation/Scope/Identity；
- Archive 出现不等于当前 URL 仍有效；
- Archive 缺失也不能证明文章从未存在。

### 6.6 Crawl4AI URL Seeder 的定位

AsyncUrlSeeder 可批量从 Sitemap/CC 等发现 URL，但平台必须：

- pin release；
- 限定 modes/domain；
- 将返回值转成 Observation；
- 保存 provider evidence 和 cutoff；
- 不把 Seeder 内部 cache/seen/queue 当 durable checkpoint；
- 不用 Seeder 返回条数证明 Coverage。

### 6.7 Coverage 计算

每个 Source 维护：

```text
provider_inventory
provider_attestation
historical_time_range
observed_url_count
fetchable_url_count
article_count
known_gap_count
unresolved_gap_count
backfill_stop_reason
```

Web 后台必须能回答：“为什么系统认为这个站回填完成/未完成？”

## 7. URL Identity、Canonical 与去重

### 7.1 三种 URL 分开

```text
observed_url      Provider 实际看到的 URL
normalized_url    平台规则归一化后的 URL
canonical_url     经证据判定的文章主 URL
```

不能直接把 `<link rel=canonical>` 当绝对真相，因为网站模板、镜像、错误配置可能把大量文章指向同一个 canonical。

### 7.2 Normalize

可安全做：host 小写、默认端口移除、fragment 移除、已知 tracking query 移除、Unicode/percent encoding 规范化、Source 级 trailing slash 规则。

不可全局盲做：query 参数排序/删除、path 大小写合并、日期段重写、`www` 与 apex 合并、HTTP/HTTPS 强制合并。这些必须受 Source Policy 控制。

### 7.3 Dedup

```text
URL exact identity
        -> redirect/canonical alias
        -> raw body hash exact duplicate
        -> semantic body hash
        -> SimHash/MinHash near duplicate
```

近重复只用于候选关联，不能自动删除原始 Document Version。


### 9.3 证据强度

**STRONG**：

- CMS/API revision/version id；
- 使用“绑定到当前 authoritative Raw Artifact”的 validator 得到的标准 Conditional GET 304；
- 完整 GET 后 body hash 与历史一致。

**MEDIUM**：

- ETag/Last-Modified 发生变化；
- Sitemap/RSS 更新时间发生变化；
- 已知可靠但非正文级的 Provider change signal。

**WEAK**：

- `<head>` fingerprint 相同；
- 页面长度相近；
- link graph 相似；
- 局部 metadata 未变化；
- Agent/LLM 认为页面“没有变化”。

只有符合 Source Policy 的强证据才允许推进 `last_verified_at`。

### 9.4 Validator Binding Invariant

这是避免 Smart Cache 把旧正文错误升级为 fresh 的关键约束。

平台维护：

```text
validator_binding_state = BOUND | UNBOUND_HINT | INVALIDATED
validator_artifact_id
validator_body_sha256
validator_origin = FULL_GET | CMS_REVISION | HEAD_HINT | RUNTIME_HINT
```

规则：

1. **只有与完整网络响应一起获得的 validator，才能绑定到该 Raw Artifact。**
2. HEAD、局部 metadata、head fingerprint 流程看到的新 ETag/Last-Modified 只能记录为 `UNBOUND_HINT`，不能覆盖当前 authoritative validator；
3. 304 只有在请求使用的 validator 已绑定到“当前 authoritative Raw Artifact/body hash”时，才能计为 STRONG unchanged；
4. Runtime Smart Cache 在 weak head match 后更新的 Runtime ETag/Last-Modified，不得直接导入业务 Ledger 作为 authoritative validator；
5. 若绑定 Artifact 已被新 DocumentVersion 取代，旧 validator 必须失效或进入历史绑定；
6. 每次 Runtime 升级必须测试“body 改变、head 不变、ETag 改变”的场景，防止 validator promotion/stale validator poisoning。

### 9.5 状态机

```text
DUE_FOR_REVALIDATION
      |
      +-- Provider 明确 changed ------> FETCH_REQUIRED
      |
      +-- bound validator 304 --------> VERIFIED_UNCHANGED
      |
      +-- validator changed ----------> FETCH_REQUIRED / UNBOUND_HINT
      |
      +-- weak unchanged -------------> WEAK_UNCHANGED
      |                                  |
      |                                  +-- sample due -> FETCH_REQUIRED
      |
      +-- validation error -----------> VALIDATION_DEGRADED
                                         |
                                         +-- 可服务旧版本
                                         +-- 不推进 last_verified_at
                                         +-- 安排重试

FETCH_REQUIRED
      |
      v
RAW_ARTIFACT
      |
      +-- body hash unchanged --------> VERIFIED_UNCHANGED + bind validators
      |
      +-- body hash changed ----------> NEW_DOCUMENT_VERSION + bind new validators
```

### 9.6 强制定期完整抽样

任何 weak/validator 路径都必须配置：

```text
forced_full_refresh_interval
forced_sample_rate
min_validator_trust_score
```

抽样完整抓取发现“validator 未报变化但 body hash 已变”时：记录 false negative、降低 Source validator trust score、缩短强制刷新周期、提高 fresh-fetch 比例，必要时禁用该 Source 的弱验证跳过策略。

## 10. HTTP Fast Lane、Browser Slow Lane 与 Runtime Cache

### 10.1 HTTP First

普通文章优先 `httpx/aiohttp`：

- GET/Conditional GET；
- Redirect chain；
- ETag/Last-Modified；
- Content-Type/MIME；
- Content-Length 上限；
- robots；
- Response headers；
- 原始字节与编码检测。

满足正文质量条件则不启 Browser。

### 10.2 Browser Escalation

仅以下情况进入 Browser Slow Lane：

- HTTP 页面正文为空/占位；
- JS 客户端渲染；
- 需要有限滚动/点击才能出现正文；
- Shadow DOM/iframe 且 Source Policy 允许；
- HTTP Candidate 明显低质量；
- Source Recipe 指定。

Browser 通过长期 Runtime Pool 复用，不为每 URL 启新进程。生产默认使用**确定性 Browser Recipe Executor**；只有普通 Browser Recipe 无法稳定完成、Source onboarding 需要探索、或 Operator 主动诊断时，才允许进入 Agentic Repair。

### 10.2.1 Agentic Browser Repair / Recipe Studio

Agentic Browser 不是新的默认抓取器，而是 Browser Slow Lane 内的**疑难诊断与 Recipe 候选生成器**：

```text
HTTP / deterministic Browser failed
        |
        v
Agentic Browser Repair Sandbox
        |
        +--> BrowserState(DOM/AX/screenshot/current URL)
        +--> LLM chooses bounded structured actions
        +--> controlled Browser Gateway executes
        +--> immutable action trace / screenshots / DOM evidence
        |
        v
Selector Compiler + Recipe Compiler
        |
        v
Recipe Candidate
```

运行必须绑定：

```text
source_id
url_id
fetch_variant_key
browser_profile_release
browser_use_release
browser_build_release
agent_model_release
agent_prompt_release
agent_tool_policy_release
agent_observation_schema_release
agent_security_policy_release
agentic_repair_policy_release
```

并设置硬预算：`max_steps`、`max_actions_per_step`、总 action 数、wall-time、token、cost、page/tab count、artifact bytes。预算耗尽、循环、无新链接、越界导航均返回 typed stop reason，不能被解释为 Provider Complete。

**录制/候选编译模式默认 `max_actions_per_step=1`。** 如果探索模式允许一次返回多个动作，则任何可能改变 DOM、URL 或 focus target 的动作后必须强制重新采样 BrowserState。Browser Use 内部对导航/URL/target 变化有动作队列截断保护，但 URL 和 target 不变的 SPA 局部重绘仍可能使旧元素 index 失效，因此不能把一次 Agent step 视为原子事务。

Browser Use 的 `output_model_schema` 可约束结构化输出格式，可用于生成 `RecipeCandidate`，但它只解决 schema/格式问题，不能把模型推理路径变成确定性生产执行。

Agentic Sandbox 的执行面必须比通用浏览器 Agent 更严格。不能继承通用库默认值作为安全策略：Browser Use 通用配置中 IP 阻断、下载、Browser Permission、`data:`/`blob:` 等行为需要平台显式覆盖，默认 Tool Set 还包含任意 JS、上传和文件读写等高能力动作。平台必须强制：

- `allowed_domains/paths` 直接来自已审批 Source Scope，并在导航前、重定向后、新 tab 三处强制校验；
- DNS/网络层默认阻止 IP、localhost、private/link-local/metadata 地址并防 DNS rebinding；
- 容器/Pod egress 再做独立 allowlist，不把 Runtime URL 检查当唯一 SSRF 防线；
- 默认禁用上传、表单提交、发布/删除/支付、下载、文件系统、剪贴板、任意 JS、任意 CDP、自定义外部回调；
- 默认不允许 `data:`、`blob:`、`file:` 等非普通网络导航，确有需求时单独 Capability 审批；
- Browser Permission 默认最小化；
- Cookie、Storage State、Proxy、locale、UA、timezone 必须按 `fetch_variant_key` 隔离；
- public blog 默认使用临时无认证 Profile，不复用真实用户 Chrome Profile；
- secret 只通过引用注入，trace 只保存脱敏参数；
- screenshot、DOM/AX 摘要、action/result、目标元素证据、URL 变化、耗时和费用写入不可变诊断 Artifact。

Agent 成功后输出的是有限 `browser_interaction_dsl` 的 `recipe_candidate`，例如 `NAVIGATE`、`WAIT_SELECTOR`、`CLICK`、`SCROLL(max)`、`EXPAND`、`NEXT_PAGE`、`EXTRACT_LINKS`、`ASSERT_*`、`STOP`。默认不允许候选携带任意 JavaScript；所有循环必须有次数上限，wait 必须有 timeout，selector 必须引用经过编译和验证的稳定 SelectorBundle。

Agentic Run 可以新增 URL Observation 或提出“可能存在归档入口”的提示，但**不能直接写 Coverage Complete、推进 `last_verified_at`、创建权威 Document Version，或把 Agent `extract` / `final_result` 文本直接当 canonical Markdown**。

### 10.2.2 Deterministic Recipe Promotion Gate

Agentic 探索要进入生产，必须从“模型决策流程”编译为“无需 LLM 的确定性 Recipe”，并通过以下晋升链：

```text
Agentic Evidence
   -> Selector Compiler
   -> Recipe Compiler
   -> Recipe Candidate
   -> Schema / Static Policy Validation
   -> Selector Ambiguity Validation
   -> Deterministic Fixture Replay
   -> Repeated Replay on same fixture
   -> Sampled Live Replay
   -> Shadow Run
   -> Source Canary
   -> Human/Policy Approval
   -> recipe_release
```

门禁至少验证：

- 动作是否全部属于 DSL allowlist；
- 是否越过 Source Scope；
- 是否含任意 JS/CDP/file/upload/download 或其他未授权副作用；
- loop 是否都有 hard bound、wait 是否都有 timeout；
- selector 的 expected cardinality 是否满足约束；
- selector 多页面命中率、歧义率、mutation survival 是否达到 Policy 阈值；
- 相同 fixture 多次 replay 的 URL/output 是否稳定；
- URL discovery 与旧 Recipe/Provider 差异是否可解释；
- 正文质量、Protected Structure Recall 是否回归；
- Browser wall-time、错误率和成本是否可接受。

如果某一步仍需要“再次询问 LLM 下一步”，或者临时元素引用无法编译成稳定 SelectorBundle，它只能停留在 Agentic Repair 层，不能自动晋升为生产 Recipe。

发布后的 Recipe 由普通 Browser Slow Lane 确定性执行；升级仍遵循 shadow → canary → release → rollback。这样 Agent 只承担长尾探索成本，不把模型非确定性带入百万 URL 的常规抓取主链。

### 10.2.3 Browser Use 元素身份、Replay 与 Selector Compiler

Browser Use Agent 常以当前 selector map 中的 `highlight index` 定位元素，Actor/CDP 还可以使用 node id/backend node id。这些都属于**当前浏览器状态/会话中的临时标识**，页面插入元素、DOM 重绘、A/B、locale、Cookie、viewport、iframe/shadow DOM 变化都可能使其失效。

因此建立强约束：

> `highlight index`、CDP node id、backend node id 只能用于单次 Agent Run 内动作执行和证据关联，禁止直接进入 `recipe_release`。

Browser Use 的 history replay 本身也不会盲目复用旧 index，而会使用历史 `DOMInteractedElement` 对当前 DOM 做分层重定位，当前实现的主要匹配级别为：

```text
EXACT      元素 hash 完全匹配
STABLE     过滤动态 CSS class 后的 stable hash
XPATH      历史 XPath
AX_NAME    节点类型 + Accessibility Name
ATTRIBUTE  name / id / aria-label 等属性回退
```

这说明 history replay 的正确定位是**诊断和尽力复现**，不是长期 selector contract。平台必须将 Agent evidence 交给独立 `Selector Compiler`，生成：

```text
selector_bundle
  selector_bundle_id
  semantic_role
  accessible_name
  stable_attributes
  data_attributes
  id_name_candidates[]
  stable_text_anchor
  css_candidates[]
  xpath_candidates[]
  ancestor_constraints[]
  frame_scope
  expected_cardinality
  fallback_order[]
  selector_fingerprint
  fixture_match_rate
  live_sample_match_rate
  ambiguity_rate
  mutation_survival_rate
  selector_strategy_release
```

Selector 优先使用稳定业务属性、role/accessible name、稳定 `data-*`、稳定 id/name、语义文本和结构约束；随机 class、纯位置 index、`nth-child` 只能作为最后 fallback，且不能在无稳定替代项时通过 Promotion Gate。

Production Recipe 只引用 `selector_ref` / `selector_bundle_id`，例如：

```yaml
steps:
  - click:
      selector_ref: archive_load_more_v3
  - wait_dom_change:
      timeout_ms: 5000
```

如果 Candidate 无法将临时 index 编译为无歧义 SelectorBundle，必须返回 `UNCOMPILABLE_ELEMENT_REFERENCE` 并拒绝晋升。

### 10.2.4 Agentic Runtime 恢复与证据边界

Browser Use 的 EventBus/Watchdog/CDP session 具备浏览器连接异常检测、等待 reconnect、重新取得 CDP session 等运行时恢复能力，但这只解决“浏览器执行层还能否继续工作”，不能替代平台 durable recovery。

必须区分：

```text
Browser Use history replay    = 启发式复现历史交互
Production Recipe replay      = 无 LLM 的确定性 DSL 重放
Platform Task recovery        = Task/Attempt/Lease/Fencing/Artifact 的业务恢复
```

规则：

- CDP reconnect 只记录为当前 Attempt 的 runtime event，不因此推进 Task、Freshness、Coverage 或 Version；
- Agentic Browser 崩溃时，保存已经晋升到平台对象存储的 evidence，当前 Attempt 标失败；按策略创建新的 Agentic Run，而不是宣称恢复了同一个业务事务；
- AgentState、in-memory History、EventBus history、Browser profile/session 均不是 durable checkpoint；
- 确定性 Recipe Executor 可按平台定义的 step checkpoint 和幂等语义重放；
- history replay 的 match level（EXACT/STABLE/XPATH/AX_NAME/ATTRIBUTE）只作为诊断指标，不因 replay 成功自动提高 Recipe Release 信任等级；
- Agent `extract`/structured final result 只用于诊断、候选生成或 Observation；要形成文章版本，最终页面 HTML/PDF 必须先成为正常平台 Raw Artifact，再经过 Cleaner → Candidate → Quality → IR → Markdown 确定性管线。

### 10.3 平台 Cache Policy Compiler

业务层不直接暴露 Crawl4AI `CacheMode`，只暴露：

```text
AUTHORITATIVE_FETCH
VALIDATE_THEN_FETCH
REPLAY_FROM_ARTIFACT
RUNTIME_CACHE_WARMUP
DIAGNOSTIC_CACHE_READ
```

Compiler 根据 pinned runtime release 生成实际配置，并把 effective config 写入 Attempt。

生产 Attempt 必须显式生成：

```text
runtime_cache_policy
cache_mode_effective
check_cache_freshness_effective
cache_validation_timeout_effective
runtime_cache_namespace
fetch_variant_key
runtime_release
runtime_cache_contract_release
```

不能依赖 Runtime 默认值；尤其不能让“遗漏配置”退化为 `ENABLED + freshness off`。

#### AUTHORITATIVE_FETCH

- 禁止从 Runtime cache 返回旧正文；
- 必须产生真实网络响应证据；
- 使用 Contract Test 验证过的配置，不按 enum 名称猜测；
- 结果晋升平台 Raw Artifact；
- 响应 validator 绑定到该 Artifact/body hash。

#### VALIDATE_THEN_FETCH

- 平台 Revalidation Engine 先使用 bound validator 判断；
- 确认需要抓取后使用 fresh fetch；
- Runtime Smart Cache 只做可选额外优化；
- Runtime `hit_validated` 不能覆盖平台 Freshness 结论；
- Runtime 新发现的 validator 若来自 weak flow，只作为 hint。

#### REPLAY_FROM_ARTIFACT

- 直接处理 S3/MinIO Raw Artifact；
- 不访问网络；
- Replay Worker 使用 egress deny；
- **不能映射成 Crawl4AI `READ_ONLY` 来保证离线**，因为 cache miss 仍可能真实联网。

#### RUNTIME_CACHE_WARMUP / DIAGNOSTIC_CACHE_READ

允许 Runtime cache，但不推进业务 Version、Freshness、Coverage 或 authoritative validator。

### 10.4 Crawl4AI CacheMode 的生产契约

当前已验证源码的读写矩阵为：

| 模式 | 读 Runtime Cache | 写 Runtime Cache |
|---|---:|---:|
| ENABLED | 是 | 是 |
| DISABLED | 否 | 否 |
| READ_ONLY | 是 | 否 |
| WRITE_ONLY | 否 | 是 |
| BYPASS | 否 | 否 |

同时当前源码旧参数迁移为：

```text
disable_cache -> DISABLED
bypass_cache -> BYPASS
no_cache_read -> WRITE_ONLY
no_cache_write -> READ_ONLY
```

但官方不同文档页面与当前源码存在语义漂移，特别是旧参数映射以及 BYPASS 的描述。因此：

- 禁止新配置使用 legacy boolean flags；
- 生产只允许 pinned release；
- 每次升级都重新验证 `should_read/should_write/network_called/cache_written`；
- Runtime Registry 保存 `known_behavior_diff`；
- **行为以 Contract Test 为准，不以文档名称为准。**

### 10.5 Smart Cache 的使用边界

当前 Smart Cache 是 `check_cache_freshness` 的附加校验，默认关闭。典型流程：

```text
Runtime cache hit
    -> 条件 HEAD(If-None-Match / If-Modified-Since)
        -> 304: Runtime 判 FRESH
        -> 200: 取新 validator，再流式读取 <head>
                 -> head fingerprint 相同: Runtime 判 FRESH
                 -> head fingerprint 变化: STALE -> full crawl
        -> error/timeout: ERROR -> hit_fallback
```

`<head>` 流式读取会在发现 `</head>` 或达到大小上限后停止，fingerprint 聚焦 title、description、OpenGraph、modified-time 等元信息。

平台必须遵守：

1. `check_cache_freshness` 必须显式配置，不能假定默认启用；
2. `<head>` fingerprint 是 WEAK 证据，正文可以在 head 不变时变化；
3. Runtime validation error 可能返回旧 cache (`hit_fallback`)；
4. `hit_fallback` 只能作为 serving fallback，不得更新 `last_verified_at`；
5. Runtime cache 不进入 Coverage/Version 真值；
6. `READ_ONLY` 只表示不写 Runtime cache，不表示禁止联网；
7. Runtime 在 weak head match 后获得的新 validator 不得升级为平台 authoritative validator；
8. CacheMode 真实语义必须以 pinned release Contract Test 为准。

### 10.6 URL-only Runtime Cache 风险与隔离

当前 Runtime Cache 本质上以 URL 为核心键，并保存完整 CrawlResult，包括 HTML、Cleaned HTML、Markdown、Extracted Content、Metadata 等。

因此以下情况默认禁止共享 Runtime Cache：

- Cookie/Auth；
- session；
- proxy/region；
- locale/timezone；
- User-Agent/device profile；
- 自定义 JS/交互状态；
- 不同 Browser profile；
- 同 URL 可能按用户/地区/语言返回不同内容。

若确有性能收益，必须按：

```text
source_id + fetch_variant_key + runtime_release
```

隔离 Runtime cache namespace/实例。

### 10.8 Runtime Cache Contract Test Matrix

每次 Runtime package/image 升级至少验证：

| 场景 | 必验结果 |
|---|---|
| ENABLED + hit + freshness=false | 可直接 hit，不发生 freshness 网络校验 |
| ENABLED + hit + 304 | Runtime `hit_validated`；平台仍校验 validator binding |
| ENABLED + hit + 200 + head 相同 | Runtime 可判 fresh；平台只认 WEAK |
| ENABLED + hit + head 变化 | 重新抓取 |
| ENABLED + hit + timeout/error | `hit_fallback`，不推进业务验证时间 |
| READ_ONLY + hit | 读 cache，不写 |
| READ_ONLY + miss | 会真实联网，但不写 Runtime cache |
| WRITE_ONLY + hit | 不读旧 cache，真实抓取并写 |
| DISABLED | 不读、不写、真实抓取 |
| BYPASS | 实测读写/联网语义，禁止按名字推断 |
| legacy `no_cache_read/no_cache_write` | 验证 pinned release 的实际映射 |
| 同 URL、不同 locale/cookie/UA | 不得错误跨 variant 复用 |
| 同 URL、不同 extractor/markdown release | canonical 必须从 Raw Artifact 重放 |
| body 改变、head 不变、ETag 改变 | 新 ETag 不得绑定到旧 Artifact；后续 304 不得误报强验证 |
| validation error | stale serving 与 business verification 分离 |

## 14. Document、Version 与变化判定

```text
Document = 逻辑文章身份

```

完整抓取后：

```text

    -> 不创建新 DocumentVersion
    -> 更新 fetch evidence，并可重新绑定当前响应 validator

            -> 只更新 fetch evidence / metadata
        -> semantic content hash changed
```

## 21. 安全、合规与抓取边界

### 21.1 SSRF

所有 URL Fetch 前解析 DNS，禁止 loopback/private/link-local/metadata IP；redirect 每跳重新校验；防 DNS rebinding；执行 Approved Host/Scope allowlist。

Agentic Browser 再增加容器/Pod egress allowlist。即使 Browser Use URL SecurityWatchdog 配置失效，网络层仍应阻断私网、metadata 和非批准公网目标。

### 21.2 Browser 隔离

独立容器/Pod、非 root、只读/最小文件系统权限、egress policy、secret 不进入页面 JS、禁止任意 host CDP。

普通确定性 Browser 与 Agentic Browser 分池。Agentic Sandbox 默认：

- 临时 profile，不共享真实用户 profile；
- `block_ip_addresses=true` 语义在平台网络层和 Runtime 层双重执行；
- 禁止下载和自动 PDF 下载，特殊 PDF Source 走专门 Fetch Path；
- Browser permissions 为空或最小 allowlist；
- 禁止任意 `evaluate`/CDP/file read/write/upload/clipboard；
- `data:`、`blob:`、`file:` 等 scheme 默认拒绝；
- storage state 仅在 source-authenticated variant 中按 Source 隔离、加密和 TTL 管理。

### 21.3 Robots / Rate Limit / Terms

默认遵守 robots；保存 robots snapshot/release；429/Retry-After 优先；Source 可配置 legal/compliance note；登录、付费墙、明确禁止自动化的 Source 单独审批。

CAPTCHA、付费墙和明确反自动化控制默认不通过 Agent 自动绕过；需要特殊处理时进入合规与人工审批流程。

### 21.4 Secret

Source Profile 只保存 secret reference，真实值由 Vault/KMS 在受控 Worker 注入。公开技术博客 Agentic Repair 默认不注入任何 secret。

Secret、Cookie、Authorization、Storage State、TOTP 等不得进入普通 Agent trace、截图说明、模型长时记忆或日志；必须按字段策略脱敏/拒绝持久化。

### 21.5 Agentic Prompt Injection

网页正文、DOM 属性、Accessibility Name、隐藏文本、截图中文字、下载内容均视为**不可信外部输入**。网页可以建议 Agent 做什么，但不能修改平台 Policy。

强制规则：

1. System task / Source Scope / Tool Policy / Secret Policy 来自版本化平台配置，与网页内容分离；
2. 页面文本要求“忽略之前规则”“上传文件”“发送 Cookie”“访问另一域名”“执行 JS”时，Tool Registry/Gateway 仍按静态 Capability 判定并拒绝；
3. 模型不能动态注册新 Tool、扩大 `allowed_domains`、打开 CDP/file/upload/download 等能力；
4. public Source 不向 Agent 注入 secret；authenticated Source 仅提供最小 Source-scoped secret reference；
5. 所有 Policy Deny、cross-scope、可疑 prompt injection 写 `agentic_policy_decision` 与审计日志；
6. 维护恶意页面 Fixture Corpus，任何 Browser Use/model/prompt/tool policy 升级都必须做 injection regression test。

结构化输出只能降低格式风险，不能替代执行层能力隔离。

- Coverage 长期无进展；
- `hit_fallback` 激增；
- validator false negative 超阈值；
- validator binding violation；
- Runtime cache variant mismatch；
- 某 host 429/403 增长；
- Browser crash/OOM；
- Queue Age 超 SLO；
- Artifact Promotion 失败；
- Protected Structure Recall 下跌；
- Runtime Contract Test 失败；
- Agentic policy deny / cross-scope 尝试突然升高；
- Prompt Injection Fixture 回归或线上阻断激增；
- Browser Use 升级后 history/selector replay 命中率下降；
- Agentic Repair Browser minute/token/cost 异常增长；
- Candidate 大量生成但 Promotion pass ratio 明显下降；
- 新 Recipe Canary 的 URL discovery/正文质量明显回归；
- screenshot/HAR/trace 检测到 secret 泄露。

## 23. 容量、成本与扩展

初始建议：PostgreSQL 高可用、Redis HA、S3/MinIO、HTTP Worker 与 Browser Worker 分池、Browser Pool 独立 autoscaling、Extraction/Render Worker 水平扩展、OpenSearch/pgvector 独立 Serving Plane。

进一步将 Browser 分为：

```text
fetch-browser-deterministic   生产 Recipe 执行，高优先级、无 LLM
agentic-repair               长尾探索，低优先级、低并发、独立 token/cost 配额
```

扩容按 workload 独立进行：Discovery CPU/IO、HTTP network、Browser memory/CPU、Agentic LLM/API quota、Extraction CPU、Embedding GPU/API quota、Index IO。不要使用一个万能 Worker 承载所有工作。

成本优化顺序：

1. Provider 权威发现减少无效 crawl；
2. HTTP First；
3. 平台 Revalidation 避免重复 Browser；
4. 在可证明安全的 fetch variant 上使用 Runtime cache；
5. 确定性 Browser Pool 复用；
6. Agentic Repair 只处理难例并将成功探索编译为长期可复用 Recipe；
7. Candidate/IR Replay 避免重新联网；
8. embedding 只对 PASS Version；
9. 历史旧 Artifact 使用对象存储生命周期策略。

Agentic Repair 每个 Source 还需单独限制：最大步骤、每步 action、页面/tab、wall-time、LLM token、总费用、Artifact bytes、每小时/每日运行次数。任何预算耗尽都返回明确 stop reason，不把部分结果误标完成。

## 24. 测试与发布门禁

### 24.1 Fixture Corpus

维护代表性站点：WordPress、Ghost、Hugo/Jekyll、Next.js/React、Medium/Substack 类、中文技术博客、大量代码/表格/公式、JS 渲染、Redirect/404、错误 canonical、不可靠 ETag/Last-Modified、正文变化但 head 不变、同 URL 多 locale/UA/Cookie 表示。

Agentic/Browser Fixture 再包括：

- “加载更多”导致 URL 不变但 DOM 全量/局部重绘；
- 随机 CSS class、列表插入广告、元素顺序变化；
- 重复 id/name/aria-label、同名按钮；
- iframe/shadow DOM；
- redirect/new tab 跨域；
- IP/localhost/private/link-local/metadata、`data:`/`blob:`/`file:`；
- 恶意页面 prompt injection；
- 页面诱导 upload/file read/JS/CDP/secret exfiltration；
- CDP disconnect/reconnect、browser crash。

### 24.2 Golden Tests

对：

```text
Raw -> Cleaner -> Candidate -> IR -> Markdown
```

做 Golden hash/结构 diff。

对 Production Browser Recipe：

```text
fixture browser state + recipe_release
-> deterministic actions
-> discovered URLs / final Raw Artifact
```

做重复 replay 与行为 diff，禁止调用 LLM。

### 24.3 Runtime Contract Tests

每次 Crawl4AI/Playwright 升级必须验证：

- CacheMode 读写矩阵；
- legacy flags 的真实映射；
- 文档/源码行为漂移；
- Smart Cache；
- cache miss 行为；
- `hit_fallback`；
- `READ_ONLY` 联网语义；
- body changed + head same + ETag changed 的 validator poisoning 场景；
- 同 URL 不同 fetch variant 的污染场景；
- 同 URL 不同 extractor/markdown 配置的派生结果复用场景；
- Browser 参数；
- URL/result correlation；
- Markdown Candidate schema；
- timeout/error；
- Artifact 输出；
- security allowlist。

每次 Browser Use / Chromium / Agent model / prompt / Tool Policy / Observation Schema / Selector Strategy 升级还必须验证：

**Agent/Action Contract**

- recording mode `max_actions_per_step=1`；
- 若开启 multi-action，navigate/switch/URL/target change 后剩余动作被截断；
- URL/target 不变但 DOM 重绘后平台会重新采样，而不是复用旧 highlight index；
- output schema 验证失败显式失败，不静默接受自由文本；
- max step/action/wall-time/token/cost/page 等预算全部可硬中止并返回 typed stop reason。

**Element/Replay Contract**

- highlight index 改变时 history replay 只作为诊断，可记录 `EXACT/STABLE/XPATH/AX_NAME/ATTRIBUTE` match level；
- Production Recipe 中不存在 highlight index、CDP node id、backend node id；
- 同名 AX 元素、重复 id/aria-label 不会被 Selector Compiler 当唯一 selector；
- `nth-child`、随机 class、纯位置 selector 在无稳定 fallback 时无法通过 Promotion Gate；
- DOM 插广告、顺序变化、动态 class 变化后 selector 仍满足 match/ambiguity/mutation survival 阈值；
- 无法把临时元素引用编译为 SelectorBundle 时返回 `UNCOMPILABLE_ELEMENT_REFERENCE`；
- 仍依赖 LLM 决策的 Candidate 必须拒绝自动晋升。

**Security Contract**

- approved domain 正常；
- 直接跨域、redirect 跨域、popup/new tab 跨域均阻断；
- IP/localhost/private/link-local/metadata 阻断；
- `data:`/`blob:`/`file:` 按平台策略阻断；
- downloads/upload/file tools/evaluate/arbitrary CDP/clipboard 默认不可用；
- Storage State 不跨 Source/fetch variant；
- 恶意网页文本不能扩大工具权限、改变 Source Scope 或泄露 secret；
- 容器 egress 在 Runtime 层规则失效时仍能兜底；
- Agent trace/HAR/screenshot metadata 不泄露 Cookie/Authorization/Storage State。

**Recovery Contract**

- CDP disconnect/reconnect 记录 runtime event，但不错误推进 Task/Freshness/Coverage；
- Browser crash 后当前 Attempt 可终止并保留已晋升 evidence；
- Agentic rerun 不被标记成 deterministic resume；
- Production Recipe 可按平台 checkpoint 重放；
- history replay 成功不能自动提升 recipe_release 信任等级。

**Artifact Contract**

- DOM/AX/screenshot/trace 与 `run_id/step_no/source_id/fetch_variant_key` 强关联；
- action params、HAR headers、Storage State 经过脱敏；
- Agent extracted/final content 不绕过 Raw Artifact pipeline；
- Recipe 获取的最终 HTML/PDF 仍生成正常 Raw Artifact 并走现有质量门禁。

### 24.4 Canary

Runtime/Cleaner/Extractor/Renderer/Recipe 升级：

```text
fixture
-> shadow run
-> 1% Source canary
-> quality/freshness/cost/validator integrity/security diff
-> 扩大灰度
-> 全量
```

Browser Use/model/prompt/tool policy 升级只影响 Agentic Repair Runtime，不应自动改变已发布 Production Recipe；若升级后重新生成 Candidate，仍需完整 Promotion Gate。

## 27. 最终推荐架构

最终采用：

> **PostgreSQL Truth Store + S3/MinIO Immutable Artifact + Redis Streams Durable Transport + Declarative Source/Profile + Multi-Provider Discovery + Persistent Frontier + Revalidation Engine + Validator-to-Artifact Binding + Fetch Variant Isolation + HTTP First / Deterministic Browser Slow Lane + Crawl4AI Runtime Service Plane + 可选 Hermetic Agentic Browser Repair / Recipe Studio + Selector Compiler + Recipe Compiler + Deterministic Recipe Promotion Gate + Cache Policy Compiler + Runtime Contract Release Gate + Extraction Portfolio + Canonical IR + Deterministic Markdown + OpenSearch/pgvector + Web Admin。**

最关键的边界是：

- **Provider 返回不是 Coverage 真相；**
- **Runtime cache 不是 Freshness、Version 或 Replay 真相；**
- **同一个 URL 不代表同一个表示，Runtime cache 不能跨 fetch variant 盲目复用；**
- **Runtime 已缓存的 Markdown/Extracted Content 不是 canonical，处理 Release 变化必须从平台 Raw Artifact 重放；**
- **Smart Cache 的 head fingerprint 是弱证据，不能证明正文未变化；**
- **Runtime weak match 得到的新 validator 不能绑定到旧正文；业务 validator 必须绑定 Raw Artifact/body hash；**
- **只有使用 bound validator 得到的 304 才能作为强 unchanged 证据；**
- **`hit_fallback` 是可用性降级，不是 freshness proof；**
- **`READ_ONLY` 不是离线安全边界；**
- **CacheMode、legacy flags、BYPASS 等生产语义以 pinned release + Contract Test 为准，不以名称或单页文档为准；**
- **生产 Runtime 配置必须显式编译和审计，不能依赖默认值；**
- **Raw Artifact 不可变，所有清洗/抽取/Markdown 都可重放；**
- **Browser 是昂贵慢路径，不是默认路径；**
- **LLM/Agentic Browser 只能提出诊断、Observation 或 Recipe Candidate；未经 Selector/Recipe Compiler、确定性 Replay、Shadow、Canary、审批，不得进入生产 Recipe，更不得推进 Coverage/Freshness/Version；**
- **Browser Use highlight index/CDP node identity 只是当前观测内的临时标识，Production Recipe 只能引用经过多样本稳定性验证的 SelectorBundle；**
- **Browser Use history replay 是启发式诊断能力，不是确定性 Recipe Replay，也不是 Task/Attempt Recovery；**
- **任何 DOM/URL/target 变更动作后都重新采样页面状态，Agent multi-action 不是事务边界；**
- **网页内容是不可信 prompt 输入，不能扩大 Tool、Domain、Secret、JS/CDP/File 等 Capability；**
- **Agentic Browser 的通用库默认值不是安全边界，必须显式执行 Tool allowlist、Source Scope、IP/私网阻断、容器 egress、临时 profile 和最小 Browser Permission；**
- **Agent extracted/final text 不是文章正文真相；canonical Markdown 必须来自权威 Raw Artifact 的确定性处理流水线；**
- **Coverage、Version、Freshness、Validator Binding、Markdown 的最终真相始终在平台层。**
