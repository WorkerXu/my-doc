# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站与公开 Newsletter** 的长期采集与知识库平台，并能继续扩展到数千站点、百万至千万级文章。

系统必须同时满足：

1. **全历史回填**：尽可能完整发现每个已批准 Source 的历史文章，并能解释各发现通道的覆盖范围、已知缺口、截断原因与停止原因；
2. **持续增量同步**：稳定发现新文章、正文更新、URL 迁移、重定向、删除、重发布与元数据变化；
3. **稳定 Markdown**：保存不可变 Raw Artifact，经版本化清洗、多路 Candidate、结构质量门禁、Canonical IR 与确定性 Renderer 生成可重放 Markdown；
4. **技术结构保真**：代码块、表格、公式、Mermaid、引用、图片说明、脚注和列表不能被通用降噪算法静默删除；
5. **多语言安全**：中文、日文及中英混排不能因为英文空格分词假设被误判为低质量内容；
6. **低成本扩站**：新增网站优先通过 Source Profile、Provider、Extraction Recipe、Traversal Policy 配置完成，不维护 1000 份站点脚本；
7. **Web 可运营**：支持站点接入、审批、Backfill、Incremental、Coverage、Frontier、质量、成本、诊断、暂停、恢复、重跑、灰度与审计；
8. **任务可恢复**：Provider Run、Task、Attempt、URL、Artifact、Candidate、Document、Version 全链路可追踪，Worker/Runtime 崩溃后自动恢复；
9. **可搜索/RAG**：支持 BM25、向量与混合检索，并能回溯原文、版本、Source、抓取证据和全部 Release；
10. **主链不依赖 LLM**：LLM 只做可选 Repair/Enrichment，不参与历史完整性、URL 身份、robots、正文存在性和版本真相的最终判定。

### 1.1 核心 SLO

- **Coverage**：每个 Source 可查看 Provider Inventory、Completion Attestation、Known Gap、Backfill Stop Reason；
- **Freshness**：新文章从发布/发现到 PASS Markdown 的 P50/P95/P99 延迟；
- **TTFM**：URL 首次发现到首个可用 Markdown 的时间；
- **Extraction Quality**：标题、正文、代码、表格、列表、链接、图片说明、公式等结构召回率与噪声率；
- **Protected Structure Recall**：被 Source Policy 标记为受保护的技术节点在 Candidate/IR 中的保留率；
- **Multilingual Retention**：CJK 与混合语言页面正文保留率；
- **Reliability**：Task 成功率、Retry、DLQ、Queue Age、Lease Recovery；
- **Replayability**：相同 Raw Artifact + 相同 Release 可重放 Cleaner/Candidate/IR/Markdown；
- **Provider Integrity**：部分返回、缓存命中、预算耗尽不能被误报为“已完整枚举”；
- **Artifact Durability**：必须保留的 Runtime/Provider Artifact 在 TTL 到期前晋升平台对象存储；
- **Browser Efficiency**：HTTP 命中率、Browser Avoided、Pool Reuse、Browser 单文档成本；
- **Fairness**：大型 Backfill 不得长期饿死 Incremental、小站、Repair 与 Reconcile。

### 1.2 非目标

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不默认使用个人持久 Browser Profile 或模拟真人操作绕过限制；
- 不把 HTTP 200、Runtime `success=true`、DOM 很长直接视为有效文章；
- 不把 Common Crawl、Wayback、搜索结果、Deep Crawl、URL Seeder 返回条数单独视为历史完整性证明；
- 不把 Crawl4AI `raw_markdown` / `fit_markdown`、LLM 摘要或任一第三方抽取结果直接作为 Canonical Markdown；
- 不把 `fit_html` 当成原始 DOM 快照；
- 不把 Redis、Runtime Queue、Seeder Cache、Browser Session、Visited Set、Search Index 当业务真相；
- 不允许普通 Web/API 用户透传任意 JS/Python、代理、CDP、服务器路径、原生高能力 Seeder 配置、secret 或任意 webhook URL。

## 2. 核心设计原则

1. **Coverage First**：先建立可解释 URL Inventory，再抓正文；
2. **Authoritative First**：官方 CMS/API、Sitemap、Feed、Archive 优先；
3. **Observation Before Selection**：发现事实先保存，再 Normalize/Scope/Classify/Dedup；
4. **Successful Return != Provider Complete**：正常返回、非空结果、cache hit、`status=valid` 都不能自动代表 Provider 完成；
5. **Completion Must Be Attested**：只有具备可验证结束语义的 Provider Adapter 才能声明完成；
6. **Discovery / Fetch / Clean / Extract / Quality / Canonicalize / Projection 分离**；
7. **HTTP First, Browser Slow Lane**；
8. **Snapshot First**：先保存不可变 Provider Evidence / Raw Artifact；
9. **Candidate Portfolio, Not Single Extractor**：多个确定性候选互相校验；
10. **Protected Structures Are First-Class**：代码、表格、公式等先识别、再验证召回，不信任单一 preserve 参数；
11. **Language Assumptions Must Be Explicit**：任何 word/token threshold 都必须声明适用语言；
12. **Canonical IR First, Markdown as Projection**；
13. **Recipe, Not 1000 Site Scripts**；
14. **Persistent Frontier, Not In-Memory Traversal**；
15. **Idempotent + Recoverable**：幂等键、Lease、Fencing Token、Checkpoint、Inbox/Outbox；
16. **Fair by Default**：Incremental、Provider Revalidate、Repair 必须预留容量；
17. **Bounded Concurrency Everywhere**：任务数、在途请求、结果集合、Browser 和进程生命周期均有硬边界；
18. **No Silent Degradation**：过滤、截断、预算耗尽、partial result、cache fallback、降级必须有 typed reason；
19. **Correlate by Identity, Never by Position**；
20. **Config Is Capability**：高能力配置统一经过 Capability Firewall；
21. **Runtime Is Execution Plane**：第三方 Runtime 不拥有 Coverage、Identity、Document 或 Markdown 真相；
22. **Behavior Beats Naming**：生产语义以 pinned release + Contract Test 为准，不以参数名或文档描述推断；
23. **Runtime Artifact Is Ephemeral Until Promoted**；
24. **Result Transport Is Not State Store**；
25. **Drain/Replace Before In-Place Kill**；
26. **Zero Must Not Mean Unbounded by Accident**；
27. **External Historical Index Is Evidence**：Common Crawl、Wayback 可显著补洞，但单独不能证明全历史完整；
28. **Derived Artifact Never Overwrites Evidence**：Cleaned HTML、Candidate、IR、Markdown 全部是可重放派生物。

## 4. 技术选型与 Release 模型

### 4.1 控制面

- **FastAPI + Pydantic**：REST API、Command、Webhook Inbox、配置编译；
- **PostgreSQL**：Truth Store、Task、Frontier、Coverage、Version、Audit、Provider Checkpoint；
- **Redis Streams**：Durable Task Transport；
- **Redis Lua Token Bucket/Semaphore**：host/domain/source/browser 全局限流与并发控制；
- **React/Next.js + TypeScript**：Web 管理后台；
- **S3/MinIO**：不可变对象存储；
- **OpenTelemetry + Prometheus + Grafana + Structured Logging**；
- **Vault/KMS/Secret Manager**：secret 引用；
- **Nginx/Envoy/API Gateway**：TLS、请求体上限、Rate Limit、Correlation ID。

### 4.2 Discovery / Fetch

- **httpx/aiohttp**：CMS API、robots、Sitemap、Feed、Conditional GET、普通网页；
- **RFC 9309 Robots Engine**；
- **平台原生 SitemapProvider**：显式 sitemap URL、robots sitemap、Conditional GET、Sitemap Index durable shard；
- **平台原生 CommonCrawlIndexProvider**：固定 `cc_index_id`、流式查询、Evidence 与 Checkpoint；
- **Crawl4AI AsyncUrlSeeder pinned release**：best-effort Sitemap/CC bulk discovery、metadata probe；
- **Crawl4AI pinned release/image digest**：JS Render、复杂页面、Deep/Adaptive gap discovery、自托管 Browser Runtime、Markdown Candidate；
- **Playwright**：必要时作为受控慢路径；
- **Wayback Adapter**：历史补洞证据；
- **PyMuPDF/pdftotext**：PDF，扫描件再进入受控 OCR 慢路径。

### 4.3 Extraction / Search

- **Trafilatura**：Generic Candidate；
- **lxml/BeautifulSoup**：DOM/XPath、Metadata、Repair、Protected Structure Fingerprint；
- **JSON-LD/OpenGraph/Microdata**；
- **CSS/XPath/Regex Recipe**；
- **Crawl4AI DefaultMarkdownGenerator + PruningContentFilter**：Markdown Candidate，不直接作为 canonical；
- **Crawl4AI BM25ContentFilter**：诊断/query projection，默认不参与全量正文 canonical winner；
- **SimHash/MinHash**：近重复检测；
- **OpenSearch BM25 + pgvector + RRF**；
- embedding/reranker/LLM 仅作可选增强。

## 5. Source 接入与配置模型

新增站点使用声明式 Source Profile：

```yaml
source:
  name: example-tech-blog
  entry_url: https://example.com/blog/
  approved_hosts: [example.com]
  allowed_paths: [/blog/]
  denied_paths: [/login/, /account/]
  timezone: UTC
  language: auto

providers:
  - type: sitemap
    url: https://example.com/sitemap.xml
    conditional_get: true
  - type: rss
    url: https://example.com/feed.xml
  - type: archive
    start_url: https://example.com/blog/archive/
  - type: common_crawl_index
    purpose: historical_gap
  - type: crawl4ai_url_seeder
    purpose: discovery_acceleration
    modes: [sitemap, cc]

fetch:
  mode: auto
  http_timeout_s: 20
  max_response_bytes: 15000000
  browser_profile_class: public-default
  browser_intent:
    render_js: true
    scroll: bounded
    wait_selector: article

extract:
  recipe: generic_article_v4
  content_selectors: ["article", ".post-content"]
  exclude_selectors: ["nav", "footer", ".related"]
  protected_structures:
    tags: [pre, code, table, blockquote, figure, figcaption]
    classes: [highlight, codehilite, mermaid, math, katex, admonition]
    policy: ancestor_chain
  language_policy:
    mode: auto
    cjk_safe: true
  markdown_candidate:
    pruning:
      threshold_type: dynamic
      threshold: 0.48
      min_word_threshold: null
      preserve_tags: [pre, code, table, blockquote]
      preserve_classes: [highlight, codehilite, mermaid, math]
    platform_guardrails:
      unicode_length_gate: true
      validate_protected_recall: true

incremental:
  feed_poll: 10m
  sitemap_poll: 1h
  archive_reconcile: 1d
  full_reconcile: 7d
```

其中 `protected_structures`、`language_policy`、`platform_guardrails` 是平台 Intent，不要求第三方 Runtime 原生支持同名字段。Config Compiler 根据 pinned Runtime 能力编译成实际参数和平台侧验证逻辑。

### 5.1 Capability Firewall

Web/API 用户只提交 intent，禁止透传：

- 任意 `js_code` / Python；
- 任意 proxy / CDP / `user_data_dir`；
- 任意 cookies、secret、服务器 path；
- 任意 LLM base URL / webhook destination；
- 未审批的 Seeder/Common Crawl query；
- 无硬上限的 `concurrency` / queue / time / result budget；
- `0=unbounded` 的配置；
- 不受控 deep crawl strategy；
- 任意网络目标与本地文件协议；
- 无限制 selector/regex 数量或复杂度。

Config Compiler 将 Source Intent 编译为 Provider/Runtime Config，并记录最终能力、硬预算、effective options 与拒绝原因。

### 5.2 Browser Profile Class

平台只维护少量受审 Browser Profile：

```text
public-default
public-js-heavy
public-media-light
isolated-authenticated
```

站点 selector/wait/scroll 优先放低成本 CrawlerRunConfig/Recipe。只有改变浏览器进程能力、网络边界或 credential scope 才新建 Browser Profile Release。

### 5.3 Effective Configuration

第三方组件经常存在 constructor option、per-call option、默认值之间的优先级。平台必须保存 **最终生效配置**，不能只保存用户 override：

```text
effective_config_json
effective_config_hash
compiler_release_id
runtime_release_id
```

Candidate 重放以 effective config 为输入，避免升级时发生隐性参数漂移。

## 7. 历史 URL 发现与 Coverage

### 7.1 Provider 优先级

优先使用能明确分页/结束语义的 Provider：

1. CMS/官方内容 API；
2. Native Sitemap / Sitemap Index；
3. RSS/Atom；
4. 官方 Archive / Category / Pagination；
5. Native CommonCrawlIndex；
6. Wayback Gap Provider；
7. Crawl4AI URL Seeder；
8. Domain Mapping / Deep Crawling / Adaptive Crawling 作为 gap discovery。

后四类可补洞，但不能单独声明 Source 全历史完整。

### 7.2 Completion Attestation

Provider Run 只有满足 Adapter 定义的终止契约才允许 `completion_attested=true`。

典型终止原因：

```text
EXHAUSTED_CURSOR
EXHAUSTED_PAGE_RANGE
SITEMAP_INDEX_COMPLETE
ARCHIVE_END_REACHED
EMPTY_PAGE_CONFIRMED
BUDGET_EXHAUSTED
TIME_LIMIT
RATE_LIMIT_ABORT
ROBOTS_BLOCKED
PARTIAL_PROVIDER_RESULT
REMOTE_ERROR
MANUAL_STOP
```

只有可证明完成的终止原因计入 completion；预算、时间、限流和异常必须成为 Known Gap。

### 7.3 Provider Evidence

每个 Provider Run 保存：

- 请求参数、Adapter Release、Effective Config；
- 响应摘要或不可变原始 Evidence；
- cursor/page/checkpoint；
- 返回条数；
- 过滤前后条数；
- terminal reason；
- truncation/partial 标记；
- 时间范围与 URL 范围；
- cache 命中及 cache freshness。

Coverage 页面展示 Provider 交集/差集，不能只给一个“已完成”绿灯。

### 7.4 Backfill 完成判定

```text
COMPLETE:
  authoritative providers exhausted
  + required reconciliation finished
  + no unresolved critical gaps

COMPLETE_WITH_GAPS:
  providers exhausted where possible
  + gaps explicitly typed and accepted
```

永远不使用“连续 N 页没有新 URL”作为唯一完整性证明；它最多是 heuristic stop，必须显示原因。

## 8. URL Normalize、Scope 与去重

处理顺序固定：

```text
Observed URL
 -> parse/validate
 -> absolute URL
 -> scheme/host normalization
 -> remove fragment
 -> tracking parameter policy
 -> path normalization
 -> Source Scope Gate
 -> canonical/redirect evidence
 -> URL Identity
```

规则必须 Release 化，避免升级 URL 归一化后静默合并或拆分历史身份。

### 8.1 去重层级

- URL exact identity；
- redirect/canonical cluster；
- content hash exact duplicate；
- SimHash/MinHash near duplicate；
- semantic duplicate 只作为辅助，不替代 URL/Raw 证据。

### 8.2 迁移与重发布

若 A URL 301 到 B，或页面 canonical 指向 B：

- 保留 A 作为 alias；
- B 进入 canonical cluster；
- 不删除历史 Artifact；
- Document 是否合并由 identity policy + content evidence 决定。

## 9. 增量同步

### 9.1 信号源

```text
RSS/Atom            5-15 分钟
Sitemap             30-120 分钟
CMS API             5-30 分钟
Archive Reconcile   每日
Full Reconcile      每周/每月
Webhook             可选，仅作提示
```

Webhook 不能成为唯一真相；Reconciler 最终根据 PostgreSQL + Object Storage 证据闭合。

### 9.2 Conditional GET

HTTP Fast Lane 保存并复用：

```text
ETag -> If-None-Match
Last-Modified -> If-Modified-Since
```

304 只说明该 URL 此次未返回新实体，不代表 Source 没有新文章。

### 9.3 变化判定使用四层哈希

```text
raw_content_hash       # 网络取得的规范化原始内容
extraction_hash        # 某 cleaner/extractor/filter release 的候选
semantic_ir_hash       # Canonical IR 的语义结构
projection_hash        # 某 Renderer 的 Markdown 输出
```

规则：

1. Raw 不变：通常无需重新抽取，除非新 Release 触发 Reprocess；
2. Raw 变、semantic IR 不变：记录抓取变化但不创建知识文档语义版本；
3. semantic IR 变：创建新 Document Version；
4. 只有 projection_hash 变：属于 Renderer 投影变化，不冒充原文更新。

### 9.4 删除判定

单次 404/5xx 不直接判删除。状态机：

```text
ACTIVE
 -> SUSPECT_MISSING
 -> RECHECKING
 -> GONE_CONFIRMED
```

结合多次时间间隔重试、Sitemap/Feed 消失、明确 404/410、redirect/canonical 证据后再确认。

## 10. Persistent Frontier、任务模型与公平调度

### 10.1 Task 不等于 Queue Message

PostgreSQL Task/Frontier 是业务状态；Redis Streams 只是运输。

```text
task
- id
- type
- identity_key
- priority_class
- state
- not_before
- lease_until
- fencing_token
- max_attempts
- payload_ref
```

幂等键示例：

```text
DISCOVER:{source_id}:{provider_release}:{shard}
FETCH:{url_identity_id}:{fetch_policy_release}:{desired_revision}
CLEAN:{raw_artifact_id}:{cleaner_release}
EXTRACT:{cleaned_artifact_id}:{candidate_release_tuple}
CANONICALIZE:{raw_artifact_id}:{quality_ir_release_tuple}
PROJECT:{document_version_id}:{projection_release}
```

### 10.2 Lease + Fencing Token

Worker claim 时事务性增加 `fencing_token`。任何晚到结果提交都必须携带 token；小于数据库当前 token 的结果拒绝，解决旧 Worker 超时后又回来写入的竞态。

### 10.3 公平队列

至少区分：

```text
P0 incremental
P1 provider_revalidate
P2 repair
P3 new_source_backfill
P4 deep_gap_discovery
P5 bulk_reprocess
```

使用 weighted fair queue / deficit round robin，并设置每个优先级最低保障，避免百万 URL Backfill 挤死增量同步。

### 10.4 全局 Admission

并发控制至少覆盖：

- 全平台；
- Source；
- eTLD+1/domain；
- host；
- browser profile；
- runtime instance；
- task type；
- object-store write；
- extraction CPU/memory。

本地 dispatcher 的 memory-adaptive concurrency 只能作为实例内二级保护，不能取代跨 Worker 的全局预算。

## 11. Fetch Plane：HTTP First + Browser Slow Lane

### 11.1 HTTP Fast Lane

默认使用 httpx/aiohttp：

- robots；
- HEAD/GET；
- redirects；
- MIME；
- Conditional GET；
- gzip/br；
- response byte limit；
- connect/read/total timeout；
- retry-after；
- charset detection。

多数静态技术博客不应启动浏览器。

### 11.2 Browser Escalation Gate

只有满足受控理由才进入 Browser：

```text
JS_REQUIRED
EMPTY_STATIC_BODY
CLIENT_RENDERED_CONTENT
INTERACTION_REQUIRED_BOUNDED
STATIC_EXTRACTION_LOW_QUALITY
```

禁止“HTTP 一失败就 Browser”。DNS、TLS、robots、明确 404、超大文件、scope 拒绝等不应靠 Browser 修复。

### 11.3 Crawl4AI Runtime Service Plane

```text
Runtime Gateway
 -> Config Compiler
 -> bounded micro-batch
 -> local dispatcher
 -> browser pool
 -> result materializer
 -> artifact promotion gate
```

平台通过 `runtime_request_id` / `task_id` / `url_identity_id` 关联结果，绝不按批次返回位置匹配。

### 11.4 Browser 生命周期

- 复用 browser process/context 降低启动成本；
- auth scope 必须隔离；
- 达到页面数、内存、时间阈值后 drain/replace；
- 不在有在途任务时直接 kill；
- browser crash 只影响 Attempt，不改变业务真相；
- Runtime 本地 cache/queue 不用于恢复 Coverage。

## 12. Runtime Artifact Promotion Gate

Runtime screenshot/PDF/HTML snapshot 等只持有 server-owned opaque artifact ID，并有 TTL/quota，不能直接成为永久知识库引用。

```text

- runtime_id
- runtime_task_id
- attempt_id
- runtime_artifact_id
- required
- declared_mime
- declared_size
- discovered_at
- fetch_started_at
- durable_artifact_id
- sha256
- status
- error_class
```

状态：

```text

                    -> MISSING_EXPIRED
```

晋升：


## 14. Raw Artifact、Cleaned Artifact 与可重放管线

### 14.1 Raw Artifact 不可变

任何解析前先保存原始网络响应：

```text
raw/{source}/{url_identity}/{timestamp}/{sha256}.html
```

Manifest 至少记录：headers、status、final URL、fetch release、bytes、hash、timing、runtime/browser 信息。

Raw 一旦写入不原地覆盖；重新抓取得到新 Artifact。

### 14.2 Cleaned HTML 是派生物

Cleaned HTML 由 `cleaner_release` 产生，可从 Raw 重放，不覆盖 Raw。

清洗可以包括：

- script/style/noscript 等无正文节点；
- 明确站点噪声 selector；
- 安全属性标准化；
- 相对 URL absolute 化；
- DOM 修复；
- 保留代码、表格、公式、图片说明等技术结构。

### 14.3 Protected Structure Fingerprint

在有损过滤前，对 Cleaned DOM 识别受保护结构：

```text
pre/code
table
blockquote
figure/figcaption
mermaid
math/katex/mathjax
admonition/callout
source-specific technical blocks
```

为每个节点保存：

```text
node_fingerprint
node_type
text_hash
normalized_dom_path
ancestor_fingerprint_chain
ordinal
content_length
```

该 Manifest 是之后判断“过滤器是否误删技术结构”的基线。

## 16. Crawl4AI Markdown Candidate 设计

### 16.1 raw / fit / references 是相关证据

Crawl4AI `DefaultMarkdownGenerator` 可以产出：

```text
raw_markdown
markdown_with_citations
references_markdown
fit_markdown
fit_html
```

平台把它们视为同一个 `MarkdownCandidateManifest` 的相关 Evidence：

- raw：高召回候选；
- fit：降噪候选；
- fit_html：过滤后结构证据；
- references：链接 provenance 辅助。

### 16.2 `fit_html` 明确标记为 synthetic

Content Filter 返回若干 block 后，生成链路会把这些 block 重新包装并拼接成 fit HTML。因此 `fit_html` 不是原 DOM 的原样连续子树。

平台保存：

```text
fit_html_is_synthetic = true
filter_block_manifest_uri
ordered_filter_block_hashes
source_dom_artifact_id
```

若需要追踪原 DOM 位置，应使用预先记录的 DOM path/fingerprint，不能从 fit HTML 猜测。

### 16.3 HTML→Markdown Effective Options

平台 Config Compiler 必须解析第三方 options 的真实优先级，生成完整 effective options，再对它做 hash。

不允许只记录部分 override，因为 constructor/per-call/default 的覆盖关系可能导致实际行为与操作人员预期不同。

### 16.4 PruningContentFilter 的生产定位

Pruning 本质是 DOM 子树启发式评分，综合：

```text
text density
link density
semantic tag weight
class/id signal
text length
```

当前默认权重近似：

```text
text_density   0.4
link_density   0.2
tag_weight     0.2
class/id       0.1
text_length    0.1
```

它适合大规模通用降噪，但不是正文完整性证明。

### 16.5 Native preserve 不能当绝对保护

第三方 `preserve_tags/classes` 对当前节点有效，但递归过程中如果未受保护的祖先先被整体剪除，后代受保护节点仍可能消失。

所以平台必须实现 **ancestor-aware Protected Structure Policy**：

```text
预标记技术节点
 -> 保存 ancestor chain
 -> native pruning / third-party candidate
 -> 对比 protected node recall
 -> 缺失则 FAIL/WARN
 -> 必要时通过独立技术块抽取或自定义 filter 修复
```

不能仅靠 `preserve_tags=[pre,code,table]` 宣称代码/表格绝不会丢。

### 16.6 `min_word_threshold` 的多语言边界

当前实现的词数判定依赖空格近似计数，对中文、日文等 CJK 文本不可靠。

生产规则：

- 全局 Profile 默认 `min_word_threshold=null`；
- CJK/未知语言禁止启用未经验证的空格计词门槛；
- 需要长度门禁时用平台 Unicode-aware char/token/grapheme 策略；
- tokenizer policy Release 化；
- 中文、日文、中英混排必须纳入回归集。

### 16.7 class/id 负向信号不能被过度依赖

第三方源码中 class/id 的负向模式与最终 composite score 的实际组合可能和参数命名直觉不同。平台不把 `sidebar/ads/...` class 命中等同于必然强扣分。

真正的生产降噪由：

- explicit exclude selector；
- Site Recipe；
- boilerplate fingerprint；
- link/text metrics；
- 多 Candidate 交叉验证；
- Contract Test；

共同完成。

### 16.8 BM25ContentFilter 的定位

BM25 是 query-conditioned relevance filter，适合：

- 搜索结果预览；
- query-time context reduction；
- 抓取诊断；
- 辅助 Candidate 对比。

默认不用于“全量正文 canonical”，原因包括：

- 标题/query 不能覆盖所有技术章节；
- whitespace tokenization 对 CJK 不可靠；
- 完全相同 chunk 的去重可能删除有意重复代码/提示；
- relevance chunk 不等价于 Canonical IR 的结构 block。

### 16.9 LLM Filter

只进入 REPAIR/REVIEW 慢路径，保存 model/prompt release、token usage、输入输出 hash 和 finish/error reason。主链不依赖 LLM。

## 17. Candidate Quality Gate

质量评估不能只看总字数，至少计算：

```text

repeated_block_retention
main_text_ratio
noise_ratio
duplicate_block_ratio

```

### 17.1 多候选交叉验证

示例规则：

- raw Markdown 有 12 个 code fence，fit 只有 3 个 -> `STRUCTURE_LOSS_CODE`；
- Site Recipe 与 Trafilatura 都有 5 个表格，fit 为 0 -> `STRUCTURE_LOSS_TABLE`；
- 受保护 `<pre>` 位于低密度祖先内且在 fit 消失 -> `PROTECTED_DESCENDANT_LOSS`；
- 中文正文数千字符但过滤后只剩标题 -> `CJK_WORD_GATE_LOSS`；
- 重复代码块在 raw/Recipe 出现 2 次、BM25 fit 只剩 1 次 -> `REPEATED_BLOCK_LOSS`；
- fit 比 raw 少 70% 文本，但标题、主段落和技术结构覆盖高 -> 可能是有效降噪；
- 所有确定性候选正文过短 -> Browser Repair 或人工 Review；
- metadata 冲突 -> 保存各来源 provenance，按 policy 选择。

### 17.2 Candidate 状态

## 18. Canonical IR 与确定性 Markdown Renderer

### 18.1 Canonical IR

最终真相不是第三方 Markdown 字符串，而是结构化 IR：

```text
DocumentIR
- document_id
- version_id
- source_id
- canonical_url
- title
- authors[]
- published_at
- updated_at
- language
- tags[]
- sections[]
  - heading
  - level
  - blocks[]
    - paragraph
    - code(language, text)
    - list(ordered, items)
    - table(headers, rows)
    - quote
    - image(src, alt, caption)
    - math
    - mermaid
    - link
- references[]
- provenance[]
```

每个关键字段可保存 provenance：来自 JSON-LD、OpenGraph、DOM、Trafilatura、Crawl4AI Candidate 或人工修正。

### 18.2 Markdown Renderer

Renderer 只负责 IR -> Markdown：

- 稳定 front matter；
- 稳定标题层级；
- fenced code + language；
- GFM table；
- 统一链接/图片；
- 确定性 references 编号；
- 不按固定列宽换行；
- 统一空行；
- UTF-8；
- 文件名冲突转义与长度限制。

因此更换 Markdown 语法或 references 风格无需重新抓网页。

### 18.3 推荐 Front Matter

```yaml
---
document_id: doc_xxx
version_id: ver_xxx
source: example-tech-blog
url: https://example.com/blog/a
canonical_url: https://example.com/blog/a
published_at: 2026-08-01T10:00:00Z
updated_at: 2026-08-03T10:00:00Z
fetched_at: 2026-08-16T00:00:00Z
language: zh
raw_artifact_sha256: ...
semantic_ir_hash: ...
---
```

不把内部 secret、cookie、proxy、个人标识写入知识库文件。

## 19. Reprocess：调参不重新下载

只要 Raw Artifact 尚在，升级以下 Release 都应优先创建 Reprocess Task：

```text

markdown_candidate_release
content_filter_release
extractor_release
quality_policy_release

```

流程：

```text

```

## 20. Document Identity、Version 与删除

### 20.1 Document Identity

综合：

- source_id；
- normalized URL；
- canonical/redirect relation；
- CMS post id；
- published_at/title；
- content fingerprint。

避免只靠 URL 或标题。

### 20.2 Version

Document Version 以 `semantic_ir_hash` 控制语义版本。

Raw 变化不一定等于文章语义更新；Renderer 变化也不能冒充原文更新。

### 20.3 Tombstone

单次 404/410/缺失不立即删除知识库内容。

建议：

- 多次重复确认；
- Provider inventory 同时消失；
- redirect/canonical 迁移检查；
- 标记 `TOMBSTONE_CANDIDATE`；
- 达阈值后 `TOMBSTONED`；
- 历史 Version 永久保留。

## 21. Search / RAG Projection

从 Canonical IR/Document Version 构建，可随时重建：

- OpenSearch BM25；
- pgvector embedding；
- RRF 混合；
- optional reranker；
- chunk 保留 `document_id/version_id/section_path/source/url`；
- code/table 可单独 chunk；
- references 与链接图作为附加特征。

### 21.1 Chunk 原则

- 先按 IR section/blocks 切分，不从 Markdown 任意字符位置截断；
- code block 不切碎；
- table 尽量完整；
- heading path 附加到 chunk；
- CJK 使用合适 analyzer/tokenizer；
- chunker_release 版本化；
- embedding 失败不影响 canonical 文档有效性。

### 21.2 Serving Index 不是业务真相

- Index 损坏可从 Document Version 全量重建；
- 文档删除/隐藏由业务状态驱动 tombstone；
- 不从“向量库里有没有”反推业务存在性。

## 26. 故障恢复与 Reconciler

### 26.1 Worker Crash

- Lease 到期；
- Scheduler 重新 claim；
- Fencing Token 拒绝旧结果；
- 幂等键避免重复业务写。

### 26.2 Redis 丢失

从 PostgreSQL `READY/RUNNING-but-expired` 状态重新发布运输消息。

### 26.3 Runtime Crash

Attempt 失败；已晋升 Raw 不丢；未晋升临时 Artifact 可重新执行。

### 26.4 Object Storage 暂时失败

没有完成 Artifact Promotion 前，Task 不得进入最终 SUCCESS。

### 26.5 Reconciler

周期检查：

- expired leases；
- Task 与 Outbox 不一致；
- DB manifest 指向缺失对象；
- 已上传对象但 DB 未提交的 orphan；
- Document current_version 指针；
- Search projection lag；
- Provider Run 无 terminal reason；
- `completion_attested=true` 但缺 Evidence；
- Candidate PASS 但缺 artifact；
- Canonical Version 引用非 PASS Candidate；
- Protected Structure Manifest 与 quality evaluation 缺失。

## 27. Backpressure 与容量规划

### 27.1 有界流水线

```text
Discovery -> URL Inventory -> Fetch -> Raw -> Clean -> Candidate -> Canonical -> Projection
```

每层都有：

- max ready；
- max inflight；
- per-source quota；
- per-host quota；
- retry budget；
- age alert。

Discovery 不能无限把 URL 推给 Fetch。超过水位后降低 Backfill/Deep Gap 速率，优先保持 Incremental freshness。

### 27.2 粗略容量估算

示例：1000 个站点，每站历史 3000 篇，约 300 万 URL。

若平均 HTML 500 KB：

```text
Raw ≈ 1.5 TB 未压缩
```

对象存储压缩、生命周期分层可以降低热存储压力。Candidate 与 Markdown 通常远小于 Raw。

实际容量必须测：

- p50/p95 response bytes；
- HTTP 页面比例；
- Browser 页面比例；
- extraction CPU/memory；
- object-store write throughput；
- index/embedding throughput；
- Candidate Portfolio 放大系数；
- Reprocess 峰值吞吐。

不要用 Browser 节点数量直接推算总抓取吞吐。

```text
                                      |        |
```

```text
                  -> FAILED
```

```text
             |   |   |
```

```text
   +---------------+-------------+

```

## 32. 验收标准

一个 Source 上线前至少通过：

1. Scope/SSRF/robots 验证；
2. 至少一个 authoritative discovery provider；
3. Provider terminal semantics 已定义；
4. HTTP 与 Browser escalation 行为可解释；
5. Raw Artifact 可回放；
6. 确定性 Extraction Candidate 至少两路或有明确站点 Recipe；
7. code/table/list/math 等结构质量门禁通过；
8. Protected Structure Recall 达标；
9. CJK/站点主语言 retention 达标；
10. Canonical IR 与 Markdown 可重放；
11. Incremental 信号和 full reconcile 已配置；
12. Backfill/Incremental 同时运行时无 starvation；
13. Web 可查看 Coverage、任务、Artifact、Candidate、Quality、Version；
14. Release 升级可在历史 Raw 上回归、灰度和回滚；
15. 第三方 Runtime 关键语义有 Contract Test 锁定。

平台级验收：

- 任意 Worker/Redis/Runtime 单点故障不造成业务真相丢失；
- 任意第三方 Runtime 升级不绕过 Release/Regression；
- 任意过滤器/Tokenizer 参数变化不要求重新下载 Raw；
- Search Index 全损可从 Document Version 重建；
- 对 1000+ Source 的大 Backfill 不影响 Incremental Freshness SLO；
- 不允许因为空格计词假设批量删除 CJK 正文；
- 不允许因为局部 preserve 语义静默丢失受保护代码/表格而仍判 Candidate PASS。

## 33. 最终推荐架构

```text
Authoritative Discovery + Gap Discovery
                |
       Provider Evidence / Coverage
                |
      Persistent URL Inventory
                |
     Fair Frontier + Admission
                |
     HTTP First / Browser Slow Lane
                |
        Immutable Raw Artifact
                |
        Versioned Cleaned HTML
                |
 Protected Structure + Language Baseline
                |
        Extraction Portfolio
  Recipe / Trafilatura / Crawl4AI raw+fit
                |
 Structure + Language Candidate Quality
                |
           Canonical IR
                |
       Semantic Document Version
                |
 Deterministic Markdown / Search / RAG
                |
 Web Operations + Replay + Contract Test
       + Regression + Audit
```

这套方案的核心不是“选一个最强爬虫”，而是把 **Coverage、执行、Raw 证据、清洗、抽取候选、技术结构保护、多语言安全、语义版本和最终投影分层**。

Crawl4AI 负责高效执行、JS 页面、URL 发现与 Markdown 候选；PostgreSQL + Object Storage 负责业务真相；Protected Structure/Language Policy 负责防止启发式过滤静默损坏技术内容；Canonical IR 与版本化 Renderer 负责长期稳定的知识库格式。

这样才能在站点数量、历史文章量、网页结构、语言类型和第三方组件版本持续变化时，仍保持可扩展、可恢复、可解释、可重放和可运营。
