# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站、公开 Newsletter** 的长期知识库采集平台，并能够平滑扩展到数千站点、百万级文章。

核心目标：

1. **全历史尽量抓全**：先建立 URL Inventory，再抓正文；覆盖度必须由 Provider、时间范围、游标、穷尽证据和 Known Gap 共同解释。
2. **持续增量同步**：支持新文章发现、正文更新、元数据变化、URL 迁移、删除、重发布和周期复检。
3. **稳定生成 Markdown**：原始抓取事实不可变保存，经抽取、质量校验、Canonical IR 后，由版本化 Renderer 生成 Markdown。
4. **新增站点低成本**：站点差异优先由 Site Family、Source Profile、Discovery Recipe、Route Policy、Extraction/Repair Recipe 表达，避免维护 1000 个独立爬虫。
5. **Web 可管理**：支持 Source 接入、Probe、配置、调度、Coverage、URL Inventory、任务、质量、版本、回放、成本、导出、Enrichment、Evaluation、Agent 建议和审批。
6. **可追溯、可重建**：任何 Markdown、结构化增强、检索结果都能回溯 Source Release、URL、Artifact、Extractor、Quality、Document Version、Renderer/Enrichment/Retrieval Release 和完整执行树。
7. **幂等可恢复**：任务可重试、续跑、Replay，不产生脏重复。
8. **确定性数据面优先**：HTTP、Browser Recipe、正文抽取、版本判定和 Markdown 渲染默认不依赖 LLM。
9. **LLM 只进入低频或可选阶段**：用于 Source Probe、Gap/Quarantine/Drift 诊断、规则建议、Canonical 后 Structured Enrichment，以及可选问答生成。
10. **成本可治理**：Authoritative Discovery、HTTP First、Browser Last；Browser、External Search、LLM、Embedding、Reranker、Graph 分别预算和熔断。
11. **最终知识访问也可验证**：抓对内容不等于用户能检索到正确内容，Search/RAG/Agent 必须有 Golden Query、离线评估、Canary 和回归保护。

### 1.1 核心 SLO

- **Coverage**：Provider coverage、exhaustion evidence、时间跨度、Known Gap；
- **Freshness**：文章发布到进入 PASS/WARN Canonical Markdown 的延迟；
- **Extraction Correctness**：正文完整率、噪声率、结构保留率、Candidate Agreement；
- **Routing Efficiency**：Page Type 分类准确率、HTTP 命中率、Browser avoided 比例；
- **Fallback Efficiency**：Browser/Repair recovery rate、quality delta、p95 latency、cost per recovered document；
- **Reliability**：Task 成功率、Retry/DLQ、Queue Age、Worker 恢复率；
- **Traceability**：任意结果可回溯不可变 Artifact、Release 和执行树；
- **Enrichment Quality**：Schema 成功率、字段证据覆盖率、VALID_EMPTY/ERROR 区分率、实体合并错误率；
- **Retrieval Quality**：Recall@K、MRR、nDCG、metadata filter accuracy、stale-version rate；
- **Answer Quality**：citation coverage、evidence precision、groundedness、正确拒答率；
- **Cost**：按 Source、Run、Queue Class、每 1000 个 PASS 文档统计成本。

### 1.2 非目标

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不把 HTTP 200、Crawler success、DOM 很长直接等同于正文正确；
- 不把搜索引擎结果数量当作历史完整性证明；
- 不把 Crawl4AI Markdown、LLM 摘要或改写直接作为 Canonical Markdown；
- 不让 LLM 改写第三方源正文；
- 不因 URL 曾抓过就永久停止复检；
- 不允许规则、Prompt、模型、Renderer、Schema、Retrieval 配置无版本地改变生产结果；
- 不把 Redis、Browser Session、Agent Memory、CSV、Google Sheets、Slack Bot 当业务真相；
- 不默认为所有文档构建 GraphRAG；
- 不因为昂贵慢路径熔断而把未通过 Quality Gate 的内容静默标记为 PASS；
- 不因为 Retrieval/Agent 返回自然语言答案就省略证据和版本边界。

## 2. 核心设计原则

1. **Coverage First**：先建 URL Inventory，再批量 Fetch。
2. **Authoritative First**：CMS/API、Sitemap、RSS/Atom、Archive 优先。
3. **Search Is Gap Filling**：外部搜索只用于补洞和候选发现，不用于证明完整性。
4. **Discovery Before Fetch**：发现、规范化、分类、抓取、抽取彻底分离。
5. **Cheap Routing Before Expensive Execution**：Provider Hint、URL Rule、MIME、Structured Metadata、DOM Heuristic 优先。
6. **HTTP First, Browser Last**：只有可解释证据证明必要时才升级 Browser。
7. **Snapshot First**：先保存不可变 Artifact，再抽取、清洗和增强。
8. **Fetch != Extract != Quality**：网络成功、抽取成功、质量通过是独立状态。
9. **Extractor Is Candidate Generator**：任何 Extractor 只产生 Candidate。
10. **Critique Before Publish**：Candidate 必须经过独立 Quality Gate。
11. **Repair Is Bounded**：修复是有限状态机，不允许无限循环。
12. **IR First, Markdown as Projection**：Canonical IR 是结构事实，Markdown 可重建。
13. **Enrichment After Canonical**：结构化抽取只能建立在 PASS/WARN Document Version 之上，不能污染原文。
14. **Evidence-bound Structured Data**：结构化字段尽量绑定 Canonical Block/Artifact 证据。
15. **Entity Identity Is Separate**：跨文档实体合并属于知识层，不覆盖文档事实。
16. **Recipe, Not Site Code**：站点差异通过 Profile/Policy/Recipe 表达。
17. **Stable Identity**：Source、URL、Artifact、Document、Version、Entity 使用稳定 ID，不用 URL 文本直接当主键或文件名。
18. **Idempotent + Recoverable**：Task 有幂等键、lease、fencing token、checkpoint、Retry、DLQ。
19. **Fair by Default**：大站 Backfill 不饿死 Incremental 和小站。
20. **Slow Path Isolated**：Browser、External Search、LLM、Agent、Graph 使用独立 Queue/Pool/Budget。
21. **Release Everything That Changes Results**：Profile、Route、Recipe、Runtime、Extractor、Renderer、Schema、Prompt、Model、Chunker、Embedding、Reranker、Fusion、Workflow Contract 全版本化。
22. **No Silent Degradation**：预算耗尽、截断、能力未执行、慢路径熔断必须显式 DEGRADED/QUARANTINE/Known Gap。
23. **Bounded Concurrency Everywhere**：HTTP、Browser Context、批处理、LLM Tool Call 均有边界和背压。
24. **Deterministic Orchestrator Around Agent Pockets**：平台工作流持有状态，Agent 只处理开放式子任务。
25. **One Trace Tree Per Run**：从 Discovery 到 Projection/Enrichment/Evaluation 保持统一 Trace Context。
26. **Evaluate User-facing Knowledge Access**：Retrieval、RAG、Agent 变更必须有可复现评估，不能只监控爬虫成功率。

### 3.1 真相边界

**PostgreSQL + Object Storage 是业务真相。**

- PostgreSQL：身份、状态、关系、游标、任务、版本、发布、评估、指标索引；
- S3/MinIO：Raw HTML、Browser Render、PDF、Candidate、IR、Markdown、Search Evidence、Agent Evidence、Enrichment Result、Eval Evidence、导出物；
- Redis Streams：运输层，不保存不可替代业务状态；
- OpenSearch/pgvector/Graph/CSV/Sheets：可重建 Projection；
- Browser Session、Crawler Cache、Agent Memory：易失执行状态。

## 4. 技术选型与组件边界

### 4.1 控制面

- **FastAPI + Pydantic**：REST API、Command、Schema 校验；
- **PostgreSQL**：Source、Release、Coverage、URL、Task、Artifact、Quality、Version、Enrichment、Entity、Evaluation、Audit；
- **Redis Streams**：任务运输、consumer group、backpressure；
- **Redis Lua token bucket/semaphore**：跨 Worker 域名级限流和资源令牌；
- **React/Next.js + TypeScript**：Web 管理后台；
- **OpenTelemetry + Prometheus + Grafana + 结构化日志**：Trace、Metric、Log；
- **S3/MinIO**：不可变大对象和派生对象；
- **OpenSearch + pgvector**：BM25 与向量检索。

### 4.2 Discovery / Fetch

- **httpx/aiohttp**：robots、Sitemap、Feed、CMS API、普通页面、Conditional GET；
- **Crawl4AI**：动态页面、链接/媒体发现、Browser Fetch Adapter、诊断 Candidate；
- **Playwright**：复杂但确定性的滚动、点击、分页 Recipe，以及必要的 Search Provider Browser Adapter；
- **SearXNG/合规 Search API Adapter**：优先用于 External Search Gap；Browser 搜索只作为受控 fallback；
- **PyMuPDF/pdftotext**：PDF；扫描件才进入 OCR。

### 4.3 Extraction

- **Trafilatura**：Generic Main-Content Candidate；
- **lxml**：DOM/XPath；
- **BeautifulSoup**：Structured Metadata、DOM Repair、诊断；
- **JSON-LD/OpenGraph/Microdata**：Metadata Candidate；
- **CSS/XPath/Regex Recipe**：确定性字段和正文抽取；
- **Crawl4AI Markdown**：诊断/Candidate，不直接成为 Canonical。

### 4.4 Enrichment

- 只处理 PASS/WARN `document_version`；
- 可用规则、NER、LLM 或混合 Extractor；
- 输出必须匹配 JSON Schema/Pydantic；
- Prompt、Model、Schema、Chunker、Merger 均版本化；
- 字段尽量保存 evidence block refs；
- 失败不阻塞 Canonical Markdown 主链。

### 4.5 Knowledge Access

- **OpenSearch BM25**：关键词、代码、专有名词、版本号；
- **pgvector**：语义召回；
- **RRF/weighted fusion**：混合召回；
- **可选 reranker**：高价值查询重排；
- **统一 Query Service**：权限、版本、metadata filter、证据上下文；
- **可选 Answer Generator**：只使用检索证据，输出引用；
- **n8n/Slack/Chat Adapter**：交付层，不直接读取真相库。

## 5. Source、Site Family、Profile 与不可变 Release

新增站点最小输入：

```text
name + base_url + 可选标签/策略约束
```

Source 初始进入 `PROBING`，自动探测：

1. robots.txt；
2. Sitemap/Sitemap Index；
3. RSS/Atom；
4. CMS API；
5. Archive/Category/Tag/Pagination；
6. JSON-LD/OpenGraph/Microdata；
7. HTTP 是否能得到完整正文；
8. Browser 是否有真实恢复收益；
9. Site Family 指纹；
10. URL pattern、canonical、redirect、分页；
11. ARTICLE/DOC/INDEX/TAG/AUTHOR/ASSET/API 样本；
12. 多 Extractor 样本质量；
13. Infinite Scroll/Load More 行为；
14. 是否需要 Deterministic/Repair Recipe；
15. 是否存在历史 Coverage Gap，需要 External Search Gap 探测。

Probe 只生成 Candidate Source Profile：

```text
Family Defaults
 + Source Overrides
 + Discovery Recipe
 + Route Policy
 + Extraction/Repair Recipe
 + Quality Policy
 -> Effective Config Hash
 -> Candidate Source Release
 -> Static Validation
 -> Golden Replay
 -> Live Sample
 -> Canary
 -> Approval
 -> ACTIVE
```

模板升级不能直接改变 ACTIVE Source；所有会改变结果的配置都生成新的 Release。

```text

REPEATED_PAGE_FINGERPRINT

```

约束：

- Search Provider 有独立 QPS、页数、成本和 Browser 预算；
- Query/Provider/结果页证据可审计；
- selector/API 漂移进入 `PROVIDER_DEGRADED`，不能静默返回“0 结果”；
- Search 结果缺失不能证明页面不存在；
- Search 新 URL 必须进入统一 Normalize/Identity/Dedup，不建立独立 URL 真相。

### 6.5 Coverage Evidence

Coverage 是证据集合：

```text

 + Cursor/Range

 + Provider Diff
 + Search Gap Evidence
 + Known Gap
```

Web 后台展示 Provider 交并差、时间跨度、最早/最晚文章、缺口区间、Known Gap、Search Gap、补洞任务和 Replay。

## 7. URL 规范化、Identity、去重与分类

### 7.1 URL 规范化

- host 小写、去 fragment、默认端口规范化；
- tracking query 去除、query 排序；
- trailing slash 按站点策略；
- canonical link 只作为 Identity Candidate；
- redirect chain 完整记录；
- 相对 URL 转绝对 URL；
- Scope Policy 阻止越域或不允许路径进入正文队列。

### 7.2 多层去重

1. normalized URL；
2. canonical/redirect identity；
3. Artifact sha256；
4. Canonical semantic hash；
5. 可选近似正文指纹识别镜像/转载。

不能只使用 `set(raw_url)` 作为长期去重机制。

### 7.3 Page Type Classification

在 Browser、正文 Extraction、LLM、Embedding 前完成：

```text
Provider Hint
 -> URL Rule
 -> MIME/Header
 -> Structured Metadata
 -> Cheap DOM Heuristic
 -> Manual Override
 -> LLM Exception(低比例)
```

类型：

```text
ARTICLE | DOC | INDEX | TAG | AUTHOR | HOME |
ASSET | API | AUTH | ERROR | UNKNOWN
```

执行路由：

```text
ARTICLE -> HTTP_ARTICLE -> Extraction Portfolio
DOC     -> HTTP_DOC -> Document Extraction
INDEX/TAG/AUTHOR/HOME -> DISCOVERY_ONLY
ASSET   -> ASSET_PIPELINE
API     -> STRUCTURED_API
ERROR   -> REJECT
UNKNOWN -> CHEAP_PROBE -> Reclassify / QUARANTINE
```

## 8. 调度、队列、幂等与公平性

Queue Class：

```text
DISCOVERY
SEARCH_GAP
CLASSIFY
HTTP
BROWSER
EXTRACT
QUALITY_REPAIR
ENRICHMENT
ENTITY_RESOLUTION
AGENT_CONTROL
PROJECTION
EVALUATION
```

Browser、Search Gap、Enrichment/LLM、Agent、Evaluation、Projection 独立容量，不能拖垮 HTTP 主链。

典型幂等键：

```text
DISCOVER:{source_release}:{provider}:{cursor}
SEARCH:{source_release}:{provider_release}:{query_hash}:{partition}:{cursor}
CLASSIFY:{url_id}:{classifier_release}:{route_policy}
FETCH:{url_id}:{fetch_policy}:{validator_state}
EXTRACT:{artifact_id}:{extractor_release}:{mode}
QUALITY:{artifact_id}:{quality_release}
REPAIR:{artifact_id}:{repair_release}:{step}
RENDER:{version_id}:{renderer_release}
ENRICH:{version_id}:{schema_release}:{extractor_release}:{chunker_release}
ENTITY:{enrichment_version}:{identity_release}
VECTOR:{version_id}:{chunker_release}:{embedding_release}
EVAL:{dataset_release}:{retrieval_or_answer_release}
AGENT:{source_id}:{agent_release}:{evidence_set_hash}:{purpose}
```

Worker 使用 lease + fencing token；旧 lease Worker 不能覆盖新结果。

Weighted Fair Scheduling：Incremental > Backfill；长等待 aging；单 Source 最大并发占比；Browser/Search/LLM 独立配额。

Global Admission 在真实 HTTP/Browser/Search/LLM 调用前检查：global/per-domain concurrency、QPS、Browser slot、Source budget、slow-path share、circuit state、robots/policy。

禁止对百万 URL 一次性创建无界 `asyncio.gather`；所有批处理必须 bounded prefetch/semaphore。

## 9. Fetch：HTTP First，Browser Last

### 9.1 HTTP Worker

异步 HTTP Client 支持：gzip/br、redirect、连接/读取/总 timeout、response size limit、ETag/If-None-Match、Last-Modified/If-Modified-Since、Content-Type/Charset、错误分类和 Raw Snapshot。

### 9.2 Browser Worker 生命周期

禁止每 URL 启动完整 Browser/Crawler：

```text
Browser Worker Process
 -> long-lived browser/crawler
 -> bounded Context Pool
 -> per-context page lifecycle
 -> recycle by request count / memory / time
```

文章型站点大多数应通过 HTTP 完成；Browser 只处理真实 JS 依赖页面。

### 9.3 Browser Fallback 条件

- HTTP 仅得到 JS shell；
- 正文依赖 JS；
- 确定性点击/滚动后正文才出现；
- HTTP Candidate 低质量且历史样本证明 Browser 有恢复收益；
- Source Profile 明确指定。

持续统计 fallback recovery rate、quality delta、p95 latency、cost；低收益触发 Source-scoped circuit breaker。

### 9.4 Readiness 与错误分类

优先 selector、最小正文、DOM/text quiet window、关键响应；固定 sleep 或 networkidle 不作为统一完成条件。

错误至少区分：

```text
NETWORK | TIMEOUT | RATE_LIMITED | ACCESS_DENIED |
BROWSER_CRASH | EMPTY_SHELL | NOT_FOUND |
POLICY_BLOCKED | TOO_LARGE | INVALID_CONTENT
```

不同错误有不同 Retry/Backoff/DLQ 策略。

## 10. Immutable Artifact 与 Extraction Portfolio

每次有内容或诊断价值的 Fetch 都生成不可变 Artifact：

```text
artifact_id
url_id
fetch_kind
object_key
content_type
status_code
etag
last_modified
fetched_at
sha256
runtime_release
parent_artifact_id
```

HTTP Artifact 与 Browser Render Artifact 分开保存。

Extraction Portfolio：

1. Structured Metadata/JSON-LD；
2. Trafilatura Precision/Balanced/Recall；
3. Deterministic CSS/XPath Recipe；
4. DOM Repair + Generic Extractor；
5. Crawl4AI Markdown 诊断 Candidate。

任何 Extractor 都只产生 Candidate，不直接发布。

图片和链接直接从原始 DOM/Crawler media metadata 获取，不走“Markdown → HTML → 再找图片”。资产 URL 绝对化、sha256 去重，并保存 alt/title/source artifact。

## 11. Quality Gate、Candidate Agreement 与有限修复

```text
DISCOVERED
 -> CLASSIFIED
 -> FETCHED
 -> EXTRACTED
 -> QUALITY_CHECK
      -> PASS/WARN -> CANONICALIZE
      -> FAIL_RECOVERABLE -> REPAIR_PENDING
      -> FAIL_UNKNOWN -> QUARANTINE
      -> NON_CONTENT -> REJECT
```

Quality Gate 至少检查：

- title；
- 正文长度；
- paragraph/heading 分布；
- link density；
- boilerplate；
- code/table/list 保留；
- language；
- 错误页/WAF/登录墙指纹；
- Candidate Agreement；
- 分类冲突；
- 历史异常截断；
- 结构突变；
- 重复正文比例。

Repair 顺序：

```text
ALTERNATE_EXTRACTOR
 -> DETERMINISTIC_RECIPE
 -> DOM_REPAIR
 -> BROWSER_REFETCH(有收益证据时)
 -> QUALITY_CHECK
```

Repair 有固定 `max_steps/max_wall_time/browser_budget/cost_budget`。失败进入 QUARANTINE，不让 LLM 改写原文补齐内容。

## 12. Canonical IR 与 Markdown

Canonical IR 保存：

```text
metadata:
  title / author / published_at / updated_at /
  canonical_url / source_id / document_id / version_id
blocks:
  heading / paragraph / code / list / table / quote / image
```

统一 Renderer：

- heading 层级稳定；
- fenced code 保留语言；
- list/table/blockquote 正确；
- 图片保留 alt 与原 URL/归档 URL；
- 相对链接转绝对链接；
- Front Matter 保存 source/document/version/canonical/published/updated；
- Renderer 版本化。

Markdown 只从 Canonical IR 生成。Renderer 升级可离线重建，无需重新访问源站。

**Markdown 是知识库主要交付格式，但不是唯一真相。** Canonical IR + Immutable Artifact 才能支撑后续重建和算法升级。

## 13. 增量同步与版本管理

Freshness 分层：`HOT / WARM / COLD`。

增量发现优先级：

```text
RSS/API
 -> Sitemap lastmod/diff
 -> Archive first pages
 -> bounded dynamic listing
 -> periodic Search Gap check(仅异常/低频)
```

已知 URL 优先 Conditional GET；周期抽样强制 re-fetch，防止上游 ETag/lastmod 不可信。

版本判定：

```text
Artifact
 -> Extraction Portfolio
 -> Quality
 -> Canonical IR
 -> Normalize Semantic Content
 -> semantic_hash
 -> Compare Current Version
```

- semantic hash 相同：只更新 `last_checked_at`；
- 正文变化：创建新 Document Version；
- 仅元数据变化：记录 metadata change；
- PASS/WARN 新版本原子切换 `current_version_id`；
- 相同 semantic hash 不重复向量化和 Enrichment。

删除：多次 404/410 + Provider 缺失等证据后，从 `SUSPECT_MISSING` 进入 `REMOVED`；301/308 建 Redirect Relationship。

## 17. 控制面 Agent Workflow 与治理

Agent 只适合低频、高语义、需综合证据的任务。

外层 Workflow Engine 持有：

- 当前状态；
- 条件分支；
- Retry/Backoff；
- Timeout/Cancel；
- Checkpoint/Resume；
- Budget；
- Human Approval；
- 副作用提交；
- Root Trace Context。

Agent/Crew 仅作为：

```text
RunAgentActivity(contract, evidence_refs)
```

推荐工作流：

```text
Evidence Collector
 -> Profile Planner
 -> Rule/Recipe Generator
 -> Critic
 -> Reviser
 -> Candidate Release Assembler
 -> Deterministic Validation
```

每一步声明：

```yaml
step: profile_planner
consumes: ProbeEvidenceSet/vN
produces: CandidateProfile/vN
required_evidence_roles: [robots, discovery, article_sample, non_article_sample]
allowed_tools: []
retry_policy: agent-semantic-vN
on_validation_failure: REVISE_OR_REVIEW
```

Tool 分级：

- `READ_ONLY`：Probe/Search/Inspect；
- `CANDIDATE_WRITE`：SaveCandidateRelease/SaveDiagnostic；
- `EXTERNAL_SIDE_EFFECT`：默认禁止，若开放必须 Human Approval + 幂等。

Agent 永远只产 Candidate，不能直接修改 ACTIVE 生产规则。

## 23. 安全与合规

### 23.1 网络安全

## 27. 验收标准

### 27.1 历史与增量

- 每个 URL 可解释来自哪个 Provider/Query/Page Observation；
- Authoritative Provider 有 stop reason/exhaustion evidence；
- Known Gap 可见；
- External Search 只作为补洞，不虚报 Coverage 完整；
- 动态 Search Gap 可识别重复页、连续无新增和 Provider DEGRADED；
- 新文章在 Freshness 目标内进入 PASS/WARN Markdown；
- 304 不生成正文版本；正文变化生成新 Version；
- 删除需多证据；
- 重复任务不产生脏重复；
- 大站 Backfill 不阻塞 Incremental。

### 27.2 抽取与质量

- Fetch/Extraction/Quality 独立；
- 多 Candidate 可追溯；
- Selector drift 可检出；
- Repair 有固定上限；
- Browser/Repair 收益和成本可量化；
- 未通过 Quality Gate 不会因慢路径熔断被标记 PASS；
- Markdown 可回溯 Canonical IR；
- Renderer 升级可离线重建。

### 27.3 External Search

- Query、Page/Cursor、Provider、排名、结果页证据、stop reason 可追溯；
- 搜索归零与 Provider Failure 可区分；
- Query 有页数/QPS/成本上限；
- repeated page fingerprint 不会无限循环；
- Search URL 进入统一 Normalize/Identity/Dedup。

### 27.4 Enrichment 与 Entity

- 只处理 PASS/WARN Document Version；
- Schema Validation 失败不会写入有效结果；
- VALID_EMPTY 与 MODEL_ERROR 分离；
- 长文可分块且无静默 Top-N 截断；
- Prompt/Model/Schema/Chunker 可版本化；
- 字段有 Evidence 或明确 `evidence_missing`；
- Enrichment 失败不阻塞 Markdown；
- 同一 Document Version + Release 幂等；
- Entity Merge 不删除原文证据；
- 错误合并可拆分并重建 Projection。

### 27.5 Retrieval / RAG / Agent

- Golden Query Dataset 可版本化；
- Retrieval Release 有 Recall@K/MRR/nDCG/filter accuracy 基线；
- 旧版本文档不会被错误优先返回；
- Answer 有 citation coverage/groundedness 指标；
- 无证据问题支持正确拒答；
- Slack/n8n/Chat 均走统一 Query Service；
- Retrieval/Answer 变更必须过 Offline Eval + Canary；
- 回归超过阈值可阻止发布或回滚。

### 27.6 可复现与治理

- 全新容器可加载当前 Release 完成 Golden Corpus；
- Runtime Image、Chromium、Extractor、Renderer、Agent/Enrichment/Retrieval Release 明确版本；
- 同一 Artifact + 同一 Release 可离线重建同一 Canonical/Markdown；
- 外层 Workflow State 可持久化、恢复和回放；
- Source Candidate 必须过 Deterministic Validation + Golden Replay + Canary + Approval；
- Retrieval/Answer Candidate 必须过 Golden Query Eval + Canary。
