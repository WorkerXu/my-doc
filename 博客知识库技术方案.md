# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站和公开 Newsletter** 的长期知识库采集平台，可平滑扩展到数千站点、百万级到千万级文章。

系统必须满足：

1. **全历史回填**：尽可能完整发现并抓取每个已批准 Source 的历史文章，并能解释已知缺口、未知边界和停止原因；
2. **持续增量同步**：持续发现新文章、正文更新、URL 迁移、重定向、删除和重发布；
3. **稳定 Markdown**：Markdown 从可追溯 Raw Artifact 经确定性抽取、质量门禁和 Canonical IR 生成；
4. **低成本扩站**：新增网站优先通过 Source Profile、Provider、Traversal Policy、Extraction Recipe 配置，不维护 1000 份独立爬虫；
5. **Web 可运营**：支持 Source 接入、审核、Backfill、Incremental、Coverage、Frontier、质量、成本、失败诊断、暂停/恢复/停止和审计；
6. **可搜索与 RAG**：支持关键词、向量和混合检索，并可回溯原文、版本、来源和抓取证据；
7. **可观测、可恢复、可重放**：任意 URL、任务、Artifact、Markdown 和 Focused Score 都能解释来源、版本和执行路径；
8. **渐进扩展**：开发期 Docker Compose，生产期按队列和 Worker 类型水平扩容；
9. **主链不依赖 LLM**：LLM 只用于可选增强，不参与 Coverage Truth、URL Identity、Canonical URL、Robots Access 和历史完整性最终判定；
10. **高成本抓取智能预算**：Browser、Deep Crawl、Repair、专题知识包可用 Focused Information-Gain Scheduler 排序，但不得因此永久丢弃历史 URL。

### 1.1 核心 SLO

- **Coverage**：每个 Source 能解释 Provider、已发现 URL、Frontier、Known Gap 和 Backfill 停止原因；
- **Freshness**：新文章从发布/发现到 PASS Markdown 的延迟；
- **TTFM**：URL 首次发现到首个可用 Markdown 的时间；
- **Extraction Quality**：标题、正文完整率、噪声率、代码块/表格/列表保留率、截断率；
- **Reliability**：任务成功率、Retry、DLQ、Queue Age、Lease Recovery、Checkpoint Resume 成功率；
- **Browser Efficiency**：HTTP 命中率、Browser avoided/recovery、每文档 Browser 成本；
- **Identity Quality**：重复文章误合并/漏合并率；
- **Validity Quality**：Soft-404、假 200、空壳 SPA 识别准确率；
- **Traceability**：任意 Markdown 可回溯 Source、URL、Artifact、Extractor、Quality、Renderer Release；
- **Cancellation**：停止请求到停止发新 Lease、到 Run 完全 STOPPED 的延迟；
- **Cost**：按 Source、Run、Queue Class、每 1000 篇 PASS 文档统计抓取、Browser、存储、索引和模型成本；
- **Focused Efficiency**：专题/慢路径统计 pages-per-useful-result、expected gain、Browser 节省比例和 stop reason；
- **Budget Accuracy**：Focused Job 的 page/preview/browser/model/query-expansion 调用不超过平台硬预算；
- **Replayability**：同 scorer release + 同 candidate snapshot + 同 query set 可复现同一评分结果。

### 1.2 非目标

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不把 HTTP 200、DOM 很长或 crawler success 直接视为正文正确；
- 不把搜索结果数、Common Crawl、Wayback、Deep Crawl 页数、Adaptive confidence、`max_pages`、runtime `max_depth` 当历史完整性证明；
- 不把 Crawl4AI 即时 Markdown、LLM 摘要或改写直接作为 Canonical Markdown；
- 不因 URL 曾抓过就永久停止复检；
- 不把 Redis、Browser Session、Crawler Cache、Visited Set、Dispatcher Queue、Adaptive State、Search Index 当业务真相；
- 不允许优先级、Scorer、相关性阈值、信息增益阈值或执行预算永久删除潜在历史文章；
- 不默认对所有文档构建 GraphRAG。

## 2. 核心设计原则

1. **Coverage First**：先建立 URL Inventory，再批量抓正文；
2. **Authoritative First**：CMS/API、Sitemap、RSS/Atom、官方 Archive 优先；
3. **Historical Gap Is Evidence, Not Truth**：Common Crawl、Wayback 用于历史补洞，不作为完整性证明；
4. **Deep Crawl Is Gap Provider**：站内深度抓取用于补洞，不作为 Coverage Truth；
5. **Focused Is Optimization**：Focused confidence 表示专题信息充分度，不等于历史 Coverage；
6. **Discovery / Fetch / Extract / Quality / Projection 分离**；
7. **HTTP First, Browser Last**：Browser 是受治理慢路径；
8. **Snapshot First**：先保存不可变 Artifact，再抽取与清洗；
9. **Canonical IR First, Markdown as Projection**；
10. **Recipe, Not 1000 Site Scripts**；
11. **Stable Identity**：Source、Host、URL、Artifact、Document、Version 使用稳定 ID；
12. **Idempotent + Recoverable**：任务使用幂等键、Lease、Fencing Token、Checkpoint；
13. **Fair by Default**：大站 Backfill 不能饿死 Incremental 和小站；
14. **Bounded Concurrency Everywhere**：禁止无界 asyncio gather、Browser Context、Preview 和模型 fan-out；
15. **No Silent Degradation**：截断、预算耗尽、降级、过滤、跳过必须记录原因；
16. **Release Everything That Changes Results**：Profile、Provider、Traversal、Adaptive、Recipe、Runtime、Extractor、Quality、Renderer、Embedding、Rank 全部版本化；
17. **Priority Means When, Not Whether**：优先级和 expected gain 决定何时处理，不决定 URL 是否永久保存；
18. **Observation Before Selection**：观察到链接后先保存事实，再 Filter/Score/Budget；
19. **Persistent Frontier, Not In-Memory Traversal**：BFS/DFS/Best-First/Focused 的业务候选进入数据库；
20. **Runtime Checkpoint != Business Checkpoint**：第三方 crawler resume state 只是执行优化，PostgreSQL 才是恢复真相；
21. **Cooperative Cancellation**：停止是状态机，不把点击停止等同于所有 in-flight 工作结束；
22. **Approved Scope First**：发现子域、路径或外部归档 URL 不等于允许主动访问；
23. **Soft-404 Is First-class**：URL 存在性不能只依赖 HTTP 状态码；
24. **Global Admission + Local Adaptation**：跨 Worker 公平和限流由平台负责，Worker 内存自保护由运行时负责；
25. **Runtime Result Is Advisory**：第三方 crawler 的 dedup、status、score、limit、timeout、cache、confidence 都不能直接升级为平台业务真相；
26. **Normalize Conservatively**：scheme/host 可标准化，path/query 默认保留大小写与原始语义；
27. **Explicit Runtime Capabilities**：生产配置不得依赖第三方 crawler 默认 source/path 集；
28. **Robots Policy Is Access Control Input**：robots 访问判定由平台 RFC 9309 Policy Engine 负责；
29. **Correlate by Identity, Never by Position**：批量结果按 `attempt_id/url_id/requested_url` 关联，禁止依赖过滤后数组位置；
30. **Strict Budget Is Platform-owned**：page/preview/browser/model/query-expansion 预算由平台 Admission 硬控；
31. **Graph Depth Is Platform-owned**：真实 depth 来自持久 URL edge，第三方 runtime 的批次 round 不得冒充 graph depth；
32. **Config Must Prove Effective**：第三方配置只有经过 pinned-release `config -> actual behavior` 测试后才作为生产有效配置；
33. **Score Input Must Be Replayable**：Focused score 保存 candidate snapshot/query set/release hash，支持确定性回放。

```text
       |                              |                               |
       +------- Observation -> Persistent URL Inventory / Frontier --+
                                      |
                              URL Validity Gate
                                      |
                             Immutable Artifact
                                      |

                                      |

                              /              \
                           PASS              REPAIR
                              \              /

                                      |
```

### 3.1 业务真相边界

**PostgreSQL + Object Storage 是业务真相。**

- PostgreSQL：Source、Approved Host、Provider、URL Identity、URL Observation、Robots Policy、Validity、Frontier、Task、Cursor、Coverage、Focused Run、Quality、Document、Version、Release、Checkpoint Pointer、Audit；
- S3/MinIO：Raw HTML、MHTML、截图、Trace、Provider Evidence、Preview、Candidate、IR、Markdown、PDF、Runtime Checkpoint、Focused Query Set、Enrichment；
- Redis Streams：任务运输、Consumer Group、Backpressure、分布式 Token Bucket，不保存不可替代业务状态；
- OpenSearch / pgvector：可重建 Serving Projection；
- Crawl4AI cache、dispatcher queue、rate limiter、Browser Session、Adaptive `CrawlState`、Playwright Context、Worker 内存：易失执行状态。

## 4. 技术选型与 Release

### 4.1 控制面

- **FastAPI + Pydantic**：REST API、Command、Schema 校验；
- **PostgreSQL**：Truth Store、任务、Coverage、Frontier、版本、审计；
- **Redis Streams**：任务运输、Consumer Group、Backpressure；
- **Redis Lua Token Bucket / Semaphore**：跨 Worker 域名限流和资源令牌；
- **React / Next.js + TypeScript**：Web 管理后台；
- **OpenTelemetry + Prometheus + Grafana + Structured Logging**：Trace / Metric / Log；
- **S3/MinIO**：不可变对象存储；
- **Vault/KMS/Secret Manager**：凭据引用。

### 4.2 Discovery / Fetch

- **httpx/aiohttp**：robots、Sitemap、Feed、CMS API、Conditional GET、普通网页和 SafeProbe；
- **RFC 9309 Robots Parser/Policy Engine**：User-Agent group、最长匹配、Allow/Disallow 判定与缓存；
- **Crawl4AI**：Domain Mapping、AsyncUrlSeeder、Browser Render、Deep Crawl Prefetch、Link Preview baseline、Adaptive baseline；
- **Crawl4AI MemoryAdaptiveDispatcher**：Browser Worker 本地内存自保护；
- **Playwright Python**：复杂多步、有状态、需要 Step 级恢复的交互；
- **Common Crawl Adapter**：公共历史索引补洞；
- **Wayback CDX Adapter**：历史 URL 补洞；
- **SearXNG / 合规 Search API Adapter**：External Search Gap、新 Source Candidate；
- **PyMuPDF/pdftotext**：PDF；扫描件进入 OCR 慢路径；
- **Python email/MIME parser**：Newsletter Inbox Provider。

### 4.3 Extraction / Search

- **Trafilatura**：Generic Main Content Candidate；
- **lxml/BeautifulSoup**：DOM/XPath、Metadata、DOM Repair；
- **JSON-LD/OpenGraph/Microdata**：结构化元数据；
- **CSS/XPath/Regex Recipe**：确定性正文与字段抽取；
- **SimHash/MinHash**：近重复候选；
- **OpenSearch BM25 + pgvector + RRF**：混合检索；
- **可选 embedding/reranker/LLM**：只在 Canonical 数据或 Focused Job 上运行。

### 4.4 Focused Scorer

```text
platform_statistical_v1       # 生产默认
platform_embedding_v1         # 可选
crawl4ai_statistical_baseline # 行为对照
crawl4ai_embedding_baseline   # 小规模实验
```

`platform_statistical_v1` 使用 Unicode/CJK-aware analyzer，并保留 C++、C#、.NET、Go、R、JS、AI、DB、S3、K8s 等技术词；`platform_embedding_v1` 从 Canonical IR 的标题、Heading 和代表性 Chunk 构建语义表示。

## 6. Source 接入流程

新增网站先自动探测，再人工确认并发布 immutable Source Profile Release。

```text
1. exact-host robots.txt / Sitemap / Feed
2. CMS 特征：WordPress/Ghost/Medium/Substack/自建 API
3. 首页和安全内容路径探测
4. Archive / Pagination / URL Pattern
5. Canonical / Redirect / Query 参数行为
6. Soft-404 baseline
7. HTTP vs Browser route sampling
8. metadata-only 子域候选发现
9. 人工审核 Content Host
10. Common Crawl / Wayback 历史 Gap inventory
11. Deep Crawl 浅层 Prefetch
12. 发布 Source Profile Release
```

Domain Recon 默认：

- `include_subdomains=false`；
- 显式编译 runtime source allowlist；
- 未批准 host 只保留 metadata evidence；
- DomainMapper 原生 `probe/robots` 默认关闭；
- SafeProbe 只访问 approved exact-host + robots allow 的配置路径；
- DNS resolve 和 redirect 每跳做 SSRF / scope 校验；
- 所有请求经过全局 Token Bucket 和 Audit。

Source Profile 示例：

```yaml
source:
  canonical_domain: example.com
  approved_hosts:
    - host: example.com
      scheme: https
      type: CONTENT
  providers:
    - sitemap
    - rss_atom

    - common_crawl_gap
    - wayback_gap
    - safe_probe
    - deep_crawl
  fetch_route:
    default: http
    browser_patterns: [/interactive/*]

    engine: rfc9309
    user_agent_product_token: MyKnowledgeBot
  traversal:
    mode: bfs

  focused:
    enabled: false

    max_preview_requests_per_run: 500
```

## 7. Discovery、Backfill 与 Coverage

### 7.1 Provider 顺序

```text
CMS/API
 -> Sitemap
 -> RSS/Atom
 -> Archive/Pagination
 -> HTML Listing
 -> Common Crawl / Wayback Historical Gap
 -> Safe Domain Recon Gap
 -> SafeProbe Content Paths
 -> Deep Crawl Prefetch
 -> External Search Gap
```

最终 URL Inventory 是多个 Provider 的集合并集，保留每条 Observation 证据。高优 Provider 成功不能阻止其它 Provider 执行。

### 7.2 Backfill 流程

```text
Source Approved
 -> Probe Authoritative Providers
 -> Build Initial URL Inventory
 -> Archive/Pagination Enumeration
 -> Common Crawl / Wayback Historical Gap
 -> Safe Domain Recon Gap
 -> SafeProbe Content Paths
 -> Deep Crawl Gap Scan
 -> Persistent Frontier
 -> Robots Policy / URL Validity
 -> Fetch
 -> Extract / Quality / IR / Markdown
 -> Coverage Reconcile
 -> Gap Review
 -> Backfill Complete
```

### 7.3 Backfill 完成条件

至少满足：

- 权威 Provider 完成或明确不可用；
- Historical Gap Provider 运行到配置边界并记录限制；
- Persistent Frontier 无 READY/LEASED/RETRY；
- Archive/Deep Crawl 不再产生新增文章候选，或达到可解释收敛；
- 失败任务成功、进入 DLQ 或被人工接受；
- Soft-404 疑似已确认、延期或人工接受；
- Known Gap 为空或被人工接受；
- 多 Provider URL 集合差异处于阈值内。

**Focused confidence、saturation、max_pages、runtime round/max_depth、low gain 绝不能作为 Backfill Complete 条件。**

### 7.4 URL 规范化

```text
resolve relative
 -> normalize scheme
 -> lower host / IDNA
 -> remove default port
 -> strip fragment
 -> normalize dot segments
 -> preserve path case by default
 -> preserve query case/order before Query Policy
 -> tracking parameter policy
 -> redirect identity
 -> rel=canonical evidence
```

不提前删除 query 参数；每个 Source 通过采样生成 Query Policy 后发布 release。

## 8. Focused Information-Gain Scheduler

### 8.1 定位

Focused Scheduler 只用于：

- Browser 慢路径预算；
- Deep Crawl Gap Scan 候选排序；
- 专题知识包；
- Backfill 未完成时的专题 RAG 冷启动；
- Repair/Browser fallback 优先级。

不用于：历史完成判定、RSS/CMS/Sitemap 增量同步、URL Identity、Robots Access、Soft-404 Truth、Tombstone、Canonical Markdown。

### 8.2 生产默认：Platform-owned

```text
Persistent URL Inventory
 -> Candidate Slice Builder
 -> Platform Preview
 -> Focused Scorer
 -> Strict Budget + Graph Depth Admission
 -> Frontier priority update
 -> HTTP/Browser/Repair Worker
 -> Canonical IR
 -> Focused metric update
```

平台负责 URL durability、scope/robots/SSRF、graph depth、strict budget、attempt correlation、retry/DLQ、fairness、lease/fencing、cancellation。

### 8.3 Statistical Scorer

Crawl4AI StatisticalStrategy 仅作 baseline。平台解释：

```text
Coverage    = query term/topic coverage
Consistency = topical overlap/coherence
Saturation  = marginal information gain diminishing
```

生产 `platform_statistical_v1`：

- Unicode/CJK-aware analyzer；
- 技术词保留；
- title/heading/anchor/body 分字段；
- Canonical IR/clean text；
- 权重真实进入公式；
- component score 可解释；
- score 只映射 priority。

### 8.4 Embedding Scorer

`platform_embedding_v1` 默认关闭，启用时：

- query model 与 embedding model 显式配置；
- query expansion 使用严格 JSON Schema；
- 保存 raw response、actual variation set、train/validation split 和 hash；
- split 可 Replay；
- 正文向量来自 Canonical IR representative chunks，不只截正文开头；
- 模型、prompt、analyzer、embedding 全部版本化；
- 模型或 query set 变化后旧 checkpoint 不直接 resume；
- 所有模型调用纳入硬预算。

### 8.5 Crawl4AI Native Adaptive 边界

Crawl4AI `AdaptiveCrawler` 只作为 baseline、小规模实验或经过补丁的 bounded runtime，不拥有业务 Frontier。

固定 release 必须验证：

1. Statistical confidence 权重配置是否真正生效；
2. authority 是否真的区分候选；
3. 文档 ExpectedGain 与源码真实公式是否一致；
4. Link Preview 产生哪些额外请求；
5. 无 `head_data` 的链接是否被过滤；
6. `max_pages` 是否可能批次 overshoot；
7. batch 部分失败后结果是否仍和原 URL 正确关联；
8. embedding query/validation/checkpoint 是否完整恢复；
9. 同实例是否存在跨 Run 状态污染；
10. runtime `max_depth` 是 graph depth 还是 batch round；
11. Embedding active confidence 实际读取哪些配置；
12. `coverage_score`、`learning_score` 和最终展示 confidence 是否一致。

### 8.6 Runtime Round 与 Graph Depth 分离

平台定义：

```text
graph_depth  = URL 在持久链接图上的真实深度
runtime_round = Adaptive 一次 top-k 批次扩展轮次
```

Admission 先检查 `graph_depth <= max_graph_depth`。Native `max_depth` 仅映射为 `max_runtime_rounds`，即使 runtime resume 后 round 重置，也不能突破平台 graph depth。

### 8.7 严格预算

```text
remaining_pages = page_budget - admitted_count
batch_size = min(top_k, remaining_pages)
```

同时硬控：

```text
page admission
HTTP attempts
Browser attempts
preview requests
embedding calls
query-expansion calls
wall-clock deadline
```

分别记录 admitted/attempted/successful，不能用成功页面数代替成本计数。

### 8.8 Native Resume

Runtime checkpoint 只是 hint。Embedding 模式在未补齐以下状态前 native resume 默认关闭：

```text
query_hash
actual generated query variations
train query set
held-out validation query set
confidence history
validation state
runtime round
query/model/prompt/analyzer release hashes
```

平台始终从 PostgreSQL Frontier 恢复 graph depth、URL 生命周期和任务状态。

### 8.9 Link Preview 安全

Native Preview 可能产生额外 metadata 请求。任何 preview 必须经过：

```text
Approved Scope
 -> RobotsPolicy
 -> SSRF Validation
 -> Redis per-domain Token Bucket
 -> bounded preview concurrency
 -> strict request budget
 -> Audit
```

如果无法证明 runtime 内部每个 preview 请求都经过这些策略，则主链关闭 native preview，改用平台 Preview Artifact。

Raw Link Observation 必须先落库。无 `head_data`、低 score、低 gain、preview 失败的 URL 仍保留在 Inventory。

### 8.10 Deterministic Score Replay

每个评分保存：

```text
candidate_snapshot_hash
query_set_hash
scorer_release
analyzer_release
embedding_release(optional)
component_scores
final_score
rank
```

同一输入和 release 在 Offline Replay 中必须可复现；不能复现则禁止升级为生产默认 scorer。

### 8.11 Stop Reason

```text
FOCUSED_SUFFICIENT
FOCUSED_SATURATED
FOCUSED_MAX_PAGES
FOCUSED_MAX_RUNTIME_ROUNDS
FOCUSED_MAX_GRAPH_DEPTH
FOCUSED_LOW_GAIN
FOCUSED_NO_LINKS
FOCUSED_IRRELEVANT
FOCUSED_BUDGET_EXHAUSTED
FOCUSED_CANCELLED
```

这些只结束 Focused Run，不改变 Historical Coverage。

## 9. Deep Crawl、Domain Mapping 与 Traversal

### 9.1 两阶段 Deep Crawl

```text
Phase A: Prefetch Discovery
- 获取 HTML / links / minimal metadata
- 记录 from_url -> to_url Observation/Edge
- 跳过 Markdown / LLM / 重型抽取
- 形成 Persistent Frontier

Phase B: Full Processing
- Fetch Raw Artifact
- URL Validity
- Extraction / Quality / IR / Markdown
```

### 9.2 Observation Before Selection

```text
Page Result
 -> Extract Raw Links
 -> Persist Observation/Edge
 -> Normalize / Scope Check
 -> Graph Depth Check
 -> Filter Reason
 -> Score / Expected Gain
 -> Budget / Admission
 -> Persistent Frontier
 -> Runtime Slice
```

禁止先由 visited/threshold/max_pages/low gain 裁剪，再只保存幸存 URL。

### 9.3 Traversal

- **BFS**：Backfill 默认探测；
- **DFS**：路径深度结构明确时启用；
- **Best-First**：固定预算优先处理更像文章、归档、分页的 URL；
- **Focused**：专题/高成本慢路径按信息增益排序。

统一语义：`score -> priority`。

Bounded Slice：每 Source Backfill 200~500 URL；focused 10~50 URL；Browser 慢队列独立。Slice 结束后未处理候选仍在 PostgreSQL Frontier。

## 10. Fetch Plane 与访问治理

### 10.1 HTTP First

```text
HTTP fetch
 -> 正文充分
    -> HTTP Artifact
 -> JS shell / challenge / content incomplete
    -> Browser slow path
```

### 10.2 Conditional Fetch

增量复检使用 `If-None-Match` / `If-Modified-Since`。304 不生成新正文版本，但更新 freshness observation。

### 10.3 Retry

```text
DNS/TCP timeout       -> exponential retry
429                   -> Retry-After + domain throttle
5xx                   -> bounded retry
403/challenge         -> policy-based browser route
404/410               -> tombstone candidate + grace policy
soft-404 suspected    -> validity/repair queue
parse/extract failure -> repair queue，不等于必须 refetch
```

### 10.4 多层限流

```text
Redis Token Bucket       = 跨 Worker 精确节流
Worker Semaphore         = 本地并发保护
Crawler RateLimiter      = 本地 429/503 退避
MemoryAdaptiveDispatcher = Worker 内存压力保护
Focused top_k            = 本次排序 fan-out hint
```

### 10.5 Raw Artifact First

Fetch 成功先写不可变对象：

```text
raw/{source_id}/{yyyy}/{mm}/{artifact_id}.html.gz
```

附 `attempt_id/url_id/requested_url/final_url/status/headers/timing/runtime_release/payload_sha256/trace_id`。Artifact durable 后任务才能进入 EXTRACT。

## 17. 安全、合规与抓取礼仪

- 默认尊重 RFC 9309 robots/access policy；
- 未批准 host 的 CT/DNS/Archive 发现只保留 metadata evidence；
- SafeProbe 只在 approved CONTENT exact-host 且 RobotsPolicy allow 后执行；
- Focused Preview 同样经过 Scope、Robots、SSRF、Token Bucket；
- 不自动绕过登录、付费墙、CAPTCHA、明确禁止；
- 禁止 SSRF 到 loopback、RFC1918、link-local、云 metadata、file:// 等；
- DNS 解析 IP 做禁止网段校验，Redirect 每一跳重新校验；
- Crawler Docker/API 只放内网；
- Web 用户不能直接提交任意 JS hook 或完整 CrawlerRunConfig；
- JS execution、下载路径、Webhook 等高风险能力默认关闭；
- 凭据只存 Secret Manager 引用；
- 所有第三方查询纳入 egress、超时和审计；
- 无法验证第三方 runtime 内部请求经过 Access Policy 时，关闭该网络功能并用平台受控实现。

```text
11. Soft-404 先 Validity 再 Admission
12. HTTP First，Browser 只慢路径
13. Raw Artifact durable 后再 Extract
14. Frontier 清空 + Provider 完成 + Known Gap 审核后才完成
```

## 22. 验收标准

平台达到可生产使用至少满足：

1. 新增标准博客主要通过 Web Source Profile 完成，不新增独立爬虫脚本；
2. 新 host 未经批准不能主动抓取；
3. 任意 Source 可执行全历史 Backfill，并解释 Coverage、Historical Gap、Known Gap；
4. Common Crawl/Wayback/Adaptive confidence 不被误当完整性证明；
5. 任意 URL 能解释 Provider、Observation、Graph Depth、Filter、Score、Admission、Validity、Frontier；
6. SPA/自定义 404 不会仅因 HTTP 200 大规模进入正文库；
7. URL Normalizer 默认保留 path/query 大小写语义；
8. Worker 任意 kill 后不丢业务 Frontier，可通过 Lease/Checkpoint 恢复；
9. Crawler local queue/cache/adaptive state 丢失仍可从 PostgreSQL/Object Storage 重建；
10. `max_pages`、低 score、低 gain、Provider timeout 不会让历史候选静默消失；
11. runtime round 重置不会突破平台 max graph depth；
12. 点击停止后停止发新 Lease并最终 STOPPED；
13. Raw Artifact 可重放生成新 IR/Markdown，不必重新抓网页；
14. Incremental 通过 RSS/Sitemap/Conditional GET 持续同步；
15. Markdown 保留标题、正文、代码、表格、列表等关键结构并通过质量门禁；
16. Search Index 全部可从 Canonical 数据重建；
17. 所有改变结果组件都有 release，并通过 Golden Replay；
18. Web Admin 可完成接入、审核、Backfill、Incremental、Coverage、失败诊断、暂停/恢复/停止和审计；
19. Focused 高 confidence/saturation 不改变 Source 历史 Coverage；
20. Focused 未选择、preview 失败、低 gain URL 仍保留 Observation/Frontier；
21. Embedding 失败或模型升级不破坏主链和业务恢复；
22. Browser/Deep Crawl/Repair 可通过 expected gain 降低成本并量化收益；
23. page/preview/browser/model/query-expansion 预算 Golden Test overshoot 为 0；
24. 批次部分失败时成功结果按 `attempt_id/url_id` 正确关联；
25. 同一 Crawl4AI AdaptiveCrawler 实例不跨 Focused Run 并发复用；
26. Embedding checkpoint 未恢复完整 query/validation/round 语义时不得宣称 deterministic resume；
27. 技术词和中文 statistical analyzer 通过 Golden Test；
28. 长技术文章语义表示覆盖全文代表性 Chunk；
29. 第三方 runtime 配置只有 `VERIFIED_EFFECTIVE` 才作为生产硬控制项；
30. Focused score 输入可回放，同 release 同输入结果可复现。

最终架构原则：

> **权威 Provider 建 Inventory，Common Crawl / Wayback / Safe Domain Recon / SafeProbe / Deep Crawl 补 Coverage Gap；Observation 与 URL Edge 先于选择，Approved Scope 与 RFC 9309 RobotsPolicy 先于主动访问，Persistent Frontier 与 Platform Graph Depth 保证不丢不越界；Focused Information-Gain Scheduler 只决定高成本候选的处理顺序，confidence/saturation/low-gain/runtime-round 都不能替代 Historical Coverage；严格预算、请求身份关联、Retry、Fairness、真实 depth 和恢复由平台拥有，第三方 runtime 的 dedup/status/score/limit/timeout/confidence/config 只作 advisory；Raw Artifact 保证可重放，Canonical IR 保证稳定 Markdown；Runtime Checkpoint 提升执行恢复效率，但业务真相始终在 PostgreSQL + Object Storage。**
