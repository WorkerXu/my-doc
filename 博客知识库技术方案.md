# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站和公开 Newsletter** 的长期知识库采集平台，并可持续扩展到数千站点。

平台必须同时解决：

1. **历史尽量抓全**：知道文章有哪些、从哪里发现、为什么认为 Provider 已到边界、仍有哪些 Known Gap；
2. **持续增量同步**：及时发现新文章、修改、迁移和删除；
3. **内容稳定可用**：把 HTML、动态页面、PDF 等转换为可追溯 Canonical IR 和 Markdown；
4. **低成本扩展**：新增站点主要依赖 Site Family、Source Profile、Discovery/Extraction Recipe，不为每站长期维护专用爬虫；
5. **Web 可管理**：接入、Probe、审核、调度、回放、失败处理、Coverage、质量、成本、Release 和回滚都可管理；
6. **结果可审计**：任意 Markdown 都能定位到 Source、URL、Artifact、Recipe、Runtime、Extractor、IR、Quality、Version 和 Release；
7. **AI 友好但不牺牲事实完整性**：Canonical 内容与面向 RAG 的 Fit/Filter 投影明确分层；
8. **运行时可替换**：Crawl4AI/Playwright/httpx 是 Adapter，不是平台业务真相；
9. **配置复用但控制爆炸半径**：Site Family Template 可复用，但生产只消费不可变 Effective Source Release；
10. **防静默抽错**：确定性 selector 即使仍命中，也要通过 Candidate Agreement/Shadow Extraction 发现“命中但抓错”的漂移。

最终提供：

- 全历史 URL Discovery + Backfill；
- Sitemap/RSS/CMS/API/Archive/动态列表/受限 Deep Crawl 等多 Provider；
- 定时 Incremental、Known URL Verify、删除/迁移判定；
- HTTP-first、Browser-last 正文获取；
- Infinite Scroll / Load More / Virtual Scroll；
- CSS/XPath/Regex Deterministic Extraction Recipe 与 Generic Extractor 双轨；
- Site Family Template + Source Override + Immutable Effective Release；
- Raw Fact、Canonical IR、Canonical Markdown、AI Fit Markdown、全文和向量索引分层；
- Web 管理、RBAC、审计、成本治理、告警、Canary/回滚；
- Markdown/JSONL/IR 全量与增量导出。

### 1.1 核心 SLO

平台不以 HTTP 200 比例作为核心 SLO，而以业务结果衡量：

- **Coverage**：历史 URL 覆盖、Provider exhaustion evidence、Known Gap；
- **Freshness**：新文章从发布到进入 PASS Canonical Markdown 的延迟；
- **Quality**：正文完整率、噪声率、结构质量、Quarantine 比例；
- **Extraction Correctness**：selector hit/completeness 与 candidate agreement；
- **Data Supply**：URL 首次发现到 `Quality=PASS` 且投影可用的 `time_to_usable_data`；
- **Reliability**：Task 成功率、Retry/DLQ、队列年龄、Worker 恢复、Browser 资源回收；
- **Cost**：每 Source、每 1000 个 PASS 文档、每 accepted version 的网络/CPU/Browser/存储/LLM 成本；
- **Traceability**：任意结果可回溯到不可变事实和版本化执行环境。

### 1.2 非目标

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不用 LLM 主观判断代替 Coverage 证明；
- 不把 Redis、Browser session、Crawler cache/frontier 当业务真相；
- 不允许 Web/API 直接透传任意 JavaScript、Playwright evaluate、代理或 Chromium 参数；
- 不把 LLM 摘要/重写作为 Canonical Markdown；
- 不把 BM25/Pruning/Fit Markdown 作为 Canonical 内容事实；
- 不把标题、slug、图片 alt、图片 URL 或展示文本当跨阶段唯一主键；
- 不因为 URL 曾经抓过就永久停止复检；
- 不把 `crawler success=true`、HTTP 200、最终 DOM 较长直接等价为正文成功或 Coverage 完成；
- 不允许 Family Template 更新原地改变所有 ACTIVE Source；
- 不因为 selector 命中且字段完整就直接认为正文正确。

## 2. 核心设计原则

1. **Coverage First**：先证明“文章有哪些”，再批量抓正文。
2. **Authoritative First**：CMS/API、Sitemap、Feed、Archive 优先，动态列表/Deep Crawl 用于补洞。
3. **Discovery Before Fetch**：URL 发现、规范化、Scope、分类、去重独立于正文抓取。
4. **Discover Cheap, Fetch Expensive**：低成本 Provider 先跑，Browser 后置。
5. **HTTP First, Browser Last**：静态 HTTP 优先；确定性 Browser fallback；Agent Browser 极少使用。
6. **Deterministic Before Agentic**：主链在没有 LLM 时也能完成 Backfill 与 Incremental。
7. **Snapshot First**：先保存不可变抓取事实，再 Extract/IR/Markdown。
8. **IR First, Markdown as Projection**：Canonical IR 是内容事实，Markdown 是可重建投影。
9. **Canonical Before Fit**：Pruning/BM25/Fit Markdown 只做 AI/RAG 投影，不改变 Canonical Version。
10. **Quality Is First-Class**：传输成功与内容合格是两套状态。
11. **Cost Is First-Class**：高成本 Browser/LLM 必须可归因、可预算。
12. **Tool Contract, Not Framework Coupling**：Crawler 通过 Adapter 接入。
13. **Recipe, Not Site Code**：selector、pagination、scroll、click、virtual scroll、结构化 extraction 通过版本化 Recipe 表达。
14. **Semantic Recipe, Not Runtime Parameters**：Recipe 表达业务动作语义，不绑定 crawler 参数名。
15. **Capability != Outcome**：Runtime Capability 是“支持什么”，Runtime Outcome 是“本次实际执行了什么”。
16. **Business Identity Over Runtime Dedup**：文章 Coverage 以规范化 URL/URL Identity 为准，不依赖 crawler 内部 DOM/文本去重。
17. **Stable Identity**：Source、URL、Artifact、Document、Version 使用稳定不可变 ID。
18. **Idempotent + Recoverable**：Task 有幂等键、lease、fencing token、checkpoint、retry、DLQ。
19. **Fair by Default**：大站 Backfill 不得长期饿死 Incremental 和小站。
20. **Micro-batch Is Execution Optimization**：stream/batch 只优化 Worker 吞吐，Task 仍是幂等、重试、落库单位。
21. **Detect Drift Online**：Golden Corpus 防平台升级回归，Drift Detector 防站点改版静默退化。
22. **Security on Every Hop**：start URL、redirect、href、iframe、Asset、Browser navigation、proxy destination 每跳重新校验。
23. **Release Everything That Changes Results**：Profile、Family Template、Recipe、Compiler、Runtime、Extractor、Schema、Renderer、Filter 全版本化。
24. **Projection Is Rebuildable**：Markdown、Fit Markdown、全文索引、向量等派生结果可从事实层重建。
25. **Fail Closed on Semantic Incompatibility**：运行时无法保持 Recipe 语义时阻止 Release，不能静默少抓。
26. **No Silent Fallback for Coverage**：动态能力未真正生效时标记 Known Gap/DEGRADED，不能借 crawler success 宣称抓全。
27. **Family Reuse, Effective Immutability**：家族模板用于复用，生产只执行已编译、不可变的 Effective Source Release。
28. **Agreement Before Trust**：selector hit/completeness 不是正文正确性证明；通过 Generic/Deterministic Agreement 和 shadow sampling 发现静默抽错。

## 4. 技术选型

### 4.1 控制面

- **FastAPI + Pydantic**：REST、Command API、Schema 校验；
- **PostgreSQL**：Source/Family/Profile、Run/Task、Coverage、Observation、Artifact、Recipe/Result/Agreement、Document/Version、Projection、Quality、Drift、Cost、Release、Audit、Outbox；
- **Redis Streams**：任务运输、consumer group、backpressure；
- **Redis Lua token bucket / semaphore**：跨 Worker Domain Admission；
- **React/Next.js + TypeScript**：Web 管理台；
- **Prometheus + Grafana + OpenTelemetry**：Metric/Log/Trace；
- **S3/MinIO**：Raw HTML、DOM/MHTML、IR、附件、失败诊断、导出；
- **OpenSearch**：全文/BM25；
- **pgvector**：首期向量检索，通过 Adapter 可替换；
- **Docker Compose**：开发/小规模验证；
- **Kubernetes**：生产 Worker Pool 横向扩展与 HPA。

### 4.2 抓取与解析

- **httpx/aiohttp**：HTTP、Sitemap、Feed、CMS API、Conditional GET、附件；
- **Crawl4AI**：动态页面、streamed batch、URL mapping、Virtual Scroll、CSS/XPath/Regex extraction 等，通过 Adapter 使用；
- **Playwright**：复杂但确定性的交互 Recipe；
- **lxml + trafilatura/readability 类算法**：默认 Generic Extractor；
- **JSON-LD/OpenGraph/Microdata**：结构化元数据候选；
- **Pruning/BM25**：仅 AI Fit/RAG 投影或辅助候选，不直接决定 Canonical；
- **PyMuPDF/pdftotext**：PDF；扫描件才进入 OCR。

### 4.3 Crawler 边界

```text
平台负责：
Source/Family/Release / Task / Retry / DLQ / Coverage / Fairness /
Global Rate Limit / Budget / Checkpoint / Quality / Audit /
Runtime Outcome / Extraction Agreement / Projection Semantics

Crawler 负责：
单次导航 / 页面动作 / DOM / 链接 / 媒体 / 浏览器资源管理 /
局部 batch/stream / 结构化 extractor 执行
```

生产锁定经过 Golden Corpus 验证的 Crawl4AI、Playwright、Chromium 与镜像 digest；升级必须经过 Capability、Compile、Replay、Benchmark、Canary、Approval。

### 5.10 Projection

```text
projection
- projection_id
- version_id
- type: CANONICAL_MD | AI_FIT_MD | FULLTEXT | VECTOR_CHUNKS
- projection_release_id
- config_hash
- object_key
- content_hash
- created_at
```

规则：

```text
CANONICAL_MD = 只从 Canonical IR 稳定渲染
AI_FIT_MD    = 可使用 Pruning/BM25/领域 Filter，可重建
FULLTEXT/VECTOR = 派生投影，可重建
```

## 6. 新站点接入：Probe -> Family -> Effective Release -> Review

### 6.1 自动 Probe

新增 Source 进入 `PROBING`：

1. 读取 robots.txt；
2. 探测 `/sitemap.xml`、Sitemap Index、RSS/Atom；
3. 识别 WordPress/Ghost/Medium/Substack/Hugo/Jekyll/Docusaurus 等特征；
4. 生成 Site Family fingerprint 和命中证据；
5. 发现 CMS/API、Archive、分页、year/month/category index；
6. 抽取 URL/path 样本，生成 include/exclude 候选；
7. 随机选择 5~10 篇文章，并覆盖长文、代码、表格、旧模板、新模板；
8. 比较 HTTP Extractor 与 Browser/Recipe 正文质量；
9. 检测 JSON-LD、作者、发布时间、代码块、图片、表格；
10. 优先套用 Family Discovery/Extraction Template，再生成 Source override；
11. 生成 Generic/Deterministic candidate diff 与 agreement；
12. 权威发现不足时做受限 Prefetch Mapping；
13. JavaScript 栏目识别 Pagination/Load More/Append Scroll/Virtual Scroll；
14. Probe 动态能力时记录 Runtime Outcome，确认能力真正 engaged；
15. 评估 Canonical Markdown 与 AI Fit Markdown 差异；
16. 估算历史 URL 数、时间分布、Browser 比例、Backfill 和日常成本；
17. 编译为不可变 Candidate Effective Source Release。

### 6.2 Family Template 复用与安全升级

Family Template 只用于生成候选，不允许运行时动态继承。

```text
Template ACTIVE v5
 -> 生成 Source A/B/C Candidate Release
 -> replay 各自 Golden Corpus
 -> Canary 部分 Source
 -> Compare Coverage/Quality/Agreement/Cost
 -> 分批提升为 ACTIVE
```

模板升级失败只影响 Candidate，不影响旧 ACTIVE Release。

### 6.3 Web 审核

管理员审核：

- Family fingerprint 与证据；
- Family Template 与 Source override diff；
- Effective Config diff/hash；
- Provider 与优先级；
- URL 样本、include/exclude/path 分类；
- HTTP/Browser 正文质量；
- Dynamic Listing 每轮 URL 增长、Runtime Outcome、编译计划、收敛原因；
- Generic vs Deterministic Extractor diff；
- Agreement 分项和 shadow 策略；
- Raw/IR/Canonical/Fit 预览；
- selector hit/field completeness/Quality；
- robots/Scope；
- estimated vs discovered、Known Gap；
- Backfill 成本和 Browser 占比。

审核通过后发布 Source Release，再进入 Backfill。

## 7. 历史全量 URL 发现与 Coverage

### 7.1 Provider 优先级

```text
1. CMS / 官方 API
2. Sitemap / Sitemap Index
3. RSS / Atom
4. Archive / Pagination / Year-Month Index
5. Category/Tag Index（补充）
6. URL Seeder / 公开索引
7. Prefetch Mapping
8. Dynamic Listing Discovery
9. bounded Deep Crawl
10. 人工补充 / CSV 导入
```

Browser Provider 默认不压过可用的权威低成本数据源。

### 7.2 Coverage 不是“队列空了”

Backfill 完成必须有可审计证据：

- CMS/Sitemap cursor 已穷尽或明确不可用；
- Archive 到达最老分页/年份；
- Provider 交叉后新增 URL 收敛；
- Dynamic Listing 达到可解释 exhaustion boundary，且 Runtime Outcome 证明交互语义实际生效；
- Prefetch/Deep Crawl 达 `max_pages/max_depth/time budget` 时形成 Known Gap；
- expected_count 存在时数量对照；
- 历史时间分布异常空洞进入补洞队列。

以下不能单独作为 Coverage 完成证据：

```text
queue empty
crawler success=true
HTTP 200
DOM 高度不再变化
最终 HTML 体积较大
selector 一次命中
crawler 内部 merge/dedup item 数
structured extraction 返回合法 JSON
```

### 7.3 URL 规范化

- scheme/host 小写；
- 默认端口清理；
- fragment 移除；
- tracking 参数移除；
- query 只保留 Source allowlist；
- trailing slash 由 Profile 决定；
- relative URL resolve；
- Canonical Link 只作为证据，不无条件信任；
- redirect final URL 重新过 Scope/SSRF；
- 保留 original observed URL 与 normalized URL。

### 7.4 Prefetch Mapping

```text
Phase A: Map
seed URLs
 -> cheap HTML + links
 -> normalize/scope/filter
 -> URL Observation + parent edge
 -> page/path classifier
 -> 估算站点空间

Phase B: Process
article candidates
 -> 正式 HTTP/Browser Fetch
 -> Snapshot/Render
 -> Extract/IR/Quality
```

必须设置 `max_depth/max_pages/time_budget`，并对日历、搜索、tag、query 无限空间设置 guard。

```yaml
  max_items: 5000
```

```text
PAGINATION
```

### 8.3 Recipe Compiler


### 8.4 Runtime Outcome Gate

请求动态能力时必须验证：

```text
feature_requested
feature_engaged
container_found
detected_mode
actions_attempted
actions_completed
waits_satisfied
harvest_rounds
unique_url_union_count
stop_reason
warnings
```

Gate：

```text
feature_requested && !feature_engaged
 -> Provider DEGRADED
 -> exhausted=false
 -> Known Gap

VIRTUAL_SCROLL && !container_found
 -> VIRTUAL_SCROLL_CONTAINER_NOT_FOUND
 -> exhausted=false

expected_runtime_mode != detected_mode
 -> INTERACTION_MODE_MISMATCH
 -> 保存 Artifact/Trace
 -> Recipe Review
```

### 8.5 收敛算法

```python
seen = set()
no_growth = 0

for round_no in range(max_rounds):
    candidates = harvest_current_state()
    urls = normalize_scope_filter_classify(candidates)
    new_urls = urls - seen
    seen |= new_urls
    persist_observations(new_urls, round_no)

    if incremental_overlap_reached(new_urls):
        stop("OVERLAP_BOUNDARY")
        break

    no_growth = no_growth + 1 if not new_urls else 0
    if no_growth >= no_growth_rounds:
        stop("NO_GROWTH")
        break

    outcome = perform_next_semantic_action()
    verify_runtime_outcome(outcome)
    wait_for_item_growth_or_timeout()
else:
    stop("MAX_ROUNDS")
```

收敛依据是“规范化并通过 Scope/文章分类后的唯一文章 URL 是否继续增长”。DOM 高度、文本量、runtime merged item 只能辅助。

### 8.6 动作安全白名单

```text
WAIT_SELECTOR
CLICK_SELECTOR
SCROLL_PAGE
SCROLL_CONTAINER
WAIT_ITEM_GROWTH
EXTRACT_LINKS
```

Adapter 生成受控脚本，生产禁止任意 JavaScript 透传。

## 9. 正文抓取与最小成本路由

### 9.1 Acquisition Planner

```text
L0 CMS/API payload
L1 HTTP
L2 Crawl4AI deterministic Browser
L3 Playwright deterministic Recipe
L4 LLM-assisted extraction / Controlled Agent Browser
```

目标：

```text
minimize expected_cost / expected_accepted_document_version
subject to Quality SLO and Freshness SLO
```

### 9.2 HTTP Worker

支持：

- `If-None-Match`；
- `If-Modified-Since`；
- gzip/br；
- connect/read/write timeout；
- redirect 上限；
- per-domain connection pool；
- `Retry-After`；
- 429/503 指数退避 + jitter；
- body size 上限；
- MIME allowlist；
- 原始 header + body hash 保存。

### 9.3 Browser Worker

Browser 进程复用，Context 按安全域隔离，Page 按 Task 短生命周期：

- 默认拦截广告、追踪、字体、视频等非必要资源；
- 默认不截图、不生成 PDF；
- 诊断/Golden Corpus/审核才截图；
- wait/scroll/click 来自版本化 Semantic Recipe；
- crawler 内限流只作第二层保护；
- Page 完成后强制关闭；
- Context 只在同一安全域短 session 复用；
- Browser 按 RSS/年龄/pages-since-recycle/error-rate 回收。

资源池：

```text
Browser Discovery Worker
- 长页面、多轮交互、低并发、强预算

Browser Content Worker
- 单文章、短生命周期、正文完整度优先
```

### 9.4 受控 streamed micro-batching

Browser Content Worker 可在 Adapter 内使用 Crawl4AI `arun_many(..., stream=True)` 或等价能力：

```text
Scheduler
 -> claim 8~32 个已通过 Admission 的 Task
 -> 按 runtime/browser config/resource class 分组
 -> streamed micro-batch
 -> 每个 result 按 task_id 独立落库
```

约束：

- batch_id 不是幂等键；
- 单 URL 失败不回滚全批；
- 每 URL 独立 lease/fencing/retry；
- batch 不绕过 per-domain token bucket；
- 跨安全域不共享持久 Cookie/Profile；
- stream cancel/SIGTERM 必须清理未完成 page/context；
- Runtime 升级必须回归 `stream cancel -> active pages 回到基线`。

### 9.5 Browser 生命周期

```text
Page          -> 每 Task 关闭
Context       -> session/安全域结束关闭
Browser       -> max pages / RSS / age / crash rate 触发 recycle
Worker Pod    -> 长期内存或异常阈值滚动重启
```

业务 checkpoint 永远在 PostgreSQL，不依赖 Browser 存活。

### 9.6 Browser Fallback 条件

HTTP 成功但以下条件不满足才升级 Browser：

- 正文过短；
- text density 低；
- JSON-LD/正文 DOM 明显缺失；
- 仅 hydration shell；
- Challenge/login/cookie 模板命中；
- Source Release 明确要求 Browser。

Browser 仍失败则 Quarantine，不无限重试。

## 10. 正文抽取、Candidate Agreement 与 Canonical IR

### 10.1 Extractor Pipeline

```text
Snapshot / Render Artifact
 -> MIME / encoding normalize
 -> metadata candidates
 -> DOM sanitize
 -> template route
 -> Deterministic Extraction Candidate
 -> Generic Main-content Candidate
 -> Agreement / Reconciliation
 -> block reconstruction
 -> Canonical IR
 -> Quality Gate
 -> Document Version
 -> Projection Renderer
```

### 10.2 Deterministic Extraction Recipe

示例：

```yaml
name: article_template_v3
match:
  path_regex: "^/blog/.+"
mode: JSON_CSS
base_selector: "article"
fields:
  - {name: title, selector: "h1", type: text, required: true}
  - {name: author, selector: ".author", type: text}
  - {name: published_at, selector: "time", type: attribute, attribute: datetime}
  - {name: body, selector: ".post-content", type: html, required: true}
quality:
  min_field_completeness: 0.8
  min_body_chars: 500
```

候选融合示例：

```text
published_at:
JSON-LD(valid) > time[datetime] recipe > OpenGraph > text heuristic

body:
explicit selector candidate 与 generic candidate 比较
 -> 结构/长度/boilerplate/agreement 合格 -> accept
 -> 异常 -> generic fallback + Quarantine/Drift signal
```

不能因为 selector 命中或 JSON 可解析就直接判定正文成功。

### 10.3 Candidate Agreement

最危险的漂移是：selector 仍命中，但命中的是摘要、推荐区或错误副本。对此要检测：

```text
selector_hit_rate 高
field_completeness 高
candidate_agreement 低
```

建议比较：

- normalized title similarity；
- body token/char n-gram similarity；
- heading path similarity；
- code/table/list delta；
- author/published_at/canonical URL consensus；
- content length ratio；
- link density、boilerplate ratio。

决策：

```text
PASS
 -> 进入 reconciliation

SUSPICIOUS
 -> 保存双候选
 -> Quarantine 或人工复核
 -> Drift Observation
 -> 不覆盖 current version

FAIL
 -> Recipe failure/fallback
```

### 10.4 Shadow Extraction

为了控制 CPU：

```text
Probe / Extraction Recipe Release / Runtime Canary -> 100% 双抽取
稳定 Source                                    -> 1%~5% shadow
Quality/Drift 异常窗口                         -> 临时 100%
```

Shadow sample 需要覆盖：

- 最新文章；
- 历史旧模板；
- 长文；
- 代码/表格密集文；
- 不同 URL path/template route。

Agreement 只是异常信号，不把 Generic Extractor 当绝对真相。

### 10.5 Canonical IR

```json
{
  "schema_version": 3,
  "title": "...",
  "canonical_url": "...",
  "author": ["..."],
  "published_at": "...",
  "updated_at": "...",
  "language": "zh-CN",
  "blocks": [
    {"type": "heading", "level": 2, "text": "..."},
    {"type": "paragraph", "text": "..."},
    {"type": "code", "language": "python", "text": "..."},
    {"type": "image", "src": "...", "alt": "..."},
    {"type": "table", "rows": []}
  ],
  "metadata": {}
}
```

IR 作用：

- Markdown Renderer 升级后可重建；
- 向量切块按 heading/block；
- code/table/image 语义不丢；
- semantic hash 不受 Markdown 格式变化；
- 不受 BM25 query/Filter 参数影响。

### 12.3 在线 Drift Detector

信号：

- selector hit rate 下降；
- required field completeness 下降；
- **hit/completeness 不变但 candidate agreement 下降**；
- deterministic vs generic body 差异暴涨；
- container_found rate 下降；
- feature engaged rate 下降；
- detected_mode 分布变化；
- action completion rate 下降；
- Dynamic Listing URL yield 骤降；

```text
Drift Alert

 -> Approval
 -> New Effective Source Release
```

如果同一 Runtime Release 后多个不同 Source 同时退化，优先判断平台回归。

## 13. 增量同步与版本管理

### 13.1 增量发现

```text
RSS/Atom
CMS cursor
Sitemap lastmod
Archive 最近分页
Dynamic Listing 顶部窗口
低频 Prefetch/Deep Crawl 补漏
```

使用 overlap window，例如从上次 watermark 向前回退 24 小时，通过 URL Identity 去重吸收重复。

Freshness Class：

```text
HOT  -> 5~30 min
WARM -> 1~6 h
COLD -> 1~7 d
```

实际频率由历史更新率、Provider 能力、429/503、预算、新 URL yield、业务优先级共同决定。

### 13.2 Dynamic Listing 增量

```text
打开列表顶部
 -> harvest
 -> normalize/dedupe
 -> 继续动作并验证 Runtime Outcome
 -> 遇到 overlap 时间边界
    或连续 K 个已知 URL + N 轮无 unseen URL
 -> 停止
```

Browser session 不是 checkpoint。PostgreSQL 保存 watermark、Observation、Provider cursor、Release、Outcome、Coverage Evidence。

### 13.3 已知 URL 复检

```text
Conditional GET
 -> 304: 更新时间，不创建 Version
 -> 200 + body hash 相同: 不 Extract
 -> body hash 变化: Extract -> IR
 -> semantic hash 相同: 不创建 Version
 -> semantic hash 变化: 新 Version -> Quality -> Projection rebuild
```

Recipe/Renderer/Filter 变化但 Artifact 未变时，可离线 Reprocess/Reproject，无需重新联网。

### 13.4 删除与迁移

不能把一次 404 当永久删除：

- 404/410 连续 N 次；
- 多个增量 run 不再观察到；
- Sitemap/CMS 明确消失；
- redirect 指向新 canonical；
- grace period 后再标记 DELETED/MOVED。

保留旧 Version 和 URL Identity。

### 13.5 周期性校验

- 周/月 Provider cross-check；
- 随机历史 URL Verify；
- Sitemap 全量 diff；
- 低频 Archive/Prefetch gap scan；
- Coverage 时间分布空洞检测；
- Dynamic Outcome 异常样本复跑；
- Deterministic Recipe 历史 Snapshot 抽样回放；
- 稳定 Source 定期 shadow extraction。

## 14. 调度、可靠性与公平性

### 14.1 Transactional Outbox

```text
DB transaction:
  update business state
  insert outbox event
commit

Outbox Relay -> Redis Streams
```

Worker 完成先写 PostgreSQL 再 ACK；Redis 丢失可从事实层重建运输层。

### 14.2 Lease + Fencing Token

```text
lease_owner
lease_until
fencing_token++
```

最终写检查 fencing token，旧 Worker 恢复后不能覆盖新结果。

### 14.3 Retry 分类

```text
RETRYABLE:
timeout / connection reset / 429 / 503 / browser crash

RECIPE_OR_SOURCE:
selector timeout / required field missing / candidate disagreement /
container not found / interaction mode mismatch / feature not engaged /
template drift / no article links

RUNTIME:
stream cleanup regression / browser recycle failure / page leak

PERMANENT:
out-of-scope / unsupported MIME / explicit denied
```

指数退避 + jitter，超过 max_attempts 进入 DLQ。

### 14.4 Weighted Fair Scheduler

- Incremental > Verify > Backfill；
- Source 轮转；
- 大站分片；
- per-domain concurrency；
- Browser/HTTP 独立资源池；
- aging 防永久饥饿；
- micro-batch 只能从 Scheduler/Admission 已接受 Task 中组装。

### 14.5 Global Domain Admission

```text
Redis token bucket  -> requests/sec
Redis semaphore     -> concurrent requests
DB policy           -> Source truth
```

429/503/Retry-After 自动降速并逐步恢复。Crawler 内部限速只作第二层。

### 14.6 Backpressure

监控：

- stream lag；
- oldest task age；
- Browser pool saturation；
- active pages/contexts；
- object storage latency；
- Extract/index throughput。

压力高时优先保 Incremental Freshness，暂停低优先级 Deep Crawl/Backfill；不得通过无限增大 batch 掩盖背压。

## 25. 最终验收标准

### 25.1 Coverage

- Sitemap/CMS/Archive Provider 有 exhaustion evidence；
- 动态列表有逐轮 URL 增长曲线与 exhaustion reason；
- 交互能力有 `feature_engaged/container_found/detected_mode/actions_completed` 证据；
- crawler success 但 feature 未生效时不得判 exhausted；
- bounded Provider 达预算时明确 Known Gap；
- Provider 交叉后历史时间分布无无法解释的大空洞；
- crawler 内部文本/HTML dedup 不作为文章身份或 Coverage 主键。

### 25.2 Freshness

- HOT Source 新文章在目标时间进入 PASS Canonical Markdown；
- Backfill 期间 Freshness SLO 不显著退化；
- watermark 丢失可通过 overlap/Observation 恢复；
- micro-batch 不破坏 Incremental 优先级。

### 25.3 Quality / Extraction Correctness

- Cookie/Login/Challenge 不进入 current version；
- code/heading/time/table 等结构在 Golden Corpus 稳定；
- Deterministic Recipe required completeness 达阈值；
- Recipe 失效可 fallback/Quarantine；
- **selector hit/completeness 正常但 Candidate Agreement 异常时必须可检测、告警并阻止静默覆盖**；
- 稳定 Source 的 shadow sample 能持续发现静默漂移；
- Canonical Version 不受 BM25/Filter 改变；
- Runtime/Extractor/Renderer 升级无明显 Quality 回归。

### 25.4 Site Family / Release

- 常见 CMS/模板站可复用 Family Template；
- Source override 只描述差异；
- ACTIVE Source 可定位唯一 `effective_config_hash`；
- Family Template 更新不会原地修改 ACTIVE Source；
- 批量提升前完成 Replay/Canary；
- 任意 Source 可回滚旧 Effective Release。

### 25.5 Reliability

- Worker 强杀后 lease/fencing 自动恢复；
- Redis 清空后可从 PostgreSQL 重建；
- 重复投递不产生重复 Document Version；
- 单 URL 失败不回滚 micro-batch 其他任务；
- stream cancel/SIGTERM 后 active pages/contexts 回到基线；
- Browser recycle 不造成任务丢失或重复写；
- DLQ 可定位并重放。

### 25.6 Runtime Compatibility & Outcome

- 所有 ACTIVE Recipe 可针对目标 Runtime 编译；
- `trigger -> wait -> harvest` 等语义升级后保持；
- 不支持能力时 Release 失败而非静默降级；
- Runtime 声称支持的关键能力在 Golden Corpus 产生符合预期 Outcome；
- container/mode/feature 异常时 Provider 不能宣称 Coverage 完成；
- stream cleanup/recycle regression 阻止 Runtime Release；
- Render Artifact 能定位 `recipe_release + compiler_version + runtime_release + capability_hash + compiled_plan_hash + runtime_outcome`。

### 25.7 Cost

- 每 Source/accepted version 成本可归因；
- Browser 秒、RSS、recycle 可观察；
- Deterministic/Generic/Shadow/LLM extractor 成本可区分；
- 预算阈值可暂停非关键 Provider，不产生无界成本。

## 26. 最终方案结论

平台以 **PostgreSQL + Object Storage 为事实层，Redis Streams 为运输层，Site Family + Immutable Effective Source Release 为规模化配置层，Discovery/Extraction Semantic Recipe 为扩展面，HTTP-first/Browser-last 为成本策略，Canonical IR 为内容事实，Canonical/Fit Projection 为 AI 使用边界，Agreement/Quality/Coverage/Release 为正确性护栏**。

1000+ 站点的可扩展性来自五层解耦：

```text
同类站点公共能力
 -> Site Family Template

单站差异
 -> Source Override + Effective Source Release

站点发现/正文模板差异
 -> Discovery / Extraction Recipe

工具/版本差异
 -> Runtime Capability + Recipe Compiler + Adapter

单次实际执行差异
 -> Runtime Outcome + URL Observation + Extraction Agreement
```

新增第 1001 个站点主要是：

```text
Probe
 -> Family Fingerprint
 -> Reuse Template
 -> Source Override
 -> Effective Release
 -> Golden Corpus
 -> Review
 -> Backfill
 -> Incremental
```

而不是复制一份新的爬虫代码。

动态栏目统一通过：

```text
Dynamic Listing Provider
 -> Semantic Recipe
 -> Compiled Plan
 -> Runtime Outcome
 -> URL Observation
 -> Coverage Evidence
```

正文统一通过：

```text
Artifact
 -> Deterministic Candidate
 -> Generic Candidate
 -> Agreement / Reconciliation
 -> Canonical IR
 -> Quality Gate
```

AI 输出统一通过：

```text
Canonical IR
 -> Canonical Markdown
 -> optional AI Fit Markdown / Search / Vector
```

Browser 批量能力只作为执行优化：

```text
Independent Tasks
 -> Scheduler/Admission
 -> streamed micro-batch
 -> per-task persist
 -> cleanup/recycle
```

必须长期坚持四个边界：

1. **Crawler success、最终 DOM、内部去重、Runtime Capability 都不能单独证明 Coverage。**
2. **selector 命中、JSON 可解析、字段完整都不能单独证明 Canonical 正文正确。**
3. **AI Fit Markdown 的“更适合模型”不能替代 Canonical 内容完整性。**
4. **Family Template 的“复用”不能变成对数百 ACTIVE Source 的隐式动态修改。**

最终形成可恢复、可审计、可扩展的知识供应链：

```text
Discover
 -> Prove Runtime Outcome when needed
 -> Prove Coverage
 -> Fetch
 -> Preserve Fact
 -> Extract Candidates
 -> Agreement/Reconcile
 -> Canonical IR
 -> Quality Gate
 -> Version
 -> Canonical/Fit Projection
 -> Index/RAG
 -> Incremental Verify
 -> Shadow Extraction
 -> Drift/Release Governance
```

这套方案使知识库长期正确性不绑定某个 crawler 的临时参数、DOM 合并逻辑、文本指纹、Filter 算法、批量执行机制或共享模板的动态变化，并能在站点数量、页面模板和抓取运行时持续变化时稳定演进。
