# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站和公开 Newsletter** 的长期知识库采集平台，可平滑扩展到数千站点和百万级至千万级文章，并持续接入新网站。

系统必须满足：

1. **全历史回填**：尽可能完整发现并抓取每个已批准 Source 的历史文章，能够解释 Coverage、Known Gap、失败和停止边界；
2. **持续增量同步**：发现新文章、正文更新、URL 迁移、重定向、删除和重发布；
3. **稳定 Markdown**：Markdown 从不可变 Raw Artifact 经确定性抽取、质量门禁和 Canonical IR 生成；
4. **低成本扩站**：新增网站优先通过 Source Profile、Provider、Traversal Policy、Extraction Recipe 配置完成，不维护线性增长的站点专用爬虫；
5. **Web 可运营**：支持 Source 接入、审批、配置发布、Backfill、Incremental、Coverage、Frontier、质量、成本、失败诊断、暂停、恢复、停止和审计；
6. **可搜索与 RAG**：支持 BM25、向量和混合检索，并可回溯原文、版本、Source、Artifact 和抓取证据；
7. **可观测、可恢复、可重放**：任意 URL、Task、Runtime Result、Artifact、IR、Markdown 均可解释来源、版本和执行路径；
8. **渐进扩展**：开发期 Docker Compose，生产期按 Discovery、HTTP、Browser、Extraction、Projection Worker 水平扩容；
9. **主链不依赖 LLM**：LLM 仅作可选增强，不参与 Coverage Truth、URL Identity、Canonical URL、Robots Access 和历史完整性最终判定；
10. **高成本路径有硬预算**：Browser、Deep Crawl、Repair、Focused Job、模型调用和诊断 Artifact 均有平台级 page/request/process/model/byte/wall-clock 预算；
11. **Web 配置安全**：外部用户只提交声明式低能力配置，不能直接获得任意 JS、代理、CDP、浏览器 Profile、Deep Crawl Strategy 等 Runtime 能力；
12. **停止后真正静默**：取消、暂停、Lease 丢失、Context recycle、Browser Process recycle 或 Worker recycle 后，运行时 task/page/context/session/resource token 必须收敛；
13. **Runtime 多结果不静默丢失**：Deep Crawl、批量、流式结果必须逐条显式物化；
14. **Browser 进程可控寿命**：Runtime Context 回收与 Browser 进程/Pod 代际分层治理，不能让长期进程无限寿命运行。

### 1.1 核心 SLO

- **Coverage**：每个 Source 可解释 Provider、URL Inventory、Frontier、Known Gap 和 Backfill Stop Reason；
- **Freshness**：新文章从发布/发现到 PASS Markdown 的延迟；
- **TTFM**：URL 首次发现到首个可用 Markdown 的时间；
- **Extraction Quality**：标题、正文完整率、噪声率、代码块/表格/列表保留率、截断率；
- **Reliability**：Task 成功率、Retry、DLQ、Queue Age、Lease Recovery、Checkpoint Resume；
- **Browser Efficiency**：HTTP 命中率、Browser avoided/recovery、每文档 Browser 成本；
- **Context Stability**：Runtime context generation pages、drain latency、context leak；
- **Process Stability**：Browser process generation age/pages/RSS、drain latency、PID 替换成功率、强制 kill 率；
- **Identity Quality**：重复文章误合并/漏合并率；
- **Validity Quality**：Soft-404、假 200、空壳 SPA 识别准确率；
- **Result Integrity**：Runtime 返回结果物化完整率、cardinality mismatch 和 identity mismatch；
- **Cancellation**：停止请求到停止新 Admission、Runtime QUIESCED、Run STOPPED 的延迟；
- **Config Safety**：Power-field 绕过数为 0，Runtime Config 可回溯编译报告和 Release；
- **Admission Accuracy**：硬预算 overshoot 为 0；
- **Evidence Cost**：Durable/Diagnostic Artifact 的字节、采样和 TTL 可观测；
- **Replayability**：同输入 + 同 Release 可复现抽取、渲染和评分结果。

### 1.2 非目标

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不默认使用个人持久 Browser Profile、Magic/模拟用户等反爬绕过能力；
- 不把 HTTP 200、Runtime `success`、DOM 很长或 downloaded file 存在直接视为文章正确；
- 不把搜索结果数、Common Crawl、Wayback、Deep Crawl 页数、Adaptive confidence、`max_pages`、runtime depth/round 当历史完整性证明；
- 不把 Crawl4AI 即时 Markdown、LLM 摘要或改写直接作为 Canonical Markdown；
- 不把 Redis、Runtime Cache、Browser Session、Visited Set、Dispatcher Queue、Search Index 当业务真相；
- 不允许 priority、score、low gain 或预算永久删除尚未保存的历史候选；
- 不允许 Web/API 调用者构造任意 Runtime 对象、运行任意代码或指定服务器文件路径；
- 不默认永久保存所有 MHTML、network、console、screenshot、trace；
- 不默认对全部文档构建 GraphRAG。

## 2. 核心设计原则

1. **Coverage First**：先建立 URL Inventory，再抓正文；
2. **Authoritative First**：CMS/API、Sitemap、RSS/Atom、官方 Archive 优先；
3. **Historical Gap Is Evidence, Not Truth**：Common Crawl、Wayback 只补洞；
4. **Deep Crawl Is Gap Provider**：Deep Crawl 不拥有 Coverage Truth；
5. **Discovery / Fetch / Extract / Quality / Projection 分离**；
6. **HTTP First, Browser Slow Lane**；
7. **Snapshot First**：先保存不可变 Raw Artifact；
8. **Canonical IR First, Markdown as Projection**；
9. **Recipe, Not 1000 Site Scripts**；
10. **Stable Identity**：Source、URL、Attempt、Runtime Result、Artifact、Document、Version 使用稳定 ID；
11. **Idempotent + Recoverable**：幂等键、Lease、Fencing Token、Checkpoint；
12. **Fair by Default**：大站 Backfill 不能饿死 Incremental、小站和 Repair；
13. **Bounded Concurrency Everywhere**；
14. **No Silent Degradation**：过滤、截断、预算耗尽、降级和结果缺失必须记录原因；
15. **Observation Before Selection**：链接事实先保存，再 Filter/Score/Budget；
16. **Persistent Frontier, Not In-Memory Traversal**；
17. **Approved Scope First**：发现 host/path 不等于允许访问；
18. **Soft-404 Is First-class**；
19. **Global Admission + Local Adaptation**：平台负责跨 Worker，Runtime 只做本地自保护；
20. **Runtime Result Is Advisory**：Runtime status/success/cache/score 不直接升级为业务真相；
21. **Normalize Conservatively**：path/query 默认保留大小写和语义；
22. **Correlate by Identity, Never by Position**；
23. **Graph Depth Is Platform-owned**；
24. **Strict Budget Is Platform-owned**；
25. **Config Is Capability**：能改变代码、网络、浏览器、secret 的字段受 Capability Firewall 控制；
26. **Untrusted by Default at Network Boundary**；
27. **Caller Never Owns Paths**；
28. **Quiesce Before Reuse**：Runtime 未清零不得复用或宣称 STOPPED；
29. **Zero Must Not Mean Unbounded by Accident**；
30. **Materialize Before Interpreting**：Container/Generator 先逐条物化；
31. **Prefetch Is Observation, Not Document**；
32. **Evidence Is Tiered**：Durable 与 Diagnostic Evidence 分层；
33. **Runtime Schema Drift Must Fail Loudly**；
34. **Security State Never Crosses Isolation Key**；
35. **Behavior Beats Naming**：第三方参数名、注释和文档不是生产行为契约，必须通过 pinned release 源码和 Contract Test 验证；
36. **Context Generation != Process Generation**：Runtime Context 回收不等价于 Browser 进程重启；
37. **Process Generation Is Platform-owned**：实际 Browser PID/进程/Pod 生命周期由平台治理。

### 3.1 业务真相边界

**PostgreSQL + Object Storage 是业务真相。**

- PostgreSQL：Source、Approved Host、Provider、URL Identity、Observation、Robots、Validity、Frontier、Task、Cursor、Coverage、Attempt、Runtime Result Envelope、Runtime Cleanup、Context Generation Evidence、Browser Process Generation、Quality、Document、Version、Release、Audit；
- S3/MinIO：Raw HTML、原始 PDF、Provider Evidence、Preview、Candidate、IR、Markdown、Checkpoint、按策略保存的 Trace/MHTML/截图；
- Redis Streams：任务运输和 Backpressure；
- Redis Lua：Token Bucket/Semaphore/短期资源令牌；
- OpenSearch/pgvector：可重建 Serving Projection；
- Crawl4AI cache、dispatcher queue、visited set、browser context、Playwright page/session、adaptive state：均为可丢失 Runtime State。

### 3.2 Runtime Adapter 边界

```text
Platform Command
 -> compiled runtime_config_release
 -> Crawl4AI Adapter
 -> HTTP/Browser/Deep Crawl
 -> Runtime Result Container/Stream
 -> Result Materializer
 -> Runtime Result Envelope
 -> Raw Artifact / Observation
 -> Platform Truth
```

Runtime 不拥有 Source 生命周期、全局 Frontier、Coverage、最终 Canonical Identity、最终 Version、最终 Markdown、跨 Worker 限流、访问审批和文章有效性。

## 4. 技术选型与 Release

### 4.1 控制面

- **FastAPI + Pydantic**：REST API、Command、Schema；
- **PostgreSQL**：Truth Store、Task、Frontier、Coverage、Version、Audit；
- **Redis Streams**：任务运输；
- **Redis Lua Token Bucket/Semaphore**：跨 Worker 域名和资源限流；
- **React/Next.js + TypeScript**：Web 管理后台；
- **OpenTelemetry + Prometheus + Grafana + Structured Logging**；
- **S3/MinIO**：不可变对象；
- **Vault/KMS/Secret Manager**：Secret 引用；
- **Nginx/Envoy/API Gateway**：TLS、请求体上限、Rate Limit、Correlation ID。

### 4.2 Discovery / Fetch

- **httpx/aiohttp**：robots、Sitemap、Feed、CMS API、Conditional GET、普通网页、SafeProbe；
- **RFC 9309 Robots Engine**；
- **Crawl4AI pinned release**：Browser Render、Deep Crawl Prefetch、链接发现、局部 Runtime 调度；
- **MemoryAdaptiveDispatcher**：仅 Worker 本地内存自保护；
- **Playwright Python**：复杂页面慢路径；
- **Common Crawl / Wayback CDX Adapter**：历史补洞；
- **合规 Search API/SearXNG Adapter**：Gap 和 Source Candidate；
- **PyMuPDF/pdftotext**：PDF；扫描件走 OCR 慢路径；
- **Python MIME Parser**：Newsletter Inbox Provider。

Crawl4AI 的 `max_pages_before_recycle` 只在 pinned release 行为测试通过后映射为 **Runtime Context recycle**，不得作为 Browser 进程级回收保证。

### 4.3 Extraction / Search

- **Trafilatura**：Generic Candidate；
- **lxml/BeautifulSoup**：DOM/XPath、Metadata、Repair；
- **JSON-LD/OpenGraph/Microdata**；
- **CSS/XPath/Regex Recipe**；
- **SimHash/MinHash**：近重复候选；
- **OpenSearch BM25 + pgvector + RRF**；
- embedding/reranker/LLM 仅作可选增强。

## 6. Source 接入与声明式配置

新增网站先自动探测，再人工确认并发布 immutable Source Profile Release：

```text
1. exact-host robots / Sitemap / Feed
2. CMS 特征：WordPress/Ghost/Medium/Substack/API
3. 首页与安全内容路径探测
4. Archive / Pagination / URL Pattern
5. Canonical / Redirect / Query 参数行为
6. Soft-404 baseline
7. HTTP vs Browser route sampling
8. metadata-only 子域候选发现
9. 人工审核 Content Host
10. Common Crawl / Wayback Gap inventory
11. Deep Crawl 浅层 Prefetch
12. 生成 Source Profile Draft
13. Capability Compile + Dry Run
14. 发布 immutable Source Profile Release
```

### 6.1 Source Profile 示例

```yaml

  canonical_domain: example.com
  approved_hosts:
    - host: example.com
      scheme: https
      type: CONTENT

providers:
  - sitemap
  - rss_atom
  - archive
  - common_crawl_gap
  - wayback_gap
  - deep_crawl

fetch:
  route: auto
  default: http
  browser_patterns:
    - /interactive/*
  page_timeout_ms: 30000
  wait_until: domcontentloaded
```

## 7. Discovery、Backfill 与 Coverage

### 7.1 Provider 顺序

```text
CMS/API
 -> Sitemap
 -> RSS/Atom
 -> Archive/Pagination
 -> HTML Listing
 -> Common Crawl / Wayback Historical Gap
 -> Safe Domain Recon Gap
 -> SafeProbe Content Paths
 -> Deep Crawl Prefetch
 -> External Search Gap
```

URL Inventory 是多个 Provider 的并集并保留 Observation 证据。高优 Provider 成功不能阻止其它 Provider 执行。

### 7.2 Backfill 主流程

```text
Source Approved
 -> Probe Authoritative Providers
 -> Initial URL Inventory
 -> Archive/Pagination
 -> CC/Wayback Gap
 -> Safe Domain Recon/SafeProbe
 -> Deep Crawl Prefetch Gap Scan
 -> Persistent Frontier
 -> Robots / Scope / Validity
 -> Fetch
 -> Result Materialize
 -> Raw Artifact
 -> Extract / Quality / IR / Markdown
 -> Coverage Reconcile
 -> Gap Review
 -> Backfill Complete
```

### 7.3 Backfill 完成条件

至少满足：

- 权威 Provider 完成或明确不可用；
- Historical Gap Provider 到达配置边界且有限制证据；
- Persistent Frontier 无 READY/LEASED/RETRY；
- Archive/Deep Crawl 无新增候选或达到可解释收敛；
- Runtime 多结果完整物化，无未解决 cardinality mismatch；
- 失败任务已成功、DLQ 或人工接受；
- Soft-404 疑似已确认/延期/接受；
- Known Gap 为空或人工接受；
- 多 Provider URL 集合差异在阈值内；
- 结束的 Runtime Slice、Context Generation 和 Browser Process Generation 已完成 Quiescence/终止要求。

**Prefetch count、Focused confidence、saturation、max_pages、low gain、Runtime Cache Hit、runtime depth/round 绝不能成为 Backfill Complete 充分条件。**

### 7.4 URL 规范化

```text
resolve relative
 -> normalize scheme
 -> lower host / IDNA
 -> remove default port
 -> strip fragment
 -> dot-segment normalize
 -> preserve path case
 -> preserve query case/order before Query Policy
 -> tracking parameter policy
 -> redirect evidence
 -> rel=canonical evidence
```

不提前任意删除 query 参数；按 Source 采样后发布 Query Policy Release。


## 11. Browser 生命周期：Context Generation 与 Process Generation

### 11.1 Runtime Context Generation

在当前 pinned Crawl4AI 行为中，`max_pages_before_recycle` 的可验证机制是：

```text
pages_served reaches threshold
 -> _browser_version bump
 -> Context signature changes
 -> new requests create/use new Context generation
 -> old Context refs drain
 -> old Context close
```

这可以释放 Context 级状态，但 **不作为 Browser PID/进程重启保证**。平台把它映射为 `runtime_context_recycle_pages`，只视为 Runtime 内部卫生策略。

### 11.2 Browser Process Generation

长期 Browser Worker 即使 Context 正常 close，仍可能发生 Browser/V8/共享缓存/进程碎片长期增长。进程级生命周期由平台拥有：

```text
ACTIVE P1
 -> pages/age/RSS/error threshold
 -> DRAINING P1 + ACTIVE P2
 -> P1 no-new-admission
 -> drain task/page/context/session refs
 -> QUIESCED P1
 -> crawler.close()/terminate process or Pod
 -> verify old PID gone
 -> TERMINATED P1
```

推荐阈值：

```text
process_generation_max_pages
process_generation_max_age
process_generation_max_rss
process_generation_max_consecutive_errors
max_draining_process_generations
```

具体值经 Canary 和容量测试调优。

### 11.3 Quiescence 状态机

```text
RUNNING
 -> STOP_REQUESTED
 -> QUIESCING
 -> QUIESCED
 -> STOPPED
```

“停止派发”“async generator 返回”“Context version bump”都不等于 Runtime 已静默。

### 11.4 Cleanup Protocol

Cancel/Pause/Lease Lost/Recycle/Shutdown：

```text
1. stop local admission
2. cancel unfinished runtime tasks
3. await active tasks with grace timeout
4. drain local queue
5. close/release page/context/session
6. cancel/await helper and monitor tasks
7. release Redis domain/browser/resource tokens
8. flush cleanup evidence
9. verify counters == 0
10. mark QUIESCED
```

必须满足：

```text
active_tasks == 0
local_queue == 0
pages == 0
contexts == 0
sessions == 0
held_tokens == 0
```

Process Generation 关闭还必须满足旧 `browser_pid_set` 已退出。

### 11.5 Drain Timeout

```text
TIMED_OUT
 -> kill isolated worker/process/Pod
 -> fencing rejects late commit
 -> lease expires/releases
 -> unfinished URL RETRY
 -> incident metric
```

### 11.6 状态隔离

```text
isolation_key = tenant + source_lane + runtime_config_release + process_generation
```

普通公开博客禁止跨 Tenant/Source 共享 Cookie/localStorage/sessionStorage，禁止 Web 用户指定 CDP/user-data-dir/context-id/target-id，未 QUIESCED 的状态不能进入公共复用池。认证站点使用独立 `AUTHENTICATED_SOURCE` Lane。

### 19.6 Runtime Quiescence

关闭部分消费的 stream 后验证：active task 全 done/cancelled、queued item drained、page/context/session/token 为 0。再验证 cleanup timeout -> worker killed、fencing 拒绝 late commit、unfinished URL -> RETRY、未 quiesced runtime 禁止复用。

### 19.7 Context Generation Contract

```text
runtime_context_recycle_pages threshold -> _browser_version/signature changes
old Context refs -> 0 then context closes
new requests use new Context generation
concurrency causes no URL loss/duplicate commit
this test MUST NOT claim browser PID replaced
```

### 19.8 Browser Process Generation Contract

```text
pages threshold -> P1 draining + P2 active
age threshold -> process generation switch
RSS threshold -> process generation switch
error threshold -> process generation switch
new tasks never enter P1 after draining
P1 refs=0 -> old Browser PID exits
P2 browser PID/process identity differs from P1
RSS baseline re-established after process replacement
max draining process generations bounded
drain timeout -> kill + fencing
state never crosses isolation_key
```

只有明确验证旧 PID 退出、新 PID/进程实例不同，才能把某能力标记为 `VERIFIED_EFFECTIVE_AS_PROCESS_RECYCLE`。

## 22. 验收标准

平台达到生产可用至少满足：

1. 新增标准博客主要通过 Web Source Profile 完成，不新增独立爬虫脚本；
2. 新 host 未经批准不能主动抓取；
3. 任意 Source 可执行全历史 Backfill，并解释 Coverage、Historical Gap、Known Gap；
4. CC/Wayback/Focused confidence/Prefetch count 不被误当完整性证明；
5. 任意 URL 可解释 Provider、Observation、Graph Depth、Filter、Admission、Validity、Frontier；
6. SPA/自定义 404 不会仅因 HTTP 200/Runtime success 进入正文库；
7. URL Normalizer 默认保留 path/query 大小写语义；
8. Worker 任意 kill 后不丢业务 Frontier，可通过 Lease 恢复；
9. Runtime local queue/cache/session 丢失仍可从 PostgreSQL/Object Storage 重建；
10. `max_pages`、低 score、low gain、Provider timeout 不让历史候选静默消失；
11. CrawlResult Container/Stream 多结果全部显式物化；
12. 批量/流式乱序和部分失败按 attempt/url identity 正确关联；
13. Runtime cardinality/schema drift 被 Contract Test 检测并阻断上线；
14. `prefetch=True` 只产生 Discovery Observation；
15. 点击停止后停止新 Admission，并最终 Runtime QUIESCED；
16. STOPPED 时 task/page/context/session/local queue/token 为 0；
17. cleanup timeout 后 Worker 被隔离，late commit 被 fencing 拒绝；
18. Runtime Context recycle 能按 pinned 行为完成 version/signature 切换和旧 Context 排空；
19. Runtime Context recycle 不被误报为 Browser 进程已重启；
20. Browser Process Generation 能按 pages/age/RSS/errors 轮换；
21. Process Generation DRAINING 后不接新任务；
22. 旧 Process Generation 正常关闭时有旧 Browser PID 已退出证据；
23. Process drain timeout 可 kill，未完成 URL 可安全 RETRY；
24. Process replacement 后新进程身份/PID 与旧代不同并重新建立 RSS 基线；
25. Browser 状态、Cookie、CDP、持久 Context 不跨 Tenant/Source isolation key；
26. Raw Artifact 可重放新 IR/Markdown，不必重新抓网页；
27. Incremental 通过 RSS/Sitemap/CMS/Conditional GET 持续同步；
28. Markdown 保留标题、正文、代码、表格、列表等关键结构并通过质量门禁；
29. Search Index 可从 Canonical 数据重建；
30. 改变结果、权限、Runtime Schema/生命周期的组件均有 Release 和 Golden/Contract/Posture Test；
31. Web Admin 可完成接入、审核、Backfill、Incremental、Coverage、失败诊断、暂停/恢复/停止和审计；
32. Web/API 不能直接提交 JS、browser extra_args、proxy、CDP、user-data-dir、cookies、任意 Runtime Strategy；
33. 不可信配置不能读取服务端环境变量 Secret；
34. 外部配置都有 compilation report，显示 accepted/rejected/clamped/injected；
35. request/principal/queue 超限分别有 413/429/503 语义；
36. page/http/browser/process/model/evidence 硬预算 overshoot 为 0；
37. caller 不能指定服务器文件系统输出路径；
38. 临时 Screenshot/PDF/Trace/MHTML/Network/Console 使用 opaque artifact id、RBAC、TTL、quota；
39. normal PASS 不默认永久保存重型诊断证据；
40. Runtime Cache 不推进 Cursor，不改变 Coverage/Version Truth；
41. Deep Crawl runtime depth/visited/queue 不替代平台 graph depth/Frontier；
42. Browser Runtime 不默认绕过登录墙、付费墙、CAPTCHA 或 WAF；
43. 未 QUIESCED 的 Runtime/Process Generation 不能回到复用池；
44. Redis/PostgreSQL/MinIO/Browser Runtime 不直接公网暴露；
45. 第三方 Runtime 配置只有经过 pinned-release 行为验证才可作为生产硬控制；
46. Source/Run/Task/URL/Attempt/RuntimeResult/Artifact/Version 全链路有 correlation/trace；
47. 系统能够从 1000 站扩展到更多站点，而不引入线性数量的专用爬虫代码。

最终架构原则：

> **权威 Provider 建 URL Inventory，Common Crawl / Wayback / Deep Crawl 只补 Coverage Gap；Observation 与 URL Edge 先于选择，Approved Scope 与 RFC 9309 Robots 先于主动访问，Persistent Frontier、Lease/Fencing 与平台 Graph Depth 保证不丢不串；外部配置一律 UNTRUSTED，经 Capability Firewall 与 Config Compiler 才变成 Runtime 能力；Runtime Container/Stream 先完整物化，Prefetch 只产生 Observation；HTTP First、Browser Slow Lane，Crawl4AI Context recycle 只作为 Context 级卫生策略，真正 Browser 进程/Pod 代际由平台以 pages/age/RSS/error 阈值、Quiescence、PID 退出证据和 fencing 管理；Raw Artifact 与 Diagnostic Evidence 分层治理；Canonical IR 生成稳定 Markdown；PostgreSQL + Object Storage 始终拥有业务真相。**
