# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站、公开 Newsletter** 的长期知识库采集平台，可平滑扩展到数千站点、百万级到千万级文章。

系统必须满足：

1. **全历史回填**：尽可能完整发现并抓取每个已批准 Source 的历史文章，并能解释未知与已知缺口；
2. **持续增量同步**：发现新文章、正文更新、URL 迁移、重定向、删除与重发布；
3. **稳定 Markdown**：Markdown 由可追溯 Raw Artifact 经过确定性抽取、质量门禁、Canonical IR 后生成；
4. **低成本扩站**：新增网站优先通过 Source Profile、Provider、Traversal Policy、Extraction Recipe 配置完成，不复制 1000 份站点脚本；
5. **Web 可运营**：支持 Source 接入、审核、Backfill、Incremental、Coverage、Frontier、失败诊断、暂停/恢复/停止、质量、成本和审计；
6. **可搜索与 RAG**：支持关键词、向量、混合检索，并能回溯原文、版本和抓取证据；
7. **可观测、可恢复、可重放**：任意 URL、任务、Artifact、Markdown 都能解释来源、版本和执行路径；
8. **渐进扩展**：开发期 Docker Compose，生产期按队列和 Worker 类型水平扩容；
9. **主链不依赖 LLM**：LLM 仅用于可选增强，不参与 Coverage Truth、URL Identity、Canonical URL 的最终判定。

### 1.1 核心 SLO

- **Coverage**：每个 Source 能解释 Provider、已发现 URL、Frontier、Known Gap 与 Backfill 停止原因；
- **Freshness**：新文章从发布/发现到 PASS Markdown 的延迟；
- **TTFM**：URL 首次发现到首个可用 Markdown 的时间；
- **Extraction Quality**：标题、正文完整率、噪声率、代码块/表格/列表保留率、截断率；
- **Reliability**：任务成功率、Retry、DLQ、Queue Age、Lease Recovery、Checkpoint Resume 成功率；
- **Browser Efficiency**：HTTP 命中率、Browser avoided、Browser recovery、每文档 Browser 成本；
- **Identity Quality**：重复文章误合并/漏合并率；
- **Validity Quality**：Soft-404、假 200、空壳 SPA 的识别准确率；
- **Traceability**：任意 Markdown 可回溯 Source、URL、Artifact、Extractor、Quality、Renderer Release；
- **Cancellation**：停止请求到不再领取新任务、到 Run 完全 STOPPED 的延迟；
- **Cost**：按 Source、Run、Queue Class、每 1000 篇 PASS 文档统计抓取、Browser、存储、索引和模型成本。

### 1.2 非目标

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不把 HTTP 200、DOM 很长或 crawler success 直接视为正文正确；
- 不把搜索结果数、Common Crawl、Wayback、Deep Crawl 页数或 `max_pages` 当历史完整性证明；
- 不把 Crawl4AI 即时 Markdown、LLM 摘要或改写直接作为 Canonical Markdown；
- 不因 URL 曾抓过就永久停止复检；
- 不把 Redis、Browser Session、Crawler Cache、Visited Set、Dispatcher Queue、Search Index 当业务真相；
- 不允许优先级、Scorer、相关性阈值或执行预算永久删除潜在历史文章；
- 不默认对所有文档构建 GraphRAG。

## 2. 核心设计原则

1. **Coverage First**：先建立 URL Inventory，再批量抓正文；
2. **Authoritative First**：CMS/API、Sitemap、RSS/Atom、官方 Archive 优先；
3. **Historical Gap Is Evidence, Not Truth**：Common Crawl、Wayback 用于历史补洞，不作为完整性证明；
4. **Deep Crawl Is Gap Provider**：站内深度抓取用于补洞，不作为 Coverage Truth；
5. **Discovery / Fetch / Extract / Quality / Projection 分离**；
6. **HTTP First, Browser Last**：Browser 是受治理慢路径；
7. **Snapshot First**：先保存不可变 Artifact，再抽取与清洗；
8. **Canonical IR First, Markdown as Projection**；
9. **Recipe, Not 1000 Site Scripts**；
10. **Stable Identity**：Source、Host、URL、Artifact、Document、Version 使用稳定 ID；
11. **Idempotent + Recoverable**：任务使用幂等键、lease、fencing token、checkpoint；
12. **Fair by Default**：大站 Backfill 不能饿死 Incremental 和小站；
13. **Bounded Concurrency Everywhere**：禁止无界 asyncio gather、Browser Context、LLM fan-out；
14. **No Silent Degradation**：截断、预算耗尽、降级、过滤、跳过必须显式记录原因；
15. **Release Everything That Changes Results**：Profile、Provider、Traversal、Recipe、Runtime、Extractor、Quality、Renderer、Embedding、Rank 全部版本化；
16. **Priority Means When, Not Whether**：优先级决定何时处理，不决定是否永久保存；
17. **Observation Before Selection**：观察到链接后先保存事实，再做 Filter/Score/Budget 选择；
18. **Persistent Frontier, Not In-Memory Traversal**：BFS/DFS/Best-First 的业务语义进入数据库；
19. **Runtime Checkpoint != Business Checkpoint**：第三方 crawler resume state 只是执行优化，PostgreSQL 才是恢复真相；
20. **Cooperative Cancellation**：停止是状态机，不把点击停止等同于所有 in-flight 工作已经结束；
21. **Approved Scope First**：发现子域、路径或外部归档 URL 不等于允许主动访问；
22. **Soft-404 Is First-class**：URL 存在性不能只依赖 HTTP 状态码；
23. **Global Admission + Local Adaptation**：跨 Worker 公平/限流由平台负责，Worker 内存自保护由运行时负责；
24. **Same Semantics, Different Topology**：单机 Pilot 与生产集群共享状态机、模型和任务协议；
25. **Runtime Result Is Advisory**：第三方 crawler 的 `status`、dedup、score、limit、timeout、cache 只能作为运行时结果，不可直接升级为平台业务真相；
26. **Normalize Conservatively**：scheme/host 可标准化，path/query 默认保留大小写与原始语义，只有 Source Policy 有证据时才进一步归一化；
27. **Explicit Runtime Capabilities**：生产配置不得依赖第三方 crawler 默认 source/path 集，必须由平台显式编译允许启用的网络行为；
28. **Robots Policy Is Access Control Input**：robots 访问判定由平台 RFC 9309 Policy Engine 负责，发现工具的简化解析不能替代访问决策。

```text

       |                              |                               |

       |                              |                               |

       +------- Observation -> Persistent URL Inventory / Frontier --+
                                      |

                                      |

                                      |
```

### 3.1 业务真相边界

**PostgreSQL + Object Storage 是业务真相。**

- PostgreSQL：Source、Approved Host、Provider、URL Identity、URL Observation、Robots Policy、Validity、Crawl Frontier、Task、Cursor、Coverage、Quality、Document、Version、Release、Checkpoint Pointer、Audit；
- S3/MinIO：Raw HTML、MHTML、截图、Trace、Provider Evidence、Candidate、IR、Markdown、PDF、Runtime Checkpoint State、Enrichment；
- Redis Streams：任务运输、Consumer Group、Backpressure、分布式 token bucket，不保存不可替代业务状态；
- OpenSearch / pgvector：可重建 Serving Projection；
- Crawl4AI local cache、dispatcher queue、rate limiter、Browser Session、Playwright Context、Worker 内存：易失执行状态。

## 4. 技术选型

### 4.1 控制面

- **FastAPI + Pydantic**：REST API、Command、Schema 校验；
- **PostgreSQL**：Truth Store、任务、Coverage、Frontier、版本、审计；
- **Redis Streams**：任务运输、Consumer Group、Backpressure；
- **Redis Lua Token Bucket / Semaphore**：跨 Worker 域名限流和资源令牌；
- **React / Next.js + TypeScript**：Web 管理后台；
- **OpenTelemetry + Prometheus + Grafana + Structured Logging**：Trace / Metric / Log；
- **S3/MinIO**：不可变对象存储；
- **Vault/KMS/Secret Manager**：凭据引用。

### 4.2 Discovery / Fetch

- **httpx/aiohttp**：robots、Sitemap、Feed、CMS API、Conditional GET、普通网页、平台 SafeProbe；
- **RFC 9309 兼容 Robots Parser/Policy Engine**：User-Agent group、最长匹配、Allow/Disallow 访问判定与缓存；
- **Crawl4AI**：Domain Mapping、AsyncUrlSeeder、Browser Render、Deep Crawl Prefetch、动态链接发现、多 URL 执行；
- **Crawl4AI MemoryAdaptiveDispatcher**：Browser Worker 本地内存自保护与有界并发；
- **Playwright Python**：复杂多步、有状态、需要 Step 级恢复的交互；
- **Common Crawl Adapter**：公共历史索引补洞；
- **Wayback CDX Adapter**：历史 URL 补洞，支持分页/时间窗口；
- **SearXNG / 合规 Search API Adapter**：External Search Gap、新 Source Candidate；
- **PyMuPDF/pdftotext**：PDF；扫描件进入 OCR 慢路径；
- **Python email/MIME parser**：Newsletter Inbox Provider。

### 4.3 Extraction / Search

- **Trafilatura**：Generic Main Content Candidate；
- **lxml/BeautifulSoup**：DOM/XPath、Metadata、DOM Repair；
- **JSON-LD/OpenGraph/Microdata**：结构化元数据；
- **CSS/XPath/Regex Recipe**：确定性正文与字段抽取；
- **SimHash/MinHash**：近重复候选；
- **OpenSearch BM25 + pgvector + RRF**：混合检索；
- **可选 reranker / LLM**：只在 Canonical 数据之后运行。

### 4.4 Release 冻结

必须记录：

```text
runtime_release
source_profile_release
host_scope_release
robots_policy_release
provider_adapter_release
traversal_policy_release
interaction_recipe_release
extractor_release
validity_release
quality_release
identity_release
renderer_release
embedding_release

```

任何改变结果的升级必须经过 Golden Replay / Offline Eval，必要时 Canary。Crawler 运行时必须 pin 到经过验证的 immutable release，不使用浮动 latest。

## 6. Source 接入流程

新增网站先自动探测，再人工确认并发布 immutable Source Profile Release。

### 6.1 接入探测顺序

```text
1. Exact-host robots.txt / Sitemap / Feed
2. CMS 特征：WordPress/Ghost/Medium/Substack/自建 API
3. 首页与平台 SafeProbe 内容路径探测
4. Archive / Pagination / URL Pattern
5. Canonical / Redirect / Query 参数行为
6. Soft-404 baseline
7. HTTP vs Browser route sampling
8. 可选 metadata-only 子域候选发现
9. 人工审核 Content Host
10. Common Crawl / Wayback 历史 Gap inventory
11. Deep Crawl 浅层 Prefetch
12. 发布 Source Profile Release
```

### 6.2 Domain Recon 的安全边界

DomainMapper 的能力不能原样开放给 Web 用户。平台包装 `DomainReconAdapter`：

- 默认 `include_subdomains=false`；
- **显式编译 `source` allowlist，禁止依赖 DomainMapper 默认 `sitemap+cc+crt+probe`；**
- 第三方 approved exact-host 默认只允许 `sitemap+feed+homepage` 这一类低风险运行时来源；
- 子域发现优先通过 metadata-only CT / Archive Adapter 只生成 `host_candidate`；
- 未批准 host 不允许触发 DomainMapper 的主动 HEAD/GET 验证或正文抓取；
- 只有批准为 CONTENT 后才可做 exact-host Domain Recon；
- **第三方 Source 禁用 DomainMapper 原生 `probe` source。当前源码中 `config.probe_paths` 只追加到 `DEFAULT_PROBE_PATHS`，不能替换默认 `/api`、`/login`、`/dashboard`、`/graphql`、`/health` 等路径；**
- **第三方 Source 同时禁用 DomainMapper 原生 `robots` source。当前源码中启用 `robots` 也会进入 Probe 分支并从完整 `DEFAULT_PROBE_PATHS` 开始；**
- 内容型路径探测统一交给平台 `SafeProbeAdapter`，只允许 `/blog`、`/posts`、`/articles`、`/news`、`/engineering`、`/tech`、`/archive` 等 Source Profile allowlist；
- robots 的 `Sitemap:` 可被 Sitemap Provider 用于发现；`Allow/Disallow` 由平台 RFC 9309 `RobotsPolicyEngine` 计算访问权限，不能变成主动 probe 候选；
- 每次 DNS resolve 与 redirect 每一跳都重新做 SSRF / approved scope 校验；
- 所有目标仍经过全局 token bucket、Source/Host scope 与 audit。

只有在维护经过审计的 Crawl4AI fork/patch，并能**替换**而不是追加默认 probe path 集时，才允许重新启用 DomainMapper 原生 `probe`。

### 6.3 Source Profile 示例

```yaml
source:
  canonical_domain: example.com
  approved_hosts:
    - host: example.com
      scheme: https
      type: CONTENT
  providers:
    - sitemap
    - rss_atom

    - common_crawl_gap
    - wayback_gap
    - safe_probe
    - deep_crawl
  fetch_route:
    default: http
    browser_patterns:
      - /interactive/*
  robots:
    engine: rfc9309
    user_agent_product_token: MyKnowledgeBot
  recon:
    runtime_sources:
      - sitemap
      - feed
      - homepage
    include_subdomains: false
    enable_domainmapper_probe: false
    enable_domainmapper_robots: false
    extract_head: false
    max_urls: -1
  safe_probe:
    paths:
      - /blog

      - /articles

  traversal:
```

### 6.4 Seed 与主动访问安全校验

创建 Run 或 SafeProbe 前必须验证：

```text
seed 属于 approved CONTENT host
scheme 为 http/https
Source enabled
RFC 9309 robots/access policy 已计算
Traversal/Provider Policy 已发布
SSRF destination validation 通过
DNS resolved IP 不在禁止网段
redirect 每一跳仍在 approved scope
凭据/代理策略合法
```

## 7. Discovery 与 Coverage

### 7.1 Provider 优先级

```text
CMS/API
 -> Sitemap
 -> RSS/Atom
 -> Archive/Pagination
 -> HTML Listing
 -> Common Crawl / Wayback Historical Gap
 -> Safe Domain Recon Gap
 -> SafeProbe Content Paths
 -> Deep Crawl Prefetch
 -> External Search Gap
```

高优 Provider 的结果不能阻止其它 Provider 执行。最终 URL Inventory 是多个 Provider 的集合并集，并保留每条 Observation 的来源证据。

### 7.2 Backfill 流程

```text
Source Approved
 -> Probe Authoritative Providers
 -> Build Initial URL Inventory
 -> Archive/Pagination Enumeration
 -> Common Crawl / Wayback Historical Gap
 -> Safe Domain Recon Gap
 -> SafeProbe Content Paths
 -> Deep Crawl Gap Scan
 -> Persistent Frontier
 -> Robots Policy / URL Validity Gate
 -> Fetch
 -> Extract / Quality / IR / Markdown
 -> Coverage Reconcile
 -> Gap Review
 -> Backfill Complete
```

### 7.3 Historical Gap Provider

#### Common Crawl

用于发现当前站点已经不再链接的旧 URL。结果必须回源验证，不直接认定为当前有效文章。

Common Crawl 必须作为独立 `common_crawl_gap` Provider 管理索引范围、窗口、cursor 和 URL-level Observation。不能假设 DomainMapper 的 `cc` source 等价于全历史 Common Crawl URL Provider；当前源码检查中其 CC 路径明确参与 host discovery，但未看到与 Wayback `_wayback_urls` 对称的 URL merge 主路径。

#### Wayback CDX

不能只做单次 `limit=10000` 查询。大型站点按以下方式切片：

```text
year window
URL prefix
CDX page/resume key
```

每个窗口有独立 `provider_run` 和 cursor，确保可恢复、可审计。Wayback observation 只证明历史上出现过该 URL，不证明当前有效。

### 7.4 Coverage Ledger

```text
coverage_snapshot
- source_id
- provider_run_id
- provider_type
- discovered_count
- unique_url_count
- article_candidate_count
- fetched_count
- pass_count
- failed_count
- deferred_count
- soft404_suspected_count
- known_gap_count
- stop_reason
- captured_at
```

### 7.5 Backfill 完成条件

至少满足：

- 权威 Provider 已完成或明确不可用；
- Historical Gap Provider 已运行到配置边界并记录限制；
- Persistent Frontier 无 READY/LEASED/RETRY；
- Deep Crawl / Archive 不再产生新增文章候选，或达到明确可解释的收敛条件；
- 失败任务全部成功、进入 DLQ 或被人工接受；
- Soft-404 疑似批次已经确认、延期或人工接受；
- Known Gap 为空或被人工接受；
- 多 Provider URL 集合差异处于阈值内。

### 7.6 URL 规范化

```text
resolve relative
 -> normalize scheme
 -> lower host / IDNA
 -> remove default port
 -> strip fragment
 -> normalize dot segments
 -> preserve path case by default
 -> preserve query case/order before Query Policy
 -> tracking parameter policy
 -> redirect identity
 -> rel=canonical evidence
```

规则：

- host 大小写不敏感，可以 lowercase；
- path/query 默认不能整体 lowercase，HTTP path 在实际服务中可能大小写敏感；
- 不要过早删除 query 参数；
- 每个 Source 先采样生成 Query Policy，再发布 release；
- 保存 `raw_url`、`runtime_normalized_url`、`platform_normalized_url`，第三方 crawler dedup 不直接作为业务 Identity。

## 8. Domain Mapping、Robots 与 Safe Recon

### 8.1 角色定位

Domain Mapping 只用于：

- approved exact-host 接入期识别 Sitemap、Feed、首页结构；
- 发现当前 Sitemap 漏掉的低风险内容入口；
- 在独立 metadata-only Adapter 已发现并批准 host 后进行结构勘探；
- 建立 Soft-404 行为基线；
- 周期性发现站点结构变化。

它不用于：

- 自动扩大 approved scope；
- 把所有证书子域当抓取目标；
- 探测管理、登录、调试或内部接口；
- 证明历史完整；
- 替代独立 Sitemap / Feed / Common Crawl / Wayback Provider；
- 提供最终 URL Identity 或当前 URL Validity Truth；
- 提供最终 robots 访问许可。

### 8.2 多源结果处理

上游运行时可能把同一 URL 的来源合并为一个字符串，平台必须拆开保存原始 Provider Observation：

```text
同一 URL
- sitemap observation
- homepage observation
- wayback observation
- common_crawl observation
```

随后平台 URL Identity 再做去重。

不能直接复用 DomainMapper 的 dedup key 作为业务身份。当前源码会对 `normalized.rstrip("/")` 后的完整 URL 做 `.lower()`，可能错误合并大小写敏感 path/query。

### 8.3 Nonsense Filter 与内容类型

运行时可以过滤静态资源、webpack chunk 等噪声，但平台要区分：

```text
Observation Evidence
vs
Content Type Classification
vs
Article Admission
```

DomainMapper 的 asset extension 列表包含 PDF、Office 文档等。对于 PDF-heavy 技术站，这些可能是知识库内容，不应被 blanket filter 永久丢弃。

建议：

```text
CONTENT_HTML
CONTENT_PDF
ATTACHMENT
ASSET
UNKNOWN
```

纯 HTML 博客可在 Recon Preview 开启 `filter_nonsense_urls`；文档型 Source 应由平台 Content Policy 决定，Filter reason 必须可解释。

### 8.4 Runtime `status` 不是业务有效性

DomainMapper 结果里的 `status="valid"` 只表示运行时发现流程状态，不能直接映射到平台 `VALID`。

特别是：

- Wayback URL 会被直接并入结果并标记为 `valid`，但没有逐 URL live validation；
- `extract_head=false` 时，大量 Sitemap/Feed/Homepage 候选不会发生后续逐 URL metadata fetch；
- Host HEAD 可收到 403/404 仍可能被视为 reachable host。

所有候选统一走：

```text
URL Observation
 -> Approved Scope
 -> Robots Policy
 -> URL Validity Gate
 -> Fetch Admission
```

### 8.5 Soft-404：runtime advisory + platform profile

DomainMapper 使用一个随机不存在路径建立指纹，核心比较为：

```text
HTTP 200
first 2048 bytes MD5 exact match
or exact title match
```

这对固定 SPA shell 很有效，但平台需要更稳健：

```text
2~3 random probes
redirect_chain
normalized title
text SimHash
DOM structure hash
content length bucket
canonical target
main text length
error token features
```

当 Sitemap 大批 URL 被上游抽样判 Soft-404 时，平台必须保留全部 Sitemap Observation，只允许延迟 admission，不能把已发现 URL 从 Inventory 删除。

### 8.6 Full-history / Coverage Recon 的 DomainMapper 配置契约

第三方 approved exact-host 的 Safe Domain Recon 默认编译为：

```yaml
source: sitemap+feed+homepage
include_subdomains: false
extract_head: false
query: null
score_threshold: null
max_urls: -1
soft_404_detection: true
```

说明：

- **必须显式传 `source`，不能依赖上游默认 `sitemap+cc+crt+probe`；**
- `probe` 与 `robots` source 在第三方 Source 上默认禁止；
- Sitemap、RSS、Common Crawl、Wayback 长期同步仍走独立 Provider，DomainMapper 只是 bounded recon；
- `extract_head=true` 会为大量 URL 额外产生 metadata 请求，只用于小样本 Onboarding / Focused UI；
- `query` / `score_threshold` 只用于 focused job，不用于全历史过滤；
- `max_urls` 只能作为 UI/临时预算，不能成为 Coverage 边界；
- score 必须先落 Observation，再映射为 scheduler priority；
- `source_timeout` 超时记为 `PARTIAL/TIMED_OUT`，不能记作 Provider COMPLETE。

### 8.7 限流与并发契约

DomainMapper 的 `hits_per_sec` 当前通过 `asyncio.Semaphore` 实现，本质上更接近在途并发上限，不是严格按秒计数的 RPS。

同时源码会并行：

- host discovery sources；
- candidate host validation；
- 多 host `_scan_host()`；
- probe paths；
- DNS prefixes；
- head extraction。

因此平台必须外包一层有界执行：

```text
Fair Scheduler
 -> Redis per-domain token bucket
 -> bounded DomainRecon exact-host slice
 -> Worker semaphore
 -> DomainMapper
```

SafeProbe 走独立链路：

```text
RobotsPolicyEngine
 -> approved exact-host
 -> content path allowlist
 -> Redis per-domain token bucket
 -> bounded HEAD/GET
 -> Observation
```

禁止把 `hits_per_sec` 或 `config.concurrency` 当作整个平台的统一限流器。

### 8.8 Host Candidate 与 Active Recon 分离

当前 DomainMapper 会对发现的 host 主动做 HTTP HEAD validation。为了防止 CT/DNS 发现 staging/admin 等 host 后立即产生主动请求，平台必须区分：

```text
Metadata-only Host Discovery
 -> host_candidate
 -> APPROVED_CONTENT review
 -> Exact-host Active Recon
```

Metadata-only 阶段由独立 CT / Archive / DNS Evidence Adapter 完成，不直接调用全域 DomainMapper active scan。

Host Scope 还要保存：

```text
preferred_scheme
canonical_origin
redirect_origin
```

因为 DomainMapper 的 Soft-404、Probe、Feed、Homepage 多处直接构造 HTTPS URL，HTTP-only / 特殊 origin 需要平台先确定实际 origin。

### 8.9 第三方配置与版本行为要回归验证

配置字段不能只看名字判断能力。对每个 Crawl4AI runtime release 建立行为测试：

```text
config -> actual network requests
config -> actual filtering
config -> actual browser/http route
config -> actual timeout/limit semantics
```

例如当前源码检查中，`use_browser_for_homepage` 能在配置/文档中找到，但 DomainMapper 的 homepage 实现路径仍主要使用 HTTP client；升级前后必须用 Golden Test 验证真实行为。

### 8.10 DomainMapper 原生 Probe 的强制禁用规则

当前实现中：

```text
probe_paths = DEFAULT_PROBE_PATHS
if config.probe_paths:
    probe_paths.extend(config.probe_paths)
```

所以 `probe_paths` 是扩展点，不是替换点。第三方站点即使只配置 `/blog`、`/archive`，上游仍会探测默认 `/login`、`/dashboard`、`/api`、`/graphql`、`/health` 等路径。

平台强制规则：

```text
third_party_source && runtime == DomainMapper
 -> source MUST NOT contain probe
```

如未来升级/自维护 patch 提供“完全替换默认 probe path”的能力，必须通过 Golden Network Trace 验证后才能发布新的 `provider_adapter_release`。

### 8.11 DomainMapper `robots` source 不是 RobotsPolicyEngine

源码中：

```text
if "probe" in sources or "robots" in sources:
    probe_paths = DEFAULT_PROBE_PATHS
    ...
    if "robots" in sources:
        probe_paths += disallow/allow paths
```

因此 `source=robots` 会触发主动 Probe，并不能作为“只读取 robots.txt”的安全模式。

同时 DomainMapper 的 robots path 提取不负责 RFC 9309 完整 User-Agent group 和最长匹配访问判定。平台强制规则：

```text
third_party_source && runtime == DomainMapper
 -> source MUST NOT contain robots

robots.txt
 -> platform RobotsPolicyEngine
 -> versioned ALLOW/DENY/UNKNOWN
```

Sitemap Provider 可以读取 `Sitemap:` 扩展字段，但 `Allow/Disallow` 只进入访问策略，不变成 URL Probe 输入。

### 8.12 DomainMapper Scan 不是业务级 Streaming Checkpoint

`scan()` 会聚合多 host 结果到内存 List，再统一 normalize/dedup/head/score/limit。它适合 bounded recon，不适合把大型历史 Provider 当一个不可分割任务。

平台规则：

- DomainMapper 每次只跑小规模 exact-host recon slice；
- 大 Sitemap / CC / Wayback 使用独立分页 Provider，发现一批就 durable 写 Observation/cursor；
- DomainMapper crash 可以安全重跑当前 bounded slice；
- DomainMapper cache、内存结果、运行时 dedup 均不是业务 checkpoint。

## 9. Deep Crawl 与 Traversal Policy

### 9.1 角色定位

Deep Crawl 只用于：

- 发现 Sitemap/RSS/API 漏掉的站内 URL；
- 发现归档、分页、标签、年份入口；
- 验证导航结构与 URL pattern；
- 处理 JS 动态链接；
- 定期执行 Coverage Gap 扫描。

不用于证明历史已经完整。

### 9.2 两阶段 Prefetch

```text
Phase A: Prefetch Discovery
- 获取 HTML / links / minimal metadata
- 记录 from_url -> to_url Observation
- 跳过 Markdown / LLM / 重型抽取
- 形成 Persistent Frontier

Phase B: Full Processing
- Fetch Raw Artifact
- URL Validity
- Extraction / Quality / IR / Markdown
```

若 HTTP/Sitemap 已能完成发现，优先不用 Browser Prefetch。

### 9.3 Observation Before Selection

```text
Page Result
 -> Extract Raw Links
 -> Persist Observation
 -> Normalize / Scope Check
 -> Filter Reason
 -> Score
 -> Budget / Admission
 -> Persistent Frontier
 -> Runtime Slice
```

禁止先由 visited/threshold/max_pages 裁剪，再只保存被选中的 URL。

### 9.4 BFS / DFS / Best-First

- **BFS**：Backfill 默认探测策略；
- **DFS**：路径深度结构明确时启用；
- **Best-First**：固定预算下优先处理更像文章、归档、分页的 URL。

全历史模式统一解释：

```text
score -> priority
```

除明确 deny rule 或 focused job 外，不因低分永久删除 URL。

### 9.5 Bounded Slice

大型站点按 Source 切片：

```text
incremental_high: 立即调度
source A backfill: 200~500 URL slice
source B backfill: 200~500 URL slice
browser_slow: 独立慢队列
```

Slice 结束后未处理候选仍在 PostgreSQL Frontier。

### 9.6 Runtime Checkpoint 与 Business Checkpoint

```text
Crawl4AI resume_state = 执行优化
PostgreSQL crawl_frontier = 业务恢复真相
S3 Artifact = 抓取事实
Transactional Outbox = 状态与消息一致性
```

Runtime state 可周期性写 Object Storage，PostgreSQL 只保存 pointer、hash、release、captured_at。

### 9.7 协作式取消

```text
RUNNING
 -> STOP_REQUESTED
 -> DRAINING
 -> STOPPED
```

Scheduler 停止发新 lease；Worker 读取 cancellation token；in-flight Fetch 完成或超时；最后一次 durable commit 后释放 lease。

### 9.8 Crawl4AI Adapter

业务代码统一经 Adapter：

```text
validate_scope()
build_config()
build_fresh_filter_chain()
build_scorer()
discover_slice()
run_many_stream()
normalize_result()
emit_observations()
capture_runtime_checkpoint()
map_cancellation()
translate_error()
```

禁止业务代码依赖 Crawl4AI 内部 visited、queue、ContextVar 或 Browser 对象。

## 10. Fetch Plane

### 10.1 HTTP First

```text
HEAD/GET probe
 -> 普通 HTTP 成功且正文足够
    -> HTTP artifact
 -> JS shell / challenge / content incomplete
    -> Browser slow path
```

Browser 不是默认抓取器。

### 10.2 Conditional Fetch

增量复检使用：

```text
If-None-Match: ETag
If-Modified-Since: Last-Modified
```

`304` 不生成新正文版本，但更新 freshness observation。

### 10.3 Retry 分类

```text
DNS/TCP timeout       -> exponential retry
429                   -> Retry-After + domain throttle
5xx                   -> bounded retry
403/challenge         -> policy-based browser/proxy route
404/410               -> tombstone candidate, grace policy
soft-404 suspected    -> validity/repair queue
parse/extract failure -> repair queue，不等于必须 refetch
```

### 10.4 多层限流

每个域名维护：

```text
requests_per_second
burst
max_http_concurrency
max_browser_concurrency
retry_after_until
robots crawl-delay / local policy
```

职责分离：

```text
Redis Token Bucket       = 跨 Worker 精确节流
Worker Semaphore         = 本地并发保护
Crawler RateLimiter      = 429/503 自适应退避
MemoryAdaptiveDispatcher = Worker 内存压力保护
DomainMapper hits_per_sec= 运行时并发提示，不是严格 RPS
```

不能把本地 Semaphore 当作严格 RPS，也不能把进程内 RateLimiter 当跨 Worker 协调器。

### 10.5 Raw Artifact First

Fetch 成功后先写不可变对象：

```text
raw/{source_id}/{yyyy}/{mm}/{artifact_id}.html.gz
```

附 metadata：

```text
requested_url
final_url
status_code
headers
fetch_started_at
fetch_finished_at
runtime_release
proxy/session route
payload_sha256
trace_id
```

只有 Artifact durable 后，任务才能进入 EXTRACT。

## 11. Worker 本地自适应执行

### 11.1 Browser Worker

Browser Worker 从平台领取有限 Slice，再交给 Crawl4AI：

```text
DB/Redis Lease Slice
 -> arun_many(stream=true)
 -> MemoryAdaptiveDispatcher
 -> result-by-result durable commit
```

建议：

- `max_session_permit` 按容器内存、页面平均 RSS 和 Browser Context 成本压测标定；
- memory pressure 时停止领取新本地任务；
- critical pressure 允许本地重新排队，但平台 lease 仍有超时与 fencing；
- stream 关闭时 cancel + await 活跃 task，避免 Browser page/context 泄漏；
- 不等整批完成后再统一写结果。

### 11.2 Local Dispatcher 不是业务队列

Dispatcher Queue、local fairness、local retry 都是执行层优化。Worker 崩溃后恢复依据仍然是：

```text
PostgreSQL task/frontier
+ lease_until
+ fencing_token
+ durable artifact/checkpoint
```

## 12. 正文抽取、清洗与 Markdown

### 12.1 Extraction Portfolio

每个 Artifact 可产生多个 Candidate：

```text
recipe_css_xpath
structured_data
trafilatura
readability-like fallback
site-specific repair
browser rendered DOM fallback
```

不要直接选择第一个有文字的结果。

### 12.2 Candidate Quality Gate

核心指标：

```text
title_present
body_char_count
text_density
link_density
boilerplate_ratio
code_block_count
heading_count
table_count
image_count
published_time_confidence
truncation_signal
repeated_nav_signal
soft404_similarity
```

判定：

```text
PASS
REPAIR
REJECT_NOT_ARTICLE
REJECT_EMPTY
REJECT_BLOCKED
REJECT_SOFT_404
```

### 12.3 Canonical IR

Markdown 前生成稳定中间表示：

```text
document_id
title
authors
published_at
updated_at
canonical_url
blocks[]
  heading
  paragraph
  code
  list
  table
  quote
  image
```

这样 Renderer 升级不用重抓；Markdown、Preview、Chunk、Embedding 都从同一 IR 生成。

### 12.4 清洗规则

确定性移除：

- 顶部导航、页脚、Cookie banner、分享按钮；
- 推荐阅读、热门文章、站点通用 CTA；
- 评论区默认不入主正文；
- 重复标题、重复作者卡片；
- tracking 图片、1px beacon。

尽量保留：

- Heading 层级；
- Code Fence 与语言；
- 列表；
- 表格；
- Blockquote；
- 数学公式；
- 图片 alt / caption / 原始 URL；
- 内联链接。

### 12.5 Markdown Projection

Front Matter：

```yaml
---
document_id: ...
source_id: ...
title: ...
canonical_url: ...
published_at: ...
updated_at: ...
fetched_at: ...
content_hash: ...
version_id: ...
---
```

文件路径使用稳定 ID：

```text
md/{source_slug}/{yyyy}/{document_id}.md
```

标题只作为 metadata，避免改标题导致文件身份漂移。

### 12.6 版本判断

```text
same normalized content_hash -> 不生成新 Document Version
changed hash                 -> 新 Version，旧版本保留
```

广告、时间戳、推荐卡片变化应尽量在 IR 清洗前消除。

## 13. 增量同步

### 13.1 增量信号优先级

```text
RSS/Atom
 -> CMS API
 -> Sitemap lastmod
 -> Homepage / Archive probe
 -> Conditional recrawl
 -> Periodic Historical/Domain/Deep Gap Scan
```

### 13.2 自适应频率

```text
高频站：RSS 5~10m，主页 15~30m
普通站：RSS 30m，Sitemap 6h
低频站：Sitemap/Archive 12~24h
```

根据历史更新速率动态调节，不对 1000 站统一高频。

```text
读取 cursor
 -> 拉取一批
 -> 写 Observation / URL Inventory
 -> 创建 Fetch Task

```

失败时 cursor 不推进。

### 13.4 更新与删除

- 正文 hash 变化 -> 新 Document Version；
- canonical 迁移 -> identity merge / redirect evidence；
- 404/410 首次出现 -> `MISSING_SUSPECTED`；
- 多次确认或权威 API 明确删除 -> `TOMBSTONED`；
- 历史 Markdown 不物理删除，Serving Index 可隐藏 current tombstone。

### 13.5 周期性 Gap Scan

每个 Source 低频执行：

```text
Authoritative Provider Reconcile
+ Common Crawl / Wayback delta
+ Safe Domain Recon
+ SafeProbe content paths
+ shallow/deep prefetch
+ URL Inventory diff
```

## 14. Task、队列与可靠性

### 14.1 Task 类型

```text
DISCOVER_PROVIDER
DISCOVER_DOMAIN_RECON
DISCOVER_SAFE_PROBE
DISCOVER_HISTORICAL_GAP
DISCOVER_DEEP_SLICE
VALIDATE_ROBOTS
VALIDATE_URL
FETCH_HTTP
FETCH_BROWSER
EXTRACT
QUALITY
REPAIR
IDENTITY_RESOLVE
RENDER_MD
INDEX
ENRICH
RECONCILE_COVERAGE
```

### 14.2 幂等键

```text
DISCOVER: source_id + provider + run_id + cursor_window
ROBOTS:   hostname + user_agent_product_token + robots_policy_release + freshness_window
VALIDATE: url_id + validity_release + freshness_window
FETCH:    url_id + fetch_policy_release + freshness_window
EXTRACT:  artifact_id + extractor_release
RENDER:   document_version_id + renderer_release
INDEX:    document_version_id + retrieval_release
```

### 14.3 Lease + Fencing Token

```text
READY
 -> LEASED(owner, lease_until, fencing_token)
 -> DONE
 -> RETRY
 -> DLQ
```

## 19. 安全、合规与抓取礼仪

- 默认尊重 RFC 9309 robots/access policy，并把策略版本化；
- DomainMapper 的简化 robots path 提取不作为最终访问许可；
- `robots.txt Disallow/Allow` 都不转为主动 Probe；
- 第三方 Source 默认禁用 DomainMapper `probe` 与 `robots` source；
- SafeProbe 仅在 approved CONTENT exact-host 上、经 RobotsPolicy allow 后，对 Source Profile 内容路径 allowlist 执行；
- 不自动绕过登录、付费墙、CAPTCHA、明确禁止；
- approved CONTENT host allowlist，禁止自动扩大 scope；
- 未批准 host 的 CT/DNS/Archive 发现默认只保留 metadata evidence，不主动 HEAD/GET；
- 禁止任意 SSRF：loopback、RFC1918、link-local、云 metadata、file:// 等；
- DNS 解析得到的 IP 也做禁止网段校验；
- Redirect 每一跳重新解析并校验目的地，防止跳转/解析变化突破边界；
- Crawler Docker/API 只放内网，不直接暴露公网；
- Web 用户不能直接提交任意目标 URL、任意 JS hook 或任意 CrawlerRunConfig；
- JS execution、下载路径、webhook 等高风险能力默认关闭，确需启用时通过 Recipe allowlist；
- Browser 下载、文件协议、JS hook 按最小权限控制；
- 凭据只存 Secret Manager 引用；
- Proxy 使用有审计；
- 速率限制按域名、Source 和全局多层执行；
- Common Crawl/Wayback/CT 等第三方查询也纳入 egress、超时和审计；
- 删除/下线遵循数据保留策略和来源许可。

## 24. 验收标准

平台达到可生产使用至少满足：

1. 新增一个标准博客主要通过 Web Source Profile 完成，不新增独立爬虫脚本；
2. 新 host 只能以 Candidate 出现，未经批准不能主动抓取或主动 DomainMapper host validation；
3. 任意 Source 能执行全历史 Backfill，并解释 Coverage、Historical Gap 与 Known Gap；
4. Common Crawl/Wayback 只作为补洞证据，不被误当完整性证明；
5. Common Crawl 独立 Provider 能产生 URL-level Observation，不依赖 DomainMapper 的 host discovery 语义；
6. 任意发现 URL 都能解释 Provider、Filter、Score、Admission、Runtime Status、Platform Validity、Frontier 状态；
7. SPA/自定义 404 不会仅因 HTTP 200 大规模进入正文库；
8. Wayback/Runtime `status=valid` 不会绕过平台 Validity Gate；
9. URL Normalizer 默认保留 path/query 大小写语义，大小写敏感 URL 不被错误合并；
10. Worker 任意 kill 后不丢业务 Frontier，可通过 lease/checkpoint 恢复；
11. Crawl4AI local queue/cache/runtime state 丢失时仍可从 PostgreSQL/Object Storage 重建；
12. `max_pages`、`max_urls`、低 score、Provider timeout 不会让全历史候选静默消失；
13. 点击停止后立即停止发新 lease，并最终进入 STOPPED；
14. Browser Worker 内存压力可自动降低/暂停本地并发，且不会破坏平台任务状态；
15. DomainMapper `hits_per_sec` 不作为严格 RPS，跨 Worker RPS 可由全局 token bucket 验证；
16. HTTP-only / 特殊 origin 可通过 Source Host Scope 正确路由；
17. PDF-heavy Source 的内容文档不会被 runtime nonsense filter 永久丢弃；
18. 第三方 DomainMapper 配置不包含 `probe/robots`，不会因 `probe_paths` 只是追加项而意外探测 `/login`、`/dashboard`、`/graphql` 等默认路径；
19. robots 访问决策由 RFC 9309 兼容 Policy Engine 产生，User-Agent group 与最长匹配可测试、可解释；
20. DomainMapper bounded scan 失败可重跑，Coverage/cursor 不依赖其内存 List 或本地 cache；
21. Raw Artifact 可重放生成新的 IR/Markdown，不必重新抓网页；
22. Incremental 能通过 RSS/Sitemap/Conditional GET 持续同步新内容与更新；
23. Markdown 保留标题、正文、代码、表格、列表等关键结构并通过质量门禁；
24. Search Index 全部可从 Canonical 数据重建；
25. 所有改变结果的组件都有 release，并通过 Golden Replay 后发布；
26. Web Admin 能完成接入、审核、Backfill、Incremental、Coverage、失败诊断、暂停/恢复/停止和审计。

最终架构原则：

> **权威 Provider 建 Inventory，Common Crawl / Wayback / Safe Domain Recon / SafeProbe / Deep Crawl 补 Coverage Gap；Observation 先于选择，Approved Scope 与 RFC 9309 RobotsPolicy 先于主动访问，Soft-404 先于有效性判断，Persistent Frontier 保证不丢；第三方 runtime 的 dedup/status/score/limit/timeout 只作 advisory，URL Identity 与 Validity 由平台判定；DomainMapper 生产配置必须显式声明低风险 source，第三方站点禁用其原生 `probe/robots`，内容路径探测由平台 SafeProbeAdapter 接管；Raw Artifact 保证可重放，Canonical IR 保证稳定 Markdown；Global Scheduler 管跨 Worker 公平与限流，MemoryAdaptiveDispatcher 管 Worker 本地资源；Runtime Checkpoint 提升执行恢复效率，但业务真相始终在 PostgreSQL + Object Storage。**
