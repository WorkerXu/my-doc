# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站和公开 Newsletter** 的长期知识库采集平台，并可平滑扩展到数千站点、百万级到千万级文章。

系统必须满足：

1. **全历史回填**：尽可能完整发现并抓取每个已批准 Source 的历史文章，并能解释已知缺口、未知边界和停止原因；
2. **持续增量同步**：持续发现新文章、正文更新、URL 迁移、重定向、删除和重发布；
3. **稳定 Markdown**：Markdown 必须从可追溯 Raw Artifact 经确定性抽取、质量门禁和 Canonical IR 生成；
4. **低成本扩站**：新增网站优先通过 Source Profile、Provider、Traversal Policy、Extraction Recipe 配置完成，不维护 1000 份独立爬虫；
5. **Web 可运营**：支持 Source 接入、审核、Backfill、Incremental、Coverage、Frontier、质量、成本、失败诊断、暂停/恢复/停止和审计；
6. **可搜索与 RAG**：支持关键词、向量和混合检索，并可回溯原文、版本、来源和抓取证据；
7. **可观测、可恢复、可重放**：任意 URL、任务、Artifact、Markdown 都能解释来源、版本和执行路径；
8. **渐进扩展**：开发期 Docker Compose，生产期按队列和 Worker 类型水平扩容；
9. **主链不依赖 LLM**：LLM 只用于可选增强，不参与 Coverage Truth、URL Identity、Canonical URL、Robots Access 和历史完整性最终判定；
10. **高成本抓取可智能预算**：Browser、Deep Crawl、Repair、专题补洞可用 Focused Information-Gain Scheduler 排序，但不得因此永久丢弃历史 URL。

### 1.1 核心 SLO

- **Coverage**：每个 Source 能解释 Provider、已发现 URL、Frontier、Known Gap 和 Backfill 停止原因；
- **Freshness**：新文章从发布/发现到 PASS Markdown 的延迟；
- **TTFM**：URL 首次发现到首个可用 Markdown 的时间；
- **Extraction Quality**：标题、正文完整率、噪声率、代码块/表格/列表保留率、截断率；
- **Reliability**：任务成功率、Retry、DLQ、Queue Age、Lease Recovery、Checkpoint Resume 成功率；
- **Browser Efficiency**：HTTP 命中率、Browser avoided、Browser recovery、每文档 Browser 成本；
- **Identity Quality**：重复文章误合并/漏合并率；
- **Validity Quality**：Soft-404、假 200、空壳 SPA 识别准确率；
- **Traceability**：任意 Markdown 可回溯 Source、URL、Artifact、Extractor、Quality、Renderer Release；
- **Cancellation**：停止请求到停止发新 Lease、到 Run 完全 STOPPED 的延迟；
- **Cost**：按 Source、Run、Queue Class、每 1000 篇 PASS 文档统计抓取、Browser、存储、索引和模型成本；
- **Focused Efficiency**：专题/慢路径任务统计 pages-per-useful-result、expected gain、Browser 节省比例和 focused stop reason；
- **Budget Accuracy**：Focused Job 的 admitted/attempted/successful/preview/model 调用均不超过平台硬预算。

### 1.2 非目标

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不把 HTTP 200、DOM 很长或 crawler success 直接视为正文正确；
- 不把搜索结果数、Common Crawl、Wayback、Deep Crawl 页数、Adaptive confidence、`max_pages` 当历史完整性证明；
- 不把 Crawl4AI 即时 Markdown、LLM 摘要或改写直接作为 Canonical Markdown；
- 不因 URL 曾抓过就永久停止复检；
- 不把 Redis、Browser Session、Crawler Cache、Visited Set、Dispatcher Queue、Adaptive State、Search Index 当业务真相；
- 不允许优先级、Scorer、相关性阈值、信息增益阈值或执行预算永久删除潜在历史文章；
- 不默认对所有文档构建 GraphRAG。

## 2. 核心设计原则

1. **Coverage First**：先建立 URL Inventory，再批量抓正文；
2. **Authoritative First**：CMS/API、Sitemap、RSS/Atom、官方 Archive 优先；
3. **Historical Gap Is Evidence, Not Truth**：Common Crawl、Wayback 用于历史补洞，不作为完整性证明；
4. **Deep Crawl Is Gap Provider**：站内深度抓取用于补洞，不作为 Coverage Truth；
5. **Focused Is Optimization**：Focused confidence 表示专题信息充分度，不等于历史 Coverage；
6. **Discovery / Fetch / Extract / Quality / Projection 分离**；
7. **HTTP First, Browser Last**：Browser 是受治理慢路径；
8. **Snapshot First**：先保存不可变 Artifact，再抽取与清洗；
9. **Canonical IR First, Markdown as Projection**；
10. **Recipe, Not 1000 Site Scripts**；
11. **Stable Identity**：Source、Host、URL、Artifact、Document、Version 使用稳定 ID；
12. **Idempotent + Recoverable**：任务使用幂等键、Lease、Fencing Token、Checkpoint；
13. **Fair by Default**：大站 Backfill 不能饿死 Incremental 和小站；
14. **Bounded Concurrency Everywhere**：禁止无界 asyncio gather、Browser Context 和模型 fan-out；
15. **No Silent Degradation**：截断、预算耗尽、降级、过滤、跳过必须记录原因；
16. **Release Everything That Changes Results**：Profile、Provider、Traversal、Adaptive、Recipe、Runtime、Extractor、Quality、Renderer、Embedding、Rank 全部版本化；
17. **Priority Means When, Not Whether**：优先级和 expected gain 决定何时处理，不决定是否永久保存；
18. **Observation Before Selection**：观察到链接后先保存事实，再 Filter/Score/Budget；
19. **Persistent Frontier, Not In-Memory Traversal**：BFS/DFS/Best-First/Focused 的业务候选进入数据库；
20. **Runtime Checkpoint != Business Checkpoint**：第三方 crawler resume state 只是执行优化，PostgreSQL 才是恢复真相；
21. **Cooperative Cancellation**：停止是状态机，不把点击停止等同于所有 in-flight 工作已结束；
22. **Approved Scope First**：发现子域、路径或外部归档 URL 不等于允许主动访问；
23. **Soft-404 Is First-class**：URL 存在性不能只依赖 HTTP 状态码；
24. **Global Admission + Local Adaptation**：跨 Worker 公平和限流由平台负责，Worker 内存自保护由运行时负责；
25. **Runtime Result Is Advisory**：第三方 crawler 的 dedup、status、score、limit、timeout、cache、confidence 都不能直接升级为平台业务真相；
26. **Normalize Conservatively**：scheme/host 可标准化，path/query 默认保留大小写与原始语义；
27. **Explicit Runtime Capabilities**：生产配置不得依赖第三方 crawler 默认 source/path 集；
28. **Robots Policy Is Access Control Input**：robots 访问判定由平台 RFC 9309 Policy Engine 负责；
29. **Correlate by Identity, Never by Position**：批量请求结果必须按 `attempt_id/url_id/requested_url` 关联，禁止依赖过滤后数组位置；
30. **Strict Budget Is Platform-owned**：page/preview/browser/model 预算由平台 Admission 硬控，不信任 runtime 的 soft limit。

```text
       |                              |                               |
       +------- Observation -> Persistent URL Inventory / Frontier --+
                                      |

                                      |

                                      |

                                      |

                              /              \

                              \              /
```

### 3.1 业务真相边界

**PostgreSQL + Object Storage 是业务真相。**

- PostgreSQL：Source、Approved Host、Provider、URL Identity、URL Observation、Robots Policy、Validity、Frontier、Task、Cursor、Coverage、Focused Run 元数据、Quality、Document、Version、Release、Checkpoint Pointer、Audit；
- S3/MinIO：Raw HTML、MHTML、截图、Trace、Provider Evidence、Candidate、IR、Markdown、PDF、Runtime Checkpoint、Focused Query Set、Enrichment；
- Redis Streams：任务运输、Consumer Group、Backpressure、分布式 Token Bucket，不保存不可替代业务状态；
- OpenSearch / pgvector：可重建 Serving Projection；
- Crawl4AI cache、dispatcher queue、rate limiter、Browser Session、Adaptive `CrawlState`、Playwright Context、Worker 内存：易失执行状态。

## 4. 技术选型

### 4.1 控制面

- **FastAPI + Pydantic**：REST API、Command、Schema 校验；
- **PostgreSQL**：Truth Store、任务、Coverage、Frontier、版本、审计；
- **Redis Streams**：任务运输、Consumer Group、Backpressure；
- **Redis Lua Token Bucket / Semaphore**：跨 Worker 域名限流和资源令牌；
- **React / Next.js + TypeScript**：Web 管理后台；
- **OpenTelemetry + Prometheus + Grafana + Structured Logging**：Trace / Metric / Log；
- **S3/MinIO**：不可变对象存储；
- **Vault/KMS/Secret Manager**：凭据引用。

### 4.2 Discovery / Fetch

- **httpx/aiohttp**：robots、Sitemap、Feed、CMS API、Conditional GET、普通网页和平台 SafeProbe；
- **RFC 9309 Robots Parser/Policy Engine**：User-Agent group、最长匹配、Allow/Disallow 判定与缓存；
- **Crawl4AI**：Domain Mapping、AsyncUrlSeeder、Browser Render、Deep Crawl Prefetch、Link Preview baseline、Adaptive 算法 baseline；
- **Crawl4AI MemoryAdaptiveDispatcher**：Browser Worker 本地内存自保护；
- **Playwright Python**：复杂多步、有状态、需要 Step 级恢复的交互；
- **Common Crawl Adapter**：公共历史索引补洞；
- **Wayback CDX Adapter**：历史 URL 补洞；
- **SearXNG / 合规 Search API Adapter**：External Search Gap、新 Source Candidate；
- **PyMuPDF/pdftotext**：PDF；扫描件进入 OCR 慢路径；
- **Python email/MIME parser**：Newsletter Inbox Provider。

### 4.3 Extraction / Search

- **Trafilatura**：Generic Main Content Candidate；
- **lxml/BeautifulSoup**：DOM/XPath、Metadata、DOM Repair；
- **JSON-LD/OpenGraph/Microdata**：结构化元数据；
- **CSS/XPath/Regex Recipe**：确定性正文与字段抽取；
- **SimHash/MinHash**：近重复候选；
- **OpenSearch BM25 + pgvector + RRF**：混合检索；
- **可选 embedding/reranker/LLM**：只在 Canonical 数据或 Focused Job 上运行。

### 4.4 Focused Scorer

生产默认采用平台拥有的 scorer：

```text
platform_statistical_v1       # 默认
platform_embedding_v1         # 可选
crawl4ai_statistical_baseline # 行为对照
crawl4ai_embedding_baseline   # 小规模实验
```

`platform_statistical_v1` 使用 Unicode/CJK-aware analyzer，并保留 C++、C#、.NET、Go、R、JS、AI、DB、S3、K8s 等技术词；`platform_embedding_v1` 从 Canonical IR 的标题、Heading 和代表性 Chunk 构建语义表示，不使用“正文前 N 字符”作为长期真相。

## 6. Source 接入流程

新增网站先自动探测，再人工确认并发布 immutable Source Profile Release。

### 6.1 接入探测顺序

```text
1. Exact-host robots.txt / Sitemap / Feed
2. CMS 特征：WordPress/Ghost/Medium/Substack/自建 API
3. 首页与平台 SafeProbe 内容路径探测
4. Archive / Pagination / URL Pattern
5. Canonical / Redirect / Query 参数行为
6. Soft-404 baseline
7. HTTP vs Browser route sampling
8. 可选 metadata-only 子域候选发现
9. 人工审核 Content Host
10. Common Crawl / Wayback 历史 Gap inventory
11. Deep Crawl 浅层 Prefetch
12. 发布 Source Profile Release
```

### 6.2 Domain Recon 安全边界

平台包装 `DomainReconAdapter`：

- 默认 `include_subdomains=false`；
- 显式编译 runtime source allowlist，禁止依赖第三方默认 source；
- 第三方 approved exact-host 默认只允许 `sitemap+feed+homepage` 一类低风险来源；
- 子域发现优先 metadata-only，只生成 `host_candidate`；
- 未批准 host 不允许主动 HEAD/GET 验证或正文抓取；
- 第三方 Source 默认禁用 DomainMapper 原生 `probe`；
- 第三方 Source 默认禁用 DomainMapper 原生 `robots`；
- 内容型路径探测由平台 `SafeProbeAdapter` 执行，只允许 `/blog`、`/posts`、`/articles`、`/news`、`/engineering`、`/tech`、`/archive` 等配置项；
- robots `Sitemap:` 可用于发现，但 Allow/Disallow 由平台 RFC 9309 引擎计算；
- 每次 DNS resolve 与 redirect 每一跳重新做 SSRF / approved scope 校验；
- 所有请求经过全局 Token Bucket、Source/Host Scope 和 Audit。

## 7. Discovery 与 Coverage

### 7.1 Provider 优先级

```text
CMS/API
 -> Sitemap
 -> RSS/Atom
 -> Archive/Pagination
 -> HTML Listing
 -> Common Crawl / Wayback Historical Gap
 -> Safe Domain Recon Gap
 -> SafeProbe Content Paths
 -> Deep Crawl Prefetch
 -> External Search Gap
```

高优 Provider 的结果不能阻止其它 Provider 执行。最终 URL Inventory 是多个 Provider 的集合并集，并保留 Observation 来源证据。

### 7.2 Backfill 流程

```text
Source Approved
 -> Probe Authoritative Providers
 -> Build Initial URL Inventory
 -> Archive/Pagination Enumeration
 -> Common Crawl / Wayback Historical Gap
 -> Safe Domain Recon Gap
 -> SafeProbe Content Paths
 -> Deep Crawl Gap Scan
 -> Persistent Frontier
 -> Robots Policy / URL Validity Gate
 -> Fetch
 -> Extract / Quality / IR / Markdown
 -> Coverage Reconcile
 -> Gap Review
 -> Backfill Complete
```

### 7.3 Historical Gap Provider

**Common Crawl**：用于发现当前站点已经不再链接的旧 URL。结果必须回源验证，不直接认定为当前有效文章。

**Wayback CDX**：大型站点按 year window、URL prefix、CDX page/resume key 切片。Wayback Observation 只证明历史上出现过 URL，不证明当前有效。

### 7.4 Coverage Ledger

```text
coverage_snapshot
- source_id
- provider_run_id
- provider_type
- discovered_count
- unique_url_count
- article_candidate_count
- fetched_count
- pass_count
- failed_count
- deferred_count
- soft404_suspected_count
- known_gap_count
- stop_reason
- captured_at
```

### 7.5 Backfill 完成条件

至少满足：

- 权威 Provider 已完成或明确不可用；
- Historical Gap Provider 已运行到配置边界并记录限制；
- Persistent Frontier 无 READY/LEASED/RETRY；
- Deep Crawl / Archive 不再产生新增文章候选，或达到可解释收敛条件；
- 失败任务成功、进入 DLQ 或被人工接受；
- Soft-404 疑似批次已确认、延期或人工接受；
- Known Gap 为空或被人工接受；
- 多 Provider URL 集合差异处于阈值内。

**Focused confidence、saturation、max_pages、low gain 绝不能作为 Backfill Complete 条件。**

### 7.6 URL 规范化

```text
resolve relative
 -> normalize scheme
 -> lower host / IDNA
 -> remove default port
 -> strip fragment
 -> normalize dot segments
 -> preserve path case by default
 -> preserve query case/order before Query Policy
 -> tracking parameter policy
 -> redirect identity
 -> rel=canonical evidence
```

不提前删除 query 参数；每个 Source 先采样生成 Query Policy，再发布 release。

## 8. Focused Information-Gain Scheduler

### 8.1 定位

Focused Scheduler 只用于：

- Browser 慢路径预算；
- Deep Crawl Gap Scan 候选排序；
- 专题知识包；
- Backfill 未完成时的专题 RAG 冷启动；
- Repair/Browser fallback 队列优先级。

不用于：

- 全历史完成判定；
- RSS/CMS/Sitemap 增量同步；
- URL Identity；
- Robots Access；
- Soft-404 Truth；
- Tombstone；
- Canonical Markdown。

### 8.2 默认运行方式：Platform-owned

生产默认不是把 `AdaptiveCrawler.digest()` 当平台调度器，而是：

```text
Persistent URL Inventory
 -> Candidate Slice Builder
 -> Platform Preview
 -> Focused Scorer
 -> Strict Budget Admission
 -> Frontier priority update
 -> HTTP/Browser/Repair Worker
 -> Canonical IR
 -> Focused metric update
```

平台负责：

```text
URL durability
scope/robots/SSRF
strict budget
attempt correlation
retry/DLQ
fairness
lease/fencing
cancellation
```

Scorer 只负责估计 priority/expected gain。

### 8.3 Statistical Strategy

内置 Crawl4AI StatisticalStrategy 的思想可用作 baseline：Coverage、Consistency、Saturation 组合 focused confidence，候选按 relevance/novelty/authority 评分。

平台统一解释为：

```text
Coverage    = query term/topic coverage
Consistency = topical overlap/coherence
Saturation  = marginal information gain diminishing
```

不解释为历史完整率或事实一致性。

生产默认 `platform_statistical_v1` 增加：

- Unicode/CJK-aware analyzer；
- 技术词保留；
- title/heading/anchor/body 分字段；
- 平台 clean text / Canonical IR；
- 配置权重真实进入公式；
- component score 可解释；
- score 只映射 `priority / next_fetch_order`。

### 8.4 Embedding Strategy

`platform_embedding_v1` 可选，使用 query expansion + semantic embedding + held-out validation 估计专题语义覆盖和缺口。

生产规则：

- 默认关闭；
- query model 和 embedding model 必须显式配置；
- query expansion 使用严格 JSON Schema，不接受自由格式隐式约定；
- 保存模型原始 expansion artifact、实际 variation set、train/validation split 和 hash；
- split 必须可 Replay；
- 正文向量来自 Canonical IR chunk/pooling，不只截取正文开头；
- query expansion/embedding 失败不能破坏 Persistent Frontier；
- 模型、prompt、analyzer、embedding 都有 release；
- 模型或 query set 变化后旧 checkpoint 不得直接 resume；
- 预算按 Source/Run 记录。

### 8.5 Crawl4AI Native Adaptive 的生产边界

Crawl4AI AdaptiveCrawler 保留为算法 baseline、小规模专题实验或经过补丁的 bounded runtime，不拥有业务 Frontier。

固定 release 必须验证以下行为：

1. Statistical confidence 的权重配置是否实际生效；
2. authority component 是否真的参与区分候选；
3. 文档描述的 expected gain 与源码真实公式是否一致；
4. Link Preview 会发出哪些额外请求；
5. 无 `head_data` 的链接是否被 runtime 过滤；
6. `max_pages` 是否为严格上限；
7. batch 中部分失败后结果是否仍和原 URL 正确关联；
8. resume state 是否完整恢复 embedding validation/query split；
9. 同一个 AdaptiveCrawler 实例是否会发生跨 Run 状态污染。

### 8.6 Native Runtime Guardrail

当前生产规则：

```text
1 AdaptiveCrawler instance = 1 Focused Run
```

禁止同实例并发 `digest()`，也不长期跨 Run 复用 Strategy state。

若使用未经修复的 native batch 路径，默认：

```text
top_k_links = 1
```

直到通过“批次中间项失败仍正确关联 URL”的 Golden Test。修复后的 adapter 必须按 `{attempt_id,url_id,requested_url}` 返回结果，不能使用过滤后的成功数组和原请求数组做 positional zip。

### 8.7 严格预算

平台预算独立于 runtime `max_pages`：

```text
remaining_pages = budget_pages - admitted_count
batch_size = min(top_k, remaining_pages)
```

同时硬控：

```text
page admission
HTTP attempts
Browser attempts
preview requests
embedding calls
query-expansion calls
wall-clock deadline
```

分别记录 admitted/attempted/successful，不用“成功页面数”替代成本计数。

### 8.8 Native Resume 规则

Crawl4AI runtime checkpoint 只能作为 hint。Embedding 模式在未补齐以下状态前，native resume 默认关闭：

```text
actual generated query variations
train query set
held-out validation query set
confidence history
validation state
query/model/prompt/analyzer release hashes
```

平台始终先验证 `query_hash + release envelope`；不匹配则从 Persistent Frontier 重建 Focused Slice。

### 8.9 Link Preview 安全

Native Link Preview 可能产生额外 metadata 请求。任何 preview 都必须经过：

```text
Approved Scope
 -> RobotsPolicy
 -> SSRF Validation
 -> Redis per-domain Token Bucket
 -> bounded preview concurrency
 -> request budget
 -> Audit
```

如果无法证明 runtime 内部每个 preview 请求都经过这些策略，则生产主链关闭 native preview，改用平台受控 Preview Artifact。

Raw Link Observation 必须先落库。没有 `head_data`、低 expected gain、低 score、preview 失败的 URL 仍保留在平台 Inventory。

### 8.10 Focused Stop Reason

```text
FOCUSED_SUFFICIENT
FOCUSED_SATURATED
FOCUSED_MAX_PAGES
FOCUSED_MAX_DEPTH
FOCUSED_LOW_GAIN
FOCUSED_NO_LINKS
FOCUSED_IRRELEVANT
FOCUSED_BUDGET_EXHAUSTED
FOCUSED_CANCELLED
```

这些 stop reason 只结束 Focused Run。

## 9. Deep Crawl、Domain Mapping 与 Traversal

### 9.1 Deep Crawl 两阶段

```text
Phase A: Prefetch Discovery
- 获取 HTML / links / minimal metadata
- 记录 from_url -> to_url Observation
- 跳过 Markdown / LLM / 重型抽取
- 形成 Persistent Frontier

Phase B: Full Processing
- Fetch Raw Artifact
- URL Validity
- Extraction / Quality / IR / Markdown
```

若 HTTP/Sitemap 已能发现，优先不用 Browser Prefetch。

### 9.2 Observation Before Selection

```text
Page Result
 -> Extract Raw Links
 -> Persist Observation
 -> Normalize / Scope Check
 -> Filter Reason
 -> Score / Expected Gain
 -> Budget / Admission
 -> Persistent Frontier
 -> Runtime Slice
```

禁止先由 visited/threshold/max_pages/low gain 裁剪，再只保存幸存 URL。

### 9.3 BFS / DFS / Best-First / Focused

- **BFS**：Backfill 默认探测；
- **DFS**：路径深度结构明确时启用；
- **Best-First**：固定预算下优先处理更像文章、归档、分页的 URL；
- **Focused**：专题/高成本慢路径按信息增益排序。

统一语义：

```text
score -> priority
```

### 9.4 Bounded Slice

```text
incremental_high: 立即调度
source A backfill: 200~500 URL slice
source B backfill: 200~500 URL slice
browser_slow: 独立慢队列
focused: 10~50 URL bounded run
```

Slice 结束后未处理候选仍保存在 PostgreSQL Frontier。

### 9.5 Runtime 配置验证

每个 Crawl4AI runtime release 都建立行为测试：

```text
config -> actual network requests
config -> actual filtering
config -> actual browser/http route
config -> actual timeout/limit semantics
config -> actual scoring/stopping semantics
config -> actual batch-result correlation
config -> actual checkpoint semantics
```

不能只看配置字段名字判断能力。

## 10. Fetch Plane

### 10.1 HTTP First

```text

    -> HTTP artifact
```

### 10.2 Conditional Fetch

增量复检使用：

```text

If-Modified-Since: Last-Modified
```

304 不生成新正文版本，但更新 freshness observation。

### 10.3 Retry 分类

```text
DNS/TCP timeout       -> exponential retry
429                   -> Retry-After + domain throttle
5xx                   -> bounded retry
403/challenge         -> policy-based browser route
404/410               -> tombstone candidate, grace policy
soft-404 suspected    -> validity/repair queue
parse/extract failure -> repair queue，不等于必须 refetch
```

### 10.4 多层限流

每个域名维护：

```text
requests_per_second
burst
max_http_concurrency
max_browser_concurrency
max_preview_concurrency
max_safe_probe_concurrency
retry_after_until
```

职责分离：

```text
Redis Token Bucket       = 跨 Worker 精确节流
Worker Semaphore         = 本地并发保护
Crawler RateLimiter      = 本地 429/503 退避
MemoryAdaptiveDispatcher = Worker 内存压力保护
Focused top_k            = 本次排序 fan-out hint，不是全局限流
```

### 10.5 Raw Artifact First

```text
status_code
```

## 12. 增量同步

### 12.1 增量信号优先级

```text
RSS/Atom
 -> CMS API
 -> Sitemap lastmod
 -> Homepage / Archive probe
 -> Conditional recrawl
 -> Periodic Historical/Domain/Deep Gap Scan
```

Focused Scheduler 不替代上述信号，只能在周期 Gap/慢路径中做排序。

### 12.2 自适应频率


### 12.3 Cursor 一致性

```text
读取 cursor
 -> 拉取一批
 -> 写 Observation / URL Inventory
 -> 创建 Fetch Task
 -> 同一 DB 事务推进 cursor + outbox
```

失败时 cursor 不推进。

### 12.4 更新与删除

- 正文 hash 变化 -> 新 Document Version；
- canonical 迁移 -> identity merge / redirect evidence；
- 404/410 首次出现 -> `MISSING_SUSPECTED`；
- 多次确认或权威 API 明确删除 -> `TOMBSTONED`；
- 历史 Markdown 不物理删除，Serving Index 可隐藏 current tombstone。

## 17. 安全、合规与抓取礼仪

- 默认尊重 RFC 9309 robots/access policy；
- DomainMapper 简化 robots path 不作为最终访问许可；
- 第三方 Source 默认禁用 DomainMapper `probe` 和 `robots` source；
- SafeProbe 只在 approved CONTENT exact-host 上、经 RobotsPolicy allow 后执行；
- Focused Preview 也必须经过 Approved Scope、Robots、SSRF、Token Bucket；
- 不自动绕过登录、付费墙、CAPTCHA、明确禁止；
- 未批准 host 的 CT/DNS/Archive 发现只保留 metadata evidence；
- 禁止任意 SSRF：loopback、RFC1918、link-local、云 metadata、file:// 等；
- DNS 解析得到的 IP 也做禁止网段校验；
- Redirect 每一跳重新解析并校验目的地；
- Crawler Docker/API 只放内网；
- Web 用户不能直接提交任意 URL、JS hook 或完整 CrawlerRunConfig；
- JS execution、下载路径、Webhook 等高风险能力默认关闭；
- 凭据只存 Secret Manager 引用；
- Proxy 使用有审计；
- 所有第三方查询纳入 egress、超时和审计；
- 无法验证第三方 runtime 内部请求经过 Access Policy 时，关闭该网络功能并改用平台受控实现。

## 22. 验收标准

平台达到可生产使用至少满足：

1. 新增一个标准博客主要通过 Web Source Profile 完成，不新增独立爬虫脚本；
2. 新 host 只能以 Candidate 出现，未经批准不能主动抓取；
3. 任意 Source 能执行全历史 Backfill，并解释 Coverage、Historical Gap 与 Known Gap；
4. Common Crawl/Wayback 不被误当完整性证明；
5. 任意发现 URL 都能解释 Provider、Filter、Score、Admission、Runtime Status、Platform Validity、Frontier；
6. SPA/自定义 404 不会仅因 HTTP 200 大规模进入正文库；
7. URL Normalizer 默认保留 path/query 大小写语义；
8. Worker 任意 kill 后不丢业务 Frontier，可通过 Lease/Checkpoint 恢复；
9. Crawler local queue/cache/adaptive state 丢失时仍可从 PostgreSQL/Object Storage 重建；
10. `max_pages`、`max_urls`、低 score、低 expected gain、Provider timeout 不会让全历史候选静默消失；
11. 点击停止后停止发新 Lease，并最终进入 STOPPED；
12. Browser Worker 内存压力可自动降低本地并发且不破坏平台任务状态；
13. Raw Artifact 可重放生成新的 IR/Markdown，不必重新抓网页；
14. Incremental 能通过 RSS/Sitemap/Conditional GET 持续同步新内容与更新；
15. Markdown 保留标题、正文、代码、表格、列表等关键结构并通过质量门禁；
16. Search Index 全部可从 Canonical 数据重建；
17. 所有改变结果的组件都有 release，并通过 Golden Replay 后发布；
18. Web Admin 能完成接入、审核、Backfill、Incremental、Coverage、失败诊断、暂停/恢复/停止和审计；
19. Focused Run 达到高 confidence 或 saturation 时，不会改变 Source 的历史 Coverage 状态；
20. Focused 过滤、preview 失败、低 gain 的 URL 仍保留 Observation/Frontier；
21. Embedding strategy 失败或模型升级不会破坏主链和业务恢复；
22. Browser/Deep Crawl/Repair 慢路径可以通过 expected gain 降低成本，并能量化收益；
23. page/preview/model 预算由平台硬控，Golden Test 中 budget overshoot 为 0；
24. 批次部分失败时，成功结果仍按 `attempt_id/url_id` 正确关联，correlation error 为 0；
25. 同一 Crawl4AI AdaptiveCrawler 实例不跨 Focused Run 并发复用；
26. Embedding checkpoint 未恢复完整 query/validation 语义时不得宣称 deterministic resume；
27. 技术词和中文 query 的 statistical analyzer 通过 Golden Test；
28. 长技术文章的语义表示覆盖全文代表性 Chunk，而不是只覆盖开头。

最终架构原则：

> **权威 Provider 建 Inventory，Common Crawl / Wayback / Safe Domain Recon / SafeProbe / Deep Crawl 补 Coverage Gap；Observation 先于选择，Approved Scope 与 RFC 9309 RobotsPolicy 先于主动访问，Soft-404 先于有效性判断，Persistent Frontier 保证不丢；Focused Information-Gain Scheduler 只决定高成本候选的处理顺序，confidence/saturation/low-gain 都不能替代 Historical Coverage；严格预算、请求身份关联、Retry、Fairness 和恢复由平台拥有，第三方 runtime 的 dedup/status/score/limit/timeout/confidence 只作 advisory；Raw Artifact 保证可重放，Canonical IR 保证稳定 Markdown；Global Scheduler 管跨 Worker 公平与限流，MemoryAdaptiveDispatcher 管 Worker 本地资源；Runtime Checkpoint 提升执行恢复效率，但业务真相始终在 PostgreSQL + Object Storage。**
