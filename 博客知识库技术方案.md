# 博客知识库技术方案

## 1. 目标与范围

建设一套长期运行、可横向扩展、可审计、可回放、支持全量历史回填与持续增量同步的技术博客知识库平台。

首期目标：

- 接入约 1000 个技术博客、工程博客、技术文档站和公开 Newsletter，后续可扩展到数千 Source；
- 尽可能抓取每个 Source 的完整历史文章，并持续发现新增、更新、迁移和删除；
- 将正文清洗为稳定、可重建的 Markdown，同时保留原始网络事实、渲染事实、内容版本与完整 lineage；
- 新增站点主要通过 Probe、Source Profile、Recipe、Schema 与审核完成，不为普通站点新增专用爬虫代码；
- 支持 Web 管理、任务调度、失败重试、Coverage、版本管理、派生处理、资源下载、搜索/RAG、导出、审计与运行时治理；
- 按百万级 Document/Version、数百万到千万级 URL Observation 设计；
- HTTP 为默认主路径，确定性 Browser 为 fallback，固定 Recipe 处理稳定交互，Agent Browser 只处理极少量未知 UI/异常场景。

平台必须能回答：

1. 一个站点有哪些已知历史文章，为什么认为历史基本覆盖；
2. 某 URL 从哪里发现，如何规范化，为什么被抓取、过滤或升级到 Browser；
3. 某个已知 URL 上次何时检查，为什么本轮产生或没有产生新版本；
4. 某次抓取使用了哪个 Profile、Planner、Adapter、Runtime、Recipe、Policy；
5. 某篇 Markdown 来自哪个 Snapshot/Render Artifact、Extractor、IR 和 Document Version；
6. 某个摘要、翻译、分类或实体结果来自哪个 Document Version、模型、Prompt、Schema 和 Release；
7. Worker、Redis、Browser 或第三方 crawler 故障后如何恢复；
8. Agent Browser 若发生过交互，具体做了哪些动作、访问了哪些 URL、为何停止；
9. 第 1001 个站点是否可以不修改核心代码直接接入。

非目标：

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不以 Agent/LLM 的“完成判断”作为历史 Coverage 证明；
- 不把 Redis、crawler 内部缓存/frontier、runtime checkpoint、Agent memory 当业务真相；
- 不让自由 Agent 直接拥有核心数据库、内部网络、Shell、Secret 或无限 Browser 权限；
- 不把 LLM 重写、摘要或翻译作为 Canonical Markdown；
- 不把标题、slug 或展示文本当跨阶段主键；
- 不把搜索 Top K、BestFirst score、主题相关度或抓取成功率当全量历史边界。

## 2. 核心原则

1. **Coverage First**：历史完成必须有 Provider Evidence、cursor、exhaustion reason 和 known gap。
2. **Authoritative First**：CMS API、Sitemap、Feed、Archive 优先，Common Crawl/Deep Crawl 只补洞和交叉验证。
3. **Discovery Before Fetch**：先发现 URL，再 normalize/scope/filter/dedupe，最后抓正文。
4. **Discover Cheap, Fetch Expensive**：发现阶段不支付不必要的 Browser、Markdown、媒体或 LLM 成本。
5. **Seen URL != Freshness**：URL 已知只表示“不再重复首次发现”，绝不能因此跳过后续更新检查。
6. **HTTP First, Browser Last**：静态页先 HTTP；JS 页再确定性 Browser；未知 UI 最后才进入 Agent Browser。
7. **Deterministic Before Agentic**：Backfill/Incremental 主链不依赖 LLM 决策即可运行。
8. **Planner / Executor Separation**：Planner 只产出受约束 FetchPlan；Executor 才拥有最小联网/浏览器权限。
9. **Tool Contract, Not Framework Coupling**：业务层面向能力契约，不直接依赖 Crawl4AI、Browser Use、Playwright 或 Agent 框架 DTO。
10. **Tool Exposure != Tool Execution**：给 LLM/MCP 暴露 schema 与绑定真实执行器分离，Tool 只能调用平台能力，不能绕过 Policy Gate。
11. **Snapshot First**：先保存不可变抓取事实，再 Extract、IR、Markdown、Chunk、Embedding。
12. **Rendered Evidence First-Class**：Browser 路径保存 Network Snapshot 与最终 Render Artifact。
13. **Interaction Is Evidence**：Agent Browser 每一步都可审计、可停止、可回放。
14. **IR First, Markdown as Projection**：Canonical IR/Document Version 是内容事实，Markdown 可确定性重建。
15. **Canonical / Enrichment Separation**：翻译、摘要、分类、标签、实体、排序等均为版本化派生结果，不覆盖源事实。
16. **Stable Identity Across Stages**：跨阶段关联只使用不可变 ID；标题、URL 展示形式和模糊文本匹配都不能承担身份关联。
17. **LLM Optional and Budgeted**：LLM 只用于疑难结构化抽取、派生内容、Probe、Research、异常诊断。
18. **Schema First**：结构化抽取与 LLM 输出使用版本化 JSON Schema/Pydantic，拒绝依赖脆弱字符串切片。
19. **Recipe, Not Site Code**：selector、wait、scroll、click、iframe、Shadow DOM、分页规则版本化配置。
20. **Reuse Browser, Isolate Context**：Browser 进程复用，Context 按 Source/安全域隔离，Page 按 Task 短生命周期。
21. **Idempotent + Recoverable**：Task 有幂等键、lease、fencing token、retry、checkpoint、DLQ。
22. **Source Friendly**：robots、Retry-After、per-domain rate/concurrency、backoff/circuit breaker 优先。
23. **Security on Every Hop**：起始 URL、redirect、Browser navigation、iframe、Agent action target、媒体 URL 每跳做 Scope/SSRF/Egress 校验。
24. **Release Everything That Changes Results**：Profile、Planner、Adapter、Runtime、Recipe、Policy、Schema、Extractor、IR、Markdown、Enrichment、Embedding 都版本化。
25. **Projection Is Rebuildable**：全文索引、向量、Markdown、派生结果和 Export 都可从事实层或上游版本重建。

```text

              |
      Command / Query Layer
              |
      PostgreSQL Truth Store

 Snapshot/RenderArtifact/Interaction/Document/Version/Asset/
 EnrichmentRelease/EnrichmentResult/Audit/Outbox)
              |
      Transactional Outbox
              |
      Redis Streams (transport only)
              |
+---------------------+-------------------+--------------------+
|                     |                   |                    |
Discovery Workers     HTTP Workers        Browser Workers      Interaction Workers
CMS/Sitemap/Feed      httpx/aiohttp       Crawl4AI/Playwright  Controlled Agent Browser
Archive/Seeder/CC     conditional GET     deterministic render explicit policy only

|                     |                   |                    |
+---------------------+-------------------+--------------------+
                              |
                 Snapshot / Render / Trace
                              |
                    Extract -> Canonical IR
                              |

                              |

      |               |               |                |
  Markdown         Assets         Search/RAG      Optional Enrichment
      |                               |            translate/classify/
```

真相边界：

```text
PostgreSQL + Object Storage = 业务真相
Observation                 = 持久 URL 发现事实

Agent memory                = 临时执行状态

```

## 4. 技术选型

### 4.1 控制面

- FastAPI + Pydantic：REST、Schema 校验、Webhook、内部 Command API；
- PostgreSQL：Source、Run、Task、Coverage、Observation、Version、Release、Audit、Outbox；
- Redis Streams：consumer group、backpressure、retry transport；
- React/Next.js 或 Vue + TypeScript：Web 管理台；
- Prometheus + Grafana + OpenTelemetry：指标、日志、Trace；
- Docker Compose：开发/单机；Kubernetes：生产横向扩展。

### 4.2 抓取与解析

- HTTPX/aiohttp：静态 HTML、Feed、Sitemap、API、Conditional GET、媒体下载；
- Crawl4AI：确定性 Browser/render、批量抓取、Deep Crawl、URL Seeder 等能力 Adapter；
- Playwright：复杂但可固定的 JS/交互 Recipe；
- Browser Use 或同类：受控 L4 Interactive Browser Adapter；
- lxml / trafilatura / readability 类算法：正文候选抽取；
- JSON Schema/Pydantic：结构化抽取与派生结果契约；
- PyMuPDF/pdftotext：PDF；扫描 PDF 才进入 OCR fallback；
- S3/MinIO：原始响应、Rendered DOM、MHTML、截图、IR、附件、导出包；
- OpenSearch：全文/BM25；
- pgvector：首期向量检索，可通过 Adapter 换 Qdrant/Milvus。

### 4.3 Crawl4AI 集成约束

生产代码不直接散落调用具体 Crawl4AI API，而通过 `CrawlerAdapter` 封装。Runtime 固定版本、镜像 digest、Chromium 版本和 lockfile；升级先走 Golden Corpus、Benchmark、Canary。

批量能力如 `arun_many` 只能执行平台已经授权的小批任务窗口；crawler 自身的 dispatcher、cache、frontier、checkpoint 均不能代替平台的 Task、Observation、Coverage 与限流事实。

## 5. Source、Profile、Adapter 与 Tool 边界

### 5.1 Source Profile

每个 Source 通过版本化 Profile 描述：

```yaml
source:
  base_url: https://example.com
  allowed_hosts: [example.com, www.example.com]
  include_paths: [/blog/, /posts/]
  exclude_paths: [/tag/, /author/, /search/, /login/]

discovery:
  providers:
    - {type: cms_api, priority: 10}
    - {type: sitemap, priority: 20}
    - {type: feed, priority: 30}
    - {type: archive, priority: 40}
    - {type: common_crawl, priority: 80, mode: gap_only}
    - {type: deep_crawl, priority: 90, mode: gap_only, max_depth: 3, max_pages: 5000}

incremental:
  overlap_seconds: 86400
  verify_known_urls: true

fetch:
  mode: AUTO
  requests_per_second: 0.5
  max_concurrency: 2
  browser_fallback: true
  interaction_fallback: false

browser_recipe:
  wait_for: "css:article"
  process_iframes: false
  flatten_shadow_dom: false

extract:
  target_elements: [article, main]
  remove_selectors: [nav, footer, .newsletter-signup]

assets:
  enabled: true
  max_bytes: 20971520
  allowed_mime_prefixes: [image/, application/pdf]
```

### 5.2 能力型 Adapter

业务层只依赖稳定接口：

```text
CrawlerAdapter
  probe(url, profile, limits) -> ProbeResult
  discover(seed, strategy, checkpoint) -> ObservationStream
  fetch(request, runtime) -> FetchResultStream
  render(snapshot_or_url, recipe, runtime) -> RenderResult
  interact(plan, runtime) -> InteractionResult
  extract_structured(artifact, schema_release) -> StructuredResult
  cancel(run_id)
  resume(checkpoint)
```

能力声明示例：

```text
STATIC_FETCH
CONDITIONAL_FETCH
LINK_DISCOVERY
SITEMAP_SEEDING
PREFETCH_DISCOVERY
DEEP_CRAWL
DEEP_CRAWL_RESUME
STREAMING_BATCH
JS_RENDER
SESSION_REUSE
IFRAME_PROCESS
SHADOW_DOM_FLATTEN
SCREENSHOT
MHTML_CAPTURE
STRUCTURED_EXTRACTION
INTERACTIVE_NAVIGATION
```

第三方 crawler 只能作为内部 Runtime；它自己的 REST/JWT/cache/frontier 不成为平台权限、业务状态或事实层。

### 5.3 Tool Exposure 与 Execution Binding

平台定义 Tool Registry，但 Tool Registry 不承载抓取业务实现：

```text
Tool Registry
  expose_schema(tool_name, input_schema, capability_requirements)
  bind_executor(tool_name, platform_command)
```

调用链：

```text
LLM / MCP / Operator
 -> Tool schema
 -> ToolInvocationContext
 -> Platform Command
 -> FetchPlan
 -> Policy Gate
 -> Adapter/Executor
 -> Artifact/Result
```

```text
ToolInvocationContext
  invocation_id
  actor_id
  source_id
  run_id
  task_id
  requested_capabilities
  deadline
  budget_ref
  policy_release_id
  cancellation_token
```

```text
ToolResult
  status
  final_url
  snapshot_id
  render_artifact_id
  interaction_run_id
  document_version_id
  output_refs[]
  usage
  diagnostics
```

约束：

- Tool 只返回平台对象引用和受控摘要，不泄漏第三方 Runtime DTO；
- schema 暴露不代表权限授予，执行仍通过 RBAC、Capability、Scope、SSRF/Egress、Budget 和 Action Policy；
- Tool Registry 可长生命周期复用，Browser/Page/Agent 仍按执行层生命周期管理；
- Tool 主要用于运维、Probe、Research、MCP/Agent 集成和 L4 异常能力，不成为百万 URL 主链调度器；
- 页面文本永远是 untrusted data，不能修改 Tool 集合、权限、预算、Secret 或系统策略。

## 7. 新站点接入与 Probe

创建 Source 后执行 `PROBE`：

1. DNS/TLS/redirect/robots/SSRF/Egress；
2. 探测 robots 中 Sitemap、`sitemap.xml`、RSS/Atom/JSON Feed；
3. 识别 WordPress/Ghost/Substack/静态站/Docs Framework；
4. 探测 CMS API、Archive、Category/Tag、Docs TOC；
5. 抽样 10~30 篇正文，比较 HTTP 与 Browser；
6. 检测 JS shell、hydration、iframe、Shadow DOM、Load More、分页；
7. 动态页面重复 2~3 次确认稳定 wait 条件；
8. 尝试 selector/规则/DOM 抽取；
9. 只有低质量时才试 LLM Schema Extraction；
10. 复杂 UI 先生成确定性 Recipe；
11. Recipe 无法稳定表达才允许 Agent Browser 探索；
12. Agent 探索成功后生成 Recipe 草稿；
13. Web 审核 Profile/Recipe/Schema 后激活。

## 8. 历史全量发现与 Coverage

Provider 优先级：

```text
CMS/API
 -> Sitemap/Sitemap Index
 -> Feed
 -> Archive/年月页/分页
 -> Category/Tag/Docs TOC
 -> URL Seeder/Common Crawl 补洞
 -> bounded Deep Crawl 补洞
```

Interactive Browser 只能帮助发现特殊入口，不能独立证明历史完整。

大站发现使用 Durable Streaming Frontier：

```text
fetch provider page/window
 -> parse URL items
 -> normalize + scope/filter
 -> upsert Observation 小批次
 -> persist provider cursor
 -> enqueue eligible FetchTask
 -> commit
 -> next page/window
```

禁止一次把全站几十万 URL 放入内存。

`BACKFILL COMPLETE` 至少满足：

- required authoritative provider 明确耗尽；
- cursor/checkpoint 已持久化；
- 年/月/分页边界交叉验证；
- known gap 为空或有明确接受理由；
- discovered/filtered/fetched/failed 数量可核对；
- Deep Crawl/Common Crawl 不再持续发现大量新正文；
- robots/policy/长期失败 URL 单独计为可解释缺口；
- max_pages/max_depth/cancelled 等截断必须记录；
- Agent “没有更多”、LLM confidence 或 BestFirst score 不能等同完整。

## 9. Fetch Planner 与路由

### 9.1 分层路由

```text
L0 Authoritative     CMS/API/Feed/Sitemap
L1 HTTP              静态正文/API/文件
L2 Browser Render    JS hydration，无复杂交互
L3 Fixed Recipe      固定 click/scroll/load-more/分页
L4 Interactive       未知 UI，多步骤 Agent Browser
```

AUTO：

```text
static/API/XML -> L1
JS shell/low quality -> L2
known interaction -> L3
unknown interaction -> L4 only if explicit policy
```

### 9.2 FetchPlan

```text
fetch_plan
  id
  task_id
  planner_kind: RULE_ENGINE | OPERATOR | LLM_ASSISTED
  planner_release_id
  route
  capability_set_json
  recipe_release_id
  schema_release_id
  allowed_hosts_json
  allowed_actions_json
  max_steps
  max_wall_time
  max_navigation_count
  max_bytes
  max_cost
  decision_evidence_json
  fingerprint
```

Planner 不拥有 Browser、核心 DB 或 Secret。

### 9.3 Policy Gate

任何执行前：

```text
Capability Check
 -> Allowed Host / Scope
 -> SSRF / Egress
 -> Robots / Compliance
 -> Action Policy
 -> Budget
 -> Domain/Source Rate Permit
 -> Executor
```

即使 LLM/Tool 提议了某动作，也必须经过同一 Gate。

## 10. Browser 生命周期与受控 Agent Browser

### 10.1 Browser Pool

```text
Browser Process = Worker 级复用
Context         = Source | Security Domain 隔离
Page            = Task 级短生命周期
Session         = 明确的 Recipe/Interaction Run
```

禁止跨 Source 共享 Cookie、LocalStorage、登录态、下载目录、代理身份。按 RSS/内存、Page 总数、Task 数、uptime、Browser crash/异常率阈值 recycle。

### 10.2 批量执行约束

HTTP/Browser Runtime 可以批量执行，但批量窗口由平台 Dispatcher 授权：

```text
global permit
 -> domain permit
 -> source permit
 -> bounded lease 20~100 tasks
 -> runtime small batch
 -> result per URL commit
```

禁止一次把单个大站的全部 URL 交给 crawler 内部队列，否则会破坏跨 Source 公平性、可取消性和 durable task 语义。

### 10.3 L4 Interactive Browser

只用于 Probe 未知站点、难以规则化的 UI、Research、连续确定性路线失败后的受控异常处理。

硬限制：

```text
allowed_hosts
allowed_actions
max_steps
max_wall_time
max_navigation_count
max_bytes
max_cost
allow_downloads=false by default
```

成功交互优先转成 L3 Recipe 草稿；日常增量默认禁用 L4。

### 10.4 Interaction Trace

```text
interaction_run
  fetch_plan_id
  model_release_id
  action_policy_release_id
  stop_reason

interaction_step
  step_no
  url_before
  observation_artifact
  action_type
  action_args_redacted
  url_after
  result_summary
  screenshot/rendered_dom
  policy_decision
```

最终页面 Artifact 再进入普通 Extract/IR/Markdown 链。

## 12. Durable Task、幂等与恢复

PostgreSQL 保存 durable task state，Transactional Outbox 同事务产生消息，Redis Streams 只负责运输。

```text
PENDING -> LEASED -> RUNNING -> SUCCEEDED
                    |          -> PARTIAL
                    -> RETRY_WAIT -> PENDING
                    -> QUARANTINED
                    -> DEAD
```

Task 领取时返回 `lease_until + fencing_token`，旧 Worker 不得用过期 token 覆盖新结果。

幂等键示例：

```text
DISCOVER: source + provider + release + cursor/window
OBSERVE: source + provider + normalized_url + evidence_identity
FETCH: source + normalized_url + sync_run
RENDER: snapshot + recipe_release + runtime_release
INTERACT: fetch_plan + policy_release + generation
TOOL: actor + tool + request_fingerprint + policy_release
EXTRACT: source_artifact + extractor_release
MARKDOWN: version + markdown_release
ASSET: document_version + normalized_asset_url + asset_policy_release
ENRICH: document_version + enrichment_kind + enrichment_release
EMBED: chunk + embedding_release
EXPORT: export_spec_hash + release
```

所有派生结果必须以 immutable ID 关联：

```text
DocumentVersion ID -> IR Block ID -> Chunk ID -> Embedding ID
DocumentVersion ID -> Asset ID
DocumentVersion ID -> Enrichment Result ID
```

禁止用标题相似度、slug、显示 URL 或 LLM 返回文本重新猜测对象身份。

Redis 清空后可从 PostgreSQL Task/Outbox 重建运输队列。

## 13. 并发、限流与背压

分层 Permit：

```text
global concurrency
 -> domain concurrency/rate
 -> source concurrency/rate
 -> worker-local dispatcher/semaphore
```

Worker 只 lease 20~100 条有界任务；批量 crawler 只能处理已授权窗口，结果逐 URL 提交。

初始压测范围：

```text
HTTP slots:          50~200 / cluster
Browser pages:       10~40 / cluster
Interactive pages:   2~10 / cluster
per-domain HTTP:     1~4
per-domain Browser:  1~2
```

真实上限按 robots、429、延迟、内存和 Browser crash 自动下调。

优先级：

```text
Incremental > Backfill > Verify > Projection/Enrichment > LLM fallback > Interactive Research
```

派生任务、Asset 下载与历史 Backfill 必须服从主抓取链背压，不能挤占新增文章的增量 SLA。

## 14. 内容抽取、Canonical IR、Markdown、Asset 与 Enrichment

### 14.1 内容抽取

候选 Extractor：site selector、trafilatura、readability、lxml/Crawl4AI candidate、DOM density。

质量评分至少包含正文长度、标题一致性、导航污染、链接密度、代码块/表格保留、metadata、语言异常、iframe/Shadow DOM 完整度。

站点专属 `h1`、日期正则、stop marker、正文 selector、图片 selector 等规则都应配置为版本化 Recipe/Schema，不散落到专用爬虫代码中。

### 14.2 Canonical IR

```text
DocumentVersion
  metadata
  blocks[]
    HEADING | PARAGRAPH | CODE | LIST | TABLE | QUOTE | IMAGE
```

每个 block 保存 locator 与 provenance。

### 14.3 Markdown

```text
CANONICAL_MARKDOWN = 完整正文，事实级导出
FIT_MARKDOWN       = Pruning/BM25/LLM 等有损过滤，仅用于检索上下文
ENHANCED_MARKDOWN  = 内部链接/展示增强，不替代事实版本
```

Canonical Markdown 规则：

- 标题层级稳定；
- 代码块保留空白与语言；
- 表格优先 GFM，不稳定时保留 HTML block；
- 相对链接转绝对链接；
- 图片保留 URL/alt/caption；
- 去导航/广告/Cookie banner；
- 不写入 AI 摘要、翻译、分类或改写正文。

Front Matter 至少包含：

```text
document_id
version_id
source_url
canonical_url
title
author
published_at
fetched_at
content_sha256
source_artifact_id
extractor_release
markdown_release
```

导出路径：

```text
knowledge/sources/{source_slug}/{yyyy}/{slug}--{document_id}.md
```

### 14.4 Asset Pipeline

正文 Extractor 只产出资源引用，不在 async 解析函数内用阻塞 I/O 下载图片或附件。

```text
IR IMAGE / ATTACHMENT reference
 -> AssetObservation
 -> Policy Gate
 -> async fetch
 -> redirect/SSRF/Egress recheck
 -> MIME / size validate
 -> sha256
 -> Object Storage
 -> document_asset relation
```

下载失败不阻塞 Canonical Document Version 建立；Markdown 可继续保留源站绝对 URL，并由 Asset Worker 异步重试。

### 14.5 Derived Enrichment

翻译、分类、摘要、关键词、实体、主题、排序等均从 `DocumentVersion` 异步派生：

```text
DOCUMENT_VERSION_READY
 -> optional typed DAG
    -> translate
    -> classify/tag
    -> summarize
    -> entity extraction
```

固定步骤优先用 Typed DAG/状态机，不使用自由 Agent 决定已知顺序。只有步骤本身未知、需要探索或动态规划时才使用 Agent。

LLM 输出必须使用结构化 Schema，例如：

```json
{
  "language": "zh-CN",
  "summary": "...",
  "category": "technical",
  "entities": []
}
```

校验失败进入 `INVALID -> repair/retry -> QUARANTINED`，禁止依赖“标题:”/“内容:”等字符串位置切片。

Canonical Version 成功与否不依赖 Enrichment。模型欠费、超时、Schema 失败只能影响派生分支，不能让正文事实链失败。

## 16. 增量同步与版本

### 16.1 Provider 独立 Cursor / Watermark

Provider 分别保存 cursor，不使用单一 `last_sync_time`。

优先：

1. CMS API `updated_at`/cursor；
2. Sitemap `lastmod`；
3. Feed GUID/published/updated；
4. Archive 最近窗口；
5. 定期低频 Coverage Verify/Deep Crawl 补洞。

对于时间型 Provider，必须使用 Watermark + Overlap：

```text
query_start = committed_watermark - overlap
query_end   = now
```

本轮允许重复发现，依赖 Observation 幂等吸收；只有数据和 next cursor 已 durable commit，才推进 watermark。

Overlap 解决：

- late arrival；
- 时区与 clock skew；
- 延迟发布；
- 老文章补发；
- Worker 中断后重跑；
- Provider 短暂漏项。

Feed 建议保留 rolling GUID/link 窗口；Archive 持续回扫最近 N 页/N 天；Sitemap `lastmod` 只作为候选优先级和证据之一，不能作为唯一事实。

### 16.2 已知 URL 仍需检查 Freshness

```text
URL 已知
 != 内容未变
 != 不需要再抓
```

已知 URL 只避免重复建立首次 Observation，不能跳过 Conditional Fetch 或 Provider 更新信号。

### 16.3 Conditional Fetch 与版本判定

```text
304
 -> 更新 observation/fetch evidence
 -> 不创建 Version

200 + raw hash same
 -> HTTP 页面无需重抽
 -> Browser-required 页面按 Profile 决定是否 verify render

200 + raw changed
 -> Extract/Render
 -> canonical hash same: 模板/广告噪音变化
 -> canonical hash changed: 新 Version
```

同 URL 可产生多个 Document Version；URL hash 只能作为 URL 身份辅助，绝不能直接承担内容版本身份。

### 16.4 删除检测

```text
ACTIVE -> SUSPECT_MISSING -> MISSING
       -> ACTIVE（再次发现）
```

综合 Sitemap/CMS 消失、连续 404、迁移/redirect 证据，不直接删除历史 Artifact。

## 18. 安全与合规

### 18.1 SSRF / Egress

起始 URL、redirect、iframe、Browser navigation、Deep Crawl 新链接、Agent action target、Asset URL 每跳重新解析并校验。

### 18.2 Prompt Injection 与 Tool 安全

```text
Web page / LLM
 -> proposes Tool/action
 -> Platform Policy Gate
 -> allowed capability/host/action/budget check
 -> execute or block
```

网页内容不能修改 allowed hosts、提升 Tool 权限、增加步骤/预算、读取 Secret、访问内部 URL、打开 Shell/文件系统/核心 DB。

### 18.3 Source Friendly

- 遵守 robots 和站点政策；
- 429 使用 Retry-After；
- exponential backoff + jitter；
- per-domain token bucket；
- 403/CAPTCHA 进入 `POLICY_BLOCKED`/人工审核；
- 不用代理轮换规避封禁、限流、付费墙或登录限制。

## 22. 失败模式与降级

- Redis 不可用：停止运输；PostgreSQL Task/Outbox 保持真相，恢复后重发；
- PostgreSQL 不可用：Worker 停止领取新任务；
- Object Storage 不可用：抓取不得标记持久成功；
- Browser crash：单 URL/小窗口重试并 recycle；
- wait 超时：按 Recipe fallback/失败证据处理；
- 429/503：domain circuit breaker + Retry-After + jitter；
- 403/CAPTCHA：Policy Block，不自动绕过；
- Extractor 质量下降：Quarantine，旧 Snapshot 离线重跑；
- Schema 失败：结果 INVALID/PARTIAL，不生成正式 Observation；
- Asset 下载失败：保留源 URL 与失败证据，异步重试，不阻塞 Canonical Version；
- Asset MIME/size/SSRF 违规：Policy Block，不自动放宽限制；
- Enrichment 模型不可用/欠费/超时：只暂停派生任务，不影响正文入库；
- Enrichment Schema 失败：Quarantine 对应派生结果，不覆盖旧正式结果；
- LLM 成本异常：预算熔断；
- Tool 未绑定执行器/无权限/超时：失败并保留 Invocation/Audit，不自动扩大权限；
- Interactive 超步数/超时/越域：立即停止并保留 Trace；
- Runtime 升级回归失败：保持旧 ACTIVE；
- checkpoint 丢失：从 seed 重跑，Observation 幂等吸收重复；
- watermark 窗口失败：不得提前推进 committed watermark；恢复后从 overlap 窗口重跑；
- Agent memory 丢失：只增加重复执行，不丢业务事实。

## 24. 最终验收标准

**历史完整性**：权威 Provider 有 Coverage Evidence；大站 URL 流式持久化；中断可恢复；选择性 crawler/Agent 不误报完整。

**增量**：新文章按 SLA 发现；时间型 Provider 使用 overlap，late arrival 不因硬切时间窗口丢失；已知 URL 仍会按策略检查 Freshness；304 不产生版本；模板噪音不制造大量假版本；删除有多阶段判定。

**可回放**：每篇正文可回溯 Snapshot/Render Artifact；不联网即可重跑 Extractor/Markdown；Watermark、Provider cursor 和检查证据可审计。

**Markdown**：同一 IR + Markdown Release 输出确定；代码、表格、链接、图片稳定；Canonical 与 FIT/Enrichment 分离。

**身份稳定性**：所有跨阶段关联均使用 DocumentVersion/Block/Chunk/Asset 等 immutable ID，不使用标题模糊匹配恢复对象。

**派生隔离**：翻译、摘要、分类、实体、排序有独立 Release 与幂等结果；模型故障不影响 Canonical 入库；升级模型可批量重建且不污染旧版本。

**资源处理**：图片/附件异步获取，MIME/size/hash/SSRF/Egress 有统一策略；失败不阻塞正文；hash 可去重且引用关系完整。

**扩展性**：新增 Source 主要靠 Probe + Profile/Recipe/Schema，不需要修改核心抓取框架。

**Browser 成本**：静态页不进入 Browser；Browser Process 复用；Context 安全隔离；Interaction Pool 独立预算。

**Tool/Agent 解耦**：同一平台能力可暴露给 Web/MCP/Agent，但 schema 暴露与执行权限分离；更换 Agent/Crawl Runtime 不改变核心事实契约。

**Agent 安全**：L4 只有显式策略可用；每步有 URL/动作/预算 Gate；Prompt Injection 无法扩大权限；成功流程可固化 Recipe。

**可恢复性**：Redis 清空可重建；lease/fencing 防止旧 Worker 覆盖；runtime state 丢失不丢业务事实；Watermark 只在 durable commit 后推进。

**版本治理**：Crawler、Browser、Agent、Policy、Extractor、Enrichment 升级都有 Release、benchmark、canary 和回滚。

## 25. 最终结论

最终系统应是一套 Coverage-first 数据平台，而不是一个爬虫脚本：

```text
Coverage-first Discovery
        +
Durable Observation / Task / Cursor / Watermark+Overlap
        +
Rule-based Fetch Planner
        +
Policy-gated Executor
        +
HTTP -> Browser -> Recipe -> exceptional Agent Browser
        +
Snapshot / Render / Interaction Evidence
        +
Canonical IR / Deterministic Markdown
        +
Known-URL Freshness / Incremental Versioning
        +
Async Asset Pipeline
        +
Versioned Derived Enrichment
        +
Stable Immutable IDs Across Stages
        +
Rebuildable Search / Vector / Export
        +
Tool Schema / Execution Binding Separation
        +
```

主链保持确定性：`CMS/Sitemap/Feed/Archive -> Observation -> HTTP -> deterministic Browser -> versioned Recipe -> Snapshot -> IR -> Version`。已知 URL 只意味着“曾被发现”，不意味着“内容永久不变”；时间型增量使用 Watermark + Overlap 吸收晚到与中断；Crawl4AI 作为可替换 Runtime 由 Adapter 隔离，Browser Agent 只作为受控异常能力。

Canonical 内容建立后，Asset、Search/Vector、翻译、分类、摘要、实体等通过独立异步分支处理。所有派生任务以 `DocumentVersion + Release` 幂等，所有跨阶段关联使用稳定 ID，不依靠标题或文本相似度。这样可以同时满足 1000+ 站点全量历史覆盖、持续增量、后续扩容、低成本、高吞吐、可恢复、可审计、可回放与 Web 管理需求。
