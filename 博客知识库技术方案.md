# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站和公开 Newsletter** 的长期知识库采集平台，可平滑扩展到数千站点、百万级到千万级文章，并持续支持新增站点。

系统必须满足：

1. **全历史回填**：尽可能完整发现并抓取每个已批准 Source 的历史文章，能够解释 Coverage、Known Gap、失败、停止原因和边界；
2. **持续增量同步**：持续发现新文章、正文更新、URL 迁移、重定向、删除和重发布；
3. **稳定 Markdown**：Markdown 从不可变 Raw Artifact 经确定性抽取、质量门禁和 Canonical IR 生成，而不是直接把某个 crawler 的即时 Markdown 当最终结果；
4. **低成本扩站**：新增网站优先通过 Source Profile、Provider、Traversal Policy、Extraction Recipe 配置完成，不维护 1000 份独立爬虫脚本；
5. **Web 可运营**：支持 Source 接入、审批、配置发布、Backfill、Incremental、Coverage、Frontier、质量、成本、失败诊断、暂停/恢复/停止和审计；
6. **可搜索与 RAG**：支持 BM25、向量和混合检索，并能从检索结果回溯原文、版本、Source、Artifact 和抓取证据；
7. **可观测、可恢复、可重放**：任意 URL、Task、Artifact、IR、Markdown、Focused Score 都能解释来源、版本和执行路径；
8. **渐进扩展**：开发期 Docker Compose，生产期按 Discovery、HTTP、Browser、Extraction、Projection 等 Worker 类型水平扩容；
9. **主链不依赖 LLM**：LLM 只用于可选增强，不参与 Coverage Truth、URL Identity、Canonical URL、Robots Access、历史完整性最终判定；
10. **高成本抓取有硬预算**：Browser、Deep Crawl、Repair、Focused Job 都有平台拥有的 page/request/browser/model/wall-clock 预算；
11. **Web 配置安全**：Web/API 用户只能提交声明式、低能力配置，不能直接获得任意 JS、代理、CDP、浏览器 profile、Deep Crawl Strategy 等 Runtime 能力；
12. **停止后真正静默**：取消、暂停、Lease 丢失或 Worker recycle 后，运行时所有 task/page/context/session 必须完成清理，不能留下幽灵抓取。

### 1.1 核心 SLO

- **Coverage**：每个 Source 能解释 Provider、已发现 URL、Frontier、Known Gap、Backfill 停止原因；
- **Freshness**：新文章从发布/发现到 PASS Markdown 的延迟；
- **TTFM**：URL 首次发现到首个可用 Markdown 的时间；
- **Extraction Quality**：标题、正文完整率、噪声率、代码块/表格/列表保留率、截断率；
- **Reliability**：Task 成功率、Retry、DLQ、Queue Age、Lease Recovery、Checkpoint Resume 成功率；
- **Browser Efficiency**：HTTP 命中率、Browser avoided/recovery、每文档 Browser 成本；
- **Identity Quality**：重复文章误合并/漏合并率；
- **Validity Quality**：Soft-404、假 200、空壳 SPA 识别准确率；
- **Traceability**：任意 Markdown 可回溯 Source、URL、Artifact、Extractor、Quality、Renderer Release；
- **Cancellation**：停止请求到停止新 Admission、到 Runtime QUIESCED、到 Run STOPPED 的延迟；
- **Runtime Quiescence**：Run/Worker 释放前 active task/page/context/session/local queue/resource token 均为 0；
- **Config Safety**：Web/API power-field 绕过数为 0，所有 Runtime Config 可回溯编译报告和 Release；
- **Admission Accuracy**：硬预算 overshoot 为 0；429/503/413 等容量语义可观测；
- **Cost**：按 Source、Run、Queue Class、每 1000 篇 PASS 文档统计抓取、Browser、存储、索引和模型成本；
- **Focused Efficiency**：pages-per-useful-result、expected gain、Browser 节省比例和 stop reason；
- **Replayability**：同 release + 同输入可复现抽取、渲染和评分结果。

### 1.2 非目标

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不默认使用个人持久 Browser Profile、Magic/模拟用户或反爬绕过能力；
- 不把 HTTP 200、DOM 很长或 crawler success 直接视为正文正确；
- 不把搜索结果数、Common Crawl、Wayback、Deep Crawl 页数、Adaptive confidence、`max_pages`、runtime round/depth 当历史完整性证明；
- 不把 Crawl4AI 即时 Markdown、LLM 摘要或改写直接作为 Canonical Markdown；
- 不因 URL 曾抓过就永久停止复检；
- 不把 Redis、Browser Session、Crawler Cache、Visited Set、Dispatcher Queue、Adaptive State、Search Index 当业务真相；
- 不允许优先级、相关性阈值、信息增益阈值或执行预算永久删除潜在历史文章；
- 不允许 Web/API 调用者直接构造任意 Runtime 对象、运行任意代码或指定任意文件系统路径；
- 不默认对所有文档构建 GraphRAG。

## 2. 核心设计原则

1. **Coverage First**：先建立 URL Inventory，再批量抓正文；
2. **Authoritative First**：CMS/API、Sitemap、RSS/Atom、官方 Archive 优先；
3. **Historical Gap Is Evidence, Not Truth**：Common Crawl、Wayback 用于历史补洞，不作为完整性证明；
4. **Deep Crawl Is Gap Provider**：站内深度抓取用于补洞，不作为 Coverage Truth；
5. **Focused Is Optimization**：Focused confidence 只表示专题信息充分度，不等于历史 Coverage；
6. **Discovery / Fetch / Extract / Quality / Projection 分离**；
7. **HTTP First, Browser Last**：Browser 是受治理慢路径；
8. **Snapshot First**：先保存不可变 Artifact，再抽取和清洗；
9. **Canonical IR First, Markdown as Projection**；
10. **Recipe, Not 1000 Site Scripts**；
11. **Stable Identity**：Source、Host、URL、Artifact、Document、Version 使用稳定 ID；
12. **Idempotent + Recoverable**：任务使用幂等键、Lease、Fencing Token、Checkpoint；
13. **Fair by Default**：大站 Backfill 不能饿死 Incremental 和小站；
14. **Bounded Concurrency Everywhere**：禁止无界 asyncio gather、Browser Context、Preview、模型 fan-out；
15. **No Silent Degradation**：截断、预算耗尽、降级、过滤、跳过必须记录原因；
16. **Release Everything That Changes Results**：Profile、Provider、Traversal、Runtime Config、Extractor、Quality、Renderer、Embedding、Rank 全部版本化；
17. **Priority Means When, Not Whether**：priority/expected gain 决定何时处理，不决定 URL 是否永久保存；
18. **Observation Before Selection**：观察到链接后先保存事实，再 Filter/Score/Budget；
19. **Persistent Frontier, Not In-Memory Traversal**：业务候选进入数据库；
20. **Runtime Checkpoint != Business Checkpoint**：第三方 crawler resume state 只是执行优化；
21. **Cooperative Cancellation + Runtime Quiescence**：停止必须结束本地 in-flight 资源后才算静默；
22. **Approved Scope First**：发现 host/path 不等于允许访问；
23. **Soft-404 Is First-class**：存在性不能只依赖状态码；
24. **Global Admission + Local Adaptation**：跨 Worker 公平/限流由平台负责，Worker 内存保护由 Runtime 负责；
25. **Runtime Result Is Advisory**：第三方 dedup/status/score/limit/cache/confidence 都不能直接升级为平台业务真相；
26. **Normalize Conservatively**：scheme/host 可标准化，path/query 默认保留大小写和语义；
27. **Explicit Runtime Capabilities**：生产行为不得依赖第三方默认能力集；
28. **Robots Policy Is Access Control Input**：由平台 RFC 9309 Policy Engine 负责；
29. **Correlate by Identity, Never by Position**：批量结果按 `attempt_id/url_id/requested_url` 关联；
30. **Strict Budget Is Platform-owned**：所有高成本预算由平台硬控；
31. **Graph Depth Is Platform-owned**：真实 depth 来自持久 URL Edge；
32. **Config Must Prove Effective**：配置只有经过 pinned-release 行为测试后才能作为生产硬控制项；
33. **Score Input Must Be Replayable**；
34. **Config Is Capability**：外部配置不是普通数据，能改变网络、代码执行、浏览器和 secret 的字段必须由 Capability Firewall 控制；
35. **Untrusted by Default at Network Boundary**：来自 Web/API 的配置一律按 UNTRUSTED 处理，经平台编译后才成为 Runtime Config；
36. **Caller Never Owns Paths**：调用者只持 opaque artifact id，文件系统路径/Object Key 由服务端生成；
37. **Quiesce Before Reuse**：Runtime 未清零前不得复用 crawler/browser/worker，也不得宣称 STOPPED；
38. **Zero Must Not Mean Unbounded by Accident**：生产预算 0 不默认解释成无限，解除上限只能由 Operator Policy 明确发布。

```text

                                         |
                              Auth + RBAC + Audit
                                         |
                          API Resource Admission
                                         |
                       Declarative Source/Profile API
                                         |
                    Capability Policy + Config Compiler
                                         |
                              PostgreSQL Truth Store
                                         |
                             Transactional Outbox
                                         |
                                Redis Streams
                                         |
                      Global Admission + Fair Scheduler
                                         |
       +---------------------------------+----------------------------------+
       |                                 |                                  |
 Discovery Plane                    Fetch Plane                     Projection Plane
       |                                 |                                  |
 CMS/API/Sitemap/RSS                   HTTP                              Markdown
 Archive/Listing                       Browser                           OpenSearch
 CommonCrawl/Wayback                   Crawl4AI Runtime                  pgvector
 Safe Domain Recon                     Playwright                       Enrichment
 SafeProbe                             PDF/Other                        Preview
 Deep Crawl Prefetch                   Runtime Quiescence               Artifact Gateway
 Focused Scheduler
       |                                 |                                  |
       +--------- Observation -> Persistent URL Inventory / Frontier -------+
                                         |
                                URL Validity Gate
                                         |
                                Immutable Artifact
                                         |
                              Extraction Portfolio
                                         |
                            Candidate Quality Gate
                                /                \
                             PASS                REPAIR
                                \                /
                                 Canonical IR
                                         |
                                  Document Version
                                         |
                              Identity / Provenance
```

### 3.1 业务真相边界

**PostgreSQL + Object Storage 是业务真相。**

- PostgreSQL：Source、Approved Host、Provider、URL Identity、Observation、Robots、Validity、Frontier、Task、Cursor、Coverage、Quality、Document、Version、Release、Runtime Cleanup、Audit；
- S3/MinIO：Raw HTML、MHTML、PDF、Provider Evidence、Preview、Candidate、IR、Markdown、Checkpoint、Trace；
- Redis Streams：任务运输、Consumer Group、Backpressure；
- Redis Lua：Token Bucket/Semaphore/短期资源令牌；
- OpenSearch / pgvector：可重建 Serving Projection；
- Crawl4AI cache、local dispatcher queue、visited set、browser context、Playwright page/session、Adaptive state：全部属于可丢失 Runtime State。

### 3.2 Runtime Adapter 边界

Crawl4AI 作为版本固定的 Adapter：

```text
Platform Command
 -> compiled runtime_config_release
 -> Crawl4AI Adapter
 -> HTTP/Browser/Deep Crawl execution
 -> Runtime Result Envelope
 -> Raw Artifact / Observation
 -> Platform Truth
```

Runtime 不拥有：Source 生命周期、全局 Frontier、Coverage、最终 Canonical Identity、最终 Version、最终 Markdown、全局限流或安全审批。

## 4. 技术选型与 Release

### 4.1 控制面

- **FastAPI + Pydantic**：REST API、Command、Schema；
- **PostgreSQL**：Truth Store、任务、Frontier、Coverage、版本、审计；
- **Redis Streams**：任务运输与 Backpressure；
- **Redis Lua Token Bucket/Semaphore**：跨 Worker 域名和资源限流；
- **React / Next.js + TypeScript**：Web 管理后台；
- **OpenTelemetry + Prometheus + Grafana + Structured Logging**；
- **S3/MinIO**：不可变对象；
- **Vault/KMS/Secret Manager**：secret 引用；
- **Nginx/Envoy/API Gateway**：TLS、请求体上限、Rate Limit、Correlation ID。

### 4.2 Discovery / Fetch

- **httpx/aiohttp**：robots、Sitemap、Feed、CMS API、Conditional GET、普通网页、SafeProbe；
- **RFC 9309 Robots Engine**；
- **Crawl4AI pinned release**：Browser Render、Deep Crawl Prefetch、Domain Mapping/Seeder 等受控能力；
- **MemoryAdaptiveDispatcher**：仅 Worker 本地内存自保护；
- **Playwright Python**：复杂页面慢路径；
- **Common Crawl Adapter / Wayback CDX Adapter**：历史补洞；
- **合规 Search API/SearXNG Adapter**：Gap、新 Source Candidate；
- **PyMuPDF/pdftotext**：PDF；扫描件进入 OCR 慢路径；
- **Python MIME Parser**：Newsletter Inbox Provider。

### 4.3 Extraction / Search

- **Trafilatura**：Generic Candidate；
- **lxml/BeautifulSoup**：DOM/XPath、Metadata、Repair；
- **JSON-LD/OpenGraph/Microdata**；
- **CSS/XPath/Regex Recipe**；
- **SimHash/MinHash**：近重复候选；
- **OpenSearch BM25 + pgvector + RRF**；
- 可选 embedding/reranker/LLM，仅作用于 Canonical 数据或 Focused Job。

## 6. Source 接入与声明式配置

新增网站先自动探测，再人工确认并发布 immutable Source Profile Release：

```text
1. exact-host robots / Sitemap / Feed
2. CMS 特征：WordPress/Ghost/Medium/Substack/API
3. 首页与安全内容路径探测
4. Archive / Pagination / URL Pattern
5. Canonical / Redirect / Query 参数行为
6. Soft-404 baseline
7. HTTP vs Browser route sampling
8. metadata-only 子域候选发现
9. 人工审核 Content Host
10. Common Crawl / Wayback Gap inventory
11. Deep Crawl 浅层 Prefetch
12. 生成 Source Profile Draft
13. Capability Compile + Dry Run
14. 发布 immutable Source Profile Release
```

### 6.2 Capability Firewall

Web/API 用户只能编辑平台声明字段。以下能力默认不得由外部请求直接提供：

```text
js_code / c4a_script
browser extra_args
proxy / proxy_config / proxy rotation
cdp_url / debugging_port
user_data_dir / browser context id / target id
cookies / storage_state / init_scripts
fallback_fetch_function
runtime session_id
deep_crawl_strategy object
dispatcher object
arbitrary class/type construction
env:SECRET style secret resolution
caller filesystem output_path
```

执行路径：

```text
UNTRUSTED request
 -> API JSON Schema
 -> semantic validation
 -> capability allowlist
 -> numeric clamps
 -> server-side secret references
 -> operator policy injection
 -> config compiler
 -> compilation report
 -> immutable compiled runtime config
```

未知字段在 Web Admin 必须显式提示，不能让运营人员误以为已生效。

### 6.3 数量级 Clamp

至少硬控：

### 7.3 Backfill 完成条件

至少满足：

- 权威 Provider 完成或明确不可用；
- Historical Gap Provider 到达配置边界且限制有记录；
- Persistent Frontier 无 READY/LEASED/RETRY；
- Archive/Deep Crawl 不再产生新增候选，或达到可解释收敛；
- 失败任务成功、DLQ 或人工接受；
- Soft-404 疑似已确认/延期/接受；
- Known Gap 为空或人工接受；
- 多 Provider URL 集合差异在阈值内；
- 所有结束的 Runtime Slice 已 QUIESCED。

**Focused confidence、saturation、max_pages、low gain、Runtime Cache Hit、runtime round/depth 绝不能作为 Backfill Complete 条件。**


## 11. Runtime Quiescence 与停止/恢复

### 11.1 为什么停止必须是状态机

“Web 点停止”“Scheduler 不再发 Lease”“async generator 返回”都不等于运行时已停止。Browser Runtime 可能仍存在后台 asyncio task、page、context、session、monitor 或本地队列。

统一状态：

```text
RUNNING
 -> STOP_REQUESTED
 -> QUIESCING
 -> QUIESCED
 -> STOPPED
```

正常结束也必须经过 cleanup，只是 trigger 不同。

### 11.2 Cleanup Protocol

收到 Cancel/Pause/Lease Lost/Recycle/Shutdown 时：

```text
1. 停止本 slice 的 local admission
2. cancel 未完成 runtime tasks
3. await 所有 active tasks（有 grace timeout）
4. drain local runtime queue
5. close page/context/session
6. cancel/await memory monitor/helper tasks
7. release Redis browser/domain/resource token
8. flush cleanup evidence
9. 校验 counters == 0
10. 标记 QUIESCED
```

必须满足：

```text
active_tasks == 0
local_queue == 0
pages == 0
contexts == 0
sessions == 0
held_tokens == 0
```

才允许 crawler/browser/worker 复用。

### 11.3 Cleanup Timeout

若 grace timeout 到期：

```text
mark TIMED_OUT
 -> terminate isolated worker process/container
 -> fencing rejects late commit
 -> release/expire lease
 -> unfinished URL RETRY
 -> record incident metric
```

不能为了“优雅退出”无限等待。

### 11.4 Lease 与 Runtime 生命周期

数据库 Lease 是业务恢复手段，Runtime cleanup 是执行资源恢复手段，二者必须同时存在：

- Lease 解决 Worker crash 后 URL 不丢；
- Fencing 解决迟到 Worker 覆盖新结果；
- Quiescence 解决旧 Runtime 继续抓取和资源串扰。

## 21. 推荐默认策略

### Backfill

```text
1. CMS/API + Sitemap + RSS 建 Inventory
2. Archive/Pagination 补官方历史入口
3. Common Crawl + Wayback 补历史盲区
4. 新 host 只生成 Candidate，批准后访问
5. Deep Crawl Prefetch 只做 Gap Scan
6. BFS 默认，max_graph_depth 2~3 起步
7. 每 Source 每 Slice 200~500 URL
8. Observation/Edge 先落库
9. score 只映射 priority
10. Soft-404 先 Validity
11. HTTP First，Browser Slow Lane
12. Raw Artifact durable 后再 Extract
13. Runtime Slice 结束必须 QUIESCED
14. Frontier 清空 + Provider 完成 + Known Gap 审核后才完成
```

### Incremental

```text
RSS/CMS 高频
Sitemap 中频
Homepage/Archive 低频
Conditional GET
Head Fingerprint fallback
周期 CC/Wayback delta
周期 Deep Gap Scan
```

### Web/API Config

```text
all external config = UNTRUSTED
declarative source profile only
power fields default deny
unknown fields visible
server-side secret refs only
hard numeric caps
compiled immutable runtime config
```

### Browser Runtime

```text
HTTP first
no default magic/simulated-user/auth-profile
one attempt has stable identity
local concurrency bounded
stream/cancel always cleanup+await+drain
not quiesced => no reuse
cleanup timeout => kill isolated worker
```

### Artifact

```text
caller never supplies path/object key
durable raw -> S3 immutable key
ephemeral debug -> opaque artifact id + TTL + quota + RBAC
```

## 22. 验收标准

平台达到可生产使用至少满足：

1. 新增标准博客主要通过 Web Source Profile 完成，不新增独立爬虫脚本；
2. 新 host 未经批准不能主动抓取；
3. 任意 Source 可执行全历史 Backfill，并解释 Coverage、Historical Gap、Known Gap；
4. Common Crawl/Wayback/Focused confidence 不被误当完整性证明；
5. 任意 URL 能解释 Provider、Observation、Graph Depth、Filter、Admission、Validity、Frontier；
6. SPA/自定义 404 不会仅因 HTTP 200 大规模进入正文库；
7. URL Normalizer 默认保留 path/query 大小写语义；
8. Worker 任意 kill 后不丢业务 Frontier，可通过 Lease 恢复；
9. Runtime local queue/cache/session 丢失仍可从 PostgreSQL/Object Storage 重建；
10. `max_pages`、低 score、low gain、Provider timeout 不让历史候选静默消失；
11. 点击停止后停止新 Admission，并最终完成 Runtime QUIESCED；
12. STOPPED 时 active task/page/context/session/local queue/held token 为 0；
13. cleanup timeout 后 Worker 被隔离，late commit 被 fencing 拒绝；
14. Raw Artifact 可重放生成新 IR/Markdown，不必重新抓网页；
15. Incremental 通过 RSS/Sitemap/CMS/Conditional GET 持续同步；
16. Markdown 保留标题、正文、代码、表格、列表等关键结构并通过质量门禁；
17. Search Index 全部可从 Canonical 数据重建；
18. 所有改变结果或权限的组件都有 Release，并通过 Golden Replay/Posture Test；
19. Web Admin 可完成接入、审核、Backfill、Incremental、Coverage、失败诊断、暂停/恢复/停止和审计；
20. Web/API 不能直接提交 `js_code`、browser `extra_args`、proxy、CDP、user-data-dir、cookies、任意 Runtime Strategy；
21. 不可信配置不能读取服务端环境变量 Secret；
22. 所有外部配置都有 compilation report，能看到 rejected/clamped/injected 字段；
23. request/body/principal/queue 超限分别有 413/429/503 等明确语义；
24. page/http/browser/model 等硬预算 Golden Test overshoot 为 0；
25. 批量部分失败时成功结果按 `attempt_id/url_id` 正确关联；
26. 任何 caller 都不能指定服务器文件系统输出路径；
27. 临时 Screenshot/PDF/Trace 使用 opaque artifact id、RBAC、TTL 和 quota；
28. Runtime Cache 不推进业务 Cursor，不改变 Coverage/Version Truth；
29. Deep Crawl Runtime depth/visited/queue 不替代平台 graph depth/Frontier；
30. Browser Runtime 不默认绕过登录墙、付费墙、CAPTCHA 或 WAF；
31. Browser Worker 未 QUIESCED 前不能回到复用池；
32. Redis/PostgreSQL/MinIO/Browser Runtime 不直接公网暴露；
33. 第三方 Runtime 配置只有 `VERIFIED_EFFECTIVE` 才可作为生产硬控制；
34. Source/Run/Task/URL/Artifact/Version 全链路有 correlation/trace；
35. 整体系统能够从 1000 站扩展到更多站点而不引入线性数量的专用爬虫代码。

最终架构原则：

> **权威 Provider 建 URL Inventory，Common Crawl / Wayback / Deep Crawl 等只补 Coverage Gap；Observation 与 URL Edge 先于选择，Approved Scope 与 RFC 9309 Robots 先于主动访问，Persistent Frontier、Lease/Fencing 与平台 Graph Depth 保证不丢不串；外部配置一律视为 UNTRUSTED，经 Capability Firewall 与 Config Compiler 才变成 Runtime 能力；HTTP First、Browser Slow Lane，任何停止都必须通过 Runtime Quiescence Barrier；调用者只持 opaque Artifact ID，不拥有服务器路径；Raw Artifact 保证可重放，Canonical IR 保证稳定 Markdown；第三方 crawler 负责高效执行，PostgreSQL + Object Storage 始终拥有业务真相。**
