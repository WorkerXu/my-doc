# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站和公开 Newsletter** 的长期知识库采集平台，并能平滑扩展到数千站点、百万级文章。

系统必须满足：

1. **全历史尽量抓全**：历史完整性用 Discovery Provider、游标、时间范围、穷尽证据和 Known Gap 解释，而不是以“爬虫跑完”代替 Coverage；
2. **持续增量同步**：发现新文章、正文更新、元数据变化、URL 迁移、删除和重发布；
3. **稳定生成 Markdown**：保存不可变原始抓取事实，经抽取、质量校验、Canonical IR 后由版本化 Renderer 生成 Markdown；
4. **新增站点低成本**：以 Site Family、Source Profile、Discovery Recipe、Route Policy、Extraction/Repair Recipe 复用能力，避免每站长期维护独立爬虫；
5. **Web 可管理**：支持接入、Probe、配置、调度、Coverage、URL Inventory、任务、质量、回放、版本、成本、导出、Agent 建议、审批和告警；
6. **可追溯、可重建**：任意 Markdown 能回溯 Source Release、URL、Artifact、Extractor、Quality、Repair/Fallback、Document Version、Renderer 和运行记录；
7. **幂等可恢复**：任务可重试、续跑、回放，不产生脏重复；
8. **高吞吐数据面保持确定性**：HTTP、Browser Recipe、正文抽取、版本判定和 Markdown 渲染默认不依赖 LLM；
9. **智能能力位于低频控制面**：用于 Source Probe、Gap/Quarantine/Drift 诊断、规则建议和 Canary 辅助审查，不允许无审批地修改生产规则；
10. **成本可治理**：Authoritative Discovery、Cheap Routing、HTTP First、Browser Last，Browser/LLM/Graph 都有独立预算、收益统计和熔断；
11. **隐式状态显式化**：业务真相、Agent 输入输出、Tool Failure、模型、Prompt、Schema、Release、Trace 都可记录、审计和回放；
12. **运行时可复现**：Crawler、Browser、Extractor、Renderer、Agent Prompt/Model/Tool Schema 升级经过冷启动测试、Replay、Canary 和版本发布；
13. **确定性外层编排**：Agent/Crew 只能是有界的“智能活动”，流程顺序、分支、重试、恢复、审批和副作用由平台状态机/Workflow Engine 控制。

### 1.1 核心 SLO

- **Coverage**：Provider coverage、exhaustion evidence、Known Gap；
- **Freshness**：文章发布到进入 PASS/WARN Canonical Markdown 的延迟；
- **Extraction Correctness**：正文完整率、噪声率、结构保留率、Candidate Agreement；
- **Routing Efficiency**：Page Type 分类准确率、Browser avoided、UNKNOWN/LLM Exception 比例；
- **Fallback Efficiency**：Browser/Repair recovery rate、quality delta、p95 latency、cost per recovered document；
- **Reliability**：Task 成功率、Retry/DLQ、Queue Age、Worker 恢复率；
- **Traceability**：任意结果可回溯不可变 Artifact、Release 和完整执行树；
- **Agent Governance**：Candidate 接受率、Schema Validation 失败率、Tool Failure、预算超限率、Golden Replay 通过率；
- **Cost**：按 Source、Run、Queue Class、每 1000 个 PASS 文档统计成本。

### 1.2 非目标

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不把 HTTP 200、Crawler success、DOM 很长直接等同于正文正确；
- 不用 LLM 主观判断代替 Coverage Evidence；
- 不把 Crawl4AI `fit_markdown`、LLM 摘要或改写直接作为 Canonical Markdown；
- 不因 URL 曾抓取过就永久停止复检；
- 不允许规则、模板、Prompt、模型升级无 Release/审计地改变生产结果；
- 不默认为全部文档构建 GraphRAG；
- 不让 Agent Memory、Notebook Kernel、Redis Cache、Browser Session 成为业务真相；
- 不给 Agent 任意文件系统、Shell、任意 JS/evaluate、无限网络访问或任意外部副作用权限；
- 不因为昂贵慢路径熔断而把未通过 Quality Gate 的内容静默标记为 PASS。

## 2. 核心设计原则

1. **Coverage First**：先建立 URL Inventory，再批量抓正文；
2. **Authoritative First**：CMS/API、Sitemap、RSS/Atom、Archive 优先；
3. **Discovery Before Fetch**：发现、规范化、分类、抓取、抽取分离；
4. **Cheap Routing Before Expensive Execution**：Provider Hint、URL Rule、MIME、Structured Metadata、DOM Heuristic 优先；
5. **HTTP First, Browser Last**：只有可解释证据证明必要时才升级 Browser；
6. **Snapshot First**：先保存不可变 Artifact，再抽取与清洗；
7. **Fetch != Extract != Quality**：网络成功、抽取成功、质量通过是独立状态；
8. **Extractor Is Candidate Generator**：任何 Extractor 只产生 Candidate；
9. **Critique Before Publish**：Candidate 必须通过独立 Quality Gate；
10. **Repair Is Bounded**：修复是有限状态机，不允许无限 Agent/LLM 循环；
11. **IR First, Markdown as Projection**：Canonical IR 是结构事实，Markdown 可重建；
12. **Recipe, Not Site Code**：站点差异通过版本化 Profile/Policy/Recipe 表达；
13. **Stable Identity**：Source、URL、Artifact、Document、Version 使用稳定 ID；
14. **Idempotent + Recoverable**：Task 有幂等键、lease、fencing token、checkpoint、Retry、DLQ；
15. **Fair by Default**：大站 Backfill 不饿死增量和小站；
16. **Slow Path Isolated**：Browser、LLM Exception、Agent、Graph 使用独立 Queue/Pool/Budget；
17. **Fallback Must Earn Its Cost**：慢路径持续比较 recovery、quality gain、latency、cost；
18. **Release Everything That Changes Results**：Profile、Route、Recipe、Runtime、Extractor、Renderer、Schema、Prompt、Tool Schema、Model、Workflow Contract 全版本化；
19. **No Silent Degradation**：预算耗尽、能力未执行、慢路径熔断必须显式 DEGRADED/QUARANTINE/Known Gap；
20. **Agent In Control Plane**：Agent 可建议、分析、批评、修订候选，但不成为百万级逐 URL 默认数据面；
21. **Typed Handoff, No Hidden Memory**：跨阶段只传 Schema + Artifact/Evidence Ref；
22. **Capability-Scoped Tools**：Tool 采用最小权限和结构化输入输出；
23. **Bounded Concurrency Everywhere**：HTTP、Browser Context、`gather`、Agent Tool Call 都有边界和背压；
24. **Cold-start Reproducibility**：发布前在全新 Runtime 通过集成测试和 Golden Replay；
25. **Deterministic Orchestrator Around Agent Pockets**：平台工作流持有状态和控制权，Agent/Crew 只处理开放式子任务；
26. **Explicit Workflow Contract**：每步声明 consumes、produces、input/output schema、required evidence、failure/retry policy；
27. **One Trace Tree Per Run**：Agent Step、Model Call、Tool Call 必须继承同一 Root Trace，不允许每个 Tool 自建互不关联 Trace；
28. **Side-effect Classified Tools**：Tool 分为 READ_ONLY、CANDIDATE_WRITE、EXTERNAL_SIDE_EFFECT，副作用越大审批和幂等约束越严格。

### 3.1 真相边界

**PostgreSQL + Object Storage 是业务真相。** Redis Streams 是运输层；Browser Session、Crawler Cache、Agent Memory、Notebook Kernel 都是易失执行状态；Markdown、全文索引、向量和 Graph 是可重建 Projection。

需要持久化的关键事实：

- URL Observation / Coverage Evidence；
- URL Classification / Route Decision；
- Fetch Attempt / Immutable Artifact；
- Extraction Attempt / Candidate；
- Quality Result / Repair Evaluation；
- Canonical IR / Document Version；
- Source Release / Runtime Release；
- Workflow Run / Step / Evidence / Model Call / Tool Call；
- Cost Event / Audit Event。

## 4. 技术选型与组件边界

### 4.1 控制面

- **FastAPI + Pydantic**：REST API、Command、Schema 校验；
- **PostgreSQL**：Source、Release、Run、Task、Coverage、URL、Route、Artifact、Extraction、Quality、Version、Agent、Cost、Audit、Outbox；
- **Redis Streams**：任务运输、consumer group、backpressure；
- **Redis Lua token bucket/semaphore**：跨 Worker 域名级限流与并发；
- **React/Next.js + TypeScript**：Web 管理后台；
- **OpenTelemetry + Prometheus + Grafana + 结构化日志**：Trace、Metric、Log；
- **S3/MinIO**：Raw HTML、Rendered DOM/MHTML、PDF、Candidate、IR、Markdown、Agent Evidence、Workflow Snapshot、导出物；
- **OpenSearch**：全文/BM25；
- **pgvector**：首期向量检索，通过 Adapter 可替换。

### 4.2 Discovery / Fetch

- **httpx/aiohttp**：Sitemap、Feed、CMS API、普通页面、Conditional GET；
- **Crawl4AI**：动态页面、链接/媒体发现、受控 Browser Fetch，仅通过 Adapter 接入；
- **Playwright**：复杂但确定性的 Browser Recipe；
- **PyMuPDF/pdftotext**：PDF；扫描件才进入 OCR。

### 4.3 Extraction

- **Trafilatura**：默认 Generic Main-Content Candidate；
- **lxml**：高性能 DOM/XPath；
- **BeautifulSoup**：Structured Metadata、DOM Repair、诊断；
- **JSON-LD/OpenGraph/Microdata**：结构化 Metadata Candidate；
- **CSS/XPath/Regex Recipe**：确定性字段抽取；
- **Crawl4AI Markdown**：诊断/Candidate，不直接成为 Canonical。

### 4.4 Agent / Workflow

可使用 CrewAI、LangGraph 或自研 Workflow Engine，但平台依赖自身稳定协议而不是框架隐式状态。

- **外层 Workflow Engine/State Machine**：负责状态、分支、重试、超时、恢复、Human Gate、幂等和 Trace Context；
- **Agent Runtime Adapter**：把开放式 Probe/诊断/规则生成封装为有界 Activity；
- **Crew/多 Agent**：适合 Research/Plan/Critique 等开放式语义任务，不持有生产流程真相；
- **确定性 Validator**：最终决定 Candidate 是否有资格进入 Canary/Approval。

### 4.5 运行时边界

```text
Platform  = Coverage / Truth / Scheduling / Retry / DLQ / Classification /
            Routing / Fairness / Budget / Quality / Version / Release /
            Workflow State / Audit / Replay / Projection Semantics
Crawler   = 单次 HTTP/Browser 请求、动作、DOM、链接、媒体、局部 batch
Extractor = Artifact -> Candidate
Renderer  = Canonical IR -> Markdown
Agent     = Evidence -> Candidate Suggestion / Diagnosis / Draft Config
```

所有外部 Tool 返回统一 Typed Result：

```json
{
  "status": "OK | RETRYABLE_ERROR | PERMANENT_ERROR | DEGRADED",
  "output_ref": "object://...",
  "evidence_refs": [],
  "metrics": {},
  "error": {"code": null, "retryable": false, "retry_after_ms": null},
  "trace_id": "..."
}
```

禁止把错误字符串混入正常正文或研究材料。

## 5. Source、Site Family、Profile 与不可变 Release

新增站点最小输入：

```text
name + base_url + 可选标签/策略约束
```

Source 进入 `PROBING`，自动探测：

1. robots.txt 和 Sitemap 声明；
2. Sitemap / Sitemap Index；
3. RSS/Atom；
4. 常见 CMS API；
5. Archive/Category/Tag/Pagination；
6. JSON-LD/OpenGraph/Microdata；
7. HTTP 是否能直接得到完整正文；
8. Browser 是否有真实恢复收益；
9. Site Family 指纹；
10. URL pattern、canonical、分页；
11. 多 Extractor 样本质量；
12. ARTICLE/DOC/INDEX/TAG/AUTHOR/ASSET/API 样本；
13. 动态列表/Infinite Scroll 行为；
14. 是否需要 Deterministic/Repair Recipe。

Probe 只生成 Candidate Source Profile；发布流程：

```text
Family Defaults
 + Source Overrides
 + Route Policy
 + Extraction/Repair Recipe
 + Quality Policy
 -> Effective Config Hash
 -> Candidate Source Release
 -> Static Validation
 -> Golden Replay
 -> Live Sample
 -> Canary
 -> Approval
 -> ACTIVE
```

模板更新不直接影响生产站点。

## 6. 历史 URL Discovery 与 Coverage

### 6.1 Provider 优先级

```text
CMS/API
 -> Sitemap / Sitemap Index
 -> RSS/Atom
 -> Archive/Category/Tag
 -> Static Pagination
 -> Dynamic Listing
 -> Bounded Deep Crawl
 -> Optional Search/Common Crawl/Web Archive Gap Filling
```

RSS/Atom 主要用于增量和时间提示，不能单独证明历史完整。

### 6.2 Provider Run

记录：source_id、provider_type、cursor/range/page、discovered_count、new_count、stop_reason、exhausted、gap_reason、started_at、finished_at。

Sitemap 支持 Index 递归、gzip、多 Sitemap、lastmod、大站 checkpoint；Archive/Pagination 支持重复页签名、连续 N 页无新 URL、最大页数/时间的停止条件；Infinite Scroll/Load More 有最大动作轮数和无新 URL 停止条件。

### 6.3 Coverage Evidence

Coverage 是证据集合：

```text
Provider Set + Time Range + Cursor/Range + Exhaustion Evidence + Provider Diff + Known Gap
```

Web 后台展示 Provider 交并差、时间跨度、Known Gap、补洞任务与 Replay。

## 7. URL 规范化、Identity、分类与路由

### 7.1 URL 规范化

- host 小写、去 fragment、默认端口规范化；
- tracking query 去除、query 排序；
- trailing slash 策略；
- canonical link 只作为 Identity Candidate；
- redirect chain 完整记录。

### 7.2 多层去重

1. normalized URL；
2. canonical/redirect identity；
3. Artifact sha256；
4. Canonical semantic hash；
5. 可选近似正文指纹识别镜像/转载。

### 7.3 Page Type Classification

在 Browser、正文 Extraction、LLM、Embedding 前完成：

```text
Provider Hint -> URL Rule -> MIME/Header -> Structured Metadata
 -> Cheap DOM Heuristic -> Manual Override -> LLM Exception(低比例)
```

页面类型：ARTICLE | DOC | INDEX | TAG | AUTHOR | HOME | ASSET | API | AUTH | ERROR | UNKNOWN。

### 7.4 Execution Routing

```text
ARTICLE -> HTTP_ARTICLE -> Extraction Portfolio
DOC     -> HTTP_DOC -> Document Extraction
INDEX/TAG/AUTHOR -> DISCOVERY_ONLY
ASSET   -> ASSET_PIPELINE
API     -> STRUCTURED_API
ERROR   -> REJECT
UNKNOWN -> CHEAP_PROBE -> Reclassify / QUARANTINE
```

Browser 是 Fetch fallback，不是分类器；Source 规则属于 Source Release，不散落在 Worker 域名 `if` 中。

## 8. 调度、队列、幂等与公平性

Queue Class：

```text
DISCOVERY | CLASSIFY | HTTP | BROWSER | LLM_EXCEPTION |
EXTRACT | QUALITY_REPAIR | AGENT_CONTROL | PROJECTION
```

Browser、Agent/LLM、Projection 独立容量，不能拖垮 HTTP 主链。

典型幂等键：

```text
DISCOVER:{source_release}:{provider}:{cursor}
CLASSIFY:{url_id}:{classifier_release}:{route_policy}
FETCH:{url_id}:{fetch_policy}:{validator_state}
EXTRACT:{artifact_id}:{extractor_release}:{mode}
QUALITY:{artifact_id}:{quality_release}
REPAIR:{artifact_id}:{repair_release}:{step}
AGENT:{source_id}:{agent_release}:{evidence_set_hash}:{purpose}
RENDER:{version_id}:{renderer_release}
VECTOR:{version_id}:{chunker_release}:{embedding_release}
```

Worker 使用 lease + fencing token；旧 lease Worker 不可覆盖新结果。

Weighted Fair Scheduling：Incremental 高于 Backfill；HOT 高优先；长等待 aging；单 Source 最大并发占比；Browser/Agent 独立配额。

Global Admission 在真实 HTTP/Browser/LLM/Tool 调用前检查 global/per-domain concurrency、QPS、Browser slot、Source budget、slow-path share、circuit state、robots/policy。

任何异步批处理必须 bounded prefetch/semaphore，禁止对全量 URL 一次性构造无界 `asyncio.gather`。

## 9. Fetch：HTTP First，Browser Last

### 9.1 HTTP Worker

异步 HTTP Client 支持 gzip/br、redirect、连接/读取/总 timeout、response size limit、ETag/If-None-Match、Last-Modified/If-Modified-Since、Content-Type/Charset、错误分类、Raw Snapshot。

生产 Worker 自己拥有事件循环，不依赖 Notebook 的 `nest_asyncio` 或同步 Agent Tool 嵌套事件循环。

### 9.2 Browser Worker 生命周期

禁止“每 URL 创建完整 Browser/Crawler”。推荐：

```text
Browser Worker Process
 -> long-lived browser/crawler
 -> bounded Context Pool
 -> per-context page lifecycle
 -> recycle by request count / memory / time
```

### 9.3 Browser Fallback 条件

只有以下情形进入 Browser：

- HTTP 仅得到 JS shell；
- 正文依赖 JS；
- 确定性点击/滚动后正文才出现；
- HTTP Candidate 低质量且 Probe/Golden Sample 证明 Browser 有恢复收益；
- Source Profile 明确指定。

持续统计 fallback recovery rate、quality delta、p95 latency、cost；低收益触发 Source-scoped circuit breaker。

### 9.4 Readiness 与错误分类

优先 selector、最小正文、DOM/text quiet window、关键响应；固定 sleep/networkidle 不作为统一完成条件。

错误至少区分 NETWORK、TIMEOUT、RATE_LIMITED、ACCESS_DENIED、BROWSER_CRASH、EMPTY_SHELL、NOT_FOUND、POLICY_BLOCKED，并按类型 Retry/DLQ。

## 10. Immutable Artifact 与正文抽取

每次成功或有诊断价值的 Fetch 生成不可变 Artifact：artifact_id、url_id、fetch_kind、object_key、content_type、status_code、etag、last_modified、fetched_at、sha256、runtime_release、parent_artifact_id。

HTTP Artifact 与 Browser Render Artifact 分开保存。

Extraction Portfolio：

1. Structured Metadata/JSON-LD；
2. Trafilatura Precision/Balanced/Recall；
3. Deterministic CSS/XPath Recipe；
4. DOM Repair + Generic Extractor；
5. Crawl4AI Markdown 诊断 Candidate。

图片和链接直接从原始 DOM/Crawler media metadata 获取，不走“Markdown -> HTML -> 再找图片”。资产 URL 绝对化、sha256 去重、保留 alt/title 和来源 Artifact。

## 11. Quality Gate、Candidate Agreement 与有限修复

```text
DISCOVERED -> CLASSIFIED -> FETCHED -> EXTRACTED -> QUALITY_CHECK
  -> PASS/WARN -> CANONICALIZE -> VERSIONED -> RENDERED
  -> FAIL_RECOVERABLE -> REPAIR_PENDING
       -> ALTERNATE_EXTRACTOR
       -> DETERMINISTIC_RECIPE
       -> DOM_REPAIR
       -> BROWSER_REFETCH(有收益证据时)
       -> QUALITY_CHECK
  -> FAIL_UNKNOWN -> QUARANTINE
  -> NON_CONTENT -> REJECT
```

Quality Gate 至少检查：title、正文长度、paragraph/heading、link density、boilerplate、code/table/list、language、错误页/WAF/登录墙指纹、Candidate Agreement、分类冲突、历史异常截断/结构突变、重复正文比例。

Candidate Agreement 比较元数据、normalized text similarity、首尾段、heading/paragraph 分布、代码/表格/列表保留、link density。

Repair 有固定 max_steps、max_wall_time、Browser budget、cost budget；不让 LLM 改写第三方源正文。失败进入 QUARANTINE。

## 12. Canonical IR 与 Markdown

Canonical IR 保存结构化块：heading、paragraph、code、list、table、image，并保存 title、author、published_at、updated_at、canonical_url、source/document/version 等元数据。

统一 Renderer：

- heading 层级稳定；
- fenced code 保留语言；
- list/table/blockquote 正确；
- 图片保留 alt 与原 URL/归档 Asset URL；
- 相对链接转绝对链接；
- Front Matter 保存 source/document/version/canonical/published/updated；
- Renderer 版本化。

Markdown 只从 Canonical IR 生成；Renderer 升级可离线重建，无需重新访问源站。

## 13. 增量同步与版本管理

Freshness 分层：HOT / WARM / COLD。

增量发现：RSS/API -> Sitemap lastmod/diff -> Archive first pages -> bounded dynamic listing。

已知 URL 复检优先 Conditional GET；周期抽样强制 re-fetch 防止上游元数据不可信。

版本判定：

```text
Artifact -> Extraction Portfolio -> Quality -> Canonical IR
 -> Normalize Semantic Content -> semantic_hash -> Compare Current Version
```

- semantic hash 相同：只更新 last_checked_at；
- 正文变化：创建新 Version；
- 仅元数据变化：记录 metadata change；
- PASS/WARN 新版本原子切换 current_version_id；
- 相同 semantic hash 不重复向量化。

删除需多次 404/410 + Provider 缺失等证据后从 SUSPECT_MISSING 进入 REMOVED；301/308 建 Redirect Relationship。

## 14. 核心领域模型

## 15. 控制面 Agent Workflow 与治理

Agent 只适合低频、高语义、需综合证据的任务。

### 15.1 外层确定性编排

不让 Crew/Agent 自己决定生产流程。平台 Workflow Engine 持有：

- 当前状态；
- 条件分支；
- Retry/Backoff；
- Timeout/Cancel；
- Checkpoint/Resume；
- Budget；
- Human Approval；
- 副作用提交；
- Root Trace Context。

Agent/Crew 仅作为 `RunAgentActivity(contract, evidence_refs)` 之类的有界 Activity。这样即使模型崩溃、上下文截断、Tool 失败，也能从持久化 Workflow Step 恢复，而不是依赖 Agent Memory。

### 15.2 推荐工作流

```text
Evidence Collector
 -> Profile Planner
 -> Rule/Recipe Generator
 -> Critic
 -> Reviser
 -> Candidate Release Assembler
 -> Deterministic Validation
```

Evidence Collector 只允许 ProbeRobots、ProbeSitemap、ProbeFeed、FetchSample、InspectDOM、InspectStructuredMetadata、SearchGapEvidence、ReplaySample 等受限工具。

Planner 提出 Discovery、Page Type、Route、Extractor Portfolio、Quality、Repair；Critic 检查过拟合、遗漏非文章页、Browser 滥用、selector 脆弱、Coverage 证据、robots/egress、Canonical 污染风险；Reviser 只修改 Candidate。

### 15.3 显式 Workflow Contract

每一步必须有机器可校验契约：

```yaml
step: profile_planner
consumes: ProbeEvidenceSet/v3
produces: CandidateProfile/v4
required_evidence_roles: [robots, discovery, article_sample, non_article_sample]
allowed_tools: []
retry_policy: agent-semantic-v2
on_validation_failure: REVISE_OR_REVIEW
```

自由文本可以作为解释字段，但不能作为唯一跨阶段协议。Step 输出先 JSON/Pydantic Schema Validate，再进入对象存储和下一步。

### 15.4 Evidence Store 与 Context 控制

完整网页/DOM/Tool 输出外置：

```text
Raw Evidence Artifact
 -> deterministic metadata/excerpt
 -> evidence_id
 -> bounded context
```

Agent 建议必须带 evidence_refs；防止 Context Window 膨胀、重复内容和 Prompt Injection。

### 15.5 Tool Capability 与副作用分类

- `READ_ONLY`：Probe/Search/Inspect，可按策略安全重试；
- `CANDIDATE_WRITE`：SaveCandidateRelease/SaveDiagnostic，只写固定对象命名空间，必须有 idempotency key + content hash；
- `EXTERNAL_SIDE_EFFECT`：对外发布、任意外部修改，默认禁止；若未来开启，必须 Human Approval + 明确幂等语义。

禁止 Agent 获得任意本地文件路径、Shell、任意 JS/evaluate、任意内网、Secret 明文和 unrestricted browser navigation。

### 15.6 预算与模型路由

每个 Agent Run 有 max_steps、max_tool_calls、max_wall_time、max_tokens、max_cost、per-provider RPM、Tool allowlist。预算耗尽进入 `DEGRADED_NEEDS_REVIEW`。

小模型负责简单归纳/分类，强模型负责少量复杂根因；Planner 与 Critic 可不同 model release。Prompt、Model、Tool Schema、Workflow Contract 全部进入 `agent_release`。

### 15.7 发布流程

```text
Failure Samples / Probe Evidence
 -> Agent Suggestion
 -> Candidate Rule/Recipe
 -> Static Validation
 -> Golden Replay
 -> Live Sample
 -> CANARY
 -> Metrics Compare
 -> Human Approval
 -> ACTIVE
```

Agent 永远只产 Candidate。

### 15.8 Trace Context 必须贯通

一个 workflow_run 创建一个 Root Trace；workflow_step、agent_run、model_call、tool_call 全部是其子 Span。跨 Redis/Worker 传播 W3C Trace Context 或等价关联字段。

禁止 Tool 自己创建脱离父链的新 Trace；如第三方 SDK 只能创建独立 Trace，必须至少保存 parent/root correlation id 并在平台重建树。

## 21. 成本、安全与合规

Cost Event 统一记录 NETWORK、CPU、BROWSER、STORAGE、EMBEDDING、LLM、AGENT、GRAPH 成本。

优化顺序：Authoritative Discovery -> Cheap Route -> HTTP First -> Conditional GET -> Hash 去重 -> 确定性抽取 -> 有收益才 Browser -> 低频 Agent -> 有效版本 Projection。

SSRF：每个请求/Redirect 校验 scheme、DNS、private/loopback/link-local/metadata endpoint；Browser 子请求和 Agent Tool 继承同一 egress policy。

Agent 安全：Tool allowlist、Schema input、Typed Failure、最小权限、Side-effect Class、候选写幂等、无 Shell/任意文件/任意代码/Secret 回显。

Web 管理：viewer/operator/admin RBAC；Source Release 激活可要求 Approval；Audit 记录配置、Circuit、Replay、Candidate、审批。

每个 Source 记录 robots policy、crawl delay、授权/许可证备注、资产下载策略和导出权限。技术可访问不等于拥有再分发权。

## 24. 验收标准

### 24.1 历史与增量

- URL 可解释来自哪个 Provider；Provider 有 stop reason/exhaustion evidence；Known Gap 可见；
- 新文章在 Freshness 目标内进入 PASS/WARN Markdown；
- 304 不生成正文版本；正文变化生成新 Version；删除需多证据；
- 重复任务不产生脏重复，大站 Backfill 不阻塞 Incremental。

### 24.2 抽取与质量

- Fetch/Extraction/Quality 独立；
- 多 Candidate 可追溯；Selector drift 可检出；Repair 有固定上限；
- Browser/Repair 收益和成本可量化；
- 未通过 Quality Gate 不会因慢路径熔断被标记 PASS；
- Markdown 可回溯 Canonical IR，Renderer 升级可离线重建。

### 24.3 Agent / Workflow 治理

- 外层 Workflow State 可持久化、恢复和回放，Crew/Agent 不是状态真相；
- 每步有 consumes/produces Schema，Schema Validation 失败不能进入下一步；
- Agent Memory 不作为持久状态；每个建议带 Evidence；
- Tool Failure 是结构化状态；
- READ_ONLY/CANDIDATE_WRITE/EXTERNAL_SIDE_EFFECT 分类生效；Candidate Write 幂等；External Side Effect 默认禁止；
- 一个 Workflow Run 能展示连续 Root Trace -> Step -> Model/Tool 树，不存在不可解释孤儿 Trace；
- max_steps/tool_calls/tokens/cost/wall-time 生效；
- Prompt/Model/Tool Schema/Workflow Contract 可版本化；
- Candidate 必须过 Deterministic Validation + Golden Replay + Canary + Approval。

### 24.4 可复现

- 全新容器可加载当前 Release 完成 Golden Corpus；
- Runtime Image、Chromium、Extractor、Renderer、Agent Release 明确版本；
- 同一 Artifact + 同一 Release 可离线重建同一 Canonical/Markdown；
- 同一 Agent Input Snapshot + Agent Release 可重放并比较输出差异。
