# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站和公开 Newsletter** 的长期知识库采集平台，可继续扩展到数千站点和百万级至千万级文章。

平台需要同时解决：

1. **全历史回填**：尽可能完整发现每个已批准 Source 的历史文章，并能解释覆盖率、已知缺口和停止原因；
2. **持续增量同步**：及时发现新文章、正文更新、URL 迁移、重定向、删除和重发布；
3. **稳定 Markdown**：从不可变 Raw Artifact 经确定性抽取、质量门禁、Canonical IR 生成可重放 Markdown；
4. **低成本扩站**：新增网站优先通过 Source Profile、Provider、Traversal Policy、Extraction Recipe 配置完成，不维护 1000 份站点脚本；
5. **Web 可运营**：支持站点接入、审批、Backfill、Incremental、Coverage、Frontier、质量、成本、暂停、恢复、诊断和审计；
6. **可恢复、可重放**：任意 URL、Run、Task、Attempt、Runtime Result、Artifact、Document、Version 都可追溯；
7. **可搜索/RAG**：支持 BM25、向量与混合检索，并可回到原文、版本、Source 和抓取证据；
8. **渐进扩展**：开发期 Docker Compose，生产期各执行面独立水平扩容；
9. **主链不依赖 LLM**：LLM 只做可选增强，不参与历史完整性、URL 身份、robots、正文存在性等最终判定。

### 1.1 核心 SLO

- **Coverage**：每个 Source 有可解释 Provider、URL Inventory、Known Gap、Backfill Stop Reason；
- **Freshness**：新文章从发布/发现到 PASS Markdown 的延迟；
- **TTFM**：URL 首次发现到首个可用 Markdown 的时间；
- **Extraction Quality**：标题、正文、代码块、表格、列表保留率和噪声率；
- **Reliability**：Task 成功率、Retry、DLQ、Queue Age、Lease Recovery；
- **Browser Efficiency**：HTTP 命中率、Browser Avoided、Pool Reuse、每文档 Browser 成本；
- **Runtime Stability**：queue saturation、内存压力、process generation、drain latency；
- **Result Integrity**：批量/流式 Runtime Result 的物化完整率和 identity mismatch；
- **Replayability**：同 Raw Artifact + 同 Release 可复现 IR 和 Markdown；
- **Artifact Durability**：required runtime artifact 在 TTL 到期前晋升到平台对象存储的比例应接近 100%。

### 1.2 非目标

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不默认使用个人持久 Browser Profile、模拟用户等反爬绕过手段；
- 不把 HTTP 200、Runtime `success=true`、DOM 很长直接视为文章正确；
- 不把搜索结果数量、Common Crawl、Wayback 或 Deep Crawl 页数当作历史完整性证明；
- 不把 Crawl4AI 即时 Markdown、LLM 摘要直接作为 Canonical Markdown；
- 不把 Redis、Runtime Cache、Browser Session、Visited Set、Runtime Queue、Search Index 当业务真相；
- 不允许外部用户提交任意 JS/Python、代理、CDP、服务器路径或任意 webhook URL。

## 2. 核心设计原则

1. **Coverage First**：先建立 URL Inventory，再批量抓正文；
2. **Authoritative First**：CMS/API、Sitemap、RSS/Atom、官方 Archive 优先；
3. **Historical Gap Is Evidence, Not Truth**：Common Crawl、Wayback 只作为补洞证据；
4. **Discovery / Fetch / Extract / Quality / Projection 分离**；
5. **HTTP First, Browser Slow Lane**；
6. **Snapshot First**：先保存不可变 Raw Artifact；
7. **Canonical IR First, Markdown as Projection**；
8. **Recipe, Not 1000 Site Scripts**；
9. **Persistent Frontier, Not In-Memory Traversal**；
10. **Idempotent + Recoverable**：幂等键、Lease、Fencing Token、Checkpoint、Inbox/Outbox；
11. **Fair by Default**：大站 Backfill 不得饿死 Incremental、小站和 Repair；
12. **Bounded Concurrency Everywhere**；
13. **No Silent Degradation**：过滤、截断、预算耗尽、降级、结果缺失必须记录原因；
14. **Observation Before Selection**：链接事实先保存，再 Filter/Score/Budget；
15. **Runtime Is Execution Plane**：第三方 Runtime 不拥有最终 Coverage、Identity、Document 或 Markdown；
16. **Correlate by Identity, Never by Position**；
17. **Config Is Capability**：能改变代码、网络、浏览器、secret 的字段必须经过 Capability Firewall；
18. **Untrusted by Default at Network Boundary**；
19. **Caller Never Owns Paths**；
20. **Webhook Is Hint, Reconciliation Is Truth**；
21. **Runtime Queue != Durable Queue**；
22. **Context Generation != Browser Process Generation**；
23. **Behavior Beats Naming**：pinned release + Contract Test 才是生产行为契约；
24. **Runtime Artifact Is Ephemeral Until Promoted**；
25. **Zero Must Not Mean Unbounded by Accident**。

### 3.1 业务真相边界

**PostgreSQL + Object Storage 是业务真相。**

- PostgreSQL：Source、Scope、Provider、URL Identity、Observation、Frontier、Run、Task、Attempt、Runtime Envelope、Coverage、Quality、Document、Version、Release、Audit；
- S3/MinIO：Raw HTML/PDF、Provider Evidence、Candidate、Canonical IR、Markdown、Checkpoint、按策略保存的诊断材料；
- Redis Streams：任务运输和 Backpressure；
- Redis Lua：跨 Worker Token Bucket/Semaphore；
- Prometheus/TSDB：运行指标；
- OpenSearch/pgvector：可重建 Serving Projection；
- Crawl4AI queue/cache/browser pool/runtime Redis/artifact store：均为临时 Runtime State。

## 5. Source 接入与配置模型

### 5.1 Source Profile

新增网站先创建声明式 Source Profile：

```yaml
source:
  name: example-tech-blog
  entry_url: https://example.com/blog/
  approved_hosts:
    - example.com
  allowed_paths:
    - /blog/
  denied_paths:
    - /login/
    - /account/

providers:
  - type: sitemap
    url: https://example.com/sitemap.xml
  - type: rss
    url: https://example.com/feed.xml
  - type: archive
    start_url: https://example.com/blog/archive/

fetch:
  mode: auto
  http_timeout_s: 20
  browser_intent:
    render_js: true
    scroll: bounded
    wait_selector: article

extract:
  recipe: generic_article_v3
  content_selectors: ["article", ".post-content"]
  exclude_selectors: ["nav", "footer", ".related"]

incremental:
  feed_poll: 10m
  sitemap_poll: 1h
  archive_reconcile: 1d
  full_reconcile: 7d
```

### 5.2 Capability Firewall

Web/API 用户只能提交 intent，不允许直接透传 Runtime 的高能力字段。

普通配置禁止：

- 任意 `js_code` / Python code；
- `proxy` / `proxy_config`；
- `user_data_dir` / `cdp_url`；
- 任意 cookies/headers/secret；
- 任意服务器 path；
- 任意 LLM base URL；
- 任意 webhook destination；
- `0=unbounded` 的 queue/time/budget；
- 不受控 deep crawl strategy。

Config Compiler 根据审批后的 Profile Release 生成 Runtime Config，并输出编译报告和拒绝原因。

## 6. 历史 URL 发现与 Coverage

### 6.1 Provider 优先级

推荐顺序：

1. CMS/官方内容 API；
2. Sitemap / Sitemap Index；
3. RSS/Atom；
4. 官方 Archive / Category / Pagination；
5. 站内静态链接图；
6. Crawl4AI Domain Mapping / Deep Crawl 作为发现增强；
7. Common Crawl / Wayback；
8. 合规 Search Adapter 作为 Gap Evidence。

每个 Provider 只负责提供 Observation，不直接决定最终文章集合。

### 6.2 Observation

```text
url_observation
- source_id
- provider_type
- provider_ref
- observed_url
- discovered_at
- published_at_hint
- updated_at_hint
- parent_url
- anchor_text
- depth
- evidence_artifact_id
- provider_release_id
```

先保存 observation，再做 scope/filter/dedup，避免“过滤错误以后没有证据可查”。

### 6.3 Coverage 不是一个数字

每个 Source 维护：

```text
coverage_snapshot
- provider inventories
- accepted URL count
- fetched count
- PASS count
- known gaps
- excluded reasons
- pagination stop reason
- earliest known date
- latest known date
- provider disagreement
- last_full_reconcile_at
```

Backfill 停止必须有显式原因，例如：

- `AUTHORITATIVE_PROVIDER_EXHAUSTED`
- `ARCHIVE_PAGINATION_EXHAUSTED`
- `DATE_BOUND_REACHED`
- `ROBOTS_BLOCKED`
- `ACCESS_DENIED`
- `BUDGET_EXHAUSTED`
- `KNOWN_GAP_REQUIRES_REVIEW`

预算耗尽不是“抓全”。

## 7. URL Identity、Scope 与 Persistent Frontier

### 7.1 Conservative Normalization

默认：

- host 小写；
- 去 fragment；
- 标准化默认端口；
- 对明确追踪 query 参数做 allowlisted 删除；
- path/query 的大小写与未知参数默认保留；
- canonical 标签仅作为证据，不盲信。

```text
url_identity
- id
- source_id
- normalized_url
- canonical_candidate
- first_seen_at
- last_seen_at
- state
```

重定向、canonical、内容近重复分别建立 relation，不用一个 aggressive normalization 把不同文章永久合并。

### 7.2 Frontier

```text
frontier_item
- url_identity_id
- source_id
- run_id
- purpose: BACKFILL/INCREMENTAL/REPAIR/VERIFY
- priority
- depth
- next_attempt_at
- attempt_count
- state
- budget_class
- checkpoint_ref
```

Frontier 必须持久化，不能依赖 Runtime 内存 visited set。

## 8. Scheduler、Task、Lease 与公平性

### 8.1 Task Truth

PostgreSQL 保存 durable Task：

```text
task
- id
- run_id
- source_id
- url_identity_id
- task_type
- idempotency_key
- priority_class
- state
- lease_owner
- lease_until
- fencing_token
- retry_count
- next_attempt_at
- deadline_at
- created_at
```

推荐幂等键：

```text
(task_type, url_identity_id, source_profile_release, relevant_version)
```

### 8.2 Fair Scheduler

队列至少分：

- Incremental 高优先保留容量；
- New Source Backfill；
- Historical Backfill；
- Repair；
- Reconcile；
- Low-priority Enrichment。

使用 Weighted Fair Queue / Deficit Round Robin，按 tenant/source/domain 分层，不允许一个几十万页的大站占满所有 worker。

### 8.3 全局 Admission

平台拥有硬资源上限：

```text
global_http_slots
global_browser_slots
per_runtime_browser_slots
per_source_concurrency
per_registrable_domain_concurrency
per_host_rps
per_source_daily_request_budget
per_run_page_budget
per_run_byte_budget
per_run_wall_clock_budget
repair_budget
focused_discovery_budget
```

Admission 成功后才创建昂贵 Runtime 请求。

## 9. Fetch Plane

### 9.1 HTTP Fast Lane

优先使用 HTTP：

- GET/HEAD；
- ETag / If-None-Match；
- Last-Modified / If-Modified-Since；
- Content-Type / Content-Length gate；
- gzip/br；
- redirect 每跳 scope + SSRF 复验；
- status / header / timing 全部入证据。

进入 Browser 的条件应可解释，例如：

- HTML 是明显空壳；
- 正文选择器在 JS 后出现；
- 需要受控滚动/等待；
- HTTP candidate 质量门禁失败且 Browser Repair 有预算。

### 9.2 Browser Slow Lane

Crawl4AI Self-Hosted Runtime 只处理高成本慢路径。平台不直接把 Source Profile 传给 Crawl4AI，而通过 Runtime Adapter 编译成固定 schema。

## 10. Crawl4AI Runtime Service Plane

### 10.1 Runtime Registry

```text
runtime_instance
- runtime_id
- endpoint
- software_release
- image_digest
- result_schema_release
- capabilities_hash
- queue_config_hash
- security_profile_release
- browser_generation
- state: ACTIVE/DRAINING/QUARANTINED/UNROUTABLE
- capacity_score
- last_probe_at
```

加入流量前执行 Contract Probe：

- auth/security profile；
- WorkQueue 是否 started；
- queue maxsize/workers/per_principal；
- 429/503/Retry-After 行为；
- result schema；
- artifact API；
- forbidden power fields；
- internal URL/redirect 拒绝；
- monitor admin action 权限。

不匹配 pinned contract 时实例直接 `UNROUTABLE`。

### 10.2 Runtime Queue 只做局部保险丝

Crawl4AI 当前 `WorkQueue` 本质是单进程 `asyncio.Queue`：

```text
maxsize        -> 等待队列上限，满时 503
workers        -> 后台 worker 数
per_principal  -> 单调用主体在途上限，超限 429
```

因此：

- PostgreSQL + Redis Streams 才是 durable task；
- Runtime Queue 丢失后平台依赖 lease/reconciliation 恢复；
- Runtime Redis status/result 不升级为长期 Task Truth；
- `queue.maxsize=0`、`per_principal=0`、`wall_clock=0` 的 unbounded 语义禁止普通用户产生。

### 10.3 双层 Backpressure

```text
Platform Global Admission
        +
Crawl4AI Local Admission
```

平台控制跨实例公平和硬预算；Runtime 的 queue、MemoryAdaptiveDispatcher、RateLimiter、browser memory pressure 只负责单实例自保护。

错误分类：

- Runtime 429 -> `RUNTIME_PRINCIPAL_QUOTA`；
- Runtime 503 -> `RUNTIME_QUEUE_FULL`，遵守 Retry-After；
- Runtime 504 -> `RUNTIME_WALL_CLOCK`；
- pod lost/reset -> `RUNTIME_LOST`；
- 目标网站 429/503 -> 进入 host rate adaptation，不能和 Runtime 过载混淆。

### 10.4 Runtime Attempt 状态机

```text
LEASED
 -> ADMITTED
 -> RUNTIME_SUBMITTING
 -> RUNTIME_QUEUED
 -> RUNTIME_RUNNING
 -> RUNTIME_TERMINAL
 -> MATERIALIZING_RESULT
 -> PROMOTING_ARTIFACTS
 -> MATERIALIZED
 -> RAW_PERSISTED
 -> SUCCEEDED
```

`RUNTIME_TERMINAL` 不等于平台 `SUCCEEDED`。

### 10.5 Webhook Inbox + Reconciler

Webhook 是快速路径：

```text
runtime_event_inbox
- runtime_id
- runtime_task_id
- attempt_id
- event_id/payload_hash
- status
- received_at
- processed_at
```

处理必须幂等。周期性 Reconciler 对：

- 长期无 webhook；
- completed 但未 materialize；
- runtime 重启后的 orphan attempt；
- lease 即将超时；

主动查询和收敛。

### 10.6 Browser Pool 与代际

可以利用 permanent/hot/cold pool 提高复用率，但 pool 是性能缓存。

隔离 key 至少包含：

```text
runtime_profile_release
network_policy_class
credential_scope
session_isolation_class
proxy_policy_class
browser_feature_class
```

公开技术博客默认 `public-anonymous`，无持久 cookie/profile。

生命周期分两层：

1. **Context Generation**：页面数、错误、污染风险、session 状态触发回收；
2. **Browser Process Generation**：PID age、累计 page、RSS、FD、renderer crash、错误率触发 drain + replace。

Restart 流程：

```text
ACTIVE -> DRAINING -> active attempts 收敛 -> recycle -> readiness/contract probe -> ACTIVE
```

### 10.7 Runtime 监控与业务监控分离

Runtime monitor/WebSocket/Prometheus 用于：

- queue saturation；
- memory pressure；
- active request；
- browser reuse；
- janitor；
- restart/drain；

但历史覆盖、PASS Markdown 数、Known Gap 必须从平台 Truth Store 计算。

## 11. Runtime Artifact Promotion Gate

Crawl4AI 0.9 screenshot/PDF 使用 server-owned opaque `artifact_id`，运行时 artifact 有 TTL 和 quota，因此绝不能作为永久知识库引用。

### 11.1 平台模型

```text
runtime_artifact_ref
- runtime_id
- runtime_task_id
- attempt_id
- runtime_artifact_id
- declared_mime
- declared_size
- discovered_at
- fetch_started_at
- durable_artifact_id
- sha256
- status
- error_class
```

状态：

```text
PENDING -> FETCHING -> DURABLE
                    -> MISSING_EXPIRED
                    -> TOO_LARGE
                    -> CORRUPT
```

### 11.2 晋升流程

```text
Runtime Result
   -> 找到 required artifact refs
   -> GET /artifacts/{id}
   -> 流式读取 + byte limit
   -> MIME/size 校验
   -> sha256
   -> 写 S3/MinIO immutable object
   -> 写平台 artifact_id
   -> required artifacts 全部 DURABLE
   -> Attempt 才允许 MATERIALIZED
```

Raw HTML/PDF 等重放输入必须 required；screenshot/network trace 可按诊断策略 optional。

关键指标：

```text
runtime_artifact_promotion_age_seconds
runtime_artifact_ttl_headroom_seconds
runtime_artifact_missing_expired_total
runtime_artifact_promotion_failure_total
```

Artifact 晋升 backlog 接近 Runtime TTL 时，应停止提交新的高制品任务并优先排空 backlog。

## 12. Raw Artifact 与可重放管线

任何解析前先保存：

```text
raw_artifact
- platform_artifact_id
- source_id
- url_identity_id
- attempt_id
- fetched_url
- status
- headers
- mime
- bytes_sha256
- content_encoding
- fetched_at
- object_key
- runtime_release
```

对象存储 key 由服务端生成，调用方不能指定路径。

Raw Artifact 不可变；后续 extractor/renderer 升级只需重放，不必重新请求原站。

## 13. Extraction Portfolio 与 Canonical IR

### 13.1 Candidate Portfolio

同一 Raw Artifact 可生成多种候选：

1. Source Recipe；
2. JSON-LD/articleBody；
3. Trafilatura；
4. Generic DOM；
5. Browser-rendered DOM candidate；
6. Repair candidate；
7. 可选 LLM repair，不能作为默认主链。

所有 candidate 都保存 extractor release 和质量特征。

### 13.2 Quality Gate

主要特征：

- title/author/date 是否存在；
- 正文字符数/段落数；
- link density；
- boilerplate ratio；
- heading/list/table/code block 保留；
- 截断迹象；
- login/consent/soft-404 模板；
- 与同站模板相似度；
- 与其他 candidate 一致性。

输出：

```text
PASS
REPAIR_HTTP
REPAIR_BROWSER
REPAIR_RECIPE
REVIEW
REJECT_NOT_ARTICLE
REJECT_SOFT_404
```

### 13.3 Canonical IR

最终 Markdown 不直接从某个第三方 `markdown` 字段复制，而先进入 Canonical IR：

```json
{
  "schema": "article-ir/v1",
  "title": "...",
  "author": ["..."],
  "published_at": "...",
  "updated_at": "...",
  "canonical_url": "...",
  "blocks": [
    {"type": "heading", "level": 2, "text": "..."},
    {"type": "paragraph", "text": "..."},
    {"type": "code", "language": "python", "text": "..."},
    {"type": "table", "rows": []},
    {"type": "image", "src": "...", "alt": "..."}
  ]
}
```

Markdown 只是 IR 的确定性 projection。

建议每篇文章：


规则：

- 不做 LLM 改写；
- 尽量保留代码语言、列表、表格、引用、图片 alt；
- 站内相对链接转绝对 URL；
- 删除导航、广告、推荐、订阅弹窗等模板噪声；
- 保留原文语义顺序；
- renderer release 可追溯。

目录可以按稳定 ID 或 Source/年份组织，但业务引用以 `document_id/version_id` 为准，不能依赖文件路径做主键。

### 15.1 Document Identity

- source_id；
- normalized URL；
- canonical/redirect relation；
- CMS post id；
- published_at/title；

### 15.2 Version

```text

- markdown_artifact_id
- extractor_release_id
- renderer_release_id
- quality_score

- observed_at
- supersedes_version_id
```

内容 hash 不变时不制造新业务版本；抓取证据仍可以保留新的 observation/attempt。

### 15.3 Incremental Provider

优先：

- RSS/Atom newest item；
- Sitemap `lastmod`；
- CMS modified timestamp；
- Archive 第一页/最新分页；
- Conditional GET；
- 周期性 full reconciliation 防止漏事件。

Webhook/Feed 只能降低延迟，不能替代 reconciliation。

### 15.4 删除与 Tombstone

单次 404/410/缺失不立即删除知识库内容。

建议：

- 多次重复确认；
- Provider inventory 同时消失；
- redirect/canonical 迁移检查；
- 标记 `TOMBSTONE_CANDIDATE`；
- 到阈值后 `TOMBSTONED`，但历史版本仍保留。

## 19. 安全与合规

### 19.1 Robots / Scope

- 每 Source 显式 approved hosts/paths；
- robots policy 版本化；
- redirect 每跳重新检查；
- discovered host 不自动加入 scope。

### 19.2 SSRF / Egress

阻断：

- localhost；
- RFC1918/ULA/link-local；
- cloud metadata；
- 非批准 scheme；
- DNS rebinding；
- redirect 到内部地址。

Runtime 只部署私网，通过 Gateway 访问；普通用户永不直接持有 runtime token。

### 19.3 Runtime Secure Profile

生产遵循 secure-by-default：

- auth 必开；
- TLS reverse proxy；
- CORS deny by default；
- TLS verification 默认开启；
- Redis 不公开；
- admin action 仅 admin principal；
- declarative hooks；
- secret/server path 不进入网络请求体；
- request body/queue/wall-clock 全有硬上限；
- read-only rootfs、tmpfs、`cap_drop: ALL`、`no-new-privileges`、合理 `/dev/shm`；
- 对 Chromium sandbox 状态显式审计。

### 19.4 数据保留

- Durable Raw/IR/Markdown：按知识库保留策略；
- screenshot/MHTML/network/console：失败或抽样保存，短 TTL；

## 21. 取消、暂停、Drain 与恢复

### 21.1 Stop 语义

用户点击 Stop 后：

1. Run 进入 `CANCEL_REQUESTED`；
2. Scheduler 停止新 Admission；
3. 未 lease task 回收/取消；
4. 已提交 Runtime 的 attempt 请求 cooperative cancel 或进入 drain；
5. 等待 task/page/context/session/resource token 收敛；
6. 超时执行受控 kill/recycle；
7. Reconciler 处理迟到 webhook/result；
8. active=0 且资源令牌清零后才标记 `STOPPED`。

### 21.2 Crash Recovery

- Task lease 过期可重新获取；
- fencing token 防止旧 worker 迟到写覆盖新 attempt；
- Runtime Pod 重启不假设 job 恢复；
- orphan attempt 由 Reconciler 重新分类；
- 已存在 Raw Artifact 时优先重放 Extraction，不重复访问原站。

## 22. Search / RAG Projection

Canonical Markdown 进入 Serving Plane：

1. document/version 元数据；
2. heading-aware chunk；
3. OpenSearch BM25；

GraphRAG 只用于明确有价值的跨文档实体/关系场景，不作为默认成本。

## 28. 最终推荐架构结论

这套系统应把 **“发现完整性、长期状态、可恢复性、最终内容”** 放在平台控制面，把 Crawl4AI 等第三方组件降级为可替换的执行运行时：

```text
Coverage Truth        -> PostgreSQL
Durable Task          -> PostgreSQL + Redis Streams
URL Frontier          -> PostgreSQL
Raw/IR/Markdown       -> S3/MinIO
Runtime Queue         -> Crawl4AI asyncio.Queue（局部临时）
Runtime Status/Cache  -> Crawl4AI Redis（临时）
Browser Pool          -> Crawl4AI（性能缓存）
Runtime Artifact      -> Crawl4AI（短 TTL，必须晋升）
Final Markdown        -> Canonical IR deterministic projection
Search Index          -> 可重建 Projection
```

这样既能利用 Crawl4AI Self-Hosting 的异步队列、浏览器池、监控与安全加固，又不会把 1000+ 站点的历史覆盖、增量正确性、数据耐久性和知识库生命周期绑定到单个 Runtime 的内部实现。
