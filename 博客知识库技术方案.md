# 博客知识库技术方案

## 1. 建设目标与边界

建设一个长期运行、可横向扩展、可审计、可回放、可持续增量同步的技术博客知识库平台。首期接入约 1000 个技术博客、工程博客、技术文档站和公开 Newsletter，尽可能抓取完整历史文章并清洗为稳定 Markdown；后续可通过配置快速增加站点，并支持增量同步、版本管理、搜索/RAG、Web 管理、导出和离线重处理。

目标规模：

- 1000+ Source，可扩展到数千站点；
- 百万级 Document / Document Version；
- 数百万到千万级 URL Observation；
- 千万级 Chunk / Embedding；
- HTML、Markdown、TXT、JSON/API、RSS/Atom/JSON Feed 为主要输入，PDF/图片/iframe 为可选证据输入；
- 中英日韩等多语言；
- CMS API、Sitemap、Feed、Archive、Category/Tag、Docs TOC、URL Seeder、Common Crawl、受控 Deep Crawl 等多入口历史发现；
- HTTP 为默认抓取路线，确定性 Browser 为受控 fallback，交互式 Agent Browser 仅作最后一级异常能力；
- PostgreSQL + Object Storage 保存业务事实；Markdown、全文索引、向量索引、Graph、AI 派生、Export、Dashboard Read Model 均为可重建 Projection；
- Web UI、n8n、MCP、Agent、CI 和外部系统只能通过受控 API/Event 边界驱动平台。

平台必须能够回答：

1. 一个站点理论上有哪些历史文章，为什么认为历史已经基本覆盖；
2. 一个 URL 从哪里被发现、如何规范化、为何被过滤或放行、经过哪些跳转、最终抓到了什么；
3. 为什么某 URL 走 HTTP、确定性 Browser、交互 Recipe 或 Interactive Browser；
4. 谁做出了路由决策，依据是什么，执行器实际获得了哪些能力与约束；
5. Browser 页面最终抽取所依据的是哪个原始响应、哪个渲染后 DOM、执行了哪些等待/交互/iframe/Shadow DOM 处理；
6. Agentic Browser 如果被使用，执行了哪些动作、是否越域、为何停止、产生了什么可回放 Artifact；
7. 一个 Markdown 来自哪个 Snapshot / Render Artifact、Extractor Release、IR Release 和 Document Version；
8. 源站变化后哪些内容真正变化，哪些派生物需要重建；
9. Worker 崩溃、批任务部分失败或外部自动化重启后如何恢复且不丢成功项；
10. 新增第 1001 个站点时，能否主要依靠 Probe、Profile、Recipe、Schema 与审核接入，而不是增加站点专用代码；
11. 全量历史抓取是否有 durable checkpoint，能否从断点继续；
12. 百万 URL 批处理是否保持有界内存，并支持逐 URL 提交；
13. Browser 是否被复用且安全隔离，何时回收，是否因资源压力自动降并发；
14. Crawler/Browser/LLM Runtime 升级后，是否只修改 Adapter/Runtime Release 而不污染平台数据契约；
15. Markdown 导出到本地/S3/Git 后，是否仍能稳定映射回平台内部 Document Version；
16. 长时间 Deep Crawl 是否能由 Web 安全取消、同配置断点恢复，并保证 runtime checkpoint 丢失后业务事实仍不丢；
17. URL 发现阶段是否能走轻量 Prefetch/Seeder 路径，避免在确认正文 URL 之前支付 Markdown、媒体和 LLM extraction 成本；
18. Query/Adaptive Crawl 是否与历史 Coverage 严格分离；
19. iframe、Shadow DOM、动态 hydration 内容被并入正文后，是否仍保留来源与变换证据；
20. Structured Extraction 是否通过版本化 Schema 校验，并且不会绕过事实层直接污染 Canonical Markdown；
21. 网页中的 Prompt Injection 是否无法扩大 Tool 权限、访问范围、预算或 Secret。

非目标：

- 不把互联网搜索发现的任意 URL 自动算入正式 Source 的历史 Coverage；
- 不把 Adaptive/Question-driven Crawl 的 confidence 当历史覆盖率；
- 不以 LLM 输出替代原始 Snapshot、Render Artifact、Canonical IR 或人工可验证证据；
- 不把 Redis、Crawler 内部队列、Deep Crawl frontier、runtime checkpoint、Agent memory、n8n 执行记录当业务真相；
- 不默认绕过登录墙、付费墙、CAPTCHA 或源站明确的访问控制；
- 不把代理轮换作为规避限流、封禁或访问策略的默认手段；
- 不让自由 Agent 直接拥有核心数据库写权限、内部网络权限或无限制浏览器权限。

## 2. 核心设计原则

1. **Config First**：普通站点靠 Source / Profile / Recipe / Schema Release 接入，不修改核心代码。
2. **Coverage First**：历史完整性由 Provider Evidence、cursor、exhaustion reason 和 known gap 证明，队列为空不等于完整。
3. **Authoritative First**：CMS/API、Sitemap、Feed、Archive 优先，Seeder/Common Crawl/Deep Crawl 用于补洞和交叉验证。
4. **Discovery Before Fetch**：先发现、Observation、规范化、过滤、分类、去重，再抓正文。
5. **Discover Cheap, Fetch Expensive**：发现阶段优先 CMS/Sitemap/Feed/轻量 HTTP/Seeder/Prefetch，只在 URL 通过 Scope/Filter 后进入完整抓取、Browser、媒体或 LLM extraction。
6. **Durable Streaming Frontier**：大站 URL 发现必须流式、小批持久化，禁止把全站 URL 一次性物化在内存。
7. **HTTP First, Browser Last**：静态 HTML、Feed、API、Sitemap 优先 HTTP；Browser 只处理动态正文、交互和质量 fallback。
8. **Deterministic Before Agentic**：确定性 Browser 与版本化 Recipe 优先于 Agentic Browser；普通 Backfill/Incremental 必须不依赖 LLM 决策即可运行。
9. **Planner / Executor Separation**：路由决策与实际网络执行分离。Planner 只能产生受约束 FetchPlan，Executor 才拥有最小化网络/浏览器权限。
10. **Tool Contract, Not Framework Coupling**：平台面向能力契约，不让业务层依赖 Crawl4AI、Playwright、Browser Use 等第三方 DTO。
11. **Rendered Evidence Is First-Class**：Browser 抓取必须同时保留网络事实与渲染后 DOM/变换证据。
12. **Interaction Is Evidence**：Agentic/多步骤交互若发生，动作序列、URL 变化、策略判定和关键 Artifact 必须可审计。
13. **Link Graph != Content Scope**：正文抽取 selector 与 URL 发现 link graph 分离。
14. **Platform Permit Before Local Dispatcher**：global/domain/source 配额是集群上限；Crawler 内 dispatcher 只负责 Worker 内二级资源控制。
15. **Bounded Window + Stream + Commit Per URL**：Worker 只 lease 有界窗口，流式返回，成功逐 URL 落库。
16. **Snapshot First**：先保存不可变网络事实和必要的渲染事实，再做抽取、清洗、Markdown、Chunk、索引和 AI。
17. **IR First, Markdown as Projection**：Canonical IR / Document Version 是内容事实层，Markdown 可确定性重建。
18. **Canonical Before Fit**：Pruning/BM25/LLM 等有损过滤只能产生 FIT/ENHANCED Projection，不能覆盖 Canonical Markdown。
19. **Schema First for Structured Extraction**：复杂列表/metadata 抽取必须使用版本化 Schema、Instruction、Extractor 与 Validation；结果只是派生证据。
20. **LLM Is Optional and Budgeted**：LLM 只用于疑难结构化抽取、Probe、Research 或受控异常处理；不对百万篇正文默认调用。
21. **Adaptive Research Is Not Archive Coverage**：Query-driven/Adaptive Crawl 只用于专题研究、按需补充和 freshness，不参与全量历史完成判定。
22. **Reuse Browser, Isolate Session**：复用 Browser 进程降低成本，但 Cookie、LocalStorage、认证态、代理身份按 Source/Profile/安全域隔离。
23. **Deterministic Hydration**：动态站优先等待明确 selector/JS 条件，固定 sleep 仅作受控 fallback；等待规则、JS、滚动/点击进入 Recipe Release。
24. **Recipe, Not Site Code**：交互、路由、Filter、Schema、Selector、Extractor、iframe/Shadow DOM 处理声明式、版本化、可回放。
25. **Preserve Embedded Provenance**：跨域 iframe 或嵌入资源并入正文时保留 URL、Snapshot/Artifact 或独立证据映射。
26. **Release Everything**：影响结果的 Profile、Planner、Adapter、Crawler Runtime、Recipe、Structured Extraction、Extractor、IR、Markdown、Chunk、Embedding、Metric、Export 均版本化。
27. **Idempotent + Recoverable**：任务有幂等键、lease、fencing token、checkpoint、retry、partial success、dead-letter。
28. **One Durable Task System**：PostgreSQL durable state + Transactional Outbox + Redis Streams 是唯一业务任务体系。
29. **Projection Is Rebuildable**：全文、向量、Graph、AI、Export、Dashboard 都可从事实层离线重建。
30. **Security on Every Hop**：起始 URL、Redirect、Browser navigation、iframe、Deep Crawl 新链接、Agent action target、Webhook endpoint 每跳重新做 SSRF/Egress/Scope 校验。
31. **Web Content Is Untrusted Data**：网页文本不能改变 allowed hosts、Tool 权限、预算、Secret 或平台系统指令。
32. **Source Friendly**：robots、站点政策、分层限流、Retry-After 和退避优先于吞吐。
33. **Benchmark Before Switch**：Crawler、Browser、Extractor、Planner、Markdown、Embedding、LLM Model Release 升级先固定回归，再激活。
34. **Runtime Checkpoint Is Hint, Not Truth**：Deep Crawl/Agent runtime state 只用于减少重复执行；Observation、Coverage、Task、Artifact 才是 durable 事实。
35. **Pinned Runtime Supply Chain**：固定 lockfile、镜像 digest、Browser 版本、SBOM、安全扫描与模型/策略 Release。
36. **Crawler Service Is Internal**：第三方 crawler 即使自带 REST/JWT，也只作为内网 Runtime；外部鉴权、RBAC、审计和幂等由平台 API 统一承担。

```text
      │            │                               │

       │                        │                        │

       └──────────────┬─────────┴──────────────┬─────────┘
                      │                        │

                      │                        │

                                     │
                              Extract / Canonical IR
                                     │
              ┌──────────────────────┼──────────────────────┐

              │                      │
              │                 Vector / RAG
              └──────────── Derived Projections

Optional Structured Extraction Worker
 Artifact -> Versioned Schema/Instruction -> Rule/DOM/LLM Extractor
          -> Validation -> Result -> Observation/Metadata Candidate
```

真相边界：

```text
PostgreSQL + Object Storage        = Truth
URL Observation                    = Durable discovery fact
Network Snapshot                   = Immutable fetched fact
Render Artifact                    = Immutable browser-rendered fact
Interaction Trace                  = Auditable execution evidence
Canonical IR / Document Version    = Content fact
Redis Streams                      = Transport only
Crawler internal frontier          = Execution state only
Deep Crawl runtime checkpoint      = Recovery hint only
Agent memory / browser state       = Ephemeral execution state
LLM structured result              = Derived evidence only
OpenSearch / Vector Store          = Rebuildable Projection
Canonical Markdown                 = Rebuildable Projection from IR
FIT/Enhanced Markdown              = Rebuildable Derived Projection
Dashboard Read Model               = Rebuildable Projection
n8n/MCP/Agent state                = External automation state only
```

任何派生系统故障都不得把已成功保存的 Snapshot、Render Artifact 或 `Document Version READY` 回退成失败；任何 crawler/agent runtime state 丢失都只能增加重复执行，不能造成已发现 URL、Coverage Evidence 或 Document Version 丢失。

## 4. 技术选型

### 4.1 控制面

- **FastAPI + Pydantic**：REST/Command API、Schema 校验、Webhook Receiver、内部服务接口；
- **PostgreSQL**：Source、Profile、Run、Task、Coverage、Observation、FetchPlan、Artifact metadata、Document、Version、Release、Audit、Outbox；
- **Transactional Outbox**：保证数据库状态与异步消息发布一致；
- **Redis Streams**：consumer group、retry transport、backpressure，只做任务运输；
- **React/Next.js 或 Vue + TypeScript**：Web 管理台；
- **Docker/Kubernetes**：按 Discovery / HTTP Fetch / Browser / Interaction / Extract / Projection / Research 独立扩缩容。

### 4.2 抓取与解析

- **HTTPX/aiohttp**：静态 HTML、Feed、Sitemap、API、Conditional GET、Range GET、低成本 link discovery；
- **Crawl4AI**：异步多 URL 抓取、Browser、URL Seeder、Deep Crawl、Prefetch、Deep Crawl resume/cancel、Adaptive Query Crawl、iframe/Shadow DOM、Markdown candidate、Worker 内 Dispatcher；
- **Playwright**：复杂 JS、确定性滚动/点击、多步骤版本化 Recipe；
- **受控 Interactive Browser Adapter**：可接 Browser Use 或未来同类 Browser Agent，只用于 L4 交互 fallback；
- **lxml / trafilatura / readability 类算法**：快速正文候选抽取；
- **Pydantic/JSON Schema**：Structured Extraction 输出契约；
- **PyMuPDF / pdftotext**：PDF 原生文本解析，扫描型 PDF 才进入 OCR fallback；
- **RSS/Atom/JSON Feed parser、XML Sitemap parser**：权威发现入口。

### 4.3 存储与检索

- **S3/MinIO**：原始响应、渲染 DOM/MHTML、HTML/PDF、截图、Interaction Artifact、Canonical IR、导出包、大型 checkpoint；
- **OpenSearch**：BM25、字段过滤、聚合、短语/代码/错误信息检索；
- **pgvector**：首期向量检索；规模扩大时通过 Vector Adapter 替换 Qdrant/Milvus；
- **PostgreSQL JSONB**：配置、evidence、quality metrics、小型 checkpoint 与结构化结果。

## 5. 能力型 Crawler Adapter 与 Runtime Release

业务层只依赖稳定能力，不依赖第三方库名称。

```text
CrawlerCapability
  STATIC_FETCH
  CONDITIONAL_FETCH
  LINK_DISCOVERY
  PREFETCH_DISCOVERY
  SITEMAP_SEEDING
  COMMON_CRAWL_SEEDING
  JS_RENDER
  DEEP_CRAWL
  DEEP_CRAWL_RESUME
  RUN_CANCELLATION
  STREAMING_BATCH
  IFRAME_PROCESS
  SHADOW_DOM_FLATTEN
  STRUCTURED_EXTRACTION
  INTERACTIVE_NAVIGATION
  SESSION_REUSE
  SCREENSHOT
  MHTML_CAPTURE
  PROXY
```

稳定接口：

```text
CrawlerAdapter
  probe(url, profile, limits) -> ProbeResult
  fetch(request, runtime) -> FetchResultStream
  render(snapshot_or_url, recipe, runtime) -> RenderResult
  discover(seed, strategy, checkpoint) -> ObservationStream
  extract_structured(artifact, schema_release) -> StructuredResult
  interact(plan, runtime) -> InteractionResult
  cancel(run_id)
  resume(checkpoint)
```

`crawler_runtime_release`：

```text
id
adapter_name
adapter_version
capability_set_json
crawl4ai_version
playwright_version
interactive_browser_version
chromium_version
docker_image_digest
lockfile_digest
sbom_digest
image_signature
security_scan_json
config_schema_version
benchmark_result_json
status              DRAFT | TESTED | ACTIVE | RETIRED
activated_at
```

生产禁止无审核 `pip install -U`、漂移 `latest` 镜像或未固定 Browser 版本。新 Runtime 先对 Golden Corpus/Golden Interaction Cases 比较抓取成功率、Rendered DOM 稳定性、Markdown diff、代码/表格保留率、iframe/Shadow DOM、Browser crash、内存峰值、429/重试、Deep Crawl resume/cancel、结构化 Schema 校验、Agent 步数/越域动作和安全扫描，再 canary，最后激活。

## 7. 新站点接入与 Probe

新增 Source 先执行 `PROBE`：

1. DNS/TLS/robots/redirect/egress 安全检查；
2. 探测 `sitemap.xml`、robots 中 Sitemap、RSS/Atom、JSON Feed；
3. 识别 WordPress、Ghost、Substack、自建 CMS、静态站、文档框架等特征；
4. 探测公开 CMS API、分页方式、Archive/Category/Tag；
5. 抽样 10～30 个正文 URL，比较 HTTP 与 Browser 抽取质量；
6. 检测 JS shell、hydration、Shadow DOM、iframe、滚动/点击、Load More；
7. 对动态样本重复抓取 2～3 次，检查 Rendered DOM 稳定性与等待条件；
8. 优先寻找明确 `wait_for` selector/JS 条件，避免固定 sleep；
9. 探测未知链接区域是否适合 HTTP link discovery、URL Seeder 或 Prefetch Deep Crawl；
10. 分离 `content_scope` 与 `link_discovery_scope`；
11. 尝试规则/DOM Structured Extraction，只有失败或质量不足才测试 LLM Schema Extraction；
12. 对确实需要 UI 操作的站点，先尝试生成确定性 Playwright/Crawl4AI Recipe；
13. 只有 Recipe 难以稳定表达时，才允许受控 Interactive Browser 探索；
14. Agent 探索成功后优先转成 Recipe 草稿，而不是长期依赖 Agent；
15. 形成 Source Profile 草稿；
16. dry-run 只产生 Observation/Preview/Artifact Preview；
17. Web UI 审核后激活 Profile/Recipe/Schema Release。

典型配置：

```yaml
source:
  allowed_hosts: [example.com, www.example.com]
  include_paths: [/blog/, /posts/]
  exclude_paths: [/tag/, /author/, /search/, /login/]

discovery:
  providers:
    - {type: cms_api, priority: 10, required: true}
    - {type: sitemap, priority: 20, required: true}
    - {type: feed, priority: 30}
    - {type: archive, priority: 40}
    - {type: common_crawl, priority: 80, mode: gap_only}
    - {type: deep_crawl, priority: 90, mode: gap_only, strategy: bfs, prefetch: true, max_depth: 3, max_pages: 5000}

fetch:
  mode: AUTO
  requests_per_second: 0.5
  max_concurrency: 2
  browser_fallback: true
  interaction_fallback: false

browser_recipe:
  wait_for: "css:article"
  process_iframes: false
  flatten_shadow_dom: false
  scan_full_page: false

interaction_policy:
  enabled: false
  max_steps: 20
  max_wall_time_seconds: 120
  allowed_actions: [navigate, click, input, scroll, wait, extract]
  allow_downloads: false

extract:
  target_elements: [article, main]
  remove_selectors: [nav, footer, .newsletter-signup]
```

所有规则属于版本化 Release。Deep Crawl、Browser wait/interactions、Structured Schema 和 Agent Action Policy 都进入 fingerprint。

## 8. 全量历史发现与 Coverage 证明

### 8.1 Provider 优先级

1. CMS/API；
2. Sitemap/Sitemap Index；
3. Feed；
4. Archive/年月页/分页列表；
5. Category/Tag、Docs TOC；
6. URL Seeder / Common Crawl 历史索引补洞；
7. 受控 Deep Crawl 最后补洞；
8. Interactive Browser 只能帮助发现特殊 UI 背后的入口，不参与“完整性证明”。

### 8.2 Discover -> Validate -> Fetch

```text
Discover
 CMS/Sitemap/Feed/Archive/Seeder/CC/Deep/Structured List Extraction
 -> cheap discovery / prefetch
 -> URL Observation

Validate
 -> normalize
 -> SSRF/egress/scope
 -> hard/soft filter
 -> canonical candidate
 -> dedupe
 -> durable frontier

Fetch
 -> Rule Planner
 -> FetchPlan
 -> HTTP First
 -> deterministic Browser fallback
 -> versioned Recipe fallback
 -> exceptional Interactive fallback
 -> Snapshot / Render Artifact
 -> Extract / IR / Markdown
```

任何 Crawler/Agent 发现结果都不能绕过平台 Validate 阶段。

### 8.3 Durable Streaming Frontier

```text
fetch provider page / discovery window
 -> parse items/links
 -> upsert observations in small batch
 -> persist provider cursor/checkpoint
 -> enqueue eligible URL task
 -> commit
 -> next page/window
```

### 8.4 Deep Crawl：恢复、取消与 Prefetch

```text
BFS        = 广度 gap discovery 默认
DFS        = 受控深层 archive/path 探测
BestFirst  = 相关性/预算优先探索，不用于证明完整 Coverage
```

恢复：

```text
on_state_change
 -> coalesce runtime state
 -> every N URLs or T seconds persist execution checkpoint
 -> Observation commits independently

restart
 -> compare source/profile/runtime/strategy fingerprint
 -> same: resume_state
 -> mismatch: discard runtime checkpoint and restart from seed
 -> Observation idempotency absorbs repeats
```

取消：

```text
Web/API cancel
 -> discovery_run = CANCEL_REQUESTED
 -> should_cancel checks durable run status
 -> finish current safe boundary
 -> flush execution checkpoint
 -> run = CANCELLED
```

Prefetch：

```text
prefetch=true
 -> HTML + fast link extraction
 -> skip markdown/content scraping/media/LLM extraction
 -> Observation
```

### 8.5 Link Graph 与正文作用域分离

```text
content_scope
  article/main selectors

link_discovery_scope
  full page by default
  + independent allow/deny/filter rules
```

正文 selector 过窄不能导致 Archive/Navigation 历史链接被遗漏。

### 8.6 Coverage 完成条件

`BACKFILL COMPLETE` 至少满足：

- required authoritative provider 明确耗尽；
- provider cursor/checkpoint 已持久化；
- known gap 为空或有人工接受理由；
- discovered/allowed/fetched/filtered/failed 数量可核对；
- 对年份、月份、分页边界做交叉验证；
- Common Crawl/Deep Crawl 补洞不会继续发现大量新正文；
- robots/policy/长期失败 URL 被单独计为可解释缺口；
- Deep Crawl stop reason、max depth/max pages/cancelled 等截断原因明确记录；
- BestFirst、score threshold、Adaptive confidence、Agent“未发现更多”不能被误标为全站耗尽。

## 9. Fetch Planner、路由与执行边界

### 9.1 FetchMode

```text
AUTO
HTTP_ONLY
BROWSER_REQUIRED
RECIPE_REQUIRED
INTERACTION_ALLOWED
```

### 9.2 L0～L4 路由层级

```text
L0 Authoritative     CMS/API/Feed/Sitemap
L1 HTTP              静态正文、文件、API
L2 Browser Render    JS hydration，但无需复杂交互
L3 Fixed Recipe      固定 click/scroll/load-more/分页交互
L4 Interactive       未知 UI、多步骤探索，受控 Agent Browser
```

AUTO：

```text
CMS/API/Feed/Sitemap -> HTTP
static HTML          -> HTTP -> extraction quality gate
PDF/file             -> HTTP stream -> Snapshot -> parser
JS shell/low quality -> L2 deterministic Browser
known interaction    -> L3 versioned Recipe
unknown interaction  -> L4 only if policy explicitly allows
```

### 9.3 Planner 输入与输出

Planner 输入：Source Profile、URL Observation、历史 Fetch Attempt、MIME/Probe Evidence、预算、当前 Runtime Capability、站点限流和质量门。

默认由规则引擎生成不可变 FetchPlan。LLM 只允许输出“候选计划”，随后必须通过：

```text
Capability Check
 -> Allowed Host Check
 -> SSRF/Egress Check
 -> Action Policy Check
 -> Budget Check
 -> Rate/Concurrency Permit
 -> Executor
```

Planner 不拥有浏览器、数据库写权限或 Secret。

### 9.4 Executor

Executor：

- 验证 FetchPlan fingerprint；
- 获取 global/domain/source permit；
- 调用对应 Adapter；
- 每次导航重新校验 URL；
- 保存 Snapshot / Render Artifact / Interaction Trace；
- 每 URL 独立提交；
- 返回结构化 failure evidence；
- 不接受网页内容要求扩权。

## 10. Browser、交互式浏览与可回放证据

### 10.1 Browser 路由保存两层事实

```text
navigate
 -> save network response metadata/body when available
 -> execute versioned wait/interactions
 -> capture final rendered DOM
 -> optional MHTML/screenshot
 -> persist Snapshot + RenderArtifact
 -> only then emit ARTIFACT_READY
```

Extractor 从 `render_artifact.rendered_dom_object_key` 离线读取。

### 10.2 Hydration 与确定性等待

优先级：

1. 明确 selector/JS predicate；
2. 明确应用事件或 DOM 状态；
3. `wait_until` 类通用页面状态；
4. bounded fixed delay 最后 fallback。

Recipe 记录 `wait_for`、`wait_until`、delay、js_code、滚动/点击、viewport、locale/timezone、iframe/Shadow DOM 选项。重复抓取比较 DOM/正文稳定性，防止偶然早抓制造假版本。

### 10.3 iframe 与 Shadow DOM

- `process_iframes` 只在确有正文时开启；
- 跨域 iframe 每跳做 SSRF/Egress/Scope；
- 被内联的跨域 iframe 尽量单独保存 child Snapshot/Artifact；
- `flatten_shadow_dom` 进入 transform manifest 和 Recipe Release；
- iframe/Shadow DOM 失败允许退化为引用链接，不悄悄丢来源。

### 10.4 Agentic Interactive Browser

仅用于：

- Probe 未知站点；
- 难以规则化的 UI；
- 明确人工/Research 任务；
- 连续确定性路线失败后的受控异常处理。

硬限制：

```text
allowed_hosts
allowed_actions
max_steps
max_wall_time
max_navigation_count
max_bytes
max_cost
allow_downloads=false by default
```

每一步保存动作与策略结果。成功流程应优先转成版本化 Recipe 草稿，从 L4 降级为 L3。

### 10.5 Prompt Injection 边界

可信控制面：Source Profile、FetchPlan、Action Policy、System Instruction、Operator Approval。

不可信数据面：HTML、Rendered DOM、iframe、评论、页面提示语、下载文件。

硬规则：

- 网页文字不能修改 allowed hosts；
- 网页文字不能提升 Tool 权限；
- 网页文字不能提高预算、步骤数或 cost ceiling；
- 网页文字不能要求读取 Secret、内部 URL、文件系统或 shell；
- Agent 建议的新 URL 仍需平台 Policy Gate；
- Browser Worker 不直写核心业务表，仅通过受控 Result/Artifact API 提交。

## 11. Structured Extraction

Structured Extraction 主要服务于：

- 复杂 Archive/列表页 -> URL/标题/日期；
- 页面 Metadata 补充；
- 规则难以稳定解析的小规模结构化任务；
- Probe/Research。

优先级：

```text
Rule / DOM Parser
 -> Schema validation
 -> quality gate
 -> only on failure: LLM Structured Extraction
```

LLM 结构化结果必须记录：Artifact、Schema Release、Instruction Release、Model Release、token/cost、Validation Error。

例如博客列表 Schema：

```json
{
  "type": "object",
  "properties": {
    "items": {
      "type": "array",
      "items": {
        "type": "object",
        "required": ["title", "url"],
        "properties": {
          "title": {"type": "string"},
          "url": {"type": "string"},
          "published_at": {"type": ["string", "null"]}
        }
      }
    }
  },
  "required": ["items"]
}
```

Validation 通过后，URL 仍须 normalize/scope/filter/dedupe。LLM 结果不允许直接写 Canonical Markdown。

## 12. Durable Task、幂等与恢复

PostgreSQL 保存 Task state；Transactional Outbox 同事务写事件；Publisher 投递 Redis Streams；Worker 用 consumer group 消费。Redis 丢失可从 PostgreSQL 重建运输队列。

```text
PENDING -> LEASED -> RUNNING -> SUCCEEDED
                    |          -> PARTIAL
                    -> RETRY_WAIT -> PENDING
                    -> QUARANTINED
                    -> DEAD
```

Worker 领取任务获得 `lease_until + fencing_token`。超时后新 Worker 可重新 lease；旧 Worker 恢复也不能用过期 token 覆盖新结果。

幂等键：

```text
DISCOVER: source + provider + release + cursor/window
OBSERVE: source + provider + normalized_url + evidence identity
PLAN: task + planner_release + profile_release + evidence_hash
FETCH: source + normalized_url + sync_run
RENDER: snapshot + recipe_release + runtime_release
INTERACT: fetch_plan + action_policy_release + run_generation
STRUCTURED_EXTRACT: source_artifact + schema_release + extractor_release
EXTRACT: source_artifact + extractor_release
MARKDOWN: version + markdown_release + projection_type
EMBED: chunk + embedding_release
EXPORT: export_spec_hash + release
RESEARCH: source + query_hash + profile_release + budget/run
```

## 13. 有界并发、Dispatcher 与 Browser 复用

分层 Permit：

```text
global concurrency
 -> domain concurrency/rate
 -> source concurrency/rate
 -> worker-local MemoryAdaptiveDispatcher/Semaphore/RateLimiter
```

Crawl4AI `arun_many/fetch_many` 只处理 Worker 已 lease 的 20～100 条有界窗口：

```text
lease bounded tasks
 -> acquire permits
 -> crawler streaming batch
 -> each result immediately persist or retry
 -> release permits
```

Browser 隔离：

```text
Browser process scope = WORKER
Context scope         = SOURCE | SECURITY_DOMAIN
Page scope            = TASK
Session scope         = RECIPE_INSTANCE | INTERACTION_RUN
```

- Browser 进程长期复用；
- Context 按 Source/安全域隔离；
- Page 默认每任务短生命周期；
- session 只用于明确顺序交互；
- Cookie/LocalStorage/认证态/代理身份不得跨 Source；
- page 数、RSS、任务数、运行时间到阈值主动 recycle；
- Interaction Worker 与普通 Browser Worker 分池，防止长交互占满常规 slot。

### 14.1 多候选 Extractor

### 14.3 三种 Markdown Projection

## 15. 增量同步、版本与删除检测

优先使用：

1. CMS API `updated_at` / cursor；
2. Sitemap `lastmod`；
3. Feed entry id/guid/published/updated；
4. Archive 最近若干页；
5. 定期低频 Coverage Verify / Deep Crawl 补洞。

每个 Provider 单独保存 checkpoint，不能只有一个模糊 `last_sync_time`。

Conditional Fetch：

```text
304
 -> update observation/fetch evidence
 -> no new Version

200 + raw body hash same
 -> no render/extract unless profile/runtime explicitly requires verify

200 + raw body changed
 -> HTTP route: extract
 -> Browser route: render and compare rendered artifact
 -> canonical content hash same: template/ads/noise change
 -> canonical content hash changed: create new Version
```

Browser-required Source 不能只用 raw body hash 决定跳过渲染，应结合 ETag/API evidence、历史 render fingerprint 和 Profile 策略。

增量默认不允许 L4 Interactive Browser；只有异常策略或人工启用后才可进入，以避免高成本和不稳定行为污染日常 SLA。

删除：

```text
ACTIVE -> SUSPECT_MISSING -> MISSING
       -> ACTIVE（再次出现）
```

综合 Sitemap/CMS 消失、连续 404、redirect/迁移证据判断，历史 Artifact 按生命周期策略保留。

## 20. 安全、合规与源站友好

### 20.1 SSRF / Egress

用户输入 URL、HTTP redirect、Browser navigation、Deep Crawl 新链接、iframe、Agent action target、附件 follow link、Webhook callback 每跳重新解析和校验：阻止 loopback、link-local、RFC1918、metadata endpoint、未允许端口/协议，并防 DNS rebinding。

### 20.2 Browser / Interaction

- 跨域 iframe 单独做 Scope/Egress；
- Shadow DOM flatten、JS 注入和交互只运行版本化 Recipe/Policy；
- Browser 禁止任意文件系统访问；
- 下载目录隔离并限大小；
- Rendered DOM/HTML 展示做 XSS sanitize；
- 网页内容不进入权限控制通道；
- Interaction Worker 使用最小权限网络与 Secret；
- Agent 无 shell、Kubernetes、核心 DB、内部管理 API 等能力。

### 20.3 Prompt Injection

平台 Policy Gate 高于模型输出：

```text
Webpage text
 -> Untrusted Context
 -> Agent proposes action
 -> Policy Gate validates URL/action/budget
 -> allow or block
```

记录：`prompt_injection_block_count`、`out_of_scope_action_block_count`、blocked target/action evidence。

### 20.4 Proxy / Anti-bot 边界

- 429/Retry-After：减速与退避；
- 403/CAPTCHA/明确策略阻断：`POLICY_BLOCKED` 或人工审核；
- Proxy 仅用于组织批准的出口故障切换、地域访问测试或隐私网络策略；
- 不用代理轮换规避源站限流、封禁、登录墙、付费墙或访问控制。

### 20.5 Runtime 与 Secret

- Secret 使用 Vault/K8s Secret；
- Crawler/Browser Runtime 仅内网暴露；
- 平台 API 是唯一外部入口；
- 容器最小权限、只读根文件系统、受控 egress；
- 固定 lockfile、镜像 digest、SBOM、Browser version；
- LLM Agent 还必须固定 model/system-instruction/action-policy release；
- Runtime 安全回归失败不得激活。

## 24. 部署、横向扩展与成本隔离

Worker 分池：

```text
discovery-worker
http-fetch-worker
browser-fetch-worker
interaction-worker
research-worker
extract-worker
structured-extract-worker
projection-worker
embed-worker

```

Browser、Interaction、Embedding、HTTP、Discovery、Research 的资源模型不同，必须独立扩缩容。

优先级：

```text
Incremental > Backfill > Verify > Structured LLM fallback > Research/Interactive
```

Kubernetes HPA 指标：queue lag、CPU、memory、Browser slots、dispatcher pressure、discovery lag、interaction backlog、research budget usage，而不只看 CPU。

1000 Source 原则：

- 默认每域低并发；
- 横向增加不同域名 Worker，不提高单站攻击性并发；
- Backfill 和 Incremental 分 priority，增量优先；
- Browser Pool 与 HTTP Pool 分开；
- Interaction Pool 更小且独立预算；
- 大站 discovery/fetch 全程有界窗口；
- 动态站 Render Artifact 写对象存储；
- Adaptive/Interactive Research 不挤占增量同步 SLA；
- 每 Source 可独立暂停、取消、恢复、限流、重跑和回滚 Profile。

初始压测基线：

```text
HTTP fetch slots:       50~200 / cluster
Browser pages:          10~40 / cluster
Interactive pages:      2~10 / cluster
per-domain HTTP:        1~4
per-domain Browser:     1~2
worker lease window:    20~100 URLs
deep checkpoint:        every 20~100 URLs or 5~30s
interactive max steps:  10~30（默认更低，按站点策略）
```

真实上限由源站策略、429、延迟、内存、Browser crash 和 cost 自动调小。

## 26. 失败模式与降级

- Redis 不可用：暂停运输，PostgreSQL Task 保持真相，恢复后重发 Outbox；
- Object Storage 不可用：不得把网络/渲染抓取标记为持久成功；
- PostgreSQL 不可用：Worker 停止领取新任务；
- Browser crash：单 URL/小窗口重试，必要时 recycle Worker；
- Rendered DOM 捕获失败：保留 Snapshot，标记 Artifact failure，不伪装抽取成功；
- wait 条件长期不满足：按 Recipe fallback/超时并保存失败证据；
- iframe 抓取失败：保留主文档和引用证据；
- Shadow DOM flatten 失败：退化普通 DOM，质量门决定是否 Quarantine；
- 大量 429/503：domain/source circuit breaker + Retry-After + jitter backoff；
- 403/CAPTCHA：`POLICY_BLOCKED`/人工审核，不自动升级绕过模式；
- Extractor 质量下降：Version 进入 Quarantine，可切旧 Extractor 离线重跑；
- Structured Extraction Schema 校验失败：结果 `INVALID/PARTIAL`，不得生成正式 Observation，必要时人工审核；
- LLM Structured Extraction 成本异常：预算熔断并退回规则/人工；
- Interactive Browser 超步数/超时/超成本：安全停止并保留 Trace；
- Interactive Browser 尝试越域：Policy Gate 阻断，不由 Agent 自行覆盖；
- Prompt Injection：网页指令无法改变 Action Policy，记录阻断证据；
- Runtime 升级回归/扫描失败：保持旧 ACTIVE Release；
- Deep Crawl 爆炸：max depth/max pages/max wall time/max external domains 截断并记录 stop reason；
- Deep Crawl checkpoint 丢失：从 seed 重跑并幂等去重；
- Checkpoint fingerprint 不匹配：拒绝旧 resume_state；
- 用户取消：完成安全边界后停止、flush checkpoint、Run 标记 CANCELLED；
- Adaptive/Agent state 丢失：从 seed/query/FetchPlan 重启，已进入事实链的数据不丢；
- Adaptive confidence 很高或 Agent“认为完成”：仍不能标记 Source Coverage 完整。

### 最终验收

**全量历史**：权威 Provider 有 Coverage Evidence；Worker 中断可继续；百万 URL 有界内存；Deep/Seeder/Prefetch/Agent 不绕过 Scope；BestFirst/Adaptive/max_pages/Agent completion 不误报完整。

**动态页面可回放**：Browser 页面同时有 Network Snapshot 与 Render Artifact；不访问源站即可从 Rendered DOM 重跑 Extractor；wait/interaction/iframe/Shadow DOM 变换可追溯。

**路由可审计**：每个非简单 HTTP Fetch 都能追溯到 FetchPlan、Planner Release、decision evidence 和 capability/budget；普通 Backfill/Incremental 不需要 LLM 决策即可运行。

**受控交互**：Agentic Browser 只有显式 Policy 才能启用；有 allowed host/action/step/time/cost 硬限制；每步可审计；网页内容不能扩大权限；成功路径可转成确定性 Recipe。

**结构化抽取**：复杂列表可使用版本化 Schema；LLM 只作预算化 fallback；结果必须验证并通过 Scope/Filter，不能直接覆盖 Canonical IR/Markdown。

**增量**：新文章按 Source SLA 被发现；304 不创建 Version；模板变化不制造大量假版本；Browser-required Source 不因 raw HTML 静态而漏掉渲染正文变化；正常增量不依赖 Interactive Browser。

**Markdown**：同一 IR + Markdown Release 输出确定；Canonical 与 FIT 语义分离；任意导出可回溯到 document/version/source artifact。

**可恢复性**：Redis 清空可恢复；lease/fencing 防旧 Worker 覆盖；Deep/Adaptive/Agent runtime state 丢失只增加重复工作，不丢事实。

**扩展性**：第 1001 个站点主要通过 Probe + Profile/Recipe/Schema 接入；Crawler/Browser/Agent 框架升级通过 capability Adapter/Runtime 隔离；新 Provider/Research Strategy 可插拔。

**安全**：Crawler/Browser Runtime 不直接对公网；跨域 iframe/redirect/Deep link/Agent action 每跳校验；Prompt Injection 无法修改平台 Policy；Runtime 有固定 digest/lockfile/SBOM/扫描记录。

## 28. 最终架构结论

最终系统不是“一个能抓网页的脚本”，而是一套长期数据平台：

```text
Coverage-first Discovery
        +
Durable Observation / Task / Checkpoint
        +
Rule-based Fetch Planner
        +
L0~L4 分层抓取能力
        +
Snapshot / Render / Interaction 可回放证据
        +
Canonical IR / Deterministic Markdown
        +
Incremental Versioning
        +
Rebuildable Search / Vector / Export
        +
Web 管理 / RBAC / Audit / SLO
```

大规模主链坚持确定性：CMS/Sitemap/Feed -> HTTP -> Browser -> 固定 Recipe。Agentic Browser 和 LLM Structured Extraction 只作为受控、预算化、可审计的异常能力；它们的输出必须回到平台统一的 Observation、Artifact、IR 和 Version 事实链。

这样既能在 1000+ 站点规模上保持吞吐、Coverage、成本和可恢复性，又能处理少量传统规则爬虫难以覆盖的复杂交互站点，并使后续新增网站越来越依赖配置与自动 Probe，而不是持续增加不可维护的站点专用代码。
