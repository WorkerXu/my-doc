# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站、公开 Newsletter** 的长期知识库采集平台，可平滑扩展到数千站点、百万级到千万级文章。

系统必须满足：

1. **全历史回填**：尽可能完整发现并抓取每个已批准 Source 的历史文章，并能解释未知与已知缺口；
2. **持续增量同步**：发现新文章、正文更新、URL 迁移、重定向、删除与重发布；
3. **稳定 Markdown**：Markdown 由可追溯 Raw Artifact 经过确定性抽取、质量门禁、Canonical IR 后生成；
4. **低成本扩站**：新增网站优先通过 Source Profile、Provider、Traversal Policy、Extraction Recipe 配置完成，不复制 1000 份站点脚本；
5. **Web 可运营**：支持 Source 接入、审核、Backfill、Incremental、Coverage、Frontier、失败诊断、暂停/恢复/停止、质量、成本和审计；
6. **可搜索与 RAG**：支持关键词、向量、混合检索，并能回溯原文、版本和抓取证据；
7. **可观测、可恢复、可重放**：任意 URL、任务、Artifact、Markdown 都能解释来源、版本和执行路径；
8. **渐进扩展**：开发期 Docker Compose，生产期按队列和 Worker 类型水平扩容；
9. **主链不依赖 LLM**：LLM 仅用于可选增强，不参与 Coverage Truth、URL Identity、Canonical URL 的最终判定。

### 1.1 核心 SLO

- **Coverage**：每个 Source 能解释 Provider、已发现 URL、Frontier、Known Gap 与 Backfill 停止原因；
- **Freshness**：新文章从发布/发现到 PASS Markdown 的延迟；
- **TTFM**：URL 首次发现到首个可用 Markdown 的时间；
- **Extraction Quality**：标题、正文完整率、噪声率、代码块/表格/列表保留率、截断率；
- **Reliability**：任务成功率、Retry、DLQ、Queue Age、Lease Recovery、Checkpoint Resume 成功率；
- **Browser Efficiency**：HTTP 命中率、Browser avoided、Browser recovery、每文档 Browser 成本；
- **Identity Quality**：重复文章误合并/漏合并率；
- **Validity Quality**：Soft-404、假 200、空壳 SPA 的识别准确率；
- **Traceability**：任意 Markdown 可回溯 Source、URL、Artifact、Extractor、Quality、Renderer Release；
- **Cancellation**：停止请求到不再领取新任务、到 Run 完全 STOPPED 的延迟；
- **Cost**：按 Source、Run、Queue Class、每 1000 篇 PASS 文档统计抓取、Browser、存储、索引和模型成本。

### 1.2 非目标

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不把 HTTP 200、DOM 很长或 crawler success 直接视为正文正确；
- 不把搜索结果数、Common Crawl、Wayback、Deep Crawl 页数或 `max_pages` 当历史完整性证明；
- 不把 Crawl4AI 即时 Markdown、LLM 摘要或改写直接作为 Canonical Markdown；
- 不因 URL 曾抓过就永久停止复检；
- 不把 Redis、Browser Session、Crawler Cache、Visited Set、Dispatcher Queue、Search Index 当业务真相；
- 不允许优先级、Scorer、相关性阈值或执行预算永久删除潜在历史文章；
- 不默认对所有文档构建 GraphRAG。

## 2. 核心设计原则

1. **Coverage First**：先建立 URL Inventory，再批量抓正文；
2. **Authoritative First**：CMS/API、Sitemap、RSS/Atom、官方 Archive 优先；
3. **Historical Gap Is Evidence, Not Truth**：Common Crawl、Wayback 用于历史补洞，不作为完整性证明；
4. **Deep Crawl Is Gap Provider**：站内深度抓取用于补洞，不作为 Coverage Truth；
5. **Discovery / Fetch / Extract / Quality / Projection 分离**；
6. **HTTP First, Browser Last**：Browser 是受治理慢路径；
7. **Snapshot First**：先保存不可变 Artifact，再抽取与清洗；
8. **Canonical IR First, Markdown as Projection**；
9. **Recipe, Not 1000 Site Scripts**；
10. **Stable Identity**：Source、Host、URL、Artifact、Document、Version 使用稳定 ID；
11. **Idempotent + Recoverable**：任务使用幂等键、lease、fencing token、checkpoint；
12. **Fair by Default**：大站 Backfill 不能饿死 Incremental 和小站；
13. **Bounded Concurrency Everywhere**：禁止无界 asyncio gather、Browser Context、LLM fan-out；
14. **No Silent Degradation**：截断、预算耗尽、降级、过滤、跳过必须显式记录原因；
15. **Release Everything That Changes Results**：Profile、Provider、Traversal、Recipe、Runtime、Extractor、Quality、Renderer、Embedding、Rank 全部版本化；
16. **Priority Means When, Not Whether**：优先级决定何时处理，不决定是否永久保存；
17. **Observation Before Selection**：观察到链接后先保存事实，再做 Filter/Score/Budget 选择；
18. **Persistent Frontier, Not In-Memory Traversal**：BFS/DFS/Best-First 的业务语义进入数据库；
19. **Runtime Checkpoint != Business Checkpoint**：第三方 crawler resume state 只是执行优化，PostgreSQL 才是恢复真相；
20. **Cooperative Cancellation**：停止是状态机，不把点击停止等同于所有 in-flight 工作已经结束；
21. **Approved Scope First**：发现子域、路径或外部归档 URL 不等于允许主动访问；
22. **Soft-404 Is First-class**：URL 存在性不能只依赖 HTTP 状态码；
23. **Global Admission + Local Adaptation**：跨 Worker 公平/限流由平台负责，Worker 内存自保护由运行时负责；
24. **Same Semantics, Different Topology**：单机 Pilot 与生产集群共享状态机、模型和任务协议。

## 3. 总体架构

```text
                           Web Admin / REST API / CLI
                                      |
                             API + RBAC + Audit
                                      |
                           PostgreSQL Truth Store
                                      |
                            Transactional Outbox
                                      |
                               Redis Streams
                                      |
                     Global Admission + Fair Scheduler
                                      |
       +------------------------------+-------------------------------+
       |                              |                               |
 Discovery Plane                 Fetch Plane                  Projection Plane
       |                              |                               |
 CMS/API/Sitemap/RSS                 HTTP                          Markdown
 Archive/Listing                     Crawl4AI Browser              OpenSearch
 CommonCrawl/Wayback Gap             Playwright                    pgvector
 Safe Domain Recon                   PDF/Other                     Enrichment
 Deep Crawl Prefetch                 Worker Local Dispatcher       Preview
       |                              |                               |
       +------- Observation -> Persistent URL Inventory / Frontier --+
                                      |
                              URL Validity Gate
                                      |
                             Immutable Artifact
                                      |
                           Extraction Portfolio
                                      |
                         Candidate Quality Gate
                              /              \
                           PASS              REPAIR
                              \              /
                               Canonical IR
                                      |
                               Document Version
                                      |
                          Identity / Provenance
```

### 3.1 业务真相边界

**PostgreSQL + Object Storage 是业务真相。**

- PostgreSQL：Source、Approved Host、Provider、URL Identity、URL Observation、Validity、Crawl Frontier、Task、Cursor、Coverage、Quality、Document、Version、Release、Checkpoint Pointer、Audit；
- S3/MinIO：Raw HTML、MHTML、截图、Trace、Provider Evidence、Candidate、IR、Markdown、PDF、Runtime Checkpoint State、Enrichment；
- Redis Streams：任务运输、Consumer Group、Backpressure、分布式 token bucket，不保存不可替代业务状态；
- OpenSearch / pgvector：可重建 Serving Projection；
- Crawl4AI local cache、dispatcher queue、rate limiter、Browser Session、Playwright Context、Worker 内存：易失执行状态。

## 4. 技术选型

### 4.1 控制面

- **FastAPI + Pydantic**：REST API、Command、Schema 校验；
- **PostgreSQL**：Truth Store、任务、Coverage、Frontier、版本、审计；
- **Redis Streams**：任务运输、Consumer Group、Backpressure；
- **Redis Lua Token Bucket / Semaphore**：跨 Worker 域名限流和资源令牌；
- **React / Next.js + TypeScript**：Web 管理后台；
- **OpenTelemetry + Prometheus + Grafana + Structured Logging**：Trace / Metric / Log；
- **S3/MinIO**：不可变对象存储；
- **Vault/KMS/Secret Manager**：凭据引用。

### 4.2 Discovery / Fetch

- **httpx/aiohttp**：robots、Sitemap、Feed、CMS API、Conditional GET、普通网页；
- **Crawl4AI**：Domain Mapping、AsyncUrlSeeder、Browser Render、Deep Crawl Prefetch、动态链接发现、多 URL 执行；
- **Crawl4AI MemoryAdaptiveDispatcher**：Browser Worker 本地内存自保护与有界并发；
- **Playwright Python**：复杂多步、有状态、需要 Step 级恢复的交互；
- **Common Crawl Adapter**：公共历史索引补洞；
- **Wayback CDX Adapter**：历史 URL 补洞，支持分页/时间窗口；
- **SearXNG / 合规 Search API Adapter**：External Search Gap、新 Source Candidate；
- **PyMuPDF/pdftotext**：PDF；扫描件进入 OCR 慢路径；
- **Python email/MIME parser**：Newsletter Inbox Provider。

### 4.3 Extraction / Search

- **Trafilatura**：Generic Main Content Candidate；
- **lxml/BeautifulSoup**：DOM/XPath、Metadata、DOM Repair；
- **JSON-LD/OpenGraph/Microdata**：结构化元数据；
- **CSS/XPath/Regex Recipe**：确定性正文与字段抽取；
- **SimHash/MinHash**：近重复候选；
- **OpenSearch BM25 + pgvector + RRF**：混合检索；
- **可选 reranker / LLM**：只在 Canonical 数据之后运行。

### 4.4 Release 冻结

必须记录：

```text
runtime_release
source_profile_release
host_scope_release
provider_adapter_release
traversal_policy_release
interaction_recipe_release
extractor_release
validity_release
quality_release
identity_release
renderer_release
embedding_release
retrieval_release
```

任何改变结果的升级必须经过 Golden Replay / Offline Eval，必要时 Canary。Crawler 运行时必须 pin 到经过验证的 immutable release，不使用浮动 latest。

## 6. Source 接入流程

新增网站先自动探测，再人工确认并发布 immutable Source Profile Release。

### 6.1 接入探测顺序

```text
1. Exact-host robots.txt / Sitemap / Feed
2. CMS 特征：WordPress/Ghost/Medium/Substack/自建 API
3. 首页与安全内容路径探测
4. Archive / Pagination / URL Pattern
5. Canonical / Redirect / Query 参数行为
6. Soft-404 baseline
7. HTTP vs Browser route sampling
8. 可选 metadata-only 子域候选发现
9. 人工审核 Content Host
10. Common Crawl / Wayback 历史 Gap inventory
11. Deep Crawl 浅层 Prefetch
12. 发布 Source Profile Release
```

### 6.2 Domain Recon 的安全边界

DomainMapper 的能力不能原样开放给 Web 用户。平台包装 `DomainReconAdapter`：

- 默认 `include_subdomains=false`；
- 子域发现只生成 `host_candidate`；
- 未批准 host 不进行主动正文抓取；
- 不使用通用 `/admin`、`/login`、`/graphql`、`/debug` 等路径探测；
- 只允许内容型路径，例如 `/blog`、`/posts`、`/articles`、`/news`、`/engineering`、`/tech`、`/archive`；
- `robots.txt Sitemap:` 可用于发现；`Disallow:` 只用于拒绝/约束，不能作为主动 probe 候选；
- 所有目标仍经过 SSRF / approved scope 校验。

### 6.3 Source Profile 示例

```yaml
source:
  canonical_domain: example.com
  approved_hosts:
    - host: example.com
      type: CONTENT
  providers:
    - sitemap
    - rss_atom
    - archive
    - common_crawl_gap
    - wayback_gap
    - deep_crawl
  fetch_route:
    default: http
    browser_patterns:
      - /interactive/*
  recon:
    include_subdomains: false
    safe_probe_paths:
      - /blog
      - /archive
  traversal:
    mode: bfs
    max_depth: 3
    max_pages_per_slice: 300
    include_external: false
    prefetch: true
    threshold_policy: priority_only
  extraction:
    generic: trafilatura
    article_selector: null
  incremental:
    rss_interval: 10m
    sitemap_interval: 6h
    home_probe_interval: 30m
```

### 6.4 Seed 安全校验

创建 Run 前必须验证：

```text

scheme 为 http/https
Source enabled
robots/access policy 已计算
Traversal Policy 已发布
SSRF destination validation 通过
凭据/代理策略合法
```

## 7. Discovery 与 Coverage

### 7.1 Provider 优先级

```text
CMS/API
 -> Sitemap
 -> RSS/Atom
 -> Archive/Pagination
 -> HTML Listing
 -> Common Crawl / Wayback Historical Gap
 -> Safe Domain Recon Gap
 -> Deep Crawl Prefetch
 -> External Search Gap
```

高优 Provider 的结果不能阻止其它 Provider 执行。最终 URL Inventory 是多个 Provider 的集合并集，并保留每条 Observation 的来源证据。

### 7.2 Backfill 流程

```text
Source Approved
 -> Probe Authoritative Providers
 -> Build Initial URL Inventory
 -> Archive/Pagination Enumeration
 -> Common Crawl / Wayback Historical Gap
 -> Safe Domain Recon Gap
 -> Deep Crawl Gap Scan
 -> Persistent Frontier
 -> URL Validity Gate
 -> Fetch
 -> Extract / Quality / IR / Markdown
 -> Coverage Reconcile
 -> Gap Review
 -> Backfill Complete
```

### 7.3 Historical Gap Provider

#### Common Crawl

用于发现当前站点已经不再链接的旧 URL。结果必须回源验证，不直接认定为当前有效文章。

#### Wayback CDX

不能只做单次 `limit=10000` 查询。大型站点按以下方式切片：

```text
year window
URL prefix
CDX page/resume key
```

每个窗口有独立 `provider_run` 和 cursor，确保可恢复、可审计。

### 7.4 Coverage Ledger

```text
coverage_snapshot
- source_id
- provider_run_id
- provider_type
- discovered_count
- unique_url_count
- article_candidate_count
- fetched_count
- pass_count
- failed_count
- deferred_count
- soft404_suspected_count
- known_gap_count
- stop_reason
- captured_at
```

### 7.5 Backfill 完成条件

至少满足：

- 权威 Provider 已完成或明确不可用；
- Historical Gap Provider 已运行到配置边界并记录限制；
- Persistent Frontier 无 READY/LEASED/RETRY；
- Deep Crawl / Archive 不再产生新增文章候选，或达到明确可解释的收敛条件；
- 失败任务全部成功、进入 DLQ 或被人工接受；
- Soft-404 疑似批次已经确认、延期或人工接受；
- Known Gap 为空或被人工接受；
- 多 Provider URL 集合差异处于阈值内。

### 7.6 URL 规范化

```text
resolve relative
 -> lower host
 -> remove default port
 -> strip fragment
 -> normalize path
 -> query policy
 -> tracking parameter policy
 -> redirect identity
 -> rel=canonical evidence
```

不要过早删除 query 参数。每个 Source 先采样生成 Query Policy，再发布 release。

## 8. Domain Mapping 与 Safe Recon

### 8.1 角色定位

Domain Mapping 只用于：

- 接入期识别 Sitemap、Feed、首页结构和内容 host；
- 发现当前 Sitemap 漏掉的内容入口；
- 形成子域候选；
- 建立 Soft-404 行为基线；
- 周期性发现站点结构变化。

它不用于：

- 自动扩大 approved scope；
- 把所有证书子域当抓取目标；
- 探测管理、登录、调试或内部接口；
- 证明历史完整；
- 替代独立 Sitemap / Feed / Common Crawl / Wayback Provider。

### 8.2 多源结果处理

上游运行时可能把同一 URL 的来源合并为一个字符串，平台必须拆开保存原始 Provider Observation：

```text
同一 URL
- sitemap observation
- homepage observation
- wayback observation
- common_crawl observation
```

随后 URL Identity 再做去重。

### 8.3 Nonsense Filter 与业务证据

运行时可以过滤静态资源、webpack chunk 等噪声，但平台要区分：

```text
Observation Evidence
vs
Article Admission
```

对文章知识库无需保存所有图片/CSS 为 Frontier，但 Filter reason 必须可解释。任何可能是文章的 URL 不允许因相关性低直接消失。

## 9. Deep Crawl 与 Traversal Policy

### 9.1 角色定位

Deep Crawl 只用于：

- 发现 Sitemap/RSS/API 漏掉的站内 URL；
- 发现归档、分页、标签、年份入口；
- 验证导航结构与 URL pattern；
- 处理 JS 动态链接；
- 定期执行 Coverage Gap 扫描。

不用于证明历史已经完整。

### 9.2 两阶段 Prefetch

```text
Phase A: Prefetch Discovery
- 获取 HTML / links / minimal metadata
- 记录 from_url -> to_url Observation
- 跳过 Markdown / LLM / 重型抽取
- 形成 Persistent Frontier

Phase B: Full Processing
- Fetch Raw Artifact
- URL Validity
- Extraction / Quality / IR / Markdown
```

若 HTTP/Sitemap 已能完成发现，优先不用 Browser Prefetch。

### 9.3 Observation Before Selection

```text
Page Result
 -> Extract Raw Links
 -> Persist Observation
 -> Normalize / Scope Check
 -> Filter Reason
 -> Score
 -> Budget / Admission
 -> Persistent Frontier
 -> Runtime Slice
```

禁止先由 visited/threshold/max_pages 裁剪，再只保存被选中的 URL。

### 9.4 BFS / DFS / Best-First

- **BFS**：Backfill 默认探测策略；
- **DFS**：路径深度结构明确时启用；
- **Best-First**：固定预算下优先处理更像文章、归档、分页的 URL。

全历史模式统一解释：

```text
score -> priority
```

除明确 deny rule 或 focused job 外，不因低分永久删除 URL。

### 9.5 Bounded Slice

大型站点按 Source 切片：

```text
incremental_high: 立即调度
source A backfill: 200~500 URL slice
source B backfill: 200~500 URL slice
browser_slow: 独立慢队列
```

Slice 结束后未处理候选仍在 PostgreSQL Frontier。

### 9.6 Runtime Checkpoint 与 Business Checkpoint

```text
Crawl4AI resume_state = 执行优化
PostgreSQL crawl_frontier = 业务恢复真相
S3 Artifact = 抓取事实
Transactional Outbox = 状态与消息一致性
```

Runtime state 可周期性写 Object Storage，PostgreSQL 只保存 pointer、hash、release、captured_at。

### 9.7 协作式取消

```text
RUNNING
 -> STOP_REQUESTED
 -> DRAINING
 -> STOPPED
```

Scheduler 停止发新 lease；Worker 读取 cancellation token；in-flight Fetch 完成或超时；最后一次 durable commit 后释放 lease。

### 9.8 Crawl4AI Adapter

业务代码统一经 Adapter：

```text
validate_scope()
build_config()
build_fresh_filter_chain()
build_scorer()
discover_slice()
run_many_stream()
normalize_result()
emit_observations()
capture_runtime_checkpoint()
map_cancellation()
translate_error()
```

禁止业务代码依赖 Crawl4AI 内部 visited、queue、ContextVar 或 Browser 对象。

## 10. Fetch Plane

### 10.1 HTTP First

```text
HEAD/GET probe
 -> 普通 HTTP 成功且正文足够
    -> HTTP artifact
 -> JS shell / challenge / content incomplete
    -> Browser slow path
```

Browser 不是默认抓取器。

### 10.2 Conditional Fetch

增量复检使用：

```text
If-None-Match: ETag
If-Modified-Since: Last-Modified
```

`304` 不生成新正文版本，但更新 freshness observation。

### 10.3 Retry 分类

```text
DNS/TCP timeout       -> exponential retry
429                   -> Retry-After + domain throttle
5xx                   -> bounded retry
403/challenge         -> policy-based browser/proxy route
404/410               -> tombstone candidate, grace policy
soft-404 suspected    -> validity/repair queue
parse/extract failure -> repair queue，不等于必须 refetch
```

### 10.4 多层限流

每个域名维护：

```text
requests_per_second
burst
max_http_concurrency
max_browser_concurrency
retry_after_until
robots crawl-delay / local policy
```

职责分离：

```text
Redis Token Bucket       = 跨 Worker 精确节流
Worker Semaphore         = 本地并发保护
Crawler RateLimiter      = 429/503 自适应退避
MemoryAdaptiveDispatcher = Worker 内存压力保护
```

不能把本地 Semaphore 当作严格 RPS，也不能把进程内 RateLimiter 当跨 Worker 协调器。

### 10.5 Raw Artifact First

Fetch 成功后先写不可变对象：

```text
raw/{source_id}/{yyyy}/{mm}/{artifact_id}.html.gz
```

附 metadata：

```text
requested_url
final_url
status_code
headers
fetch_started_at
fetch_finished_at
runtime_release
proxy/session route
payload_sha256
trace_id
```

只有 Artifact durable 后，任务才能进入 EXTRACT。

## 11. Worker 本地自适应执行

### 11.1 Browser Worker

Browser Worker 从平台领取有限 Slice，再交给 Crawl4AI：

```text
DB/Redis Lease Slice
 -> arun_many(stream=true)
 -> MemoryAdaptiveDispatcher
 -> result-by-result durable commit
```

建议：

- `max_session_permit` 按容器内存、页面平均 RSS 和 Browser Context 成本压测标定；
- memory pressure 时停止领取新本地任务；
- critical pressure 允许本地重新排队，但平台 lease 仍有超时与 fencing；
- stream 关闭时 cancel + await 活跃 task，避免 Browser page/context 泄漏；
- 不等整批完成后再统一写结果。

### 11.2 Local Dispatcher 不是业务队列

Dispatcher Queue、local fairness、local retry 都是执行层优化。Worker 崩溃后恢复依据仍然是：

```text
PostgreSQL task/frontier
+ lease_until
+ fencing_token
+ durable artifact/checkpoint
```

- 列表；

- 数学公式；
- 图片 alt / caption / 原始 URL；

### 14.1 Task 类型

```text

```

### 14.2 幂等键

```text
DISCOVER: source_id + provider + run_id + cursor_window
VALIDATE: url_id + validity_release + freshness_window
FETCH:    url_id + fetch_policy_release + freshness_window
EXTRACT:  artifact_id + extractor_release
RENDER:   document_version_id + renderer_release
INDEX:    document_version_id + retrieval_release
```

### 14.3 Lease + Fencing Token

```text
READY
 -> LEASED(owner, lease_until, fencing_token)
 -> DONE
 -> RETRY
 -> DLQ
```

Worker 提交结果必须带 fencing token，过期 Worker 的迟到提交不能覆盖新 lease 结果。

### 14.4 Transactional Outbox

```text
BEGIN
  update task/frontier
  insert outbox_event
COMMIT

Outbox Relay -> Redis Streams
```

Consumer 通过幂等键安全重放。

### 14.5 队列分级

```text
incremental_high
incremental_normal
backfill_normal
backfill_bulk
discovery_recon
discovery_prefetch
browser_slow
validity
repair
reindex
enrichment
```

### 14.6 Fair Scheduler

```text
Queue Class 权重
 -> Source deficit round-robin
 -> Domain token bucket
 -> Worker capability admission
 -> Worker local adaptive dispatcher
```

### 14.7 有界并发

```text
Global fetch slots
Per-domain HTTP slots
Per-domain Browser slots
Per-source active tasks
Per-worker memory budget
Browser contexts
Extraction CPU slots
LLM enrichment slots
```

禁止直接 `asyncio.gather(*millions_of_urls)`。

### 14.8 Pause 与 Cancel

```text
PAUSED: 不发新任务，保留 Run 可继续
STOP_REQUESTED: 用户要求本次 Run 终止
DRAINING: 等待 in-flight 收尾
STOPPED: 本次 Run 已终止
```

## 19. 安全、合规与抓取礼仪

- 默认尊重 robots/access policy，并把策略版本化；
- `robots.txt Disallow` 只做限制，不转为主动 Probe；
- 不自动绕过登录、付费墙、CAPTCHA、明确禁止；
- approved CONTENT host allowlist，禁止自动扩大 scope；
- 禁止任意 SSRF：loopback、RFC1918、link-local、云 metadata、file:// 等；
- Crawler Docker/API 只放内网，不直接暴露公网；
- Web 用户不能直接提交任意目标 URL、任意 JS hook 或任意 CrawlerRunConfig；
- JS execution、下载路径、webhook 等高风险能力默认关闭，确需启用时通过 Recipe allowlist；
- Browser 下载、文件协议、JS hook 按最小权限控制；
- 凭据只存 Secret Manager 引用；
- Proxy 使用有审计；
- 速率限制按域名、Source 和全局多层执行；
- Common Crawl/Wayback/CT 等第三方查询也纳入 egress、超时和审计；
- 删除/下线遵循数据保留策略和来源许可。

```text
8. score 只映射 priority
9. 所有 Observation 先落库
10. Soft-404 先做 validity 再决定 admission
11. HTTP First，Browser 仅慢路径
12. Raw Artifact durable 后再 Extract
13. Frontier 清空 + Provider 完成 + Known Gap 审核后才标记完成
```

### Incremental

```text
RSS/CMS 高频
Sitemap 中频
Homepage/Archive 低频探测
Conditional GET 复检
周期性 CommonCrawl/Wayback delta
周期性 Safe Domain / Deep Crawl Gap Scan
```

### Crawl4AI Runtime

```text
runtime release 固定
source config 由平台 release 编译
filter_chain 显式新建
resume_state 只做 runtime hint
checkpoint 带 release envelope
MemoryAdaptiveDispatcher 只做 Worker local admission
RateLimiter 只做本地退避
全局 RPS 由 Redis token bucket 控制
stream close 必须 cancel + await active tasks
```

## 24. 验收标准

平台达到可生产使用至少满足：

1. 新增一个标准博客主要通过 Web Source Profile 完成，不新增独立爬虫脚本；
2. 新 host 只能以 Candidate 出现，未经批准不能主动抓取；
3. 任意 Source 能执行全历史 Backfill，并解释 Coverage、Historical Gap 与 Known Gap；
4. Common Crawl/Wayback 只作为补洞证据，不被误当完整性证明；
5. 任意发现 URL 都能解释 Provider、Filter、Score、Admission、Validity、Frontier 状态；
6. SPA/自定义 404 不会仅因 HTTP 200 大规模进入正文库；
7. Worker 任意 kill 后不丢业务 Frontier，可通过 lease/checkpoint 恢复；
8. Crawl4AI local queue/cache/runtime state 丢失时仍可从 PostgreSQL/Object Storage 重建；
9. `max_pages`、低 score、Provider timeout 不会让全历史候选静默消失；
10. 点击停止后立即停止发新 lease，并最终进入 STOPPED；
11. Browser Worker 内存压力可自动降低/暂停本地并发，且不会破坏平台任务状态；
12. Raw Artifact 可重放生成新的 IR/Markdown，不必重新抓网页；
13. Incremental 能通过 RSS/Sitemap/Conditional GET 持续同步新内容与更新；
14. Markdown 保留标题、正文、代码、表格、列表等关键结构并通过质量门禁；
15. Search Index 全部可从 Canonical 数据重建；
16. 所有改变结果的组件都有 release，并通过 Golden Replay 后发布；
17. Web Admin 能完成接入、审核、Backfill、Incremental、Coverage、失败诊断、暂停/恢复/停止和审计。

最终架构原则：

> **权威 Provider 建 Inventory，Common Crawl / Wayback / Safe Domain Recon / Deep Crawl 补 Coverage Gap；Observation 先于选择，Approved Scope 先于主动访问，Soft-404 先于有效性判断，Persistent Frontier 保证不丢；Raw Artifact 保证可重放，Canonical IR 保证稳定 Markdown；Global Scheduler 管跨 Worker 公平与限流，MemoryAdaptiveDispatcher 管 Worker 本地资源；Runtime Checkpoint 提升执行恢复效率，但业务真相始终在 PostgreSQL + Object Storage。**
