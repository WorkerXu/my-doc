# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站和公开 Newsletter** 的长期知识库采集平台，并可平滑扩展到数千站点、百万至千万级文章。

平台必须同时满足：

1. **全历史回填**：尽可能完整发现每个已批准 Source 的历史文章，并能解释覆盖率、已知缺口和停止原因；
2. **持续增量同步**：持续发现新文章、正文更新、URL 迁移、重定向、删除和重发布；
3. **稳定 Markdown**：从不可变 Raw Artifact 经确定性抽取、质量门禁、Canonical IR 生成可重放 Markdown；
4. **低成本扩站**：新增网站优先通过 Source Profile、Provider、Traversal Policy、Extraction Recipe 配置完成，不维护 1000 份站点脚本；
5. **Web 可运营**：支持站点接入、审批、Backfill、Incremental、Coverage、Frontier、质量、成本、暂停、恢复、诊断和审计；
6. **可恢复、可重放**：URL、Run、Task、Attempt、Runtime Result、Artifact、Document、Version 全链路可追溯；
7. **可搜索/RAG**：支持 BM25、向量和混合检索，并能回到原文、版本、Source 和抓取证据；
8. **渐进扩展**：开发期 Docker Compose，生产期各执行面独立水平扩容；
9. **主链不依赖 LLM**：LLM 只做可选增强，不参与历史完整性、URL 身份、robots、正文存在性等最终判定。

### 1.1 核心 SLO

- **Coverage**：每个 Source 都有 Provider Inventory、Known Gap、Backfill Stop Reason；
- **Freshness**：新文章从发布/发现到 PASS Markdown 的延迟；
- **TTFM**：URL 首次发现到首个可用 Markdown 的时间；
- **Extraction Quality**：标题、正文、代码块、表格、列表保留率和噪声率；
- **Reliability**：Task 成功率、Retry、DLQ、Queue Age、Lease Recovery；
- **Browser Efficiency**：HTTP 命中率、Browser Avoided、Pool Reuse、每文档 Browser 成本；
- **Runtime Stability**：queue saturation、真实内存压力、browser acquire latency、pool churn、drain latency；
- **Result Integrity**：批量/流式 Runtime Result 的物化完整率、cardinality mismatch、schema mismatch；
- **Replayability**：同 Raw Artifact + 同 Release 可复现 IR 和 Markdown；
- **Artifact Durability**：required runtime artifact 在 TTL 到期前晋升到平台对象存储的比例接近 100%。

### 1.2 非目标

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不默认使用个人持久 Browser Profile、模拟用户等反爬绕过手段；
- 不把 HTTP 200、Runtime `success=true`、DOM 很长直接视为文章正确；
- 不把搜索结果数、Common Crawl、Wayback 或 Deep Crawl 页数当作历史完整性证明；
- 不把 Crawl4AI 即时 Markdown、LLM 摘要直接作为 Canonical Markdown；
- 不把 Redis、Runtime Cache、Browser Session、Visited Set、Runtime Queue、Search Index 当业务真相；
- 不允许外部用户提交任意 JS/Python、代理、CDP、服务器路径或任意 webhook URL。

## 2. 核心设计原则

1. **Coverage First**：先建立 URL Inventory，再批量抓正文；
2. **Authoritative First**：CMS/API、Sitemap、RSS/Atom、官方 Archive 优先；
3. **Historical Gap Is Evidence, Not Truth**：Common Crawl、Wayback 只作为补洞证据；
4. **Discovery / Fetch / Extract / Quality / Projection 分离**；
5. **HTTP First, Browser Slow Lane**；
6. **Snapshot First**：先保存不可变 Raw Artifact；
7. **Canonical IR First, Markdown as Projection**；
8. **Recipe, Not 1000 Site Scripts**；
9. **Persistent Frontier, Not In-Memory Traversal**；
10. **Idempotent + Recoverable**：幂等键、Lease、Fencing Token、Checkpoint、Inbox/Outbox；
11. **Fair by Default**：大站 Backfill 不得饿死 Incremental、小站和 Repair；
12. **Bounded Concurrency Everywhere**；
13. **No Silent Degradation**：过滤、截断、预算耗尽、降级、结果缺失必须有原因；
14. **Observation Before Selection**：链接事实先保存，再 Filter/Score/Budget；
15. **Runtime Is Execution Plane**：第三方 Runtime 不拥有 Coverage、Identity、Document 或 Markdown 真相；
16. **Correlate by Identity, Never by Position**；
17. **Config Is Capability**：能改变代码、网络、浏览器或 secret 的字段必须经过 Capability Firewall；
18. **Untrusted by Default at Network Boundary**；
19. **Caller Never Owns Paths**；
20. **Webhook Is Hint, Reconciliation Is Truth**；
21. **Runtime Queue != Durable Queue**；
22. **Context Generation != Browser Process Generation**；
23. **Behavior Beats Naming**：pinned release + Contract Test 才是生产行为契约；
24. **Runtime Artifact Is Ephemeral Until Promoted**；
25. **Zero Must Not Mean Unbounded by Accident**；
26. **Runtime State Is Observation, Not Truth**：Runtime 粗粒度状态不能伪装成精确 queued/running 真相；
27. **Control Browser Config Cardinality**：大量站点应映射到少量 Browser Profile Class；
28. **Result Transport Is Not State Store**：Runtime Redis Result 只做短期交接，结果立即逐条物化；
29. **Drain/Replace Before In-Place Kill**：生产运维优先摘流、收敛、替换，再重新探活。

## 5. Source 接入与配置模型

### 5.1 Source Profile

新增网站创建声明式 Source Profile：

```yaml
source:
  name: example-tech-blog
  entry_url: https://example.com/blog/
  approved_hosts: [example.com]
  allowed_paths: [/blog/]
  denied_paths: [/login/, /account/]

providers:
  - type: sitemap
    url: https://example.com/sitemap.xml
  - type: rss
    url: https://example.com/feed.xml
  - type: archive
    start_url: https://example.com/blog/archive/

fetch:
  mode: auto
  http_timeout_s: 20
  browser_profile_class: public-default
  browser_intent:
    render_js: true
    scroll: bounded
    wait_selector: article

extract:
  recipe: generic_article_v3
  content_selectors: ["article", ".post-content"]
  exclude_selectors: ["nav", "footer", ".related"]

incremental:
  feed_poll: 10m
  sitemap_poll: 1h
  archive_reconcile: 1d
  full_reconcile: 7d
```

### 5.2 Capability Firewall

Web/API 用户只提交 intent，不允许直接透传 Runtime 高能力字段。

普通配置禁止：

- 任意 `js_code` / Python code；
- `proxy` / `proxy_config`；
- `user_data_dir` / `cdp_url`；
- 任意 cookies/headers/secret；
- 任意服务器 path；
- 任意 LLM base URL；
- 任意 webhook destination；
- `0=unbounded` 的 queue/time/budget；
- 不受控 deep crawl strategy。

Config Compiler 根据已审批 Profile Release 生成 Runtime Config，并输出编译报告、最终能力集合、预算和拒绝原因。

### 5.3 Browser Profile Class

不要让 1000 个 Source 产生 1000 个 BrowserConfig。平台维护少量、受审的 Browser Profile：

```text
public-default
public-js-heavy
public-media-light
isolated-authenticated
```

站点特有 selector、wait、scroll、正文规则优先放入低成本 CrawlerRunConfig/Extraction Recipe。只有真正改变浏览器进程能力、网络边界或 credential scope 的需求才生成新的 Browser Profile Release。

## 6. 历史 URL 发现与 Coverage

### 6.1 Provider 优先级

推荐：

1. CMS/官方内容 API；
2. Sitemap / Sitemap Index；
3. RSS/Atom；
4. 官方 Archive / Category / Pagination；
5. 站内静态链接图；
6. Crawl4AI Domain Mapping / Deep Crawl 作为发现增强；
7. Common Crawl / Wayback；
8. 合规 Search Adapter 作为 Gap Evidence。

每个 Provider 只产生 Observation，不直接决定最终文章集合。

### 6.2 Observation

```text
url_observation
- source_id
- provider_type
- provider_ref
- observed_url
- discovered_at
- published_at_hint
- updated_at_hint
- parent_url
- anchor_text
- depth
- evidence_artifact_id
- provider_release_id
```

链接事实先落库，再做 scope/filter/dedup，避免过滤错误后无证据可查。

### 6.3 Coverage 不是一个数字

```text
coverage_snapshot
- provider inventories
- accepted URL count
- fetched count
- PASS count
- known gaps
- excluded reasons
- pagination stop reason
- earliest known date
- latest known date
- provider disagreement
- last_full_reconcile_at
```

Backfill 停止原因必须显式，例如：

```text
AUTHORITATIVE_PROVIDER_EXHAUSTED
ARCHIVE_PAGINATION_EXHAUSTED
DATE_BOUND_REACHED
ROBOTS_BLOCKED
ACCESS_DENIED
BUDGET_EXHAUSTED
KNOWN_GAP_REQUIRES_REVIEW
```

预算耗尽不能标记为“抓全”。

### 6.4 Adaptive / Focused Discovery

对 Provider 完整性差的站点，可使用：

- Domain Mapping 建立候选 URL 图；
- BFS/DFS/Best-First 做 bounded traversal；
- Pattern/Content Type/Path Filter；
- 已知文章日期区间驱动 focused discovery；
- soft-404 模板过滤；
- checkpoint + budget。

Adaptive Crawling 只用于降低无效探索成本，不替代 authoritative provider coverage 证明。

## 7. URL Identity、Scope 与 Persistent Frontier

### 7.1 Conservative Normalization

默认：

- host 小写；
- 去 fragment；
- 标准化默认端口；
- allowlist 删除明确追踪参数；
- path/query 大小写和未知参数默认保留；
- canonical 标签只做证据，不盲信。

```text
url_identity
- id
- source_id
- normalized_url
- canonical_candidate
- first_seen_at
- last_seen_at
- state
```

Redirect、canonical、内容近重复分别建立 relation，避免 aggressive normalization 永久误合并不同文章。

### 7.2 Persistent Frontier

```text
frontier_item
- url_identity_id
- source_id
- run_id
- purpose: BACKFILL/INCREMENTAL/REPAIR/VERIFY
- priority
- depth
- next_attempt_at
- attempt_count
- state
- budget_class
- checkpoint_ref
```

Frontier 必须持久化，不能依赖 Runtime 内存 visited set。

## 8. Scheduler、Task、Lease 与公平性

### 8.1 Durable Task

```text
task
- id
- run_id
- source_id
- url_identity_id
- task_type
- idempotency_key
- priority_class
- state
- lease_owner
- lease_until
- fencing_token
- retry_count
- next_attempt_at
- deadline_at
- created_at
```

推荐幂等键：

```text
(task_type, url_identity_id, source_profile_release, relevant_version)
```

### 8.2 Fair Scheduler

至少分：

- Incremental 高优先保留容量；
- New Source Backfill；
- Historical Backfill；
- Repair；
- Reconcile；
- Low-priority Enrichment。

使用 Weighted Fair Queue / Deficit Round Robin，并按 tenant/source/domain 分层，避免几十万页的大站占满全部 Worker。

### 8.3 Global Admission

```text
global_http_slots
global_browser_slots
per_runtime_browser_slots
per_source_concurrency
per_registrable_domain_concurrency
per_host_rps
per_source_daily_request_budget
per_run_page_budget
per_run_byte_budget
per_run_wall_clock_budget
repair_budget
focused_discovery_budget
```

Admission 成功后才创建昂贵 Runtime 请求。

## 9. Fetch Plane

### 9.1 HTTP Fast Lane

优先使用 HTTP：

- GET/HEAD；
- ETag / If-None-Match；
- Last-Modified / If-Modified-Since；
- Content-Type / Content-Length gate；
- gzip/br；
- redirect 每跳 scope + SSRF 复验；
- status/header/timing 全部入证据。

进入 Browser 的条件必须可解释：

- HTML 明显空壳；
- 正文只有 JS 后出现；
- 需要受控滚动/等待；
- HTTP candidate 质量门禁失败且 Browser Repair 有预算。

### 9.2 Browser Slow Lane

Crawl4AI Self-Hosted Runtime 只处理高成本慢路径。Source Profile 不直接传给 Crawl4AI，而由 Runtime Adapter 编译成固定 schema。

## 10. Crawl4AI Runtime Service Plane

### 10.1 Runtime Registry

```text
runtime_instance
- runtime_id
- endpoint
- software_release
- image_digest
- result_schema_release
- config_schema_release
- capabilities_hash
- queue_config_hash
- security_profile_release
- browser_generation
- state: ACTIVE/DRAINING/QUARANTINED/UNROUTABLE
- capacity_score
- last_probe_at
```

加入流量前执行 Contract Probe：

- auth/security profile；
- WorkQueue started；
- queue maxsize/workers/per_principal；
- 429/503/Retry-After；
- async task status semantics；
- result schema/cardinality；
- artifact API/TTL；
- forbidden power fields；
- internal URL/redirect 拒绝；
- monitor admin action 权限；
- Browser Profile 行为。

不匹配 pinned contract 就 `UNROUTABLE`。

### 10.2 Runtime Queue 只做局部保险丝

Crawl4AI WorkQueue 本质是单进程 `asyncio.Queue`：

```text
maxsize        -> 等待队列上限，满时 503
workers        -> 后台 worker 数
per_principal  -> queued + running 在途上限，超限 429
```

因此：

- PostgreSQL + Redis Streams 才是 durable task；
- Runtime Queue 丢失后靠 lease/reconciliation 恢复；
- Runtime Redis status/result 不是长期 Task Truth；
- `maxsize=0`、`per_principal=0`、`wall_clock=0` 的 unbounded 语义禁止普通用户产生；
- WorkQueue 未 started 时 Runtime readiness 失败，不能允许回退到无界 BackgroundTasks 进入生产流量。

### 10.3 双层 Backpressure

```text
Platform Global Admission
        +
Crawl4AI Local Admission
```

平台控制跨实例公平和硬预算；Runtime queue、process page semaphore、MemoryAdaptiveDispatcher、RateLimiter、browser memory pressure 只负责单实例自保护。

错误分类：

```text
429 Runtime -> RUNTIME_PRINCIPAL_QUOTA
503 Runtime -> RUNTIME_QUEUE_FULL
504 Runtime -> RUNTIME_WALL_CLOCK
pod lost    -> RUNTIME_LOST
origin 429  -> ORIGIN_RATE_LIMIT
origin 503  -> ORIGIN_UNAVAILABLE
```

### 10.4 Runtime Attempt 与观察态

Runtime 异步 Job 的可持久查询状态主要是粗粒度：

```text
PROCESSING -> COMPLETED
           -> FAILED
```

平台不能假装 Runtime 提供了精确 queued/running 状态。建议 Attempt 保存：

```text
attempt
- id
- task_id
- attempt_no
- fencing_token
- fetch_mode
- runtime_id
- runtime_task_id
- runtime_observed_status
- runtime_state_source: SUBMIT/POLL/MONITOR/WEBHOOK/RECONCILER
- runtime_state_observed_at
- state
- error_class
- result_cardinality
- materialization_status
- started_at
- ended_at
- raw_artifact_id
```

推荐状态机：

```text
LEASED
 -> ADMITTED
 -> RUNTIME_SUBMITTING
 -> RUNTIME_ACCEPTED
 -> RUNTIME_OBSERVED_PROCESSING
 -> RUNTIME_TERMINAL
 -> MATERIALIZING_RESULT
 -> PROMOTING_ARTIFACTS
 -> MATERIALIZED
 -> RAW_PERSISTED
 -> SUCCEEDED
```

UI 可以显示推断的 `RUNTIME_QUEUED/RUNTIME_RUNNING`，但必须标明是观察态。`RUNTIME_TERMINAL` 不等于平台 `SUCCEEDED`。

### 10.5 Webhook Inbox + Reconciler

```text
runtime_event_inbox
- runtime_id
- runtime_task_id
- attempt_id
- event_id/payload_hash
- status
- received_at
- processed_at
```

Webhook 快速路径必须幂等。Reconciler 主动处理：

- 长期无 webhook；
- completed 但未 materialize；
- Runtime 重启后的 orphan；
- lease 即将超时；
- late/duplicate webhook。

### 10.6 Runtime Result Materialization

异步 Job 完成结果可能作为完整 JSON 临时保存在 Runtime Redis。平台不得把 Runtime Redis 作为大型结果总线或长期结果库。

Runtime Gateway 限制：

```text
max_urls_per_runtime_job
max_expected_result_bytes
max_input_body_bytes
max_runtime_wall_clock
max_artifact_bytes
```

高完整性 Browser Repair 默认 1 URL/Job；批量使用受控 micro-batch，并为每个预期结果建立：

```text
runtime_task_item
- runtime_task_id
- attempt_id
- input_url_identity_id
- expected_correlation_key
- result_status
- result_sha256
- materialized_at
```

Runtime terminal 后立即逐条物化，检测 duplicate/missing/extra/cardinality/schema mismatch，禁止按列表下标认领结果。

### 10.7 Browser Pool 与配置基数控制

可以利用 permanent/hot/cold pool，但它是性能缓存。

BrowserConfig 的 signature 应来自少量稳定 Browser Profile Class，而不是 1000 个 Source 各自一份独特配置。原因：

- BrowserConfig signature 过多会制造大量 cold browser；
- 冷启动/关闭增加 Chromium 内存和 CPU 抖动；
- pool reuse 下降；
- 浏览器池获取路径可能受全局锁和慢 start/close 形成 Head-of-Line Blocking。

隔离 key 至少包含：

```text
runtime_profile_release
network_policy_class
credential_scope
session_isolation_class
proxy_policy_class
browser_feature_class
```

公开博客默认 `public-anonymous`，无持久 cookie/profile。

生命周期分两层：

1. **Context Generation**：页面数、错误、污染风险、session 状态触发回收；
2. **Browser Process Generation**：PID age、累计 page、RSS、FD、renderer crash、错误率触发 drain + replace。

### 10.8 Runtime 监控与业务监控分离

Runtime Monitor/WebSocket/Prometheus 用于：

- queue saturation；
- active request；
- cgroup/process memory pressure；
- browser reuse/churn；
- browser acquire latency；
- janitor；
- restart/drain；
- artifact backlog。

Monitor 的短窗口数据主要用于运维，Browser `memory_mb` 等估算值不能作为容量真相。Autoscaling 应优先使用 cgroup memory/PSI/OOM、真实 RSS、queue age、slot utilization、pool reuse/churn、artifact headroom。

历史覆盖、PASS Markdown 数、Known Gap 必须从平台 Truth Store 计算。

### 10.9 运维优先 Drain/Replace

底层 Runtime 的 cleanup/kill/restart_browser 只作为 emergency/diagnostic action，不作为平台零中断运维原语。

生产动作：

```text
ACTIVE
 -> DRAINING
 -> Registry 禁止新 Admission
 -> active attempts 收敛到 0
 -> replace Runtime Pod / Browser Generation
 -> readiness
 -> contract probe
 -> ACTIVE
```

底层 kill/cleanup 只有在平台确认无绑定 active attempt 或执行受审 emergency 操作时才能调用。普通 Web Operator 不直接持有 Runtime admin token。

- cloud metadata；

## 21. 取消、暂停、Drain 与恢复

### 21.1 Stop 语义

1. Run -> `CANCEL_REQUESTED`；
2. Scheduler 停止新 Admission；
3. 未 lease task 回收/取消；
4. 已提交 Runtime 的 Attempt 请求 cooperative cancel 或进入 drain；
5. 等待 task/page/context/resource token 收敛；
6. 超时执行受控 replace/kill，并明确标记 affected Attempt；
7. Reconciler 处理迟到 webhook/result；
8. active=0 且资源令牌清零后 -> `STOPPED`。

### 21.2 Crash Recovery

- Task lease 过期可重新获取；
- fencing token 防止旧 Worker 迟到写覆盖新 Attempt；
- Runtime Pod 重启不假设 Job 恢复；
- orphan attempt 由 Reconciler 分类；
- 已存在 Raw Artifact 时优先重放 Extraction，不重复访问原站。

## 28. 最终架构结论

平台应把 **发现完整性、长期状态、可恢复性、最终内容** 放在自己的控制面，把 Crawl4AI 等第三方组件定位为可替换执行 Runtime：

```text
Coverage Truth        -> PostgreSQL
Durable Task          -> PostgreSQL + Redis Streams
URL Frontier          -> PostgreSQL
Raw/IR/Markdown       -> S3/MinIO
Runtime Queue         -> Crawl4AI asyncio.Queue（局部临时）
Runtime Status        -> Crawl4AI Redis（粗粒度、TTL 临时）
Runtime Result        -> 短期交接，立即逐条物化
Browser Pool          -> Crawl4AI（性能缓存，控制 Profile 基数）
Runtime Artifact      -> Crawl4AI（短 TTL，必须晋升）
Final Markdown        -> Canonical IR deterministic projection
Search Index          -> 可重建 Projection
```

该边界既利用 Crawl4AI Self-Hosting 的异步队列、浏览器池、监控和安全加固，又不会把 1000+ 站点的历史覆盖、增量正确性、结果耐久性、浏览器生命周期和知识库长期可重放性绑定到单个 Runtime 的进程内状态。
