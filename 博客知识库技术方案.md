# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站与公开 Newsletter** 的长期知识库采集平台，并能平滑扩展到数千站点、百万级文章。

系统必须同时满足：

1. **全历史尽量抓全**：不只“能抓页面”，还要知道文章从何发现、哪些 Provider 已穷尽、还有哪些 Known Gap；
2. **持续增量同步**：发现新文章、正文修改、URL 迁移、删除和重发布；
3. **稳定产出 Markdown**：HTML、动态页面、PDF 等统一转换为可追溯 Canonical IR，再投影为 Markdown；
4. **新增站点低成本**：以 Site Family、Source Profile、Discovery Recipe、Extraction Recipe 复用能力，不为每个站长期维护一套爬虫；
5. **Web 可管理**：站点接入、Probe、配置、调度、回放、失败处理、Coverage、质量、成本、版本、导出均可操作；
6. **可审计、可重建**：任意 Markdown 都可以定位到 URL、原始快照、抽取器、配置版本、正文版本和运行记录；
7. **增量链路幂等可恢复**：任务可重试、可续跑、不重复污染数据；
8. **AI 友好但事实层独立**：全文、向量、摘要、GraphRAG 都是可重建 Projection，不改变 Canonical 内容；
9. **抓取运行时可替换**：Crawl4AI、Playwright、httpx 是 Adapter，不是平台业务真相；
10. **成本可治理**：HTTP 优先、Browser 后置，LLM/GraphRAG 默认不进入关键抓取路径。

### 1.1 核心 SLO

平台核心指标不是 HTTP 200 比例，而是：

- **Coverage**：历史 URL 覆盖率、Provider exhaustion evidence、Known Gap；
- **Freshness**：新文章发布到进入 PASS Canonical Markdown 的延迟；
- **Quality**：正文完整率、噪声率、结构正确率、Quarantine 比例；
- **Extraction Correctness**：selector hit/completeness 与候选一致性；
- **Reliability**：Task 成功率、Retry/DLQ、队列年龄、Worker 恢复率；
- **Cost**：每 Source、每 1000 个 PASS 文档、每 accepted version 的网络/CPU/Browser/存储/LLM 成本；
- **Traceability**：结果可回溯到不可变事实和版本化执行环境；
- **Retrieval Quality**：BM25/Vector/Rerank/可选 Graph 增强的 Recall、nDCG、回答引用命中率与查询成本。

### 1.2 非目标

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不使用 LLM 主观判断替代 Coverage 证明；
- 不把 Redis、Browser session、Crawler cache/frontier 当业务真相；
- 不把 LLM 摘要或改写作为 Canonical Markdown；
- 不把 BM25/Pruning/Fit Markdown 当 Canonical 正文；
- 不因为 URL 曾经抓过就永久停止复检；
- 不把 crawler success、HTTP 200、DOM 长度直接等同于“正文正确”或“历史抓全”；
- 不允许 Source Family Template 更新后原地改变所有生产 Source；
- 不默认对全部文章做 GraphRAG 建图。

## 2. 核心设计原则

1. **Coverage First**：先证明“文章有哪些”，再批量抓正文；
2. **Authoritative First**：CMS/API、Sitemap、RSS/Atom、Archive 优先，动态列表与受限 Deep Crawl 补洞；
3. **Discovery Before Fetch**：URL 发现、规范化、Scope、分类、去重独立于正文抓取；
4. **Discover Cheap, Fetch Expensive**：低成本发现手段先跑，Browser 后置；
5. **HTTP First, Browser Last**：静态 HTTP 优先，确定性 Browser Recipe 兜底；
6. **Deterministic Before Agentic**：没有 LLM 也必须能完成 Backfill 和 Incremental；
7. **Snapshot First**：先保存不可变抓取事实，再做 Extract/IR/Markdown；
8. **IR First, Markdown as Projection**：Canonical IR 是正文结构事实，Markdown 可重建；
9. **Canonical Before Fit**：AI Fit/Chunk/Embedding/Graph 都是派生投影；
10. **Quality Is First-Class**：传输成功和正文合格是两套状态；
11. **Cost Is First-Class**：高成本 Browser/LLM 必须可归因、可预算；
12. **Recipe, Not Site Code**：分页、滚动、点击、selector 通过版本化语义 Recipe 表达；
13. **Stable Identity**：Source、URL、Artifact、Document、Version 使用稳定 ID；
14. **Idempotent + Recoverable**：Task 有幂等键、lease、fencing token、checkpoint、Retry、DLQ；
15. **Fair by Default**：大站历史回填不能饿死增量任务与小站；
16. **Agreement Before Trust**：selector 命中不是正确证明，关键站点通过 Generic/Deterministic Candidate Agreement 防静默抽错；
17. **Release Everything That Changes Results**：Profile、Recipe、Compiler、Runtime、Extractor、Schema、Renderer、Filter 都版本化；
18. **Projection Is Rebuildable**：Markdown、全文、向量、Graph 可从 Canonical Version 重建；
19. **No Silent Fallback for Coverage**：动态能力未真正执行时标记 Known Gap/DEGRADED，不能假装抓全；
20. **Graph Is Enhancement, Not Truth**：GraphRAG 只做可选、Schema-guided、Provenance-aware、Quality-gated、Budgeted Projection；
21. **Graph Is Query-Routed**：关系增强只对有多跳/关系价值的查询启用，不能把所有问题都强制走图。

## 4. 技术选型

### 4.1 控制面

- **FastAPI + Pydantic**：REST API、Command、Schema 校验；
- **PostgreSQL**：Source、Release、Run、Task、Coverage、URL、Artifact、Document、Version、Quality、Cost、Audit、Outbox；
- **Redis Streams**：任务运输、consumer group、backpressure；
- **Redis Lua token bucket/semaphore**：跨 Worker 域名限流与并发控制；
- **React/Next.js + TypeScript**：Web 管理台；
- **Prometheus + Grafana + OpenTelemetry**：Metric/Log/Trace；
- **S3/MinIO**：Raw HTML、DOM/MHTML、IR、附件、诊断文件、导出物；
- **OpenSearch**：全文/BM25；
- **pgvector**：首期向量检索，通过 Adapter 可替换；
- **Neo4j 或兼容图引擎**：仅在 Graph Projection 开启时使用；
- **neo4j-graphrag-python / Neo4j Driver**：Graph Projection/Retrieval 的优先生产 Adapter；LangChain 可作为可替换集成层，不进入领域模型；
- **Docker Compose**：开发与小规模验证；
- **Kubernetes**：生产 Worker Pool 横向扩展。

Neo4j 2026.01+ 如使用带 `filterable_properties` 的 vector index，可在图专题检索规模扩大后利用 in-index filtering；该能力属于实现优化，不改变平台统一的 metadata filter 语义。

### 4.2 抓取与解析

- **httpx/aiohttp**：HTTP、Sitemap、Feed、CMS API、Conditional GET、附件；
- **Crawl4AI**：动态页面、批量抓取、Virtual Scroll、CSS/XPath/Regex Extraction 等，通过 Adapter 使用；
- **Playwright**：复杂但确定性的交互 Recipe；
- **lxml + trafilatura/readability 类算法**：Generic Extractor；
- **JSON-LD/OpenGraph/Microdata**：结构化元数据候选；
- **PyMuPDF/pdftotext**：PDF；扫描件才进入 OCR。

### 4.3 Crawler 边界

```text
平台负责：
Source/Release / Task / Retry / DLQ / Coverage / Fairness /
Global Rate Limit / Budget / Checkpoint / Quality / Audit /
Projection Semantics / Version / Trace

Crawler 负责：
单次请求与导航 / 页面动作 / DOM / 链接 / 媒体 /
浏览器资源管理 / 局部 batch/stream / extractor 执行
```

生产锁定经过 Golden Corpus 验证的 Crawl4AI、Playwright、Chromium 与镜像 digest；升级需经过 Replay、Benchmark、Canary 和 Approval。

## 6. 站点接入与自动 Probe

新增网站只要求输入：

```text
name + base_url + 可选标签/抓取策略约束
```

系统进入 `PROBING`，自动探测：

1. robots.txt；
2. sitemap.xml / sitemap index / robots 中 sitemap 声明；
3. RSS/Atom；
4. 常见 CMS API（WordPress REST、Ghost、公开 JSON endpoint 等）；
5. 首页、archive、category、tag、pagination；
6. JSON-LD/OpenGraph；
7. 静态 HTTP 是否可得到正文；
8. 是否必须 Browser；
9. Site Family 指纹；
10. URL pattern、canonical、分页规则和文章样本。

Probe 输出 Candidate Source Profile，由 Web 管理员查看建议后激活。

### 6.1 Source Profile 示例

```yaml
source:
  base_url: https://example.com
  scope:
    allowed_hosts: [example.com]
    include:
      - /blog/**
    exclude:
      - /tag/**
      - /author/**

discovery:
  providers:
    - sitemap
    - rss
    - archive
  deep_crawl:
    enabled: false

fetch:
  mode: http_first
  browser_fallback: true
  concurrency_per_host: 2

extraction:
  generic: true
  deterministic_recipe: article-v3

incremental:
  class: WARM
  verify_known_urls: true
```

Profile 是业务语义配置，Adapter 再编译为 Crawl4AI/Playwright/httpx 参数。

## 7. 历史 URL Discovery 与 Coverage

“抓全历史”必须先建立 URL 集合，再抓正文。

### 7.1 Provider 优先级

推荐按成本与权威性：

```text
CMS/API
 -> Sitemap
 -> RSS/Atom
 -> Archive/Category/Tag
 -> Static Pagination
 -> Dynamic Listing
 -> Bounded Deep Crawl
```

每个 Provider 产生 Observation 和 Coverage Evidence。

### 7.2 Sitemap

支持：

- sitemap index 递归；
- gzip；
- 多 sitemap；
- lastmod；
- 大站 checkpoint；
- URL Scope 过滤；
- Sitemap 与已知 URL 差异比较。

### 7.3 RSS/Atom

RSS 不用于证明完整历史，但非常适合：

- 快速增量；
- 获取 publish/update 时间；
- 发现 canonical URL；
- 辅助判断文章类型。

### 7.4 Archive/分页

支持语义 Recipe：

```text
OPEN start_url
EXTRACT article_links
LOOP:
  FIND next_page
  IF absent -> EXHAUSTED
  OPEN next_page
  EXTRACT article_links
  STOP_IF max_pages / duplicate_page_signature / no_new_urls
```

### 7.5 Infinite Scroll / Load More / Virtual Scroll

Browser Discovery Recipe 表达：

- scroll_to_bottom；
- wait_for_network_idle；
- click_load_more；
- virtual_scroll container；
- stop when N rounds no new URL；
- 最大动作轮数、最大运行时间、最大 DOM/URL 数。

若运行时不支持某语义动作，Release Compile 失败或 Run 标记 DEGRADED，不能静默变成一次普通抓取。

### 7.6 Coverage Evidence

```text
coverage_evidence
- evidence_id
- source_id
- provider_type
- run_id
- range_start/range_end nullable
- cursor_start/cursor_end nullable
- discovered_count
- new_count
- stop_reason
- exhausted: bool
- gap_reason nullable
- created_at
```

Coverage 页面展示：

- Provider 是否成功；
- 是否真正穷尽；
- URL 数；
- 新增数；
- 时间跨度；
- Known Gap；
- 不同 Provider 之间的交并差异。

## 8. URL 规范化、Scope 与去重

### 8.1 规范化

规则包括：

- host 小写；
- 去 fragment；
- 默认端口；
- tracking query 去除；
- query 参数排序；
- trailing slash 策略；
- canonical link 作为候选而不是盲信；
- redirect chain 记录。

### 8.2 多层去重

1. URL normalization；
2. canonical/redirect identity；
3. artifact sha256；
4. canonical content semantic hash；
5. 可选近似正文指纹用于镜像/转载识别。

标题、slug 或页面展示文本不能作为跨阶段唯一主键。

## 9. Fetch：HTTP First，Browser Last

### 9.1 HTTP Content Worker

默认使用 httpx/aiohttp：

- gzip/br；
- redirect；
- timeout；
- response size limit；
- ETag/If-None-Match；
- Last-Modified/If-Modified-Since；
- Content-Type；
- Charset；
- SSL/错误分类；
- Raw Snapshot 入对象存储。

### 9.2 Browser Fallback 判定

满足以下条件之一才进入 Browser：

- HTML 只有 shell；
- 正文依赖 JS；
- 确定性点击/滚动后出现正文；
- 关键字段质量失败且 Browser Golden Sample 证明可恢复；
- Source Profile 明确指定。

Browser 与 HTTP 使用独立 Queue/Worker Pool，避免 Chromium 资源耗尽拖垮全局。

### 9.3 Browser Session

Session 只用于执行优化，例如同一站分页、cookie、资源复用。Session 丢失后 Task 必须能重新执行，因此业务 checkpoint 不放在 session 内。

## 10. 正文抽取：Generic + Deterministic 双轨

### 10.1 Generic Extractor

默认结合：

- DOM text density；
- link density；
- heading/paragraph structure；
- article/main 标签；
- trafilatura/readability 类算法；
- JSON-LD articleBody/headline/datePublished/author；
- OpenGraph 元数据。

### 10.2 Deterministic Recipe

对高价值或特殊站点配置：

```yaml
article:
  title: css:h1.article-title
  published_at: css:time::attr(datetime)
  content: css:article.post-content
  remove:
    - css:.newsletter-signup
    - css:.related-posts
    - css:.share-buttons
```

支持 CSS/XPath/Regex，但 Recipe 表达的是语义字段，不直接暴露任意浏览器脚本。

### 10.3 Candidate Agreement

确定性 selector 最大风险是“仍然命中，但命中错误区域”。因此：

- 新 Release 在 Golden Corpus 上同时运行 Generic/Deterministic；
- 对 ACTIVE Source 做小比例 shadow extraction；
- 比较标题、正文长度、文本相似度、heading 分布、link/code/table 比例；
- Agreement 降低触发 Drift Alert；
- 大幅偏离时自动进入 QUARANTINE 或回滚 Recipe。

## 11. Canonical IR 与 Markdown

### 11.1 Canonical IR

不要 HTML 直接字符串替换成 Markdown。先生成结构化 IR：

```json
{
  "document_id": "...",
  "version_id": "...",
  "title": "...",
  "author": ["..."],
  "published_at": "...",
  "updated_at": "...",
  "canonical_url": "...",
  "blocks": [
    {"type":"heading","level":2,"text":"..."},
    {"type":"paragraph","text":"..."},
    {"type":"code","language":"python","text":"..."},
    {"type":"list","items":["..."]},
    {"type":"table","rows":[...]},
    {"type":"image","src":"...","alt":"..."}
  ]
}
```

### 11.2 Markdown Renderer

统一规则：

- heading 层级稳定；
- fenced code 保留语言；
- list/table/blockquote 正确；
- 图片保留 alt + 原 URL 或归档 Asset URL；
- 相对链接转绝对链接；
- 移除菜单、推荐、广告、cookie、订阅弹层；
- Front Matter 保存来源元数据；
- Renderer 版本化。

示例：

```yaml
---
document_id: ...
version_id: ...
source: Example Blog
url: https://example.com/a
published_at: 2026-01-01T10:00:00Z
fetched_at: 2026-01-02T08:00:00Z
content_hash: ...
---
```

Markdown 是知识库主要消费格式，但 Canonical IR 保证未来可以无损重渲染。

## 12. 内容质量 Gate

Quality Gate 不依赖单一长度阈值，而综合：

- 标题存在；
- 正文最小有效长度；
- 正文/链接比；
- boilerplate 特征；
- 代码块、表格、列表结构保留率；
- 页面语言一致性；
- Generic/Deterministic agreement；
- 与历史版本长度/结构异常偏移；
- 登录墙/错误页/WAF/CAPTCHA 指纹；
- 重复文档比例。

状态：

```text
PASS        可进入 Canonical 与下游 Projection
WARN        可用但存在低风险异常
QUARANTINE  等待人工或自动回放
REJECT      明确非文章/错误内容
```

Web 管理端必须支持查看 Raw、DOM、候选正文、Canonical IR、Markdown 的并排差异。

## 13. 增量同步

### 13.1 分层调度

Source 分为：

- HOT：高频更新，RSS/API/Sitemap 高频；
- WARM：常规技术博客；
- COLD：长期不更新但保留低频验证。

调度不要简单 `for source in sources`，而用 Weighted Fair Scheduler：

```text
priority = urgency + freshness_class + retry_age + source_weight - estimated_cost
```

独立队列：

- discovery_incremental；
- fetch_http；
- fetch_browser；
- verify_known；
- extract；
- project；
- graph_project（可选）。

### 13.2 新文章发现

增量优先：

```text
RSS/API -> Sitemap lastmod/diff -> Archive first pages -> bounded dynamic listing
```

### 13.3 已知 URL 复检

使用：

- ETag；
- Last-Modified；
- RSS updated；
- sitemap lastmod；
- 周期性抽样强制 re-fetch。

304 仍写 Fetch Attempt，但不创建新正文版本。

### 13.4 正文版本判定

流程：

```text
fetch artifact
 -> extract canonical IR
 -> normalize semantic content
 -> semantic_hash
 -> compare current version
```

- hash 相同：只更新 last_checked；
- 正文变化：新建 Document Version；
- 仅元数据变化：按字段策略决定 metadata-only version 或更新可变元数据；
- 新版本 PASS 后原子切换 `current_version_id`。

### 13.5 删除与迁移

不能看到一次 404 就删除：

```text
ACTIVE
 -> 404/410 or provider missing
 -> SUSPECT_MISSING
 -> 多次复检 + sitemap/archive evidence
 -> REMOVED
```

301/308：记录 redirect relationship，判断是否为同一 Document 的 URL 迁移。

## 14. 任务幂等、恢复与队列语义

### 14.1 幂等键

示例：

```text
DISCOVER:{source_release}:{provider}:{cursor/range}
FETCH:{url_id}:{fetch_policy_version}:{validator_state}
EXTRACT:{artifact_id}:{extractor_release}

```

### 14.2 Lease + Fencing

Worker 领取 Task 获得 lease 与 fencing token。长任务心跳续租；旧 Worker 在 lease 失效后即使恢复，也不能覆盖新 Worker 已提交的结果。

### 14.3 Retry / DLQ

按错误类型分类：

- transient network；
- rate limit；
- browser crash；
- extraction quality；
- permanent 404/410；
- access denied；
- semantic recipe unsupported。

退避策略、最大次数和 DLQ 原因分开配置。Web 端支持单任务、单 Source、按错误类型 replay。

## 15. 全文、向量与 RAG 投影

### 15.1 Chunk 不是事实层

Chunk 由 `document_version_id + chunker_release` 生成，必须可重建。

建议按结构切分：

1. heading section；
2. paragraph group；
3. code block 尽量不拆；
4. 超长 section 再递归切分；
5. 每 chunk 保留 source/document/version/heading path。

### 15.2 默认检索链

```text
Query
 -> metadata filter
 -> OpenSearch BM25 recall
 -> pgvector semantic recall
 -> RRF/weighted fusion
 -> reranker
 -> dedup/diversity
 -> evidence context
 -> RAG/搜索结果
```

元数据过滤包括：source、domain、时间、语言、标签、内容类型、版本状态。

这条主链必须独立于 GraphRAG 工作。

## 16. GraphRAG：可选关系增强层

### 16.1 定位

GraphRAG **不进入**：

- URL Discovery；
- Fetch；
- Canonical IR；
- Canonical Markdown；
- 默认增量关键路径。

它与全文、向量一样是 `Document Version` 之上的可重建 Projection。

```text
Canonical Version
     |
     +-> BM25 Projection
     +-> Vector Projection
     +-> Graph Projection (optional)
```

### 16.2 为什么默认不开全量 Graph

对 1000+ 博客，全历史文章可能达到几十万到百万级。Graph Extraction 通常要求 LLM 对 Chunk 做实体与关系抽取：

- 成本显著高于抓取与 Embedding；
- 小模型容易出现实体碎裂、关系不一致和大量孤岛；
- 强模型成本又更高；
- 通用自由 Schema 容易导致关系类型膨胀；
- 图三元组未必比原文文本更能回答问题。

因此 Source 默认：

```text
graph_enrichment.enabled = false
```

仅对明确存在关系推理价值的 Collection/Topic 开启。

### 16.3 Schema-guided Graph Extraction

技术博客推荐受控实体：

```text
Technology | Library | Product | Company | Person | Paper |
Standard | Version | Vulnerability | Concept
```

受控关系：

```text
USES | DEPENDS_ON | IMPLEMENTS | REPLACES | COMPARES_WITH |
CREATED_BY | AFFECTS | RELEASED_AS | PART_OF | SUPPORTS |
INTEGRATES_WITH | MENTIONS
```

Schema、Prompt、Model、Normalizer 都版本化。未知关系先作为 Candidate/Quarantine，不允许直接扩张 ACTIVE Schema。

### 16.4 Entity Identity 与 Resolution

Graph 质量首先取决于稳定实体身份。不要把 LLM 输出的展示名直接当全局主键。

```text
graph_entity
- entity_id
- entity_type
- canonical_name
- normalized_key
- external_ids JSONB
- status

graph_entity_alias
- entity_alias_id
- entity_id
- alias
- normalized_alias
- source
- confidence
```

解析顺序：

```text
stable external id
 -> exact canonical
 -> exact alias
 -> normalized match
 -> fuzzy candidate
 -> type/context disambiguation
 -> resolved / unresolved
```

Fuzzy/Lucene edit-distance 只用于候选召回，不能直接决定实体 `MERGE`；短技术词、包名、版本号必须使用更严格规则。所有 merge/split 要可审计、可回放。

### 16.5 Graph Quality Gate

Graph Projection 必须先成为 Candidate，不能“构图任务成功”就直接进入在线检索。

核心指标：

- schema violation rate；
- provenance coverage；
- unsupported edge rate；
- orphan entity ratio；
- isolated component ratio；
- relation type cardinality；
- unresolved/ambiguous entity ratio；
- cross-chunk entity consistency；
- duplicate fact ratio；
- projection failure rate。

最低要求：所有 Active edge 能回溯原文；Schema/Model/Normalizer 升级先在 Graph Golden Corpus Replay，通过阈值后再原子激活新 Projection。

### 16.6 Graph Provenance 与增量

```text
graph_projection
- graph_projection_id
- document_version_id
- graph_schema_version
- extractor_release
- model_release
- normalizer_release
- status: CANDIDATE | ACTIVE | RETIRED | REJECTED
- entity_count
- edge_count
- token_cost
- quality_score

graph_fact
- graph_fact_id
- graph_projection_id
- subject_entity_id
- predicate
- object_entity_id
- source_chunk_id
- confidence
- valid_from
- valid_to
```

V5 成为当前正文版本后：

```text
if graph policy enabled:
  enqueue GRAPH(V5)
  build candidate projection
  entity resolution
  graph quality gate
  atomically activate V5 graph projection
  exclude V4 graph projection from active retrieval
```

所有边必须能回溯到 `source_chunk_id -> document_version -> artifact`，不能只在 Neo4j 中裸 `MERGE` 后失去来源。

多个文档共同支持同一关系时维护 provenance/support，不因单个 Document Version 失效就物理删除全局关系；只有最后一个有效 support 消失时才退出 active evidence。

### 16.7 Query Router 与检索方式

不默认使用“自然语言直接生成自由 Cypher”，也不让每个问题都强制走 Graph。

默认：

```text
Query
 -> BM25 + Vector + Rerank
 -> Top textual evidence
 -> Query Router
      OFF -> textual evidence
      ON  -> identify high-value entities from query/top chunks
          -> exact/alias/fuzzy candidate lookup
          -> entity resolution
          -> bounded graph neighborhood expansion
          -> graph evidence scoring
 -> Evidence Budgeter
 -> merge with textual evidence
```

Graph 更适合关系、多跳、依赖、替代、兼容、跨文档聚合问题；单文档事实、代码片段和普通语义相似问题默认不启用 Graph。

如果提供 NL-to-Graph：

- 注入实时裁剪 Schema；
- LLM 只生成受限 AST/DSL；
- 服务端编译参数化 Cypher；
- read-only；
- 强制 allowlist、LIMIT、max hop、timeout；
- 失败回退到确定性实体邻域检索。

### 16.8 Graph Evidence Renderer 与 Evidence Budgeter

图证据必须限制：

- 每实体 Top-N 邻居；
- 最大 hop；
- 最大 graph token；
- 优先多来源支持、高 confidence、新鲜关系；
- 去除与 Top-K 原文重复的三元组；
- relation allowlist；
- Graph context 占总上下文比例上限。

不要把 Neo4j 节点/边原样 dump 给 LLM。输出紧凑 Evidence Unit：

```text
Fact: Library A DEPENDS_ON Library B
Evidence: document_version=V5, chunk=C17
Support: 3 active documents
Confidence: 0.91
Excerpt: <短原文证据>
```

原文短证据能补足三元组缺失的条件、范围和上下文。

### 16.9 Graph Cost Preflight 与 Circuit Breaker

大规模 Graph Backfill 前先对代表性 Source/Topic 抽样 100～1000 个 Document Version，统计：

- tokens/chunk；
- entities/edges per chunk；
- accepted facts per chunk；
- orphan/unsupported edge；
- cost/1000 docs；
- cost/1000 accepted facts；
- projected full backfill cost；
- projected monthly incremental cost。

只有质量 Gate 与预算同时通过，Graph Policy 才从 `PILOT` 升级到 `SELECTIVE/ON`。

Graph Worker 使用独立：

- daily/monthly hard cap；
- per-run/per-source cap；
- max chunks/tokens per document；
- provider price change re-estimation；
- budget circuit breaker。

Graph 暂停永远不能影响 Discovery、Fetch、Canonical Markdown、Search/Vector。

### 16.10 Graph 启用条件

通过离线评测对比：

- BM25；
- Vector；
- BM25 + Vector；
- + Rerank；
- + Graph。

比较 Recall@K、nDCG/MRR、回答正确率、引用命中率、p95 latency、token/query cost、graph activation rate、graph context utilization。只有 Graph 在目标问题集存在稳定净收益，且构图质量和成本预算同时达标时才扩大覆盖。

## 19. 调度、公平性与容量控制

### 19.1 Global Admission

每次实际网络/Browser 请求前统一检查：

- global concurrency；
- per-domain concurrency；
- request rate；
- Browser slots；
- Source budget；
- robots/policy；
- maintenance window。

### 19.2 Weighted Fair Scheduling

调度维度：

- Incremental 高于 Backfill；
- HOT Freshness 高优先；
- 长时间等待任务 aging；
- 单 Source 有最大并发占比；
- Browser 队列独立公平；
- Graph 队列永远不能抢占抓取关键资源。

### 19.3 反压

当 Extract/Storage/Search 延迟升高：

- 降低新 Fetch admission；
- Discovery 仍可低成本进行，但限制后续正文任务生成速率；
- Browser 首先降速；
- Graph/LLM projection 可完全暂停。

## 21. 安全与合规

### 21.1 SSRF

每个网络跳转重新校验：

- scheme 仅 http/https；
- DNS 解析；
- 禁止 loopback、link-local、private CIDR、metadata endpoint；
- redirect 后重验；
- Browser iframe/navigation/request 同样执行 egress policy；
- proxy 目标不能绕过校验。

### 21.2 Web 管理

- RBAC：viewer/operator/admin；
- Secret 不回显；
- Recipe 不接受任意 JS/evaluate；
- 高风险 Release 激活需要 Approval；
- Audit Log 记录配置与人工操作；
- 导出权限独立控制。

Graph/NL-to-Graph 额外要求：只读数据库账号、查询 allowlist、参数化 Cypher、强制 LIMIT/hop/timeout。

### 21.3 来源策略

记录每 Source：

- robots policy；
- crawl delay；
- 登录需求；
- 内容授权/许可证备注；
- 是否允许资产下载；
- 是否允许公开导出。

抓取系统和版权授权是两个问题，平台必须保留来源与许可元数据，不能因为技术上可访问就假设可再分发。

- 多文档共同支持；

- selector hit rate；
- 正文长度分布；
- heading 数；
- code/table/list 比例；
- candidate agreement；
- QUARANTINE；

- orphan/isolation 激增；
- relation cardinality 膨胀；
- unresolved/ambiguous entity 激增；
- provenance coverage 下降；
- graph-on 净收益下降；

### 24.3 Release 流程

```text

 -> compile
 -> static validation
 -> Golden replay
 -> sample live test
 -> CANDIDATE
 -> CANARY sources
 -> metrics compare
 -> approval
 -> ACTIVE
```

- Coverage Evidence；
- Drift/Golden Corpus；
- OpenSearch + pgvector。

### Phase 3：生产强化

- 删除/迁移判断；
- 成本治理；
- Canary/自动回滚；
- 多 Worker Pool/HPA；
- 更细粒度权限与 Audit；
- 检索评测体系；
- Graph PILOT/Cost Preflight；
- Schema-guided Graph + Entity Resolution + Quality Gate；
- Query Router + Evidence Budgeter；
- 按价值选择性启用 Graph Projection；
- 生产 Graph Adapter 优先使用 Neo4j Driver/第一方 neo4j-graphrag-python，框架保持可替换。

## 27. 验收标准

### 历史抓取

- 每 Source 能展示 URL 从哪个 Provider 发现；
- Provider 有明确 stop reason/exhaustion evidence；
- Known Gap 可见；
- 失败可回放；
- 不以“爬虫结束”代替“Coverage 完成”。

### 增量

- RSS/Sitemap/API 新文章可在目标 Freshness 内入库；
- 304 不生成新正文版本；
- 正文修改生成新 Version；
- 删除需要多证据确认；
- 任务重复执行不产生脏重复。

### Markdown

- 标题/段落/列表/代码/表格结构稳定；
- 菜单、推荐、广告等噪声受控；
- Markdown 可回溯 Raw Artifact；
- Renderer 升级可批量重建。

### 扩展性

- 新 Source 主要通过 Probe/Profile/Family 接入；
- 大站 Backfill 不阻塞增量；
- Browser 故障不拖垮 HTTP；
- Graph/LLM 停止不影响 Canonical 主链。

### 检索

- 默认 BM25 + Vector + Rerank 有固定离线评测集；
- GraphRAG 启用前必须证明其相对默认检索存在稳定质量净收益；
- Graph Query Router 能证明仅在目标查询类型启用 Graph；
- Graph Projection 必须通过 Schema/Entity/Provenance/Connectivity Quality Gate；
- 大规模 Graph Backfill 前必须完成 Cost Preflight 且预算审批通过；
- 所有 Graph 关系可追溯到具体 Document Version 和 Chunk；
- Graph 预算熔断时默认检索仍可正常工作。

## 28. 最终推荐

该系统的核心不是选择某一个“万能爬虫”，而是构建一个 **以 Coverage、不可变事实、版本、幂等任务、质量与可重建 Projection 为核心的平台**。

推荐主链：

```text
Authoritative Discovery
 -> URL Truth / Coverage Evidence
 -> HTTP First Fetch
 -> Browser Fallback
 -> Immutable Artifact
 -> Generic + Deterministic Extraction
 -> Candidate Agreement
 -> Canonical IR
 -> Quality Gate
 -> Document Version
 -> Canonical Markdown
 -> BM25 / Vector / Export
```

增量主链：

```text
RSS/API/Sitemap Diff
 + Conditional GET
 + Known URL Verify
 -> Semantic Version Detection
 -> Atomic Current Version Switch
 -> Rebuild Search/Vector Projection
```

GraphRAG 的最终定位：

```text
Optional
+ Query-routed
+ Schema-guided
+ Entity-resolved
+ Provenance-aware
+ Quality-gated
+ Incremental
+ Cost-preflighted
+ Budgeted
+ Evaluated
```

默认先把 **Metadata + BM25 + Vector + Rerank** 做扎实；只有关系结构能提供文本召回没有的独特信息，并且离线评测证明收益覆盖额外成本、延迟与运维复杂度，同时 Graph Quality Gate 与 Cost Preflight 均通过时，才对对应专题启用 Graph Projection。

这样既能满足 1000 个网站的全历史与增量同步，又能为未来新增网站、检索能力、知识图谱和模型升级保留稳定边界；即使 Graph/LLM 完全停用，Canonical Markdown 与默认检索主链仍能独立、可恢复地运行。
