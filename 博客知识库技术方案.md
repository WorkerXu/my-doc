# 博客知识库技术方案

## 1. 建设目标与规模

建设一个长期运行、可横向扩展、可审计、可回放的技术博客知识库平台。首期接入约 1000 个技术博客、工程博客、技术文档站和公开 Newsletter，尽可能抓取完整历史文章并清洗为稳定 Markdown；后续能够持续新增网站，并支持低成本增量同步、版本追踪、全文/向量/图谱检索、Web 管理、质量审计、单 URL 手工摄取、离线重处理、外部自动化和 AI 派生分析。

设计规模：

- 1000+ Source，后续扩展到数千；
- 百万级 Document / Document Version；
- 数百万到千万级 URL Observation；
- 千万级 Chunk / Embedding；
- HTML、PDF、Markdown、TXT、JSON/API、RSS/Atom/JSON Feed；
- 中英日韩等多语言；
- HTTP 为默认抓取路线，Browser 为受控 fallback；
- CMS API、Sitemap、Feed、Archive、Docs TOC、Common Crawl、Deep Crawl 等多入口历史发现；
- PostgreSQL + Object Storage 保存事实；Markdown、Structured Record、Chunk、Embedding、全文索引、向量索引、Graph、AI Insight、Export、Dashboard Read Model 均作为可重建 Projection；
- Web UI、n8n、MCP、CI、外部系统都只能通过受控 API / Event 边界驱动平台。

平台必须能够回答：

1. 一个站点理论上有哪些历史文章，为什么认为历史已经基本覆盖；
2. URL 从哪里被发现、如何规范化、为何被过滤或放行、经过哪些跳转、最终抓到了什么；
3. 为什么使用 HTTP、API、文件流、Crawl4AI Browser 或 Playwright；
4. 一个 Markdown 来自哪个 Snapshot、Extractor、Release 和 Document Version；
5. 源站变化后哪些内容真的发生变化，哪些派生物需要重建；
6. Worker 崩溃、外部工作流重启或批任务部分失败后如何恢复且不丢成功项；
7. 新增站点、规则、模型、索引、图谱、Webhook、Export 策略时如何灰度、回放和回滚；
8. Web 管理中的暂停、重跑、重新分析、切 Release 等动作由谁发起、是否幂等、是否经过 RBAC；
9. BM25、Vector、Graph 三条召回链路是否严格遵守 SOURCE/DOCUMENT/VERSION/ACL Scope；
10. Graph 是否真的对一次查询产生增量贡献，而不是仅仅“已经建图”；
11. Dashboard 指标处理到什么 watermark、覆盖多少 Source、使用哪一版指标定义；
12. 外部自动化收到的事件是否可验证、可重放、可去重；
13. Markdown 导出到本地/S3/Git 后，是否仍能稳定映射回平台内部 Document Version。

## 2. 核心设计原则

1. **Config First**：普通站点靠 Source / Site Profile / Release 接入，不修改核心代码。
2. **Coverage First**：历史完整性由 Provider Evidence、cursor 和 exhaustion reason 证明，队列为空不代表完整。
3. **Authoritative First**：CMS/API、Sitemap、Feed、Archive 优先，Deep Crawl/Common Crawl 主要用于补洞。
4. **Discovery Before Fetch**：先发现、规范化、过滤、分类、去重 URL，再抓正文。
5. **Filter With Evidence**：URL Filter 区分 HARD/SOFT，但任何过滤都保存 Observation、规则和 reason。
6. **URL Is Locator**：资源类型由响应 MIME、签名、跳转和站点规则共同判断，不能只看后缀。
7. **HTTP First, Browser Last**：Browser 只处理动态发现、动态正文或质量 fallback。
8. **Recipe, Not Site Code**：动态交互、Filter、结构化抽取均声明式、版本化、可回放。
9. **Bounded Crawl**：Deep Crawl、Browser、LLM Extraction、Graph Expansion 都有预算和终止条件。
10. **Snapshot First**：先保存不可变网络事实，再做抽取、清洗、Schema、Graph、AI。
11. **IR First, Markdown as Projection**：Canonical IR / Document Version 是内容事实层，Markdown 可确定性重建。
12. **Canonical Before AI**：LLM 可以生成 Enhanced Markdown、摘要、FAQ、主题，但不得覆盖 canonical Markdown。
13. **Structured Record Is Projection**：结构化抽取不覆盖 canonical 内容。
14. **Graph Is Projection**：实体、关系、事实、社区和 GraphRAG 来自 Document Version，不成为唯一事实源。
15. **Literal Is Not Entity by Default**：日期、分数、数量、配置值、版本字符串等标量默认建 Statement/Literal，不制造全局“伪实体”。
16. **Hard Record Boundary**：Chunk、Embedding、Graph Extraction 不跨 Document Version 或 Structured Record 硬边界。
17. **Provenance Before Activation**：没有 Document/Chunk Evidence 的 Graph Relation/Statement 不进入 ACTIVE Graph。
18. **Graph Built != Graph Valuable**：是否启用 Graph Retrieval 由增量检索收益、延迟和成本共同决定。
19. **LLM Is Projection, Not Truth**：LLM Extraction/Analysis 失败不阻塞 Source Sync。
20. **Stable Identity**：Document、Version、Chunk、Embedding、Graph Entity/Relation/Statement、Analysis、Export 身份稳定且 release-aware。
21. **Release Everything**：影响结果的 Filter、Recipe、Schema、Extractor、Ontology、Model、Prompt、Graph、Metric、Index、Webhook、Export、Runtime 全部版本化。
22. **Idempotent + Recoverable**：任务有幂等键、lease、fencing、checkpoint、retry、partial success。
23. **Stream and Commit Per URL**：批任务按 URL 独立提交，一个失败项不回滚其他成功项。
24. **One Durable Task System**：PostgreSQL durable state + Transactional Outbox + Redis Streams 是唯一业务任务体系。
25. **Async Command API**：抓取、解析、Embedding、Graph、AI、重建、导出等长任务统一使用 202 + durable command ID。
26. **Event-Driven Completion Before Polling**：跨系统长任务优先用事件/Webhook 通知完成，轮询仅作兼容 fallback。
27. **External Automation Is Adapter, Not Truth**：n8n、MCP、CI、Agent 只能调用强类型 API，不能成为 Coverage/Task/Version 真相。
28. **Export Is Projection**：本地目录、S3、Git、ZIP 只是 Markdown 发布投影，不取代平台 Truth。
29. **Projection Readiness Explicit**：Canonical、Markdown、Structured、Chunk、Embedding、Graph、AI、Export、Index、Dashboard 状态分别表达。
30. **Hybrid Retrieval by Default**：BM25 + Vector 是基线，Graph 是按需启用的第三召回通道，Reranker 可降级。
31. **Hard Scope Filter**：SOURCE/DOCUMENT/VERSION/ACL Scope 必须下推到所有召回通道和 Graph expansion。
32. **Generation Instead of Destructive Rebuild**：全文、向量、Graph 新版本后台构建、验证、原子切换。
33. **Dashboard Is Read Model**：Dashboard 读取可重建聚合，不把缓存、WebSocket 或 Worker 内存当真相。
34. **Security on Every Hop**：起始 URL、Redirect、Browser navigation、Webhook endpoint 每跳重新做 SSRF/Egress/Scope 校验。
35. **Benchmark Before Switch**：Filter、Extractor、Analyzer、Embedding、Graph、Retrieval、Metric 等升级先固定回归再激活。

## 4. 技术选型

### 4.1 控制面

- FastAPI + Pydantic：REST/Command API、Schema 校验、Webhook Receiver、内部服务接口；
- PostgreSQL：Source、Profile、Run、Task、Coverage、Observation、Snapshot、Document、Version、Release、Audit、Outbox、Event、Webhook Delivery、Export metadata、Graph metadata；
- Transactional Outbox：保证数据库事务与异步消息发布一致；
- Redis Streams：consumer group、retry、backpressure，只做任务运输；
- React/Vue + TypeScript：生产 Web 管理台；
- Docker/Kubernetes：隔离不同 Worker 类型并弹性扩缩容。

### 4.2 抓取与解析

- HTTPX/aiohttp：静态 HTML、Feed、Sitemap、API、Conditional GET、Range GET；
- Crawl4AI：URL Seeding、Deep Crawl、Browser Interaction、Markdown/Structured Extraction Adapter；
- Playwright：复杂 JS 页面和特殊交互 fallback；
- lxml/BeautifulSoup/CSS/XPath/Regex：确定性抽取；
- Trafilatura/Readability：通用正文候选；
- PDF Parser + OCR fallback；
- S3/MinIO：raw response、HTML、Rendered DOM、PDF、WARC、Canonical IR、Markdown、Structured JSON、Graph artifact、AI artifact、fixture。

### 4.3 外部自动化

- n8n：可选低代码运营编排 Adapter；
- MCP：Model Context Protocol，仅作为 Agent Tool/Context Adapter；
- Signed Webhook：任务完成/失败/Ready 事件推送；
- Git/S3/Local FS：Markdown Export Sink Adapter。

### 4.4 检索与图谱

- OpenSearch：生产 BM25、过滤、聚合、Alias/Generation；
- pgvector/OpenSearch kNN：首期向量；规模增长后可替换 Qdrant/Milvus；
- RRF/Controlled Fusion：BM25 + Vector 基线融合；
- Graph：首期 PostgreSQL entity/relation/statement/evidence 表验证价值；需要高阶图查询后再增加 Neo4j/Memgraph/其他图引擎 Adapter；
- R2R/其他 GraphRAG 平台：只作为可替换 Graph/RAG Projection Adapter，不接管平台 Truth；
- Cross Encoder Reranker：可选精排。

### 4.5 运营分析

- Prometheus + Grafana + OpenTelemetry：低基数指标和 Trace；
- PostgreSQL Materialized/Incremental Read Model：首期运营聚合；
- 数据量进一步增长后可引入 ClickHouse；
- SSE/WebSocket：Web UI 失效通知；
- Webhook：外部系统事件交付。

### 7.2 历史发现顺序


### 7.3 Coverage 事实

```text

- provider_type

- status
- exhaustion_reason
```

预算耗尽只能标记：


## 8. URL Observation、Normalization 与 Filter

### 8.1 Observation First

每个被发现 URL 先保存 Observation：

```text
url_observation
- source_id
- observed_url
- provider_type
- provider_run_id
- parent_url nullable
- anchor_text nullable
- depth nullable
- observed_at
- evidence_ref
```

Filter 不能删除“曾经发现过这个 URL”的事实。

### 8.2 Normalization

全局安全规则：lowercase host、default port removal、fragment removal、path slash、安全 percent-encoding、query key ordering、tracking param removal。

站点规则：semantic query allowlist/denylist。

禁止全局删除 query；`?id=123`、`?p=456`、`?page=7` 可能包含业务语义。

### 8.3 URL Filter Chain

```text
url_filter_release
- rules[]
- action: HARD_REJECT / SOFT_REJECT / DEPRIORITIZE / ACCEPT
- reason_code
- fixture_refs
```

HARD_REJECT 仅用于明确禁止域、robots/policy、后台/登录、静态资产等；路径模式、相关性、category/tag 推断默认属于 SOFT_REJECT/DEPRIORITIZE。

每次 decision 保存：

```text
url_filter_decision
- url_id
- filter_release_id
- rule_id
- action
- reason_code
- score nullable
- evidence_ref
- decided_at
```

新 Filter Release 上线前对已知文章 URL fixture 做 recall 回归。

批任务必须 partial success：成功事实立即持久化，失败项独立 retry。

### 10.1 为什么不把 n8n/Crawl4AI Job Queue 当平台任务真相

外部或内部 Adapter 可以有自己的 task_id，但必须映射到平台 durable Task：

```text
platform_task_id <-> adapter_job_id
```

Adapter Job 丢失、重启或升级不能导致平台丢失任务事实；Adapter callback 只推进平台状态机，不直接成为最终事实。

## 11. Rate Limit、Backpressure 与预算

固定 sleep 只适合调试。生产系统按层级治理：

```text
Global capacity
 -> route quota
 -> registrable-domain quota
 -> source quota
 -> host quota
 -> worker local limiter
```

每个 Source/Profile 可配置：

```text
max_rps
max_concurrency
burst
max_browser_seconds_per_hour
max_bytes_per_hour
max_pages_per_run
retry_budget
```

策略：

- 429/503 识别 Retry-After；
- 网络瞬时故障 exponential backoff + jitter；
- robots/policy/明确 4xx 不盲目重试；
- Browser/PDF/OCR/LLM 单独预算；
- 同 registrable domain 的多个 Source 共享上层域配额；
- 队列积压时 Source Sync 高于 Graph/AI/Reembed/非关键导出优先级。


### 12.2 Deep Crawl Adapter

Crawl4AI BFS/DFS/Best-First 只作为 Worker 内策略 Adapter，平台 Scheduler 才是 durable 调度真相。

```text

max_duplicate_ratio

```

发现 URL 后立即持久化 Observation/Task，不能只留在 crawler 内存 frontier。

### 12.3 Crawl4AI 自托管集成

可以使用：

- 同步 `/crawl`；
- streaming endpoint；
- async `/crawl/job`；
- job Webhook。

但无论采用哪种方式，平台 Task 与 Snapshot 才是最终事实。Callback 必须携带/映射 platform task id、adapter job id、attempt，并经过幂等校验。

## 16. Document Identity、版本与增量同步

### 16.1 Identity

- redirect evidence；

## 20. Chunk、Embedding、全文索引与向量索引

### 20.1 Chunk

Structure-aware：Heading/Section 优先；段落、列表、引用尽量完整；code/table 默认不拆；保存 heading path/page/block range；超长 section 才 recursive fallback；长度按目标 Embedding tokenizer 计数。

硬规则：

```text
Chunk NEVER crosses Document Version boundary
Chunk NEVER crosses Structured Record boundary
```

```text
chunk_id = hash(boundary_id + chunk_release_id + logical_block_range + normalized_text_hash)
```

### 20.2 Embedding

```text
embedding_id = hash(chunk_id + embedding_release_id)
```

Worker 支持 batch token 上限、OOM 自动缩 batch、lease、retry、partial success、backpressure。写向量前校验 dimension、finite value、normalization、release 和 payload schema。

### 20.3 Index Generation

全文、向量、Graph 都使用 Generation：后台构建、固定 judgment set 验证、canary、Alias/逻辑指针原子切换。

`RECHUNK / REEMBED / REINDEX / REGRAPH` 都不重新抓源站。

## 26. 安全与合规

- 遵守 robots 和站点策略；
- 不绕过登录、付费墙、验证码、WAF 或明确访问控制；

- 限制 redirect、响应大小、附件大小、解压比、Browser wall-clock、OCR 页数；
- Browser Worker 独立网络/CPU/内存；
- Secret 进入 Secret Manager；
- Query Plane 原则上无公网访问；
- Graph/AI Worker 只访问内部只读内容 API、模型服务和对象存储；
- Graph expansion 在 tenant/scope 层做硬限制；
- Webhook endpoint 必须经过 egress allow policy；
- Webhook 使用 HMAC 签名、timestamp、防重放；
- Export Local FS 必须限制 root，不允许路径逃逸；
- Git/n8n/MCP credential 不进入普通配置文本或导出文件；
- 所有高风险管理操作经过 RBAC、强类型 Command 和 Audit。

## 27. 存储、分区与生命周期

PostgreSQL 只保存 metadata/state/hash/ref，不保存大 body。

高增长表按时间/source hash 分区：URL Observation、Fetch/Probe/Interaction、Task、Audit、Event、Webhook Delivery、Retrieval Trace、Structured Record metadata、Graph Evidence、AI Analysis、Ops Metric。

Object Storage：raw response、HTML、Rendered DOM、Feed、PDF、WARC、Canonical IR、Markdown、Filtered/Enhanced Markdown、Structured JSON、Graph artifact、AI raw output、fixture、debug artifact、export staging。

推荐 Key：

```text
snapshot/{snapshot_id}/body
rendered/{snapshot_id}/dom.html
ir/{document_version_id}/{ir_release_id}.json
markdown/{document_version_id}/{markdown_release_id}.md
enhanced/{document_version_id}/{enhanced_release_id}.md
structured/{document_version_id}/{structured_extraction_release_id}/{record_id}.json
graph/{graph_generation_id}/{document_version_id}.json
analysis/{document_version_id}/{analysis_release_id}/{manifest_hash}.json
export-stage/{export_id}/payload
```

所有搜索、向量、Graph、Export、Dashboard Read Model 都必须能从 Truth 重建。

## 29. 测试、Replay 与发布门禁

### 29.1 Coverage

测试 Sitemap/API cursor/Archive pagination exhaustion、known gap；Budget exceeded 不得 COMPLETE。

### 29.2 Filter Recall

固定已知文章 URL fixture：article_url_recall、non_article_reject_rate、soft_filter_false_negative_rate。

### 29.3 Snapshot Replay

新 Extractor/Quality/Markdown/Structured/Graph/AI/Export 在旧 Snapshot/Document Version 离线重放，不访问源站。

### 29.4 Resource Probe

覆盖：无扩展名 PDF、`.pdf` 跳 HTML、错误 Content-Type、HEAD 405、超大文件、签名冲突。

### 29.5 Crash / Idempotency

- 重复 Command/message 不重复 Version；
- Worker 退出后 lease 恢复；
- fencing 阻止旧 Worker 覆盖；
- batch partial success 不丢失；
- Adapter callback 重复到达不重复提交结果。

### 29.6 Structured / Boundary

- required field/type/null/multi-item/DOM drift/LLM invalid JSON/timeout；
- Chunk 不跨 Document Version；
- Chunk 不跨 Structured Record；
- Graph Extraction 不跨硬边界；
- `chunk_boundary_violation_rate = 0`。

### 29.7 Webhook

必须覆盖：

```text
receiver 2xx
receiver 4xx
receiver 5xx
connect timeout
DNS failure
duplicate event
late delivery
secret rotation
DLQ replay
SSRF blocked endpoint
```

验收：Webhook 故障不阻塞 Source Sync；同 event_id 可重复投递但业务只生效一次。

### 29.8 Export

必须覆盖：

- 同一 Version 重跑不产生重复文件；
- path 不逃逸 root；
- 标题变更不改变 Document identity；
- temp write 失败不暴露半文件；
- Git/S3 暂时失败可重试；
- Export 失败不影响 canonical READY。

### 29.9 Retrieval / Graph

固定 judgment set 覆盖中英文、技术 token、HTML/PDF/MD、SOURCE/DOCUMENT/VERSION/URL/ACL Scope。

Graph 必须对比 `BM25+Vector` 与 `BM25+Vector+Graph`，不能仅用实体/关系数量证明价值。

### 29.10 Dashboard

测试 watermark、Read Model 一致性、高基数、UI rerun 不触发 Crawl/LLM、Command Audit、Metric Release diff。

### 29.11 发布流程

```text
fixture/offline replay
 -> benchmark
 -> shadow
 -> canary sources
 -> observe
 -> staged rollout
 -> ACTIVE
```

Coverage/Quality/Scope/Cost/Graph provenance/Record Boundary/Webhook security/Export idempotency 回归时停止扩大并回滚。

## 31. 验收标准

### Coverage

- 每个 Source 有可解释 Provider；
- FULL_BACKFILL 有 exhaustion evidence；
- known gap 可枚举、可重跑；
- Deep Crawl 队列为空不能冒充完整；
- Common Crawl 不作为完整性证明。

### Incremental

- Feed/API/Sitemap 新文章在目标 SLA 内入库；
- Sitemap 自身支持 ETag/Last-Modified 增量；
- 304 不重复抽取/建版/投影；
- Reconcile 能发现 Feed 窗口外遗漏和结构漂移。

### Filter / Crawl

- URL Filter 有 release/evidence；
- HARD/SOFT 明确；
- 新 Filter Release 有文章 recall fixture；
- Browser 不是默认路线；
- Deep Crawl/Interaction 有预算；
- 批处理按 URL 独立提交；
- 固定 Wait 不是生产限流手段，限流由平台配额/退避管理。

### Markdown / Export

- Markdown 可从 IR 确定性重建；
- heading/code/list/table/image/link 有质量验证；
- LLM Enhanced Markdown 不覆盖 canonical；
- Export 使用稳定路径和 manifest；
- Export 重放幂等；
- Local FS 无路径逃逸；
- Git/S3/Local Sink 可替换，不承担 Document Version 真相。

### Structured / Search

- Structured Schema 有 fixture 和 validation；
- 多 item 具有独立 Structured Record 身份；
- Chunk/Graph 不跨 Document/Record 边界；
- RECHUNK/REEMBED 不访问源站；
- BM25 + Vector + optional Graph 可解释；
- Scope 不召回范围外 Chunk；
- 新 Generation 验证后才能 ACTIVE。

### Graph

- Graph 是 Projection，不是 Truth；
- Entity/Relation/Statement 有 Document/Chunk provenance；
- ACTIVE Graph 的 provenance coverage = 1.0；
- 标量默认使用 Statement/Literal；
- Ontology 可版本化、可验证；
- REGRAPH 不重新抓源站；
- Graph 失败不阻塞 Source Sync；
- Graph 是否启用以增量检索收益为依据。

### Automation / Webhook

- n8n/MCP/CI 删除或重启不会丢平台任务状态；
- 外部动作全部进入 Command API；
- Webhook 使用签名、重试、DLQ、replay；
- 重复 event_id 可去重；
- Webhook receiver 故障不阻塞 Source Sync；
- 外部系统不得直改 Redis/Task/Coverage。

### Web / Ops

- Fleet Overview 不实时扫描所有事实表；
- 每个趋势图显示 watermark/coverage；
- Filter/Schema/Ontology/Graph/Webhook/Export Release 可调试、diff、回滚；
- UI 刷新不触发 Crawl/LLM；
- Prometheus 无 URL/Document/Task/Event 高基数 label；
- Dashboard Command 全部经过幂等、RBAC、Audit。

### Reliability / Security

- Worker crash 后 lease 可恢复；
- fencing 防止旧 Worker 覆盖；
- fan-out 保留 partial success；
- Embedding/Graph/AI/Export/Webhook/Search/Dashboard 故障不阻塞 Source Sync；
- Query Plane 无任意公网 URL 访问权限；
- Runtime/Model/Ontology/Graph/Metric/Webhook/Export Artifact 可复现、可回滚。

## 32. 最终技术路线

```text
Coverage-driven Discovery
 -> Evidence-preserving URL Filter
 -> Normalize / Resolve / Probe
 -> Durable Per-URL Task
 -> HTTP-first Fetch
 -> Immutable Snapshot
 -> Deterministic Canonical IR
 -> Stable Canonical Markdown + Document Version
 -> Async Projections
      ├─ Structured Record with Hard Boundary
      ├─ Chunk / BM25 / Vector
      ├─ Graph Entity / Relation / Statement / Evidence
      ├─ AI Insight / Enhanced Markdown
      ├─ Markdown Export Sink
      └─ Ops Analytics
 -> BM25 + Vector + on-demand Graph Retrieval
 -> Contribution / Scope / Cost Gate
 -> Outbox Event
      ├─ Web UI invalidation
      └─ Signed Webhook -> n8n / MCP-side automation / external system
 -> Web-operable Release / Generation / Audit
```

这条路线保证：

- 新增站点主要靠配置扩展；
- 全量历史有 Coverage 证据；
- Sitemap、Feed、API、Conditional GET 和 Reconcile 共同支持低成本增量同步；
- Browser 和 LLM 只处理必要长尾；
- Markdown 是稳定、可重建的知识资产；
- AI 重写内容与 canonical 内容严格分离；
- Markdown 可幂等导出到本地/S3/Git 等外部知识库消费端；
- n8n/MCP/CI 可作为自动化入口，但不会成为抓取任务和数据版本真相；
- 异步任务优先用可靠事件/Webhook 完成通知，避免外部高频轮询；
- Structured Record 与 Chunk 保持严格记录边界；
- 图谱使用 Entity/Relation/Statement 正确表达实体关系和标量事实；
- 每条 ACTIVE 图谱事实都有 provenance；
- GraphRAG 必须用实际增量检索收益证明价值；
- R2R、图数据库、向量库、n8n、Crawl4AI job queue、Export Sink 均处于可替换 Adapter/Projection 边界；
- 所有关键策略均可版本化、回放、灰度和回滚；
- Source Sync、检索、Graph、AI、Export、Webhook Delivery、Dashboard 可以独立扩缩容和故障隔离。

该方案能够支撑 1000+ 技术博客的长期全量历史抓取、Markdown 知识资产沉淀、增量同步、Web 化运营和外部自动化，并为后续结构化数据、GraphRAG、AI 助手及多种知识库消费端提供可控、可验证、可替换的扩展路径。
