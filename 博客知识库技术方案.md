# 博客知识库技术方案

## 1. 建设目标与规模

建设一个长期运行、可横向扩展、可审计、可回放的技术博客知识库平台。首期接入约 1000 个技术博客、工程博客、技术文档站和公开 Newsletter，尽可能抓取完整历史文章并清洗为稳定 Markdown；后续持续增加网站，并低成本完成增量同步、版本管理、搜索/RAG、知识派生、Web 管理、导出和离线重处理。

目标规模：

- 1000+ Source，可扩展到数千站点；
- 百万级 Document / Document Version；
- 数百万到千万级 URL Observation；
- 千万级 Chunk / Embedding；
- HTML、PDF、Markdown、TXT、JSON/API、RSS/Atom/JSON Feed；
- 中英日韩等多语言；
- HTTP 为默认抓取路线，Browser 为受控 fallback；
- CMS API、Sitemap、Feed、Archive、Category/Tag、Docs TOC、Common Crawl、受控 Deep Crawl 等多入口历史发现；
- PostgreSQL + Object Storage 保存事实；Markdown、全文索引、向量索引、Graph、AI Insight、Relation、Annotation、Export、Dashboard Read Model 均为可重建 Projection；
- Web UI、n8n、MCP、CI、Agent、外部系统只能通过受控 API / Event 边界驱动平台。

平台必须能够回答：

1. 一个站点理论上有哪些历史文章，为什么认为历史已经基本覆盖；
2. 一个 URL 从哪里被发现、如何规范化、为何被过滤或放行、经过哪些跳转、最终抓到了什么；
3. 为什么某 URL 走 HTTP、平台 API、文件流、Crawl4AI Browser 或 Playwright；
4. 一个 Markdown 来自哪个 Snapshot、Extractor、Release 和 Document Version；
5. 源站变化后哪些内容真正变化，哪些派生物需要重建；
6. Worker 崩溃、批任务部分失败或外部自动化重启后如何恢复且不丢成功项；
7. 新增第 1001 个站点时，能否主要依靠配置、Probe 与审核接入，而不是增加站点专用代码；
8. 全量历史抓取是否有 durable checkpoint，能否从断点继续；
9. 百万 URL 批处理是否保持有界内存，并支持逐 URL 提交；
10. Browser 是否被复用且安全隔离，何时回收，是否因资源压力自动降并发；
11. 第三方 crawler API 升级后，是否只修改 Adapter 而不污染平台数据契约；
12. Markdown 导出到本地/S3/Git 后，是否仍能稳定映射回平台内部 Document Version；
13. 一条 AI Insight 到底来自哪个原文版本、哪些 block、哪个模型和 Prompt；
14. 一个所谓“引用”到底是逐字原文、清理后的 transcript，还是模型 paraphrase；
15. 两篇内容被判断为“同文转载”“翻译”或“相关主题”时，依据是什么，是否可逆；
16. 自动研究发现的新站点为什么进入知识库、消耗多少预算、是否会影响受管理站点 Coverage；
17. 一个回答是否直接引用 Source Block，还是只在反复总结 AI Summary/Insight；
18. AI 声称“只加链接/格式”时，系统如何证明它没有偷偷改正文。

## 2. 核心设计原则

1. **Config First**：普通站点靠 Source / Site Profile / Release 接入，不修改核心代码。
2. **Coverage First**：历史完整性由 Provider Evidence、cursor、exhaustion reason 和 known gap 证明，队列为空不等于完整。
3. **Authoritative First**：CMS/API、Sitemap、Feed、Archive 优先，Common Crawl/Deep Crawl 用于补洞和交叉验证。
4. **Discovery Before Fetch**：先发现、Observation、规范化、过滤、分类、去重，再抓正文。
5. **Durable Streaming Frontier**：大站 URL 发现必须流式、小批持久化，禁止把全站 URL 一次性物化在内存。
6. **Filter With Evidence**：Filter 可 HARD/SOFT/DEPRIORITIZE，但任何决定都保存规则、原因和证据。
7. **URL Is Locator**：资源类型由响应 MIME、签名、跳转和站点规则判断，不能只看扩展名。
8. **HTTP First, Browser Last**：静态 HTML、Feed、API、Sitemap 优先 HTTP；Browser 只处理动态正文、交互和质量 fallback。
9. **Reuse Browser, Isolate Session**：复用 Browser/Crawler 进程降低成本，但 Cookie、LocalStorage、认证态和代理身份按 Source/Profile/安全域隔离。
10. **Adapter Is Boundary**：Crawl4AI/Playwright/HTTP 客户端只输出平台内部稳定契约，第三方 DTO、字段名和版本变化不得泄漏到事实层。
11. **Platform Permit Before Local Dispatcher**：平台 global/domain/source 配额是并发上限；Crawler Dispatcher/Semaphore 只负责 Worker 内二级自适应控制。
12. **Bounded Window + Commit Per URL**：Worker 只 lease 有界窗口，流式返回结果；每个 URL 成功立即落库，不等待整批完成。
13. **Snapshot First**：先保存不可变网络事实，再做抽取、清洗、Markdown、Chunk、Graph、AI。
14. **IR First, Markdown as Projection**：Canonical IR / Document Version 是内容事实层，Markdown 可确定性重建。
15. **Full Canonical Before Fit Markdown**：Pruning/BM25/LLM 等有损过滤只能产生 FILTERED/ENHANCED Projection，绝不能覆盖 Canonical Markdown。
16. **Recipe, Not Site Code**：交互、路由、Filter、Schema、Selector、Extractor 均声明式、版本化、可回放。
17. **Stable Identity**：URL Alias、Document、Version、Chunk、Embedding、Relation、Knowledge Note、Annotation、Export 身份分离且稳定。
18. **Release Everything**：影响结果的 Profile、Provider、Filter、Adapter、Recipe、Extractor、Markdown、Chunk、Embedding、Graph、Relation、Grounding、Validation、Model、Prompt、Research、Metric、Webhook、Export、Runtime 全部版本化。
19. **Idempotent + Recoverable**：任务有幂等键、lease、fencing token、checkpoint、retry、partial success。
20. **One Durable Task System**：PostgreSQL durable state + Transactional Outbox + Redis Streams 是唯一业务任务体系。
21. **External Automation Is Adapter, Not Truth**：n8n/MCP/CI/Agent 不能成为 Coverage、Task、Snapshot、Version 或 retry 状态真相。
22. **Projection Is Rebuildable**：全文、向量、Graph、AI、Relation、Annotation、Export、Dashboard 都可从事实层离线重建。
23. **Generation Instead of Destructive Rebuild**：索引/图谱/语义关系/AI 派生/Annotation 新版本后台构建、验证、原子切换。
24. **Security on Every Hop**：起始 URL、Redirect、Browser navigation、Webhook endpoint 每跳重新做 SSRF/Egress/Scope 校验。
25. **Source Friendly**：吞吐最大化不是唯一目标，robots、站点策略、分层限流和退避优先于速度。
26. **Benchmark Before Switch**：Adapter、Filter、Extractor、Markdown、Embedding、Graph、Retrieval、Grounding、Metric 升级先固定回归，再激活。
27. **Source Truth != AI Derivation**：摘要、Insight、FAQ、实体、研究问题不能写回 Canonical IR 或 Document Version。
28. **User Note != AI Insight**：用户自己的判断/批注与模型生成内容必须有不同 origin、权限和审计。
29. **Similarity Is Evidence, Not Identity**：向量、标题距离和 LLM 判定只产生关系证据，不能单独触发不可逆 Document 合并。
30. **Collapse Is Projection, Not Destructive Merge**：同文转载可在 UI 中折叠，但事实记录和来源引用保持可恢复。
31. **Research Expansion Is Bounded**：自动研究必须有 max depth/fanout/URL/domain/cost budget 和明确 stop reason。
32. **External Research != Managed Source**：搜索发现的外部 URL 不计入正式 Source Coverage，只有显式 Promote 后才走 PROBE/Backfill。
33. **Hybrid Retrieval First**：代码符号、错误信息、版本号和专有名词必须依靠 BM25/字段检索与 Vector 互补，不能只靠 Embedding。
34. **Provenance to Block Level**：AI Insight、检索片段和知识关系都应尽可能回溯到 Document Version + IR block。
35. **Derived Knowledge Is Context, Not Sole Evidence**：AI Summary/Insight 可用于召回、排序和 query planning，但高可信回答和 quote 必须回到 Source Block。
36. **Ground Before Cite**：任何可引用 Claim 都要绑定 Evidence Span；无法绑定的派生物只能标为 PARTIAL/UNGROUNDED，不能冒充原文。
37. **Validate AI by Invariant**：Schema 正确只是最低门槛；还要验证引用、目标、证据和语义不变量，有限修复后失败即隔离。
38. **Annotation Over Mutation**：内部链接、高亮、关系提示优先作为独立 Annotation Projection，不修改基础原文或 Knowledge Note 内容。
39. **No Recursive Derivation Drift**：跟踪 derivation lineage/depth，禁止“摘要的摘要”长期递归成为唯一证据。
40. **Evidence Role Is Explicit**：每个派生输入明确标为 EVIDENCE / CONTEXT / QUERY_EXPANSION / RANKING_SIGNAL，不能混用。

## 4. 技术选型

### 4.1 控制面

- **FastAPI + Pydantic**：REST/Command API、Schema 校验、Webhook Receiver、内部服务接口；
- **PostgreSQL**：Source、Profile、Run、Task、Coverage、Observation、Snapshot metadata、Document、Version、Release、Audit、Outbox、Knowledge/Research metadata；
- **Transactional Outbox**：保证业务数据库事务与异步消息发布一致；
- **Redis Streams**：consumer group、retry transport、backpressure，只做任务运输；
- **React/Vue + TypeScript**：Web 管理台；
- **Docker/Kubernetes**：按 Discovery / HTTP Fetch / Browser / Extract / Projection / Derive / Research Worker 独立扩缩容。

### 4.2 抓取与解析

- **HTTPX/aiohttp**：静态 HTML、Feed、Sitemap、API、Conditional GET、Range GET；
- **Crawl4AI**：URL Seeder、`arun_many()` 流式多 URL 抓取、Browser Interaction、Markdown/Structured Extraction Adapter、Worker 内 Dispatcher；
- **Playwright**：复杂 JS 与特殊交互 fallback；
- **lxml/BeautifulSoup/CSS/XPath/Regex**：确定性抽取；
- **Trafilatura/Readability**：通用正文候选；
- **PDF parser + OCR fallback**；
- **S3/MinIO**：raw response、HTML、Rendered DOM、PDF、WARC、Canonical IR、Markdown、Structured JSON、AI/Graph artifact、fixture。

### 4.3 检索、知识派生与研究扩展

- **OpenSearch**：BM25、字段过滤、聚合、Alias/Generation；
- **pgvector/OpenSearch kNN**：首期向量；规模增长后可切 Qdrant/Milvus；
- **RRF/Controlled Fusion**：BM25 + Vector 基线；
- **Cross Encoder Reranker**：可选；
- **Graph**：首期 PostgreSQL 关系表验证价值，高阶图查询再增加 Neo4j/Memgraph Adapter；
- **LLM Gateway**：统一 Provider、模型、结构化输出、token/cost/latency 计量；
- **Search Provider Adapter**：Exa/Brave/SearXNG/其他 Web Search 通过稳定 Adapter 接入研究扩展层；
- **Grounding/Evidence Resolver**：把模型 evidence hint 对齐到 Canonical IR block/offset；
- **Validation Engine**：Schema、引用、Grounding、语义不变量、target whitelist 的确定性校验。

### 4.4 可观测与运营

- Prometheus + Grafana + OpenTelemetry；
- PostgreSQL incremental/materialized read model；
- 数据规模进一步增长后可增加 ClickHouse；
- SSE/WebSocket：Web UI 实时状态；
- Signed Webhook：外部系统事件交付。

## 7. 全量历史发现、Coverage 与 Durable Frontier

### 7.1 Provider Contract

```text
probe(source, profile) -> capability
discover(cursor, budget) -> candidates + evidence + next_cursor
checkpoint() -> durable_cursor
exhaustion() -> explicit_reason
```

Provider：

```text
CMS_API
SITEMAP
FEED
ARCHIVE
CATEGORY_TAG_AUTHOR
DOCS_TOC
DISCOVERY_SURFACE
BROWSER_DISCOVERY_SURFACE
COMMON_CRAWL_URL_INDEX
SITE_SEARCH
DEEP_CRAWL_BFS
DEEP_CRAWL_DFS
DEEP_CRAWL_BEST_FIRST
```

历史发现优先级：

```text
CMS/API
 -> Sitemap/Sitemap Index
 -> Historical Feed
 -> Archive year/month
 -> Category/Tag/Author
 -> Blog Index / Docs TOC
 -> Common Crawl
 -> HTTP/Browser Discovery Surface
 -> Best-First/BFS gap filling
 -> Site Search supplement
```

Deep Crawl 是 gap discovery，不是 Coverage 真相。

### 7.2 Coverage 事实

```text
coverage_provider_run
- run_id
- source_id
- provider_type
- provider_release_id
- cursor_before
- cursor_after
- status
- exhaustion_reason
- candidate_count
- committed_observation_count
- completed_count
- failed_count
- known_gap
- blocker
- evidence_ref
```

预算耗尽只能标记：

```text
known_gap = true
exhaustion_reason = BUDGET_EXCEEDED
```

只有主要权威 Provider exhausted，或剩余缺口均成为可解释、可枚举的 known gap，`FULL_BACKFILL` 才能结束。

### 7.3 Sitemap Index 分片与 checkpoint

```text
sitemap_shard_state
- source_id
- sitemap_url
- parent_sitemap_url nullable
- etag
- last_modified
- content_hash
- parse_cursor
- observation_commit_cursor
- state
- last_success_at
- provider_release_id
```

处理：

```text
conditional fetch child sitemap
 -> stream parse URLs
 -> observation mini-batch commit
 -> outbox/task publish
 -> advance durable observation cursor
 -> finish shard
```

Provider checkpoint 只能在 Observation 已持久化后推进。

### 7.4 Durable Streaming Frontier

禁止全站 URL 一次性进内存。推荐：

```text
Provider page/shard
 -> 100~1000 URL mini-batch
 -> Observation commit
 -> Normalize/Filter/Classify
 -> Durable Task
 -> next page/shard
```

优先级：

```text
P0 new feed/API item
P1 manual/targeted fetch
P2 incremental high-yield URL
P3 historical authoritative provider
P4 historical gap/deep crawl
P5 reprocess/reindex/AI/research optional work
```

维护 `frontier_low_watermark`、`frontier_high_watermark`、`max_pending_per_source`、`max_pending_per_domain`、`max_observation_commit_lag`；积压超过高水位时暂停非紧急 Discovery。

## 8. URL Observation、Normalization、Filter 与 Resolution

### 8.1 Observation First

```text
url_observation
- source_id nullable
- observation_origin: MANAGED_DISCOVERY | EXTERNAL_RESEARCH
- observed_url
- provider_type
- provider_run_id nullable
- research_run_id nullable
- parent_url nullable
- anchor_text nullable
- depth nullable
- observed_at
- evidence_ref
```

Filter 不能删除“曾经发现过这个 URL”的事实。

### 8.2 Normalization

全局安全规则：host lowercase、default port removal、fragment removal、path slash、安全 percent-encoding、query key ordering、tracking param removal。

站点规则：semantic query allowlist/denylist。禁止全局删除 query；`?id=123`、`?p=456`、`?page=7` 可能有业务语义。

### 8.3 URL Filter Chain

```text
HARD_REJECT
SOFT_REJECT
DEPRIORITIZE
ACCEPT
```

每次决策保存 `filter_release_id`、`rule_id`、`action`、`reason_code`、`score`、`evidence_ref`、`decided_at`。新 Filter Release 上线前对已知文章 URL fixture 做 recall 回归。

### 8.4 Classification / Resolution / Resource Probe

Candidate：

```text
ARTICLE_CANDIDATE
DISCOVERY_SURFACE
ASSET
NAVIGATION
EXTERNAL_REFERENCE
IGNORE_BY_POLICY
UNKNOWN
```

Resolution：

```text
Observed URL
 -> Normalized Candidate
 -> HTTP Redirect
 -> Wrapper Param / HTML Target
 -> Meta Refresh
 -> Browser Navigation Fallback
 -> Resolved Target
```

每一跳重新执行 DNS/IP/SSRF/origin scope 校验。`canonical`/`og:url` 是 Identity Evidence，不等同于 redirect。

Resource Probe 综合 Content-Type、Content-Disposition、magic bytes、Content-Length、HTML 壳、Range GET、redirect 和 Site Profile，产出 HTML/PDF/Markdown/Text/JSON/XML/Image/Archive/Unknown Binary 类型。

```text

 -> each result completes independently
 -> persist Snapshot/Attempt/links
 -> ACK current URL
 -> refill below low watermark
```

N 是几十/数百量级执行窗口，不是全量历史 URL 数。

### 10.4 Browser Pool

长期存活池按 `runtime_release + profile/security_scope + proxy_scope` 分组。Browser Process 可复用，认证态不跨安全边界共享。

### 10.5 两层并发控制

平台 permit：

```text
Global -> route -> registrable-domain -> source -> host
```

Worker 本地：MemoryAdaptiveDispatcher / Semaphore / RateLimiter / browser page ceiling。本地控制只能收缩，不能突破平台上限。

### 10.6 新链接不能直接递归抓

```text
URL Observation
 -> Normalize
 -> Scope
 -> Filter
 -> Classify
 -> Dedupe
 -> Budget/Priority
 -> Durable Task
```

## 11. Rate Limit、Retry 与端到端 Backpressure

每 Source/Profile 配置：

```text
max_rps
max_concurrency
burst
max_browser_seconds_per_hour
max_bytes_per_hour
max_pages_per_run
retry_budget
```

同 registrable domain 的多个 Source 共享域配额。

Retry：

- 429/503：解析 `Retry-After`，退避并降低并发；
- timeout/connection reset：exponential backoff + jitter；
- 401/403/404/410：按原因分类，不盲目重试；
- robots/policy：终止；
- Browser crash：换实例后有限重试；
- HTTP 正文质量不足：可触发 Browser fallback；
- Extractor 失败：优先从 Snapshot 离线重试；
- LLM schema/grounding 失败：走有限 repair，而不是网络型无限重试。

背压指标：`fetch_queue_lag`、`extract_queue_lag`、`snapshot_upload_lag`、`DB_commit_p95`、`object_store_p95`、`worker_RSS`、`browser_RSS`、`429_503_rate`、`fetch_error_rate`。

Source Sync 主链路优先级高于 AI/Research；AI/Research backlog 不允许拖垮抓取链路。

## 16. Evidence Binding 与 Grounding：可引用知识必须回源

### 16.1 为什么只存 snippet 不够

模型生成的 snippet 可能：

- 省略中间文本；
- 清理 transcript 语气词和语法；
- paraphrase；
- 在长文截断输入上生成；
- 来自另一个 AI Summary，而非原始正文。

因此 `snippet` 只是展示字段，不是证据身份。

### 16.2 Knowledge Evidence

```text
knowledge_evidence
- id
- knowledge_note_id nullable
- derivation_run_id
- document_version_id
- block_id
- start_offset nullable
- end_offset nullable
- source_text_hash
- evidence_kind: VERBATIM | NORMALIZED_TRANSCRIPT | PARAPHRASE
- anchor_status: BOUND | AMBIGUOUS | UNBOUND
- alignment_release_id
- evidence_ref
- created_at
```

### 16.3 Evidence Resolver

模型输出最好直接包含 `block_hint / quote_hint / claim_id`，再执行：

```text
claim + evidence hint
 -> exact normalized match
 -> block/offset resolve
 -> source text hash
 -> transcript-normalization alignment when explicitly allowed
 -> fuzzy candidate only if exact fails
 -> BOUND / AMBIGUOUS / UNBOUND
```

规则：

1. `VERBATIM` 必须逐字/规范化后可确定匹配原文；
2. 清理口语后的文本只能标 `NORMALIZED_TRANSCRIPT`；
3. `PARAPHRASE` 不允许使用引号伪装成直接引用；
4. `UNBOUND` 可保留为低可信派生物，但不能进入 citable 高可信通道；
5. Source Version 变化后 evidence 不静默重绑，必须重新 resolve；
6. 每条 Evidence 保存 source text hash，防止 offset 在后续版本漂移。

### 16.4 Evidence Floor

不同用途设置最小证据要求：

```text
SEARCH_PREVIEW        DERIVED_OK_LABELED
IDEA_DISCOVERY        DERIVED_OK_LABELED
RAG_HIGH_TRUST        SOURCE_BLOCK_REQUIRED
DIRECT_QUOTE          VERBATIM_BOUND_REQUIRED
AUTO_PUBLISH          SOURCE_BLOCK_REQUIRED + CLAIM_VALIDATION
```

### 16.5 防止 Derived-on-Derived 漂移

AI Summary/Insight 可以作为：

```text
CONTEXT
QUERY_EXPANSION
RANKING_SIGNAL
```

但高可信答案中不能是唯一 `EVIDENCE`。

回答前执行 Evidence Assembler：

```text
hit Note / relation / search result
 -> resolve associated Document Version
 -> fetch exact Source Blocks
 -> dedupe/pack context
 -> answer model
 -> claim/evidence validation
```

这可以阻止“Summary -> Summary -> Search Summary -> Quote”的递归失真。

## 17. AI Structured Output、有限 Repair 与语义不变量

### 17.1 四级验证

```text
Level 1 Schema Validation
  JSON/Pydantic required/type/enum/length

Level 2 Referential Validation
  document/version/block/target id 必须存在且在允许范围

Level 3 Grounding Validation
  evidence 必须能绑定；quote 必须满足 evidence kind

Level 4 Semantic Invariant Validation
  声称只做链接/格式等非语义变换时，正文必须不变
```

### 17.2 有限 Repair

建议默认最多 2 次修复：

```text
model output
 -> validator failure
 -> feed precise validation error back to model
 -> retry <= 2
 -> still failed => QUARANTINED
```

不同错误不要统一重试：

```text
MODEL_SCHEMA_ERROR        可修复重试
INVALID_REFERENCE         通常重新生成或直接隔离
UNGROUNDED_EVIDENCE       可尝试一次重新选证据
INVALID_TARGET            直接拒绝/重新生成
INVARIANT_VIOLATION       不接受原输出
REPAIR_EXHAUSTED          隔离
```

### 17.3 非语义变换必须证明 invariant

例如 AI 只负责“给已有文本加内部链接”，至少验证：

```text
strip_allowed_markup(output) == normalized_input
all targets in allowed_target_manifest
no broken/overlapping spans
input text hash unchanged
```

Prompt 中写“不要改文字”不够，必须由程序证明。

## 20. Structured Extraction、Chunk、Embedding、Search 与 Grounded RAG

结构化抽取优先级：

```text
platform API / JSON-LD / CSS / XPath / Regex
 -> deterministic extractors
 -> LLM only for complex/unstructured fields
```

LLM 使用 JSON Schema/Pydantic，记录 token、latency、cost、validation error。

Chunk 使用 Structure-aware 规则：Heading/Section 优先，段落、列表、引用尽量完整，code/table 默认不拆；Chunk 不跨 Document Version boundary，并保存 heading path/page/block range。

```text
chunk_id = hash(boundary_id + chunk_release_id + block_range + normalized_text_hash)
embedding_id = hash(chunk_or_note_id + embedding_release_id)
```

检索基线：

```text
BM25 + Vector
 -> hard SOURCE/DOCUMENT/VERSION/ACL scope
 -> metadata filters
 -> RRF/controlled fusion
 -> optional relation/graph boost
 -> optional reranker
 -> candidate notes/chunks
 -> Evidence Assembler
 -> original Source Blocks
 -> answer model
 -> claim/evidence validation
```

代码符号、函数名、错误信息、版本号、RFC/CVE 等必须保留 lexical route。Vector 不能成为唯一召回通道。

Graph 是可选第三召回通道，不替代原文/BM25/Vector。只有固定 judgment set 证明增量收益后才默认开启。

### 20.1 高可信回答规则

- AI Note 可以帮助发现候选，但最终上下文优先拉回 Source Blocks；
- 每个 answer claim 尽量绑定 `document_version_id + block_id`；
- direct quote 必须来自 `VERBATIM + BOUND` Evidence；
- 只基于 AI Summary/Insight 的结果必须明确标为 derived-only，不进入高可信引用模式；
- Evidence Assembler 去重同文转载，保留不同来源 provenance。

## 23. Web 管理功能

### 23.1 Fleet Overview

展示 Source 状态、FULL_BACKFILL completion/known gap、freshness SLA、pending/leased/running/retry queue、changed documents、HTTP/Browser 比例、quality quarantine、Embedding/Graph/AI/Research/Export backlog、index lag、watermark/coverage。

### 23.4 Browser Pool

### 23.5 Adapter / Runtime

### 23.6 URL Filter 与单 URL Trace


每步查看 input/output hash、release、耗时、错误、evidence、artifact。

### 23.7 内容比较

同一 Document Version 可比较 raw HTML、cleaned HTML、Canonical IR、Canonical Markdown、Filtered/Fit Markdown、Browser 与 HTTP 候选、不同 Extractor/Adapter Release diff。

### 23.8 Derived Knowledge

### 23.10 AI Validation Quarantine

查看：

- Schema failure；
- invalid reference；
- ungrounded evidence；
- unknown target；
- invariant violation；
- repair attempts；
- replay/review 操作。

### 23.11 Relation Review

展示 SAME_WORK/REPUBLISHED/TRANSLATION/RELATED/CONTRASTS 等候选及 exact hash、canonical、embedding、title、LLM 等证据；支持 Confirm/Reject。默认不 destructive merge。

### 23.12 Annotation Review

显示内部链接/高亮 Annotation 的 source field、offset、target、input text hash、validation state；Annotation Generation 可整体切换/回滚。

### 23.13 Research Expansion

### 23.14 AI Cost & Audit

### 23.15 操作审计

暂停、恢复、重跑、REPROCESS、REINDEX、RERELATE、REDERIVE、REGROUND、RESEARCH、EXPORT、切 Release 全部走 Command API，生成 command id、actor、reason、idempotency key 和 audit log。

## 24. 安全、合规与抓取策略

### 24.1 SSRF / Egress

每跳解析 URL、验证 scheme、DNS resolve、拒绝 private/link-local/loopback/metadata IP、验证 allowed origin/domain；Redirect 与 Browser navigation/request interception 重新验证。

### 24.2 Browser Session 隔离

- tenant/source/profile 安全域隔离；
- 不跨域共享 Cookie/LocalStorage；
- Secret 只经 Secret Manager 注入；
- 日志禁止输出 Cookie、Authorization、API key；
- screenshot/HTML 按 Object Policy 管理。

### 24.3 抓取策略与版权

- robots 与站点 policy 可配置且默认尊重；
- 不默认绕过认证、付费墙或访问控制；
- per-domain rate limit；
- 保存来源 URL、抓取时间和 provenance；
- 对需要长期完整转载的第三方内容，确认版权/许可证与内部使用范围；
- Research Expansion 与 Managed Source 均使用相同合规策略；
- 自动研究发现的新域不能因为模型判断“有用”就绕过准入。

## 27. 初始容量、部署与成本隔离

按站点类型拆 Worker：

```text
静态/Feed/API 站点         -> HTTP Worker
轻度 JS                    -> HTTP + Browser fallback
重度 JS/交互               -> Browser Worker 专属队列
PDF/OCR                     -> CPU/OCR Worker
Extractor/IR                -> CPU Worker
Embedding/Graph             -> Projection Worker
AI Derivation/Grounding     -> AI Worker
Research Expansion          -> 独立预算/并发 Worker
```

起步模板，最终由压测调整：

- 每 domain 并发 1~4；
- 每 Source 并发 1~8；
- Browser Worker context/page 上限远低于 HTTP 并发；
- Browser adaptive ceiling 根据 RSS 自动收缩；
- Discovery mini-batch 100~1000 URL；
- Fetch lease window 20~200 URL；
- AI Derivation Worker 不和 Source Sync 共用不可控并发池；
- Research Worker 默认低并发，强制 run budget；
- Redis Stream backlog 只做运输观测，任务状态以 PostgreSQL 为准。

资源优先级：

```text
P0 Fresh incremental sync
P1 Full historical authoritative fetch
P2 Extract/Canonical IR
P3 Search index
P4 Derivation/Grounding
P5 Relation/Annotation
P6 Research Expansion
```

## 28. 实施阶段

### Phase 1：可用的全量历史库

Source/Profile、CMS/Sitemap/Feed/Archive Provider、URL Observation + Durable Frontier、HTTP Fetch、Snapshot、Extract + Canonical IR + Canonical Markdown、Document Identity/Version、Local/S3/Git Export、Web Source/Coverage/URL Trace、基础增量同步。

验收：30~50 个结构差异大的站点可恢复全量，Coverage 可解释，Markdown 可重建。

### Phase 2：动态站与规模化执行

Crawl4AI Browser Adapter、稳定 `FetchAdapterResult`、`arun_many(stream=True)` bounded window、Browser Pool、MemoryAdaptiveDispatcher/Semaphore 二级并发、Domain/Source permit、Interaction Recipe、Adapter fixture/canary、1000 Source 分层调度。

验收：长时间运行无明显内存爬升；Worker 重启可恢复；crawler 升级只改 Adapter；高峰 backlog 可通过背压消化。

### Phase 3：质量与检索

Extractor fixture、Quality quarantine、Filtered/Fit Markdown、Chunk/Embedding/OpenSearch、Hybrid Retrieval、Generation 切换。

验收：Canonical Markdown 完整性与检索 Projection 解耦；Filter/Embedding 升级不重新抓源站。

### Phase 4：Derived Knowledge + Evidence Grounding

Derivation Run、AI/User Knowledge Note、multi-input lineage、Knowledge Evidence、block/offset binding、Grounding Policy、AI Validation/Repair、Evidence Inspector、AI Cost/Audit。

验收：AI 输出不可修改 Source Fact；所谓 quote 无法回源时不能标为 direct quote；只基于 Summary/Insight 的派生不能进入 high-trust citable 模式。

### Phase 5：Relation + Annotation

Semantic Relation Candidate、Relation Review、可逆 UI Collapse、独立 Link Annotation Projection、Invariant Validation。

验收：相似关系误判不会导致不可逆文档合并；“只加链接”的 AI 输出若改动正文或越权 target 必须被拒绝。

### Phase 6：Bounded Research Expansion

Research Query、Search Provider Adapter、四阶段 Candidate Admission、Controlled Fetch、Novelty/Diversity、Budget/Depth/Fanout、Promote to Source。

验收：外部研究 URL 不污染正式 Coverage；标题相关但正文无关的候选会在 fetch/evidence 阶段被淘汰；预算和深度可证明终止。

### Phase 7：高级能力

Graph、n8n/MCP、Signed Webhook、高级运营分析/ClickHouse。高级能力不得反向阻塞 Source Sync 主链路。

## 29. 关键验收测试

### 29.1 全量历史与恢复

- Sitemap Index 中途 Worker 崩溃，checkpoint 从已提交 Observation 继续；
- 百万 URL 发现保持有界内存；
- Redis 丢消息可由 PostgreSQL Task/Outbox 恢复；
- Browser Worker 重启不丢平台任务；
- Provider 预算耗尽只能产生 known gap，不能错误标记 FULL_BACKFILL 完整。

### 29.2 增量同步

- ETag/Last-Modified 304 不创建新 Version；
- Feed overlap 捕获迟到文章；
- Sitemap lastmod 错误时 periodic reconcile 仍可发现真实变化；
- 404/410 保留历史版本。

### 29.3 Adapter 与 Markdown

- crawler runtime 升级固定 fixture old/new diff；
- 第三方字段漂移不会改变事实表 schema；
- Canonical Markdown 可从 IR 确定性重建；
- fit markdown 不能覆盖 canonical。

### 29.4 Insight Provenance 与 Quote Binding

构造：

- 原文逐字引用；
- 中间用 `...` 收紧的 excerpt；
- 删除口头语后的 transcript；
- 模型 paraphrase；
- 完全不存在于原文的伪 quote。

验证：

- 逐字引用可标 `VERBATIM + BOUND`；
- transcript 清理只能标 `NORMALIZED_TRANSCRIPT`；
- paraphrase 不渲染为 quote；
- UNBOUND 不能进入 citable 通道；
- 新 Document Version 不静默覆盖旧 Evidence。

### 29.5 Derived-on-Derived Drift

只输入 Article Summary + Insight，不输入 Source Block，让模型生成“quote”。系统必须拒绝标为 source-grounded。

通过 Evidence Assembler 补回原文 block 后才允许进入高可信回答。

### 29.6 Structured Output Repair

- 首次 JSON schema 失败，第二次修复成功；
- 连续失败超过 repair 上限；
- schema 通过但 reference 不存在；
- schema 通过但 evidence 无法绑定；
- schema 通过但 semantic invariant 失败。

验证失败进入 quarantine，不无限重试。

### 29.7 Annotation Invariant

模拟“只增加内部链接”：

- 只加合法 target 的链接 -> 通过；
- 偷改一个词 -> 拒绝；
- 指向 whitelist 外 target -> 拒绝；
- offset 重叠/markup 损坏 -> 拒绝；
- rebuild Annotation 不改变 Note base content hash。

### 29.8 Relation Safety

构造同文转载不同标题、同标题不同正文、同主题相反观点、多语言翻译等 fixture。验证 embedding/title/LLM 只产生 relation candidate；只有稳定 Identity Evidence 才可影响身份。

### 29.9 Research Admission 与 Budget

- 标题高度相关但正文无关的候选，Stage 0 可进入，Stage 2/3 后必须拒绝；
- 达到 max depth、max URLs、max domains、max cost 后明确停止；
- 同域过多被 diversity policy 抑制；
- External Candidate 不计入 Managed Source Coverage。

### 29.10 AI Release Replay

升级 Prompt/Model/Grounding Policy 后：

- 旧 derivation/evidence 保留；
- 新 generation 并行计算；
- 差异可审计；
- 切 Active Generation 不修改 Document Version；
- Grounding Policy 升级可只做 REGROUND，不必重新抓源站。

## 30. 最终推荐运行链路

### 30.1 全量历史

```text
Add Source
 -> PROBE
 -> Profile Review/Activate
 -> authoritative Providers
 -> stream URL Observations
 -> Durable Frontier
 -> bounded Fetch lease window
 -> platform permits
 -> HTTP or Browser Pool
 -> stable Fetch Adapter normalization
 -> per-URL Snapshot commit
 -> Extract / Quality / Canonical IR
 -> Identity / Document Version
 -> Canonical Markdown
 -> Export
 -> async Chunk/Index
 -> async Derived Knowledge
 -> async Evidence Grounding
 -> async Relation/Annotation
 -> Coverage reconcile
```

### 30.2 增量同步

```text
Feed/API cursor + overlap
 -> Sitemap Conditional GET
 -> high-yield surfaces
 -> Conditional GET / 304
 -> changed Snapshot only
 -> new Document Version only when canonical content changes
 -> rebuild affected Projections
 -> re-evaluate affected Derived Knowledge/Evidence/Relations
 -> periodic Reconcile
```

### 30.3 动态页面

```text
HTTP quality insufficient
 -> Browser route
 -> acquire domain/source permit
 -> lease/reuse Browser Pool instance
 -> worker-local adaptive dispatcher
 -> interaction recipe with hard budget
 -> normalize Crawl4AI/Playwright result through Adapter
 -> Snapshot
 -> release context/page
 -> recycle browser by policy
```

### 30.4 知识派生与证据绑定

```text
Document Version READY
 -> Derivation Run
 -> Summary / Insight / Question
 -> Schema/Reference validation
 -> Evidence Resolver
 -> block/offset binding
 -> Grounding Policy
 -> GROUNDED / PARTIAL / UNGROUNDED
 -> optional Relation/Annotation
 -> review/audit
```

### 30.5 高可信检索/RAG

```text
User Query
 -> BM25 + Vector + optional Relation
 -> candidate chunks/notes
 -> Evidence Assembler
 -> original Source Blocks
 -> answer model
 -> claim/evidence validation
 -> response with block-level provenance
```

### 30.6 主动研究

```text
Document / Insight / User Note
 -> Research Question
 -> bounded Research Expansion Run
 -> Search Provider Adapter
 -> cheap policy
 -> controlled candidate fetch
 -> relevance + novelty + diversity + evidence ranking
 -> External Research Candidates
 -> external evidence ingest
 -> explicit Promote to Source when valuable
 -> normal PROBE/Profile/Backfill
```

最终架构把“受管理站点同步”“原文事实”“检索投影”“AI 派生知识”“证据绑定”“语义关系”“展示型 Annotation”“主动研究扩展”明确分层：Coverage、Snapshot、Canonical IR、Document Version 始终是可审计事实；Markdown、Search、Embedding、Graph、AI Insight、Relation 和 Annotation 都可重建；AI 派生不得用自身递归总结冒充原文证据；任何 direct quote 必须回到 Source Block；自动研究有预算、有终止条件、有来源多样性和正文复核，并且必须显式 Promote 才能进入正式 Source 治理。这样既能支撑首期 1000 个技术博客的全量历史与增量同步，也能在后续不断增加网站、模型和研究能力时保持可扩展、可恢复、可解释。
