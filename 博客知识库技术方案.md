# 博客知识库技术方案

## 1. 建设目标与边界

建设一个长期运行、可横向扩展、可审计、可回放的技术博客知识库平台。首期接入约 1000 个技术博客、工程博客、技术文档站和公开 Newsletter，尽可能抓取完整历史文章并清洗为稳定 Markdown；后续持续增加网站，并低成本完成增量同步、版本管理、搜索/RAG、Web 管理、导出和离线重处理。

目标规模：

- 1000+ Source，可扩展到数千站点；
- 百万级 Document / Document Version；
- 数百万到千万级 URL Observation；
- 千万级 Chunk / Embedding；
- HTML、Markdown、TXT、JSON/API、RSS/Atom/JSON Feed 为主要输入，PDF/图片/iframe 为可选证据输入；
- 中英日韩等多语言；
- HTTP 为默认抓取路线，Browser 为受控 fallback；
- CMS API、Sitemap、Feed、Archive、Category/Tag、Docs TOC、URL Seeder、Common Crawl、受控 Deep Crawl 等多入口历史发现；
- PostgreSQL + Object Storage 保存事实；Markdown、全文索引、向量索引、Graph、AI 派生、Export、Dashboard Read Model 均为可重建 Projection；
- Web UI、n8n、MCP、CI、Agent、外部系统只能通过受控 API/Event 边界驱动平台。

平台必须能够回答：

1. 一个站点理论上有哪些历史文章，为什么认为历史已经基本覆盖；
2. 一个 URL 从哪里被发现、如何规范化、为何被过滤或放行、经过哪些跳转、最终抓到了什么；
3. 为什么某 URL 走 HTTP、Crawl4AI Browser 或特殊 Playwright Recipe；
4. Browser 页面最终抽取所依据的是哪个原始响应、哪个渲染后 DOM、执行了哪些等待/交互/iframe/Shadow DOM 处理；
5. 一个 Markdown 来自哪个 Snapshot、Rendered Artifact、Extractor Release 和 Document Version；
6. 源站变化后哪些内容真正变化，哪些派生物需要重建；
7. Worker 崩溃、批任务部分失败或外部自动化重启后如何恢复且不丢成功项；
8. 新增第 1001 个站点时，能否主要依靠配置、Probe 与审核接入，而不是增加站点专用代码；
9. 全量历史抓取是否有 durable checkpoint，能否从断点继续；
10. 百万 URL 批处理是否保持有界内存，并支持逐 URL 提交；
11. Browser 是否被复用且安全隔离，何时回收，是否因资源压力自动降并发；
12. Crawl4AI 等第三方 crawler 升级后，是否只修改 Adapter/Runtime Release 而不污染平台数据契约；
13. Markdown 导出到本地/S3/Git 后，是否仍能稳定映射回平台内部 Document Version；
14. 长时间 Deep Crawl 是否能由 Web 安全取消、同配置断点恢复，并保证 runtime checkpoint 丢失后业务事实仍不丢；
15. URL 发现阶段是否能走轻量 Prefetch/Seeder 路径，避免在确认正文 URL 之前支付 Markdown、媒体和 LLM extraction 成本；
16. Query/Adaptive Crawl 是否与“历史 Coverage”严格分离，避免相关性抓取被误报为全站完整；
17. iframe、Shadow DOM、动态 hydration 内容被并入正文后，能否仍保留来源与变换证据。

非目标：

- 不把“互联网搜索发现的任意 URL”自动算入正式博客源的历史 Coverage；
- 不把 Adaptive/Question-driven Crawl 的 confidence 当历史覆盖率；
- 不以模型输出替代原始 Snapshot、Rendered Artifact、Canonical IR 或人工可验证证据；
- 不把 Redis、Crawler 内部队列、Deep Crawl frontier、runtime checkpoint、n8n 执行记录当业务真相；
- 不默认绕过登录墙、付费墙、CAPTCHA 或源站明确的访问控制；
- 不把代理轮换作为绕过限流、封禁或访问策略的默认手段。

## 2. 核心设计原则

1. **Config First**：普通站点靠 Source / Site Profile / Release 接入，不修改核心代码。
2. **Coverage First**：历史完整性由 Provider Evidence、cursor、exhaustion reason 和 known gap 证明，队列为空不等于完整。
3. **Authoritative First**：CMS/API、Sitemap、Feed、Archive 优先，Seeder/Common Crawl/Deep Crawl 用于补洞和交叉验证。
4. **Discovery Before Fetch**：先发现、Observation、规范化、过滤、分类、去重，再抓正文。
5. **Discover Cheap, Fetch Expensive**：发现阶段优先 CMS/Sitemap/Feed/轻量 HTTP/URL Seeder/Prefetch，只在 URL 通过 Scope/Filter 后进入完整抓取、Markdown、媒体或 LLM extraction。
6. **Durable Streaming Frontier**：大站 URL 发现必须流式、小批持久化，禁止把全站 URL 一次性物化在内存。
7. **HTTP First, Browser Last**：静态 HTML、Feed、API、Sitemap 优先 HTTP；Browser 只处理动态正文、交互和质量 fallback。
8. **Rendered Evidence Is First-Class**：Browser 抓取必须同时保留原始网络响应与渲染后 DOM/变换证据；否则无法真正离线重放动态页面。
9. **Link Graph != Content Scope**：正文抽取可以只看 `article/main`，但 URL 发现应独立评估整页 link graph；两套作用域不能被同一 selector 隐式绑定。
10. **Adapter Is Boundary**：HTTPX、Crawl4AI、Playwright 只输出平台内部稳定契约，第三方 DTO 和版本变化不得进入事实层。
11. **Platform Permit Before Local Dispatcher**：平台 global/domain/source 配额是并发上限；Crawler 内 MemoryAdaptiveDispatcher/Semaphore/RateLimiter 只负责 Worker 内二级资源控制。
12. **Bounded Window + Stream + Commit Per URL**：Worker 只 lease 有界窗口，流式返回结果，每个 URL 成功立即落库，不等待整批完成。
13. **Snapshot First**：先保存不可变网络事实和必要的渲染事实，再做抽取、清洗、Markdown、Chunk、索引和 AI。
14. **IR First, Markdown as Projection**：Canonical IR / Document Version 是内容事实层，Markdown 可确定性重建。
15. **Canonical Before Fit**：Pruning/BM25/LLM 等有损过滤只能产生 FIT/ENHANCED Projection，绝不能覆盖 Canonical Markdown。
16. **Adaptive Research Is Not Archive Coverage**：Query-driven/Adaptive Crawl 只用于专题研究、按需补充和 RAG freshness，不参与全量历史完成判定。
17. **Reuse Browser, Isolate Session**：复用 Browser 进程降低成本，但 Cookie、LocalStorage、认证态、代理身份按 Source/Profile/安全域隔离。
18. **Deterministic Hydration**：动态站优先等待明确 selector/JS 条件，固定 sleep 仅作受控 fallback；等待规则、JS、滚动/点击都必须进入 Recipe Release。
19. **Recipe, Not Site Code**：交互、路由、Filter、Schema、Selector、Extractor、iframe/Shadow DOM 处理均声明式、版本化、可回放。
20. **Preserve Embedded Provenance**：跨域 iframe 或嵌入资源并入正文时必须保留其 URL、Snapshot/Rendered Artifact 或独立证据映射。
21. **Release Everything**：影响结果的 Profile、Adapter、Crawler Runtime、Recipe、Extractor、IR、Markdown、Chunk、Embedding、Metric、Export 均版本化。
22. **Idempotent + Recoverable**：任务有幂等键、lease、fencing token、checkpoint、retry、partial success、dead-letter。
23. **One Durable Task System**：PostgreSQL durable state + Transactional Outbox + Redis Streams 是唯一业务任务体系。
24. **Projection Is Rebuildable**：全文、向量、Graph、AI、Export、Dashboard 都可从事实层离线重建。
25. **Security on Every Hop**：起始 URL、Redirect、Browser navigation、iframe、Deep Crawl 新链接、Webhook endpoint 每跳重新做 SSRF/Egress/Scope 校验。
26. **Source Friendly**：robots、站点政策、分层限流、Retry-After 和退避优先于吞吐。
27. **Benchmark Before Switch**：Crawler Runtime、Extractor、Markdown、Embedding 等升级先固定回归，再激活。
28. **Runtime Checkpoint Is Hint, Not Truth**：Deep Crawl `resume_state`、内部 visited/pending 等只用于减少重复执行；平台 Observation、Coverage、Task、Snapshot 才是 durable 事实。
29. **Pinned Runtime Supply Chain**：Crawler/Browser 运行时必须固定 lockfile、镜像 digest、Browser 版本与安全扫描结果，禁止漂移依赖直接进入生产。
30. **Crawler Service Is Internal**：即使 Crawl4AI Docker 提供 REST/JWT，也只作为内网 Runtime；用户鉴权、RBAC、审计和幂等仍由平台 API 统一承担。

## 3. 总体架构与真相边界

```text
                     Web / REST / MCP / n8n / CI
                               │
                   API + RBAC + Idempotency
                               │
                 PostgreSQL Truth Store
 Source/Profile/Release/Run/Task/Observation/Coverage/ResearchRun
 Snapshot/RenderArtifact/Document/Version/Audit/Outbox/Export
                  │                    │
               Outbox               Query
                  │                    │
            Redis Streams        Read Models
                  │             Search/Dashboard
        ┌─────────┴──────────────┐
        │                        │
 Discovery Workers          Fetch Workers
 CMS/Sitemap/Feed/         HTTP Pool / Browser Pool
 Archive/Seeder/CC/        Crawl4AI / Playwright
 Deep Crawl/Prefetch            │
        │                      │
 URL Observation -> Durable Frontier -> Network Snapshot
                                      │
                              optional Render Artifact
                                      │
                              Extract / Canonical IR
                                      │
                ┌─────────────────────┼─────────────────┐
                │                     │                 │
       Canonical Markdown       Chunk/Search       Export Sink
                │                     │
                │                Vector/RAG
                └────────────── Derived Projections

Optional Research Workers
 Query/Adaptive Crawl -> ResearchRun -> Observation/Snapshot
                     -> never marks historical Coverage complete
```

真相边界：

```text
PostgreSQL + Object Storage      = Truth
Network Snapshot                = Immutable fetched fact
Rendered Artifact               = Immutable browser-rendered fact
Redis Streams                   = Transport
Crawler internal frontier       = Execution state only
Deep Crawl runtime checkpoint   = Execution recovery hint only
AdaptiveCrawler state           = Research execution state only
Crawler dispatcher              = Worker-local execution control only
Seeder/cache state              = Execution/cache state only
Browser/session cache           = Ephemeral execution state
OpenSearch / Vector Store       = Rebuildable Projection
Canonical Markdown              = Rebuildable Projection from IR
FIT/Enhanced Markdown           = Rebuildable Derived Projection
Dashboard Read Model            = Rebuildable Projection
n8n/MCP/Agent state             = External automation state only
```

任何派生系统故障都不得把已经成功保存的 Snapshot、Render Artifact 或 `Document Version READY` 回退成失败；任何 crawler runtime checkpoint 丢失都只能造成重复执行，不能造成已发现 URL、Coverage evidence 或 Document Version 丢失。

## 4. 技术选型

### 4.1 控制面

- **FastAPI + Pydantic**：REST/Command API、Schema 校验、Webhook Receiver、内部服务接口；
- **PostgreSQL**：Source、Profile、Run、ResearchRun、Task、Coverage、Observation、Snapshot/Render metadata、Document、Version、Release、Audit、Outbox；
- **Transactional Outbox**：保证数据库状态与异步消息发布一致；
- **Redis Streams**：consumer group、retry transport、backpressure，只做任务运输；
- **React/Next.js 或 Vue + TypeScript**：Web 管理台；
- **Docker/Kubernetes**：按 Discovery / HTTP Fetch / Browser / Extract / Projection / Research Worker 独立扩缩容。

### 4.2 抓取与解析

- **HTTPX/aiohttp**：静态 HTML、Feed、Sitemap、API、Conditional GET、Range GET、低成本 link discovery；
- **Crawl4AI**：异步多 URL 抓取、Browser、URL Seeder、Deep Crawl、Prefetch、Deep Crawl resume/cancel、Adaptive Query Crawl、iframe/Shadow DOM 处理、Markdown candidate、Worker 内 Dispatcher；
- **Playwright**：复杂 JS、滚动/点击、多步骤交互等特殊 Recipe fallback；
- **lxml / trafilatura / readability 类算法**：快速正文候选抽取；
- **PyMuPDF / pdftotext**：PDF 原生文本解析；扫描型 PDF 才进入 OCR fallback；
- **RSS/Atom/JSON Feed parser、XML Sitemap parser**：权威发现入口。

### 4.3 存储与检索

- **S3/MinIO**：原始响应、渲染 DOM/MHTML、HTML/PDF、Snapshot blob、Canonical IR、导出包、超大 runtime checkpoint 可选对象；
- **OpenSearch**：BM25、字段过滤、聚合、短语/代码/错误信息检索；
- **pgvector**：首期向量检索；规模扩大时通过 Vector Adapter 替换 Qdrant/Milvus；
- **PostgreSQL JSONB**：配置、evidence、quality metrics、小型 checkpoint 与结构化数据。

## 5. Crawler Adapter 与 Runtime Release

Crawler 不直接暴露给业务层，统一通过稳定接口：

```text
CrawlerAdapter
  probe(url, profile) -> ProbeResult
  fetch_one(task, profile) -> FetchResult
  fetch_many(tasks, profile) -> AsyncIterator[FetchResult]
  discover(seed, profile, checkpoint?) -> AsyncIterator[DiscoveryObservation]
  research(seed, query, profile, state?) -> ResearchResult
  cancel(run_id) -> CancelResult
  capabilities() -> CapabilitySet
```

`CapabilitySet` 至少描述：

```text
HTTP_FETCH
BROWSER_RENDER
RENDER_ARTIFACT_CAPTURE
JS_INTERACTION
IFRAME_PROCESS
SHADOW_DOM_FLATTEN
STREAMING_BATCH
DEEP_CRAWL
DEEP_CRAWL_RESUME
RUN_CANCELLATION
PREFETCH_DISCOVERY
SITEMAP_SEEDING
COMMON_CRAWL_SEEDING
ADAPTIVE_QUERY_CRAWL
MARKDOWN_CANDIDATE
STRUCTURED_EXTRACTION
PROXY
SESSION_REUSE
```

`crawler_runtime_release`：

```text
id
adapter_name
adapter_version
crawl4ai_version
playwright_version
chromium_version
docker_image_digest
lockfile_digest
sbom_digest
image_signature
security_scan_json
config_schema_version
benchmark_result_json
status              DRAFT | TESTED | ACTIVE | RETIRED
activated_at
```

禁止生产环境无审核 `pip install -U`、漂移的 `latest` 镜像或未固定 Browser 版本。新 Runtime 先对 Golden Corpus 比较抓取成功率、Rendered DOM 稳定性、Markdown diff、代码/表格保留率、iframe/Shadow DOM、Browser crash、内存峰值、429/重试、Deep Crawl resume/cancel、Prefetch、Adaptive Crawl 和安全扫描，再做小流量 canary，最后激活。

Crawler Docker REST/JWT 仅用于平台内部服务间调用；公网用户不得直接获得 Runtime endpoint。

```text
research_run
  id
  source_id
  query
  query_hash
  strategy           STATISTICAL | EMBEDDING | CUSTOM
```

## 7. 新站点接入与 Probe

新增 Source 先执行 `PROBE`：

1. DNS/TLS/robots/redirect/egress 安全检查；
2. 探测 `sitemap.xml`、robots 中 sitemap、RSS/Atom、JSON Feed；
3. 识别 WordPress、Ghost、Substack、自建 CMS、静态站、文档框架等特征；
4. 探测公开 CMS API、分页方式、Archive/Category/Tag；
5. 抽样 10～30 个正文 URL，比较 HTTP 抽取与 Browser 抽取质量；
6. 检测 JS shell、hydration、Shadow DOM、iframe、滚动/点击、Load More；
7. 对动态样本重复抓取 2～3 次，检查 Rendered DOM 稳定性与等待条件；
8. 优先寻找明确 `wait_for` selector/JS 条件，避免盲目依赖固定 sleep；
9. 探测未知链接区域是否适合 HTTP link discovery、URL Seeder 或 Crawl4AI Prefetch Deep Crawl；
10. 分离“content target selectors”和“link discovery scope”；
11. 形成 Source Profile 草稿；
12. dry-run 只产生 Observation/Preview/Artifact Preview；
13. Web UI 审核后激活 Profile Release。

典型配置：

```yaml
source:
  allowed_hosts: [example.com, www.example.com]
  include_paths: [/blog/, /posts/]
  exclude_paths: [/tag/, /author/, /search/, /login/]

discovery:
  providers:
    - {type: cms_api, priority: 10, required: true}
    - {type: sitemap, priority: 20, required: true}
    - {type: feed, priority: 30}
    - {type: archive, priority: 40}
    - {type: common_crawl, priority: 80, mode: gap_only}
    - {type: deep_crawl, priority: 90, mode: gap_only, strategy: bfs, prefetch: true, max_depth: 3, max_pages: 5000}

fetch:
  mode: AUTO
  requests_per_second: 0.5
  max_concurrency: 2
  browser_fallback: true

browser_recipe:
  wait_for: "css:article"
  process_iframes: false
  flatten_shadow_dom: false
  scan_full_page: false

extract:
  target_elements: [article, main]
  remove_selectors: [nav, footer, .newsletter-signup]
```

所有规则属于版本化 Release。Deep Crawl 的 start seed、strategy、depth/page limit、Filter/Scorer、allowed scope、prefetch 都进入配置 fingerprint；Browser 的 wait/interactions/iframe/Shadow DOM 同样进入 Recipe fingerprint。

## 8. 全量历史发现与 Coverage 证明

### 8.1 Provider 优先级

1. CMS/API；
2. Sitemap/Sitemap Index；
3. Feed；
4. Archive/年月页/分页列表；
5. Category/Tag、Docs TOC；
6. Crawl4AI URL Seeder / Common Crawl 历史索引补洞；
7. 受控 Deep Crawl 最后补洞。

### 8.2 两阶段：Discover -> Fetch

```text
Discover Stage
 CMS/Sitemap/Feed/Archive/Seeder/CC/Deep
 -> cheap discovery / prefetch where appropriate
 -> URL Observation
 -> normalize/scope/filter
 -> dedupe
 -> durable frontier

Fetch Stage
 eligible URL
 -> HTTP First
 -> Browser fallback
 -> Snapshot
 -> optional Render Artifact
 -> Extract/IR/Markdown
```

Deep Crawl、Prefetch、URL Seeder 只能产生 Observation，不能绕过平台 Filter/Scope 直接把任意站内链接当正文抓取。

### 8.3 Durable Streaming Frontier

```text
fetch provider page / discovery window
 -> parse items/links
 -> upsert observation in small batch
 -> persist provider cursor/checkpoint
 -> enqueue eligible URL task
 -> commit
 -> next page/window
```

### 8.4 Deep Crawl：恢复、取消与 Prefetch

```text
BFS        = 广度 gap discovery 默认
DFS        = 受控深层 archive/path 探测
BestFirst  = 相关性/预算优先探索，不用于证明完整 Coverage
```

恢复：

```text
on_state_change
 -> coalesce runtime state
 -> every N URLs or T seconds persist execution checkpoint
 -> Observation commits independently

restart
 -> compare source/profile/runtime/strategy fingerprint
 -> same: resume_state
 -> mismatch: discard runtime checkpoint and restart from seed
 -> Observation idempotency absorbs repeats
```

取消：

```text
Web/API cancel
 -> discovery_run = CANCEL_REQUESTED
 -> should_cancel checks external run status
 -> finish current safe boundary
 -> flush execution checkpoint
 -> run = CANCELLED
```

Prefetch：

```text
prefetch=true
 -> HTML + fast link extraction
 -> skip markdown/content scraping/media/LLM extraction
 -> Observation
```

### 8.5 Link Graph 与正文抽取作用域分离

动态或复杂页面经常需要 `target_elements/css_selector` 只保留正文，但这不意味着发现阶段只能看到正文里的链接。平台应分别配置：

```text
content_scope
  article/main selectors

link_discovery_scope
  full page by default
  + independent allow/deny/filter rules
```

这样既能获得干净正文，又不会因为正文 selector 过窄而漏掉 archive/navigation 中指向历史文章的链接。

### 8.6 Coverage 完成条件

`BACKFILL COMPLETE` 至少满足：

- required authoritative provider 明确耗尽；
- provider cursor/checkpoint 已持久化；
- known gap 为空或有人工接受理由；
- discovered/allowed/fetched/filtered/failed 数量可核对；
- 对年份、月份、分页边界做交叉验证；
- Common Crawl/Deep Crawl 补洞不会发现大量新正文；
- robots/policy/长期失败 URL 被单独计为可解释缺口；
- Deep Crawl 的 stop reason、max depth/max pages/cancelled 等截断原因明确记录；
- BestFirst、score threshold、Adaptive Crawl confidence、max_pages 等选择性策略没有被误标为“全站耗尽”。

## 9. Query/Adaptive Crawl 的独立定位

Crawl4AI 的 Adaptive/Question-driven Crawl 适合“围绕一个 query 收集足够信息”，其停止依据是 coverage/consistency/saturation/confidence，而不是全站 URL 穷尽。因此仅用于：

- RAG 查询发现知识库缺口后的按需补充；
- 专题研究或竞争情报；
- 文档站中围绕主题的低预算探索；
- 运营人员手工触发的临时 freshness 调研。

不用于：

- 全站历史归档；
- required provider Coverage 证明；
- 日常固定增量默认路径。

执行链：

```text
ResearchRun(query, page_budget)
 -> Adaptive Crawler
 -> selected URL observations
 -> platform scope/filter
 -> normal Fetch/Snapshot/Render/Extract chain
 -> research metrics stored on ResearchRun
 -> never set coverage_state.is_exhausted
```

Adaptive runtime state 与 Deep Crawl checkpoint 一样只用于执行恢复，可丢弃重建。

## 10. URL 规范化、过滤与身份

默认规则：scheme/host 小写、去 fragment、规范默认端口、删除明确追踪参数；query 删除/排序按 Source Profile 配置，避免全局激进处理。

Filter：

```text
HARD           永不抓：登录、搜索结果、管理页
SOFT           默认不抓，可规则/人工覆盖
DEPRIORITIZE   可抓但低优先级：Tag 聚合页
ALLOW          正常正文抓取
```

每次决定保存 `filter_release_id + reason + evidence`。Crawler 自带 URLPatternFilter/DomainFilter/Scorer 只能做前置执行优化，最终 Filter 决策仍由平台版本化规则完成。

requested URL、final URL、canonical URL 分开保存；`<link rel=canonical>` 只是身份判断证据之一，跨域 canonical 必须审核。

## 11. Durable Task、幂等与恢复

PostgreSQL 保存 durable Task state；Transactional Outbox 同事务写事件；Publisher 投递 Redis Streams；Worker 用 consumer group 消费。Redis 丢失可从 PostgreSQL 重建运输队列。

```text
PENDING -> LEASED -> RUNNING -> SUCCEEDED
                    |          -> PARTIAL
                    -> RETRY_WAIT -> PENDING
                    -> QUARANTINED
                    -> DEAD
```

Worker 领取任务获得 `lease_until + fencing_token`。超时后新 Worker 可重新 lease；旧 Worker 即使恢复，也不能用过期 token 覆盖新结果。

幂等键：

```text
DISCOVER: source + provider + release + cursor/window
OBSERVE: source + provider + normalized_url + evidence identity
FETCH: source + normalized_url + sync_run
RENDER: snapshot + recipe_release + runtime_release
EXTRACT: source_artifact + extractor_release
MARKDOWN: version + markdown_release + projection_type
EMBED: chunk + embedding_release
EXPORT: export_spec_hash + release
RESEARCH: source + query_hash + profile_release + budget/run
```

## 12. 抓取路由、动态渲染与可回放证据

### 12.1 FetchMode

```text
AUTO
HTTP_ONLY
BROWSER_REQUIRED
RECIPE_REQUIRED
```

AUTO：

```text
CMS/API/Feed/Sitemap -> HTTP
static HTML          -> HTTP -> extraction quality gate
PDF/file             -> HTTP stream -> Snapshot -> parser
JS shell/low quality -> Crawl4AI Browser
special interaction  -> Playwright/Crawl4AI Recipe
```

### 12.2 Browser 路由必须保存两层事实

动态网页的“网络响应 HTML”与“JavaScript 执行后的 DOM”可能完全不同。若只保存最初 HTML，后续离线 Extractor 无法重现 Browser 当时看到的正文。因此 Browser 成功链必须是：

```text
navigate
 -> save network response metadata/body when available
 -> execute versioned wait/interactions
 -> capture final rendered DOM
 -> optionally capture MHTML/screenshot for evidence/debug
 -> persist Snapshot + RenderArtifact
 -> only then emit ARTIFACT_READY
```

Extractor 明确读取 `render_artifact.rendered_dom_object_key`。Rendered Artifact 不替代网络 Snapshot，而是同一次 fetch attempt 的第二层事实。

### 12.3 Hydration 与确定性等待

优先级：

1. 明确 selector/JS predicate；
2. 明确应用事件或 DOM 状态；
3. `wait_until` 类通用页面状态；
4. bounded fixed delay 最后 fallback。

Recipe 必须记录：`wait_for`、`wait_until`、delay、js_code、滚动/点击、viewport、locale/timezone、iframe/Shadow DOM 选项。对重复抓取结果做 DOM/正文稳定性比较，防止“偶然早抓”制造假版本。

### 12.4 iframe 与 Shadow DOM

- `process_iframes` 只在确有正文需要时开启；
- 跨域 iframe 每跳做 SSRF/Egress/Scope 校验；
- 被内联的跨域 iframe 尽量单独保存 child Snapshot/Artifact；
- `flatten_shadow_dom` 属于 DOM 变换，必须进入 transform manifest 和 Recipe Release；
- Shadow DOM flatten 后 IR block 仍保留 locator/provenance；
- iframe/Shadow DOM 处理失败时允许退化为引用链接，不应悄悄丢失来源。

### 12.5 有界多 URL 流式执行

Crawl4AI `arun_many/fetch_many` 只处理 Worker 已 lease 的 20～100 条有界窗口：

```text
lease bounded tasks
 -> acquire global/domain/source permits
 -> crawler streaming batch
 -> each result immediately persist Snapshot/Artifact or retry
 -> release permits
```

成功结果逐 URL 提交，长尾或失败 URL 不拖住已完成项。

## 13. Dispatcher、Browser 复用与运行指标

分层 Permit：

```text
global concurrency
 -> domain concurrency/rate
 -> source concurrency/rate
 -> worker-local MemoryAdaptiveDispatcher/Semaphore/RateLimiter
```

Worker Local Dispatcher 解决本机内存/会话压力，不替代集群级 domain/source 限流。429/503/Retry-After 证据反馈到平台 circuit breaker。

Browser 隔离：

```text
Browser process scope = WORKER
Context scope         = SOURCE | SECURITY_DOMAIN
Page scope            = TASK
Session scope         = RECIPE_INSTANCE
```

- Browser 进程长期复用；
- Context 按 Source/安全域隔离；
- Page 默认每任务短生命周期；
- session 只用于明确顺序交互；
- Cookie/LocalStorage/认证态/代理身份不得跨 Source；
- page 数、RSS、任务数、运行时间到阈值主动 recycle；
- 下载、弹窗和外部导航受 egress policy 限制。

`fetch_attempt` 持久化：

```text
dispatcher_wait_ms
dispatcher_active_peak
process_rss_peak_mb
browser_pages_peak
browser_recycle_count
local_throttle_count
route
adapter_release_id
render_capture_ms
rendered_dom_bytes
```

## 14. 内容解析、Canonical IR 与 Markdown

### 14.1 多候选 Extractor

```text
site selector candidate
trafilatura candidate
readability candidate
lxml/Crawl4AI candidate
DOM density candidate
```

统一质量评分：正文长度、标题一致性、链接密度、导航污染、代码块保留率、表格完整性、时间/作者命中、语言异常、iframe/shadow content 完整度。

Extractor 从 Snapshot/Render Artifact 离线读取，不重新访问源站。

### 14.2 IR

```text
DocumentVersion
  metadata
  blocks[]
    heading(level, text, provenance)
    paragraph(text, provenance)
    code(language, exact_text, provenance)
    list(items, provenance)
    table(cells, provenance)
    quote(text, provenance)
    image(src, alt, caption, provenance)
```

Markdown 是 IR 的确定性 Renderer。

### 14.3 三种 Markdown Projection

```text
CANONICAL_MARKDOWN
  完整正文，由 Canonical IR 确定性生成；默认展示、导出和事实引用。

FIT_MARKDOWN
  Pruning/BM25/LLM 等有损过滤；用于检索、摘要或 query-specific context。

ENHANCED_MARKDOWN
  可叠加内部链接、标注或展示增强；不能替代事实版本。
```

Crawl4AI raw/cleaned/fit Markdown 可作为候选、回归对照或派生实现，但不得绕过 Snapshot/Render Artifact/IR 直接成为不可追溯事实。

Canonical Markdown：标题层级稳定、代码块保留原始空白、表格稳定则 GFM 否则保留 HTML block、相对链接转绝对链接、图片保留原 URL/alt/caption、去导航/广告/Cookie banner，但不把 AI 摘要写入 canonical。

导出：

```text
knowledge/sources/{source_slug}/{yyyy}/{slug}--{document_id}.md
```

Front Matter 至少含 `document_id/version_id/source_artifact_id/source_url/canonical_url/title/author/published_at/fetched_at/content_sha256`。

## 15. 增量同步、版本与删除检测

优先使用：

1. CMS API `updated_at` / cursor；
2. Sitemap `lastmod`；
3. Feed entry id/guid/published/updated；
4. Archive 最近若干页；
5. 定期低频 Coverage Verify / Deep Crawl 补洞。

每个 Provider 单独保存 checkpoint，不能只有一个模糊的 `last_sync_time`。

Conditional Fetch：

```text
304
 -> update observation/fetch evidence
 -> no new Version

200 + raw body hash same
 -> no render/extract unless recipe/runtime explicitly requires verify

200 + raw body changed
 -> HTTP route: extract
 -> Browser route: render and compare rendered artifact
 -> canonical content hash same: template/ads/noise change
 -> canonical content hash changed: create new Version
```

动态站可能出现“raw HTML 基本相同，但 API/JS 渲染正文变化”，因此 Browser-required Source 不能只用 raw body hash 决定跳过渲染；应结合 Source Profile、ETag/API evidence、历史 render fingerprint 制定条件策略。

删除：

```text
ACTIVE -> SUSPECT_MISSING -> MISSING
       -> ACTIVE（再次出现）
```

综合 Sitemap/CMS 消失、连续 404、redirect/迁移证据判断，历史 Artifact 按生命周期策略保留。

## 20. 安全、合规与源站友好

### 20.1 SSRF/Egress

用户输入 URL、HTTP redirect、Browser navigation、Deep Crawl 新链接、iframe、附件 follow link、Webhook callback 每跳都重新解析和校验：阻止 loopback、link-local、RFC1918、metadata endpoint、未允许端口/协议，并防 DNS rebinding。

### 20.2 Browser/嵌入内容

- 跨域 iframe 单独做 Scope/Egress；
- Shadow DOM flatten、JS 注入和交互只运行版本化 Recipe；
- Browser 禁止任意文件系统访问；
- 下载目录隔离并限大小；
- Rendered DOM/HTML 展示做 XSS sanitize；
- iframe 内联后仍保留来源，不允许把第三方内容无标记伪装成主站正文。

### 20.3 Proxy/Anti-bot 边界

Crawler 可能提供代理轮换、anti-bot retry、undetected browser 等能力，但平台默认策略是：

- 429/Retry-After：减速与退避；
- 403/CAPTCHA/明确策略阻断：进入 `POLICY_BLOCKED` 或人工审核；
- Proxy 仅用于组织批准的出口故障切换、地域访问测试或隐私网络策略；
- 不用代理轮换规避源站限流、封禁、登录墙、付费墙或访问控制。

### 20.4 运行时与服务边界

- Secret 使用 Vault/K8s Secret；
- Crawler Docker Runtime 仅内网暴露，平台 API 是唯一外部入口；
- 即使 Runtime 自带 JWT，也不能替代平台 RBAC、审计、速率限制与 tenancy；
- 容器最小权限、只读根文件系统、受控 egress；
- 固定 lockfile、镜像 digest、SBOM 与扫描结果；
- Runtime 安全回归失败不得激活。

开启 object versioning/生命周期策略。Runtime checkpoint/Research state 有 TTL，因为它们不是业务事实；Snapshot、Render Artifact、Document Version 按数据保留政策管理。

## 24. 部署与横向扩展

Worker 分池：

```text
discovery-worker
http-fetch-worker
browser-fetch-worker
research-worker
extract-worker
projection-worker
embed-worker
export-worker
```

Browser、Embedding、HTTP、Discovery、Research 的资源模型不同，必须独立扩缩容。Crawl4AI 可作为固定镜像内部执行服务，也可嵌入 Browser/Discovery Worker；无论哪种方式都不保存平台业务真相。

Kubernetes HPA 指标：queue lag、CPU、memory、Browser slots、dispatcher pressure、discovery lag、research budget usage，而不只看 CPU。

1000 Source 原则：

- 默认每域低并发；
- 横向增加不同域名 Worker，不提高单站攻击性并发；
- Backfill 和 Incremental 使用不同 priority，增量优先；
- Browser Pool 与 HTTP Pool 分开；
- 大站 discovery/fetch 全程有界窗口；
- 动态站 Render Artifact 写对象存储，避免 PostgreSQL 大字段；
- Adaptive Research 使用独立低优先级/预算池，不能挤占增量同步 SLA；
- 每 Source 可独立暂停、取消、恢复、限流、重跑和回滚 Profile。

初始压测基线：

```text
HTTP fetch slots:     50~200 / cluster
Browser pages:        10~40 / cluster
per-domain HTTP:      1~4
per-domain Browser:   1~2
worker lease window:  20~100 URLs
deep checkpoint:      every 20~100 URLs or 5~30s（压测后定）
```

真正上限由源站策略、429、延迟、内存和 Browser crash 数据自动调小。

## 26. 失败模式与降级

- Redis 不可用：暂停运输，PostgreSQL Task 保持真相，恢复后重发 Outbox；
- Object Storage 不可用：不得把网络/渲染抓取标记为持久成功；
- PostgreSQL 不可用：Worker 停止领取新任务；
- Browser crash：单 URL/小窗口重试，必要时 recycle Worker；
- Rendered DOM 捕获失败：保留网络 Snapshot，标记 Browser artifact failure，不伪装成抽取成功；
- wait 条件长期不满足：按 Recipe fallback/超时策略处理并保存失败证据；
- iframe 抓取失败：保留主文档和引用证据，child 标记失败；
- Shadow DOM flatten 失败：可退化为普通 DOM，质量门判断是否 Quarantine；
- 大量 429/503：domain/source circuit breaker + Retry-After + jitter backoff；
- 403/CAPTCHA：POLICY_BLOCKED/人工审核，不自动升级为绕过模式；
- Extractor 质量下降：Version 进入 Quarantine，保留 Artifact，可切旧 Extractor 离线重跑；
- Runtime 升级回归/扫描失败：保持旧 ACTIVE Release；
- Deep Crawl 爆炸：max depth/max pages/max wall time/max external domains 截断并记录 stop reason；
- Deep Crawl checkpoint 丢失：从 seed 重跑并幂等去重；
- Checkpoint fingerprint 不匹配：拒绝旧 resume_state；
- 用户取消：完成安全边界后停止、flush checkpoint、Run 标记 CANCELLED；
- Adaptive state 丢失：ResearchRun 从 seed/query 重启，已进入事实链的数据不丢；
- Adaptive confidence 很高：仍不能标记 Source Coverage 完整。

## 27. 实施阶段与验收标准

### Phase 1：事实层与 20～50 个站点

- Source/Profile/Release；
- Sitemap/Feed/CMS/Archive Discovery；
- PostgreSQL durable Task + Outbox + Redis Streams；
- HTTP Fetch、Snapshot、Object Storage；
- 基础 IR/Canonical Markdown；
- Web Source/Run/Task/Document 页面；
- ETag/Last-Modified 增量；
- Markdown 导出。

### Phase 2：1000 站全量与动态站能力

- Durable Streaming Frontier；
- Crawl4AI Adapter + Runtime Release；
- URL Seeder/Common Crawl/Deep Crawl gap workflow；
- Prefetch、execution checkpoint、fingerprint、cancel/resume；
- Browser Pool/Session 隔离/MemoryAdaptiveDispatcher；
- Network Snapshot + Render Artifact 双层事实；
- deterministic hydration Recipe；
- iframe/Shadow DOM provenance；
- Coverage Evidence/Gap Dashboard；
- 多候选 Extractor + Golden Corpus；
- Canonical/FIT Markdown 分层；
- Runtime lockfile/SBOM/image digest/security scan；
- OpenSearch/pgvector。

### Phase 3：知识检索与研究

- Hybrid RAG；
- block-level provenance；
- Query/Adaptive ResearchRun；
- 转载/翻译关系；
- Projection generation 原子切换；
- Runtime/Extractor benchmark 页面。

### Phase 4：高可用与治理

- 多副本 API/Worker；
- DB/对象存储备份演练；
- SSRF/Egress/嵌入内容安全强化；
- Deep Crawl/Browser/Research 故障演练；
- SLO、告警、成本和权限治理完善。

### 最终验收

**全量历史**：权威 Provider 有 Coverage Evidence；Worker 中断可继续；百万 URL 有界内存；Deep/Seeder/Prefetch 不绕过 Scope；BestFirst/Adaptive/max_pages 等不误报完整。

**动态页面可回放**：Browser 页面同时有 Network Snapshot 与 Render Artifact；不访问源站即可从 Rendered DOM 重跑 Extractor；wait/interaction/iframe/Shadow DOM 变换可追溯。

**增量**：新文章按 Source SLA 被发现；304 不创建新 Version；模板变化不制造大量假版本；Browser-required Source 不因 raw HTML 静态而漏掉渲染正文变化。

**Markdown**：同一 IR + Markdown Release 输出确定；Canonical 与 FIT 语义分离；任意导出可回溯到 document/version/source artifact。

**可恢复性**：Redis 清空可恢复；lease/fencing 防旧 Worker 覆盖；Deep/Adaptive runtime state 丢失只增加重复工作，不丢事实。

**扩展性**：第 1001 个站点主要通过 Probe + Profile/Recipe 接入；Crawler 升级通过 Adapter/Runtime 隔离；新 Provider/Research Strategy 可插拔。

**安全**：Crawler Runtime 不直接对公网；代理/anti-bot 能力受组织策略约束；跨域 iframe/redirect/Deep link 每跳校验；Runtime 有固定 digest/lockfile/SBOM/扫描记录。

最终系统应把“抓到网页”升级为一套可证明 Coverage、可重放网络与渲染事实、可稳定增量、可安全扩展的长期数据平台：Crawl4AI 提供异步、Browser、Deep Crawl、Adaptive Crawl、URL Seeder、Prefetch、iframe/Shadow DOM、Dispatcher 和 Markdown 候选能力，但它始终位于版本化 Adapter 与平台调度边界之后；PostgreSQL + Object Storage 保存业务真相，Durable Frontier 保证全量历史可恢复，Network Snapshot + Render Artifact 保证动态页面可回放，Canonical IR 保证 Markdown 可重建，Query-driven Research 与历史 Coverage 严格分离。
