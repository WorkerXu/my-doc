# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站与公开 Newsletter** 的长期采集与知识库平台，并能继续扩展到数千站点、百万至千万级文章。

系统必须同时满足：

1. **全历史回填**：尽可能完整发现每个已批准 Source 的历史文章，并能解释各发现通道的覆盖范围、已知缺口、截断原因与停止原因；
2. **持续增量同步**：稳定发现新文章、正文更新、URL 迁移、重定向、删除、重发布与元数据变化；
3. **稳定 Markdown**：保存不可变 Raw Artifact，经版本化抽取、候选质量门禁、Canonical IR 与确定性 Renderer 生成可重放 Markdown；
4. **低成本扩站**：新增网站优先通过 Source Profile、Provider、Extraction Recipe、Traversal Policy 配置完成，不维护 1000 份站点脚本；
5. **Web 可运营**：支持站点接入、审批、Backfill、Incremental、Coverage、Frontier、质量、成本、诊断、暂停、恢复、重跑、灰度与审计；
6. **任务可恢复**：Provider Run、Task、Attempt、URL、Artifact、Candidate、Document、Version 全链路可追踪，Worker/Runtime 崩溃后自动恢复；
7. **可搜索/RAG**：支持 BM25、向量与混合检索，并能回溯原文、版本、Source、抓取证据和抽取 Release；
8. **主链不依赖 LLM**：LLM 只做可选 Repair/Enrichment，不参与历史完整性、URL 身份、robots、正文存在性、版本真相等最终判定。

### 1.1 核心 SLO

- **Coverage**：每个 Source 均可查看 Provider Inventory、Completion Attestation、Known Gap、Backfill Stop Reason；
- **Freshness**：新文章从发布/发现到 PASS Markdown 的 P50/P95/P99 延迟；
- **TTFM**：URL 首次发现到首个可用 Markdown 的时间；
- **Extraction Quality**：标题、正文、代码块、表格、列表、链接、图片说明保留率与噪声率；
- **Reliability**：Task 成功率、Retry、DLQ、Queue Age、Lease Recovery；
- **Replayability**：相同 Raw Artifact + 相同 Release 可重放 Candidate/IR/Markdown；
- **Provider Integrity**：部分返回、缓存命中、预算耗尽不能被误报为“已完整枚举”；
- **Artifact Durability**：必须保留的 Runtime/Provider Artifact 在 TTL 到期前晋升平台对象存储；
- **Browser Efficiency**：HTTP 命中率、Browser Avoided、Pool Reuse、Browser 单文档成本；
- **Fairness**：大型 Backfill 不得长期饿死 Incremental、小站和 Repair。

### 1.2 非目标

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不默认使用个人持久 Browser Profile 或模拟真人操作绕过访问限制；
- 不把 HTTP 200、Runtime `success=true`、DOM 很长直接视为有效文章；
- 不把 Common Crawl、Wayback、搜索结果、Deep Crawl、URL Seeder 返回条数单独视为历史完整性证明；
- 不把 Crawl4AI 即时 `raw_markdown` / `fit_markdown`、LLM 摘要或任一第三方抽取器结果直接作为 Canonical Markdown；
- 不把 Redis、Runtime Queue、Seeder Cache、Browser Session、Visited Set、Search Index 当业务真相；
- 不允许普通 Web/API 用户透传任意 JS/Python、代理、CDP、服务器路径、任意原生 Seeder 配置、任意 secret 或 webhook URL。

## 2. 核心设计原则

1. **Coverage First**：先建立可解释 URL Inventory，再抓正文；
2. **Authoritative First**：官方 CMS/API、Sitemap、Feed、Archive 优先；
3. **Observation Before Selection**：发现事实先保存，再 Normalize/Scope/Classify/Dedup；
4. **Successful Return != Provider Complete**：正常返回、非空结果、cache hit、`status=valid` 都不能自动代表 Provider 完成；
5. **Completion Must Be Attested**：只有具备可验证结束语义的 Provider Adapter 才能声明完成；
6. **Discovery / Fetch / Extract / Quality / Canonicalize / Projection 分离**；
7. **HTTP First, Browser Slow Lane**；
8. **Snapshot First**：先保存不可变 Provider Evidence / Raw Artifact；
9. **Candidate Portfolio, Not Single Extractor**：多个确定性候选互相校验；
10. **Canonical IR First, Markdown as Projection**；
11. **Recipe, Not 1000 Site Scripts**；
12. **Persistent Frontier, Not In-Memory Traversal**；
13. **Idempotent + Recoverable**：幂等键、Lease、Fencing Token、Checkpoint、Inbox/Outbox；
14. **Fair by Default**：Incremental、Provider Revalidate、Repair 必须预留容量；
15. **Bounded Concurrency Everywhere**：任务数、在途请求、结果集合、Browser 和进程生命周期均有硬边界；
16. **No Silent Degradation**：过滤、截断、预算耗尽、partial result、cache fallback、降级必须有 typed reason；
17. **Correlate by Identity, Never by Position**；
18. **Config Is Capability**：高能力配置统一经过 Capability Firewall；
19. **Runtime Is Execution Plane**：第三方 Runtime 不拥有 Coverage、Identity、Document 或 Markdown 真相；
20. **Behavior Beats Naming**：生产语义以 pinned release + Contract Test 为准，不以参数名或宣传语推断；
21. **Runtime Artifact Is Ephemeral Until Promoted**；
22. **Result Transport Is Not State Store**；
23. **Drain/Replace Before In-Place Kill**；
24. **Zero Must Not Mean Unbounded by Accident**；
25. **External Historical Index Is Evidence**：Common Crawl、Wayback 可显著补洞，但单独不能证明全历史完整。

- **Redis Streams**：Durable Task Transport；

- **React/Next.js + TypeScript**：Web 管理后台；
- **S3/MinIO**：不可变对象存储；
- **OpenTelemetry + Prometheus + Grafana + Structured Logging**；
- **Vault/KMS/Secret Manager**：secret 引用；
- **Nginx/Envoy/API Gateway**：TLS、请求体上限、Rate Limit、Correlation ID。

### 4.2 Discovery / Fetch

- **httpx/aiohttp**：CMS API、robots、Sitemap、Feed、Conditional GET、普通网页；
- **RFC 9309 Robots Engine**；
- **平台原生 SitemapProvider**：显式 sitemap URL、robots sitemap、Conditional GET、Sitemap Index durable shard；
- **平台原生 CommonCrawlIndexProvider**：显式固定 `cc_index_id`、流式查询、Evidence 与 Checkpoint；
- **Crawl4AI AsyncUrlSeeder pinned release**：best-effort Sitemap/CC bulk discovery、metadata probe；
- **Crawl4AI pinned release/image digest**：JS Render、复杂页面、Deep/Adaptive gap discovery、自托管 Browser Runtime、Markdown Candidate；
- **Playwright**：必要时作为受控慢路径；
- **Wayback Adapter**：历史补洞证据；
- **PyMuPDF/pdftotext**：PDF，扫描件再进入 OCR 慢路径。

### 4.3 Extraction / Search

- **Trafilatura**：Generic Candidate；
- **lxml/BeautifulSoup**：DOM/XPath、Metadata、Repair；
- **JSON-LD/OpenGraph/Microdata**；
- **CSS/XPath/Regex Recipe**；
- **Crawl4AI DefaultMarkdownGenerator + PruningContentFilter**：Markdown Candidate，不直接作为 canonical；
- **SimHash/MinHash**：近重复检测；
- **OpenSearch BM25 + pgvector + RRF**；
- embedding/reranker/LLM 仅作可选增强。

## 5. Source 接入与配置模型

新增站点使用声明式 Source Profile：

```yaml
source:
  name: example-tech-blog
  entry_url: https://example.com/blog/
  approved_hosts: [example.com]
  allowed_paths: [/blog/]
  denied_paths: [/login/, /account/]
  timezone: UTC

providers:
  - type: sitemap
    url: https://example.com/sitemap.xml
    conditional_get: true
  - type: rss
    url: https://example.com/feed.xml
  - type: archive
    start_url: https://example.com/blog/archive/
  - type: common_crawl_index
    purpose: historical_gap
  - type: crawl4ai_url_seeder
    purpose: discovery_acceleration
    modes: [sitemap, cc]

fetch:
  mode: auto
  http_timeout_s: 20
  max_response_bytes: 15000000
  browser_profile_class: public-default
  browser_intent:
    render_js: true
    scroll: bounded
    wait_selector: article

extract:
  recipe: generic_article_v3
  content_selectors: ["article", ".post-content"]
  exclude_selectors: ["nav", "footer", ".related"]
  markdown_candidate:
    pruning:
      threshold_type: dynamic
      threshold: 0.48
      preserve_tags: [pre, code, table, blockquote]
      preserve_classes: [highlight, codehilite, mermaid, math]

incremental:
  feed_poll: 10m
  sitemap_poll: 1h
  archive_reconcile: 1d
  full_reconcile: 7d
```

### 5.1 Capability Firewall

Web/API 用户只提交 intent，禁止透传：

- 任意 `js_code` / Python；
- 任意 proxy / CDP / `user_data_dir`；
- 任意 cookies、secret、服务器 path；
- 任意 LLM base URL / webhook destination；
- 未审批的 Seeder/Common Crawl query；
- 无硬上限的 `concurrency` / queue / time / result budget；
- `0=unbounded` 的配置；
- 不受控 deep crawl strategy；
- 任意网络目标与本地文件协议。

Config Compiler 将已审批 Source Intent 编译成 Provider/Runtime Config，并记录最终能力、硬预算和拒绝原因。

### 5.2 Browser Profile Class

平台只维护少量受审 Browser Profile：

```text
public-default
public-js-heavy
public-media-light
isolated-authenticated
```

站点 selector/wait/scroll 优先放低成本 CrawlerRunConfig/Recipe。只有改变浏览器进程能力、网络边界或 credential scope 才新建 Browser Profile Release。

## 7. 历史 URL 发现与 Coverage

### 7.1 Provider 优先级

优先使用能明确分页/结束语义的 Provider：

1. CMS/官方内容 API；
2. Native Sitemap / Sitemap Index；
3. RSS/Atom；
4. 官方 Archive / Category / Pagination；
5. Native CommonCrawlIndex；
6. Wayback Gap Provider；
7. Crawl4AI URL Seeder；
8. Domain Mapping / Deep Crawling / Adaptive Crawling 作为 gap discovery。

后四类可补洞，但不能单独声明 Source 全历史完整。

### 7.2 Completion Attestation

Provider Run 只有满足 Adapter 定义的终止契约才允许 `completion_attested=true`。

典型终止原因：

```text
EXHAUSTED_CURSOR
EXHAUSTED_PAGE_RANGE
SITEMAP_INDEX_COMPLETE
ARCHIVE_END_REACHED
EMPTY_PAGE_CONFIRMED
BUDGET_EXHAUSTED
TIME_LIMIT
RATE_LIMIT_ABORT
ROBOTS_BLOCKED
PARTIAL_PROVIDER_RESULT
REMOTE_ERROR
MANUAL_STOP
```

只有前一组“可证明完成”的原因计入 completion；预算、时间、限流、异常必须保留为 Known Gap。

### 7.3 Provider Evidence

每个 Provider Run 保存：

- 请求参数和 Release；
- 响应摘要或不可变原始 Evidence；
- cursor/page/checkpoint；
- 返回条数；
- 过滤前后条数；
- terminal reason；
- truncation/partial 标记；
- 时间范围与 URL 范围。

Coverage 页面展示 Provider 交集/差集，不能只给一个“已完成”绿灯。

### 7.4 Backfill 完成判定

一个 Source 的 Backfill 可进入 `COMPLETE_WITH_GAPS` 或 `COMPLETE`：

```text
COMPLETE:
  authoritative providers exhausted
  + required reconciliation finished
  + no unresolved critical gaps

COMPLETE_WITH_GAPS:
  providers exhausted where possible
  + gaps explicitly typed and accepted
```

永远不使用“连续 N 页没有新 URL”作为唯一完整性证明；它最多是 heuristic stop，必须显示原因。

## 8. URL Normalize、Scope 与去重

处理顺序固定：

```text
Observed URL
 -> parse/validate
 -> absolute URL
 -> scheme/host normalization
 -> remove fragment
 -> tracking parameter policy
 -> path normalization
 -> Source Scope Gate
 -> canonical/redirect evidence
 -> URL Identity
```

规则必须 Release 化，避免升级 URL 归一化后静默合并或拆分历史身份。

### 8.1 去重层级

- URL exact identity；
- redirect/canonical cluster；
- content hash exact duplicate；
- SimHash/MinHash near duplicate；
- semantic duplicate 只作为辅助，不替代 URL/Raw 证据。

### 8.2 迁移与重发布

若 A URL 301 到 B，或页面 canonical 指向 B：

- 保留 A 作为 alias；
- B 进入 canonical cluster；
- 不删除历史 Artifact；
- Document 是否合并由 identity policy + content evidence 决定。

## 9. 增量同步

### 9.1 信号源

```text
RSS/Atom            5-15 分钟
Sitemap             30-120 分钟
CMS API             5-30 分钟
Archive Reconcile   每日
Full Reconcile      每周/每月
Webhook             可选，仅作提示
```

Webhook 不能成为唯一真相；Reconciler 最终根据 PostgreSQL + Object Storage 证据闭合。

### 9.2 Conditional GET

HTTP Fast Lane 保存并复用：

```text
ETag -> If-None-Match
Last-Modified -> If-Modified-Since
```

304 只说明该 URL 此次未返回新实体，不代表 Source 没有新文章。

### 9.3 变化判定使用四层哈希

```text
raw_content_hash       # 网络取得的规范化原始内容
extraction_hash        # 某 extractor/filter release 的候选结果
semantic_ir_hash       # Canonical IR 的语义结构
projection_hash        # 某 Renderer 的 Markdown 输出
```

规则：

1. Raw 不变：通常无需重新抽取，除非新 Release 触发 Reprocess；
2. Raw 变、semantic IR 不变：记录抓取变化但不创建知识文档语义版本；
3. semantic IR 变：创建新 Document Version；
4. 只有 projection_hash 变：属于 Renderer 投影变化，不冒充原文更新。

### 9.4 删除判定

单次 404/5xx 不直接判删除。状态机：

```text
ACTIVE
 -> SUSPECT_MISSING
 -> RECHECKING
 -> GONE_CONFIRMED
```

结合多次时间间隔重试、Sitemap/Feed 消失、明确 404/410、redirect/canonical 证据后再确认。

## 10. Persistent Frontier、任务模型与公平调度

### 10.1 Task 不等于 Queue Message

PostgreSQL Task/Frontier 是业务状态；Redis Streams 只是运输。

```text
task
- id
- type
- identity_key
- priority_class
- state
- not_before
- lease_until
- fencing_token
- max_attempts
- payload_ref
```

幂等键示例：

```text
DISCOVER:{source_id}:{provider_release}:{shard}
FETCH:{url_identity_id}:{fetch_policy_release}:{desired_revision}
EXTRACT:{raw_artifact_id}:{extractor_release}
PROJECT:{document_version_id}:{projection_release}
```

### 10.2 Lease + Fencing Token

Worker claim 时事务性增加 `fencing_token`。任何晚到结果提交都必须携带 token；小于数据库当前 token 的结果拒绝，解决“旧 Worker 超时后又回来写入”的竞态。

### 10.3 公平队列

至少区分：

```text
P0 incremental
P1 provider_revalidate
P2 repair
P3 new_source_backfill
P4 deep_gap_discovery
P5 bulk_reprocess
```

使用 weighted fair queue / deficit round robin，并设置每个优先级最低保障，避免百万 URL Backfill 挤死增量同步。

### 10.4 全局 Admission

并发控制必须至少覆盖：

- 全平台；
- Source；
- eTLD+1/domain；
- host；
- browser profile；
- runtime instance；
- task type。

本地 dispatcher 的 memory-adaptive concurrency 只能作为实例内二级保护，不能取代跨 Worker 的全局预算。

## 11. Fetch Plane：HTTP First + Browser Slow Lane

### 11.1 HTTP Fast Lane

默认使用 httpx/aiohttp：

- robots；
- HEAD/GET；
- redirects；
- MIME；
- Conditional GET；
- gzip/br；
- response byte limit；
- connect/read/total timeout；
- retry-after；
- charset detection。

多数静态技术博客不应启动浏览器。

### 11.2 Browser Escalation Gate

只有满足受控理由才进入 Browser：

```text
JS_REQUIRED
EMPTY_STATIC_BODY
CLIENT_RENDERED_CONTENT
INTERACTION_REQUIRED_BOUNDED
STATIC_EXTRACTION_LOW_QUALITY
```

禁止“HTTP 一失败就 Browser”。DNS、TLS、robots、明确 404、超大文件、scope 拒绝等不应靠 Browser 修复。

### 11.3 Crawl4AI Runtime Service Plane

Runtime 以独立服务池运行：

```text
Runtime Gateway
 -> Config Compiler
 -> bounded micro-batch
 -> local dispatcher
 -> browser pool
 -> result materializer
 -> artifact promotion gate
```

平台通过 `runtime_request_id` / `task_id` / `url_identity_id` 关联结果，绝不按批次返回位置匹配。

### 11.4 Browser 生命周期

- 复用 browser process/context 以降低启动成本；
- auth scope 必须隔离；
- 达到页面数、内存、时间阈值后 drain/replace；
- 不在有在途任务时直接 kill；
- browser crash 只影响 Attempt，不改变业务真相；
- Runtime 本地 cache/queue 不用于恢复 Coverage。

## 13. Raw Artifact、清洗与 Extraction Portfolio

### 13.1 Raw Artifact 不可变

每次有效网络响应先晋升对象存储：

```text
raw/{source}/{url_identity}/{timestamp}/{sha256}.html
```

Manifest 记录 headers、status、final URL、fetch release、bytes、hash、timing、runtime/browser 信息。

Raw 一旦写入不原地覆盖。重新抓取得到新 Artifact。

### 13.2 Cleaned HTML 是派生 Artifact

Cleaned HTML 由 `cleaner_release` 产生，可重放，不覆盖 Raw。

清洗包括：

- script/style/noscript 等无正文节点；
- 明确站点噪声 selector；
- 安全属性标准化；
- URL absolute 化；
- DOM 修复；
- 保留代码、表格、公式、图片说明等技术结构。

### 13.3 多路 Candidate

同一 Raw 可以并行生成：

```text
site_recipe_dom
trafilatura
jsonld_article_body
crawl4ai_raw_markdown
crawl4ai_fit_pruning
crawl4ai_fit_bm25       # 默认只作诊断/query projection
llm_repair              # slow lane
```

任何单一路径失败都不污染 Raw，也不自动宣告页面无正文。

## 14. Crawl4AI Markdown Candidate 设计

### 14.1 为什么保留 raw 与 fit 两套视图

Crawl4AI `DefaultMarkdownGenerator` 可以从 HTML 生成：

```text
raw_markdown
markdown_with_citations
references_markdown
fit_markdown
fit_html
```

平台将它们视为同一个 `MarkdownCandidateManifest` 的相关 Evidence，而不是五选一：

- raw：高召回候选；
- fit：降噪候选；
- fit_html：解释过滤结果的结构证据；
- references：链接 provenance 的辅助证据。

### 14.2 PruningContentFilter 的生产定位

Pruning 本质是 DOM 子树启发式评分，综合文本密度、链接密度、标签权重、class/id 信号、文本长度后剪枝。

它适合大规模通用降噪，但不是正文完整性证明。技术站常见高风险结构：

- code/pre；
- table；
- mermaid/math；
- 短列表 changelog；
- figure/figcaption；
- 脚注和引用；
- 上下篇关系。

通过受控 Recipe 设置 `preserve_tags` / `preserve_classes`，同时必须依赖结构质量门禁防止误删。

### 14.3 BM25ContentFilter 的生产定位

BM25 是 query-conditioned relevance filter，适合搜索预览、query-time context reduction 和诊断，不默认用于“全量正文 canonical”。

如果 query 主要来自 title/h1/meta，文章中低词面相关但重要的代码、运维、回滚章节可能被删除。

### 14.4 LLM Filter

只进入 REPAIR/REVIEW 慢路径，必须保存 model/prompt release、token usage、输入输出 hash。主链不依赖 LLM。

### 14.5 异常结果防护

第三方生成器可能在异常路径返回非空错误描述。平台 Candidate Contract 必须把：

```text
status
error_code
error_message
artifact
```

分开存储；质量门禁禁止“字段非空即成功”。

## 16. Canonical IR 与确定性 Markdown Renderer

### 16.1 Canonical IR

最终真相不是第三方 Markdown 字符串，而是结构化 IR：

```text
DocumentIR
- document_id
- version_id
- source_id
- canonical_url
- title
- authors[]
- published_at
- updated_at
- language
- tags[]
- sections[]
  - heading
  - level
  - blocks[]
    - paragraph
    - code(language, text)
    - list(ordered, items)
    - table(headers, rows)
    - quote
    - image(src, alt, caption)
    - math
    - link
- references[]
- provenance[]
```

每个关键字段可保存 provenance：来自 JSON-LD、OpenGraph、DOM、Trafilatura、Crawl4AI Candidate 或人工修正。

### 16.2 Markdown Renderer

Renderer 只负责 IR -> Markdown：

- 稳定 front matter；
- 稳定标题层级；
- fenced code + language；
- GFM table；
- 统一链接/图片；
- 确定性 references 编号；
- 不按固定列宽换行；
- 统一空行；
- UTF-8；
- 文件名冲突转义与长度限制。

因此更换 Markdown 语法或 references 风格无需重新抓网页。

### 16.3 推荐 Markdown Front Matter

```yaml
---
document_id: doc_xxx
version_id: ver_xxx
source: example-tech-blog
url: https://example.com/blog/a
canonical_url: https://example.com/blog/a
published_at: 2026-08-01T10:00:00Z
updated_at: 2026-08-03T10:00:00Z
fetched_at: 2026-08-16T00:00:00Z
language: zh
raw_artifact_sha256: ...
semantic_ir_hash: ...
---
```

不把内部 secret、cookie、proxy、个人标识写入知识库文件。

## 17. Reprocess：调参不重新下载

只要 Raw Artifact 尚在，升级以下 Release 都应优先创建 Reprocess Task：

```text
cleaner_release
markdown_candidate_release
content_filter_release
extractor_release
quality_policy_release
ir_schema_release
markdown_renderer_release
```

流程：

```text
Raw Artifact
 -> old/new Candidate 并行重放
 -> Regression Diff
 -> Quality Gate
 -> New Canonical Version（仅语义变化时晋升）
```

这避免每次改 Markdown 过滤阈值都对百万 URL 重新发网络请求。

## 18. Search / RAG Projection

从 Canonical IR/Document Version 构建，可随时重建：

- OpenSearch BM25；
- pgvector embedding；
- RRF 混合；
- optional reranker；
- chunk 保留 `document_id/version_id/section_path/source/url`；
- code/table 可单独 chunk；
- references 与链接图作为附加特征。

### 18.1 Chunk 原则

- 先按 IR section/blocks 切分，不从 Markdown 任意字符位置截断；
- code block 不切碎；
- table 尽量完整；
- heading path 附加到 chunk；
- chunker_release 版本化；
- embedding 失败不影响 canonical 文档有效性。

### 18.2 删除与版本

Serving Index 只是一种 Projection：

- Index 损坏可从 Document Version 全量重建；
- 文档删除/隐藏使用业务状态驱动 tombstone；
- 不从“向量库里有没有”反推业务存在性。

## 23. 故障恢复与 Reconciler

### 23.1 Worker Crash

- Lease 到期；
- Scheduler 重新 claim；
- Fencing Token 拒绝旧结果；
- 幂等键避免重复业务写。

### 23.2 Redis 丢失

从 PostgreSQL `READY/RUNNING-but-expired` 状态重新发布运输消息。

### 23.3 Runtime Crash

Attempt 失败；已晋升 Raw 不丢；未晋升临时 Artifact 可重新执行。

### 23.4 Object Storage 暂时失败

没有完成 Artifact Promotion 前，Task 不得进入最终 SUCCESS。

### 23.5 Reconciler

周期检查：

- expired leases；
- Task 与 Outbox 不一致；
- DB manifest 指向缺失对象；
- 已上传对象但 DB 未提交的 orphan；
- Document current_version 指针；
- Search projection lag；
- Provider Run 无 terminal reason；
- `completion_attested=true` 但缺 Evidence 的非法状态。

## 24. Backpressure 与容量规划

### 24.1 有界流水线

```text
Discovery -> URL Inventory -> Fetch -> Artifact -> Extraction -> Projection
```

每层都有：

- max ready；
- max inflight；
- per-source quota；
- per-host quota；
- retry budget；
- age alert。

Discovery 不能无限把 URL 推给 Fetch。超过水位后降低 Backfill/Deep Gap 速率，优先保持 Incremental freshness。

### 24.2 粗略容量估算

示例：1000 个站点，每站历史 3000 篇，约 300 万 URL。

若平均 HTML 500 KB：

```text
Raw ≈ 1.5 TB 未压缩
```

使用对象存储压缩、生命周期分层后可显著降低热存储压力。候选与 Markdown 通常远小于 Raw。

容量模型必须按以下维度实际测量：

- p50/p95 response bytes；
- HTTP 页面比例；
- Browser 页面比例；
- extraction CPU；
- object-store write throughput；
- index/embedding throughput。

不要用 Browser 节点数量直接推算总抓取吞吐。

## 29. 验收标准

一个 Source 上线前至少通过：

1. Scope/SSRF/robots 验证；
2. 至少一个 authoritative discovery provider；
3. Provider terminal semantics 已定义；
4. HTTP 与 Browser escalation 行为可解释；
5. Raw Artifact 可回放；
6. 确定性 Extraction Candidate 至少两路或有明确站点 Recipe；
7. code/table/list 等结构质量门禁通过；
8. Canonical IR 与 Markdown 可重放；
9. Incremental 信号和 full reconcile 已配置；
10. Backfill/Incremental 同时运行时无 starvation；
11. Web 可查看 Coverage、任务、Artifact、Candidate、Version；
12. Release 升级可在历史 Raw 上回归并回滚。

平台级验收：

- 任意 Worker/Redis/Runtime 单点故障不造成业务真相丢失；
- 任意第三方 Runtime 升级不绕过 Release/Regression；
- 任意过滤器参数变化不要求重新下载 Raw；
- Search Index 全损可从 Document Version 重建；
- 对 1000+ Source 的大 Backfill 不影响增量 Freshness SLO。

这套方案的核心不是“选一个最强爬虫”，而是把 **Coverage、执行、Raw 证据、抽取候选、语义版本和最终投影分层**。Crawl4AI 负责高效执行、JS 页面、URL 发现与 Markdown 候选；PostgreSQL + Object Storage 负责业务真相；Canonical IR 与版本化 Renderer 负责长期稳定的知识库格式。这样才能在站点数量、历史文章量、第三方组件版本和网页结构持续变化的情况下，仍保持可扩展、可恢复、可解释、可重放和可运营。
