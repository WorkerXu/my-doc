# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站和公开 Newsletter** 的长期知识库采集平台，并可继续扩展到数千站点、百万级文章。

系统必须同时解决：

1. **全历史回填**：尽可能发现并抓取每个站点的全部历史文章，而不是只抓首页或 RSS；
2. **持续增量同步**：发现新文章、正文更新、URL 迁移、删除和重发布；
3. **稳定产出 Markdown**：从不可变网页事实经过抽取、质量校验和 Canonical IR 生成可重建 Markdown；
4. **可持续运营**：新增站点成本低，有 Web 管理、任务治理、失败诊断、成本控制、版本回放、质量评估和扩展能力。

### 1.1 核心 SLO

- **Coverage**：每个 Source 能解释 Provider、时间区间、游标、分区、停止条件和 Known Gap；
- **Freshness**：新文章从发布到进入 PASS/WARN Canonical Markdown 的延迟可监控；
- **Extraction Quality**：标题、正文完整率、噪声率、代码块/表格/列表保留率、截断率可量化；
- **Reliability**：任务成功率、Retry、DLQ、Queue Age、Checkpoint Resume 成功率；
- **Browser Efficiency**：HTTP 命中率、Browser avoided、Browser recovery、每恢复文档成本；
- **Interaction Reliability**：复杂交互 Step 成功率、Locator Drift、Resume 成功率、Semantic Wait 超时率；
- **Traceability**：任意 Markdown 可回溯 Source Release、URL Identity、Artifact、Extraction、Quality、Document Version、Renderer Release；
- **Retrieval Quality**：Recall@K、MRR、nDCG、metadata filter accuracy、stale-version rate；
- **Cost**：按 Source、Run、Queue Class、每 1000 个 PASS 文档统计 HTTP、Browser、Storage、LLM、Embedding、Search 成本。

### 1.2 非目标

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不把 HTTP 200、Crawler success、DOM 很长直接视为正文正确；
- 不把搜索引擎结果数当历史完整性证明；
- 不把 Crawl4AI 输出 Markdown、LLM 摘要或改写直接作为 Canonical Markdown；
- 不让 LLM 改写第三方原文来“修复”缺失正文；
- 不因 URL 曾抓过就永久停止复检；
- 不允许 Source 规则、Browser Recipe、Extractor、Renderer、Prompt、Model 等无版本改变生产结果；
- 不把 Redis、Browser Session、Crawler Cache、CSV、Sheets、Agent Memory 当业务真相；
- 不为所有文档默认建设 GraphRAG；
- 不让慢路径失败、预算耗尽或降级结果静默进入 PASS。

## 2. 核心设计原则

1. **Coverage First**：先建立 URL Inventory，再批量抓正文；
2. **Authoritative First**：CMS/API、Sitemap、RSS/Atom、Archive 优先；
3. **Search Is Gap Filling**：External Search 只做补洞和候选发现；
4. **Discovery / Fetch / Extract / Quality 分离**：各层独立重试、回放、评估；
5. **HTTP First, Browser Last**：Browser 是受治理慢路径；
6. **按交互复杂度选择工具**：静态、渲染、简单交互、复杂有状态交互分别路由；
7. **Crawl4AI 做内容型抽象，Playwright 做状态型交互**；
8. **Prevent Abstraction Leakage**：复杂状态机不能被重新塞回 L2 的 JS/C4A 脚本；
9. **Snapshot First**：先保存不可变 Artifact，再抽取和清洗；
10. **Extractor Is Candidate Generator**：Extractor 只产生 Candidate；
11. **Critique Before Publish**：Candidate 必须经过独立 Quality Gate；
12. **Repair Is Bounded**：修复是有限状态机；
13. **Canonical IR First, Markdown as Projection**：Markdown 可离线重建；
14. **Recipe, Not 1000 Site Scripts**：站点差异优先由 Profile/Policy/Recipe 表达；
15. **Complex Interaction Is a First-class Workflow**：多步 Browser 流程必须有 Step、Checkpoint、Trace、Budget；
16. **Semantic Wait Over Time Guessing**：业务状态变化优先于固定 sleep 或通用 `networkidle`；
17. **Stable Logical Key Over DOM Handle**：动态列表按业务 key 重新定位，不长期持有易漂移 DOM 引用；
18. **Stable Identity**：Source、URL、Artifact、Document、Version 使用稳定 ID；
19. **Idempotent + Recoverable**：任务有幂等键、lease、fencing token、checkpoint；
20. **Fair by Default**：大站 Backfill 不饿死 Incremental 和小站；
21. **Bounded Concurrency Everywhere**：禁止无界 asyncio gather、Browser Context、LLM 并发；
22. **No Silent Degradation**：Provider 截断、预算耗尽、Recipe 超限必须显式 DEGRADED/QUARANTINE/Known Gap；
23. **Release Everything That Changes Results**：Profile、Route、Recipe、Runtime、Extractor、Renderer、Chunker、Embedding 全部版本化；
24. **LLM 低频、旁路、可替换**：主链默认确定性，LLM 只做诊断、规则候选、结构化增强和可选问答；
25. **User-facing Knowledge Access 也要评估**：最终检索/RAG 用 Golden Query 做回归保护。

### 3.1 真相边界

**PostgreSQL + Object Storage 是业务真相。**

- PostgreSQL：身份、状态、关系、游标、任务、Release、Coverage、Interaction Step、Checkpoint、Quality、Version、Evaluation、Audit；
- S3/MinIO：Raw HTML、Browser MHTML、截图、Trace、Candidate、IR、Markdown、Search Evidence、Interaction Evidence、Enrichment、导出物；
- Redis Streams：任务运输、背压、consumer group，不保存不可替代业务状态；
- OpenSearch/pgvector：可重建 Search Projection；
- Browser Session、Crawler Cache、Worker 内存：易失执行状态。

## 4. 技术选型

### 4.1 控制面

- **FastAPI + Pydantic**：REST API、Command、Schema 校验；
- **PostgreSQL**：核心 Truth Store；
- **Redis Streams**：任务队列、consumer group、backpressure；
- **Redis Lua Token Bucket / Semaphore**：跨 Worker 域名限流和资源令牌；
- **React/Next.js + TypeScript**：Web 管理后台；
- **OpenTelemetry + Prometheus + Grafana + Structured Logging**：Trace/Metric/Log；
- **S3/MinIO**：不可变对象；
- **OpenSearch + pgvector**：关键词 + 向量混合检索。

### 4.2 Discovery / Fetch

- **httpx/aiohttp**：robots、Sitemap、Feed、CMS API、Conditional GET、普通网页；
- **Crawl4AI**：Browser Render、简单交互、动态链接发现、诊断 Candidate；
- **Playwright Python**：复杂多步、有状态、需要 Step 级控制和恢复的 Browser Interaction Engine；
- **SearXNG/合规 Search API Adapter**：External Search Gap；
- **PyMuPDF/pdftotext**：PDF；仅扫描件进入 OCR。

### 4.3 Extraction / Search

- **Trafilatura**：Generic Main Content Candidate；
- **lxml/BeautifulSoup**：DOM/XPath、Metadata、DOM Repair；
- **JSON-LD/OpenGraph/Microdata**：结构化元数据；
- **CSS/XPath/Regex Recipe**：确定性正文/字段抽取；
- **OpenSearch BM25 + pgvector + RRF/weighted fusion**：混合检索；
- **可选 reranker / LLM**：只在 Canonical 与统一 Query Service 之后工作。

### 4.4 版本冻结

生产环境必须记录：

```text
runtime_release
- image_digest
- python_version
- chromium_version
- playwright_version
- crawl4ai_version
- trafilatura_version
- parser_versions
- renderer_version
```

Browser/Extractor 升级不能直接覆盖 ACTIVE 结果，必须经过 Golden Replay + Canary。

## 6. Source 接入、Site Family 与 Release

新增站点最小输入：

```text
name + base_url + 可选标签/策略约束
```

Source 初始进入 `PROBING`，自动检测：

1. robots.txt；
2. Sitemap / Sitemap Index；
3. RSS/Atom；
4. CMS/API；
5. Archive/Category/Tag/Pagination；
6. JSON-LD/OpenGraph/Microdata；
7. HTTP 是否能得到完整正文；
8. 是否仅需 Browser Render；
9. 是否存在单次 Load More/Scroll；
10. 是否存在多步 tab/filter/pagination/foreach；
11. Site Family 指纹；
12. ARTICLE/DOC/INDEX/TAG/AUTHOR/ASSET/API 样本；
13. canonical、redirect、URL pattern；
14. 多 Extractor 样本质量；
15. 历史 Coverage Gap / Search Gap 风险；
16. Locator/DOM 稳定性；
17. 预估 Browser Action 数和成本；
18. L2 Recipe 是否出现抽象泄漏特征。

配置发布链：

```text
Family Defaults
 + Source Overrides
 + Discovery Recipe
 + Route Policy
 + Extraction/Repair Recipe
 + Interaction Recipe(optional)
 + Quality Policy
 -> Effective Config Hash
 -> Candidate Source Release
 -> Static Validation
 -> Golden Replay
 -> Live Sample
 -> Canary
 -> Approval
 -> ACTIVE
```

模板升级不能自动改变 ACTIVE Source。

## 7. 历史 URL Discovery 与 Coverage

### 7.1 Provider 优先级

```text
CMS/API
 -> Sitemap / Sitemap Index
 -> RSS/Atom
 -> Archive/Category/Tag
 -> Static Pagination
 -> Dynamic Listing
 -> Bounded Deep Crawl
 -> External Search Gap Fill
 -> Optional Web Archive/Common Crawl Gap Fill
```

RSS/Atom 主要用于增量和时间提示，不能独自证明完整历史。

### 7.2 Provider Run

```text
provider_run
- source_id
- source_release_id
- provider_type
- cursor/range/page/partition
- discovered_count
- new_count
- stop_reason
- exhausted
- gap_reason
- checkpoint
- started_at
- finished_at
```

Sitemap 支持 Index 递归、gzip、多 Sitemap、lastmod、checkpoint；Archive/Pagination 支持重复页签名、连续 N 页无新增、最大页数、最大动作数、最大 wall time。

### 7.3 Dynamic Listing

动态归档先进入 Interaction Complexity Router：

- 简单 Load More / Scroll：Crawl4AI Simple Interaction；
- 多筛选器、多 Tab、每页/每步要提交 URL、循环/分支：Direct Playwright Stateful Interaction。

无论哪种 Browser 发现方式，结果统一回到 URL Inventory。

### 7.4 External Search Gap

Search 只产生候选 URL 与 Gap Evidence：

```text
SearchQueryTemplate
 -> SearchPartition
 -> Query Instance
 -> Provider Adapter
 -> Search Page Observation
 -> URL Normalize
 -> URL Identity Merge
 -> URL Inventory
```

停止原因至少包括：

```text
PROVIDER_EXHAUSTED
PROVIDER_RESULT_CAP
MAX_PAGES
MAX_WALL_TIME
COST_BUDGET_EXHAUSTED
N_PAGES_NO_NEW
REPEATED_PAGE_FINGERPRINT
PROVIDER_DEGRADED
POLICY_BLOCKED
CANCELLED
```

### 7.5 自适应分区

宽查询持续产生新 URL 但触及 Provider 上限时，自动按可解释维度细分：

```text
YEAR -> MONTH -> PATH_PREFIX -> 受控 TOPIC/CUSTOM
```

每个分区保存 parent、depth、split_reason、query_budget、new_url_count、marginal_new_rate，并受 `max_depth/max_partitions/cost_budget` 限制。

### 7.6 Coverage Evidence

```text
Provider Set
 + Time Range
 + Cursor/Range
 + Exhaustion Evidence
 + Provider Diff
 + Search Gap Evidence
 + Search Partition Tree
 + Known Gap
```

Web 后台展示 Provider 交并差、最早/最晚文章、时间缺口、Known Gap、Search Partition Tree、补洞收益。

## 8. URL 规范化、Identity、去重与分类

### 8.1 URL Normalize

- host 小写；
- 去 fragment；
- 默认端口规范化；
- tracking query 去除；
- query 排序；
- trailing slash 按 Source Policy；
- 相对 URL 转绝对；
- canonical link 只作为 Identity Candidate；
- redirect chain 完整记录；
- Scope Policy 阻止越域和不允许路径。

### 8.2 多层去重

1. normalized URL；
2. canonical/redirect identity；
3. Artifact sha256；
4. Canonical semantic hash；
5. 可选 SimHash/MinHash 识别镜像/转载。

### 8.3 Page Type

在 Browser、LLM、Embedding 前分类：

```text
Provider Hint
 -> URL Rule
 -> MIME/Header
 -> Structured Metadata
 -> Cheap DOM Heuristic
 -> Manual Override
 -> LLM Exception(低比例)
```

类型：

```text
ARTICLE | DOC | INDEX | TAG | AUTHOR | HOME |
ASSET | API | AUTH | ERROR | UNKNOWN
```

## 9. Interaction Complexity Router

这是 Browser 路径的核心控制点。不能把“动态页面”统一视为一种任务。

### 9.1 分级

```text
L0 STATIC
- HTTP 即可得到完整内容

L1 RENDER_ONLY
- 需要 JavaScript 渲染，无动作
- Crawl4AI Browser Render

L2 SIMPLE_INTERACTION
- 单次/少量 scroll、Load More、click 后抓最终 DOM
- Crawl4AI js_code/c4a_script + wait_for

L3 STATEFUL_INTERACTION
- 多步 click/wait/extract
- foreach tab/filter
- 分页后每步都要提交输出
- 有循环、条件分支、step retry、checkpoint
- Direct Playwright Interaction Engine

L4 UNSUPPORTED_OR_BLOCKED
- 登录墙、CAPTCHA、明确访问控制、无法合规自动化
- Known Gap / Manual Review
```

### 9.2 路由证据

`route_decision` 必须保存：

```text
http_content_complete
requires_render
interaction_count_estimate
has_loop
has_branch
extract_after_each_action
requires_partial_commit
requires_step_retry
requires_checkpoint
needs_session
simple_interaction_success_rate
simple_interaction_drift_rate
playwright_recovery_delta
browser_cost_estimate
policy_constraints
selected_level
selected_engine
reason_codes
```

不能只保存不可解释评分。

### 9.3 L2 抽象泄漏保护

Candidate Source Release 在 Static Validation 阶段检查 L2 Recipe：

```text
L2_ALLOWED
- action_count <= max_simple_actions
- no foreach
- no branch
- no nested loop
- no extract-after-each-action
- no per-item checkpoint
- no long arbitrary JS orchestration blob
- only bounded simple interaction primitives
```

出现下列任一信号时，拒绝 L2 Candidate 或升级到 L3：

```text
HAS_LOOP
HAS_BRANCH
EXTRACT_AFTER_EACH_ACTION
REQUIRES_PARTIAL_COMMIT
REQUIRES_STEP_RETRY
REQUIRES_CHECKPOINT
JS_ORCHESTRATION_TOO_COMPLEX
SIMPLE_INTERACTION_DRIFT_HIGH
```

这条规则用于从平台层防止复杂状态机被重新塞进 Crawl4AI 的 JavaScript 字符串。

### 9.4 路由原则

- L0/L1/L2 应覆盖绝大多数技术博客；
- L3 只给复杂归档、筛选器、多 Tab、动态分页等确有必要页面；
- L3 Pool 与普通 HTTP/Crawl4AI Pool 隔离；
- Source 长期 L3 成本高、收益低时触发 Source-scoped circuit breaker 和人工审查。

## 10. 调度、队列、幂等与公平性

Queue Class：

```text
DISCOVERY
SEARCH_GAP
CLASSIFY
HTTP
CRAWL4AI_BROWSER
PLAYWRIGHT_INTERACTION
EXTRACT
QUALITY_REPAIR
ENRICHMENT
PROJECTION
EVALUATION
```

典型幂等键：

```text
DISCOVER:{source_release}:{provider}:{cursor}
SEARCH:{source_release}:{partition_id}:{query_hash}:{cursor}
CLASSIFY:{url_id}:{classifier_release}:{route_policy}
FETCH:{url_id}:{fetch_policy}:{validator_state}
INTERACT:{url_id}:{recipe_release}:{logical_run_key}
INTERACT_STEP:{interaction_run_id}:{step_id}:{logical_item_key}
EXTRACT:{artifact_id}:{extractor_release}:{mode}
QUALITY:{artifact_id}:{quality_release}
REPAIR:{artifact_id}:{repair_release}:{step}
RENDER:{version_id}:{renderer_release}
VECTOR:{version_id}:{chunker_release}:{embedding_release}
EVAL:{dataset_release}:{retrieval_release}
```

Worker 使用 lease + fencing token；旧 lease Worker 不能覆盖新 Worker 提交状态。

### 10.1 公平调度

- Incremental 优先于 Backfill；
- 长等待任务做 aging；
- 单 Source 有最大并发占比；
- HTTP、Crawl4AI Browser、Playwright、Search、LLM 独立配额；
- 大站 Backfill 必须分片；
- Global Admission 在真实外部调用前检查 global/per-domain concurrency、QPS、Source budget、robots/policy、circuit state。

禁止一次性对百万 URL 创建无界 `asyncio.gather`。

## 11. Fetch Plane：HTTP First, Browser Last

### 11.1 HTTP Worker

支持：

- gzip/br；
- redirect；
- connect/read/total timeout；
- response size limit；
- ETag / If-None-Match；
- Last-Modified / If-Modified-Since；
- Content-Type/Charset；
- Raw Snapshot；
- 精细错误分类。

### 11.2 Browser Worker 生命周期

```text
Worker Process
 -> long-lived Browser Process
 -> bounded BrowserContext Pool
 -> Page / Crawl or Interaction Run
 -> recycle by requests / memory / time / crash rate
```

默认使用隔离 BrowserContext，避免 cookie/localStorage 污染。公开博客不依赖长期登录态。

### 11.3 Crawl4AI 路径

适用：

- L1 Render Only；
- L2 简单 Scroll/Load More/Click；
- 页面内容转 HTML/Markdown Diagnostic Candidate；
- 动态链接/媒体发现。

`js_code/js_code_before_wait/wait_for/session_id/js_only/c4a_script` 可处理简单多步交互；当业务需要每步独立抽取、独立重试、循环状态、局部提交、checkpoint 时必须升级 L3。

## 12. Direct Playwright Stateful Interaction Engine

### 12.1 工作流模型

复杂 Browser 任务的主要产物不只是最终 DOM，而是：

```text
Precondition
 -> Action
 -> Observe
 -> Semantic Wait
 -> Extract Partial Output
 -> Assert
 -> Commit
 -> Checkpoint
 -> Next Action
```

交互必须是一等工作流，不能藏在 Python 内嵌 JavaScript 字符串中。

### 12.2 Browser Interaction Recipe DSL

建议版本化 typed DSL：

```yaml
kind: browser_interaction
version: 8
entry:
  goto: "{{url}}"
  wait:
    locator: "main"

steps:
  - id: enumerate_years
    extract_keys:
      locator: "[data-year]"
      key: "attr:data-year"

  - id: crawl_years
    foreach_key: "{{steps.enumerate_years.keys}}"
    body:
      - click_by_key:
          locator: "[data-year='{{item}}']"
      - wait_signature_change:
          target: ".post-list a"
          fingerprint: href_set
      - wait_stable:
          target: ".post-list a"
          quiet_ms: 500
      - extract_links:
          locator: ".post-list a"
      - assert:
          min_items: 1
      - checkpoint:
          key: "{{item}}"

limits:
  max_actions: 200
  max_wall_time_s: 180
  max_retries_per_step: 2
```

内置动作集：

```text
GOTO
WAIT_LOCATOR
WAIT_SIGNATURE_CHANGE
WAIT_STABLE
WAIT_RESPONSE
EXPECT_VISIBLE
EXPECT_COUNT
CLICK
CLICK_BY_KEY
SCROLL
SCROLL_UNTIL_NO_NEW
EXTRACT_KEYS
FOREACH_KEY
PAGINATE
EXTRACT_LINKS
EXTRACT_HTML
EXTRACT_TEXT
ASSERT
BRANCH
COMMIT_PARTIAL
CHECKPOINT
SCREENSHOT_ON_FAIL
TRACE_ON_FAIL
```

Executor 把动作映射到 Playwright API；Source 配置不执行任意 Python/JavaScript。

### 12.3 动态列表与 Locator 策略

动态 Tab、筛选器、年份、分页项必须：

1. 先等待列表稳定；
2. 提取稳定逻辑 key；
3. 循环时按 key 重新定位；
4. 动作后验证输出属于该 key；
5. 不长期保存 ElementHandle/DOM 节点；
6. 不在动态列表尚未稳定时直接依赖瞬时 `locator.all()` 结果。

Locator 优先级：

```text
role/label/稳定语义属性
> data-* 属性
> 稳定 id
> 结构关系
> class
> 深层 CSS/XPath
```

### 12.4 Custom Plugin 例外

DSL 无法表达且站点价值足够高时启用 `CUSTOM_PLAYWRIGHT_PLUGIN`：

- 代码进入受控仓库；
- 版本化；
- 单元测试 + Golden Replay；
- Tool/网络权限受限；
- Canary 后上线；
- 不能把任意代码存数据库并直接执行。

## 14. Extraction Portfolio、Quality Gate 与 Repair

### 14.1 Extraction Portfolio

1. Structured Metadata / JSON-LD；
2. Trafilatura Precision/Balanced/Recall；
3. Deterministic CSS/XPath Recipe；
4. DOM Repair + Generic Extractor；
5. Crawl4AI Markdown 仅作 Diagnostic Candidate。

任何 Extractor 都不能直接发布。

### 14.2 Quality Gate

至少检查：

- title；
- 正文长度；
- paragraph/heading 分布；
- link density；
- boilerplate；
- code/table/list 保留；
- language；
- WAF/登录墙/错误页指纹；
- Candidate Agreement；
- 分类冲突；
- 历史异常截断；
- 结构突变；
- 重复正文比例。

状态机：

```text
DISCOVERED
 -> CLASSIFIED
 -> FETCHED
 -> EXTRACTED
 -> QUALITY_CHECK
      -> PASS/WARN -> CANONICALIZE
      -> FAIL_RECOVERABLE -> REPAIR_PENDING
      -> FAIL_UNKNOWN -> QUARANTINE
      -> NON_CONTENT -> REJECT
```

### 14.3 Bounded Repair

```text
ALTERNATE_EXTRACTOR
 -> DETERMINISTIC_RECIPE
 -> DOM_REPAIR
 -> BROWSER_REFETCH(有历史收益证据时)
 -> QUALITY_CHECK
```

Repair 有 `max_steps/max_wall_time/browser_budget/cost_budget` 硬限制，失败进入 QUARANTINE。

## 16. 增量同步与 Document Version

Freshness 分层：

```text
HOT / WARM / COLD
```

增量发现优先：

```text
RSS/API
 -> Sitemap lastmod/diff
 -> Archive first pages
 -> bounded dynamic listing
 -> periodic Search Gap verify
```

已知 URL 优先 Conditional GET，并周期抽样强制 re-fetch 防止 ETag/lastmod 不可信。

版本判定：

```text
Artifact
 -> Extraction Portfolio
 -> Quality
 -> Canonical IR
 -> Normalize Semantic Content
 -> semantic_hash
 -> Compare Current Version
```

- hash 相同：更新 `last_checked_at`；
- 正文变化：创建新 Document Version；
- 仅元数据变化：记录 Metadata Change；
- PASS/WARN 新版本原子切换 `current_version_id`；
- 相同 semantic hash 不重复向量化和 Enrichment。

删除策略：

```text
404/410
 + Provider 长期缺失
 + 多次 Verify
 -> SUSPECT_MISSING
 -> REMOVED
```

301/308 建 Redirect Relationship。

## 24. 验收标准

### 24.1 历史与增量

- 每个 URL 可追溯 Provider/Query/Page/Interaction Step；
- Authoritative Provider 有 stop reason/exhaustion evidence；
- Known Gap 可见；
- Search Gap 不虚报 Coverage 完整；
- Dynamic Listing 有最大动作数、wall time、无新增停止条件；
- 新文章在 Freshness SLO 内进入 PASS/WARN；
- 304 不产生正文新版本；
- 正文变化产生新 Version；
- 删除需多证据；
- 大站 Backfill 不阻塞 Incremental。

### 24.2 Browser 路由

- 能明确区分 L0/L1/L2/L3/L4；
- L2 出现 loop/branch/per-step extract/checkpoint 时 Static Validation 能拒绝或升级 L3；
- L2 简单交互可在 Crawl4AI 路径完成；
- L3 多步流程可记录每个 Step、logical item、错误、完成条件、checkpoint；
- 动态列表使用稳定逻辑 key，不能依赖未稳定瞬时列表；
- 完成条件默认是业务状态/Locator 条件，而不是统一固定 sleep/`networkidle`；
- Worker 崩溃后 L3 可从逻辑 checkpoint 恢复；
- Locator Drift 可从错误率和 Evidence 检出；
- 失败任务可获取 Trace/截图/MHTML/Console/PageError/RequestFailed；
- Browser/Playwright 成本和恢复收益可量化；
- Recipe 超预算不能静默标记成功。

### 24.3 抽取与 Markdown

- Fetch/Extract/Quality 独立；
- 多 Candidate 可回溯；
- Repair 有固定上限；
- 未通过 Quality Gate 不发布；
- Markdown 可回溯 Canonical IR；
- Renderer 升级可离线重建。

### 24.4 可复现与治理

- 全新容器加载相同 Release 可完成 Golden Corpus Replay；
- Runtime Image、Chromium、Crawl4AI、Playwright、Extractor、Renderer 版本明确；
- 同一 Artifact + Release 能重建相同 Canonical/Markdown；
- Source/Recipe Candidate 必须过 Static Validation + Golden Replay + Canary + Approval。

### 24.5 检索

- Golden Query Dataset 可版本化；
- Retrieval Release 有 Recall@K/MRR/nDCG 基线；
- 无答案问题支持正确拒答；
- Retrieval 变更必须过 Offline Eval + Canary。

```text
Trafilatura  = Generic Main-content Candidate
lxml/BS4     = Metadata + DOM Heuristic + DOM Repair
Search       = Gap Discovery Provider，不是 Coverage Truth
Artifact     = 不可变网页事实
Quality      = 独立发布闸门
Canonical IR = Markdown 和后续 Projection 的结构真相
Renderer     = Canonical IR -> Markdown
PostgreSQL   = 身份/状态/版本/流程真相
S3/MinIO     = Artifact/IR/Markdown/Evidence 真相
Redis        = 运输和资源协调，不是业务真相
Evaluation   = Crawl + Retrieval 的回归保护
```

系统核心不是选择一个“万能爬虫”，而是建立一个**按页面与交互复杂度路由、以 Coverage 和 Stable Identity 为基础、以不可变 Artifact 保存事实、以多 Candidate + Quality Gate 控制内容正确性、以 Canonical IR 保证 Markdown 可重建、以 Step/Checkpoint/Semantic Wait/Trace 管理复杂 Browser 工作流、以幂等任务和公平调度支撑长期增量、以 Web 管理和 Release 治理支撑持续扩站**的平台。

对于 1000+ 技术博客，绝大多数页面应停留在 HTTP 或 Crawl4AI 的低成本路径；只有真正具有多步、循环、每步抽取、局部提交和恢复需求的少量动态页面才升级到直接 Playwright。通过 L2 Complexity Guard、稳定逻辑 key、语义等待和失败 Trace，可以同时获得高吞吐、低成本、复杂站点可控性和长期维护能力。
