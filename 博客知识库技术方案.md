# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站和公开 Newsletter** 的长期知识库采集平台，可平滑扩展到数千站点和百万级文章。

系统需要同时满足：

1. **全历史尽量抓全**：不是“爬虫跑完”就算完成，而是能说明 URL 从哪个 Discovery Provider 发现、哪些 Provider 已穷尽、哪里仍存在 Known Gap；
2. **持续增量同步**：发现新文章、正文更新、元数据变化、URL 迁移、删除与重发布；
3. **稳定生成 Markdown**：保存不可变原始抓取事实，经过抽取、质量校验和 Canonical IR 后由统一 Renderer 生成 Markdown；
4. **低成本扩展新网站**：通过 Site Family、Source Profile、Discovery Recipe、Route Policy、Extraction/Repair Recipe 复用能力，避免每站维护一套独立爬虫；
5. **Web 可管理**：支持接入、Probe、配置、调度、Coverage、任务、质量、回放、版本、成本、导出和告警；
6. **可追溯、可重建**：任意 Markdown 都能回溯 Source Release、URL、Artifact、Extractor、Quality、Repair/Fallback、Document Version 和运行记录；
7. **幂等可恢复**：任务可重试、续跑、回放，不产生脏重复；
8. **高吞吐数据面保持确定性**：HTTP、Browser Recipe、正文抽取、版本判定和 Markdown 渲染默认不依赖 LLM；
9. **智能能力放在控制面与异常慢路径**：用于 Source Probe、规则建议、Quarantine 诊断和 Canary 辅助审查，不允许无审批地在线改写生产规则；
10. **成本可治理**：Authoritative Discovery、Cheap Routing、HTTP First、Browser Last，Browser/LLM/Graph 都必须有独立预算、收益统计和熔断。

### 1.1 核心 SLO

- **Coverage**：Provider coverage、exhaustion evidence、Known Gap；
- **Freshness**：文章发布到进入 PASS Canonical Markdown 的延迟；
- **Extraction Correctness**：正文完整率、噪声率、结构保留率、Candidate Agreement；
- **Routing Efficiency**：ARTICLE/DOC/INDEX/ASSET/UNKNOWN 分类准确率、Browser avoided、UNKNOWN/LLM Exception 比例；
- **Fallback Efficiency**：Browser/Repair recovery rate、quality delta、p95 latency、cost per recovered document；
- **Reliability**：Task 成功率、Retry/DLQ、Queue Age、Worker 恢复率；
- **Traceability**：任意结果能回溯不可变 Artifact、Release 和阶段执行链；
- **Cost**：按 Source、Run、Queue Class 和每 1000 个 PASS 文档统计成本。

### 1.2 非目标

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不把 HTTP 200、Crawler success 或 DOM 很长直接等同于“正文正确”；
- 不用 LLM 主观判断替代 Coverage Evidence；
- 不把 Crawl4AI `fit_markdown`、LLM 摘要或改写直接作为 Canonical Markdown；
- 不因 URL 曾抓取过就永久停止复检；
- 不允许模板或规则升级后无审计地改变全部生产 Source；
- 不默认为全部文档构建 GraphRAG；
- 不因为高成本慢路径熔断而把未通过 Quality Gate 的内容静默标记为 PASS。

## 2. 核心设计原则

1. **Coverage First**：先建立 URL Inventory，再批量抓正文；
2. **Authoritative First**：CMS/API、Sitemap、RSS/Atom、Archive 优先；
3. **Discovery Before Fetch**：URL 发现、规范化、分类、抓取、抽取分离；
4. **Cheap Routing Before Expensive Execution**：Provider Hint、URL Rule、MIME、Structured Metadata、DOM Heuristic 优先；
5. **HTTP First, Browser Last**：只有存在可解释证据时才升级 Browser；
6. **Snapshot First**：先保存不可变 Artifact，再抽取和清洗；
7. **Fetch != Extract != Quality**：网络成功、正文抽取成功、质量通过是三个不同状态；
8. **Extractor Is Candidate Generator**：任何 Extractor 都只产生 Candidate；
9. **Critique Before Publish**：Candidate 必须经过独立 Quality Gate；
10. **Repair Is Bounded**：修复是有限状态机，不允许无限 Agent 循环；
11. **IR First, Markdown as Projection**：Canonical IR 是正文结构事实，Markdown 可重建；
12. **Recipe, Not Site Code**：站点差异通过版本化 Profile/Policy/Recipe 表达；
13. **Stable Identity**：Source、URL、Artifact、Document、Version 使用稳定 ID；
14. **Idempotent + Recoverable**：Task 有幂等键、lease、fencing token、checkpoint、Retry、DLQ；
15. **Fair by Default**：大站历史回填不能饿死增量和小站；
16. **Slow Path Isolated**：Browser、LLM Exception、Graph 使用独立 Queue/Pool/Budget；
17. **Fallback Must Earn Its Cost**：慢路径持续比较 recovery rate、quality gain、latency 和 cost；
18. **Release Everything That Changes Results**：Profile、Route、Recipe、Runtime、Extractor、Renderer、Schema 都版本化；
19. **No Silent Degradation**：能力未执行、预算耗尽、慢路径熔断必须显式 DEGRADED/QUARANTINE/Known Gap；
20. **Agent In Control Plane**：Agent 可建议规则和解释异常，但不作为百万级文档热路径的默认执行器。

### 3.1 真相边界

**PostgreSQL + Object Storage 是业务真相。**

- URL Observation：某 Provider 看到某 URL 的事实；
- Coverage Evidence：Provider 范围、游标、穷尽和缺口证据；
- URL Classification：页面类型、方法、置信度和证据；
- Route Decision：某 Source Release 下选择 HTTP/Browser/Discovery/Asset 等执行路径；
- Artifact：HTTP/PDF/API/Browser 的不可变抓取事实；
- Extraction Attempt：某 Extractor 对某 Artifact 产生的 Candidate；
- Quality Result：Candidate 质量判定；
- Repair/Fallback Evaluation：修复触发、前后质量、延迟和成本；
- Canonical IR：规范正文结构；
- Document Version：语义版本；
- Source Release：生效配置；
- Cost Event：资源成本事实。

Redis Streams 是运输层；Browser Session 和 Crawler Cache 是易失执行优化；Markdown、全文索引、向量和 Graph 都是可重建 Projection。

## 4. 技术选型与组件边界

### 4.1 控制面

- **FastAPI + Pydantic**：REST API、Command、Schema 校验；
- **PostgreSQL**：Source、Release、Run、Task、Coverage、URL、Classification、Route、Artifact、Extraction、Quality、Version、Cost、Audit、Outbox；
- **Redis Streams**：任务运输、consumer group、backpressure；
- **Redis Lua token bucket/semaphore**：跨 Worker 域名级限流和并发；
- **React/Next.js + TypeScript**：Web 管理后台；
- **OpenTelemetry + Prometheus + Grafana + 结构化日志**：Trace、Metric、Log；
- **S3/MinIO**：Raw HTML、Rendered DOM/MHTML、PDF、Extraction Candidate、IR、Markdown、附件和导出物；
- **OpenSearch**：BM25/全文；
- **pgvector**：首期向量检索，可通过 Adapter 替换。

### 4.2 Discovery / Fetch

- **httpx/aiohttp**：Sitemap、Feed、CMS API、普通页面、Conditional GET；
- **Crawl4AI**：动态页面、链接/媒体发现、受控 Browser Fetch，通过 Adapter 接入；
- **Playwright**：复杂但确定性的 Browser Recipe；
- **PyMuPDF/pdftotext**：PDF；扫描件才进入 OCR。

### 4.3 Extraction

- **Trafilatura**：默认 Generic Main-Content Candidate；
- **lxml**：高性能 DOM/XPath；
- **BeautifulSoup**：Structured Metadata、DOM Repair、诊断；
- **JSON-LD/OpenGraph/Microdata**：结构化 Metadata Candidate；
- **CSS/XPath/Regex Recipe**：确定性字段抽取；
- **Crawl4AI Markdown**：诊断/Candidate，不直接作为 Canonical。

### 4.4 运行时边界

```text
平台负责：
Coverage / Truth / Scheduling / Retry / DLQ / Classification /
Routing / Fairness / Budget / Quality / Repair / Version /
Release / Audit / Projection Semantics

单次 HTTP/Browser 请求、页面动作、DOM、链接、媒体、局部 batch

从 Artifact 生成 Candidate

Renderer 负责：
Canonical IR -> Markdown
```

生产环境锁定经过 Golden Corpus 验证的 Crawl4AI、Playwright、Chromium、Trafilatura、Classifier、Renderer 和镜像 digest；升级必须经过 Replay、Benchmark、Canary 和 Approval。

## 5. Source、Profile 与不可变 Release

新增站点只要求：

```text
name + base_url + 可选标签/策略约束
```

系统进入 `PROBING`，自动探测：

1. robots.txt 和 Sitemap 声明；
2. Sitemap/Sitemap Index；
3. RSS/Atom；
4. 常见 CMS API；
5. Archive/Category/Tag/Pagination；
6. JSON-LD/OpenGraph/Microdata；
7. HTTP 是否直接得到完整正文；
8. 是否需要 Browser；
9. Site Family 指纹；
10. URL pattern、canonical、分页规则；
11. 多种 Extractor 的样本质量；
12. ARTICLE/DOC/INDEX/TAG/AUTHOR/ASSET/API 样本；
13. Browser fallback 的恢复率和质量增益；
14. 是否需要 Deterministic/Repair Recipe。

Probe 产生 **Candidate Source Profile + Route/Fallback/Quality Policy**，管理员确认后发布为 Source Release。

### 5.1 Source Profile 示例

```yaml
source:
  base_url: https://example.com
  scope:
    allowed_hosts: [example.com]
    include: [/blog/**, /docs/**]
    exclude: [/search/**]

discovery:
  providers: [sitemap, rss, archive]
  deep_crawl:
    enabled: false

routing:
  article_patterns: [/blog/**, /posts/**]
  doc_patterns: [/docs/**]
  discovery_only_patterns: [/tag/**, /category/**, /author/**]
  unknown: cheap_probe

fetch:
  http_first: true
  browser_fallback: true
  concurrency_per_host: 2
  request_rate_per_host: 1

extraction:
  portfolio: [structured, trafilatura, deterministic]
  trafilatura_mode: balanced
  deterministic_recipe: article-v3

quality:
  policy: tech-blog-v2

repair:
  sequence: [deterministic, dom_repair, browser_refetch]
  max_steps: 3

incremental:
  freshness_class: WARM
  verify_known_urls: true

slow_path:
  browser_max_share: 0.10
  llm_exception_max_share: 0.01
```

模板更新不会直接改变生产站点。必须生成新的 Effective Config/Source Release，经静态校验、Golden Replay、Canary 后原子切换。

## 6. 历史 URL Discovery 与 Coverage

历史回填先建立 URL Inventory，再抓正文。

### 6.1 Provider 优先级

```text
CMS/API
 -> Sitemap / Sitemap Index
 -> RSS/Atom
 -> Archive/Category/Tag
 -> Static Pagination
 -> Dynamic Listing
 -> Bounded Deep Crawl
 -> Optional Search/Common Crawl/Archive Gap Filling
```

### 6.2 Provider 要求

每个 Provider Run 都记录：

- source_id；
- provider_type；
- cursor/range/page；
- discovered_count；
- new_count；
- stop_reason；
- exhausted；
- gap_reason；
- started_at/finished_at。

Sitemap 支持 Index 递归、gzip、多 Sitemap、lastmod、大站 checkpoint。RSS/Atom 主要用于高频增量和 publish/update hint，不能单独作为历史完整性证明。

### 6.3 Archive/Pagination Recipe

```text
OPEN start_url
EXTRACT article_links
LOOP:
  FIND next_page
  IF absent -> EXHAUSTED
  OPEN next_page
  EXTRACT article_links
  STOP_IF max_pages / duplicate_page_signature / no_new_urls
```

Infinite Scroll/Load More Recipe 支持 scroll、wait_for、click、virtual scroll，并设置最大动作轮数、最大时间和连续 N 轮无新 URL 停止条件。

### 6.4 Coverage 页面

Web 后台展示：

- Provider 状态；
- discovered/new URL；
- 时间跨度；
- cursor/page/range；
- exhaustion evidence；
- Provider 交并差异；
- Known Gap；
- 一键补洞和 Replay。

## 7. URL 规范化、Identity、分类与路由

### 7.1 URL 规范化

- host 小写；
- 去 fragment；
- 默认端口规范化；
- tracking query 去除；
- query 参数排序；
- trailing slash 策略；
- canonical link 作为 Identity Candidate，不盲信；
- redirect chain 完整记录。

### 7.2 多层去重

1. normalized URL；
2. canonical/redirect identity；
3. Artifact sha256；
4. Canonical semantic hash；
5. 可选近似正文指纹用于镜像/转载识别。

标题、slug、展示文本不能作为跨阶段唯一主键。

### 7.3 Page Type Classification

在 Browser、正文 Extraction、LLM 和 Embedding 之前完成：

```text
Provider Hint
 -> URL Rule
 -> MIME/Header
 -> Structured Metadata
 -> Cheap DOM Heuristic
 -> Manual Override
 -> LLM Exception（低比例）
```

页面类型：

```text
ARTICLE | DOC | INDEX | TAG | AUTHOR | HOME |
ASSET | API | AUTH | ERROR | UNKNOWN
```

### 7.4 Execution Routing

```text
ARTICLE -> HTTP_ARTICLE -> Extraction Portfolio
DOC     -> HTTP_DOC -> Document Extraction
INDEX   -> DISCOVERY_ONLY
TAG     -> DISCOVERY_ONLY
AUTHOR  -> DISCOVERY_ONLY
ASSET   -> ASSET_PIPELINE
API     -> STRUCTURED_API
ERROR   -> REJECT
UNKNOWN -> CHEAP_PROBE -> Reclassify / QUARANTINE
```

原则：Browser 是 Fetch fallback，不是分类器；稳定 Source 不逐 URL 依赖 LLM；URL Rule 属于 Route Policy/Source Release，不能散落成 Worker 中的域名 `if` 分支。

## 8. 调度、队列、幂等与公平性

### 8.1 Queue Class

```text
DISCOVERY
CLASSIFY
HTTP
BROWSER
LLM_EXCEPTION
EXTRACT
QUALITY_REPAIR
PROJECTION
```

Browser、LLM、Projection 使用独立容量，不能拖垮 HTTP 主链。

### 8.2 幂等键

```text
DISCOVER:{source_release}:{provider}:{cursor/range}
CLASSIFY:{url_id}:{classifier_release}:{route_policy_version}
FETCH:{url_id}:{fetch_policy_version}:{validator_state}
EXTRACT:{artifact_id}:{extractor_release}:{mode}
QUALITY:{artifact_id}:{quality_policy_release}
REPAIR:{artifact_id}:{repair_policy_release}:{step}
RENDER:{version_id}:{renderer_release}
VECTOR:{version_id}:{chunker_release}:{embedding_release}
```

### 8.3 Lease + Fencing

Worker 领取任务获得 lease 与 fencing token。lease 失效后的旧 Worker 不允许覆盖新 Worker 的结果。

### 8.4 Weighted Fair Scheduling

- Incremental 高于 Backfill；
- HOT Source 高优先；
- 长等待任务 aging；
- 单 Source 最大并发占比；
- Browser/LLM 独立低配额；
- Projection 不抢抓取关键资源。

### 8.5 Global Admission

每次真实网络、Browser 或 LLM 调用前统一检查：

- global concurrency；
- per-domain concurrency/QPS；
- Browser slot；
- Source budget；
- slow-path share；
- circuit state；
- robots/policy；
- maintenance window。

### 8.6 Backpressure

当 Extract/Storage/Search 延迟升高：降低新 Fetch Admission；Browser 首先降速；LLM Exception 和 Graph/Embedding 可暂停；Discovery 可继续低成本运行但限制正文任务生成。

## 9. Fetch：HTTP First，Browser Last

### 9.1 HTTP Worker

默认使用异步 HTTP Client：

- gzip/br；
- redirect；
- connect/read/total timeout；
- response size limit；
- ETag / If-None-Match；
- Last-Modified / If-Modified-Since；
- Content-Type / Charset；
- SSL/错误分类；
- Raw Snapshot 入对象存储。

生产 Worker 自己拥有事件循环。不要依赖在同步 Agent Tool 中通过 `nest_asyncio` 嵌套事件循环来承载大规模抓取。

### 9.2 Browser Fallback 条件

只有以下情况进入 Browser：

- HTTP HTML 只是 JS shell；
- 正文依赖 JS；
- 确定性点击/滚动后才出现正文；
- HTTP Candidate 低质量，且 Probe/Golden Sample 证明 Browser 有恢复收益；
- Source Profile 明确指定。

Browser 与 HTTP 使用独立 Queue/Worker Pool，并持续记录 fallback recovery rate、quality delta、p95 latency 和成本。

### 9.3 Browser Readiness

正文就绪优先使用 selector、最小有效正文、DOM/text quiet window、关键响应等条件。固定 sleep 或全局 networkidle 不作为所有站点唯一完成条件。

### 9.4 Fetch 错误分类

```text
FETCH_NETWORK_ERROR
FETCH_TIMEOUT
FETCH_RATE_LIMITED
FETCH_ACCESS_DENIED
FETCH_BROWSER_CRASH
FETCH_EMPTY_SHELL
FETCH_PERMANENT_NOT_FOUND
```

Retry、退避、DLQ 根据错误类型分别配置。

## 10. Immutable Artifact 与正文抽取

### 10.1 Artifact

每次成功或具有诊断价值的 Fetch 都形成不可变 Artifact：

```text
artifact
- artifact_id
- url_id
- fetch_kind: HTTP | BROWSER | PDF | API
- object_key
- content_type
- status_code
- etag
- last_modified
- fetched_at
- sha256
- runtime_release
- parent_artifact_id nullable
```

HTTP Artifact 与 Browser Render Artifact 分开保存，后续才能判断 Browser 是否真的改善正文。

### 10.2 Extraction Portfolio

候选来源：

1. Structured Metadata/JSON-LD；
2. Trafilatura Precision/Balanced/Recall；
3. Deterministic CSS/XPath Recipe；
4. DOM Repair + Generic Extractor；
5. Crawl4AI Markdown 诊断 Candidate。

每次 Extraction Attempt 记录 extractor release、输入 Artifact、输出对象、semantic hash、quality metrics 和 failure reason。

### 10.3 图片与链接

不要通过“Markdown -> HTML -> 再找图片”作为生产主路径。应从原始 DOM/Crawler media metadata 获取资源：

- 相对 URL 绝对化；
- canonical asset URL；
- 保存 alt/title；
- 按 Source Policy 决定仅保留远程链接或下载到对象存储；
- 下载资产按 sha256 去重。

## 11. Quality Gate、阶段化审查与有限修复

质量检查是独立阶段，不能与 Extractor 成功状态混在一起。

### 11.1 Pipeline 状态机

```text
DISCOVERED
 -> CLASSIFIED
 -> FETCHED
 -> EXTRACTED
 -> QUALITY_CHECK
      -> PASS -> CANONICALIZE -> VERSIONED -> RENDERED
      -> WARN -> CANONICALIZE -> VERSIONED -> RENDERED
      -> FAIL_RECOVERABLE -> REPAIR_PENDING
           -> ALTERNATE_EXTRACTOR
           -> DOM_REPAIR
           -> BROWSER_REFETCH（有恢复证据时）
           -> QUALITY_CHECK
      -> FAIL_UNKNOWN -> QUARANTINE
      -> NON_CONTENT -> REJECT
```

这是一条 **Critique -> Revision** 式流水线，但 Revision 只允许重新抓取、替换 Extractor、执行确定性 Repair Recipe，不能让 LLM 改写源正文。

### 11.2 Quality Gate 指标

至少检查：

- title 存在；
- 正文最小有效长度；
- paragraph/heading 数量；
- link density；
- boilerplate score；
- code/table/list 保留；
- language 一致性；
- 登录墙、错误页、WAF/CAPTCHA 指纹；
- Candidate Agreement；
- Classification 与正文内容是否冲突；
- 与历史版本相比是否异常截断或结构突变；
- 重复正文比例。

状态：

```text
PASS        可进入 Canonical 和 Projection
WARN        可用但有低风险异常
QUARANTINE  等待自动回放或人工处理
REJECT      明确非文章/错误内容
```

### 11.3 Candidate Agreement

比较：

- title/author/date/canonical；
- normalized text similarity；
- 首尾段；
- 段落与 heading 分布；
- code/table/list 保留率；
- link density/boilerplate。

典型判断：

```text
Generic 与 Deterministic 高一致 -> 高置信 PASS
Generic 偏短，Recall 与 Deterministic 高一致 -> Recall 更可信
Selector 与 Generic 严重偏离 -> SELECTOR_DRIFT -> QUARANTINE
全部 Candidate 都短且 HTTP 像 shell -> Browser Candidate
Browser 后仍无增益 -> NO_GAIN -> QUARANTINE / Circuit Signal
```

### 11.4 Repair 必须有限

默认修复序列：

```text
Generic
 -> Deterministic Recipe
 -> DOM Repair + Generic
 -> Browser Fetch + same Extraction Portfolio
 -> QUARANTINE
```

每次修复记录：trigger reason、base quality、new quality、quality delta、latency、cost、recovered_to_pass。

禁止无限 Agent/LLM 自反思循环。

### 11.5 Source 级慢路径熔断

当 Browser/高成本 Repair 在滑动窗口持续低恢复、高延迟或高成本：

1. 打开 Source-scoped circuit breaker；
2. 新 Candidate 进入 QUARANTINE/DEFERRED；
3. Discovery、HTTP 和其他 Source 继续运行；
4. 生成诊断和 Candidate Policy 建议；
5. Replay/Canary/Approval 后再切换 ACTIVE Release。

熔断只停止昂贵尝试，不得降低 Quality Gate。

## 13. 增量同步与版本管理

### 13.1 Freshness 分层

- HOT：高频新闻/资讯；
- WARM：普通技术博客；
- COLD：长期低频更新站点。

增量发现优先：

```text
RSS/API
 -> Sitemap lastmod/diff
 -> Archive first pages
 -> bounded dynamic listing
```

### 13.2 Conditional Fetch

已知 URL 复检优先使用：

- ETag / If-None-Match；
- Last-Modified / If-Modified-Since；
- RSS updated；
- Sitemap lastmod；
- CMS update/revision time；
- 周期性抽样强制 re-fetch。

HTTP 304 记录 Fetch Attempt，但不创建新正文版本。

### 13.3 版本判定

```text
Artifact
 -> Extraction Portfolio
 -> Quality Gate
 -> Canonical IR
 -> Normalize Semantic Content
 -> semantic_hash
 -> Compare Current Version
```

- semantic hash 相同：只更新 `last_checked_at`；
- 正文变化：创建新 Version；
- 仅元数据变化：记录 metadata change，可按策略创建 metadata revision；
- 新 Version PASS/WARN 后原子切换 `current_version_id`；
- 相同 semantic hash 不重复向量化。

### 13.4 删除与迁移

```text
ACTIVE
 -> 404/410 或 Provider 长期缺失
 -> SUSPECT_MISSING
 -> 多次复检 + sitemap/archive evidence
 -> REMOVED
```

301/308 记录 Redirect Relationship；目标 URL 重新执行 Scope、Classification 和 Route。

### 13.5 Provider Cursor

每个 Discovery Provider 独立保存 cursor/watermark/exhaustion evidence。新增 Provider 不需要改变 Document/Version 模型。

## 17. 控制面 Agent 的使用边界

Agent 适合低频、高语义、需要综合多个证据的控制面任务，不适合成为每篇文章的默认抓取/清洗运行时。

### 17.1 允许场景

- 新 Source Probe 结果归纳；
- 根据失败样本建议 URL Pattern、CSS/XPath、DOM Repair；
- QUARANTINE 聚类与根因分析；
- Drift 告警解释；
- Canary Candidate Diff 辅助审查；
- 管理后台自然语言解释某篇文档为什么没有 PASS；
- 可选 LLM Exception 分类。

### 17.2 禁止场景

- 每 URL 用 LLM 判断是不是文章；
- 每文章让 LLM 重写正文后作为 Canonical；
- Agent 失败阻塞全站增量；
- Agent 自动修改 ACTIVE Source Profile；
- 无界 Critique/Revision 自循环；
- 用模型判断替代 Coverage Evidence 和确定性版本哈希。

### 17.3 Agent 配置发布流程

```text
Failure Samples / Probe
 -> Agent Suggestion
 -> Candidate Rule/Recipe
 -> Static Validation
 -> Golden Replay
 -> Live Sample Test
 -> CANARY
 -> Metrics Compare
 -> Human Approval
 -> ACTIVE
```

Agent 只产出 Candidate，不直接改变业务真相。

## 18. 检索、向量与可重建 Projection

Chunk 不是事实层，由 `document_version_id + chunker_release` 生成。

结构切分：

1. heading section；
2. paragraph group；
3. code block 尽量不拆；
4. 超长 section 再递归；
5. 每 chunk 保存 source/document/version/heading path。

默认检索链：

```text

 -> metadata filter
 -> OpenSearch BM25 recall
 -> pgvector semantic recall
 -> RRF/weighted fusion
 -> reranker
 -> dedup/diversity
```

Embedding、BM25、Graph 在 Document Version PASS/WARN 后异步执行；Projection 故障不能阻塞抓取和 Canonical。

## 21. 成本、安全与合规

### 21.1 成本治理

统一记录：

```text
cost_event
- source_id
- run_id
- task_id
- kind: NETWORK | CPU | BROWSER | STORAGE | EMBEDDING | LLM | GRAPH
- quantity
- unit
- estimated_cost
- occurred_at
```

优化顺序：

1. Authoritative Discovery；
2. Cheap Classification/Route；
3. HTTP First；
4. Conditional GET；
5. Artifact/Semantic Hash 去重；
6. Structured/Trafilatura/确定性抽取；
7. 有恢复证据时才 Browser；
8. Repair/Fallback 按收益持续治理；
9. LLM 仅控制面/异常路径；
10. Projection 只处理有效当前版本。

### 21.2 SSRF 与网络安全

每个请求和 Redirect 都重新校验：

- 仅 http/https；
- DNS 解析；
- 禁止 loopback、link-local、private CIDR、metadata endpoint；
- Browser iframe/navigation/request 同样执行 egress policy；
- proxy 不得绕过目标校验。

### 21.3 Web 管理安全

- RBAC：viewer/operator/admin；
- Secret 不回显；
- Recipe 默认不接受任意 JS；
- Agent/LLM 不能生成并直接执行任意脚本；
- Source Release 激活可要求 Approval；
- Audit Log 记录配置、Circuit、Replay 和人工操作。

### 21.4 来源策略

每个 Source 记录 robots policy、crawl delay、授权/许可证备注、资产下载策略和导出权限。技术上可访问不等于拥有再分发权。

## 24. 验收标准

### 24.1 历史抓取

- 每个 Source 能展示 URL 从哪个 Provider 发现；
- Provider 有 stop reason/exhaustion evidence；
- Known Gap 可见；
- 失败可 Replay；
- 不以“crawler 结束”代替 Coverage 完成。

### 24.2 增量

- 新文章在目标 Freshness 内进入 PASS/WARN Markdown；
- 304 不生成正文版本；
- 正文修改生成新 Version；
- 页面模板噪声变化尽量不制造假正文版本；
- 删除需要多证据确认；
- 重复任务不产生脏重复。

### 24.3 抽取与质量

- Fetch success 与 Extraction/Quality success 独立；
- 多 Extractor Candidate 可追溯；
- selector drift 能被 Agreement/Drift 检出；
- Repair 有固定上限；
- Repair 前后质量和成本可量化；
- 未通过 Quality Gate 的内容不会因 Browser/LLM 熔断而被标记 PASS；
- Markdown 结构稳定且可回溯 Canonical IR；
- Renderer 升级可离线重建。

### 24.4 扩展性

- 新 Source 主要通过 Probe/Profile/Family/Recipe 接入；
- 大站 Backfill 不阻塞增量；
- Browser 故障不拖垮 HTTP；
- Agent/LLM 故障不拖垮 Canonical 主链；
- 单 Extractor 故障可以切换 Candidate；
- Projection 停止不影响抓取和版本事实；
- 站点改版后可通过 Candidate Release -> Replay -> Canary 恢复。
