# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站和公开 Newsletter** 的长期采集与知识库平台，可平滑扩展到数千站点、百万到千万级文章。

平台必须同时满足：

1. **全历史回填**：尽可能完整发现每个已批准 Source 的历史文章，并能解释发现通道、覆盖率、缺口、截断与停止原因；
2. **持续增量同步**：发现新文章、正文修改、元数据变化、URL 迁移、重定向、删除与重发布；
3. **Markdown 稳定可重放**：保存不可变 Raw Artifact，经版本化 Cleaner、Extractor、Canonical IR、Renderer 生成最终 Markdown；
4. **技术内容保真**：代码块、表格、公式、Mermaid、列表、引用、脚注、图片说明不能被通用降噪算法静默删除；
5. **低成本扩站**：新增站点优先通过 Source Profile、Provider、Recipe、Traversal Policy 配置完成，不维护 1000 份独立爬虫脚本；
6. **Web 可运营**：支持站点接入、审批、Backfill、Incremental、Coverage、Frontier、质量、成本、诊断、暂停、恢复、重跑、灰度与审计；
7. **任务可恢复**：Provider Run、Task、Attempt、URL、Artifact、Candidate、Document、Version 全链路持久化，Worker/Runtime 崩溃可恢复；
8. **可搜索/RAG**：支持 BM25、向量和混合检索，并可回溯原文、版本、Source、抓取证据与处理 Release；
9. **主链不依赖 LLM**：LLM 仅用于可选 Repair/Enrichment，不参与 Coverage、URL 身份、正文存在性、版本真相、Freshness 或权限边界的最终判定。

### 1.1 核心 SLO

- **Coverage**：每个 Source 可查看 Provider Inventory、Completion Attestation、Known Gap、Backfill Stop Reason；
- **Freshness**：新文章/更新从发布或发现到 PASS Markdown 的 P50/P95/P99 延迟；
- **TTFM**：URL 首次发现到首个可用 Markdown 的时间；
- **Extraction Quality**：标题、正文、代码、表格、列表、链接、图片说明、公式召回率与噪声率；
- **Protected Structure Recall**：受保护技术节点在 Candidate/IR 中的保留率；
- **Multilingual Retention**：中文、日文及中英混排正文保留率；
- **Reliability**：Task 成功率、Retry、DLQ、Queue Age、Lease Recovery；
- **Replayability**：相同 Raw Artifact + 相同 Release 得到相同派生结果；
- **Provider Integrity**：partial、cache hit、预算耗尽不能被误报为完整枚举；
- **Validator Integrity**：业务 validator 必须绑定具体 Raw Artifact/body hash；
- **Browser Efficiency**：HTTP Fast Lane 命中率、Browser avoided、Browser 单文档成本；
- **Fairness**：大型 Backfill 不得长期饿死 Incremental、Revalidation、Repair、小站；
- **Agentic Safety**：越界导航、Policy Deny、Prompt Injection、Secret 泄露可监控、可审计；
- **Agentic Progress**：Agent 循环、停滞、无新增 Observation 必须由平台硬终止，不能依赖模型自行纠错；
- **Recipe Stability**：Production Recipe 的 selector 命中率、歧义率、mutation survival、deterministic replay 成功率可量化。

## 2. 核心设计原则

1. **Coverage First**：先构建可解释 URL Inventory，再抓正文；
2. **Authoritative First**：官方 CMS/API、Sitemap、Feed、Archive 优先；
3. **Observation Before Selection**：发现事实先落库，再 Normalize、Scope、Classify、Dedup；
4. **Successful Return != Provider Complete**：HTTP 200、非空结果、`success=true`、cache hit 都不能自动代表 Provider 完成；
5. **Completion Must Be Attested**：只有具备可验证结束语义的 Provider Adapter 才能声明完整；
6. **Discovery / Revalidation / Fetch / Clean / Extract / Quality / Canonicalize / Projection 分离**；
7. **HTTP First, Browser Slow Lane**；
8. **Snapshot First**：Provider Evidence / Raw Artifact 先保存，再生成派生物；
9. **Candidate Portfolio, Not Single Extractor**；
10. **Protected Structures Are First-Class**；
11. **Language Assumptions Must Be Explicit**；
12. **Canonical IR First, Markdown as Projection**；
13. **Recipe, Not 1000 Site Scripts**；
14. **Persistent Frontier, Not In-Memory Traversal**；
15. **Idempotent + Recoverable**：幂等键、Lease、Fencing Token、Checkpoint、Inbox/Outbox；
16. **Fair by Default**：Incremental、Revalidation、Repair 预留容量；
17. **Bounded Concurrency Everywhere**；
18. **No Silent Degradation**：过滤、截断、partial、预算耗尽、cache fallback、降级都有 typed reason；
19. **Correlate by Identity, Never by Position**；
20. **Config Is Capability**：高能力配置必须经过 Capability Firewall；
21. **Runtime Is Execution Plane**：第三方 Runtime 不拥有 Coverage、Identity、Version、Freshness、Markdown 真值；
22. **Behavior Beats Naming**：生产语义以 pinned release + Contract Test 为准；
23. **Runtime Cache Is Disposable**；
24. **Derived Artifact Never Overwrites Evidence**；
25. **Weak Freshness Signal Cannot Close Truth**；
26. **Validator Must Bind To Artifact**；
27. **Same URL Does Not Imply Same Representation**：不同 locale/Cookie/UA/Proxy/session/Browser Profile 使用 `fetch_variant_key` 隔离；
28. **Offline Means No Network**：离线 Replay 由平台 Artifact + egress deny 保证；
29. **Explicit Runtime Config**：生产 Attempt 不依赖 Runtime 默认值；
30. **Agentic Repair Is Proposal, Not Truth**：Agent 只提出诊断、Observation、Recipe Candidate；
31. **Ephemeral Element Identity**：highlight index/CDP node id 只属于当前观测，Production Recipe 只能引用 `SelectorBundle`；
32. **Agent Replay Is Diagnostic**：Browser Use history replay 不等于确定性 Recipe Replay，也不等于 Task Recovery；
33. **One Mutating Action, One State Boundary**：会改变 DOM/URL/target 的动作后重新采样；
34. **Web Content Is Untrusted Prompt Input**；
35. **Agentic Runtime Is Hermetic**：显式 Tool/Domain/IP/egress/Profile/Permission 边界；
36. **Soft Agent Heuristics Are Not Hard Limits**：Browser Use 的 loop/planning/replan 提示属于模型上下文中的 advisory signal；生产循环、停滞、无进展必须由平台独立 `Agentic Progress Guard` 硬终止。

## 6. 全历史 URL 发现与 Coverage

### 6.1 Provider 顺序

1. CMS/API；
2. Sitemap/Sitemap Index；
3. RSS/Atom；
4. Archive/Pagination/Tag/Category；
5. 静态链接图；
6. Common Crawl Index；
7. Wayback；
8. Crawl4AI URL Seeder/Domain Mapping/Deep/Adaptive 作为补洞与加速。

任何单一 Provider 都不能自动证明“全历史完整”。Agentic Browser 只能产生 Observation 或提示潜在入口，不能成为 Completion Authority。

### 6.2 Observation 与 Inventory

每条发现先写：

```text
url_observation(
  observation_id, source_id, provider_id, provider_run_id,
  observed_url, observed_at, provider_timestamp,
  provider_metadata, provider_evidence_uri
)
```

然后统一执行：

```text
Normalize -> Scope Check -> MIME Hint -> URL Identity -> Dedup -> Frontier Upsert
```

### 6.3 Provider Completion Attestation

Provider Run 保存 checkpoint/cursor/shard、items_seen、unique_urls、status、completion_type、stop_reason、truncated、budget_exhausted、known_gap、provider_release。只有 Adapter 的协议级结束条件满足时才允许 `ATTESTED_COMPLETE`。

HTTP 200、非空结果、达到 limit、cache hit、Deep Crawl 达到深度、Agent 暂时无新 URL、LLM 报“完成”都不能证明完整。

### 6.4 Sitemap / Common Crawl / Wayback

- Sitemap Index 拆 durable shard；
- Sitemap 增量使用 Conditional GET，`lastmod` 仅是变化线索；
- Common Crawl/Wayback 固定 index/release、保存查询 Evidence、流式处理；
- Archive 出现不代表当前仍有效，Archive 缺失也不能证明文章从未存在。

### 6.5 Coverage 页面

每 Source 维护 provider_inventory、provider_attestation、historical_time_range、observed/fetchable/article count、known/unresolved gap、backfill_stop_reason，并能回答“为什么认为完成/未完成”。

## 7. URL Identity、Canonical 与 Persistent Frontier

### 7.1 URL 三层身份

```text
observed_url   Provider 实际看到的 URL
normalized_url 平台规则归一化后的 URL
canonical_url  经多证据判定的文章主 URL
```

`rel=canonical` 不是绝对真相。Normalize 只做安全规则；query、path 大小写、www/apex、HTTP/HTTPS 合并必须 Source-specific。

### 7.2 去重

```text
exact URL -> redirect/canonical alias -> raw body hash -> semantic hash -> SimHash/MinHash
```

近重复只建立关系，不静默删除版本。

### 7.3 Frontier

```text
url_id, source_id, normalized_url, canonical_url, fetch_variant_key,
state, priority, next_action_at, last_discovered_at,
last_fetch_at, last_verified_at, retry_count,
lease_owner, lease_until, fencing_token
```

状态覆盖 DISCOVERED、DUE_FOR_REVALIDATION、FETCH_REQUIRED、FETCHING、FETCHED、EXTRACT_PENDING、PASS、REPAIR、REVIEW、DELETED、BLOCKED、DEAD。

### 7.4 公平调度与 Backpressure

使用 P0 incremental-hot、P1 revalidation、P2 new-source-backfill、P3 historical-gap、P4 repair/replay；按 source/host/domain/workload Weighted Fair Queueing。Redis Lua 维护 host token bucket、source/domain/browser semaphore、agentic token/cost quota。

Queue Age、DB latency、S3 backlog、Browser 饱和、429/503、Agentic cost 接近预算时，先暂停低优先级 discovery/agentic repair，保留 Incremental/Revalidation 容量。

## 8. Revalidation Engine 与增量同步

### 8.1 增量入口

CMS revision、Sitemap `lastmod`、RSS `updated`、Webhook、Archive 新链接、定时 Revalidation、强制完整刷新、人工重抓、Provider Reconcile。

### 8.2 Revalidation Ledger

保存 `last_fetch_at/last_verified_at/last_changed_at`、ETag/Last-Modified、raw/semantic hash、head fingerprint、validator strength、validator_artifact_id、validator_body_sha256、origin、binding state、validation method/result/reason、runtime cache status、consecutive_304、forced_refresh_due_at、false-negative、source trust score。

### 8.3 证据强度

- **STRONG**：CMS revision；使用绑定当前 authoritative Artifact 的 validator 得到标准 304；完整 GET 后 body hash 一致；
- **MEDIUM**：validator 变化、Sitemap/RSS 更新时间变化；
- **WEAK**：head fingerprint、长度、link graph、局部 metadata、Agent/LLM 判断未变化。

只有符合 Source Policy 的强证据才能推进 `last_verified_at`。

### 8.4 Validator Binding Invariant

1. 只有与完整网络响应一起得到的 validator 才能绑定该 Raw Artifact；
2. HEAD/弱校验得到的新 validator 只能记录 `UNBOUND_HINT`；
3. 304 只有在请求 validator 已绑定当前 authoritative Artifact/body hash 时才是 STRONG；
4. Runtime Smart Cache weak match 后更新的 validator 不得直接导入业务真相；
5. Artifact 被新版本替代后旧绑定进入历史或失效；
6. 定期完整抽样校验 false negative，并动态调整 trust score。

## 9. HTTP、Browser 与 Runtime Cache

### 9.1 HTTP Fast Lane

普通文章优先 `httpx/aiohttp`，记录 redirect、response headers、Content-Type、encoding、validator、原始字节。正文质量满足条件即不启 Browser。

### 9.2 Deterministic Browser Slow Lane

仅 HTTP 空壳、JS 渲染、有限交互、Shadow DOM/iframe、HTTP Candidate 低质量或 Source Recipe 指定时升级。生产默认使用长期 Browser Pool + **确定性 Recipe Executor**。

### 9.3 Agentic Browser Repair / Recipe Studio

只在确定性路径失败、Source onboarding 探索、长期 REPAIR/REVIEW 或 Operator 诊断时启用：

```text
HTTP / deterministic Browser failed
        |
        v
Agentic Browser Repair Sandbox
        |
        +--> BrowserState(DOM/AX/screenshot/URL)
        +--> bounded structured actions
        +--> Browser Gateway policy enforcement
        +--> Agentic Progress Guard
        +--> immutable trace/evidence
        |
        v
Selector Compiler + Recipe Compiler
        |
        v
Recipe Candidate
```

运行绑定 source/url/fetch_variant、Browser Use/Chromium/model/prompt/tool/security/observation/progress-guard release，并设置 max steps/actions/page/tab/wall-time/token/cost/artifact bytes 硬预算。

#### 9.3.1 Browser Use 内置循环检测的边界

Browser Use 当前 `ActionLoopDetector` 会对动作进行归一化 hash，维护滚动窗口，并用页面 URL、DOM 文本表示、可交互元素数量形成页面 fingerprint；重复动作达到阈值、连续页面状态不变时，它会向 LLM 上下文注入逐级 nudge。planning/replan 在探索过久或连续失败时同样通过消息提示模型调整策略。

**这些机制是 soft detection，不会阻止模型继续重复动作。** 因此它们只能作为诊断和辅助恢复信号，不能承担生产硬终止、Provider Completion 或成本保护。

#### 9.3.2 Agentic Progress Guard

平台在 Agent Loop 外部实现独立、版本化、不可被 prompt 修改的 `Agentic Progress Guard`。每一步计算：

```text
progress_fingerprint = hash(
  normalized_url,
  focus_target_id_hash,
  dom_semantic_hash,
  discovered_url_set_hash,
  candidate_or_observation_hash,
  normalized_action_signature
)
```

并维护：

- rolling action repetition；
- 同一/近似状态连续停滞次数；
- state fingerprint 重访次数；
- 连续无新 URL/Observation 的 step 数；
- action/step/page/tab/wall-time/token/cost 硬预算。

达到策略阈值时，**平台直接终止 Run，不等待下一次 LLM 自我修复**，返回 typed reason：

```text
AGENT_ACTION_LOOP
AGENT_STATE_STAGNANT
NO_NEW_OBSERVATION_PROGRESS
REPEATED_STATE_CYCLE
PLANNING_STALL
MAX_STEPS
WALL_TIME_EXHAUSTED
TOKEN_BUDGET_EXHAUSTED
COST_BUDGET_EXHAUSTED
POLICY_DENIED
CROSS_SCOPE_BLOCKED
```

Browser Use 自带 loop/replan nudge 可同时保留，并记录为 advisory evidence，但不得覆盖平台 hard-stop decision。

#### 9.3.3 一步多动作

候选录制默认 `max_actions_per_step=1`。探索模式若允许 multi-action，任何改变 DOM/URL/focus target 的动作后必须重新采样 BrowserState；URL/target 不变的 SPA 局部重绘也不能继续使用旧 highlight index。

#### 9.3.4 Agentic 安全边界

- approved domain/path 来自 Source Scope；导航前、redirect 后、新 tab 均检查；
- DNS/网络层阻止 IP、localhost、private/link-local/metadata 并防 DNS rebinding；
- Pod/容器 egress 独立 allowlist；
- 默认禁用 upload/download/file/clipboard/任意 JS/任意 CDP/表单提交/发布/删除/支付；
- `data:`/`blob:`/`file:` 默认拒绝；
- public blog 使用临时无认证 Profile；
- Cookie/Storage/Proxy/locale/UA/timezone 按 `fetch_variant_key` 隔离；
- secret 只以引用注入，trace 脱敏。

Agent 的 `extract`/final result 只能用于诊断/候选，不得直接变 canonical Markdown、Document Version、Freshness 或 Coverage。

### 9.4 Selector Compiler

Browser Use highlight index、CDP node id/backend node id 只在单次观测中有效。Agent evidence 编译为：

```text
selector_bundle
  semantic_role
  accessible_name
  stable_attributes / data_attributes
  id_name_candidates[]
  stable_text_anchor
  css_candidates[] / xpath_candidates[]
  ancestor_constraints[] / frame_scope
  expected_cardinality
  fallback_order[]
  selector_fingerprint
  fixture_match_rate
  live_sample_match_rate
  ambiguity_rate
  mutation_survival_rate
  selector_strategy_release
```

Production Recipe 只能引用 `selector_ref`。无法把临时元素引用编译成无歧义 selector 时返回 `UNCOMPILABLE_ELEMENT_REFERENCE`。

### 9.5 Deterministic Recipe Promotion Gate

```text
Agentic Evidence
 -> Selector Compiler
 -> Recipe Compiler
 -> Recipe Candidate
 -> Schema / Static / Security Validation
 -> Selector Ambiguity Validation
 -> Deterministic Fixture Replay
 -> Repeated Replay
 -> Sampled Live Replay
 -> Shadow
 -> Source Canary
 -> Human/Policy Approval
 -> recipe_release
```

所有 loop 有 hard bound、wait 有 timeout；禁止任意 JS/CDP/file/upload/download side effect；同 fixture 重放稳定；URL discovery、正文质量、Protected Structure Recall、成本无明显回归。若仍需 LLM 决策，则不能晋升生产。

### 9.6 Runtime Cache Policy

业务层只暴露：

```text
AUTHORITATIVE_FETCH
VALIDATE_THEN_FETCH
REPLAY_FROM_ARTIFACT
RUNTIME_CACHE_WARMUP
DIAGNOSTIC_CACHE_READ
```

Crawl4AI `CacheMode`、legacy flags、Smart Cache 真实语义由 pinned release Contract Test 验证。Runtime cache 仅优化执行，不能推进 Coverage/Freshness/Version/validator 真相；`READ_ONLY` 不是离线保证，`hit_fallback` 不是 freshness proof。

Runtime cache namespace 至少按 `source_id + fetch_variant_key + runtime_release` 隔离。Runtime cached Markdown/Extracted Content 永远不直接成为 canonical。

## 10. Raw Artifact、Extraction 与 Markdown

### 10.1 Raw Artifact

每次真实网络抓取生成不可变：


### 10.2 Protected Structure + Extraction Portfolio

Cleaner 前建立 `<pre>/<code>`、table、blockquote、figure/figcaption、Mermaid、MathJax/KaTeX、脚注、图片/alt/caption Manifest。

```text

  title / subtitle / authors[]

  canonical_url / source_id
  blocks[]: paragraph/heading/code/table/list/quote/image/figure/math/mermaid/footnote
  links[] / metadata / provenance
```

Markdown 是 IR 的确定性 Projection。同一 IR + renderer release 产生相同 Markdown hash。

## 11. Document、Version、删除与迁移

- `Document` = 逻辑文章；`DocumentVersion` = 业务正文版本；`RawArtifact` = 抓取证据；
- raw hash 不变不创建新 Version；raw 变但 semantic hash 不变只更新证据/metadata；semantic hash 变才创建新 Version；
- 保存完整 redirect chain，旧 URL 建 alias；
- 单次 404/5xx 仅进入 TOMBSTONE_CANDIDATE，多次确认/provider reconcile 后才 DELETED_CONFIRMED；
- 相同正文出现在新 URL 时保留独立 Observation，再建立 relation。

## 12. Task、Attempt、幂等与恢复

### 12.1 Task / Attempt

Task 保存 task_type/source/url/provider/priority/idempotency/state/lease/fencing/retry；Attempt 保存 worker/runtime/fetch_variant/config hash/start/end/result/error/artifacts。

幂等键：

```text

FETCH: url + fetch_variant + desired_fetch_generation
AGENTIC_REPAIR: source + url + fetch_variant + repair_generation + policy_release
RECIPE_VALIDATE: recipe_candidate + promotion_policy + fixture_release
EXTRACT: artifact + extractor_release
RENDER: ir_hash + renderer_release
INDEX: version + index_release
```

### 12.2 Lease + Fencing + Inbox/Outbox

Worker 领取任务原子更新 lease 并增加 fencing token，最终写入必须校验 token。PostgreSQL 状态变化通过 Transactional Outbox 发布，消费端 Inbox 幂等。

### 12.3 Browser Use 恢复语义

```text
Browser Use history replay = 启发式诊断复现
Production Recipe replay   = 无 LLM 的确定性 DSL 重放
Platform Task recovery     = Task/Attempt/Lease/Fencing/Artifact 恢复
```

CDP reconnect 只记录 runtime event；Agentic crash 结束当前 Attempt 并保存已晋升 evidence；新的 Agentic Run 不宣称“继续同一事务”。

## 13. Durable Transport 与 Runtime Service Plane

Redis Streams 仅做可重建 Transport：discovery、revalidation、fetch-http、fetch-browser、extract、repair、agentic-repair、recipe-validate、render、index、reconcile。

要求 Consumer Group、Pending Recovery、DLQ、Queue Age、从 PostgreSQL Reconcile。

使用 bounded micro-batch：限制 URLs/batch、inflight、result bytes、browser pages、batch wall time。确定性 Browser Pool 与 Agentic Repair Pool 分离。

## 16. 安全与合规

### 16.1 SSRF / Browser 隔离

所有 URL Fetch 前解析 DNS；禁止 loopback/private/link-local/metadata；redirect 每跳重验；防 DNS rebinding；Approved Host/Path allowlist。

DOM、AX、截图、隐藏文本、下载内容都是不可信输入。System task/Tool Policy/Source Scope/Secret Policy 来自版本化配置并与网页内容隔离；页面不能扩大 Tool、Domain、Secret、JS/CDP/File 权限。维护恶意 Fixture Corpus 做回归。

## 19. 测试与发布门禁

### 19.1 Fixture Corpus

覆盖 WordPress/Ghost/Hugo/Jekyll/React/Next.js/Medium/Substack、中日韩、多代码/表格/公式、JS render、redirect、错误 canonical、弱 validator、head 不变正文变化、多 locale/UA/Cookie、DOM 重绘、随机 class、同名按钮、iframe/shadow、跨域 redirect/new tab、IP/private/metadata、data/blob/file、prompt injection、CDP disconnect/crash。

### 19.2 Golden / Runtime Contract

- Raw → Cleaner → Candidate → IR → Markdown 做 Golden hash/结构 diff；
- Production Browser Recipe fixture 多次重放，禁止 LLM；
- Crawl4AI 验证 CacheMode、Smart Cache、READ_ONLY miss、hit_fallback、legacy mapping、variant 污染、validator poisoning；
- Browser Use/Chromium/model/prompt/tool/observation/selector/progress-guard 升级执行 Agentic Contract Test。

**Agent/Action Contract**：

- recording `max_actions_per_step=1`；
- multi-action 导航/DOM 变化后重新采样；
- output schema 失败显式失败；
- step/action/wall-time/token/cost/page 硬预算可强停；
- Browser Use `ActionLoopDetector` 的 soft nudge **不得**被当作 hard guard；
- 重复同一 action/state 的 fixture 必须被平台 Progress Guard 强制终止；
- 无新增 URL/Observation 的 fixture 必须产生 typed stop reason；
- evidence 必须包含 progress fingerprint、重复/停滞/revisit 计数与 guard decision。

**Element/Replay Contract**：highlight index 不进入 Recipe；history replay match 仅诊断；同名/重复 selector 不得错误晋升；`nth-child`/随机 class 无稳定 fallback 时拒绝；无法编译临时元素引用返回 `UNCOMPILABLE_ELEMENT_REFERENCE`。

**Security Contract**：跨域/IP/private/metadata/data/blob/file 阻断；upload/file/evaluate/CDP/clipboard 默认不可用；Storage State 不跨 Source/variant；网页不能扩大权限；容器 egress 兜底；trace 不泄露 secret。

**Recovery/Artifact Contract**：CDP reconnect 不推进业务状态；crash 保留 evidence；Agent rerun 不是 deterministic resume；Agent extracted text 不绕过 Raw Artifact pipeline。

### 19.3 Canary

任何 Runtime/Cleaner/Extractor/Renderer/Recipe 升级：fixture → shadow → 小比例 canary → quality/freshness/cost/security diff → 扩大灰度 → 全量。Browser Use/model/prompt/tool/progress-guard 升级不自动改变已发布 Production Recipe。

## 22. 最终推荐架构与不可破坏边界

最终采用：

> **PostgreSQL Truth Store + S3/MinIO Immutable Artifact + Redis Streams Durable Transport + Declarative Source/Profile + Multi-Provider Discovery + Persistent Frontier + Revalidation Engine + Validator-to-Artifact Binding + Fetch Variant Isolation + HTTP First / Deterministic Browser Slow Lane + Crawl4AI Runtime Service Plane + 可选 Hermetic Agentic Browser Repair / Recipe Studio + Agentic Progress Guard + Selector Compiler + Recipe Compiler + Deterministic Recipe Promotion Gate + Cache Policy Compiler + Runtime Contract Release Gate + Extraction Portfolio + Canonical IR + Deterministic Markdown + OpenSearch/pgvector + Web Admin。**

不可破坏边界：

- Provider 返回不是 Coverage 真相；
- Runtime cache 不是 Freshness、Version、Replay 真相；
- 同 URL 不等于同表示，cache 不跨 fetch variant 盲目复用；
- Runtime cached Markdown/Extracted Content 不是 canonical；
- weak freshness/head fingerprint 不能证明正文未变；
- validator 必须绑定具体 Raw Artifact/body hash；
- `hit_fallback` 不是 freshness proof，`READ_ONLY` 不是离线安全边界；
- Raw Artifact 不可变，所有清洗/抽取/Markdown 可重放；
- Browser 是昂贵慢路径，不是默认路径；
- LLM/Agentic Browser 只能提出诊断、Observation 或 Recipe Candidate；
- Browser Use highlight index/CDP node identity 不是 Production Selector；
- Browser Use history replay 不是 Recipe Replay，也不是 Task Recovery；
- 任何 DOM/URL/target 变化后重新采样；
- **Browser Use loop/planning/replan 等内部提示是 advisory，循环、停滞、无进展由平台 Agentic Progress Guard 强制终止，绝不等待 LLM 自行纠错；**
- 网页内容是不可信 prompt 输入，不能扩大 Capability；
- Agentic Browser 必须显式 Tool allowlist、Source Scope、IP/私网阻断、容器 egress、临时 profile、最小权限；
- Agent extracted/final text 不是文章正文真相；
- Coverage、Version、Freshness、Validator Binding、Markdown 的最终真相始终在平台层。
