# 博客知识库技术方案

## 1. 建设目标与规模边界

建设一个可长期运行、可横向扩展的技术博客知识库平台。首期约 1000 个技术博客、工程博客和技术文档站，抓取尽可能完整的历史文章并清洗为稳定 Markdown；后续可持续增加站点，并支持增量同步、版本追踪、全文/向量检索、Web 管理、质量审计和离线重处理。

设计按以下量级考虑：

- 1000+ Source，后续可扩展到数千站点；
- 百万级 Document；
- 数百万到千万级 URL / Observation；
- 多年运行、站点结构持续变化；
- 中英日韩等多语言技术内容；
- HTTP 为主、Browser 为受控 fallback；
- 历史 URL 发现允许接入 Sitemap、Feed、CMS API、Archive、Common Crawl URL Index 等多来源；
- 原始事实可长期保留，Markdown、Chunk、Embedding、全文索引等派生结果可删除重建。

平台核心目标不是“能抓页面”，而是形成一套可证明历史 Coverage、可恢复任务、可回放处理、可追踪版本、可解释身份、可持续发现新文章、可增量重建投影、可替换底层抓取与检索组件的系统。

## 2. 核心设计原则

1. **Config First**：新增普通站点主要通过 Source / Site Profile 配置完成，不修改核心代码。
2. **Coverage First**：历史完整性由 Provider Evidence 与 exhaustion reason 证明，不能用“队列为空”“达到 max_pages”冒充完整。
3. **Discovery Before Fetch**：先低成本发现候选 URL，再决定哪些 URL 需要真实抓取。
4. **Prefetch Before Extraction**：未知结构优先轻量获取 HTML + links，发现阶段不默认执行 Markdown/正文抽取。
5. **Discovery Surface First-class**：Sitemap、Feed、Archive、Category、Tag、Blog Index、Docs TOC 等持续产出文章 URL 的页面/接口作为长期资产维护。
6. **Graph, Not Tree**：现代站点按有环图处理，不假设严格目录树。
7. **Soft Pruning, Never Blind Deletion**：分支收益低或已饱和时只降权、设置 TTL、保留抽样复查，不做不可恢复剪枝。
8. **Authoritative First, Archive as Supplement**：CMS/API/Sitemap/Feed 优先；Common Crawl、Wayback 等第三方历史档案只作为补洞和证据。
9. **HTTP First, Browser Last**：Feed/API/Sitemap/HTTP 优先，Browser 只处理动态页面、结构探索或低质量 fallback。
10. **Resolution Is a First-class Plane**：Observed URL、Normalized Candidate、Resolved Target、Network Final URL、Canonical Identity 是不同事实。
11. **Snapshot First**：网络事实先保存不可变 Snapshot，再抽取、清洗、建版。
12. **IR First, Markdown as Projection**：Canonical IR / Document Version 是事实层；Markdown、Chunk、Embedding、全文索引均可重建。
13. **Canonical Content 与 Query View 分离**：BM25/LLM/Query-focused Fit Markdown 不能覆盖完整正文。
14. **Language-aware Retrieval**：分词、stemming、stopwords、BM25 threshold、tag weight 按 Analyzer Release 版本化。
15. **Release Everything**：Profile、Discovery、Normalization、Classifier、Branch Policy、Resolver、Fetch Route、Extractor、Quality、Markdown、Chunk、Analyzer、Embedding、Retrieval 均版本化。
16. **Idempotent + Recoverable**：所有任务有幂等键、lease、checkpoint、retry 和 partial success 语义。
17. **Source Sync 与 AI 解耦**：Embedding、Rerank、LLM、Summary 等失败不能阻塞源站事实同步；LLM 不能自动执行会导致 Coverage 丢失的永久过滤。
18. **Evidence Everywhere**：发现、分类、分支降权、跳转、抓取、抽取、身份、版本、检索都可解释、可审计。
19. **Web 管理是平台能力**：异常、Coverage、Discovery Surface、Branch、跳转链、版本、成本、索引、策略 Release 都必须可运营。
20. **安全边界每跳执行**：重定向与 Browser 导航不能绕过 SSRF/Egress/访问策略。

## 4. 技术选型

### 4.1 控制面

- **FastAPI + Pydantic**：REST / Command API、Schema 校验。
- **PostgreSQL**：Source、Profile Release、Run、Task、Coverage、Discovery Surface、Branch State、URL Observation、Redirect、Fetch、Document、Version、Projection State、Audit、Outbox。
- **Transactional Outbox**：数据库状态变更与消息发布保持事务一致。
- **Redis Streams**：任务运输、consumer group、retry、backpressure；不保存唯一业务事实。
- **React/Vue + TypeScript**：Web 管理。

### 4.2 数据面

- **HTTPX / aiohttp**：HTTP、Feed、Sitemap、API、条件请求和低成本跳转解析。
- **BeautifulSoup / lxml / CSS / XPath**：wrapper、meta refresh、selector、结构化 HTML 处理。
- **Trafilatura / Readability**：确定性正文候选。
- **Crawl4AI / Playwright**：URL Seeding、Prefetch Mapping、Deep Crawl、Domain Mapping、动态页面和 Browser fallback。
- **DuckDB / Athena / Spark / Polars**：Common Crawl URL Index 批量历史 URL 查询；1000 站点场景不依赖高并发 CDX API。
- **S3 / MinIO**：HTML、HTTP body、Rendered DOM、Feed payload、Common Crawl/WARC 恢复快照、PDF、Canonical IR、Markdown、Asset、调试产物。
- **OpenSearch**：全文检索、过滤、聚合、BM25。
- **pgvector / OpenSearch kNN** 起步；规模或独立扩展需求增加后可替换为 Qdrant / Milvus。
- **Prometheus + Grafana + OpenTelemetry**：指标、日志、Trace。

### 4.3 Crawl4AI Adapter 与版本治理

Crawl4AI 不直接渗透业务模型，通过 Adapter 隔离：

```text

```

每次运行记录：

```text

```

升级前使用固定回归集比较：URL 发现量、重复率、Surface 命中率、分支收益、正文长度、标题、代码块、表格、链接、图片、Browser 成功率、耗时和成本，验证后再切换 Release。

## 7. 新站接入与 PROBE

新增站点先执行 `PROBE`，不直接深爬：

1. 规范化 entry URL，确定 registrable domain、allowed origins 和 scope。
2. 获取 robots 及 Sitemap 声明。
3. 探测 Sitemap Index / Sitemap。
4. 探测 RSS / Atom / JSON Feed。
5. 探测 WordPress REST、Ghost、Substack 等平台能力。
6. 识别 Archive、Category/Tag/Author、Blog Index、Docs Navigation、pagination。
7. 低成本查询 Common Crawl；生产批量历史发现使用 URL Index，CDX 仅用于轻量/交互查询。
8. 必要时使用 Domain Mapping 补充发现子域/历史路径，结果必须再次经过 scope policy。
9. 对 URL path 做模板聚类，推断 article template、surface template、分页规则。
10. 使用 Prefetch Mapping 获取未知 hub 的 HTML + links，不生成 Markdown。
11. 使用 BFS 1~2 层或 BestFirst 小预算探索未知结构，寻找高产出的 Discovery Surface。
12. 建立模板级 Discovery Graph，估算分支 article probability、surface probability 与新模板率。
13. 抽样比较 HTTP 与 Browser 正文质量、JS 依赖和成本。
14. 检测 Feed/Search 链接是否存在 wrapper、短链、meta refresh、JS redirect。
15. 推断主要语言和 analyzer hint。
16. 对 Surface 灰区使用 LLM 辅助分类；只有人工接受后才进入生产 Profile。
17. 自动生成首版 Site Profile Release，在 Web 中人工审核/修正。

普通站点上线应主要完成“配置”，只有非常特殊站点才写 `SITE_CUSTOM_*` Adapter。

## 8. 全量历史发现与 Coverage

### 8.1 Provider Contract

所有发现 Provider 统一接口：

```text
probe(source, profile) -> capability
discover(cursor, budget) -> candidates + evidence + next_cursor
checkpoint() -> durable_cursor
exhaustion() -> explicit_reason
```

Provider 示例：

```text
CMS_API
SITEMAP
FEED
ARCHIVE
CATEGORY_TAG_AUTHOR
DOCS_TOC
DISCOVERY_SURFACE
PREFETCH_MAP
DEEP_CRAWL
COMMON_CRAWL_CDX
COMMON_CRAWL_URL_INDEX
SITE_SEARCH
```

### 8.2 推荐发现顺序

```text
Authoritative CMS/API
 -> Sitemap Index / Sitemap
 -> Historical Feed
 -> Archive year/month
 -> Category/Tag/Author
 -> Blog Index / Docs Navigation / TOC
 -> Common Crawl URL Index historical candidates
 -> Prefetch Mapping / Discovery Surface traversal
 -> Deep Crawl gap filling
 -> Site Search as supplement
```

站内搜索、Common Crawl、Deep Crawl 都不能作为完整历史的唯一来源。

### 8.3 Common Crawl 的语义边界

Common Crawl 只证明：

```text
某个 URL 在某个 CC-MAIN collection 中曾被观察/抓取
```

不证明：

```text
某个域名的全部历史 URL 已被 Common Crawl 收录
```

因此 Common Crawl Provider 不允许单独生成 `COMPLETE`。

`common_crawl_observation`：

```text

crawl_id
url_id
capture_time
status
mime
warc_filename
warc_offset
warc_length
content_digest
observed_at
```

小规模交互查询可使用 CDX；1000 站点历史枚举优先 URL Index（Apache Parquet）批处理并缓存 `(registered_domain, crawl_id)` 结果。

### 8.5 Provider Overlap

系统计算 Provider 交集和独有候选：

```text

Archive only
Common Crawl only
Surface only
Deep Crawl only
Multi-provider observed
```

用于发现 Sitemap 漏历史、Feed 窗口过短、Archive 不完整、Surface 结构变化等问题。

### 8.6 FULL_BACKFILL 完成条件

一个 Source 的历史回填只有在主要权威 Provider 明确 exhausted，或者所有未覆盖区间都已记录为可解释 known gap 时才结束。

Web 必须能回答：

- 使用了哪些 Provider；
- 每个 Provider 找到多少候选；
- Provider 的交集/独有 URL；
- 哪个时间区间/分页已穷尽；
- 哪些候选抓取失败；
- 哪些区间仍存在 gap；
- Common Crawl 是否只作为补充证据；
- 哪些分支因预算/soft-pruning 尚未完全探索。

## 10. Discovery Graph、URL Template 与 Branch State

### 10.1 Discovery Edge

现代站点按有环图处理。发现阶段保存必要的 parent-child 证据：

```text
discovery_edge_observation
  id
  source_id
  run_id
  parent_url_id
  child_url_id
  parent_template_id
  child_template_id
  anchor_text
  dom_path_signature
  link_region
  discovery_method
  observed_at
```

高体量原始 links 可按 Snapshot 存对象存储并设置生命周期，PostgreSQL 主要保存可查询的 provenance 与模板聚合。

### 10.2 URL Template

示例：

```text
/2026/08/my-post
/2026/08/another-post
 -> /{yyyy}/{mm}/{slug}
```

URL Template 用于：

- article pattern 推断；
- Surface/article 结构识别；
- Deep Crawl scorer；
- Branch State；
- 新 URL 异常检测；
- Site Profile 自动建议。

### 10.3 Branch State

按模板维度建立：

```text
surface_branch_state
  id
  source_id
  parent_template_id
  child_template_id
  query_signature
  sample_count
  unique_leaf_count
  unique_child_template_count
  new_url_rate_ema
  new_template_rate_ema
  article_yield_ema
  duplicate_ratio_ema
  saturation_score
  exploration_priority
  suppression_until
  suppression_reason
  last_sampled_at
  last_new_url_at
  branch_policy_release_id
```

### 10.4 饱和模型

```text
saturation_score =
    w1 * leaf_template_stability
  + w2 * duplicate_ratio
  + w3 * consecutive_zero_new_pages
  + w4 * low_new_template_rate
  + w5 * low_new_article_rate
  - w6 * coverage_gap_signal
  - w7 * structure_change_signal
  - w8 * provider_disagreement_signal
```

只有达到最小样本数后才允许降权。例如：

```text
sample_count >= N
unique_leaf_count >= M
new_template_rate_ema < epsilon
new_article_rate_ema < epsilon
连续 K 个分页/分支没有发现新候选
```

所有阈值进入 `branch_policy_release`。

### 10.5 Soft Pruning

高饱和分支只执行：

- 降低 BestFirst priority；
- 设置 `suppression_until`；
- TTL 到期重新抽样；
- Reconcile 强制穿透；
- 始终保留少量 exploration budget，例如随机复查 1%~5%；
- Sitemap/Feed/CMS 等权威新证据立即解除 suppression。

禁止：

- 删除原始 Observation；
- 永久忽略整个路径；
- 用 LLM 输出直接剪枝；
- 把 soft-pruned 分支视为 Coverage COMPLETE。

### 10.6 BestFirst 探索分数

```text
exploration_score =
    a * surface_probability
  + b * article_template_probability
  + c * coverage_gap_score
  + d * new_template_probability
  + e * historical_branch_yield
  + f * provider_disagreement
  - g * duplicate_probability
  - h * trap_probability
  - i * observed_cost
  - j * saturation_score
```

框架 scorer 仅负责执行排序，平台自己的 Branch State、Evidence、Coverage 和 Run 才是真相。

## 11. Candidate URL 规范化与分类

Discovery 与 Resolution 之间增加独立 Candidate Normalization / Classification Plane。

### 11.1 URL Normalization Release

`url_normalization_release`：

```text
id
version
host_policy
path_policy
query_policy
tracking_param_rules
semantic_param_allowlist
fragment_policy
created_at
```

典型规则：

```text
lowercase host
punycode normalization
default port removal
fragment removal
path slash normalization
safe percent-encoding normalization
query key ordering
tracking param removal
site-specific semantic param preservation
```

可以删除 `utm_*`、`gclid`、`fbclid` 等已知跟踪参数，但不能全局删除所有 query 参数，因为 `?id=123`、`?p=456`、`?page=7` 可能具有正文或分页语义。

### 11.2 分类状态

```text

DISCOVERY_SURFACE
ASSET
NAVIGATION
EXTERNAL_REFERENCE
IGNORE_BY_POLICY

```

所有过滤保留原始 Observation 与 Classification Evidence，避免不可逆丢失。

## 12. Prefetch Mapping 与 Deep Crawl

### 12.1 Prefetch Mapping

未知页面优先使用低成本发现链路：

```text
Seed URL
 -> Prefetch HTML + links
 -> URL Template / DOM Link Structure
 -> Classification / Graph
 -> 决定是否进入完整 Fetch
```

Prefetch 不生成 Markdown，不执行全文抽取，适合大量 hub/listing/navigation 页面。

### 12.2 Deep Crawl 角色

Deep Crawl 主要负责：

```text
未知站点结构探索
未知 Discovery Surface 发现
未知 URL Template 发现
Coverage gap 补充
Surface 失效后的重新探索
```

不能用：

```text
max_depth reached
max_pages reached
queue empty
```

作为历史完整证明。

### 12.3 策略

- PROBE：BFS 1~2 层，快速发现 hub/listing；
- 未知结构：Prefetch + BFS；
- 已知高价值目标路径：BestFirst；
- 特殊深层结构才使用 DFS；
- FilterChain + same-scope + query explosion/calendar/facet trap 防护；
- 使用 checkpoint/resume；
- Crawl4AI 内部恢复状态只是执行辅助，平台自己的 Task/Coverage 状态仍是事实源。

## 17. 增量同步、Pagination Early Stop 与 Reconcile

### 17.1 信号优先级

```text

 -> Sitemap lastmod
 -> High-yield Discovery Surface
 -> Conditional GET
 -> Metadata Probe
 -> Full HTTP
 -> Browser
```

### 17.2 Feed/API

保存原始 Feed payload 和 Item Observation，比较：

```text
GUID / platform id
link
updated
published
content hash
```

新 link 先进入 Candidate Normalization，再进入 URL Resolution 和 Fetch。

### 17.3 Surface 增量调度

初始层级：

```text
Tier 0: Feed / CMS API           分钟级或按需求
Tier 1: Sitemap / Blog Index     10~60 分钟
Tier 2: Category / Archive       1~6 小时
Tier 3: Deep Crawl Reconcile     每周/每月
Tier 4: Common Crawl Reconcile   新 CC-MAIN 发布后或按月
```

调度频率根据 `new_urls_per_scan`、失败率、重复率、分支收益和抓取成本动态调整。

### 17.4 Pagination Early Stop

历史回填需要完整遍历；增量扫描不应每次从新到旧扫到底。

Surface 保存：

```text
pagination_cursor
head_fingerprint
last_seen_boundary_url
last_seen_boundary_published_at
consecutive_known_pages
```

增量流程：

```text
page 1
 -> 有新 URL：继续 page 2
 -> 连续 K 页全部为已知 URL 且结构未变化：早停
 -> 遇到 Provider gap / structure drift：取消早停并升级 Reconcile
```

Early Stop 只是增量优化，不是 Coverage COMPLETE 证据。

### 17.5 Conditional Fetch

保存：

```text
ETag
Last-Modified
previous body hash
```

304：

- 不创建 Snapshot body 副本；
- 不创建 Document Version；
- 不重复 Extraction；
- 不重复 Projection。

### 17.6 Reconcile

即使有 Feed，也周期执行 Sitemap / Archive / Surface / Branch Sampling / Common Crawl 差异核对，用于发现：

- Feed 窗口外遗漏；
- URL 迁移；
- Feed 未更新但正文变化；
- 删除/下线；
- 历史 Provider 新增可见页面；
- Common Crawl 新 collection 中出现历史候选；
- Discovery Surface 失效或结构漂移；
- 被 soft-pruned 分支出现新模板；
- Provider 之间差异突然扩大。

单次 404 不立即删除知识库文档。多次观察或 authoritative API 明确下线后创建 Tombstone，历史版本保留。

## 25. 安全与合规

- 遵守 robots 和站点访问策略。
- 不绕过登录、付费墙、验证码、WAF 或明确访问控制。
- scheme 只允许配置允许的协议，默认 http/https。
- 起始 URL 和每次 redirect / Browser navigation 都重新做 DNS/IP/Egress 校验。
- 阻止访问 private、loopback、link-local、metadata 等受限网络目标。
- 跨域跳转按 Source Policy 判断，而不是默认允许。
- Domain Mapping 新发现的 staging/admin/api/dashboard 等 host 不自动纳入抓取范围，必须经过 scope policy。
- Browser Worker 独立隔离网络、CPU、内存、wall-clock。
- API token、代理、对象存储密钥放 Secret Manager，不写 Profile 明文和普通日志。
- Common Crawl/其他 Archive 的历史内容恢复显式记录来源，并遵守项目版权、许可证和使用策略。
- LLM 不能自动执行会永久忽略 URL、放宽抓取 scope 或绕过访问策略的操作。
- Branch Soft Pruning 不得改变安全边界或 Coverage 语义。
- Web 高风险操作使用强类型 Command API、RBAC 和 Audit。

## 29. 验收标准

### Coverage

- 每个 Source 有可解释 Provider。
- FULL_BACKFILL 有明确 exhaustion evidence。
- known gap 可枚举、可重跑。
- 达到预算不会错误标记为完整。
- Common Crawl 不被当成完整性证明。
- Provider overlap/unique URL 可查询。
- soft-pruned 分支不被错误计入 COMPLETE。

### Discovery Surface / Branch

- 关键 Blog Index / Archive / Category / Docs TOC 可被识别并长期监控。
- Surface 来源、审核状态、规则 Release 可追踪。
- Surface 失效或结构漂移可告警并重新审核。
- Branch saturation 有 Evidence、Release、TTL。
- soft-pruned 分支有随机复查与 Reconcile。
- 权威 Provider 新证据可解除 suppression。
- LLM 灰区判断不会自动覆盖人工确认和生产 Profile。

### 增量

- Feed/API/Sitemap/高收益 Surface 新文章在目标 SLA 内进入系统。
- Pagination Early Stop 不造成已知 Coverage 缺口。
- 304 不重复抽取、建版和投影。
- 未变化 Projection 不重复计算。
- Reconcile 能发现 Feed 窗口外遗漏、Surface 漏洞和 Branch 新模板。
- 新 Common Crawl collection 可触发低优先级历史补洞。

### Redirect / Identity

- wrapper/短链保留完整解析证据。
- 跳转循环可检测。
- 每跳执行 Egress 校验。
- final URL 与 canonical identity 分离。
- 同一文章多入口不会因包装 URL 大量产生重复 Document。

### Markdown

抽样验证：

- title / author / time；
- 正文完整性；
- 导航噪声；
- heading；
- code block；
- list；
- table；
- image；
- outbound link。

Markdown 必须可从 Canonical IR / accepted source 确定性重建。

### 多语言检索

- 中文/英文等代表性语料有独立 Analyzer Release。
- CJK 不依赖英文 whitespace tokenizer。
- BM25 Query View 可解释每块 score、threshold 和是否入选。
- Analyzer / Retrieval Release 升级有离线回归集。

### 可靠性

- Worker 崩溃后 lease 可恢复。
- Deep Crawl 可从 checkpoint 恢复，但平台不依赖框架内部状态作为唯一事实。
- fan-out 保留 partial success。
- Embedding/Index 故障不阻塞 Source Sync。
- Common Crawl CDX rate limit 不阻塞主抓取链路。
- 所有高风险管理操作可审计。
- Crawl4AI/Playwright 升级可通过 Adapter Release 回滚。

## 30. 最终原则

1. Coverage First：先证明“应该有哪些 URL”，再看抓取成功率。
2. Discovery Before Fetch：低成本发现、分类、去重后再抓正文。
3. Prefetch Before Extraction：发现 links 不需要先生成 Markdown。
4. Discovery Surface First-class：把持续产生文章 URL 的入口当长期运营资产。
5. Graph, Not Tree：站点结构按有环图处理，不用目录树假设决定正确性。
6. Yield-aware Exploration：探索预算优先给高收益、高不确定性、高 Coverage gap 的分支。
7. Soft Pruning Only：饱和分支只降权和延后，永不盲目永久删除。
8. Authoritative First, Archive as Supplement：CMS/API/Sitemap/Feed 是主要证据；Common Crawl 等只负责补洞和历史证据。
9. Common Crawl Is Evidence, Not Completeness：第三方 Web 采样不能替代站点完整性证明。
10. Evidence First：发现、分类、分支降权、解析、抓取、身份和版本都保存证据。
11. HTTP First, Browser Last：Browser 是昂贵 fallback 和结构探索工具，不是默认抓取器。
12. Resolution Is Not Identity：跳转终点和 canonical 文档身份分离。
13. Snapshot First, Replay Later：原始事实不可变，规则升级优先离线回放。
14. IR First, Markdown as Projection：Markdown 可重建，不是真相源。
15. Canonical Content 与 Query View 分离：BM25/LLM 过滤不能破坏完整正文。
16. Language-aware Analyzer：多语言分词、stemming、threshold、tag weight 必须 Release 化。
17. Release Everything：所有影响结果的策略与外部组件版本都可追踪、比较、回滚。
18. Idempotent + Recoverable：任务可重复、可恢复、可观察，partial success 不丢失。
19. Source Sync 与 AI 解耦：抓取事实不被 Embedding/LLM/Index 服务绑定，LLM 只做可审计辅助判断。
20. Web 管理是平台能力：Coverage、Surface、Branch、异常、证据、版本、成本、检索解释都必须可运营。
