# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站和公开 Newsletter** 的长期知识库采集平台，可平滑扩展到数千站点、百万级到千万级文章，并持续支持新增站点。

系统必须满足：

1. **全历史回填**：尽可能完整发现并抓取每个已批准 Source 的历史文章，能够解释 Coverage、Known Gap、失败、停止原因和边界；
2. **持续增量同步**：持续发现新文章、正文更新、URL 迁移、重定向、删除和重发布；
3. **稳定 Markdown**：Markdown 从不可变 Raw Artifact 经确定性抽取、质量门禁和 Canonical IR 生成，而不是直接把某个 crawler 的即时 Markdown 当最终结果；
4. **低成本扩站**：新增网站优先通过 Source Profile、Provider、Traversal Policy、Extraction Recipe 配置完成，不维护 1000 份独立爬虫脚本；
5. **Web 可运营**：支持 Source 接入、审批、配置发布、Backfill、Incremental、Coverage、Frontier、质量、成本、失败诊断、暂停/恢复/停止和审计；
6. **可搜索与 RAG**：支持 BM25、向量和混合检索，并能从检索结果回溯原文、版本、Source、Artifact 和抓取证据；
7. **可观测、可恢复、可重放**：任意 URL、Task、Runtime Result、Artifact、IR、Markdown 都能解释来源、版本和执行路径；
8. **渐进扩展**：开发期 Docker Compose，生产期按 Discovery、HTTP、Browser、Extraction、Projection 等 Worker 类型水平扩容；
9. **主链不依赖 LLM**：LLM 只用于可选增强，不参与 Coverage Truth、URL Identity、Canonical URL、Robots Access、历史完整性最终判定；
10. **高成本抓取有硬预算**：Browser、Deep Crawl、Repair、Focused Job、诊断 Artifact 都有平台拥有的 page/request/browser/model/byte/wall-clock 预算；
11. **Web 配置安全**：Web/API 用户只能提交声明式、低能力配置，不能直接获得任意 JS、代理、CDP、浏览器 profile、Deep Crawl Strategy 等 Runtime 能力；
12. **停止后真正静默**：取消、暂停、Lease 丢失、Browser Generation recycle 或 Worker recycle 后，运行时所有 task/page/context/session 必须完成清理；
13. **Runtime 多结果不静默丢失**：Deep Crawl、批量、流式返回必须逐条显式物化，不能依赖“第一个结果”兼容代理；
14. **长期 Browser 可控寿命**：Browser 采用代际回收、引用排空、Quiescence 和隔离策略，不能无限寿命运行。

### 1.1 核心 SLO

- **Coverage**：每个 Source 能解释 Provider、已发现 URL、Frontier、Known Gap、Backfill 停止原因；
- **Freshness**：新文章从发布/发现到 PASS Markdown 的延迟；
- **TTFM**：URL 首次发现到首个可用 Markdown 的时间；
- **Extraction Quality**：标题、正文完整率、噪声率、代码块/表格/列表保留率、截断率；
- **Reliability**：Task 成功率、Retry、DLQ、Queue Age、Lease Recovery、Checkpoint Resume 成功率；
- **Browser Efficiency**：HTTP 命中率、Browser avoided/recovery、每文档 Browser 成本；
- **Browser Stability**：Generation age/pages/RSS、drain latency、强制 kill 率；
- **Identity Quality**：重复文章误合并/漏合并率；
- **Validity Quality**：Soft-404、假 200、空壳 SPA 识别准确率；
- **Result Integrity**：Runtime 返回结果物化完整率、cardinality mismatch 数、结果身份错配数；
- **Traceability**：任意 Markdown 可回溯 Source、URL、Fetch Attempt、Runtime Result、Evidence、Artifact、Extractor、Quality、Renderer Release；
- **Cancellation**：停止请求到停止新 Admission、到 Runtime QUIESCED、到 Run STOPPED 的延迟；
- **Runtime Quiescence**：Run/Generation/Worker 释放前 active task/page/context/session/local queue/resource token 均为 0；
- **Config Safety**：Web/API power-field 绕过数为 0，所有 Runtime Config 可回溯编译报告和 Release；
- **Admission Accuracy**：硬预算 overshoot 为 0；429/503/413 等容量语义可观测；
- **Evidence Cost**：按 Source/Run/Attempt 统计 durable 与 diagnostic artifact 字节数、采样率和 TTL；
- **Cost**：按 Source、Run、Queue Class、每 1000 篇 PASS 文档统计抓取、Browser、存储、索引和模型成本；
- **Replayability**：同 release + 同输入可复现抽取、渲染和评分结果。

### 1.2 非目标

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不默认使用个人持久 Browser Profile、Magic/模拟用户或反爬绕过能力；
- 不把 HTTP 200、Runtime `success`、DOM 很长或 downloaded file 存在直接视为文章正确；
- 不把搜索结果数、Common Crawl、Wayback、Deep Crawl 页数、Adaptive confidence、`max_pages`、runtime round/depth 当历史完整性证明；
- 不把 Crawl4AI 即时 Markdown、LLM 摘要或改写直接作为 Canonical Markdown；
- 不因 URL 曾抓过就永久停止复检；
- 不把 Redis、Browser Session、Crawler Cache、Visited Set、Dispatcher Queue、Adaptive State、Search Index 当业务真相；
- 不允许优先级、相关性阈值、信息增益阈值或执行预算永久删除潜在历史文章；
- 不允许 Web/API 调用者直接构造任意 Runtime 对象、运行任意代码或指定任意文件系统路径；
- 不默认对每次抓取永久保存 MHTML、network requests、console dump、screenshot 等重型诊断证据；
- 不默认对所有文档构建 GraphRAG。

## 2. 核心设计原则

1. **Coverage First**：先建立 URL Inventory，再批量抓正文；
2. **Authoritative First**：CMS/API、Sitemap、RSS/Atom、官方 Archive 优先；
3. **Historical Gap Is Evidence, Not Truth**：Common Crawl、Wayback 用于历史补洞，不作为完整性证明；
4. **Deep Crawl Is Gap Provider**：站内深度抓取用于补洞，不作为 Coverage Truth；
5. **Focused Is Optimization**：Focused confidence 只表示专题信息充分度，不等于历史 Coverage；
6. **Discovery / Fetch / Extract / Quality / Projection 分离**；
7. **HTTP First, Browser Last**：Browser 是受治理慢路径；
8. **Snapshot First**：先保存不可变 Artifact，再抽取和清洗；
9. **Canonical IR First, Markdown as Projection**；
10. **Recipe, Not 1000 Site Scripts**；
11. **Stable Identity**：Source、Host、URL、Attempt、Artifact、Document、Version 使用稳定 ID；
12. **Idempotent + Recoverable**：任务使用幂等键、Lease、Fencing Token、Checkpoint；
13. **Fair by Default**：大站 Backfill 不能饿死 Incremental 和小站；
14. **Bounded Concurrency Everywhere**：禁止无界 asyncio gather、Browser Context、Preview、模型 fan-out；
15. **No Silent Degradation**：截断、预算耗尽、降级、过滤、跳过、结果缺失必须记录原因；
16. **Release Everything That Changes Results**：Profile、Provider、Traversal、Runtime Config、Result Schema、Extractor、Quality、Renderer、Embedding、Rank 全部版本化；
17. **Priority Means When, Not Whether**：priority/expected gain 决定何时处理，不决定 URL 是否永久保存；
18. **Observation Before Selection**：观察到链接后先保存事实，再 Filter/Score/Budget；
19. **Persistent Frontier, Not In-Memory Traversal**：业务候选进入数据库；
20. **Runtime Checkpoint != Business Checkpoint**：第三方 crawler resume state 只是执行优化；
21. **Cooperative Cancellation + Runtime Quiescence**：停止必须结束本地 in-flight 资源后才算静默；
22. **Approved Scope First**：发现 host/path 不等于允许访问；
23. **Soft-404 Is First-class**：存在性不能只依赖状态码；
24. **Global Admission + Local Adaptation**：跨 Worker 公平/限流由平台负责，Worker 内存保护由 Runtime 负责；
25. **Runtime Result Is Advisory**：第三方 status/success/dedup/score/cache/confidence 不能直接升级为平台业务真相；
26. **Normalize Conservatively**：scheme/host 可标准化，path/query 默认保留大小写和语义；
27. **Explicit Runtime Capabilities**：生产行为不得依赖第三方默认能力集；
28. **Robots Policy Is Access Control Input**：由平台 RFC 9309 Policy Engine 负责；
29. **Correlate by Identity, Never by Position**：批量/流式结果按 `attempt_id/url_id/requested_url` 关联；
30. **Strict Budget Is Platform-owned**：所有高成本预算由平台硬控；
31. **Graph Depth Is Platform-owned**：真实 depth 来自持久 URL Edge；
32. **Config Must Prove Effective**：配置只有经过 pinned-release 行为测试后才能作为生产硬控制项；
33. **Score Input Must Be Replayable**；
34. **Config Is Capability**：能改变网络、代码执行、浏览器和 secret 的字段必须由 Capability Firewall 控制；
35. **Untrusted by Default at Network Boundary**：Web/API 配置一律按 UNTRUSTED 处理，经平台编译后才成为 Runtime Config；
36. **Caller Never Owns Paths**：调用者只持 opaque artifact id，文件系统路径/Object Key 由服务端生成；
37. **Quiesce Before Reuse**：Runtime 未清零前不得复用 crawler/browser/worker，也不得宣称 STOPPED；
38. **Zero Must Not Mean Unbounded by Accident**：生产预算 0 不默认解释成无限，解除上限只能由 Operator Policy 明确发布；
39. **Materialize Before Interpreting**：第三方 Container/Generator 必须先逐条显式物化，再进入业务逻辑；
40. **Prefetch Is Observation, Not Document**：快速预抓结果只产生 Observation/Edge，不产生 PASS 文档；
41. **Browser Is Generational**：长生命周期 Browser 必须代际回收、排空并可观测；
42. **Evidence Is Tiered**：可重放 Raw Artifact 与高成本诊断 Artifact 分层存储、分层生命周期；
43. **Runtime Schema Drift Must Fail Loudly**：Runtime 版本升级若返回 cardinality/字段/语义变化，Contract Test 必须阻断上线；
44. **Security State Never Crosses Isolation Key**：Cookie、Storage、CDP、持久 Context 不跨 Tenant/Source 安全边界复用。

### 3.1 业务真相边界

**PostgreSQL + Object Storage 是业务真相。**

- PostgreSQL：Source、Approved Host、Provider、URL Identity、Observation、Robots、Validity、Frontier、Task、Cursor、Coverage、Attempt、Runtime Result Envelope、Browser Generation、Quality、Document、Version、Release、Cleanup、Audit；
- S3/MinIO：Raw HTML、原始 PDF、Provider Evidence、Preview、Candidate、IR、Markdown、Checkpoint、按策略保存的 Trace/MHTML/截图等；
- Redis Streams：任务运输、Consumer Group、Backpressure；
- Redis Lua：Token Bucket/Semaphore/短期资源令牌；
- OpenSearch / pgvector：可重建 Serving Projection；
- Crawl4AI cache、local dispatcher queue、visited set、browser context、Playwright page/session、Adaptive state：全部属于可丢失 Runtime State。

### 3.2 Runtime Adapter 边界

```text
Platform Command
 -> compiled runtime_config_release
 -> Crawl4AI Adapter
 -> HTTP/Browser/Deep Crawl execution
 -> Runtime Result Container/Stream
 -> Result Materializer
 -> Runtime Result Envelope
 -> Raw Artifact / Observation
 -> Platform Truth
```

Runtime 不拥有：Source 生命周期、全局 Frontier、Coverage、最终 Canonical Identity、最终 Version、最终 Markdown、全局限流、安全审批、最终文章有效性。

## 4. 技术选型与 Release

### 4.1 控制面

- **FastAPI + Pydantic**：REST API、Command、Schema；
- **PostgreSQL**：Truth Store、任务、Frontier、Coverage、版本、审计；
- **Redis Streams**：任务运输与 Backpressure；
- **Redis Lua Token Bucket/Semaphore**：跨 Worker 域名和资源限流；
- **React / Next.js + TypeScript**：Web 管理后台；
- **OpenTelemetry + Prometheus + Grafana + Structured Logging**；
- **S3/MinIO**：不可变对象；
- **Vault/KMS/Secret Manager**：secret 引用；
- **Nginx/Envoy/API Gateway**：TLS、请求体上限、Rate Limit、Correlation ID。

### 4.2 Discovery / Fetch

- **httpx/aiohttp**：robots、Sitemap、Feed、CMS API、Conditional GET、普通网页、SafeProbe；
- **RFC 9309 Robots Engine**；
- **Crawl4AI pinned release**：Browser Render、Deep Crawl Prefetch、受控链接发现；
- **MemoryAdaptiveDispatcher**：仅 Worker 本地内存自保护；
- **Playwright Python**：复杂页面慢路径；
- **Common Crawl Adapter / Wayback CDX Adapter**：历史补洞；
- **合规 Search API/SearXNG Adapter**：Gap、新 Source Candidate；
- **PyMuPDF/pdftotext**：PDF；扫描件进入 OCR 慢路径；
- **Python MIME Parser**：Newsletter Inbox Provider。

### 4.3 Extraction / Search

- **Trafilatura**：Generic Candidate；
- **lxml/BeautifulSoup**：DOM/XPath、Metadata、Repair；
- **JSON-LD/OpenGraph/Microdata**；
- **CSS/XPath/Regex Recipe**；
- **SimHash/MinHash**：近重复候选；
- **OpenSearch BM25 + pgvector + RRF**；
- 可选 embedding/reranker/LLM，仅作用于 Canonical 数据或 Focused Job。

硬规则：

- Runtime Container/Generator 先逐条 materialize，再解释；
- 禁止业务层直接读取第三方容器的 first-result 兼容代理；
- 批量/流式结果按 `{attempt_id,url_id,requested_url,runtime_result_ordinal}` 关联，不依赖数组位置；
- Deep Crawl root 返回 N 个结果则 N 个都必须进入 Envelope/Observation 流程；
- cardinality 异常必须产生可观测错误，不静默忽略；
- Header 只保留 allowlist/脱敏证据，Cookie/Authorization 不进入普通日志。

## 7. Discovery、Backfill 与 Coverage

### 7.1 Provider 顺序

```text
CMS/API
 -> Sitemap
 -> RSS/Atom
 -> Archive/Pagination
 -> HTML Listing
 -> Common Crawl / Wayback Historical Gap
 -> Safe Domain Recon Gap
 -> SafeProbe Content Paths
 -> Deep Crawl Prefetch
 -> External Search Gap
```

URL Inventory 是多个 Provider 的并集，并保留 Observation 证据。高优 Provider 成功不能阻止其它 Provider 执行。

### 7.2 Backfill 流程

```text
Source Approved
 -> Probe Authoritative Providers
 -> Build Initial URL Inventory
 -> Archive/Pagination Enumeration
 -> Common Crawl / Wayback Gap
 -> Safe Domain Recon
 -> SafeProbe
 -> Deep Crawl Prefetch Gap Scan
 -> Persistent Frontier
 -> Robots / Scope / URL Validity
 -> Fetch
 -> Result Materialize
 -> Raw Artifact
 -> Extract / Quality / IR / Markdown
 -> Coverage Reconcile
 -> Gap Review
 -> Backfill Complete
```

### 7.3 Backfill 完成条件

至少满足：

- 权威 Provider 完成或明确不可用；
- Historical Gap Provider 到达配置边界且限制有记录；
- Persistent Frontier 无 READY/LEASED/RETRY；
- Archive/Deep Crawl 不再产生新增候选，或达到可解释收敛；
- Runtime 多结果已完整物化，无未解决 cardinality mismatch；
- 失败任务成功、DLQ 或人工接受；
- Soft-404 疑似已确认/延期/接受；
- Known Gap 为空或人工接受；
- 多 Provider URL 集合差异在阈值内；
- 所有结束的 Runtime Slice/Browser Generation 已 QUIESCED。

**Prefetch 结果数、Focused confidence、saturation、max_pages、low gain、Runtime Cache Hit、runtime round/depth 绝不能作为 Backfill Complete 条件。**

### 7.4 URL 规范化

```text
resolve relative
 -> normalize scheme
 -> lower host / IDNA
 -> remove default port
 -> strip fragment
 -> dot-segment normalize
 -> preserve path case
 -> preserve query case/order before Query Policy
 -> tracking parameter policy
 -> redirect evidence
 -> rel=canonical evidence
```

不提前任意删除 query 参数；按 Source 采样后发布 Query Policy Release。

## 8. 增量同步

优先级：

```text
RSS/Atom
 -> CMS API
 -> Sitemap lastmod
 -> Homepage / Archive probe
 -> Conditional recrawl
 -> Periodic Historical/Domain/Deep Gap Scan
```

Cursor 一致性：

```text

 -> 拉取一批
 -> 写 Observation / URL Inventory

 -> 同一 DB 事务推进 cursor + outbox
```

### 8.1 多证据 Freshness

变化检测组合：

```text
Provider updated/lastmod
ETag
Last-Modified
Head Fingerprint
Final Raw Payload Hash
Canonical IR Content Hash
```

规则：

- RSS/CMS 明确更新 -> 高优复抓；
- HTTP validator 可用 -> `If-None-Match` / `If-Modified-Since`；
- 304 -> 不生成新正文版本，只刷新 freshness observation；
- validator 缺失/不可靠 -> 受控 HEAD/GET + head fingerprint；
- 最终是否生成 Document Version 只由 Canonical IR/content hash 和 identity policy 决定。

Crawl4AI Runtime Cache 只可作为 Worker 局部优化，不推进 Cursor、不改变 Coverage、不替代 Raw Artifact。

### 8.2 删除与迁移

```text

正文 hash 变化 -> 新 Version
```

## 9. Deep Crawl 与 Prefetch 两阶段模型

### 9.1 Phase A：Prefetch Discovery

Crawl4AI `prefetch=True` 映射为平台明确的 Discovery fast path：

```text
Seed / Frontier Candidate
 -> Browser render if necessary
 -> Crawl4AI prefetch=True
 -> Materialize all Runtime Results
 -> raw links + status + redirect + minimal evidence
 -> Persist Observation/Edge
 -> Normalize / Scope / Robots
 -> Platform Graph Depth
 -> Filter / Score / Budget
 -> Persistent Frontier
```

Phase A 不做：

```text
重型正文清洗
Canonical Markdown
LLM
Document Version
PASS article count
Historical Complete 判定
```

其业务状态应是 `DISCOVERY_OBSERVATION`，而不是 `FETCHED_DOCUMENT`。

### 9.2 Phase B：Full Processing

```text
Persistent Frontier
 -> Platform Admission
 -> HTTP First / Browser Slow Lane
 -> Result Materializer
 -> Fetch Evidence Envelope
 -> Raw Artifact
 -> URL Validity / MIME Route
 -> Extract / Quality / IR / Markdown
```

### 9.3 Observation Before Selection

```text
Page Result
 -> Materialize Result
 -> Extract Raw Links
 -> Persist Observation/Edge
 -> Normalize / Scope Check
 -> Graph Depth Check
 -> Filter Reason
 -> Score
 -> Budget Admission
 -> Persistent Frontier
```

禁止先由 visited/threshold/max_pages/low gain 裁剪，再只保存幸存 URL。

### 9.4 Traversal

- **BFS**：Backfill 默认；
- **DFS**：路径深度结构明确时；
- **Best-First**：固定预算优先文章/归档/分页；
- **Focused**：Browser/Repair/专题慢路径按信息增益排序。

统一语义：`score -> priority`，不删除业务事实。

## 10. Fetch Plane 与 Result Materialization

### 10.1 HTTP First

```text
HTTP Fetch
 -> 正文充分 -> Artifact
 -> JS shell / 内容不完整 -> Browser Slow Lane
```

Browser 不是默认路径。

### 10.2 Retry

```text
DNS/TCP timeout       -> exponential retry
429                   -> Retry-After + global domain throttle
5xx                   -> bounded retry
403/challenge         -> 标记 policy outcome，不默认绕过
404/410               -> tombstone candidate + grace
soft-404 suspected    -> validity/repair queue
parse/extract failure -> repair，不等于必须 refetch
```

### 10.3 多层限流

```text
Redis Token Bucket        = 跨 Worker 精确节流
Global Fair Scheduler     = Source/Queue 公平
Worker Semaphore          = 本地并发保护
Runtime RateLimiter       = 本地响应式退避
MemoryAdaptiveDispatcher  = 本地内存压力保护
```

### 10.4 Result Materialization Contract

Crawl4AI 可能返回单结果、多结果容器或 async stream。平台统一：

```text
Runtime Return
 -> flatten/materialize one by one
 -> assign runtime_result_ordinal
 -> validate schema/cardinality
 -> correlate by attempt identity
 -> persist Envelope
```

禁止：

```text
container.markdown
container.url
container.status_code
```

之类依赖第三方“第一个结果”兼容语义的业务代码。

流式结果允许乱序，但每条结果的提交必须幂等；任务完成前要确认所有已启动结果已物化或明确 cancelled/failed。

### 10.5 MIME Route

Runtime `success` 只表示运行成功，后续必须按 MIME/Content-Disposition 分流：

```text
text/html -> HTML Validity / Extraction
application/pdf -> PDF parser
text/plain/markdown -> text pipeline
supported docs -> document parser
image-only/scanned -> optional OCR lane
unsupported binary -> REVIEW/REJECT
```

“HTML 为空但 downloaded file 存在”不能被错误当成 HTML 正文 PASS。

### 10.6 Raw Artifact First

Fetch 成功先写不可变原始对象：

```text
raw/{source_id}/{yyyy}/{mm}/{artifact_id}.{ext}
```

附稳定证据：

```text
attempt_id
runtime_result_id
url_id
requested_url
result_url
final_url
status
selected headers
timing
runtime_release
runtime_config_release
runtime_result_schema_release
payload_sha256
trace_id
```

Artifact durable 后任务才能进入 EXTRACT。

## 11. Browser Generation、Quiescence 与停止/恢复

### 11.1 为什么 Browser 必须有代际

长期 Browser Worker 即使每页正常 close，也可能出现浏览器进程/V8/缓存/Context 长期增长。平台必须有显式 Browser Generation 生命周期，而不是让单 Browser 进程无限寿命。

建议阈值：

```text
max_pages_per_generation
max_generation_age
max_worker_rss
max_consecutive_browser_errors
max_draining_generations
```

具体阈值经 Canary/容量数据调整；第三方 `max_pages_before_recycle=0` 若表示关闭，生产不得无意识继承。

### 11.2 Generation 状态机

```text
ACTIVE G1
 -> threshold reached
 -> DRAINING G1 + ACTIVE G2
 -> G1 no-new-admission
 -> wait refs/pages/contexts -> 0
 -> QUIESCED G1
 -> CLOSED
```

回收期间新流量由 G2 接收，旧代只收敛已有 in-flight。

### 11.3 Runtime Quiescence 状态机

```text
RUNNING
 -> STOP_REQUESTED
 -> QUIESCING
 -> QUIESCED
 -> STOPPED
```

“Web 点停止”“Scheduler 不再发 Lease”“async generator 返回”都不等于 Runtime 已停止。

### 11.4 Cleanup Protocol

收到 Cancel/Pause/Lease Lost/Generation Recycle/Shutdown 时：

```text
1. 停止本 slice/generation 的 local admission
2. cancel 未完成 runtime tasks
3. await active tasks（grace timeout）
4. drain local runtime queue
5. close page/context/session
6. cancel/await memory monitor/helper tasks
7. release Redis browser/domain/resource token
8. flush cleanup evidence
9. 校验 counters == 0
10. 标记 QUIESCED
```

必须满足：

```text
active_tasks == 0
local_queue == 0
pages == 0
contexts == 0
sessions == 0
held_tokens == 0
```

才允许 crawler/browser/worker 复用。

### 11.5 Cleanup/Drain Timeout

若 grace timeout 到期：

```text
mark TIMED_OUT
 -> terminate isolated worker process/container
 -> fencing rejects late commit
 -> release/expire lease
 -> unfinished URL RETRY
 -> record incident metric
```

不能为了“优雅退出”无限等待。

### 11.6 Context/CDP/状态隔离

```text
isolation_key = tenant + source_lane + runtime_config_release + browser_generation
```

普通公开博客 Lane 禁止：

- 跨 Tenant/Source 共享 Cookie/localStorage/sessionStorage；
- Web 用户指定 CDP；
- 默认 user-data-dir/persistent profile；
- 把 Browser Context ID 或 Target ID 暴露给外部调用者；
- 未 QUIESCED generation 的 Context 进入公共复用池。

认证站点必须进入独立 Trusted Authenticated Lane。

## 14. 安全、访问治理与 Artifact Gateway

### 14.1 Scope / Robots / SSRF

每个主动网络请求统一经过：

```text
Approved Scope
 -> Robots Policy
 -> DNS Resolve
 -> SSRF IP Validation
 -> Domain Token Bucket
 -> Request Budget
 -> Fetch
 -> Redirect 每跳重新检查
```

禁止访问：loopback、RFC1918、link-local、云 metadata、`file://` 等非批准目的地。

### 14.2 Web/API Trust Boundary

- Auth 默认开启；
- RBAC + tenant/source ownership；
- CORS allowlist；
- TLS 默认校验；
- 网络请求体按 UNTRUSTED 处理；
- 不允许 arbitrary hook/code/runtime class；
- secret 只通过服务端引用注入；
- 5xx 返回通用错误 + correlation id，内部细节进日志；
- Browser Runtime 不直接暴露公网；
- Redis/PostgreSQL/MinIO 不开放公网端口。

### 14.3 Opaque Artifact Gateway

临时 Screenshot/PDF/Trace/MHTML/Network/Console/Preview：

```text
server-generated artifact_id
server-generated object key
owner/tenant authorization
content type allowlist
single artifact size cap
tenant/source quota
TTL
redaction
janitor
```

禁止 caller-supplied filesystem path/object key。

若使用本地临时盘，实现至少要求：

```text
server-owned directory
random opaque filename
O_EXCL
O_NOFOLLOW
non-symlink regular file check
0600 file / 0700 dir
TTL + quota cleanup
```

### 14.4 Evidence 分层

**Durable Evidence**：Raw HTML、原始 PDF、必要 Provider Evidence、Canonical IR 等，服务于可重放与审计。

**Diagnostic Evidence**：Screenshot、MHTML、network requests、console、full trace 等，默认关闭或按失败/采样/人工调试开启。

推荐：

```text
normal PASS      -> 不抓或极低采样诊断证据
REPAIR/error     -> 按 failure policy 抓 screenshot/trace
canary source    -> 受控采样
manual debug     -> 显式开启并受 quota/TTL 控制
```

敏感 header、Cookie、Authorization、URL query secret 必须脱敏。

### 14.5 认证站点独立 Lane

若未来确实需要组织拥有权限的私有技术站点：

- 单独 `AUTHENTICATED_SOURCE` 类型；
- 单独审批；
- Secret Manager；
- 独立 Browser Worker Pool；
- 严格 egress；
- session/profile 不跨 Source/Tenant；
- 不与公开博客默认抓取链混用。

## 22. 验收标准

平台达到可生产使用至少满足：

1. 新增标准博客主要通过 Web Source Profile 完成，不新增独立爬虫脚本；
2. 新 host 未经批准不能主动抓取；
3. 任意 Source 可执行全历史 Backfill，并解释 Coverage、Historical Gap、Known Gap；
4. Common Crawl/Wayback/Focused confidence/Prefetch count 不被误当完整性证明；
5. 任意 URL 能解释 Provider、Observation、Graph Depth、Filter、Admission、Validity、Frontier；
6. SPA/自定义 404 不会仅因 HTTP 200/Runtime success 大规模进入正文库；
7. URL Normalizer 默认保留 path/query 大小写语义；
8. Worker 任意 kill 后不丢业务 Frontier，可通过 Lease 恢复；
9. Runtime local queue/cache/session 丢失仍可从 PostgreSQL/Object Storage 重建；
10. `max_pages`、低 score、low gain、Provider timeout 不让历史候选静默消失；
11. CrawlResult Container/Stream 多结果全部显式物化，不能只取 first result；
12. 批量/流式乱序和部分失败时按 `attempt_id/url_id` 正确关联；
13. Runtime cardinality/schema drift 可被 Contract Test 检测并阻断上线；
14. Crawl4AI `prefetch=True` 只产生 Discovery Observation，不产生 Canonical Document；
15. 点击停止后停止新 Admission，并最终完成 Runtime QUIESCED；
16. STOPPED 时 active task/page/context/session/local queue/held token 为 0；
17. cleanup timeout 后 Worker 被隔离，late commit 被 fencing 拒绝；
18. Browser Generation 能按 pages/age/RSS 轮换，新旧代并发 drain 时无 URL 丢失或重复提交；
19. Browser Generation DRAINING 后不接新任务，超时可 kill；
20. Browser 状态、Cookie、CDP、持久 Context 不跨 Tenant/Source isolation key；
21. Raw Artifact 可重放生成新 IR/Markdown，不必重新抓网页；
22. Incremental 通过 RSS/Sitemap/CMS/Conditional GET 持续同步；
23. Markdown 保留标题、正文、代码、表格、列表等关键结构并通过质量门禁；
24. Search Index 全部可从 Canonical 数据重建；
25. 所有改变结果、权限或 Runtime Schema 的组件都有 Release，并通过 Golden Replay/Contract/Posture Test；
26. Web Admin 可完成接入、审核、Backfill、Incremental、Coverage、失败诊断、暂停/恢复/停止和审计；
27. Web/API 不能直接提交 `js_code`、browser `extra_args`、proxy、CDP、user-data-dir、cookies、任意 Runtime Strategy；
28. 不可信配置不能读取服务端环境变量 Secret；
29. 所有外部配置都有 compilation report，能看到 rejected/clamped/injected 字段；
30. request/body/principal/queue 超限分别有 413/429/503 等明确语义；
31. page/http/browser/model/evidence 等硬预算 Golden Test overshoot 为 0；
32. 任何 caller 都不能指定服务器文件系统输出路径；
33. 临时 Screenshot/PDF/Trace/MHTML/Network/Console 使用 opaque artifact id、RBAC、TTL 和 quota；
34. normal PASS 不默认永久保存高成本诊断证据，敏感证据经过脱敏；
35. Runtime Cache 不推进业务 Cursor，不改变 Coverage/Version Truth；
36. Deep Crawl Runtime depth/visited/queue 不替代平台 graph depth/Frontier；
37. Browser Runtime 不默认绕过登录墙、付费墙、CAPTCHA 或 WAF；
38. Browser Worker/Generation 未 QUIESCED 前不能回到复用池；
39. Redis/PostgreSQL/MinIO/Browser Runtime 不直接公网暴露；
40. 第三方 Runtime 配置只有 `VERIFIED_EFFECTIVE` 才可作为生产硬控制；
41. Source/Run/Task/URL/Attempt/RuntimeResult/Artifact/Version 全链路有 correlation/trace；
42. 整体系统能够从 1000 站扩展到更多站点而不引入线性数量的专用爬虫代码。

最终架构原则：

> **权威 Provider 建 URL Inventory，Common Crawl / Wayback / Deep Crawl 只补 Coverage Gap；Observation 与 URL Edge 先于选择，Approved Scope 与 RFC 9309 Robots 先于主动访问，Persistent Frontier、Lease/Fencing 与平台 Graph Depth 保证不丢不串；外部配置一律视为 UNTRUSTED，经 Capability Firewall 与 Config Compiler 才变成 Runtime 能力；Runtime Container/Stream 必须先完整物化再解释，Prefetch 只产生 Observation；HTTP First、Browser Slow Lane，Browser 采用代际回收，任何停止或回收都必须通过 Runtime Quiescence Barrier；调用者只持 opaque Artifact ID，不拥有服务器路径，Raw Artifact 与诊断 Evidence 分层治理；Canonical IR 保证稳定 Markdown；第三方 crawler 负责高效执行，PostgreSQL + Object Storage 始终拥有业务真相。**
