# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站与公开 Newsletter** 的长期知识库采集平台，可继续扩展到数千站点、百万至千万级文章，并满足全历史回填、持续增量、稳定 Markdown、Web 管理、可恢复调度、可解释 Coverage 与搜索/RAG。

核心目标：

1. **全历史回填**：尽可能完整发现每个已批准 Source 的历史文章，并能说明 Provider 覆盖范围、已知缺口、截断原因与停止原因；
2. **增量同步**：持续发现新文章、正文更新、URL 迁移、重定向、删除、重发布与元数据变化；
3. **稳定 Markdown**：Raw Artifact 不可变，抽取与渲染可重放，相同 Raw + Release 可得到可复现结果；
4. **可扩展接站**：新增网站优先通过 Source Profile、Provider、Extraction Recipe、Traversal Policy 配置完成，不维护 1000 份站点脚本；
5. **Web 可运营**：支持接站、审批、Backfill、Incremental、Coverage、Frontier、质量、成本、诊断、暂停、恢复、重跑和审计；
6. **任务可恢复**：Provider Run、Task、Attempt、URL、Artifact、Document、Version 全链路可追踪，Worker/Runtime 崩溃后可恢复；
7. **可搜索/RAG**：支持 BM25、向量与混合检索，并能回溯原文、版本、Source 与抓取证据；
8. **主链不依赖 LLM**：LLM 只做可选增强，不参与历史完整性、URL 身份、robots、正文存在性、版本真相等最终判定。

### 1.1 核心 SLO

- **Coverage**：每个 Source 均可查看 Provider Inventory、Completion Attestation、Known Gap、Backfill Stop Reason；
- **Freshness**：新文章从发布/发现到 PASS Markdown 的 P50/P95/P99 延迟；
- **TTFM**：URL 首次发现到首个可用 Markdown 的时间；
- **Extraction Quality**：正文、标题、代码块、表格、列表保留率和噪声率；
- **Reliability**：Task 成功率、Retry、DLQ、Queue Age、Lease Recovery；
- **Replayability**：同 Raw Artifact + 同 Release 可重放 IR/Markdown；
- **Provider Integrity**：Provider 不能把部分返回、缓存命中、预算耗尽误报为“已完整枚举”；
- **Artifact Durability**：必须保留的 Runtime/Provider Artifact 在 TTL 到期前晋升平台对象存储；
- **Browser Efficiency**：HTTP 命中率、Browser Avoided、Pool Reuse、Browser 单文档成本；
- **Fairness**：大型 Backfill 不得长期饿死 Incremental、小站和 Repair。

### 1.2 非目标

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不默认使用个人持久 Browser Profile 或模拟真人操作绕过访问限制；
- 不把 HTTP 200、Runtime `success=true`、DOM 很长直接视为有效文章；
- 不把 Common Crawl、Wayback、搜索结果、Deep Crawl、Seeder 返回条数单独视为历史完整性证明；
- 不把 Crawl4AI 即时 Markdown 或 LLM 摘要直接作为 Canonical Markdown；
- 不把 Redis、Runtime Queue、Seeder Queue/Cache、Browser Session、Visited Set、Search Index 当业务真相；
- 不允许普通 Web/API 用户透传任意 JS/Python、代理、CDP、服务器路径、任意 Seeder 原生配置、任意 secret 或 webhook URL。

## 2. 核心设计原则

1. **Coverage First**：先建立 URL Inventory，再抓正文；
2. **Authoritative First**：官方 CMS/API、Sitemap、Feed、Archive 优先；
3. **Observation Before Selection**：发现事实先保存，再 Normalize/Scope/Classify/Dedup；
4. **Successful Return != Provider Complete**：函数正常返回、非空列表、cache hit、`status=valid` 都不能自动代表 Provider 完成；
5. **Completion Must Be Attested**：只有具备可验证结束语义的 Provider Adapter 才能声明完成；
6. **Discovery / Fetch / Extract / Quality / Projection 分离**；
7. **HTTP First, Browser Slow Lane**；
8. **Snapshot First**：先保存不可变 Provider Evidence / Raw Artifact；
9. **Canonical IR First, Markdown as Projection**；
10. **Recipe, Not 1000 Site Scripts**；
11. **Persistent Frontier, Not In-Memory Traversal**；
12. **Idempotent + Recoverable**：幂等键、Lease、Fencing Token、Checkpoint、Inbox/Outbox；
13. **Fair by Default**：Incremental/Repair 必须预留容量；
14. **Bounded Concurrency Everywhere**；
15. **No Silent Degradation**：过滤、截断、预算耗尽、partial result、cache fallback、降级必须有 typed reason；
16. **Correlate by Identity, Never by Position**；
17. **Config Is Capability**：高能力配置统一经过 Capability Firewall；
18. **Runtime Is Execution Plane**：第三方 Runtime 不拥有 Coverage、Identity、Document 或 Markdown 真相；
19. **Local Safety != Global Admission**：Runtime Dispatcher、RateLimiter、Seeder Semaphore 只负责实例内保护；
20. **Behavior Beats Naming**：生产语义以 pinned release + Contract Test 为准，而不是参数名或文档描述；
21. **Runtime Artifact Is Ephemeral Until Promoted**；
22. **Result Transport Is Not State Store**；
23. **Drain/Replace Before In-Place Kill**；
24. **Zero Must Not Mean Unbounded by Accident**；
25. **External Historical Index Is Evidence**：Common Crawl、Wayback 可显著补洞，但单独不能证明全历史完整。

## 5. Source 接入与配置模型

### 5.1 Source Profile

新增站点使用声明式配置：

```yaml
source:
  name: example-tech-blog
  entry_url: https://example.com/blog/
  approved_hosts: [example.com]
  allowed_paths: [/blog/]
  denied_paths: [/login/, /account/]

providers:
  - type: sitemap
    url: https://example.com/sitemap.xml
    conditional_get: true
  - type: rss
    url: https://example.com/feed.xml
  - type: archive
    start_url: https://example.com/blog/archive/
  - type: common_crawl_index
    purpose: historical_gap
  - type: crawl4ai_url_seeder
    purpose: discovery_acceleration
    modes: [sitemap, cc]

fetch:
  mode: auto
  http_timeout_s: 20
  browser_profile_class: public-default
  browser_intent:
    render_js: true
    scroll: bounded
    wait_selector: article

extract:
  recipe: generic_article_v3
  content_selectors: ["article", ".post-content"]
  exclude_selectors: ["nav", "footer", ".related"]

incremental:
  feed_poll: 10m
  sitemap_poll: 1h
  archive_reconcile: 1d
  full_reconcile: 7d
```

### 5.2 Capability Firewall

Web/API 用户只提交 intent，禁止透传：

- 任意 `js_code` / Python；
- 任意 proxy / CDP / `user_data_dir`；
- 任意 cookies、secret、服务器 path；
- 任意 LLM base URL / webhook destination；
- 未审批的 Seeder/Common Crawl query；
- 无硬上限的 `concurrency` / queue / time / result budget；
- `0=unbounded` 的配置；
- 不受控 deep crawl strategy；
- 任意网络目标与本地文件协议。

Config Compiler 将已审批 Source Intent 编译成 Provider/Runtime Config，并记录最终能力、硬预算和拒绝原因。

### 5.3 Browser Profile Class

平台只维护少量受审 Browser Profile：

```text
public-default
public-js-heavy
public-media-light
isolated-authenticated
```

站点 selector/wait/scroll 优先放低成本 CrawlerRunConfig/Recipe。只有改变浏览器进程能力、网络边界或 credential scope 才新建 Browser Profile Release。

## 6. Provider 分层、历史 URL 发现与 Coverage

### 6.1 Provider 分层

#### A. 可声明 Completion 的 Provider

优先使用平台原生、能给出 typed terminal outcome 的 Provider：

1. CMS/官方内容 API；
2. Native Sitemap / Sitemap Index；
3. RSS/Atom；
4. 官方 Archive / Category / Pagination；
5. Native CommonCrawlIndex；
6. Wayback Gap Provider。

其中 Common Crawl/Wayback 仍属于历史证据，不单独证明 Source 的完整历史。

#### B. Discovery Accelerator

```text
Crawl4AI URL Seeder
Domain Mapping
Deep Crawling
Adaptive Crawling
Search Adapter
```

这些组件适合发现、补洞、排序与低成本 Probe，但默认 **不能声明 `completion_attested=true`**。

### 6.2 Observation First

所有发现先落：

```text
url_observation
- observation_id
- source_id
- provider_run_id
- provider_component
- provider_ref
- observed_url
- discovered_at
- published_at_hint
- updated_at_hint
- parent_url
- anchor_text
- depth
- raw_provider_status
- evidence_artifact_id
- provider_release_id
```

之后执行：

```text
normalize -> scope -> classify -> dedup -> frontier
```

不能先用不透明过滤永久丢 URL，再宣称 Coverage 完整。

### 6.3 Provider Run 与 Completion Attestation

```text
provider_run
- provider_run_id
- source_id
- provider_id
- provider_type
- provider_component
- provider_release_id
- runtime_release_id
- started_at
- terminal_at
- terminal_outcome
- completion_attested
- raw_observation_count
- selected_count
- filtered_count
- duplicate_count
- result_limit
- hard_request_budget
- hard_byte_budget
- hard_wall_clock_budget
- truncated
- error_class
- evidence_artifact_id
```

推荐 terminal outcome：

```text
EXHAUSTED
NOT_MODIFIED
RESULT_LIMIT_REACHED
REQUEST_BUDGET_REACHED
BYTE_BUDGET_REACHED
TIME_BUDGET_REACHED
DATE_BOUND_REACHED
ROBOTS_BLOCKED
ACCESS_DENIED
RATE_LIMITED
ERROR_PARTIAL
PROVIDER_ERROR
CANCELLED
```

规则：

- `EXHAUSTED` / `NOT_MODIFIED` 只有 Adapter 能证明本次约定范围完成时才可 `completion_attested=true`；
- `RESULT_LIMIT_REACHED`、预算耗尽、`ERROR_PARTIAL` 必须 `completion_attested=false`；
- 非空列表不能自动设置完成；
- 缓存命中不能自动设置完成；
- Discovery Accelerator 的普通返回默认不设置完成。

### 6.4 Provider Checkpoint

```text
provider_checkpoint
- provider_id
- request_url
- etag
- http_last_modified
- response_sha256
- observed_lastmod_hint
- cc_index_id
- page_cursor
- shard_cursor
- checkpoint_artifact_id
- checked_at
- provider_release_id
```

Provider Evidence 与 Checkpoint 必须能支撑 retry/replay，而不是依赖 Pod 本地目录。

### 6.5 Sitemap / Feed 增量同步

优先使用：

```text
If-None-Match
If-Modified-Since
```

- 304：更新检查时间，复用上次 Provider Evidence；
- 200：保存新 Provider Artifact，计算 body hash，再与旧 Inventory diff；
- 不支持 validator：退化到 body hash + `<lastmod>` hint + 周期 full reconcile；
- `<lastmod>` 只作 hint，不直接作为内容版本真相；
- 不使用字符串 `<lastmod>` 排序替代规范化时间与内容 hash。

### 6.6 超大 Sitemap Index 持久分片

当 sub-sitemap 数或预计 URL 数超过阈值：

```text
Root Sitemap Index
 -> save Provider Artifact
 -> materialize sub-sitemap list
 -> create provider_shard
 -> durable Fair Scheduler
 -> Conditional GET per shard
 -> streaming XML parse
 -> batch upsert observations
 -> shard checkpoint
```

避免单进程同时持有全站 `seen/results/discovered_urls` 或一次创建所有子 sitemap Task。

### 6.7 Native CommonCrawlIndex Provider

可重放历史回填必须显式固定：

```text
cc_index_id
url_pattern
query parameters
page/shard checkpoint
query evidence artifact
```

同一 Backfill Run 的 retry/replay 复用同一 `cc_index_id`。需要补最新 Common Crawl 时创建新 Provider Run。

Common Crawl 结果用于历史 gap evidence，不单独证明历史完整。

## 7. Crawl4AI URL Seeder 的生产定位

### 7.1 定位

```text
provider_type = CRAWL4AI_URL_SEEDER
role = DISCOVERY_ACCELERATOR
mode = SITEMAP | CC | SITEMAP_PLUS_CC
```

它可以产生 Observation 和 Probe Hint，不直接产生 Document、Coverage Complete 或 PASS Markdown。

### 7.2 Coverage 任务不把 `sitemap+cc` 当一个完整 Provider

当前 Seeder 组合模式内部按 source 顺序执行，且不能给 Sitemap 与 CC 分别提供平台级 completion 语义。

生产 Coverage 建议拆成：

```text
Provider Run A = NATIVE_SITEMAP
Provider Run B = NATIVE_COMMON_CRAWL_INDEX
Seeder Run     = DISCOVERY_ACCELERATOR
```

三者结果在 Coverage Snapshot 汇总。

### 7.3 Seeder 返回成功不代表 Provider 完成

Seeder 内部 discovery 可能在已产生部分 URL 后遇到错误，而调用仍可得到普通结果列表。因此：

```text
List returned       != Provider completed
Non-empty result    != Provider completed
```

Seeder 普通 List 返回不能自动生成 `completion_attested=true`。

### 7.4 `max_urls` 只是软停止/返回上限

多 worker 下对共享 `results` 的长度检查与 append 不是硬配额事务，内部请求/结果可能少量超出，最终再切片返回。

因此：

- `max_urls` 只作为本地软停止；
- 平台硬预算由 Scheduler/Provider Adapter 负责：`max_requests/max_observations/max_bytes/max_wall_clock`；
- 达限统一记录 `RESULT_LIMIT_REACHED` 或对应平台预算原因；
- 不能将达限解释为 Provider exhausted。

### 7.5 `hits_per_sec` 不是严格 QPS

当前实现通过 `asyncio.Semaphore` 限制局部并发，不是按秒补 token 的时间窗口限流。

平台负责：

```text
per_host_qps
per_host_concurrency
per_registrable_domain_concurrency
per_source_concurrency
Retry-After
origin_backoff_until
```

Seeder local semaphore 只做第二道保护。

### 7.6 Seeder Cache 只作 Accelerator

业务规则：

```text
cache hit          != Provider unchanged
cache file exists  != Cache complete
cache miss         != Provider changed
status=valid       != Valid article
```

尤其 Common Crawl 本地 cache 不作为 Provider completion evidence。

### 7.7 Attempt-Scoped Cache Isolation

每个 Seeder Attempt 使用独立目录：

```text
seeder-cache/<attempt_id>/...
```

- 失败 Attempt 的 cache 不复用；
- retry 使用新目录或显式强制重新获取；
- 成功 cache 可以作为可选 Accelerator Artifact 晋升，但不作为 Coverage Evidence；
- 不让一个失败的 partial cache 污染后续重试。

### 7.8 Common Crawl Index 固定不依赖 Seeder 公共配置

生产可重放 CC 使用 Native CommonCrawlIndexProvider。

若短期为复用代码而由 wrapper 固定 Seeder 内部 index，只能在 pinned release 下使用，并必须经过 Contract Test；不得把内部字段暴露给普通用户。

### 7.9 全历史模式关闭前置语义过滤

完整性优先时：

```text
pattern = *
filter_nonsense_urls = false
query = null
score_threshold = null
```

先保存 Observation，再由版本化 Selection Policy 分类。

文档描述与具体 release 的过滤规则可能漂移，行为必须按源码+fixture 测试固化。

### 7.10 Partial Head / Live Check 只作 Hint

可保存：

```text
url_probe_observation
- observed_url
- final_url
- probe_type
- status
- title_hint
- canonical_hint
- content_type_hint
- published_at_hint
- updated_at_hint
- language_hint
- probe_artifact_id
- runtime_release_id
```

最终仍需平台 Fetch + Scope + MIME + Raw Artifact + Quality Gate。

### 7.11 BM25 只做优先级

Seeder BM25 依赖当前候选集合与 metadata，且分数归一化会随候选集变化。

仅用于：

- focused discovery；
- repair/gap priority；
- 主题子集；
- 管理端候选排序。

不得用于全历史 Inventory 的永久保留/删除判定。

### 7.12 不用 `many_urls(1000 domains)` 代替平台调度

平台模式：

```text
Fair Scheduler
 -> lease Provider Task / small bounded batch
 -> Global Admission
 -> invoke Seeder Adapter
 -> materialize Observations
 -> checkpoint
 -> ack Task
```

不一次把 1000 Source 交给同一进程内 `asyncio.gather()`；同一 Seeder 实例的 local state 不应成为跨域调度契约。

## 9. URL Identity、Scope 与 Persistent Frontier

### 9.1 Conservative Normalization

URL 身份分层：

```text
observed_url
normalized_url
redirect_target
canonical_url_hint
url_identity_id
```

```text

 -> bounded micro-batch
 -> Runtime Dispatcher
 -> Browser pool / HTTP execution
 -> streaming materialization
```

平台负责 durable/global/fairness；Runtime 负责 ephemeral/local/resource safety。

### 12.3 Dispatcher Policy

MemoryAdaptive/Semaphore 均只作为单 Runtime 局部控制。

要求：

- micro-batch 有硬上限；
- 不允许 `0=unbounded`；
- Runtime local requeue 不消耗源站 retry budget；
- 高内存等待超时映射为 Runtime 资源错误；
- Semaphore 即使抓取并发有界，也不能接收 mega-batch；
- Capacity Planner 使用实测有效并发而非参数名推断。

### 12.4 Runtime Outcome 归一化

```text
FINAL_SUCCESS
FINAL_FAILURE
LOCAL_REQUEUED
NO_CONFIG_MATCH
CANCELLED_ON_STREAM_CLOSE
RUNTIME_MEMORY_PRESSURE_TIMEOUT
```

Runtime local requeue 不是平台 retry。

### 12.5 Result Identity

禁止：

```python
for input_url, result in zip(urls, results):
    persist(input_url, result)
```

必须按 correlation identity：

```text

- runtime_task_id
- attempt_id
- input_url_identity_id
- correlation_key
- normalized_outcome
- materialized_at
```

### 12.6 Streaming 与 Stream Close

Browser micro-batch 优先 streaming，完成一个物化一个。

stream 被取消时：

```text
RUNNING_STREAM
 -> RUNTIME_STREAM_ABORTED
 -> verify runtime cleanup
 -> keep already materialized terminal items
 -> reconcile unmaterialized items
 -> durable requeue with fencing
```

### 12.7 Micro-batch 计算

```text
batch_size = min(
  runtime_batch_max_urls,
  available_runtime_slots * batch_factor,
  per_domain_budget,
  lease_deadline_budget,
  expected_result_bytes_budget,
  memory_headroom_budget

```

Browser Repair 默认 1 URL/Job；Browser Backfill 采用小批量 streaming。

## 22. 取消、暂停、Drain 与恢复

### 22.1 Stop 语义

- **Pause Source**：停止发新 Task；
- **Pause Provider**：停止新 Provider Lease，保留已落 Observation/Checkpoint；
- **Cancel Run**：停止新 lease，关闭 Runtime stream，reconcile 未 terminal item；
- **Drain Runtime**：停止新 Admission，等待 active job 收敛；
- **Replace Runtime**：新实例通过 health/contract 后切流，再下线旧实例。

### 22.2 Crash Recovery

Worker/Runtime 崩溃：

1. lease 到期；
2. Reconciler 查看哪些 item/shard 已 terminal materialize；
3. 已持久化成功项不重抓；
4. 其余重新进入 PENDING；
5. fencing token 防止旧 Worker 回写；
6. Provider Checkpoint、Coverage、Frontier、origin backoff 不受 Runtime 重启影响；
7. 失败 Seeder Attempt 的 local cache 不作为重试真相。

- result/artifact schema；
- browser/context leak。

## 28. 验收标准

上线前至少满足：

1. 新站可配置接入，不复制站点爬虫代码；
2. 每个 Source 可展示 Provider Inventory、Completion Attestation、Coverage、Known Gap 和 Stop Reason；
3. `List returned`、非空结果、cache hit、`status=valid`、BM25 分数都不能自动代表 Provider/Article Truth；
4. `RESULT_LIMIT_REACHED`、预算耗尽、`ERROR_PARTIAL` 不得标记 Coverage 完成；
5. Coverage 模式的 Sitemap 与 Common Crawl 有独立 Provider Run、Evidence 与 terminal outcome；
6. Common Crawl 回填显式固定 `cc_index_id`，retry/replay 不静默漂移；
7. Seeder CC cache、Sitemap cache、HEAD cache 不作为 Provider Completion Evidence；
8. 失败 Seeder Attempt 的 partial cache 不复用为成功真相；
9. Incremental 不会被大型 Backfill 饿死；
10. Worker/Runtime 崩溃后 Task 自动恢复；
11. Raw Artifact 不可变，IR/Markdown 可重放；
12. HTTP 与 Browser 有明确升级条件；
13. Browser micro-batch 有硬上限；
14. Runtime Result 按 identity 关联，不按列表位置；
15. stream early close 后未 terminal item 可准确重调度；
16. 跨 Worker host/domain QPS/并发严格生效，Runtime/Seeder local limiter 只作第二道保护；
17. Source、Provider、Seeder、Runtime、Extractor、IR、Renderer 全部可版本追溯；
18. Web 管理端能区分 Provider Complete、Partial、Truncated、HTTP Cache、Seeder Cache、平台全局限流、本地并发与 Runtime 压力；
19. 超大 Sitemap Index 使用 durable shard，不依赖单进程全量 `seen/results`；
20. 所有 Provider 预算耗尽、截断与部分错误都进入 Coverage；
21. Search Index 可从 Canonical 数据删除后重建；
22. 全链路有 correlation、审计、Contract Test 与 Chaos Recovery。

## 29. 最终架构结论

最终系统不是“让一个爬虫进程抓 1000 个博客”，而是把长期知识库拆成几个明确的事实边界：

```text
Source / Provider / Coverage / Frontier / Task Truth
    = PostgreSQL

Provider Evidence / Raw / IR / Markdown Truth
    = Object Storage + PostgreSQL Metadata

Cross-worker Scheduling / Politeness
    = Fair Scheduler + Redis Lua + Durable Backoff

Replayable URL Inventory
    = Native CMS/Sitemap/RSS/Archive/CommonCrawlIndex Providers

Discovery Acceleration
    = Crawl4AI URL Seeder + Domain Mapping + Deep/Adaptive Gap Jobs

Browser Execution
    = Pinned Crawl4AI Runtime + bounded dispatcher/browser pool
```

生产关键约束：

**Provider 先保存 Observation 再筛选；Provider Complete 必须有可验证 Attestation；Sitemap 增量用 Conditional GET；Common Crawl 显式固定 index；超大 Sitemap 使用持久分片；Seeder 只作 Accelerator，返回列表、cache、`max_urls`、`status=valid`、BM25 和 local semaphore 都不是业务真相；平台只给 Runtime 有界 micro-batch；所有结果按 identity 关联；所有关键语义由 pinned release Contract Test 验证。**

采用该架构后，可同时获得：

- 1000+ 技术博客的可解释历史覆盖；
- 低成本增量同步；
- 新站配置化扩展；
- 大站可分片、可恢复的 URL Inventory；
- 稳定可重放 Markdown；
- 完整 Web 运维与诊断；
- 可水平扩容的 HTTP/Browser/Provider 执行面；
- 不依赖任何单个 Runtime、Seeder cache、latest index 或进程内队列的长期可靠性。
