# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站和公开 Newsletter** 的长期知识库采集平台，可平滑扩展到数千站点和百万级至千万级文章，并持续接入新网站。

平台必须同时解决“抓得到、抓得全、持续更新、稳定清洗、可运营、可恢复、可解释”六类问题，而不是把网页抓取等同于一次 HTTP 请求。

核心目标：

1. **全历史回填**：尽可能完整发现每个已批准 Source 的历史文章，保存发现证据，并能解释 Coverage、Known Gap、失败和停止边界；
2. **持续增量同步**：持续发现新文章、正文更新、URL 迁移、重定向、删除和重发布；
3. **稳定 Markdown**：从不可变 Raw Artifact 经确定性抽取、质量门禁、Canonical IR 生成可重放 Markdown；
4. **低成本扩站**：新增网站优先通过 Source Profile、Provider、Traversal Policy、Extraction Recipe 配置完成，不维护 1000 份站点专用爬虫；
5. **Web 可运营**：支持 Source 接入、审批、配置发布、Backfill、Incremental、Coverage、Frontier、质量、成本、失败诊断、暂停、恢复、停止和审计；
6. **可搜索与 RAG**：支持 BM25、向量和混合检索，并可回溯原文、版本、Source、Artifact 和抓取证据；
7. **可观测、可恢复、可重放**：任意 URL、Task、Runtime Result、Artifact、IR、Markdown 都能解释来源、版本和执行路径；
8. **渐进扩展**：开发期 Docker Compose，生产期按 Discovery、HTTP、Browser Runtime、Extraction、Projection 独立水平扩容；
9. **主链不依赖 LLM**：LLM 仅作可选增强，不参与 Coverage Truth、URL Identity、Canonical URL、Robots Access、正文是否存在和历史完整性最终判定；
10. **高成本路径有硬预算**：Browser、Deep Crawl、Repair、Focused Job、模型调用、诊断 Artifact 均有 page/request/process/model/byte/wall-clock 预算；
11. **配置安全**：外部用户只能提交声明式低能力配置，不能获得任意 JS/Python、代理、CDP、浏览器 Profile、服务器路径等 Runtime 能力；
12. **停止后真正静默**：取消、暂停、Lease 丢失、Runtime drain、Browser Process recycle 后，task/page/context/session/resource token 必须收敛；
13. **Runtime 多结果不静默丢失**：批量、流式、Deep Crawl 的每条结果都必须显式物化并按 identity 关联；
14. **Runtime 只是执行面**：第三方 crawler 的 job queue、cache、browser pool、monitor、task id 不得升级为平台业务真相。

### 1.1 核心 SLO

- **Coverage**：每个 Source 可解释 Provider、URL Inventory、Frontier、Known Gap、Backfill Stop Reason；
- **Freshness**：新文章从发布/发现到 PASS Markdown 的延迟；
- **TTFM**：URL 首次发现到首个可用 Markdown 的时间；
- **Extraction Quality**：标题、正文完整率、噪声率、代码块/表格/列表保留率、截断率；
- **Reliability**：Task 成功率、Retry、DLQ、Queue Age、Lease Recovery、Checkpoint Resume；
- **Browser Efficiency**：HTTP 命中率、Browser avoided/recovery、Browser pool reuse、每文档 Browser 成本；
- **Runtime Stability**：Runtime queue saturation、内存压力、browser process generation age/pages/RSS、drain latency、强制 kill 率；
- **Identity Quality**：重复文章误合并/漏合并率；
- **Validity Quality**：Soft-404、假 200、空壳 SPA 识别准确率；
- **Result Integrity**：Runtime 返回结果物化完整率、cardinality mismatch、identity mismatch；
- **Cancellation**：停止请求到停止新 Admission、Runtime QUIESCED、Run STOPPED 的延迟；
- **Config Safety**：Power-field 绕过数为 0，Runtime Config 可回溯编译报告和 Release；
- **Admission Accuracy**：硬预算 overshoot 为 0；
- **Replayability**：同 Raw Artifact + 同 Release 可复现 Extraction、IR、Markdown 和质量评分。

### 1.2 非目标

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不默认使用个人持久 Browser Profile、Magic/模拟用户等反爬绕过能力；
- 不把 HTTP 200、Runtime `success=true`、DOM 很长或文件下载成功直接视为文章正确；
- 不把搜索结果数、Common Crawl、Wayback、Deep Crawl 页数、`max_pages` 当历史完整性证明；
- 不把 Crawl4AI 即时 Markdown、LLM 摘要或改写直接作为 Canonical Markdown；
- 不把 Redis、Runtime Cache、Browser Session、Visited Set、Dispatcher Queue、Search Index 当业务真相；
- 不允许 priority、score、low gain 或预算永久删除尚未保存的历史候选；
- 不允许 Web/API 调用者构造任意 Runtime 对象、运行任意代码或指定服务器文件路径；
- 不默认永久保存所有 MHTML、network、console、screenshot、trace；
- 不默认对全部文档构建 GraphRAG。

## 2. 核心设计原则

1. **Coverage First**：先建立 URL Inventory，再抓正文；
2. **Authoritative First**：CMS/API、Sitemap、RSS/Atom、官方 Archive 优先；
3. **Historical Gap Is Evidence, Not Truth**：Common Crawl、Wayback 只补洞；
4. **Discovery / Fetch / Extract / Quality / Projection 分离**；
5. **HTTP First, Browser Slow Lane**；
6. **Snapshot First**：先保存不可变 Raw Artifact；
7. **Canonical IR First, Markdown as Projection**；
8. **Recipe, Not 1000 Site Scripts**；
9. **Stable Identity**：Source、URL、Run、Task、Attempt、Runtime Result、Artifact、Document、Version 使用稳定 ID；
10. **Idempotent + Recoverable**：幂等键、Lease、Fencing Token、Checkpoint、Inbox/Outbox；
11. **Fair by Default**：大站 Backfill 不能饿死 Incremental、小站和 Repair；
12. **Bounded Concurrency Everywhere**；
13. **No Silent Degradation**：过滤、截断、预算耗尽、降级、结果缺失必须记录原因；
14. **Observation Before Selection**：链接事实先保存，再 Filter/Score/Budget；
15. **Persistent Frontier, Not In-Memory Traversal**；
16. **Approved Scope First**：发现 host/path 不等于允许访问；
17. **Soft-404 Is First-class**；
18. **Global Admission + Local Adaptation**：平台负责跨 Worker/Pod，Runtime 只做本地自保护；
19. **Runtime Result Is Advisory**：Runtime status/success/cache/score 不直接升级为业务真相；
20. **Normalize Conservatively**：path/query 默认保留大小写和语义；
21. **Correlate by Identity, Never by Position**；
22. **Strict Budget Is Platform-owned**；
23. **Config Is Capability**：能改变代码、网络、浏览器、secret 的字段必须经过 Capability Firewall；
24. **Untrusted by Default at Network Boundary**；
25. **Caller Never Owns Paths**；
26. **Quiesce Before Reuse**：Runtime 未清零不得复用或宣称 STOPPED；
27. **Zero Must Not Mean Unbounded by Accident**；
28. **Materialize Before Interpreting**：Container/Generator/Stream 先逐条物化；
29. **Evidence Is Tiered**：Durable 与 Diagnostic Evidence 分层；
30. **Runtime Schema Drift Must Fail Loudly**；
31. **Security State Never Crosses Isolation Key**；
32. **Behavior Beats Naming**：第三方参数名和文档不是生产行为契约，必须用 pinned release + Contract Test 验证；
33. **Context Generation != Process Generation**：回收 Browser Context 不等价于重启 Chromium 进程；
34. **Runtime Queue != Durable Queue**：进程内 job queue 只能作为局部保险丝；
35. **Webhook Is Hint, Reconciliation Is Truth**：回调采用幂等消费并有主动对账兜底；
36. **Business Telemetry != Runtime Telemetry**：抓取服务健康不代表历史覆盖完整。

### 3.1 控制面与执行面

**平台控制面**拥有：

- Source、Scope、Provider、Profile Release；
- URL Inventory、Frontier、Coverage；
- Run、Task、Attempt、Lease、Retry、DLQ；
- Runtime Registry 与资源预算；
- Artifact、Document、Version、Quality；
- 配置审批、审计、搜索投影。

**Runtime Service Plane**只负责执行受控抓取命令：

- HTTP/Browser 实际网络请求；
- 浏览器池复用；
- 单实例内存保护与局部并发；
- Runtime Job、monitor、WebSocket、Prometheus；
- 结果返回。

Runtime 不能拥有最终 Coverage、最终 Document Identity、最终 Markdown、跨 Worker Fairness 和长期任务状态。

### 3.2 业务真相边界

**PostgreSQL + Object Storage 是业务真相。**

- PostgreSQL：Source、Approved Host、Provider、URL Identity、Observation、Robots、Validity、Frontier、Task、Cursor、Coverage、Attempt、Runtime Envelope、Runtime Event Inbox、Quality、Document、Version、Release、Audit；
- S3/MinIO：Raw HTML、原始 PDF、Provider Evidence、Candidate、IR、Markdown、Checkpoint、按策略保存的 Trace/MHTML/截图；
- Redis Streams：任务运输和 Backpressure；
- Redis Lua：Token Bucket/Semaphore/短期资源令牌；
- Prometheus/TSDB：运行指标；
- OpenSearch/pgvector：可重建 Serving Projection；
- Crawl4AI queue/cache/browser pool/monitor recent state：均为可丢失 Runtime State。

## 4. 技术选型与版本策略

### 4.1 控制面

- **FastAPI + Pydantic**：REST API、Command、Schema、Webhook Inbox；
- **PostgreSQL**：Truth Store、Task、Frontier、Coverage、Version、Audit；
- **Redis Streams**：任务运输；
- **Redis Lua Token Bucket/Semaphore**：跨 Worker 域名和 Browser 资源限流；
- **React/Next.js + TypeScript**：Web 管理后台；
- **OpenTelemetry + Prometheus + Grafana + Structured Logging**；
- **S3/MinIO**：不可变对象；
- **Vault/KMS/Secret Manager**：Secret 引用；
- **Nginx/Envoy/API Gateway**：TLS、请求体上限、Rate Limit、Correlation ID。

### 4.2 Discovery / Fetch

- **httpx/aiohttp**：robots、Sitemap、Feed、CMS API、Conditional GET、普通网页、SafeProbe；
- **RFC 9309 Robots Engine**；
- **Crawl4AI pinned release**：Browser Render、Deep Crawl Prefetch、局部 Runtime 调度；
- **Crawl4AI Self-Hosted Runtime Pool**：异步 Job、局部有界队列、browser pool、monitor；
- **Playwright Python**：作为 Runtime 内部能力或必要时独立复杂慢路径；
- **Common Crawl / Wayback CDX Adapter**：历史补洞；
- **合规 Search API/SearXNG Adapter**：Gap 和 Source Candidate；
- **PyMuPDF/pdftotext**：PDF；扫描件走 OCR 慢路径；
- **Python MIME Parser**：Newsletter Inbox Provider。

### 4.3 Extraction / Search

- **Trafilatura**：Generic Candidate；
- **lxml/BeautifulSoup**：DOM/XPath、Metadata、Repair；
- **JSON-LD/OpenGraph/Microdata**；
- **CSS/XPath/Regex Recipe**；
- **SimHash/MinHash**：近重复候选；
- **OpenSearch BM25 + pgvector + RRF**；
- embedding/reranker/LLM 仅作可选增强。

## 6. Source 接入与可扩展配置

新增站点优先配置，不写代码。

### 6.1 Source Profile DSL

示例：

```yaml
source:
  domain: engineering.example.com
  timezone: Asia/Shanghai

scope:
  allowed_hosts:
    - engineering.example.com
  allowed_paths:
    - /blog/**
    - /posts/**
  exclude_paths:
    - /tag/**
    - /author/**
    - /search/**

discovery:
  providers:
    - sitemap
    - rss
    - archive_listing
    - internal_links
  backfill:
    commoncrawl: gap_only
    wayback: gap_only

  http_first: true
  browser_fallback:
    enabled: true
    conditions:
      - empty_main_content
      - js_shell
      - extraction_quality_below: 0.65
  max_rps: 1.0
  max_concurrency: 2

browser_intent:
  block_resources: [image, font, media]
  wait_for_selector: article
  max_scroll_steps: 5

  article_selector: article
  remove_selectors:
    - nav
    - footer
    - .newsletter-box
    - .related-posts

incremental:
  feed_interval: 10m
  sitemap_interval: 6h
  listing_interval: 1h
  revisit_unchanged_after: 30d
```

### 6.2 Capability Firewall

Web/API 用户不能直接提交：

- 任意 JavaScript/Python hook；
- proxy/CDP URL；
- `user_data_dir`、本地文件路径；
- 任意 header/cookie secret；
- arbitrary browser executable/extra args；
- 任意 LLM base URL；
- Deep Crawl Strategy 对象；
- Runtime monitor admin endpoint；
- `0 = unbounded` 的生产预算。

DSL 经过：

```text
Schema Validation
 -> Scope Policy
 -> Capability Check
 -> Budget Clamp
 -> Secret Reference Resolution
 -> Runtime Config Compiler
 -> Immutable Runtime Config Release
```

高能力字段必须由管理员审批或在服务端预置成 capability profile。

## 7. 历史 URL 发现与全量回填

### 7.1 Provider 优先级

推荐顺序：

1. CMS 官方 API / GraphQL / JSON endpoint；
2. Sitemap / Sitemap Index；
3. RSS / Atom / JSON Feed；
4. 官方 Archive / Pagination / Year-Month listing；
5. 站内文章链接；
6. 安全 Domain Mapping / homepage probe；
7. Common Crawl / Wayback CDX；
8. Search API；
9. Deep Crawl / Focused Crawl 作为 Gap Provider。

每个 Provider 都输出 Observation，不直接输出“最终文章”。

### 7.2 Inventory 合并

流程：

```text
Provider Raw Result
 -> 保存 Provider Evidence
 -> URL Observation
 -> Conservative Normalize
 -> Scope Check
 -> URL Identity Upsert
 -> Article Candidate Classification
 -> Persistent Frontier
```

同一 URL 被多个 Provider 发现时保留全部 provenance。

### 7.3 Deep Crawl 的定位

Deep Crawl 只用于：

- Sitemap 不完整；
- Archive 结构复杂；
- 需要补洞；
- 找到新 listing pattern；
- 验证 Coverage Gap。

Deep Crawl 发现的每条链接先保存 Observation，再进入平台 Frontier。Runtime 自带的 visited set、depth、score 不能代替平台持久化。

### 7.4 Backfill 停止条件

停止不是“到 max_pages 了”，而是一个可解释状态：

- `PROVIDERS_EXHAUSTED`；
- `APPROVED_SCOPE_EXHAUSTED`；
- `BUDGET_EXHAUSTED`；
- `ROBOTS_BLOCKED`；
- `ACCESS_DENIED`；
- `KNOWN_GAPS_REMAIN`；
- `OPERATOR_STOPPED`；
- `SOURCE_DECOMMISSIONED`。

Coverage 页面必须展示停止原因和 Known Gap。

## 8. 增量同步

增量同步不应每天重新全站爬一遍。

### 8.1 增量信号

优先级：

- RSS/Atom 新 item；
- Sitemap `lastmod` 变化；
- CMS API `updated_at`；
- Archive/listing 首屏变化；
- HTTP `ETag` / `Last-Modified`；
- Raw content hash；
- Canonical URL / redirect 变化；
- 周期性低频审计扫描。

### 8.2 Conditional GET

普通 HTML 优先：

```http
If-None-Match: <etag>
If-Modified-Since: <last_modified>
```

304 只更新 freshness evidence，不创建新 Document Version。

### 8.3 版本判定

```text
Fetch
 -> Validity Gate
 -> Raw Artifact Hash
 -> Extraction
 -> Canonical IR Hash
 -> Normalized Content Hash
```

只有规范化正文实际变化才创建新 `document_version`。广告、推荐区、时间戳等噪声变化尽量在 IR 前消除。

### 8.4 删除与迁移

- 301/308：记录 redirect edge，谨慎更新 canonical；
- 404/410：多次确认后标记 `MISSING/DELETED_CANDIDATE`，保留历史版本；
- Soft-404：进入 Validity 判定，不直接当成功文章；
- URL 迁移：结合 canonical、标题、发布时间、内容指纹建立 alias，不轻易新建 Document。

绝大多数技术博客应走 HTTP Fast Lane。

### 9.1 HTTP Fetcher

职责：

- DNS/TLS/redirect；
- robots 检查；

- Conditional GET；

## 10. Runtime Service Plane：Crawl4AI Self-Hosted Slow Lane

### 10.1 Runtime Registry

所有 Runtime 实例注册到控制面：

```text
id
endpoint
release
result_schema_release
status
capacity
queue_capacity
feature_flags
network_policy_class
last_health_at
```

调度只选择 `READY` 实例。升级时切为 `DRAINING`，停止新 admission，等待 active request 收敛后替换。

### 10.2 双层队列

平台层：

- PostgreSQL Task Truth；
- Redis Streams 运输；
- Lease + fencing token；
- fair scheduler；
- source/domain/global browser token。

Runtime 层：

- 有界 background job queue；
- 固定 worker 数；
- per-principal/local quota；
- MemoryAdaptiveDispatcher / SemaphoreDispatcher；
- 本地 RateLimiter。

Runtime 返回 429/503 时记录 `RUNTIME_BACKPRESSURE`，按 jitter backoff 重新调度，并下调该实例可用容量估计；禁止无上限瞬时重试。

### 10.3 异步 Job 绑定

```text
crawl_attempt CREATED
 -> Global Admission token acquired
 -> Runtime Gateway POST /crawl/job
 -> 保存 runtime_id + runtime_task_id
 -> attempt RUNNING
 -> webhook 或 reconciliation 获取结果
 -> Result Materializer
 -> attempt terminal
 -> token release
```

平台 Attempt ID 必须通过 correlation metadata/side table 与 Runtime Task ID 绑定，不能只依赖 runtime 返回 ID。

### 10.4 Runtime Event Inbox

Webhook handler：

1. 认证来源；
2. 验证 body 大小、schema、timestamp；
3. 计算 `event_key` 幂等插入 inbox；
4. 快速返回 2xx；
5. 后台消费者按 attempt fencing token 处理；
6. 成功后写 outbox 驱动下一阶段。

Webhook destination 必须由服务端固定或 allowlist，普通 Web 用户不能任意指定 URL，避免 SSRF。

### 10.5 Runtime Reconciler

周期扫描：

- attempt=RUNNING 且超过 callback deadline；
- runtime task 已完成但 inbox 未收到；
- runtime 实例重启导致 task 丢失；
- lease 过期；
- result 已存在但 materialization 未完成；
- webhook 重复/乱序。

恢复策略必须检查 fencing token，防止旧 worker 的迟到结果覆盖新 attempt。

### 10.6 Result Materializer

无论 Runtime 返回 list、generator、NDJSON stream、Deep Crawl 多页结果，都先统一物化为：

```text
runtime_result_envelope
- envelope_id
- attempt_id
- runtime_id
- runtime_task_id
- result_index
- url
- final_url
- status_code
- success
- headers_ref
- html_ref
- markdown_hint_ref
- links_ref
- media_ref
- dispatch_metrics
- runtime_error
```

再按 URL identity 关联。禁止 `zip(input_urls, results)` 这类位置关联。

## 11. Browser Pool 与进程代际治理

### 11.1 Browser Pool

Runtime 可采用 permanent/hot/cold 三层池提高复用率：

- default public config：高复用；
- 高频特殊 config：hot；
- 新/低频 config：cold；
- janitor 根据内存压力缩短 cold/hot TTL。

池只是性能缓存，不拥有业务语义。

### 11.2 Isolation Key

复用 key 不能只看 viewport/headless，必须考虑安全状态：

```text
runtime_profile_release
network_policy_class
credential_scope
session_isolation_class
proxy_policy_class
browser_feature_class
```

公开博客默认 `public-stateless`；需要 cookie/login 的来源必须独立审批和隔离，不能跨 Source 复用持久 session。

### 11.3 Context Generation

Context 回收触发条件：

- max pages；
- max context age；
- JS/navigation error rate；
- suspicious storage/cookie growth；
- source/session scope change；
- cleanup verification failure。

### 11.4 Browser Process Generation

独立记录：

```text
browser_process_generation
- runtime_id
- generation_id
- pid/fingerprint
- started_at
- pages_total
- rss_peak
- crash_count
- renderer_error_count
- drain_started_at
- stopped_at
- stop_reason
```

主动替换条件：

- max process age；
- max pages；
- RSS 持续高位；
- renderer/browser crash；
- FD/process 异常增长；
- Runtime Release 升级。

流程：

```text
READY -> DRAINING -> no new tasks -> active=0 -> close -> verify PID gone -> NEW READY
```

“permanent browser”只表示池内默认浏览器优先复用，不代表生产进程永不重启。

## 22. Transactional Outbox / Inbox

### 22.1 Outbox

数据库状态变更与事件同事务写入：

```text
BEGIN
  update crawl_task ...
  insert outbox_event ...
COMMIT
```

后台 publisher 再投递 Redis Streams，避免“DB 成功但消息丢失”。

### 22.2 Inbox

Runtime webhook、外部 provider callback 等先写 Inbox，unique event key 去重，再执行业务变更。

这一组合提供现实可行的 at-least-once + idempotent 语义。

## 23. 故障恢复

### 23.1 Worker Crash

Lease 超时后新 worker 领取；fencing token 阻止旧 worker 迟到写入。

### 23.2 Redis 故障

PostgreSQL Task Truth 不丢。恢复后由 outbox/reconciler 重新投递。

### 23.3 Runtime Pod 重启

进程内 queue/browser pool 可以全部丢失。Runtime Reconciler 根据 RUNNING Attempt 与 runtime 状态重新判断，必要时新建 attempt。

### 23.4 Object Storage 暂时不可用

Raw Artifact 未 durable 前不把 Fetch 标记完成。可短时 retry，但禁止只保留内存结果后继续下游。

### 23.5 Stop / Cancel

流程：

```text
Run STOP_REQUESTED
 -> scheduler 禁止新 task admission
 -> revoke queued transport messages
 -> running attempts request cancel/drain
 -> wait runtime active=0 or timeout
 -> force terminate residual process if needed
 -> verify tokens/leases released
 -> Run STOPPED
```

停止状态必须可证明没有后台幽灵任务继续消耗资源。

- Browser RSS/peak；
- extraction CPU time；
- Raw/Markdown 存储比；
- 每文章 Browser fallback 概率；
- 每 runtime browser reuse；
- queue saturation 点。

估算：

```text
Daily Requests
= active_sources × avg_incremental_checks
  + backfill_pages
  + retry
  + repair
```

Browser 成本：

```text
Browser Seconds / Article
= fallback_rate × avg_browser_seconds
```

优化优先级：

1. 提高权威 Provider 覆盖；
2. 提高 HTTP 命中；
3. 提高 Browser pool reuse；
4. 减少 Repair；
5. 最后才增加机器。

## 29. 关键验收标准

上线前至少满足：

1. 新增普通技术博客不改代码即可完成接入；
2. 任一 Source 的历史发现来源和 Known Gap 可解释；
3. 增量同步不依赖每日全站重抓；
4. HTTP 路径失败时 Browser Slow Lane 可控升级；
5. Runtime queue 饱和不会击穿平台，429/503 能正确退避；
6. Runtime Pod 重启不会丢失平台 Task Truth；
7. Webhook 丢失/重复都能通过 Inbox + Reconciler 收敛；
8. Browser Context 与 Browser Process 生命周期均可观测和回收；
9. Runtime monitor 与业务 Coverage 在 Web 上语义分离；
10. 原始 HTML 可重放生成 Markdown；
11. 文档更新生成 Version 而不是覆盖历史；
12. 配置无法通过网络注入任意代码、proxy/CDP、服务器路径；
13. stop 后没有残留 task/page/browser token；
14. 任一 Markdown 可追溯到 Raw Artifact、Attempt、Runtime Release、Extractor Release；
15. 搜索索引损坏时可从 Truth Store + Artifact 重建。

## 30. 最终架构决策

最终采用 **“平台业务控制面 + 持久化采集数据面 + 受控 Browser Runtime Service Plane”** 的分层架构。

- **PostgreSQL/Object Storage** 掌握长期业务真相；
- **Persistent Frontier + Fair Scheduler** 掌握 1000+ 站点的完整性、公平性和增量节奏；
- **HTTP Fast Lane** 处理绝大多数低成本页面；
- **Crawl4AI Self-Hosted Runtime Pool** 作为 Browser Slow Lane，吸收其异步 Job、局部有界队列、browser pool、monitor、WebSocket、Prometheus 和运维能力；
- **Runtime Gateway + Event Inbox + Reconciler + Result Materializer** 将第三方运行时与平台事实解耦；
- **Extraction Portfolio + Canonical IR + Quality Gate** 生成稳定 Markdown；
- **Web Admin** 同时覆盖 Source/Coverage/质量和 Runtime 运维，但严格区分业务状态与运行时状态；
- **Capability Firewall + Config Compiler** 确保扩站能力来自声明式配置而不是把高权限 Runtime 暴露给用户；
- **Context Generation + Browser Process Generation** 确保 7×24 小时运行时不会因永久进程泄漏逐渐失稳。

该方案可从单机 Compose 起步，在不重写领域模型和数据契约的前提下扩展到多 Worker、多 Runtime Pod 和数千 Source，并支持全历史回填、持续增量同步、稳定 Markdown、Web 管理、搜索/RAG、故障恢复和长期运营。
