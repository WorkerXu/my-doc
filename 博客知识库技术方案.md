# 博客知识库技术方案

## 1. 建设目标与规模边界

建设一个可长期运行、可横向扩展的技术博客知识库平台。首期约 1000 个技术博客、工程博客和技术文档站，抓取尽可能完整的历史文章并清洗为稳定 Markdown；后续可持续增加站点，并支持增量同步、版本追踪、全文/向量检索、Web 管理、质量审计和离线重处理。

设计按以下量级考虑：

- 1000+ Source，后续可扩展到数千站点；
- 百万级 Document；
- 数百万到千万级 URL / Observation；
- 多年运行、站点结构持续变化；
- 中英日韩等多语言技术内容；
- HTTP 为主、Browser 为受控 fallback；
- 原始事实可长期保留，派生索引可删除重建。

平台核心目标不是“能抓页面”，而是形成一套可证明历史 Coverage、可恢复任务、可回放处理、可追踪版本、可解释身份、可增量重建投影、可替换底层抓取与检索组件的系统。

## 2. 核心设计原则

1. **Config First**：新增普通站点主要通过 Source / Site Profile 配置完成，不修改核心代码。
2. **Coverage First**：历史完整性必须由 Provider Evidence 和 exhaustion reason 证明，不能用“队列为空”“达到 max_pages”冒充完整。
3. **HTTP First, Browser Last**：Feed/API/Sitemap/HTTP 优先，Browser 只处理动态页面或低质量 fallback。
4. **Resolution Is a First-class Plane**：Observed URL、Resolved Target、Network Final URL、Canonical Identity 是不同事实。
5. **Snapshot First**：网络事实先保存不可变 Snapshot，再抽取、清洗、建版。
6. **IR First, Markdown as Projection**：Canonical IR / Document Version 是事实层；Markdown、Chunk、Embedding、全文索引均可重建。
7. **Canonical Content 与 Query View 分离**：BM25/LLM/Query-focused Fit Markdown 不能覆盖完整正文。
8. **Language-aware Retrieval**：分词、stemming、stopwords、BM25 threshold、tag weight 都必须按 Analyzer Release 版本化，不能假设所有博客都适合英文空格分词。
9. **Release Everything**：Profile、Resolver、Fetch Route、Extractor、Quality、Markdown、Chunk、Analyzer、Embedding、Retrieval 均版本化。
10. **Idempotent + Recoverable**：所有任务有幂等键、lease、checkpoint、retry 和 partial success 语义。
11. **Source Sync 与 AI 解耦**：Embedding、Rerank、LLM、Summary 等失败不能阻塞源站事实同步。
12. **Evidence Everywhere**：发现、跳转、抓取、抽取、身份、版本、检索都可解释、可审计。
13. **Web 管理是平台能力**：异常、Coverage、跳转链、版本、成本、索引、策略 Release 都必须可运营。
14. **安全边界每跳执行**：重定向与 Browser 导航不能绕过 SSRF/Egress/访问策略。

## 4. 技术选型

### 4.1 控制面

- **FastAPI + Pydantic**：REST / Command API、Schema 校验。
- **PostgreSQL**：Source、Profile Release、Run、Task、Coverage、Redirect、Fetch、Document、Version、Projection State、Audit、Outbox。
- **Transactional Outbox**：数据库状态变更与消息发布保持事务一致。
- **Redis Streams**：任务运输、consumer group、retry、backpressure；不保存唯一业务事实。
- **React/Vue + TypeScript**：Web 管理。

### 4.2 数据面

- **HTTPX / aiohttp**：HTTP、Feed、Sitemap、API、条件请求和低成本跳转解析。
- **BeautifulSoup / lxml / CSS / XPath**：wrapper、meta refresh、selector、结构化 HTML 处理。
- **Trafilatura / Readability**：确定性正文候选。
- **Crawl4AI / Playwright**：动态页面、Browser fallback、Markdown / 内容过滤 Adapter。
- **S3 / MinIO**：HTML、HTTP body、Rendered DOM、Feed payload、PDF、Canonical IR、Markdown、Asset、调试产物。
- **OpenSearch**：全文检索、过滤、聚合、BM25。
- **pgvector / OpenSearch kNN** 起步；规模或独立扩展需求增加后可替换为 Qdrant / Milvus。
- **Prometheus + Grafana + OpenTelemetry**：指标、日志、Trace。

### 4.3 Crawl4AI 版本治理

Crawl4AI 不直接渗透业务模型，通过平台 Adapter 隔离：

```text
BrowserAdapter
MarkdownAdapter
ContentFilterAdapter
```

每次运行记录：

```text
adapter_release_id
crawl4ai_version
playwright_version
config_hash
runtime_image_digest
```

升级前用固定回归集比较：正文长度、标题、代码块、表格、链接、图片、Browser 成功率和耗时，验证后再切换 Release。

## 7. 新站接入与 PROBE

新增站点先执行 `PROBE`，不直接深爬：

1. 规范化 entry URL，确定 registrable domain、allowed origins 和 scope。
2. 获取 robots 及 sitemap 声明。
3. 探测 Sitemap Index / Sitemap。
4. 探测 RSS / Atom / JSON Feed。
5. 探测 WordPress REST、Ghost、Substack 等平台能力。
6. 识别 Archive、Category/Tag/Author、Docs Navigation、pagination。
7. 抽样比较 HTTP 与 Browser 正文质量、JS 依赖和成本。
8. 检测 Feed/Search 链接是否存在 wrapper、短链、meta refresh、JS redirect。
9. 推断主要语言和 analyzer hint。
10. 自动生成首版 Site Profile Release，在 Web 中人工审核/修正。

普通站点上线应主要完成“配置”，只有非常特殊站点才写 `SITE_CUSTOM_*` Adapter。

## 8. 全量历史发现与 Coverage

### 8.1 Provider Contract

所有发现 Provider 统一接口：

```text
probe(source, profile) -> capability
discover(cursor, budget) -> candidates + evidence + next_cursor
checkpoint() -> durable_cursor
exhaustion() -> explicit_reason
```

### 8.2 推荐发现顺序

```text
Authoritative CMS/API
 -> Sitemap Index / Sitemap
 -> Historical Feed
 -> Archive year/month
 -> Category/Tag/Author
 -> Docs Navigation / TOC
 -> Next/Prev / internal links
 -> Site Search as supplement
```

站内搜索不能作为完整历史的唯一来源。

### 8.3 Coverage 数据

`coverage_provider_run`：

```text

```

`url_observation`：

```text

```

达到预算只能：

```text

```

不能标记 COMPLETE。

### 8.4 FULL_BACKFILL 完成条件

一个 Source 的历史回填只有在主要 Provider 明确 exhausted，或者所有未覆盖区间都已记录为可解释 known gap 时才结束。

Web 必须能回答：

- 哪些 Provider 被使用；
- 每个 Provider 找到多少候选；
- 哪个时间区间/分页已穷尽；
- 哪些候选抓取失败；
- 哪些区间仍存在 gap。


### 11.4 Clean Markdown

Canonical Clean Markdown 必须确定性：

- 去除导航、广告、推荐、分享、评论等噪声；

### 13.1 信号优先级

```text
Feed/API cursor
 -> Sitemap lastmod
 -> Conditional GET
 -> Metadata Probe
 -> Full HTTP
 -> Browser
```

### 13.2 Feed/API

保存原始 Feed payload 和 Item Observation，比较：

```text
GUID / platform id
link

```

新 link 先进入 URL Resolution，再 Fetch。

### 13.3 Conditional Fetch

保存：

```text
ETag
Last-Modified
previous body hash
```

304：

- 不创建 Snapshot body 副本；
- 不创建 Document Version；
- 不重复 Extraction；
- 不重复 Projection。

### 13.4 Reconcile

即使有 Feed，也周期执行 Sitemap / Archive 差异核对，用于发现：

- Feed 窗口外遗漏；
- URL 迁移；
- Feed 未更新但正文发生变化；
- 删除/下线；
- 历史 Provider 新增可见页面。

单次 404 不立即删除知识库文档。多次观察或 authoritative API 明确下线后创建 Tombstone，历史版本保留。

## 15. Chunk、全文 Analyzer 与 BM25 Query View

### 15.1 Chunk

采用 heading-aware / structure-aware 切分：

- heading path 随 chunk 保存；
- 代码块尽量保持完整；
- 表格尽量不拆；
- 保留 block range；
- 超长代码/表格采用特殊 chunk policy；
- Chunk Release 变化允许离线 `RECHUNK`。

### 15.2 为什么必须多语言 Analyzer

当前 Crawl4AI `BM25ContentFilter` 默认使用英文 stemming，并以空格 `split()` 形式拆 token。这适合多数英文内容，但不能作为全平台统一 analyzer。

1000 个技术博客可能同时包含中文、日文、韩文、英文和混合代码文本。若把中文整段当成少量 token，BM25 的 tf/df 信号会失真。

因此定义 `analyzer_release`：

```text
id
version
language_policy
tokenizer
normalizer
stemmer
stopword_set
code_token_policy
symbol_policy
created_at
```

可选实现示例：

- 英文：standard tokenizer + language-matched stemming；
- 中文：ICU / Jieba 类 tokenizer；
- 日文/韩文：语言适配 analyzer；
- mixed code：保留 `foo_bar`、`ClassName`、`package.module`、版本号等技术 token。

Analyzer 是策略，不是真相层。

### 15.3 BM25 Query View

`query_view_release`：

```text
id
version
analyzer_release_id
query_extraction_policy
bm25_parameters
threshold
tag_weights
source_projection_type
created_at
```

`BM25_QUERY_VIEW` 正确链路：

```text
Canonical IR
 -> Clean Markdown / Blocks
 -> Analyzer
 -> BM25 score
 -> threshold gate
 -> restore original document order
 -> Query View
```

不是：

```text
HTML -> BM25 -> 唯一 Markdown
```

Crawl4AI 当前 BM25 实现的一个重要行为是：阈值筛选后按原始 block index 恢复原文顺序，而不是把输出按相关度重排。平台应显式建模这一语义。

逐块保存解释证据：

```text
query_view_block_evidence
  projection_id
  original_index
  raw_score
  tag_weight
  adjusted_score
  threshold
  selected
  analyzer_release_id
```

Web 搜索调试台可以解释为什么某段进入 Query View。

## 16. Hybrid Search 与 Index Generation

默认检索：

```text
OpenSearch BM25
 + Vector Search
 -> score normalization / fusion
 -> metadata filter
 -> optional rerank
 -> Context Assembly
```

检索结果必须回溯到：

```text
Source
Document
Document Version
Canonical URL
Chunk Range
Analyzer Release
Embedding Release
Retrieval Release
```

Embedding 模型、Analyzer 或 index schema 升级时创建新的 `index_generation`：

```text
BUILDING
 -> VALIDATING
 -> READY
 -> ACTIVE
 -> RETIRED
```

新 generation 后台构建并执行回归验证，成功后原子切换 alias；旧 generation 保留回滚窗口。

支持：

```text
RECHUNK
REEMBED
REINDEX
```

且这些任务不重新抓源站。


### 17.3 幂等键

```text

```

### 17.4 Partial Success

批量 100 个 URL，90 成功、10 失败时：

- 90 个事实立即提交；
- 10 个分别 retry / terminal；
- 不因单个异常整批回滚。

## 21. 安全与合规

- 遵守 robots 和站点访问策略。
- 不绕过登录、付费墙、验证码、WAF 或明确访问控制。
- scheme 只允许配置允许的协议，默认 http/https。
- 起始 URL 和**每次 redirect / Browser navigation** 都重新做 DNS/IP/Egress 校验。
- 阻止访问 private、loopback、link-local、metadata 等受限网络目标。
- 跨域跳转按 Source Policy 判断，而不是默认允许。
- Browser Worker 独立隔离网络、CPU、内存、wall-clock。
- API token、代理、对象存储密钥放 Secret Manager，不写 Profile 明文和普通日志。
- Web 高风险操作使用强类型 Command API、RBAC 和 Audit。

## 25. 验收标准

### Coverage

- 每个 Source 有可解释 Provider。
- FULL_BACKFILL 有明确 exhaustion evidence。
- known gap 可枚举、可重跑。
- 达到预算不会错误标记为完整。

### 增量

- Feed/API/Sitemap 新文章在目标 SLA 内进入系统。
- 304 不重复抽取、建版和投影。
- 未变化 Projection 不重复计算。
- Reconcile 能发现 Feed 窗口外遗漏。

### Redirect / Identity

- wrapper/短链保留完整解析证据。
- 跳转循环可检测。
- 每跳执行 Egress 校验。
- final URL 与 canonical identity 分离。
- 同一文章多入口不会因包装 URL 大量产生重复 Document。

### Markdown

抽样验证：

- title / author / time；
- 正文完整性；
- 导航噪声；
- heading；
- code block；
- list；
- table；
- image；
- outbound link。

Markdown 必须可从 Canonical IR / accepted source 确定性重建。

### 多语言检索

- 中文/英文等代表性语料有独立 Analyzer Release。
- CJK 不依赖英文 whitespace tokenizer。
- BM25 Query View 可解释每块 score、threshold 和是否入选。
- Analyzer / Retrieval Release 升级有离线回归集。

### 可靠性

- Worker 崩溃后 lease 可恢复。
- fan-out 保留部分成功。
- Embedding/Index 故障不阻塞 Source Sync。
- 所有高风险管理操作可审计。
- Crawl4AI/Playwright 升级可通过 Adapter Release 回滚。

## 26. 最终原则

1. Coverage First：先证明“应该有哪些 URL”，再看抓取成功率。
2. Evidence First：发现、解析、抓取、身份和版本都保存证据。
3. HTTP First, Browser Last：Browser 是昂贵 fallback，不是默认抓取器。
4. Resolution Is Not Identity：跳转终点和 canonical 文档身份必须分离。
5. Snapshot First, Replay Later：原始事实不可变，规则升级优先离线回放。
6. IR First, Markdown as Projection：Markdown 可重建，不是真相源。
7. Canonical Content 与 Query View 分离：BM25/LLM 过滤不能破坏完整正文。
8. Language-aware Analyzer：多语言分词、stemming、threshold、tag weight 必须 Release 化。
9. Release Everything：所有影响结果的策略与外部组件版本都可追踪、比较、回滚。
10. Idempotent + Recoverable：任务可重复、可恢复、可观察，partial success 不丢失。
11. Source Sync 与 AI 解耦：抓取事实不被 Embedding/LLM/Index 服务绑定。
12. Web 管理是平台能力：Coverage、异常、证据、版本、成本、检索解释都必须可运营。
