# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站与公开 Newsletter** 的长期知识库采集平台，并可平滑扩展到数千站点、百万级文章。

系统必须满足：

1. **全历史尽量抓全**：不仅抓页面，还要证明 URL 从何发现、哪些 Provider 已穷尽、哪里存在 Known Gap；
2. **持续增量同步**：发现新文章、正文修改、元数据变化、URL 迁移、删除与重发布；
3. **稳定产出 Markdown**：HTML、动态页面、PDF 等先转换为可追溯 Canonical IR，再统一渲染 Markdown；
4. **新增站点低成本**：通过 Site Family、Source Profile、Discovery Recipe、Routing Policy、Extraction Recipe 和 Extraction Portfolio 复用能力，不为每个站长期维护独立爬虫；
5. **Web 可管理**：支持接入、Probe、配置、调度、Coverage、页面分类、执行路由、质量、回放、版本、成本、导出、告警；
6. **可审计、可重建**：任意 Markdown 都能追溯到 URL、分类证据、执行路由、Artifact、抽取器、配置版本、质量判定和运行记录；
7. **幂等可恢复**：任务可重试、续跑、回放，不产生脏重复；
8. **抓取运行时可替换**：httpx、Crawl4AI、Playwright 都是 Adapter，不是业务真相；
9. **正文抽取可替换**：Trafilatura、确定性 selector、DOM Repair 都是候选生成器，最终由平台质量层决定 Canonical 内容；
10. **成本可治理**：Authoritative Discovery、Cheap Routing、HTTP First、Browser Last，高成本 LLM/Graph 默认不进入关键抓取路径；
11. **高成本步骤前置分流**：在 Browser、LLM、正文抽取和 Embedding 之前完成可解释的 Page Type Classification 与 Execution Routing。

### 1.1 核心 SLO

平台核心指标：

- **Coverage**：历史 URL 覆盖率、Provider exhaustion evidence、Known Gap；
- **Freshness**：文章发布到进入 PASS Canonical Markdown 的延迟；
- **Routing Efficiency**：ARTICLE/DOC/INDEX/ASSET/UNKNOWN 分类准确性、UNKNOWN 比例、Browser 避免率、LLM Exception 比例；
- **Extraction Correctness**：正文完整率、噪声率、结构正确率、Candidate Agreement；
- **Reliability**：Task 成功率、Retry/DLQ、Queue Age、Worker 恢复率；
- **Cost**：每 Source、每 1000 个 PASS 文档、每 accepted version 的网络/CPU/Browser/存储成本；
- **Traceability**：结果能回溯到不可变事实与版本化执行环境；
- **Retrieval Quality**：BM25/Vector/Rerank/可选 Graph 的 Recall、nDCG、引用命中率与查询成本。

### 1.2 非目标

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不用 LLM 主观判断替代 Coverage 证明；
- 不把 Redis、Browser Session、Crawler Cache/Frontier 当业务真相；
- 不把 Crawl4AI `fit_markdown`、LLM 摘要或改写作为 Canonical Markdown；
- 不因为 URL 曾抓取过就永久停止复检；
- 不把 HTTP 200、Crawler success、DOM 长度直接等同于“正文正确”或“历史抓全”；
- 不允许模板升级后无审计地改变全部生产 Source；
- 不默认对全部文档构建 GraphRAG；
- 不默认逐 URL 调用 LLM 判断页面类型、选择爬虫配置或抽取正文。

## 2. 核心设计原则

1. **Coverage First**：先证明“有哪些文章”，再批量抓正文；
2. **Authoritative First**：CMS/API、Sitemap、RSS/Atom、Archive 优先，动态列表和受限 Deep Crawl 补洞；
3. **Discovery Before Fetch**：URL 发现、规范化、Scope、分类、去重与正文抓取分离；
4. **Cheap Routing Before Expensive Execution**：Provider Hint、URL Rule、MIME、Structured Metadata、DOM Heuristic 优先，Browser/LLM 最后；
5. **HTTP First, Browser Last**：静态 HTTP 优先，只有真实需要时才进入浏览器；
6. **Snapshot First**：先保存不可变抓取事实，再抽取；
7. **Fetch != Extract**：页面获取成功与正文抽取成功是两个独立状态；
8. **Extractor Is Candidate Generator**：Trafilatura、selector、DOM Repair、Crawl4AI Markdown 都只产生候选；
9. **Agreement Before Trust**：重要内容通过多候选一致性或质量证据确认；
10. **IR First, Markdown as Projection**：Canonical IR 是正文结构事实，Markdown 可重建；
11. **Quality Is First-Class**：质量状态和网络状态分离；
12. **Recipe, Not Site Code**：分页、滚动、点击、分类、清洗、selector 用版本化语义 Recipe/Policy 表达；
13. **Stable Identity**：Source、URL、Artifact、Document、Version 使用稳定 ID；
14. **Idempotent + Recoverable**：Task 有幂等键、lease、fencing token、checkpoint、Retry、DLQ；
15. **Fair by Default**：大站历史回填不能饿死增量和小站；
16. **Release Everything That Changes Results**：Profile、Route Policy、Recipe、Runtime、Extractor、Renderer、Schema、Filter 都版本化；
17. **Projection Is Rebuildable**：Markdown、全文、向量、Graph 都可从 Canonical Version 重建；
18. **No Silent Fallback for Coverage**：动态能力未执行时必须显式标记 DEGRADED/Known Gap；
19. **Cost Is First-Class**：Browser/LLM/Graph 必须可归因、可预算、可熔断。

## 4. 技术选型与组件边界

### 4.1 控制面

- **FastAPI + Pydantic**：REST API、Command、Schema 校验；
- **PostgreSQL**：Source、Release、Run、Task、Coverage、URL、Classification、Route Decision、Artifact、Extraction、Document、Version、Quality、Cost、Audit、Outbox；
- **Redis Streams**：任务运输、consumer group、backpressure；
- **Redis Lua token bucket/semaphore**：跨 Worker 域名级限流和并发；
- **React/Next.js + TypeScript**：Web 管理台；
- **Prometheus + Grafana + OpenTelemetry**：Metric/Log/Trace；
- **S3/MinIO**：Raw HTML、DOM/MHTML、PDF、Canonical IR、Markdown、附件、诊断文件、导出物；
- **OpenSearch**：全文/BM25；
- **pgvector**：首期向量检索，可通过 Adapter 替换；
- **Docker Compose**：开发/MVP；
- **Kubernetes**：生产 Worker Pool 横向扩展。

### 4.2 Discovery / Fetch

- **httpx/aiohttp**：HTTP、Sitemap、Feed、CMS API、Conditional GET、Cheap HTTP Probe、附件；
- **Crawl4AI**：动态页面、滚动/等待/交互、DOM/媒体/链接获取，通过 Adapter 使用；
- **Playwright**：复杂但确定性的 Browser Recipe；
- **PyMuPDF/pdftotext**：PDF；扫描件才进入 OCR。

### 4.3 Classification / Routing

分类信号按成本从低到高：

- Discovery Provider Hint；
- URL path/pattern；
- MIME / HTTP Header；
- JSON-LD/OpenGraph/Microdata；
- 轻量 DOM heuristic；
- 人工规则；
- 低比例 LLM Exception。

Route Policy 是平台业务配置，Crawl4AI `url_matcher`、`arun_many`、prefetch 等只作为 Adapter 编译目标。

### 4.4 Extraction

- **Trafilatura**：首选 Generic Extractor，支持 precision/balanced/recall 策略；
- **lxml**：高性能 DOM/XPath 解析；
- **BeautifulSoup**：结构化元数据、DOM Repair 和诊断，不作为全站统一正文识别器；
- **JSON-LD/OpenGraph/Microdata**：结构化 Metadata Candidate；
- **CSS/XPath/Regex Recipe**：确定性字段抽取；
- **Crawl4AI raw Markdown/cleaned HTML**：候选/诊断，不直接成为 Canonical。

### 4.5 Crawler 与平台边界

```text
平台负责：
Source/Release / Task / Retry / DLQ / Coverage / Classification /
Routing / Fairness / Global Rate Limit / Budget / Checkpoint /
Quality / Version / Extraction Arbitration / Audit / Projection Semantics

Crawler 负责：
单次请求与导航 / 页面动作 / DOM / 链接 / 媒体 /
浏览器资源管理 / 局部 batch/stream / Adapter 级 matcher
```

生产环境锁定经过 Golden Corpus 验证的 Crawl4AI、Playwright、Chromium、Trafilatura、Classifier、Renderer 和镜像 digest；升级必须经过 Replay、Benchmark、Canary 和 Approval。

## 6. 站点接入与自动 Probe

新增网站只要求：

```text
name + base_url + 可选标签/策略约束
```

系统进入 `PROBING`，自动探测：

1. robots.txt；
2. Sitemap / Sitemap Index / robots 中 Sitemap 声明；
3. RSS/Atom；
4. 常见 CMS API；
5. 首页、archive、category、tag、pagination；
6. JSON-LD/OpenGraph；
7. HTTP 是否直接得到完整正文；
8. 是否必须 Browser；
9. Site Family 指纹；
10. URL pattern、canonical、分页规则、文章样本；
11. Trafilatura precision/balanced/recall 的样本质量；
12. 是否需要 Deterministic/Repair Recipe；
13. ARTICLE/DOC/INDEX/TAG/AUTHOR/ASSET/API 等页面类型样本与 URL/Structured Metadata 分类信号；
14. Cheap Routing 的命中率、UNKNOWN 样本、Browser/LLM 是否真的能带来增益。

Probe 输出 Candidate Source Profile + Route Policy，管理员确认后激活。

### 6.1 Source Profile 示例

```yaml
source:
  base_url: https://example.com
  scope:
    allowed_hosts: [example.com]
    include: [/blog/**, /docs/**]
    exclude: [/search/**]

discovery:
  providers: [sitemap, rss, archive]
  deep_crawl:
    enabled: false

routing:
  page_types:
    article:
      url_patterns: [/blog/**, /posts/**]
      route: http_article
    doc:
      url_patterns: [/docs/**]
      route: http_doc
    index:
      url_patterns: [/tag/**, /category/**, /author/**]
      route: discovery_only
    asset:
      mime: [application/pdf]
      route: asset_pipeline
  unknown:
    route: cheap_probe
    llm_exception: false

fetch:
  mode: http_first
  browser_fallback: true
  concurrency_per_host: 2

extraction:
  portfolio:
    - structured
    - trafilatura
    - deterministic
  trafilatura:
    mode: balanced
    include_comments: false
    include_tables: true
  deterministic_recipe: article-v3
  shadow_sample_rate: 0.01

incremental:
  class: WARM
  verify_known_urls: true
```

Profile 表达业务语义，由 Adapter 编译为 Crawl4AI/Playwright/httpx/Trafilatura 参数。Crawl4AI `url_matcher` 等能力只是编译结果，不是配置真相。

## 7. 历史 URL Discovery 与 Coverage

历史回填必须先建立 URL Inventory，再抓正文。

### 7.1 Provider 优先级

```text
CMS/API
 -> Sitemap
 -> RSS/Atom
 -> Archive/Category/Tag
 -> Static Pagination
 -> Dynamic Listing
 -> Bounded Deep Crawl
 -> Optional Common Crawl Gap Filling
```

每个 Provider 产生 Observation 和 Coverage Evidence。

### 7.2 Sitemap

支持：

- Sitemap Index 递归；
- gzip；
- 多 Sitemap；
- lastmod；
- 大站 checkpoint；
- Scope 过滤；
- Sitemap 与已知 URL 差异比较；
- 子 Sitemap 名称/path 作为 Page Type Hint，但只算分类证据之一。

### 7.3 RSS/Atom

RSS 不作为历史完整性的唯一证明，但适合：

- 高频增量；
- 获取 publish/update 时间；
- 发现 canonical URL；
- 辅助文章类型判断；
- 给 ARTICLE classification 提供高置信 Provider Hint。

### 7.4 Archive / Pagination Recipe

```text
OPEN start_url
EXTRACT article_links
LOOP:
  FIND next_page
  IF absent -> EXHAUSTED
  OPEN next_page
  EXTRACT article_links
  STOP_IF max_pages / duplicate_page_signature / no_new_urls
```

### 7.5 Infinite Scroll / Load More

Browser Discovery Recipe 支持：

- scroll_to_bottom；
- wait_for；
- click_load_more；
- virtual_scroll container；
- N 轮无新 URL 停止；
- 最大动作轮数、最大运行时间、最大 URL 数。

运行时不支持某个语义动作时 Release Compile 失败或 Run 标记 DEGRADED，不允许静默退化成一次普通抓取。

当 Crawl4AI Adapter 支持 prefetch 时，可在 Bounded Deep Crawl/Discovery 阶段仅返回 HTML/links，跳过 Markdown、Extraction 和媒体处理；这只是执行优化，发现结果仍必须落 `url_observation`。

### 7.6 Coverage 页面

展示：

- Provider 状态；
- discovered/new URL；
- 时间跨度；
- cursor/page/range；
- exhaustion evidence；
- Provider 交并差异；
- Known Gap；
- 一键补洞与回放。

## 8. URL 规范化、Scope、去重与页面类型路由

### 8.1 规范化

规则：

- host 小写；
- 去 fragment；
- 默认端口；
- tracking query 去除；
- query 参数排序；
- trailing slash 策略；
- canonical link 作为候选而非盲信；
- redirect chain 记录。

### 8.2 多层去重

1. URL normalization；
2. canonical/redirect identity；
3. artifact sha256；
4. canonical semantic hash；
5. 可选近似正文指纹用于镜像/转载识别。

标题、slug、展示文本不能作为跨阶段唯一主键。

### 8.3 Page Type Classification

分类发生在 Browser、正文 Extraction、LLM 和 Embedding 之前，按成本和确定性依次使用：

```text
Provider Hint
 -> URL Rule
 -> MIME / Header
 -> Structured Metadata
 -> Cheap DOM Heuristic
 -> Manual Override
 -> LLM Exception（低比例、可关闭）
```

典型信号：

- RSS item、CMS post API -> ARTICLE 高置信；
- `/blog/`、`/posts/`、`/docs/` -> ARTICLE/DOC 候选；
- `/tag/`、`/category/`、`/author/` -> INDEX/TAG/AUTHOR；
- `application/pdf` -> ASSET；
- JSON-LD `Article` / `BlogPosting` / `TechArticle` -> ARTICLE；
- `og:type=article`、`article/main/time`、段落密度等 -> DOM/Metadata evidence。

URL Rule 不是散落在 Worker 中的 `if domain == ...`，而是 Route Policy/Source Release 的版本化配置。

### 8.4 Execution Routing

```text
ARTICLE -> HTTP_ARTICLE -> Extraction Portfolio -> Canonical
DOC     -> HTTP_DOC -> Document Extraction -> Canonical
INDEX   -> DISCOVERY_ONLY
TAG     -> DISCOVERY_ONLY
AUTHOR  -> DISCOVERY_ONLY
ASSET   -> ASSET_PIPELINE
API     -> STRUCTURED_API
ERROR   -> REJECT
UNKNOWN -> CHEAP_PROBE -> Reclassify / QUARANTINE
```

原则：

- Index/Tag/Author 页面默认不进入正文知识库；
- UNKNOWN 不直接升级到 Browser/LLM，先做 Cheap HTTP Probe；
- Browser 是 Fetch fallback，不是页面分类器；
- LLM Exception 必须记录模型、prompt/schema、classifier_release、成本和置信度；
- 稳定 Source 应持续降低 UNKNOWN/LLM Exception 比例，但不为追求零 UNKNOWN 牺牲可解释性。

### 8.5 Crawl4AI Adapter 编译

当当前锁定版本支持时，平台可把 Route Policy 编译为：

- `arun_many()` 的多 `CrawlerRunConfig`；
- `url_matcher` 的 pattern/function matcher；
- Discovery 的 prefetch 模式；
- 不同页面类型的 wait/scroll/cache/extraction 参数。

但业务层不保存“某 URL 匹配了 Crawl4AI config #3”作为唯一事实，而保存独立 `url_classification` 与 `route_decision`，以便替换运行时。

## 9. Fetch：HTTP First，Browser Last

### 9.1 HTTP Worker

默认使用 httpx/aiohttp：

- gzip/br；
- redirect；
- timeout；
- response size limit；
- ETag / If-None-Match；
- Last-Modified / If-Modified-Since；
- Content-Type / Charset；
- SSL/错误分类；
- Raw Snapshot 入对象存储。

Cheap Probe 也优先走 HTTP，只抓足够完成 MIME/Structured Metadata/DOM Heuristic 判断的信息，不默认执行完整 Browser/LLM 流程。

### 9.2 Browser Fallback 条件

只在以下情况进入 Browser：

- HTTP HTML 是 shell；
- 正文依赖 JS；
- 确定性点击/滚动后出现正文；
- HTTP Artifact 经过 Extraction Portfolio 后持续低质量，且 Browser Golden Sample 证明可恢复；
- Source Profile 明确指定；
- Route Decision 为 Browser Candidate，且有可解释 evidence。

Browser 与 HTTP 使用独立 Queue/Worker Pool。

### 9.3 Browser Session

Session 只做执行优化。业务 checkpoint 不放在 Session 中；Session 丢失后 Task 必须可重跑。

### 9.4 Browser 资源裁剪

对文本型博客可按 Source Release 配置阻止非必要图片、字体、视频和跟踪资源，以降低 Browser 延迟与内存，但必须通过 Golden Sample 验证，不能阻断正文依赖的 XHR/fetch/script。

### 9.5 阶段级耗时

Browser/HTTP Trace 至少拆分：

```text
DNS / TCP-TLS / TTFB / Body Download /
Browser Acquire / page.goto / DOM Ready /
wait_for / interaction / render serialize
```

避免只记录总 Fetch 时间导致无法判断瓶颈。

### 9.6 Fetch 错误分类

至少区分：

```text
FETCH_NETWORK_ERROR
FETCH_TIMEOUT
FETCH_RATE_LIMITED
FETCH_ACCESS_DENIED
FETCH_BROWSER_CRASH
FETCH_EMPTY_SHELL
FETCH_PERMANENT_NOT_FOUND
```

## 10. 正文抽取：Extraction Portfolio

### 10.1 Structured Candidate

优先读取：

- JSON-LD `articleBody/headline/datePublished/author`；
- OpenGraph；
- Microdata；
- canonical link；
- 页面嵌入的公开结构化状态。

结构化字段只是 Candidate，多个来源冲突时必须记录冲突，不静默覆盖。

### 10.2 Trafilatura Generic Extractor

Trafilatura 是默认 Generic Extractor，按 Source Profile 选择：

```text
PRECISION  -> 噪声风险高的新闻/媒体站
BALANCED   -> 普通技术博客默认
RECALL     -> 文档站、短段落/代码/表格容易漏失的站点
```

统一关闭评论抽取，表格/格式是否保留由 Profile 决定。输出优先进入结构化候选，不直接把第三方 Markdown 当 Canonical。

### 10.3 Deterministic Recipe

高价值或特殊站点可配置：

```yaml
article:
  title: css:h1.article-title
  published_at: css:time::attr(datetime)
  content: css:article.post-content
  remove:
    - css:.newsletter-signup
    - css:.related-posts
    - css:.share-buttons
```

支持 CSS/XPath/Regex，但不允许任意浏览器脚本进入抽取 Recipe。

### 10.4 DOM Repair + Generic

BeautifulSoup/lxml 只用于确定性 DOM 修复：

```yaml
repair:
  remove:
    - .newsletter-box
    - .related-posts
    - nav
    - footer
  unwrap:
    - .syntax-wrapper
```

Repair 后再次运行 Generic Extractor。

禁止大量 `if domain == ...` 逻辑散落在 Python Worker 中；站点差异必须沉淀为版本化 Recipe。

### 10.5 Crawl4AI Markdown

Crawl4AI `raw_markdown`、`fit_markdown` 可用于：

- 诊断；
- candidate 对比；
- RAG 派生层实验。

不得直接写成 Canonical Markdown，尤其 `fit_markdown` 可能经过 Pruning/BM25/LLM 等过滤，会不可逆地丢正文。

### 10.6 逐级回退

普通静态文章：

```text
HTTP Artifact
 -> Structured
 -> Trafilatura Precision/Balanced
 -> Quality PASS ?
      YES -> Canonical Candidate
      NO  -> Deterministic / Repair
 -> 仍失败且疑似 JS shell -> Browser Artifact
 -> 重新运行同一 Extraction Portfolio
```

### 10.7 Shadow Extraction

为了检测静默改版：

- 新 Source：多个 Candidate 全跑；
- ACTIVE 稳定 Source：主 extractor + 1%～5% shadow candidate；
- Drift 告警后临时提高 shadow 比例；
- 新 Release Canary 通过后再恢复低采样。

这样持续获得一致性信号，不必每篇文章全量跑多套抽取器。

### 10.8 LLM 使用边界

LLM 默认不进入 Canonical 正文主链。允许的主要位置：

- Source Probe：分析少量代表样本，提出 URL pattern、selector、repair 建议；
- Rule Generation：生成候选 Route/Extraction/Repair Recipe，必须 Replay/Canary 后才能 ACTIVE；
- Ambiguous Classification：规则无法区分且业务价值足够高的低比例 `LLM_EXCEPTION`；
- Quarantine Triage：解释失败原因；
- Projection：摘要、实体、关系等派生信息。

禁止：

- 每篇文章用 LLM 判断是否为 Blog/Article；
- 每篇文章用 LLM 重写 Canonical Markdown；
- LLM 失败阻塞全站增量；
- 用模型判断替代 Coverage Evidence。

## 11. Candidate Agreement 与仲裁

比较维度：

### 11.1 字段

- title similarity；
- author conflict；
- published_at / updated_at；
- canonical URL；
- language。

### 11.2 正文

- normalized text similarity；
- token/character overlap；
- 段落数量；
- heading 分布；
- code/table/list 保留率；
- 首尾段一致性；
- link density；
- boilerplate score；
- 与历史版本长度/结构偏移。

### 11.3 典型规则

```text
Trafilatura Precision 与 Deterministic 高一致
 -> 高置信 PASS

Precision 明显短，Recall 与 Deterministic 高一致
 -> Recall 更可信

Selector 命中但与 Generic 严重偏离
 -> SELECTOR_DRIFT -> QUARANTINE

所有候选都短且 HTTP 像 shell
 -> Browser fallback

所有候选都包含明显导航/推荐区
 -> DOM Repair 或人工 Recipe
```

Candidate Agreement 本身写入事实层，后续可重放和解释。

## 13. 内容质量 Gate

Quality Gate 综合：

- 标题存在；
- 正文最小有效长度；
- 正文/链接比；
- boilerplate 特征；
- 代码块、表格、列表结构保留率；
- 页面语言一致性；
- Candidate Agreement；
- 与历史版本长度/结构异常偏移；
- 登录墙/错误页/WAF/CAPTCHA 指纹；
- 重复文档比例；
- Classification 与最终内容是否明显冲突，例如 INDEX 被误判为 ARTICLE。

状态：

```text
PASS        可进入 Canonical 和 Projection
WARN        可用但有低风险异常
QUARANTINE  等待自动回放或人工处理
REJECT      明确非文章/错误内容
```

抽取错误至少区分：

```text
EXTRACT_NO_CONTENT
EXTRACT_TOO_SHORT
EXTRACT_TOO_NOISY
EXTRACT_METADATA_CONFLICT
EXTRACT_CANDIDATE_DIVERGED
EXTRACT_SELECTOR_DRIFT
QUALITY_STRUCTURE_LOSS
QUALITY_DUPLICATE_CONTENT
QUALITY_PAGE_TYPE_MISMATCH
```

Web 管理端支持 Raw、Rendered DOM、Classification Evidence、Route Decision、各 Candidate、Canonical IR、Markdown 并排 Diff。

## 14. 增量同步

### 14.1 Freshness 分层

- HOT：高频新闻/资讯源；
- WARM：常规技术博客；
- COLD：长期低频更新站点。

调度权重：

```text
priority = urgency + freshness_class + retry_age + source_weight - estimated_cost
```

### 14.2 增量发现

```text
RSS/API
 -> Sitemap lastmod/diff
 -> Archive first pages
 -> bounded dynamic listing
```

新 URL 必须经过 Normalize -> Classification -> Route；已知 URL 默认复用当前 classification，但 Source Release/Route Policy 变化、redirect、content-type 变化或抽样校验可触发重新分类。

### 14.3 增量事件语义

至少区分：

```text
NEW_URL
KNOWN_URL_UPDATED_HINT
KNOWN_URL_RECHECK
URL_RECLASSIFIED
ROUTE_CHANGED
CONTENT_VERSION_CHANGED
METADATA_CHANGED
REMOVED_OR_MOVED
```

RSS `updated`、Sitemap `lastmod` 是 hint，不直接等于正文新版本。

### 14.4 已知 URL 复检

使用：

- ETag；
- Last-Modified；
- RSS updated；
- Sitemap lastmod；
- 周期性强制抽样 re-fetch。

304 记录 Fetch Attempt，但不创建新正文版本。

### 14.5 版本判定

```text
fetch artifact
 -> extraction portfolio
 -> canonical IR
 -> normalize semantic content
 -> semantic_hash
 -> compare current version
```

- hash 相同：更新 last_checked；
- 正文变化：新建 Version；
- 仅元数据变化：按字段策略记录 metadata change；
- 新 Version PASS 后原子切换 `current_version_id`。

### 14.6 Artifact Hash 与 Content Hash 分离

```text
artifact.sha256          = 页面抓取事实
canonical.semantic_hash  = 正文语义版本
metadata_hash            = 元数据版本
```

推荐区、广告、计数器变化只应影响 Artifact，不应制造正文版本。

### 14.7 删除与迁移

```text
ACTIVE
 -> 404/410 or provider missing
 -> SUSPECT_MISSING
 -> 多次复检 + sitemap/archive evidence
 -> REMOVED
```

301/308 记录 Redirect Relationship，并判断是否属于同一 Document 的 URL 迁移；目标 URL 重新执行 Scope/Classification/Route。

## 16. 检索、向量与 RAG Projection

### 16.1 Chunk 不是事实层

Chunk 由 `document_version_id + chunker_release` 生成，可重建。

按结构切分：

1. heading section；
2. paragraph group；
3. code block 尽量不拆；
4. 超长 section 再递归切分；
5. 每 chunk 保留 source/document/version/heading path。

### 16.2 默认检索链

```text
Query
 -> metadata filter
 -> OpenSearch BM25 recall
 -> pgvector semantic recall
 -> RRF/weighted fusion
 -> reranker
 -> dedup/diversity
 -> evidence context
 -> RAG/搜索结果
```

默认检索必须独立于 GraphRAG。

### 16.3 Projection 与抓取解耦

Embedding、BM25、Graph 都在 Document Version PASS 后通过 Outbox/Queue 异步执行：

- 相同 semantic_hash 不重复向量化；
- Embedding 故障不阻塞抓取和 Canonical；
- 更换 chunker/embedding 模型可从 Version 重建；
- 默认只索引当前 PASS/WARN 版本。

### 16.4 可选 Graph Projection

Graph 只作为 Document Version 之上的可重建增强层：

```text
Canonical Version
  +-> BM25
  +-> Vector
  +-> Graph(optional)
```

仅对明确有多跳、依赖、替代、兼容、跨文档关系价值的 Collection 开启。

要求：

- Schema-guided Entity/Relation；
- Entity Resolution；
- 每条关系可回溯原文 Chunk；
- Candidate Projection + Quality Gate；
- Query Router 按需启用；
- 独立预算与熔断；
- Graph 停止不能影响抓取和默认检索。

## 19. 调度、公平性与容量控制

### 19.1 Global Admission

每次真实网络/Browser 请求前统一检查：

- global concurrency；
- per-domain concurrency；
- request rate；
- Browser slots；
- Source budget；
- robots/policy；
- maintenance window。

Classification 中不需要网络的规则优先本地执行，不占 Browser slot。

### 19.2 Weighted Fair Scheduling

- Incremental 高于 Backfill；
- HOT Freshness 高优先；
- 长等待任务 aging；
- 单 Source 最大并发占比；
- Browser 队列独立公平；
- UNKNOWN/LLM Exception 有独立低配额；
- Projection 不抢占抓取关键资源。

### 19.3 Extraction Capacity

Extraction Portfolio 按场景控制成本：

```text
新 Source      -> 多 Candidate 全跑
稳定 Source    -> 主 Candidate + 低比例 Shadow
Drift Source   -> 临时提高 Shadow
修复 Canary    -> 多 Candidate 回归后再降采样
```

### 19.4 Backpressure

当 Extract/Storage/Search 延迟升高：

- 降低新 Fetch Admission；
- Discovery/Classification 可继续低成本运行，但限制正文 Task 生成；
- Browser 首先降速；
- LLM Exception 可暂停；
- Graph/LLM Projection 可完全暂停。

## 21. 安全与合规

### 21.1 SSRF

每个网络跳转重新校验：

- scheme 仅 http/https；
- DNS 解析；
- 禁止 loopback、link-local、private CIDR、metadata endpoint；
- redirect 后重验；
- Browser iframe/navigation/request 同样执行 egress policy；
- proxy 不能绕过目标校验。

### 21.2 Web 管理

- RBAC：viewer/operator/admin；
- Secret 不回显；
- Recipe 不接受任意 JS/evaluate；
- LLM Exception 不允许生成可直接执行的任意脚本；
- 高风险 Release 激活需要 Approval；
- Audit Log 记录配置与人工操作；
- 导出权限独立控制。

### 21.3 来源策略

每个 Source 记录：

- robots policy；
- crawl delay；
- 登录需求；
- 内容授权/许可证备注；
- 是否允许资产下载；
- 是否允许公开导出。

技术上可访问不等于拥有再分发权，来源与许可元数据必须保留。


优化顺序：

2. Cheap Classification / Routing，尽早排除 INDEX/TAG/AUTHOR/ASSET 等非正文路径；

9. 多 Candidate 通过 Shadow Sampling 控制成本；
10. Projection 只处理 PASS 当前版本；
11. Graph 默认关闭并独立预算。

## 27. 验收标准

### 27.1 历史抓取

- 每个 Source 能显示 URL 从哪个 Provider 发现；
- Provider 有明确 stop reason/exhaustion evidence；
- Known Gap 可见；
- 失败可回放；
- 不以“crawler 结束”代替“Coverage 完成”。

### 27.2 增量

- RSS/Sitemap/API 新文章在目标 Freshness 内入库；
- 新 URL 经过 Classification/Route 后才进入高成本抓取；
- 304 不生成新正文版本；
- 正文修改生成新 Version；
- 页面噪声变化不制造假正文版本；
- 删除需要多证据确认；
- 任务重复执行不产生脏重复。

### 27.3 Routing / Classification

- ARTICLE/DOC/INDEX/TAG/AUTHOR/ASSET/API/UNKNOWN 的分类证据可追溯；
- Index/Tag/Author 默认不进入 Canonical 正文抽取；
- Stable Source 的逐 URL LLM 不是默认依赖，LLM Exception 可单独关闭；
- Route Policy 升级可对历史 URL Replay，不需要重新抓取所有页面；
- 分类漂移、UNKNOWN 激增、LLM Exception 激增可告警；
- Crawl4AI matcher 改变不能无审计地改变业务 page_type；
- Browser avoided、route hit 和 classification cost 可量化。

### 27.4 Extraction

- Crawl4AI Fetch success 与 Extraction success 独立；
- Trafilatura precision/balanced/recall 可按 Source 配置；
- Deterministic selector 漂移能被 Candidate Agreement 或 Shadow Extraction 检出；
- BeautifulSoup/lxml 站点特判通过版本化 Repair Recipe 管理；
- 任意 Extraction Attempt 可回溯到 Artifact 与 extractor_release；
- Extractor 升级可对历史 Artifact Replay，而无需重新请求原站。

### 27.5 Markdown

- 标题/段落/列表/代码/表格结构稳定；
- 菜单、推荐、广告等噪声受控；
- Markdown 可回溯 Canonical IR 与 Artifact；
- Renderer 升级可批量重建；
- Crawl4AI `fit_markdown` 不直接进入 Canonical。

### 27.6 扩展性

- 新 Source 主要通过 Probe/Profile/Family/Route Policy/Recipe 接入；
- 大站 Backfill 不阻塞增量；
- Browser 故障不拖垮 HTTP；
- LLM 服务故障不拖垮 Classification 主链；
- 单个 Extractor 故障可切换候选，不影响事实层；
- Graph/LLM 停止不影响 Canonical 主链。

### 27.7 检索

- 默认 BM25 + Vector + Rerank 有固定离线评测集；
- 可选 Graph 只有在质量、成本与目标问题集收益同时达标后才启用；
- 所有检索证据能追溯到具体 Document Version。

## 28. 最终推荐

系统核心不是选择一个“万能爬虫”，而是构建一个 **以 Coverage、可解释 Classification/Route、不可变 Artifact、多候选 Extraction、Canonical IR、版本、幂等任务、质量与可重建 Projection 为核心的平台**。

推荐主链：

```text
Authoritative Discovery
 -> URL Truth / Coverage Evidence
 -> Normalize / Scope / Dedup
 -> Page Type Classification
      Provider Hint
      + URL Rule
      + MIME
      + Structured Metadata
      + DOM Heuristic
      + LLM Exception (rare)
 -> Execution Route
      ARTICLE/DOC -> HTTP First
      INDEX/TAG/AUTHOR -> Discovery Only
      ASSET -> Asset Pipeline
      API -> Structured Fetch
      UNKNOWN -> Cheap Probe / Quarantine
 -> Browser Fallback（仅有证据时）
 -> Immutable Artifact
 -> Extraction Portfolio
      Structured Metadata
      + Trafilatura Precision/Balanced/Recall
      + Deterministic Recipe
      + DOM Repair
 -> Candidate Agreement
 -> Canonical IR
 -> Quality Gate
 -> Document Version
 -> Canonical Markdown
 -> BM25 / Vector / Export / Optional Graph
```

增量主链：

```text
RSS/API/Sitemap Diff
 + Known URL Verify
 -> Normalize / Reclassify when needed
 -> Route Decision
 -> Conditional GET / HTTP First
 -> Immutable Artifact
 -> Extraction Portfolio
 -> Semantic Version Detection
 -> Atomic Current Version Switch
 -> Rebuild Markdown/Search/Vector Projection
```

组件定位：

```text
Crawl4AI    = Browser/Fetch Adapter + Discovery/Prefetch Optimization + Diagnostic Candidate
Trafilatura = Generic Main-Content Candidate Extractor
lxml/BS4    = Structured Metadata + Cheap DOM Heuristic + DOM Repair + Diagnostic
LLM         = Probe/Rule Generation/Exception/Projection，不是逐 URL 默认主链
Platform    = Coverage / Truth / Classification / Routing / Arbitration / Quality / Version / Markdown
```

这套边界能同时满足 1000 个技术博客的全历史采集、长期增量同步、Markdown 知识库、Web 管理和未来新增站点需求，并能在站点改版、分类器升级、抓取器升级、抽取器升级后通过 Replay/Canary 恢复，而不退化成每站一套不可维护脚本，也不会把 Browser 与 LLM 的高成本线性放大到全部 URL。
