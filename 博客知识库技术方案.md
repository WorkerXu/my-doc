# 博客知识库技术方案

## 1. 建设目标与规模边界

建设一个长期运行、可横向扩展、可审计、可重放的技术博客知识库平台。首期接入约 1000 个技术博客、工程博客、技术文档站和公开 Newsletter，抓取尽可能完整的历史文章并清洗为稳定 Markdown；后续持续增加站点，并支持增量同步、版本追踪、全文/向量检索、Web 管理、质量审计、单 URL 手工摄取、AI 派生分析和离线重处理。

按以下量级设计：

- 1000+ Source，后续扩展到数千站点；
- 百万级 Document；
- 数百万到千万级 URL / Observation；
- 千万级 Chunk / Embedding 长期增长；
- 中英日韩等多语言内容；
- HTML、PDF、TXT、Markdown、JSON/API、RSS/Atom/JSON Feed 等多种资源；
- HTTP 为主，Browser 为受控 fallback；
- 历史发现支持 CMS API、Sitemap、Feed、Archive、Docs TOC、Common Crawl URL Index 等多入口；
- PostgreSQL + Object Storage 保存事实；Markdown、Filtered Markdown、Chunk、Embedding、全文/向量索引、AI Insight、Dashboard Read Model 均为可重建 Projection。

平台必须能够回答：

1. 一个站点理论上有哪些历史文章，为什么认为历史已基本覆盖；
2. 一个 URL 从哪里被发现、如何规范化、经过哪些跳转、最终抓取什么资源；
3. HTML/PDF/Markdown/API 等资源为什么进入某条解析路线；
4. 动态页面执行了哪些点击、滚动、等待，使用哪一版 Recipe；
5. 一个 Markdown 来自哪个 Snapshot、Extractor、Schema、Filter 和 Document Version；
6. 源站变化后哪些内容真的变化，哪些派生物需要重建；
7. Chunk、Embedding、Analyzer、Browser Runtime、Filter、AI Model、Dashboard Metric 和 Index 策略升级后能否离线重放；
8. Worker 崩溃、批任务部分失败、流式消费中断后哪些 URL 已提交、哪些需要重试；
9. 手工提交一个 URL 后，当前处于 Probe、Fetch、Extraction、Markdown、Embedding 还是 Index；
10. “只搜索某站点/某文章/某版本”时，检索作用域是否在召回层被硬性限制；
11. Dashboard 上的趋势数据处理到什么 watermark、覆盖多少 Source、使用哪一版指标公式；
12. AI 情绪/主题/摘要等派生结果用了哪些固定输入、模型、Prompt 和 Schema，失败是否会影响 Source Sync；
13. Web 中执行暂停、重跑、重新分析等操作时，谁发起、用了什么幂等键、是否经过 RBAC、最终结果是什么。

## 2. 核心设计原则

1. **Config First**：普通站点通过 Source / Site Profile / Release 接入，避免修改核心代码。
2. **Coverage First**：历史完整性由 Provider Evidence 与 exhaustion reason 证明，不能用“队列为空”冒充完整。
3. **Discovery Before Fetch**：先低成本发现、分类、去重 URL，再决定是否抓正文。
4. **Authoritative First**：CMS/API/Sitemap/Feed 优先，Archive/Common Crawl 用于补洞和外部证据。
5. **URL Is Locator**：URL 后缀只是弱证据，资源类型由最终响应、MIME、签名和规则综合判断。
6. **HTTP First, Browser Last**：Browser 仅处理动态发现、动态渲染、复杂交互或质量 fallback。
7. **Recipe, Not Site Code**：动态交互和结构化抽取声明式、版本化，避免大量站点特判代码。
8. **Bounded Interaction**：点击、滚动、等待、Session 都有预算和终止条件。
9. **Snapshot First**：先保存不可变网络事实，再抽取、清洗和建版。
10. **IR First, Markdown as Projection**：Canonical IR / Document Version 是内容事实层，Markdown 是可重建输出。
11. **Filtered Content Is Projection**：Pruning、BM25、LLM Filter 都是有损派生，不覆盖 canonical 内容。
12. **LLM Is Projection, Not Truth**：LLM 抽取、摘要、情绪、主题、实体等属于派生能力，失败不阻塞事实同步。
13. **Stable Identity**：Document、Version、Chunk、Embedding、Analysis、Metric、Index 身份稳定且 release-aware。
14. **Release Everything**：影响结果的策略、Recipe、Schema、Probe、Filter、模型、Prompt、指标、索引、Runtime 全部版本化。
15. **Idempotent + Recoverable**：任务具备幂等键、lease、fencing、checkpoint、retry、partial success。
16. **Stream and Commit Per URL**：批任务按单 URL 流式持久化和 ack，一个失败项不能回滚成功项。
17. **Local Dispatcher Is Not Global Scheduler**：Crawl4AI Dispatcher 只保护 Worker，本平台 Scheduler 才是 durable 调度真相。
18. **Async Command API**：抓取、解析、Embedding、AI Analysis、重建等长任务采用 202 + durable ID。
19. **Source Sync 与 AI 解耦**：Embedding、Rerank、LLM、Summary、Dashboard 聚合、Search Index 故障均不能阻塞抓取事实。
20. **Projection Readiness Is Explicit**：Canonical、Markdown、Fulltext、Chunk、Embedding、AI、Vector、Dashboard 状态分别表达。
21. **Evidence Everywhere**：发现、分类、资源探测、跳转、交互、抓取、抽取、身份、版本、检索、分析、聚合均保存证据。
22. **Language-aware Retrieval**：分词、stemming、stopwords、技术 token 由 Analyzer Release 管理。
23. **Hybrid Retrieval by Default**：技术语料默认 BM25 + Vector + RRF，Reranker 是可降级增强层。
24. **Retrieval Scope Is First-Class**：DOCUMENT/SOURCE/VERSION/ACL Scope 必须下推到召回层。
25. **Generation Instead of Destructive Rebuild**：索引升级构建新 Generation、验证、原子切换，禁止 drop-and-recreate。
26. **Web 管理是平台能力**：Coverage、失败、版本、成本、Recipe、Schema、Ingestion、AI、Dashboard、Generation、Release 全部可运营。
27. **Security on Every Hop**：起始 URL、Redirect、Browser navigation 每跳重新执行 SSRF/Egress/Scope 校验。
28. **Ephemeral State Is Not Truth**：Crawler cache、Browser session、Streamlit session、Worker dispatcher state 不承载业务真相。
29. **One Durable Task System**：PostgreSQL durable state + Transactional Outbox + Redis Streams 是唯一业务任务体系。
30. **Ingress-neutral Corpus**：SOURCE_CRAWL、MANUAL_URL、FILE_UPLOAD 只影响摄取路径，不分裂长期知识语料。
31. **Stable Query Target**：URL Scope 先映射内部 Document/Version；Query Plane 不访问远程 URL 判断类型。
32. **Compiled Query Runtime**：Haystack/LlamaIndex/自研 Pipeline 按 Retrieval Release 长生命周期复用，不每请求重建。
33. **Benchmark Before Switch**：Analyzer、Chunk、Embedding、Vector、RRF、Reranker、AI Model、Metric Release 升级均经过固定回归。
34. **Query Never Implicitly Ingests**：未入库 URL 必须走显式 Ingestion Command，读路径不偷偷抓网页。
35. **Dashboard Is Read Model, Not Truth**：Dashboard 默认读取版本化聚合读模型，不能直接把缓存或 websocket 消息当业务状态。
36. **Observation and Command Separation**：图表负责观察，暂停/重抓/删除/切 Release 等操作必须进入强类型 Command API。
37. **Watermark Everywhere**：趋势与运营指标必须显示数据窗口、处理水位、覆盖率和计算时间。
38. **Bounded Metric Cardinality**：Prometheus 等时序指标禁止使用 URL/Document/Task ID 等高基数 label。
39. **Agent Has Least Privilege**：Agent 只通过明确 Tool/API 消费数据和提出操作，不拥有任意数据库写入或无限网页访问能力。

### 3.1 真相边界

```text
PostgreSQL + Object Storage = Truth
Redis Streams              = Transport
OpenSearch / Vector Engine = Rebuildable Projection
Canonical Markdown         = Rebuildable Projection
Filtered/Fit Markdown      = Rebuildable Projection
AI Insight                 = Rebuildable Derived Projection

```

任何决定性业务状态不得只存在 Redis、搜索引擎、向量库、Browser session、Streamlit session、Dashboard 缓存、Agent memory 或 Worker 内存中。

## 4. 技术选型

### 4.1 控制面

- **FastAPI + Pydantic**：REST/Command API、Schema 校验、内部服务接口；
- **PostgreSQL**：Source、Profile、Run、Task、Coverage、Observation、Resolution、Probe、Fetch、Document、Version、Projection、Analysis、Metric、Release、Audit、Outbox；
- **Transactional Outbox**：数据库状态变化与消息发布事务一致；
- **Redis Streams**：consumer group、retry、backpressure，只做任务运输；
- **React/Vue + TypeScript**：生产 Web 管理台；
- **Streamlit**：PoC、研究型内部看板或实验工具，不承载生产长任务状态。

### 4.2 抓取与抽取

- **HTTPX / aiohttp**：HTML、Feed、Sitemap、API、Conditional GET、Range GET、低成本跳转；
- **libmagic/python-magic 等价能力**：文件签名辅助 MIME 判定；
- **BeautifulSoup / lxml / CSS / XPath / Regex**：wrapper、meta refresh、selector、结构化抽取；
- **Trafilatura / Readability**：确定性正文候选；
- **PDF Parser + OCR fallback**：文本型 PDF 优先确定性解析，扫描型才 OCR；
- **Crawl4AI / Playwright**：动态页面、URL Seeding、Prefetch、Browser Interaction、Markdown Candidate、Browser fallback；
- **S3 / MinIO**：raw response、HTML、Rendered DOM、PDF、WARC、Canonical IR、Markdown、Asset、AI Artifact、debug artifact。

### 4.3 历史发现

- CMS API / Sitemap / RSS / Atom / JSON Feed；
- Archive / Category / Tag / Author / Docs TOC；
- Common Crawl URL Index；
- 站点 Search 仅做 gap discovery；
- DuckDB / Athena / Spark / Polars 用于大规模历史索引扫描。

### 4.4 检索与 RAG

- **OpenSearch**：生产 BM25、过滤、聚合、Alias/Generation；
- **pgvector / OpenSearch kNN**：首期向量；
- **Qdrant / Milvus**：规模增长后可替换；
- **RRF**：默认融合；
- **Cross Encoder Reranker**：可选精排服务；
- **Haystack/LlamaIndex**：Query/RAG 编排 Adapter，而非业务状态源。

### 4.5 运营分析与可观测

- **Prometheus + Grafana + OpenTelemetry**：低基数运行指标、告警、Trace；
- **PostgreSQL Materialized/Incremental Read Model**：首期运营聚合；
- 数据量增长后可引入 **ClickHouse** 或等价分析引擎，但仍是可重建 Read Model；
- SSE/WebSocket：Dashboard 数据失效通知；
- Docker/Kubernetes：服务部署与弹性伸缩。

## 8. 新站接入 PROBE

新增站点先 PROBE，不直接深爬：

1. 规范化 entry URL，解析 registrable domain、origin、scope；
2. DNS/SSRF/robots/policy 检查；
3. 探测 Sitemap Index / Sitemap；
4. 探测 RSS / Atom / JSON Feed；
5. 探测 WordPress REST、Ghost、Substack 等平台 API；
6. 识别 Archive、Category/Tag/Author、Blog Index、Docs Navigation、pagination；
7. 低成本查询 Common Crawl；
8. 对 URL path 做模板聚类；
9. 对未知 hub 做轻量 HTML + links Prefetch；
10. 小预算探索未知结构；
11. 抽样比较 HTTP 与 Browser 的正文质量与成本；
12. 检测 wrapper、short-link、meta refresh、JS redirect；
13. 对 HTML/PDF/MD/JSON 等资源做 Resource Probe；
14. 如果只有动态页面能发现历史 URL，生成 Interaction Recipe；
15. 对重复 DOM 生成 Structured Schema 候选并用 fixture 校验；
16. 推断语言、Analyzer、article template；
17. 自动生成 Profile Draft，Web 审核后启用。

## 10. URL Normalization、Classification 与 Resolution

### 10.1 Normalization

规则包括：lowercase host、default port removal、fragment removal、path slash normalization、安全 percent-encoding、query key ordering、tracking param removal、站点 semantic param allowlist。

禁止全局删除所有 query，因为 `?id=123`、`?p=456`、`?page=7` 可能有正文或分页语义。

### 10.2 Classification

```text
ARTICLE_CANDIDATE
DISCOVERY_SURFACE
ASSET
NAVIGATION
EXTERNAL_REFERENCE
IGNORE_BY_POLICY
UNKNOWN
```

过滤只影响调度，原始 Observation 与 Evidence 永久保留。

### 10.3 Resolution Plane

```text
Observed URL
 -> Normalized Candidate
 -> HTTP Redirect
 -> Wrapper Param / HTML Target
 -> Meta Refresh
 -> Browser Navigation Fallback
 -> Resolved Fetch Target
```

`rel=canonical`、`og:url` 属于 Identity Evidence，不等同 Redirect。

`url_resolution_observation`：

```text
input_url_id
resolver_release_id
resolver_method
hop_chain
resolved_url
resolved_url_hash
cross_origin_hops
confidence
evidence_ref
outcome_code
observed_at
```

每一跳重新执行 DNS/IP/SSRF/Admission/domain scope。解析结果变化追加 Observation，禁止覆盖历史。

## 12. Fetch Route Policy

默认：

```text
HTTP_STATIC
 -> HTTP_ALT_HEADERS
 -> HTTP_PLATFORM_API
 -> FILE_STREAM_FETCH
 -> BROWSER_CRAWL4AI_RECIPE
 -> BROWSER_PLAYWRIGHT_CUSTOM
 -> SITE_CUSTOM_EXTRACTOR
```

资源类型进一步选择：

```text
HTML  -> HTML extractor chain
PDF   -> PDF parser -> OCR fallback
JSON  -> schema/API extractor
Feed  -> feed parser
MD/TXT -> deterministic text parser
```

Browser 不与 API 服务共享 Playwright event loop，独立 Worker 部署。

`fetch_attempt` 至少记录：route、status、etag、last_modified、response_bytes、latency、browser_seconds、snapshot_id、outcome_code。

Proxy 作为批准过的路由参数管理，不用于绕过明确访问控制。

## 16. Document Identity 与版本

Document Identity 综合：

- 平台稳定 ID；
- canonical/og:url；
- Redirect Evidence；
- 平台 article ID / Feed GUID；

## 17. 增量同步与 Reconcile

信号优先级：

```text
Feed/API cursor
 -> Sitemap lastmod
 -> High-yield Surface
 -> Conditional GET
 -> Metadata/Resource Probe
 -> Full HTTP
 -> Browser fallback
```

保存 ETag、Last-Modified、previous_body_hash、content_length、content_kind。

304：不创建 body Snapshot 副本、不抽取、不建新 Version、不重复 Projection。

调度分层：

```text
Tier 0 Feed/API            分钟级
Tier 1 Sitemap/Blog Index  10~60 分钟
Tier 2 Category/Archive    1~6 小时
Tier 3 Deep Reconcile      每周/每月
Tier 4 Common Crawl        新 collection 或按月
```

Feed/API 使用 overlap window，避免迟到数据、时钟漂移和排序变化导致漏项。

即使已有 Feed，也周期 Reconcile Sitemap、Archive、Surface、Common Crawl，用于发现 Feed 窗口外遗漏、URL 迁移、删除和结构漂移。

## 32. 安全与合规

- 遵守 robots 与站点访问策略；
- 不绕过登录、付费墙、验证码、WAF 或明确访问控制；
- 默认仅允许 http/https；
- 起始 URL、redirect、Browser navigation 每跳执行 DNS/IP/Egress 校验；
- 阻止 private、loopback、link-local、metadata 目标；
- DNS rebind 风险下连接前后校验；
- 限制 redirect、响应大小、PDF/附件大小、解压比、Browser wall-clock、OCR 页数；
- 禁止 `file://`、`gopher://` 等非允许 scheme；
- Browser Worker 独立网络、CPU、内存、wall-clock；
- Secret 进入 Secret Manager；
- 文件上传做 MIME/签名校验和恶意内容隔离；
- Query Plane 原则上不访问公共互联网；
- Agent/Analysis Worker 默认只访问内部只读内容 API、模型服务和必要对象存储；
- Agent 生成 SQL 必须走受限 Analytics Query API/semantic layer；
- 所有高风险管理操作走 RBAC、强类型 Command 和 Audit。

## 33. 存储、分区与生命周期

PostgreSQL 保存 metadata、state、hash、ref，不保存大 body。

高增长表按时间/source hash 分区：

- URL Observation；
- Probe/Fetch/Interaction Attempt；
- Task；
- Audit；
- Retrieval Trace；
- AI Analysis Record；
- Ops Metric Point。

Object Storage 保存：raw response、HTML、Rendered DOM、Feed、PDF、WARC、Canonical IR、Canonical Markdown、Filtered Markdown、Asset、AI raw output、fixture、debug artifact。

推荐对象 Key：

```text
snapshot/{snapshot_id}/body
rendered/{snapshot_id}/dom.html
ir/{document_version_id}/{ir_release_id}.json
markdown/{document_version_id}/{markdown_release_id}.md
filtered/{document_version_id}/{content_filter_release_id}.md
analysis/{document_version_id}/{analysis_release_id}/{manifest_hash}.json
```

Search/Vector/Dashboard Read Model 均可从事实层重建。

## 36. 测试、Replay 与发布门禁

### 36.1 Crawl / Adapter Contract

- Crawl4AI/HTTP/Browser 输入输出 Schema；
- redirect/MIME/timeout/error；
- `arun_many(stream=True)` partial success；
- Runtime 升级兼容。

### 36.2 Coverage

- Sitemap Index exhaustion；
- API cursor exhaustion；
- Archive pagination；
- known gap；
- Budget exceeded 不得 COMPLETE。

### 36.3 Snapshot Replay

新 Extractor/Quality/Markdown/Filter 在旧 Snapshot 上重放，不访问源站。

### 36.4 Resource Probe

- 无扩展名 PDF；
- `.pdf` 302 HTML；
- 错误 Content-Type；
- HEAD 405 fallback；
- 超大文件；
- 文件签名冲突。

### 36.5 Idempotency / Crash Recovery

- 重复 Command/message 不重复 Version；
- Worker 在各阶段退出后 lease 恢复；
- fencing 阻止旧 Worker 覆盖结果；
- batch partial success 不丢失。

### 36.6 Chunk / Embedding

- Chunk ID 稳定；
- 未变化 Chunk 不重算 Embedding；
- OOM 缩 batch；
- 向量维度/NaN/Inf 写前拦截。

### 36.7 Retrieval

固定 judgment set 覆盖中英文、技术 token、同义词、长问题、HTML/PDF/MD、SOURCE/DOCUMENT/VERSION/URL Scope。

指标：Recall@K、MRR、nDCG、HitRate、ScopeLeakRate、Latency、Index Size、Cost。

`ScopeLeakRate` 必须接近 0。

### 36.8 AI Analysis Replay

同一 Document Version 使用不同 Analysis/Model/Prompt/Filter Release 重放：

- 不访问源站；
- 结果可并存；
- 可计算 release drift；
- AI 失败不改变 canonical readiness。

### 36.9 Ops Analytics / Dashboard

1. **Watermark Test**：聚合 Worker 落后时 UI 明确显示旧水位；
2. **Consistency Test**：随机 Source 的 Read Model 与事实表离线重算一致；
3. **High-cardinality Test**：百万 URL 不导致 Prometheus series 线性爆炸；
4. **UI Rerun Test**：重复刷新页面不触发 Crawl/LLM/Embedding；
5. **Command Audit Test**：Dashboard 操作必须有 requester、RBAC、idempotency、Audit；
6. **Analysis Coverage Test**：AI Insight 图表同时展示样本覆盖率；
7. **Metric Release Test**：指标公式变化创建新 Release，不静默改变历史语义。

### 36.10 发布流程

```text
fixture/offline replay
 -> benchmark
 -> shadow
 -> canary sources
 -> observe
 -> staged rollout
 -> active
```

Quality/Coverage/Scope/Cost/Metric consistency 回归时停止扩大范围并回滚。

## 38. 验收标准

### 38.1 Coverage

- 每个 Source 有可解释 Provider；
- FULL_BACKFILL 有 exhaustion evidence；
- known gap 可枚举、可重跑；
- 达到预算不会错误标 COMPLETE；
- Common Crawl 不作为完整性证明。

### 38.2 增量

- Feed/API/Sitemap 新文章在目标 SLA 内进入系统；
- 304 不重复抽取、建版、投影；
- 文件未变化不重复解析；
- Reconcile 能发现 Feed 窗口外遗漏和结构漂移。

### 38.3 Browser / Batch

- Browser 不是默认路线；
- Dynamic Discovery 与正文抓取可分离；
- Recipe 版本化、可 diff、回滚；
- Interaction 有预算；
- 批处理结果按 URL 独立提交；
- Worker 退出后未 ack task 可恢复。

### 38.4 Schema / Markdown / Filter

- Schema 有 fixture、required field、zero-match 告警；
- 正文、heading、code/list/table/image/link 有质量验证；
- Markdown 可从 IR 确定性重建；
- query-dependent fit Markdown 不作为 canonical；
- LLM Extraction 失败不影响 canonical。

### 38.5 Manual Ingestion

- `POST /ingestions` 返回 202 + durable ID；
- 相同 Idempotency-Key 不重复创建 Run；
- Web 展示单 URL 全链路状态；
- Manual URL 同样执行 SSRF/robots/大小预算；
- canonical READY、Embedding PENDING 时可 PARTIAL_READY。

### 38.6 Chunk / Embedding

- HTML/PDF/MD/TXT 使用统一 Chunk Release；
- Chunk ID 不依赖 chunk_index；
- RECHUNK/REEMBED 不重新抓源站；
- Embedding backlog 不影响 Source Sync；
- 单条坏向量不导致整批回滚。

### 38.7 Retrieval

- 中英文/技术 token 有固定回归集；
- BM25 + Vector + RRF 可解释；
- DOCUMENT/SOURCE/VERSION/ACL Scope 不召回范围外 Chunk；
- URL Scope 通过内部 Alias，不访问远程 URL；
- HTML/PDF/Markdown 可在统一 Corpus 跨资源召回；
- 新 Generation 验证通过后才能 ACTIVE。

### 38.8 AI Insight

- AI Analysis 与 Document Version/Manifest/Model/Prompt Release 可追踪；
- 同一输入可离线重放；
- Model/Prompt 升级不会创建正文 Version；
- AI 故障不阻塞 Source Sync；
- Dashboard AI 趋势展示 analysis coverage 和 release；
- 近重复文章不会被无意重复加权。

### 38.9 Dashboard / Ops Analytics

- Fleet Overview 不实时扫描全部高增长事实表；
- 每个趋势图显示 window、watermark、computed_at、coverage；
- Read Model 可从 Truth Store 重建；
- UI 刷新不触发 Crawl/LLM；
- Prometheus 无 URL/Document/Task 高基数 label；
- SSE/WebSocket 断开不会丢业务状态；
- Dashboard Command 全部经过幂等、RBAC、Audit；
- Metric/Dashboard Release 可 diff、canary、回滚。

### 38.10 可靠性与安全

- Worker crash 后 lease 可恢复；
- fencing 防止旧 Worker 覆盖；
- fan-out 保留 partial success；
- Embedding/Index/Reranker/AI/Analytics 故障不阻塞 Source Sync；
- Query Plane 无任意公网 URL 访问权限；
- Agent 不拥有任意数据库写权限；
- Runtime/Model/Metric Artifact 可复现、可回滚。

## 39. 最终架构原则

1. Coverage First：先证明“应该有哪些 URL”，再看抓取成功率。
2. Discovery Before Fetch：发现、分类、去重后再抓正文。
3. Authoritative First：权威来源优先，Archive/Common Crawl 只补洞。
4. URL Is Locator：资源类型由实际响应证据决定。
5. HTTP First, Browser Last：Browser 是昂贵兼容层，不是默认抓取器。
6. Recipe, Not Site Code：动态交互版本化、可测试、可回滚。
7. Stream and Commit Per URL：批任务单 URL 提交，partial success 不丢失。
8. Snapshot First, Replay Later：原始网络事实不可变，规则升级优先离线重放。
9. IR First, Markdown as Projection：Markdown 可重建，不是真相源。
10. Filtered Content Is Derived：有损过滤不覆盖 canonical。
11. LLM Is Projection, Not Truth：AI 失败不阻塞事实同步。
12. Analysis Manifest First：AI 分析固定输入、模型、Prompt、Schema，结果可重放。
13. Unified Chunk Release：不同资源解析后进入统一检索契约。
14. Stable Chunk Identity：Chunk 身份不依赖 file path + chunk_index。
15. Streaming Embedding：批次、lease、checkpoint、幂等，不全库一次性加载。
16. Validate Before Vector Write：向量写入前校验维度、数值和 Release。
17. Language-aware BM25：生产全文检索使用版本化 Analyzer。
18. Hybrid Retrieval by Default：BM25 与 Vector 互补，RRF 为稳定基线。
19. Ingress-neutral Corpus：HTML/PDF/MD/TXT 不因输入形态分裂长期 Collection。
20. Stable Query Target：URL Scope 映射内部 Document/Version，Query 不探测远程 URL。
21. Hard Scope Filter：Scope 在召回层强制执行。
22. Query Never Implicitly Ingests：读路径不偷偷访问公网或写索引。
23. Compiled Query Runtime：Query Pipeline 与客户端按 Release 长驻复用。
24. Generation Instead of Destructive Rebuild：后台构建、验证、原子切换。
25. Async Command API：长任务使用 durable command，前台只查状态。
26. Projection Readiness Is Explicit：允许 canonical READY、AI/Embedding PENDING。
27. One Durable Task System：PostgreSQL + Outbox + Redis Streams 维护唯一任务真相。
28. Dashboard Is Read Model：运营 UI 消费可重建聚合，不把缓存当真相。
29. Watermark Everywhere：趋势必须能解释数据处理到哪里、覆盖多少。
30. Observation and Command Separation：图表只观察，高风险操作统一强类型 Command。
31. Bounded Metric Cardinality：监控系统不承载 URL/Document 级高基数维度。
32. SSE/WebSocket Is Notification Only：事件丢失可通过 API/Read Model 恢复。
33. Agent Has Least Privilege：Agent 只通过受控 Tool/API 读取与提出操作。
34. Release Everything：策略、Recipe、Schema、Filter、模型、Prompt、Metric、Dashboard、Index、Runtime 全部可追踪和回滚。
35. Benchmark Before Switch：任何影响内容、检索、分析或运营指标的升级都经过固定回归集。
36. Source Sync 与 AI/Analytics 解耦：事实同步不依赖 Embedding、Reranker、LLM、Dashboard 或 Search 服务。
37. Evidence Everywhere：所有重要判断和聚合都保存来源、Release、watermark 与 lineage。
38. Web 管理是平台能力：Coverage、质量、Probe、Recipe、Ingestion、AI、成本、Scope、Generation、Runtime 和 Release 都可运营。
