# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站与公开 Newsletter** 的长期知识库采集平台，并可平滑扩展到数千站点、百万级文章。

系统必须满足：

1. **全历史尽量抓全**：不仅抓页面，还能说明 URL 从哪个 Provider 发现、哪些 Provider 已穷尽、哪里存在 Known Gap；
2. **持续增量同步**：发现新文章、正文修改、元数据变化、URL 迁移、删除与重发布；
3. **稳定产出 Markdown**：HTML、动态页面、PDF 等先转换为可追溯 Canonical IR，再由统一 Renderer 生成 Markdown；
4. **新增站点低成本**：通过 Site Family、Source Profile、Discovery Recipe、Route Policy、Extraction Recipe、Extraction Portfolio 复用能力，不为每个站长期维护独立爬虫；
5. **Web 可管理**：支持接入、Probe、配置、调度、Coverage、分类、路由、慢路径、质量、回放、版本、成本、导出和告警；
6. **可审计、可重建**：任意 Markdown 都能回溯 URL、分类证据、Route Decision、Artifact、抽取器、Source Release、质量判定和运行记录；
7. **幂等可恢复**：任务可重试、续跑、回放，不产生脏重复；
8. **抓取运行时可替换**：httpx、Crawl4AI、Playwright 都是 Adapter，不是业务真相；
9. **正文抽取可替换**：Trafilatura、确定性 selector、DOM Repair、Crawl4AI Markdown 都只是 Candidate 生成器；
10. **成本可治理**：Authoritative Discovery、Cheap Routing、HTTP First、Browser Last，高成本 LLM/Graph 默认不进入关键抓取路径；
11. **高成本步骤前置分流**：Browser、LLM、正文抽取和 Embedding 之前完成可解释的 Page Type Classification 与 Execution Routing；
12. **慢路径必须证明收益**：HTTP -> Browser、规则 -> LLM Exception 等升级持续记录恢复率、质量增益、延迟和成本，低收益可按 Source 熔断，但不得静默降低质量标准。

### 1.1 核心 SLO

- **Coverage**：历史 URL 覆盖、Provider exhaustion evidence、Known Gap；
- **Freshness**：文章发布到进入 PASS Canonical Markdown 的延迟；
- **Routing Efficiency**：ARTICLE/DOC/INDEX/ASSET/UNKNOWN 分类准确性、UNKNOWN 比例、Browser avoided、LLM Exception 比例；
- **Fallback Efficiency**：Browser/LLM fallback recovery rate、quality delta、p95 latency、cost per recovered document；
- **Extraction Correctness**：正文完整率、噪声率、结构正确率、Candidate Agreement；
- **Reliability**：Task 成功率、Retry/DLQ、Queue Age、Worker 恢复率；
- **Cost**：每 Source、每 1000 个 PASS 文档、每 accepted version 的网络/CPU/Browser/LLM/存储成本；
- **Traceability**：结果能回溯不可变事实与版本化执行环境；
- **Retrieval Quality**：BM25/Vector/Rerank/可选 Graph 的 Recall、nDCG、引用命中率与查询成本。

### 1.2 非目标

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不用 LLM 主观判断替代 Coverage 证明；
- 不把 Redis、Browser Session、Crawler Cache/Frontier 当业务真相；
- 不把 Crawl4AI `fit_markdown`、LLM 摘要或改写直接作为 Canonical Markdown；
- 不因为 URL 曾抓取过就永久停止复检；
- 不把 HTTP 200、Crawler success、DOM 长度直接等同于“正文正确”或“历史抓全”；
- 不允许模板升级后无审计地改变全部生产 Source；
- 不默认对全部文档构建 GraphRAG；
- 不默认逐 URL 调用 LLM 判断页面类型、选择爬虫配置或抽取正文；
- 不因 Browser/LLM 熔断而把未通过 Quality Gate 的 Candidate 静默标记为 PASS。

## 2. 核心设计原则

1. **Coverage First**：先证明“有哪些文章”，再批量抓正文；
2. **Authoritative First**：CMS/API、Sitemap、RSS/Atom、Archive 优先，动态列表和受限 Deep Crawl 补洞；
3. **Discovery Before Fetch**：URL 发现、规范化、Scope、去重、分类与正文抓取分离；
4. **Cheap Routing Before Expensive Execution**：Provider Hint、URL Rule、MIME、Structured Metadata、DOM Heuristic 优先，Browser/LLM 最后；
5. **HTTP First, Browser Last**：静态 HTTP 优先，只有有证据时进入浏览器；
6. **Slow Path Isolated**：Browser、LLM Exception、Graph 使用独立 Queue/Pool/Budget，不能拖垮 HTTP 主链；
7. **Fallback Must Earn Its Cost**：慢路径持续比较 quality gain、recovery rate、latency、cost；
8. **Snapshot First**：先保存不可变抓取事实，再抽取；
9. **Fetch != Extract != Quality**：页面获取成功、正文抽取成功、质量通过是不同状态；
10. **Extractor Is Candidate Generator**：任何抽取器只生成 Candidate；
11. **Agreement Before Trust**：重要内容通过多 Candidate 一致性或可解释质量证据确认；
12. **IR First, Markdown as Projection**：Canonical IR 是正文结构事实，Markdown 可重建；
13. **Quality Is First-Class**：质量状态和网络状态分离；
14. **Recipe, Not Site Code**：分页、滚动、点击、分类、清洗、selector 用版本化 Recipe/Policy 表达；
15. **Stable Identity**：Source、URL、Artifact、Document、Version 使用稳定 ID；
16. **Idempotent + Recoverable**：Task 有幂等键、lease、fencing token、checkpoint、Retry、DLQ；
17. **Fair by Default**：大站历史回填不能饿死增量和小站；
18. **Release Everything That Changes Results**：Profile、Route Policy、Recipe、Runtime、Extractor、Renderer、Schema、Filter 都版本化；
19. **Projection Is Rebuildable**：Markdown、全文、向量、Graph 都可从 Canonical Version 重建；
20. **No Silent Fallback for Coverage/Quality**：能力未执行、慢路径熔断或预算耗尽时必须显式 DEGRADED/QUARANTINE/Known Gap；
21. **Cost Is First-Class**：Browser/LLM/Graph 必须可归因、可预算、可熔断。

## 4. 技术选型与组件边界

### 4.1 控制面

- **FastAPI + Pydantic**：REST API、Command、Schema 校验；
- **PostgreSQL**：Source、Release、Run、Task、Coverage、URL、Classification、Route、Fallback、Artifact、Extraction、Document、Version、Quality、Cost、Audit、Outbox；
- **Redis Streams**：任务运输、consumer group、backpressure；
- **Redis Lua token bucket/semaphore**：跨 Worker 域名级限流和并发；
- **React/Next.js + TypeScript**：Web 管理台；
- **Prometheus + Grafana + OpenTelemetry**：Metric/Log/Trace；
- **S3/MinIO**：Raw HTML、Rendered DOM/MHTML、PDF、Canonical IR、Markdown、附件、诊断文件、导出物；
- **OpenSearch**：全文/BM25；
- **pgvector**：首期向量检索，可通过 Adapter 替换；
- **Docker Compose**：开发/MVP；
- **Kubernetes**：生产 Worker Pool 横向扩展。

### 4.2 Discovery / Fetch

- **httpx/aiohttp**：HTTP、Sitemap、Feed、CMS API、Conditional GET、Cheap HTTP Probe、附件；
- **Crawl4AI**：动态页面、滚动/等待/交互、DOM/媒体/链接获取，通过 Adapter 使用；
- **Playwright**：复杂但确定性的 Browser Recipe；
- **PyMuPDF/pdftotext**：PDF；扫描件才进入 OCR。

### 4.3 Classification / Routing

分类信号按成本从低到高：

- Discovery Provider Hint；
- URL path/pattern；
- MIME / HTTP Header；
- JSON-LD/OpenGraph/Microdata；
- Cheap DOM heuristic；
- Manual Override；
- 低比例 LLM Exception。

Route Policy 是平台业务配置；Crawl4AI `url_matcher`、`arun_many`、prefetch 等只作为 Adapter 编译目标。

### 4.4 Extraction

- **Trafilatura**：默认 Generic Extractor，支持 precision/balanced/recall；
- **lxml**：高性能 DOM/XPath；
- **BeautifulSoup**：Structured Metadata、DOM Repair、诊断；
- **JSON-LD/OpenGraph/Microdata**：Metadata Candidate；
- **CSS/XPath/Regex Recipe**：确定性字段抽取；
- **Crawl4AI raw Markdown/cleaned HTML**：Candidate/诊断，不直接成为 Canonical。

### 4.5 Crawler 与平台边界

```text
平台负责：
Source/Release / Task / Retry / DLQ / Coverage / Classification /
Routing / Fallback Governance / Fairness / Global Rate Limit /
Budget / Checkpoint / Quality / Version / Arbitration / Audit / Projection Semantics

Crawler 负责：
单次请求与导航 / 页面动作 / DOM / 链接 / 媒体 /
浏览器资源管理 / 局部 batch/stream / Adapter 级 matcher
```

生产环境锁定经过 Golden Corpus 验证的 Crawl4AI、Playwright、Chromium、Trafilatura、Classifier、Renderer 和镜像 digest；升级必须经过 Replay、Benchmark、Canary、Approval。

## 6. 站点接入与自动 Probe

新增网站只要求：

```text
name + base_url + 可选标签/策略约束
```

系统进入 `PROBING`，自动探测：

1. robots.txt；
2. Sitemap / Sitemap Index / robots 中 Sitemap 声明；
3. RSS/Atom；
4. 常见 CMS API；
5. 首页、Archive、Category、Tag、Pagination；
6. JSON-LD/OpenGraph/Microdata；
7. HTTP 是否直接得到完整正文；
8. 是否必须 Browser；
9. Site Family 指纹；
10. URL pattern、canonical、分页规则、文章样本；
11. Trafilatura precision/balanced/recall 样本质量；
12. 是否需要 Deterministic/Repair Recipe；
13. ARTICLE/DOC/INDEX/TAG/AUTHOR/ASSET/API 等页面类型样本；
14. Cheap Routing 命中率、UNKNOWN 样本；
15. Browser fallback 对低质量 HTTP Candidate 的 recovery rate 与 quality gain；
16. LLM Exception 是否真的有信息增益。

Probe 输出 Candidate Source Profile + Route/Fallback Policy，管理员确认后激活。

### 6.1 Source Profile 示例

```yaml
source:
  base_url: https://example.com
  scope:
    allowed_hosts: [example.com]
    include: [/blog/**, /docs/**]
    exclude: [/search/**]

discovery:
  providers: [sitemap, rss, archive]
  deep_crawl:
    enabled: false

routing:
  page_types:
    article:
      url_patterns: [/blog/**, /posts/**]
      route: http_article
    doc:
      url_patterns: [/docs/**]
      route: http_doc
    index:
      url_patterns: [/tag/**, /category/**, /author/**]
      route: discovery_only
    asset:
      mime: [application/pdf]
      route: asset_pipeline
  unknown:
    route: cheap_probe
    llm_exception: false

fetch:
  mode: http_first
  browser_fallback: true
  concurrency_per_host: 2

fallback:
  browser:
    queue: slow_browser
    max_share: 0.10
    timeout_ms: 20000
    circuit_breaker:
      min_samples: 20
      min_recovery_rate: 0.20
  llm_exception:
    queue: slow_llm
    max_share: 0.01

extraction:
  portfolio: [structured, trafilatura, deterministic]
  trafilatura:
    mode: balanced
    include_comments: false
    include_tables: true
  deterministic_recipe: article-v3
  shadow_sample_rate: 0.01

incremental:
  class: WARM
  verify_known_urls: true
```

示例阈值不是全局固定值，最终由 Site Family/Source Probe/Canary 校准。

## 7. 历史 URL Discovery 与 Coverage

历史回填必须先建立 URL Inventory，再抓正文。

### 7.1 Provider 优先级

```text
CMS/API
 -> Sitemap / Sitemap Index
 -> RSS/Atom
 -> Archive/Category/Tag
 -> Static Pagination
 -> Dynamic Listing
 -> Bounded Deep Crawl
 -> Optional Common Crawl / Archive Gap Filling
```

### 7.2 Sitemap

支持：

- Sitemap Index 递归；
- gzip；
- 多 Sitemap；
- lastmod；
- 大站 checkpoint；
- Scope 过滤；
- Sitemap 与已知 URL 差异；
- 子 Sitemap 名/path 作为 Page Type Hint，但只算分类证据之一。

### 7.3 RSS/Atom

RSS 不作为历史完整性的唯一证明，但适合：

- 高频增量；
- 获取 publish/update 时间；
- 发现 canonical URL；
- 给 ARTICLE Classification 提供高置信 Provider Hint。

### 7.4 Archive / Pagination Recipe

```text
OPEN start_url
EXTRACT article_links
LOOP:
  FIND next_page
  IF absent -> EXHAUSTED
  OPEN next_page
  EXTRACT article_links
  STOP_IF max_pages / duplicate_page_signature / no_new_urls
```

### 7.5 Infinite Scroll / Load More

Browser Discovery Recipe 支持：

- scroll_to_bottom；
- wait_for；
- click_load_more；
- virtual_scroll container；
- N 轮无新 URL 停止；
- 最大动作轮数、最大运行时间、最大 URL 数。

运行时不支持某语义动作时 Release Compile 失败或 Run 标记 DEGRADED，不允许静默退化成一次普通抓取。

当锁定的 Crawl4AI Release 支持 prefetch 时，可在 Discovery 阶段只返回 HTML/links，跳过 Markdown、Extraction、媒体处理；发现结果仍必须写 `url_observation`。

### 7.6 Coverage 页面

展示：

- Provider 状态；
- discovered/new URL；
- 时间跨度；
- cursor/page/range；
- exhaustion evidence；
- Provider 交并差异；
- Known Gap；
- 一键补洞与回放。

## 8. URL 规范化、Scope、去重、分类与路由

### 8.1 规范化

- host 小写；
- 去 fragment；
- 默认端口；
- tracking query 去除；
- query 参数排序；
- trailing slash 策略；
- canonical link 作为 Identity Candidate，不盲信；
- redirect chain 记录。

### 8.2 多层去重

1. URL normalization；
2. canonical/redirect identity；
3. artifact sha256；
4. canonical semantic hash；
5. 可选近似正文指纹用于镜像/转载识别。

标题、slug、展示文本不能作为跨阶段唯一主键。

### 8.3 Page Type Classification

分类发生在 Browser、正文 Extraction、LLM 和 Embedding 之前：

```text
Provider Hint
 -> URL Rule
 -> MIME / Header
 -> Structured Metadata
 -> Cheap DOM Heuristic
 -> Manual Override
 -> LLM Exception（低比例、可关闭）
```

典型信号：

- RSS item、CMS post API -> ARTICLE 高置信；
- `/blog/`、`/posts/`、`/docs/` -> ARTICLE/DOC 候选；
- `/tag/`、`/category/`、`/author/` -> INDEX/TAG/AUTHOR；
- `application/pdf` -> ASSET；
- JSON-LD `Article/BlogPosting/TechArticle` -> ARTICLE；
- `og:type=article`、`article/main/time`、段落密度 -> Metadata/DOM Evidence。

URL Rule 必须属于 Route Policy/Source Release，不能散落在 Worker 的 `if domain == ...` 中。

### 8.4 Execution Routing

```text
ARTICLE -> HTTP_ARTICLE -> Extraction Portfolio -> Canonical
DOC     -> HTTP_DOC -> Document Extraction -> Canonical
INDEX   -> DISCOVERY_ONLY
TAG     -> DISCOVERY_ONLY
AUTHOR  -> DISCOVERY_ONLY
ASSET   -> ASSET_PIPELINE
API     -> STRUCTURED_API
ERROR   -> REJECT
UNKNOWN -> CHEAP_PROBE -> Reclassify / QUARANTINE
```

原则：

- Index/Tag/Author 默认不进入正文知识库；
- UNKNOWN 不直接升级 Browser/LLM，先 Cheap HTTP Probe；
- Browser 是 Fetch fallback，不是页面分类器；
- LLM Exception 记录模型、prompt/schema、release、成本和置信度；
- 稳定 Source 应持续降低 UNKNOWN/LLM Exception 比例，但不为追求零 UNKNOWN 牺牲可解释性。

### 8.5 Crawl4AI Adapter 编译

当锁定版本支持时，Route Policy 可编译为：

- `arun_many()` 多 `CrawlerRunConfig`；
- `url_matcher` pattern/function；
- Discovery prefetch；
- 不同页面类型的 wait/scroll/cache/extraction 参数。

业务层保存独立 `url_classification` 与 `route_decision`，不能只保存“命中了 Crawl4AI config #3”。

## 9. Fetch：HTTP First，Browser Last

### 9.1 HTTP Worker

默认使用 httpx/aiohttp：

- gzip/br；
- redirect；
- timeout；
- response size limit；
- ETag / If-None-Match；
- Last-Modified / If-Modified-Since；
- Content-Type / Charset；
- SSL/错误分类；
- Raw Snapshot 入对象存储。

Cheap Probe 也优先 HTTP，只抓足够完成 MIME/Metadata/DOM Heuristic 判断的信息。

### 9.2 Browser Fallback 条件

只有以下情况进入 Browser：

- HTTP HTML 是 shell；
- 正文依赖 JS；
- 确定性点击/滚动后出现正文；
- HTTP Artifact 经 Extraction Portfolio 后低质量，且 Probe/Golden Sample 证明 Browser 可恢复；
- Source Profile 明确指定；
- Route Decision 为 Browser Candidate 且有可解释 evidence。

Browser 与 HTTP 使用独立 Queue/Worker Pool。

### 9.3 Browser Readiness 与资源控制

- Session 只做执行优化，业务 checkpoint 不放在 Session；
- 可阻止非必要图片、字体、视频和跟踪资源，但必须 Golden 验证；
- 正文就绪优先通过 selector、最小有效正文、DOM/text quiet window、关键响应等条件判断；
- 固定 sleep、全局 networkidle、单一 load event 不能作为所有站点唯一正文完整性条件。

### 9.4 阶段级耗时

```text
DNS / TCP-TLS / TTFB / Body Download /
Browser Acquire / page.goto / DOM Ready /
wait_for / interaction / render serialize
```

### 9.5 Fetch 错误分类

```text
FETCH_NETWORK_ERROR
FETCH_TIMEOUT
FETCH_RATE_LIMITED
FETCH_ACCESS_DENIED
FETCH_BROWSER_CRASH
FETCH_EMPTY_SHELL
FETCH_PERMANENT_NOT_FOUND
```

## 10. Slow Path Isolation、Fallback Gain 与熔断

Browser 与 LLM Exception 都是慢路径，不能只是“失败后再试一次”的无界兜底。

### 10.1 慢路径执行模型

```text
HTTP / Rule 主链
 -> Quality / Classification 证据不足
 -> Fallback Admission
 -> Slow Queue
 -> Browser 或 LLM Exception
 -> Fallback Evaluation
 -> PASS / QUARANTINE / Retry / Circuit Open
```

每次升级都记录：

- trigger_reason；
- base quality；
- fallback quality；
- quality delta；
- wall time；
- cost；
- 是否从非 PASS 恢复为 PASS；
- failure/timeout/blocker。

### 10.2 Source 级 Budget 与 Circuit Breaker

每个 Source Release 可配置：

- Browser/LLM 最大任务占比；
- 最大并发；
- 单任务 timeout；
- 日/小时预算；
- 最小样本数；
- 最低 recovery rate；
- 最大 p95 latency；
- 最大 cost per recovered document。

当滑动窗口内连续出现低 recovery、高延迟或高成本：

1. 打开 Source-scoped circuit breaker；
2. 新的慢路径 Candidate 进入 `QUARANTINE/DEFERRED`，不继续无限消耗资源；
3. Discovery、HTTP、其他 Source 继续运行；
4. 自动生成诊断和 Candidate Route/Recipe 建议；
5. 只有 Replay/Canary/Approval 后才能调整 ACTIVE Release 并关闭熔断。

### 10.3 质量优先于可用率

熔断只停止高成本尝试，不能把低质量 HTTP Candidate 静默标记 PASS。没有达到 Quality Gate 的内容必须保持 QUARANTINE/DEGRADED。

### 10.4 Route 反馈闭环

```text
Cheap Route
 -> Fallback Trigger
 -> Gain Measurement
 -> Recovery/Cost Window
 -> Candidate Policy
 -> Golden Replay
 -> Canary
 -> ACTIVE
```

运行指标可以建议新策略，但不能实时自修改生产规则，避免不可解释的在线策略漂移。

## 11. 正文抽取：Extraction Portfolio

### 11.1 Structured Candidate

优先读取：

- JSON-LD `articleBody/headline/datePublished/author`；
- OpenGraph；
- Microdata；
- canonical link；
- 页面嵌入公开结构化状态。

多个来源冲突时必须记录冲突，不静默覆盖。

### 11.2 Trafilatura Generic Extractor

```text
PRECISION  -> 噪声风险高的媒体站
BALANCED   -> 普通技术博客默认
RECALL     -> 文档站、代码/表格/短段落易漏失站点
```

输出作为 Candidate，不直接把第三方 Markdown 当 Canonical。

### 11.3 Deterministic Recipe

```yaml
article:
  title: css:h1.article-title
  published_at: css:time::attr(datetime)
  content: css:article.post-content
  remove:
    - css:.newsletter-signup
    - css:.related-posts
    - css:.share-buttons
```

支持 CSS/XPath/Regex，不允许任意浏览器脚本进入抽取 Recipe。

### 11.4 DOM Repair + Generic

```yaml
repair:
  remove:
    - .newsletter-box
    - .related-posts
    - nav
    - footer
  unwrap:
    - .syntax-wrapper
```

Repair 后重新运行 Generic Extractor。

### 11.5 Crawl4AI Markdown

Crawl4AI `raw_markdown`、`fit_markdown` 只用于：

- 诊断；
- Candidate 对比；
- RAG 派生层实验。

不得直接覆盖 Canonical Markdown。

### 11.6 逐级回退

```text
HTTP Artifact
 -> Structured
 -> Trafilatura Precision/Balanced
 -> Quality PASS ?
      YES -> Canonical Candidate
      NO  -> Deterministic / Repair
 -> 仍失败且有 JS shell/recovery evidence
      -> Browser Slow Path
      -> 重新运行同一 Extraction Portfolio
      -> Fallback Evaluation
```

### 11.7 Shadow Extraction

- 新 Source：多个 Candidate 全跑；
- ACTIVE 稳定 Source：主 Extractor + 1%～5% Shadow；
- Drift 后临时提高 Shadow；
- 新 Release Canary 通过后恢复低采样。

### 11.8 LLM 使用边界

允许：

- Source Probe；
- Rule Generation；
- Ambiguous Classification 的低比例 Exception；
- Quarantine Triage；
- Projection：摘要、实体、关系、主题。

禁止：

- 每篇文章用 LLM 判断 Blog/Article；
- 每篇文章用 LLM 重写 Canonical Markdown；
- LLM 失败阻塞全站增量；
- 用模型判断替代 Coverage Evidence。

## 12. Candidate Agreement、Canonical IR 与 Quality Gate

### 12.1 Agreement 维度

字段：

- title similarity；
- author conflict；
- published/updated；
- canonical URL；
- language。

正文：

- normalized text similarity；
- token/character overlap；
- 段落数量；
- heading 分布；
- code/table/list 保留率；
- 首尾段一致性；
- link density；
- boilerplate score；
- 与历史版本长度/结构偏移。

典型规则：

```text
Precision 与 Deterministic 高一致 -> 高置信 PASS
Precision 偏短，Recall 与 Deterministic 高一致 -> Recall 更可信
Selector 与 Generic 严重偏离 -> SELECTOR_DRIFT -> QUARANTINE
所有 Candidate 都短且 HTTP 像 shell -> Browser Candidate
Browser 后仍无增益 -> NO_GAIN -> QUARANTINE / Circuit Signal
```

### 12.2 Canonical IR

```json
{
  "document_id": "...",
  "version_id": "...",
  "title": "...",
  "author": ["..."],
  "published_at": "...",
  "updated_at": "...",
  "canonical_url": "...",
  "blocks": [
    {"type":"heading","level":2,"text":"..."},
    {"type":"paragraph","text":"..."},
    {"type":"code","language":"python","text":"..."},
    {"type":"list","items":["..."]},
    {"type":"table","rows":[...]},
    {"type":"image","src":"...","alt":"..."}
  ]
}
```

### 12.3 Quality Gate

综合：

- 标题存在；
- 正文最小有效长度；
- 正文/链接比；
- boilerplate；
- 代码块/表格/列表结构保留；
- 语言一致性；
- Candidate Agreement；
- 与历史版本长度/结构异常偏移；
- 登录墙/错误页/WAF/CAPTCHA 指纹；
- 重复文档比例；
- Classification 与正文是否冲突。

状态：

```text
PASS        可进入 Canonical 和 Projection
WARN        可用但有低风险异常
QUARANTINE  等待自动回放或人工处理
REJECT      明确非文章/错误内容
```

### 12.4 Markdown Renderer

统一规则：

- heading 层级稳定；
- fenced code 保留语言；
- list/table/blockquote 正确；
- 图片保留 alt + 原 URL/归档 Asset URL；
- 相对链接转绝对链接；
- 移除菜单、推荐、广告、cookie、订阅弹层；
- Front Matter 保存来源元数据；
- Renderer 版本化。

Markdown 只从 Canonical IR 生成，Renderer 升级可批量重建而无需重新抓站。

## 13. 增量同步与版本管理

### 13.1 Freshness 分层

- HOT：高频新闻/资讯；
- WARM：普通技术博客；
- COLD：长期低频更新站点。

```text
priority = urgency + freshness_class + retry_age + source_weight - estimated_cost
```

### 13.2 增量发现

```text
RSS/API
 -> Sitemap lastmod/diff
 -> Archive first pages
 -> bounded dynamic listing
```

新 URL 必须经过 Normalize -> Classification -> Route；已知 URL 默认复用当前 Classification，但 Source Release、redirect、content-type、抽样校验可触发重新分类。

### 13.3 增量事件

```text
NEW_URL
KNOWN_URL_UPDATED_HINT
KNOWN_URL_RECHECK
URL_RECLASSIFIED
ROUTE_CHANGED
CONTENT_VERSION_CHANGED
METADATA_CHANGED
REMOVED_OR_MOVED
```

RSS `updated`、Sitemap `lastmod` 只是 Hint。

### 13.4 已知 URL 复检

- ETag；
- Last-Modified；
- RSS updated；
- Sitemap lastmod；
- 周期性抽样强制 re-fetch。

304 记录 Fetch Attempt，但不创建新正文版本。

### 13.5 版本判定

```text
fetch artifact
 -> extraction portfolio
 -> canonical IR
 -> normalize semantic content
 -> semantic_hash
 -> compare current version
```

- hash 相同：更新 last_checked；
- 正文变化：新 Version；
- 仅元数据变化：记录 metadata change；
- 新 Version PASS 后原子切换 `current_version_id`。

### 13.6 删除与迁移

```text
ACTIVE
 -> 404/410 or provider missing
 -> SUSPECT_MISSING
 -> 多次复检 + sitemap/archive evidence
 -> REMOVED
```

301/308 记录 Redirect Relationship；目标 URL 重新执行 Scope/Classification/Route。

## 14. 任务幂等、恢复、队列与公平性

### 14.1 幂等键

```text
DISCOVER:{source_release}:{provider}:{cursor/range}
CLASSIFY:{url_id}:{classifier_release}:{route_policy_version}
FETCH:{url_id}:{fetch_policy_version}:{validator_state}
FALLBACK:{url_id}:{fallback_policy_version}:{base_artifact_id}
EXTRACT:{artifact_id}:{extractor_release}:{mode}
ARBITRATE:{artifact_id}:{portfolio_release}
RENDER:{version_id}:{renderer_release}
VECTOR:{version_id}:{chunker_release}:{embedding_release}
GRAPH:{version_id}:{graph_schema}:{graph_release}
```

### 14.2 Lease + Fencing

Worker 领取 Task 获得 lease 和 fencing token；旧 Worker lease 失效后不能覆盖新 Worker 的结果。

### 14.3 Retry / DLQ

网络错误、Rate Limit、Browser Crash、Classification Unknown、Extraction Quality、404/410、Access Denied、Recipe Unsupported、Fallback No Gain 分开配置退避和最大次数。

### 14.4 Global Admission

每次真实网络/Browser/LLM 请求前统一检查：

- global concurrency；
- per-domain concurrency；
- request rate；
- Browser slots；
- Source budget；
- Slow-path share；
- Circuit state；
- robots/policy；
- maintenance window。

### 14.5 Weighted Fair Scheduling

- Incremental 高于 Backfill；
- HOT 高优先；
- 长等待任务 aging；
- 单 Source 最大并发占比；
- Browser 队列独立公平；
- UNKNOWN/LLM Exception 独立低配额；
- Projection 不抢抓取关键资源。

### 14.6 Backpressure

当 Extract/Storage/Search 延迟升高：

- 降低新 Fetch Admission；
- Discovery/Classification 可继续低成本运行，但限制正文 Task 生成；
- Browser 首先降速；
- LLM Exception 可暂停；
- Graph/LLM Projection 可完全暂停。

## 15. 检索、向量与 RAG Projection

### 15.1 Chunk 不是事实层

Chunk 由 `document_version_id + chunker_release` 生成，可重建。

按结构切分：

1. heading section；
2. paragraph group；
3. code block 尽量不拆；
4. 超长 section 再递归；
5. 每 chunk 保留 source/document/version/heading path。

### 15.2 默认检索链

```text
Query
 -> metadata filter
 -> OpenSearch BM25 recall
 -> pgvector semantic recall
 -> RRF/weighted fusion
 -> reranker
 -> dedup/diversity
 -> evidence context
 -> RAG/Search
```

### 15.3 Projection 与抓取解耦

Embedding、BM25、Graph 在 Document Version PASS 后通过 Outbox/Queue 异步执行：

- 相同 semantic_hash 不重复向量化；
- Embedding 故障不阻塞抓取和 Canonical；
- 更换 chunker/embedding 模型可重建；
- 默认只索引当前 PASS/WARN 版本。

### 15.4 可选 Graph Projection

Graph 只作为可重建增强层，仅对明确存在多跳/依赖/替代/兼容关系价值的 Collection 开启。

要求：

- Schema-guided Entity/Relation；
- Entity Resolution；
- 每条关系回溯原文 Chunk；
- Candidate Projection + Quality Gate；
- Query Router 按需启用；
- 独立预算与熔断；
- Graph 停止不影响抓取和默认检索。

## 20. Drift、Golden Corpus 与发布

### 20.1 Golden Corpus

每个 Site Family 保留：

- 普通文章；
- 短文/长文；
- 代码密集；
- 表格/图片；
- 动态页面；
- Index/Tag/Author 非文章页；
- PDF/API/Asset；
- UNKNOWN/边界样本；
- 特殊错误页；
- HTTP 失败但 Browser 可恢复样本；
- Browser 无增益样本。

任何 Runtime/Classifier/Route/Fallback/Extractor/Repair/Renderer 升级都必须 Replay。

### 20.2 在线 Drift

监控：

- page type 分布突变；
- URL Rule hit rate；
- UNKNOWN；
- LLM Exception；
- Route Decision；
- selector hit rate；
- Trafilatura quality；
- Candidate Agreement；
- Shadow divergence；
- 正文长度/结构；
- QUARANTINE；
- HTTP -> Browser fallback 激增；
- Browser recovery rate 下降；
- fallback p95 latency 上升；
- cost per recovered document 上升；
- circuit open；
- Provider URL 数突变。

### 20.3 Release 流程

```text
DRAFT
 -> compile
 -> static validation
 -> Golden replay
 -> sample live test
 -> CANDIDATE
 -> CANARY
 -> metrics compare
 -> approval
 -> ACTIVE
```

失败自动回滚上一 Source Release。运行指标只能生成 Candidate Policy，不允许无 Release 地在线自修改生产规则。

## 21. 安全、合规与来源策略

### 21.1 SSRF

每个网络跳转重新校验：

- scheme 仅 http/https；
- DNS 解析；
- 禁止 loopback、link-local、private CIDR、metadata endpoint；
- redirect 后重验；
- Browser iframe/navigation/request 同样执行 egress policy；
- proxy 不能绕过目标校验。

### 21.2 Web 管理安全

- RBAC：viewer/operator/admin；
- Secret 不回显；
- Recipe 不接受任意 JS/evaluate；
- LLM Exception 不允许生成可直接执行的任意脚本；
- 高风险 Release 激活需要 Approval；
- Audit Log 记录配置、Circuit、人工操作；
- 导出权限独立控制。

### 21.3 来源策略

每个 Source 记录：

- robots policy；
- crawl delay；
- 登录需求；
- 内容授权/许可证备注；
- 是否允许资产下载；
- 是否允许公开导出。

技术上可访问不等于拥有再分发权。

## 24. 验收标准与最终推荐

### 24.1 历史抓取

- 每个 Source 能显示 URL 从哪个 Provider 发现；
- Provider 有明确 stop reason/exhaustion evidence；
- Known Gap 可见；
- 失败可回放；
- 不以“crawler 结束”代替“Coverage 完成”。

### 24.2 增量

- RSS/Sitemap/API 新文章在目标 Freshness 内入库；
- 新 URL 经 Classification/Route 后才进入高成本抓取；
- 304 不生成新正文版本；
- 正文修改生成新 Version；
- 页面噪声变化不制造假正文版本；
- 删除需要多证据确认；
- 重复任务不产生脏重复。

### 24.3 Routing / Classification

- ARTICLE/DOC/INDEX/TAG/AUTHOR/ASSET/API/UNKNOWN 分类证据可追溯；
- Index/Tag/Author 默认不进入 Canonical；
- Stable Source 不逐 URL 依赖 LLM；
- Route Policy 升级可对历史 URL Replay；
- UNKNOWN/LLM Exception 激增可告警；
- Crawl4AI matcher 改变不能无审计改变业务 page_type；
- Browser avoided、route hit、classification cost 可量化。

### 24.4 Slow Path / Fallback

- Browser/LLM fallback 与 HTTP/Rule 主链使用独立容量；
- 每次 fallback 可回溯 trigger、base result、fallback result、latency、cost；
- recovery rate、quality gain、cost per recovered document 可按 Source 查看；
- 连续低收益可触发 Source-scoped circuit breaker；
- circuit open 不影响其他 Source/HTTP 主链；
- circuit open 不允许把未通过质量的 Candidate 静默标记 PASS；
- Fallback Policy 变化必须经 Replay/Canary/Release。

### 24.5 Extraction / Markdown

- Fetch success 与 Extraction success 独立；
- Trafilatura precision/balanced/recall 可配；
- selector 漂移能由 Agreement/Shadow 检出；
- Repair Recipe 版本化；
- 任意 Extraction Attempt 可回溯 Artifact 与 Release；
- Extractor 升级可离线 Replay；
- Markdown 结构稳定、噪声受控、可回溯 Canonical IR；
- Renderer 升级可批量重建；
- Crawl4AI `fit_markdown` 不直接进入 Canonical。

### 24.6 扩展性与检索

- 新 Source 主要通过 Probe/Profile/Family/Policy/Recipe 接入；
- 大站 Backfill 不阻塞增量；
- Browser 故障不拖垮 HTTP；
- LLM 故障不拖垮 Classification/Canonical 主链；
- 单 Extractor 故障可切换 Candidate；
- Graph/LLM Projection 停止不影响 Canonical；
- BM25 + Vector + Rerank 有固定离线评测集；
- 可选 Graph 只有质量、成本与目标问题集收益达标后启用；
- 检索证据能追溯具体 Document Version。

### 24.7 推荐主链

```text
Authoritative Discovery
 -> URL Truth / Coverage Evidence
 -> Normalize / Scope / Dedup
 -> Page Type Classification
      Provider Hint
      + URL Rule
      + MIME
      + Structured Metadata
      + DOM Heuristic
      + LLM Exception (rare)
 -> Execution Route
      ARTICLE/DOC -> HTTP First
      INDEX/TAG/AUTHOR -> Discovery Only
      ASSET -> Asset Pipeline
      API -> Structured Fetch
      UNKNOWN -> Cheap Probe / Quarantine
 -> Immutable HTTP Artifact
 -> Extraction Portfolio
 -> Quality Gate
      PASS -> Canonical Candidate
      FAIL + recovery evidence -> Slow-path Browser
 -> Fallback Gain Evaluation
 -> Candidate Agreement
 -> Canonical IR
 -> Document Version
 -> Canonical Markdown
 -> BM25 / Vector / Export / Optional Graph
```

增量主链：

```text
RSS/API/Sitemap Diff
 + Known URL Verify
 -> Normalize / Reclassify when needed
 -> Route Decision
 -> Conditional GET / HTTP First
 -> Artifact
 -> Extraction Portfolio
 -> Optional Governed Fallback
 -> Semantic Version Detection
 -> Atomic Current Version Switch
 -> Rebuild Markdown/Search/Vector Projection
```

组件定位：

```text
Crawl4AI    = Browser/Fetch Adapter + Discovery/Prefetch Optimization + Diagnostic Candidate
Trafilatura = Generic Main-Content Candidate Extractor
lxml/BS4    = Structured Metadata + Cheap DOM Heuristic + DOM Repair + Diagnostic
LLM         = Probe/Rule Generation/Exception/Projection，不是逐 URL 默认主链
Platform    = Coverage / Truth / Classification / Routing / Fallback Governance /
              Arbitration / Quality / Version / Markdown
```

系统核心不是选择一个“万能爬虫”，而是构建一个 **以 Coverage、可解释 Classification/Route、受治理的 Slow Path、不可变 Artifact、多 Candidate Extraction、Canonical IR、版本、幂等任务、质量与可重建 Projection 为核心的平台**。这套边界能满足 1000+ 技术博客的全历史采集、长期增量同步、Markdown 知识库、Web 管理和未来新增站点需求，并能在站点改版、分类器升级、抓取器升级、抽取器升级后通过 Replay/Canary 恢复，同时避免把 Browser 与 LLM 的高延迟和成本线性放大到全部 URL。
