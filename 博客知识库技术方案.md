# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站、公开 Newsletter** 的长期知识库采集平台，并能平滑扩展到数千站点、百万级文章。

系统需要同时满足：

1. **全历史回填**：尽可能完整发现并抓取每个已批准 Source 的全部历史文章；
2. **持续增量同步**：发现新文章、正文更新、URL 迁移、删除与重发布；
3. **稳定产出 Markdown**：Markdown 必须由可追溯网页事实经过抽取、质量校验和 Canonical IR 生成，而不是直接相信某个爬虫的即时 Markdown；
4. **低成本扩站**：新增网站优先通过 Source Profile、Provider、Traversal Policy、Recipe 配置完成，不复制 1000 份站点脚本；
5. **Web 可运营**：支持 Source 接入、Backfill、Incremental、Coverage、Frontier、失败诊断、暂停恢复、质量、版本、成本和审计；
6. **可搜索与 RAG**：支持关键词、向量、混合检索和可追溯引用；
7. **可观测、可恢复、可重放**：任意 URL、任务、Artifact、Markdown 都能解释来源、版本和执行路径；
8. **渐进扩展部署**：开发期单机 Docker Compose，生产期按队列与 Worker 类型水平扩容；
9. **采集主链不依赖 LLM**：LLM 只做可选增强，不参与 Coverage Truth、URL Identity 和 Canonical URL 的最终判定。

### 1.1 核心 SLO

- **Coverage**：每个 Source 能解释已发现 URL、Provider、Frontier、Known Gap 和停止原因；
- **Freshness**：新文章从发布/发现到 PASS Markdown 的延迟可监控；
- **TTFM**：URL 首次发现到首个可用 Markdown 的时间；
- **Extraction Quality**：标题、正文完整率、噪声率、代码块/表格/列表保留率、截断率；
- **Reliability**：任务成功率、Retry、DLQ、Queue Age、Checkpoint Resume 成功率；
- **Browser Efficiency**：HTTP 命中率、Browser avoided、Browser recovery、Browser 每文档成本；
- **Identity Quality**：重复文章误合并/漏合并率；
- **Traceability**：任意 Markdown 可回溯 Source、URL、Artifact、Extractor、Quality、Renderer Release；
- **Cost**：按 Source、Run、Queue Class、每 1000 篇 PASS 文档统计抓取、Browser、存储、索引与模型成本。

### 1.2 非目标

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不把 HTTP 200、DOM 很长或 crawler success 直接视为正文正确；
- 不把搜索引擎结果数、Deep Crawl 页数或 `max_pages` 当历史完整性证明；
- 不把 Crawl4AI 原始 Markdown、LLM 摘要或改写直接作为 Canonical Markdown；
- 不因 URL 曾抓过就永久停止复检；
- 不把 Redis、Browser Session、Crawler Cache、Visited Set、Search Index 当业务真相；
- 不允许优先级或相关性分数永久删除潜在历史文章；
- 不默认对所有文档构建 GraphRAG。

## 2. 核心设计原则

1. **Coverage First**：先建立 URL Inventory，再批量抓正文；
2. **Authoritative First**：CMS/API、Sitemap、RSS/Atom、Archive 优先；
3. **Deep Crawl Is Gap Provider**：站内深度抓取用于补洞，不作为 Coverage Truth；
4. **Search Is Gap Only**：外部搜索只用于补洞和发现新 Source；
5. **Discovery / Fetch / Extract / Quality 分离**；
6. **HTTP First, Browser Last**：Browser 是受治理慢路径；
7. **Snapshot First**：先保存不可变 Artifact，再抽取和清洗；
8. **Canonical IR First, Markdown as Projection**；
9. **Recipe, Not 1000 Site Scripts**；
10. **Stable Identity**：Source、URL、Artifact、Document、Version 使用稳定 ID；
11. **Idempotent + Recoverable**：任务使用幂等键、lease、fencing token、checkpoint；
12. **Fair by Default**：大站 Backfill 不能饿死 Incremental 和小站；
13. **Bounded Concurrency Everywhere**：禁止无界 asyncio gather、Browser Context、LLM fan-out；
14. **No Silent Degradation**：截断、预算耗尽、降级、过滤、跳过必须显式记录原因；
15. **Release Everything That Changes Results**：Profile、Traversal、Recipe、Runtime、Extractor、Quality、Renderer、Embedding、Rank 全部版本化；
16. **Priority Means When, Not Whether**：优先级决定何时处理，不决定是否永久保存；
17. **Listing Evidence Before Selection**：列表页、Sitemap、Feed、Deep Crawl 中观察到的 URL 先形成可回溯 Observation；
18. **Persistent Frontier, Not In-Memory Traversal**：BFS/DFS/Best-First 的算法语义进入数据库，Worker 内存仅做执行缓存；
19. **Same Semantics, Different Topology**：单机 Pilot 与生产集群共享数据模型、状态机和任务协议。

### 3.1 真相边界

**PostgreSQL + Object Storage 是业务真相。**

- PostgreSQL：Source、Provider、URL Identity、URL Observation、Crawl Frontier、Task、Cursor、Coverage、Quality、Document、Version、Release、审计；
- S3/MinIO：Raw HTML、MHTML、截图、Trace、Candidate、IR、Markdown、PDF、Enrichment；
- Redis Streams：任务运输、Consumer Group、背压，不保存不可替代业务状态；
- OpenSearch / pgvector：可重建 Serving Projection；
- Crawl4AI state、Playwright Session、Worker 内存：易失执行状态。

## 4. 技术选型

### 4.1 控制面

- **FastAPI + Pydantic**：REST API、Command、Schema 校验；
- **PostgreSQL**：Truth Store、任务状态、Coverage、Frontier、版本、审计；
- **Redis Streams**：任务队列、Consumer Group、Backpressure；
- **Redis Lua Token Bucket / Semaphore**：跨 Worker 域名限流和资源令牌；
- **React / Next.js + TypeScript**：Web 管理后台；
- **OpenTelemetry + Prometheus + Grafana + Structured Logging**：Trace / Metric / Log；
- **S3/MinIO**：不可变对象存储；
- **Vault/KMS/Secret Manager**：凭据引用。

### 4.2 Discovery / Fetch

- **httpx/aiohttp**：robots、Sitemap、Feed、CMS API、Conditional GET、普通网页；
- **Crawl4AI**：Browser Render、Deep Crawl Prefetch、动态链接发现、简单交互、内容型 Browser；
- **Playwright Python**：复杂多步、有状态、需要 Step 级恢复的交互；
- **SearXNG / 合规 Search API Adapter**：External Search Gap、新 Source Candidate；
- **PyMuPDF/pdftotext**：PDF；扫描件进入 OCR 慢路径；
- **Python email/MIME parser**：Newsletter Inbox Provider。

### 4.3 Extraction / Search

- **Trafilatura**：Generic Main Content Candidate；
- **lxml/BeautifulSoup**：DOM/XPath、Metadata、DOM Repair；
- **JSON-LD/OpenGraph/Microdata**：结构化元数据；
- **CSS/XPath/Regex Recipe**：确定性正文和字段抽取；
- **SimHash/MinHash**：近重复候选；
- **OpenSearch BM25 + pgvector + RRF**：混合检索；
- **可选 reranker / LLM**：只在 Canonical 数据之后运行。

### 4.4 版本冻结

必须记录：

```text

provider_adapter_release
traversal_policy_release
interaction_recipe_release
extractor_release
quality_release
identity_release
renderer_release
embedding_release
retrieval_release
```

任何改变结果的升级必须经过 Golden Replay / Offline Eval，生产环境必要时 Canary。

## 6. Source 接入流程

新增网站时先执行自动探测，再人工确认。

### 6.1 自动探测

```text
1. robots.txt
2. sitemap index / sitemap.xml
3. RSS / Atom
4. CMS 特征：WordPress/Ghost/Medium/Substack/自建 API
5. 首页与归档页结构
6. URL pattern
7. 是否需要 JS Render
8. 是否存在分页、年份归档、标签、分类
9. Deep Crawl 浅层 Prefetch
```

### 6.2 自动生成 Source Profile 草稿

```yaml
source:
  canonical_domain: example.com
  providers:
    - sitemap
    - rss
    - archive
    - deep_crawl
  fetch_route:
    default: http
    browser_patterns:
      - /interactive/*
  traversal:
    mode: bfs
    max_depth: 3
    max_pages_per_run: 5000
    include_external: false
    prefetch: true
    threshold_policy: priority_only
  extraction:
    generic: trafilatura
    article_selector: null
  incremental:
    rss_interval: 10m
    sitemap_interval: 6h
    home_probe_interval: 30m
```

人工在 Web Admin 审核后发布为 immutable release。

## 7. Discovery 与 Coverage

### 7.1 Provider 优先级

默认顺序：

```text
CMS/API
 -> Sitemap
 -> RSS/Atom
 -> Archive/Pagination
 -> Deep Crawl Prefetch
 -> External Search Gap
```

高优 Provider 的结果不能阻止其它 Provider 做交叉验证。

### 7.2 Coverage Evidence

每个 Provider Run 记录：

```text
provider
cursor / page / time partition
observed_count
new_url_count
existing_url_count
stop_reason
known_gap
started_at
finished_at
```

停止原因必须明确：

```text
FRONTIER_EMPTY
CURSOR_END
TIME_PARTITION_COMPLETE
MAX_DEPTH
MAX_PAGES
BUDGET_EXHAUSTED
RATE_LIMITED
CANCELLED
ERROR
```

`MAX_PAGES`、`MAX_DEPTH`、`BUDGET_EXHAUSTED` 不能被标记为 Coverage Complete。

### 7.3 URL Inventory

Discovery 的目标不是立刻抓正文，而是先建立 URL Inventory：

```text
DISCOVERED
 -> CLASSIFIED
 -> QUEUED
 -> FETCHED
 -> EXTRACTED
 -> PASS
```

这样才能先知道一个站点大致有 500 篇、5 万篇还是 50 万篇，再决定 Backfill 资源配额。

## 8. Deep Crawl 与 Traversal Policy

### 8.1 角色定位

Deep Crawl 只用于：

- 发现 Sitemap/RSS/API 漏掉的站内 URL；
- 发现归档、分页、标签、年份入口；
- 发现 JavaScript 渲染后才出现的链接；
- 验证导航结构和 URL pattern；
- 定期执行 Coverage Gap 扫描。

不用于证明“历史已经完整”。

### 8.2 Prefetch Discovery Mode

采用两阶段抓取：

```text
Phase A: Prefetch Discovery
- 获取 HTML + links
- 不做 Markdown
- 不做媒体下载
- 不做全文增强
- 快速建立 URL Inventory

Phase B: Full Fetch
- 受限并发
- 保存 Artifact
- Extraction / Quality / Markdown
```

对 1000 站历史回填，这是默认模式。

### 8.3 BFS / DFS / Best-First

- **BFS**：默认用于 Backfill 探测，先覆盖浅层导航与归档；
- **DFS**：只在路径深度结构明确的 Source Recipe 中启用；
- **Best-First**：用于固定预算下优先抓更可能有价值的 URL。

Best-First 的分数默认只映射为 priority：

```text
score -> priority
```

除明确 deny rule 外，不因低分永久删除 URL。

### 8.4 Traversal Policy Release

```yaml
traversal:
  mode: bfs
  max_depth: 3
  max_pages_per_run: 10000
  include_external: false
  prefetch: true
  filter_chain:
    allow_domains:
      - example.com
    include_patterns:
      - /blog/*
      - /archive/*
    exclude_patterns:
      - /login/*
      - /search/*
  scorer:
    type: deterministic_path
    weights:
      article_pattern: 5
      archive_pattern: 3
      pagination_pattern: 2
      query_explosion: -8
  threshold_policy: priority_only
```

每个 URL Observation 记录对应 `traversal_policy_release_id`。

### 8.5 Crawl Graph Evidence

保存 `from_url -> to_url`：

- 用于解释 URL 来源；
- 识别分页链；
- 发现孤立文章；
- 比较 Sitemap 与站内链接覆盖差异；
- 发现导航结构变化。

## 9. Fetch Router

### 9.1 路由原则

```text
HEAD/HTTP probe
  |
  +-- 静态可用 ----------> httpx
  |
  +-- JS 内容型 ---------> Crawl4AI
  |
  +-- 复杂有状态交互 ----> Playwright
  |
  +-- PDF --------------> PDF Pipeline
```

默认 HTTP First。

### 9.2 Route Decision

```text
route_decision
- url_id
- route
- reason
- route_release_id
- confidence
```

Route 决策必须可解释并可重放。

### 9.3 Browser 治理

- Browser Worker 独立队列；
- 每个域名有 Browser 并发上限；
- 全局 Browser Context 有令牌上限；
- Browser 内存按 worker RSS / Chromium process 监控；
- 超时、导航失败、JS 错误进入明确 reason code；
- 不允许普通 Backfill 任务无限占用 Browser。

## 10. 调度、并发与背压

### 10.1 队列类别

```text
incremental_high
incremental_normal
backfill_normal
backfill_bulk
browser_slow
repair
reindex
```

### 10.2 公平调度

使用 Weighted Fair Queue / Deficit Round Robin 思路：

- Incremental 有最低保证；
- 单一 Source 每轮最多获得固定 slice；
- 大站不能独占队列；
- Browser 与 HTTP 使用不同资源预算。

### 10.3 Domain Admission

每个域名维护：

```text
max_concurrency
requests_per_second
burst
retry_after_until
error_rate
latency_ewma
```

调度器根据 429/503/超时动态降低速率。

### 10.4 幂等、Lease 与 Fencing Token

任务模型：

```text
crawl_task
- id
- idempotency_key
- state
- lease_owner
- lease_until
- fencing_token
- attempt
- next_retry_at
```

Worker 必须在提交状态时携带 fencing token，避免旧 Worker 覆盖新执行结果。

执行语义接受 at-least-once，通过：

```text
unique task key
+ content hash
+ immutable artifact
+ transactional state transition
```

实现幂等。

## 11. Raw Snapshot 与不可变 Artifact

每次有效 Fetch 都先保存原始事实：

- Response headers；
- final URL / redirect chain；
- Raw HTML；
- 需要时保存 MHTML / screenshot / network trace；
- Content-Type；
- ETag / Last-Modified；
- payload SHA-256；
- runtime release。

对象存储路径建议：

```text
artifacts/{source_id}/{yyyy}/{mm}/{artifact_id}/raw.html
artifacts/{source_id}/{yyyy}/{mm}/{artifact_id}/meta.json
```

Artifact 不覆盖，只新增版本。

## 13. Quality Gate 与 Repair

### 13.1 质量指标

至少检查：

- 标题存在且合理；
- 正文最小长度；
- 正文/导航链接密度；
- boilerplate 比例；
- 代码块、表格、列表是否异常丢失；
- 是否疑似截断；
- canonical 与 host 是否合理；
- 日期是否合法；
- Candidate 与 Raw DOM 文本覆盖率；
- 与上一版本内容变化是否异常。

### 13.2 决策

```text
PASS
WARN
REPAIR
REJECT
```

只有 PASS 才默认进入当前知识库。

### 13.3 Repair 状态机

```text
Generic Extract
 -> Recipe Extract
 -> Browser Render
 -> Alternate Extractor
 -> Manual Review
```

Repair 次数有上限，禁止无限递归重试。

## 14. Canonical IR 与 Markdown

### 14.1 Canonical IR

Markdown 不是业务真相，Canonical IR 才是可重建内容层。

示例：

```json
{
  "document_id": "doc_xxx",
  "title": "...",
  "canonical_url": "...",
  "published_at": "...",
  "updated_at": "...",
  "blocks": [
    {"type": "heading", "level": 2, "text": "..."},
    {"type": "paragraph", "text": "..."},
    {"type": "code", "language": "python", "text": "..."}
  ]
}
```

### 14.2 Markdown 输出格式

```markdown
---
document_id: ...
source_id: ...
canonical_url: ...
published_at: ...
updated_at: ...
fetched_at: ...
content_hash: ...
extractor_release: ...
renderer_release: ...
---

```

文件路径使用稳定 ID，展示名可另建索引，避免标题改名导致文件漂移：

```text

```

### 14.3 Renderer 可重建

Renderer 升级后，可以从旧 IR 全量重建 Markdown，无需重新抓网站。

## 15. Document Identity、去重与版本

### 15.1 URL Identity 与 Document Identity 分离

同一文档可能存在：

- http/https；
- trailing slash；
- AMP；
- tracking query；
- URL 重定向；
- CMS slug 变化。

因此先做 URL Identity，再做 Document Identity。

### 15.2 Document Identity 信号

按确定性强弱组合：

```text
canonical URL
redirect chain
CMS stable ID
guid
same-source exact content hash
title + published_at + strong similarity
```

语义相似不能直接视为同一文档。

### 15.3 Versioning

内容 hash 变化且通过 Quality 后创建新 `document_version`。

旧版本保留，当前版本通过 `is_current` 指向。

## 16. 增量同步

### 16.1 Provider 增量

优先使用：

```text
RSS/Atom cursor
CMS API updated_at
Sitemap lastmod
Archive newest page
Homepage shallow probe
```

### 16.2 Conditional Fetch

支持：

```text
If-None-Match / ETag
If-Modified-Since / Last-Modified
```

304 只更新检查时间，不创建新 Artifact 正文版本。

### 16.3 复检策略

每个 URL 计算 `next_check_at`：

- 新文章短期高频；
- 老文章逐渐退避；
- 高变更 Source 频率更高；
- 长期不变文章低频巡检；
- 手工 pin 的关键 Source 可提高频率。

### 16.4 Deep Crawl 增量补洞

周期性执行浅层 Prefetch：

```text
首页
最近归档
最近分页
关键分类
```

同时低频执行全站 Gap Crawl，发现导航中新出现但 Feed/Sitemap 未覆盖的 URL。

### 16.5 删除与失效

不能因一次 404 就直接删除知识库内容。

建议状态：

```text
ACTIVE
SUSPECT_MISSING
CONFIRMED_REMOVED
REDIRECTED
```

需多次观测或权威 Provider 证据后确认移除。

## 20. 安全、合规与资源保护

7. Web Admin 使用 RBAC；
8. 对抓取、删除、重放、发布 Profile 等敏感操作审计；
9. 所有 Parser / Browser / Crawl4AI 镜像固定版本与 digest。

## 25. 最终推荐架构

最终采用：

```text
PostgreSQL Truth Store
+ S3/MinIO Immutable Artifact
+ Redis Streams Task Transport
+ FastAPI Control Plane
+ Next.js Web Admin
+ Authoritative Discovery Providers
+ Persistent Crawl Frontier
+ Crawl4AI Deep Crawl Prefetch
+ HTTP First / Browser Last Fetch Router
+ Playwright Stateful Recipe
+ Extraction Portfolio
+ Independent Quality Gate
+ Canonical IR
+ Deterministic Markdown Renderer
+ OpenSearch + pgvector Serving
+ OpenTelemetry Observability
```

其中最关键的边界是：

1. **历史完整性由多 Provider Coverage Evidence 证明，不由某次 crawler 运行证明；**
2. **Deep Crawl 负责补洞，BFS/DFS/Best-First 的 Frontier 持久化到平台，不依赖进程内 visited/queue；**
3. **先 Prefetch Discovery，再 Full Fetch，避免大站历史回填失控；**
4. **Best-First 的相关性优先用于调度，不能默认永久裁剪历史 URL；**
5. **所有原始网页先进入不可变 Artifact，再生成 Candidate、IR 和 Markdown；**
6. **增量同步、重试、崩溃恢复、暂停恢复都围绕幂等任务与持久化状态实现；**
7. **Web Admin 必须能解释 Coverage、Frontier、过滤、停止原因、Artifact 和版本链，而不仅是展示任务成功失败。**

这套方案能够覆盖 1000+ 技术博客的全历史抓取、持续增量同步、Markdown 知识库输出和长期 Web 运营，并可在不重写核心业务语义的前提下扩展到数千站点和百万级文档。
