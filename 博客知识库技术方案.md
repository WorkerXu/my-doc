# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站与公开 Newsletter** 的长期知识库采集平台，并可持续扩展到数千站点、百万级文章。

系统必须同时解决：

1. **全历史回填**：尽可能发现并抓取每个已批准 Source 的全部历史文章；
2. **持续增量同步**：发现新文章、正文更新、URL 迁移、删除、重发布；
3. **稳定产出 Markdown**：从不可变网页事实经过抽取、质量校验和 Canonical IR 生成可重建 Markdown；
4. **低成本扩站**：新增站点、RSS、Atom、Sitemap、CMS/JSON API 等输入不要求复制一套爬虫代码；
5. **Web 可运营**：支持 Source 接入、Backfill、Incremental、Coverage、失败诊断、版本回放、质量、成本、检索与审计；
6. **知识访问**：支持关键词/向量混合检索、RAG、同主题去重展示和可追溯引用；
7. **可选个性化发现**：允许 Topic Watch、用户反馈与自带来源帮助发现新内容，但绝不能污染正式 Collection Truth。

### 1.1 核心 SLO

- **Coverage**：每个 Source 能解释 Provider、时间区间、游标、分区、停止条件和 Known Gap；
- **Freshness**：新文章从发布/发现到 PASS/WARN Canonical Markdown 的延迟可监控；
- **TTFM（Time To First Markdown）**：从发现到首个可读、可导出的 Canonical Markdown；
- **TTFR（Time To Fully Ready）**：从发现到必需的 Summary/Embedding/Entity 等增强完成；
- **Extraction Quality**：标题、正文完整率、噪声率、代码块/表格/列表保留率、截断率；
- **Reliability**：任务成功率、Retry、DLQ、Queue Age、Checkpoint Resume 成功率；
- **Browser Efficiency**：HTTP 命中率、Browser avoided、Browser recovery、每恢复文档成本；
- **Interaction Reliability**：复杂交互 Step 成功率、Locator Drift、Semantic Wait 超时率；
- **Identity Quality**：Document Identity 误合并/漏合并、Story Cluster 误聚类/漏聚类；
- **Traceability**：任意 Markdown 可回溯 Source Release、URL、Artifact、Extraction、Quality、Document Version、Renderer Release；
- **Provenance Quality**：任意用户可见引用 URL 都能回溯真实 URL Observation/Artifact；
- **Retrieval Quality**：Recall@K、MRR、nDCG、filter accuracy、stale-version rate、duplicate-result rate；
- **Cost**：按 Source、Run、Queue Class、每 1000 个 PASS 文档统计 HTTP、Browser、Storage、Search、LLM、Embedding 成本。

### 1.2 非目标

- 不默认绕过登录墙、付费墙、CAPTCHA、WAF 或明确访问控制；
- 不把 HTTP 200、Crawler success、DOM 很长直接视为正文正确；
- 不把搜索引擎结果数当历史完整性证明；
- 不把 Crawl4AI 输出 Markdown、LLM 摘要或改写直接作为 Canonical Markdown；
- 不让 LLM 改写第三方原文来“修复”缺失正文；
- 不允许 LLM 生成或覆盖 canonical/source citation URL；
- 不因 URL 曾抓过就永久停止复检；
- 不允许 Source、Provider、Browser Recipe、Extractor、Renderer、Prompt、Model 无版本改变生产结果；
- 不把 Redis、Browser Session、Crawler Cache、Search Index、Agent Memory 当业务真相；
- 不为所有文档默认建设 GraphRAG；
- 不让慢路径失败、预算耗尽或降级结果静默进入 PASS；
- 不让 recency、domain authority、social proof、Embedding relevance、用户偏好决定某个已批准 Source 的历史文章是否值得保存；
- 不把语义相似或 Story Cluster 直接等价为同一 Document Identity；
- 不让用户反馈直接修改全局抓取规则或 Source Coverage。

## 2. 核心设计原则

1. **Coverage First**：先建立 URL Inventory，再批量抓正文；
2. **Authoritative First**：CMS/API、Sitemap、RSS/Atom、Archive 优先；
3. **Search Is Gap/Discovery Only**：SearXNG/外部 Search 只做补洞、临时主题发现和新来源候选；
4. **Discovery / Fetch / Extract / Quality 分离**：各层独立重试、回放、评估；
5. **HTTP First, Browser Last**：Browser 是受治理慢路径；
6. **按交互复杂度路由**：静态、渲染、简单交互、复杂有状态交互分别处理；
7. **Crawl4AI 做内容型抽象，Playwright 做状态型交互**；
8. **Prevent Abstraction Leakage**：复杂状态机不能塞回 L2 的任意 JS/C4A 脚本；
9. **Snapshot First**：先保存不可变 Artifact，再抽取和清洗；
10. **Extractor Is Candidate Generator**：Extractor 只产生 Candidate；
11. **Critique Before Publish**：Candidate 必须经过独立 Quality Gate；
12. **Repair Is Bounded**：修复是有限状态机；
13. **Canonical IR First, Markdown as Projection**：Markdown 可离线重建；
14. **Recipe, Not 1000 Site Scripts**：站点差异优先由 Profile/Policy/Recipe 表达；
15. **Source Adapter, Not Provider Special Cases**：RSS/API/Sitemap/Newsletter 等统一转成 Observation；
16. **Complex Interaction Is a First-class Workflow**：复杂 Browser 流程有 Step、Checkpoint、Trace、Budget；
17. **Semantic Wait Over Time Guessing**：优先等待业务状态，而不是固定 sleep；
18. **Stable Logical Key Over DOM Handle**：动态列表按业务 key 重定位；
19. **Stable Identity**：Source、URL、Artifact、Document、Version 使用稳定 ID；
20. **Idempotent + Recoverable**：任务有幂等键、lease、fencing token、checkpoint；
21. **Fair by Default**：大站 Backfill 不饿死 Incremental 和小站；
22. **Bounded Concurrency Everywhere**：禁止无界 asyncio gather、Browser Context、LLM 并发；
23. **No Silent Degradation**：截断、预算耗尽、Provider/Recipe 降级必须显式；
24. **Release Everything That Changes Results**：Profile、Route、Recipe、Runtime、Extractor、Renderer、Query Plan、Preference、Embedding、Rank 全部版本化；
25. **LLM 低频、旁路、可替换**：生产主链默认确定性；
26. **Collection Truth 与 Discovery/Serving 分离**：采集完整性、主题发现、用户排序是三套语义；
27. **Document Identity 与 Story Cluster 分离**：强证据决定同文档，弱/语义证据只决定同主题/同事件；
28. **Progressive Enrichment**：Quality PASS 后先发布 Markdown，慢增强异步补齐；
29. **Priority Means When, Not Whether**：优先级决定何时处理，不决定是否永久保存；
30. **Feedback Is Evidence, Not Policy**：用户反馈先形成不可变事件，再派生 Preference/Query Plan；
31. **Provenance Before Generation**：URL、引用、Canonical 必须来自真实网络观察，生成模型无权创造来源事实。

### 3.1 真相边界

**PostgreSQL + Object Storage 是业务真相。**

- PostgreSQL：Source/Provider、身份、状态、关系、游标、任务、Release、Coverage、Interaction Step、Checkpoint、Quality、Version、Preference Event、Query Plan、Audit；
- S3/MinIO：Raw HTML、MHTML、截图、Trace、Candidate、IR、Markdown、Search Evidence、Interaction Evidence、Enrichment、Ranking Evidence、导出物；
- Redis Streams：任务运输、背压、consumer group，不保存不可替代业务状态；
- OpenSearch/pgvector/Story Cluster/Preference Projection：均可重建，不反向覆盖 Canonical 事实；
- Browser Session、Crawler Cache、Worker 内存：易失执行状态。

## 4. 技术选型

### 4.1 控制面

- **FastAPI + Pydantic**：REST API、Command、Schema 校验；
- **PostgreSQL**：核心 Truth Store；
- **Redis Streams**：任务队列、consumer group、backpressure；
- **Redis Lua Token Bucket / Semaphore**：跨 Worker 域名限流和资源令牌；
- **React/Next.js + TypeScript**：Web 管理后台；
- **OpenTelemetry + Prometheus + Grafana + Structured Logging**：Trace/Metric/Log；
- **S3/MinIO**：不可变对象；
- **Vault/KMS/Secret Manager**：API、邮箱等凭据引用。

### 4.2 Discovery / Fetch

- **httpx/aiohttp**：robots、Sitemap、Feed、CMS API、Conditional GET、普通网页；
- **Crawl4AI**：Browser Render、简单交互、动态链接发现、诊断 Candidate；
- **Playwright Python**：复杂多步、有状态、需要 Step 级控制和恢复的 Browser Interaction Engine；
- **SearXNG/合规 Search API Adapter**：External Search Gap、Topic Watch、新 Source Candidate；
- **PyMuPDF/pdftotext**：PDF；仅扫描件进入 OCR；
- **Python email/MIME parser**：可选 Newsletter Inbox Provider。

### 4.3 Extraction / Search

- **Trafilatura**：Generic Main Content Candidate；
- **lxml/BeautifulSoup**：DOM/XPath、Metadata、DOM Repair；
- **JSON-LD/OpenGraph/Microdata**：结构化元数据；
- **CSS/XPath/Regex Recipe**：确定性正文/字段抽取；
- **SimHash/MinHash + pgvector**：近重复与同主题候选召回；
- **OpenSearch BM25 + pgvector + RRF/weighted fusion**：混合检索；
- **可选 reranker / LLM**：仅在 Canonical 与统一 Query Service 之后工作。

## 6. Source Input、Provider Adapter、Site Family 与 Release

### 6.1 新增 Source 的最小输入

```text
name + input_type + endpoint/base_url + 可选标签/策略约束
```

支持：

```text
WEB_DOMAIN
RSS
ATOM
SITEMAP
CMS_API
JSON_API
NEWSLETTER_EMAIL      # 可选扩展
MANUAL_URL_LIST
```

`SEARCH_WATCH` 不直接等价于正式 Source，只产生候选。

### 6.2 Adapter 统一契约

所有 Provider Adapter 对上层暴露统一语义：

```text
probe(input)
  -> capabilities
  -> auth_requirements
  -> provider_type
  -> sample_observations

discover(cursor/range/partition)
  -> observations[]
  -> next_cursor
  -> exhausted
  -> stop_reason
verify(item)
  -> exists/changed/redirect/deleted_hint
```

归一化输出：

```text
url_observation
- source_id
- provider_binding_id
- provider_type
- provider_item_id
- discovered_url
- canonical_hint
- published_hint
- updated_hint
- observed_at
- provenance_ref
```

正文处理链不关心 URL 是来自 Sitemap、RSS、API 还是 Newsletter。

### 6.3 Provider 与 Source 分开

一个 Source 可绑定多个 Provider：

```text
example.com
- sitemap
- rss
- wordpress api
- archive pagination
- search gap
```

多个 Provider 发现同一 URL 时保留各自 provenance，但合并到同一 `url_id`。

### 6.4 Source Probe

Source 初始进入 `PROBING`，自动检测：

1. robots.txt；
2. Sitemap / Sitemap Index；
3. RSS/Atom；
4. CMS/API；
5. Archive/Category/Tag/Pagination；
6. JSON-LD/OpenGraph/Microdata；
7. HTTP 是否能得到完整正文；
8. 是否需要 Browser Render；
9. 是否存在 Load More/Scroll；
10. 是否存在多步 tab/filter/pagination/foreach；
11. Site Family 指纹；
12. ARTICLE/DOC/INDEX/TAG/AUTHOR/ASSET/API 样本；
13. canonical、redirect、URL pattern；
14. 多 Extractor 样本质量；
15. Coverage/Search Gap 风险；
16. Locator/DOM 稳定性；
17. Browser Action 预估与成本；
18. L2 Recipe 是否有抽象泄漏特征。

### 6.5 Release 发布链

```text
Family Defaults
 + Source Overrides
 + Provider Bindings
 + Discovery Recipe
 + Route Policy
 + Extraction/Repair Recipe
 + Interaction Recipe(optional)
 + Quality Policy
 -> Effective Config Hash
 -> Candidate Source Release
 -> Static Validation
 -> Golden Replay
 -> Live Sample
 -> Canary
 -> Approval
 -> ACTIVE
```

模板升级不能自动改变 ACTIVE Source。

## 7. 全历史 URL Discovery 与 Coverage

### 7.1 Provider 优先级

```text
CMS/API
 -> Sitemap / Sitemap Index
 -> RSS/Atom
 -> Archive/Category/Tag
 -> Static Pagination
 -> Dynamic Listing
 -> Bounded Deep Crawl
 -> External Search Gap Fill
 -> Optional Web Archive/Common Crawl Gap Fill
```

RSS/Atom 主要用于增量和时间提示，不能独自证明完整历史。

### 7.2 Provider Run

```text
provider_run
- source_id
- source_release_id
- provider_binding_id
- provider_type
- cursor/range/page/partition
- discovered_count
- new_count
- stop_reason
- exhausted
- gap_reason
- checkpoint
- started_at
- finished_at
```

Sitemap 支持 Index 递归、gzip、多 Sitemap、lastmod、checkpoint；Archive/Pagination 支持重复页签名、连续 N 页无新增、最大页数、最大动作数、最大 wall time。

### 7.3 Dynamic Listing

先进入 Interaction Complexity Router：

- 简单 Load More / Scroll：Crawl4AI Simple Interaction；
- 多筛选器、多 Tab、每步提交 URL、循环/分支：Direct Playwright Stateful Interaction。

无论哪种 Browser 发现方式，结果统一写回 URL Inventory。

### 7.4 External Search Gap

Search 只产生候选 URL 与 Gap Evidence：

```text
SearchQueryTemplate
 -> SearchPartition
 -> Query Instance
 -> Provider Adapter
 -> Search Page Observation
 -> URL Normalize
 -> URL Identity Merge
 -> URL Inventory
```

停止原因至少包括：

```text
PROVIDER_EXHAUSTED
PROVIDER_RESULT_CAP
MAX_PAGES
MAX_WALL_TIME
COST_BUDGET_EXHAUSTED
N_PAGES_NO_NEW
REPEATED_PAGE_FINGERPRINT
PROVIDER_DEGRADED
POLICY_BLOCKED
CANCELLED
```

### 7.5 自适应分区

宽查询持续产生新 URL 但触及 Provider 上限时，按可解释维度细分：

```text
YEAR -> MONTH -> PATH_PREFIX -> 受控 TOPIC/CUSTOM
```

每个分区保存 parent、depth、split_reason、query_budget、new_url_count、marginal_new_rate，并受 `max_depth/max_partitions/cost_budget` 限制。

### 7.6 Coverage Evidence

```text
Provider Set
 + Time Range
 + Cursor/Range
 + Exhaustion Evidence
 + Provider Diff
 + Search Gap Evidence
 + Search Partition Tree
 + Known Gap
```

Web 后台展示 Provider 交并差、最早/最晚文章、时间缺口、Known Gap、Search Partition Tree、补洞收益。

任何排序、热度、用户偏好或 Embedding 信号都不得作为 `Coverage complete` 或“候选永久忽略”的证据。

## 8. Topic Watch、新来源发现与 Source Promotion

Topic Watch 是可选消费/发现能力，与正式全量采集分离。

### 8.1 数据流

```text
User Topic
 -> subscription_watch
 -> query_plan_release
 -> SearXNG/Search Adapters
 -> Candidate URL/Domain
 -> Safety + Policy + Scope Gate
 -> Temporary Fetch/Quality
 -> User Result
 -> source_candidate
 -> Probe
 -> Admin/User Approval
 -> Formal Source
 -> Historical Backfill
```

### 8.2 原则

- 搜索结果可以提示「有一个值得新增的博客」，不能直接成为 ACTIVE Source；
- 新域名必须执行 robots、SSRF、Probe、Sample Quality、预算估算；
- Promote 后才进入正式 Coverage 与长期 Incremental；
- Topic Watch 的个性化偏好不能改变已批准 Source 的 Backfill；
- Search Provider 结果 cap 必须显式记录，不伪装完整性。

## 9. URL 规范化、Document Identity、Story Cluster

### 9.1 URL Normalize

- host 小写；
- 去 fragment；
- 默认端口规范化；
- tracking query 去除；
- query 排序；
- trailing slash 按 Source Policy；
- 相对 URL 转绝对；
- canonical link 只作为 Identity Candidate；
- redirect chain 完整记录；
- Scope Policy 阻止越域和不允许路径。

### 9.2 Document Identity：强证据

优先证据：

```text
normalized URL
 -> redirect final URL
 -> rel=canonical
 -> CMS stable id / GUID
 -> exact Artifact hash
 -> normalized Canonical semantic hash
```

Identity 合并必须保留原始 URL、redirect、canonical 与 Provider provenance。

### 9.3 Story Cluster：弱证据关系

关系类型：

```text
SAME_DOCUMENT
SYNDICATED_COPY
SAME_STORY
RELATED
DISTINCT
```

只有强证据下的 `SAME_DOCUMENT` 可影响逻辑身份；其余只建立关系或 Cluster，保留每个独立 Document/Version。

近重复候选流水线：

```text
exact semantic hash
 -> SimHash/MinHash candidate
 -> title/time/reference features
 -> embedding ANN candidate
 -> pairwise evidence gate
 -> relation/cluster
 -> ambiguous => keep separate/manual review
```

Embedding 只能用于候选召回和软证据，不能单独触发 Document merge。

## 10. Page Type 与 Interaction Complexity Router

### 10.1 Page Type

在 Browser、LLM、Embedding 前分类：

```text
Provider Hint
 -> URL Rule
 -> MIME/Header
 -> Structured Metadata
 -> Cheap DOM Heuristic
 -> Manual Override
 -> LLM Exception(低比例)
```

类型：

```text
ARTICLE | DOC | INDEX | TAG | AUTHOR | HOME |
ASSET | API | AUTH | ERROR | UNKNOWN
```

### 10.2 交互分级

```text
L0 STATIC
- HTTP 即可得到完整内容

L1 RENDER_ONLY
- 需要 JS 渲染，无动作
- Crawl4AI Browser Render

L2 SIMPLE_INTERACTION
- 少量 scroll/load more/click
- Crawl4AI js_code/c4a_script + wait_for

L3 STATEFUL_INTERACTION
- 多步 click/wait/extract
- foreach tab/filter
- 分页后每步都要提交输出
- 有循环、条件、step retry、checkpoint
- Direct Playwright Stateful Engine

L4 UNSUPPORTED_OR_BLOCKED
- 登录墙/CAPTCHA/明确访问控制/无法合规自动化
- Known Gap / Manual Review
```

### 10.3 L2 抽象泄漏保护

L2 Recipe 静态检查：

```text
- action_count <= max_simple_actions
- no foreach
- no branch
- no nested loop
- no extract-after-each-action
- no per-item checkpoint
- no arbitrary long JS orchestration
```

出现 loop/branch/partial commit/checkpoint/复杂状态恢复需求即升级 L3。


### 11.1 公平调度

- Incremental 优先于 Backfill；
- 长等待任务 aging；
- 单 Source 最大并发占比；
- HTTP、Crawl4AI、Playwright、Search、LLM、Embedding 独立配额；
- 大站 Backfill 分片；
- Global Admission 在真实调用前检查 global/per-domain concurrency、QPS、Source budget、robots/policy、circuit state。

禁止对百万 URL 创建无界 `asyncio.gather`。

### 11.2 Backlog Priority

```text
P0 新增量正文、Freshness SLO 临近
P1 已检测正文变化的现有文档
P2 新历史文档 Canonical 主链
P3 可恢复 Browser/Repair
P4 新文档 Embedding/轻量增强
P5 历史摘要、重嵌入、低优先增强
```

每层必须有 aging。偏好/热度只能调整同层软优先级，不能删 URL Inventory。

## 12. Fetch Plane 与 Stateful Browser Engine

### 12.1 HTTP Worker

支持：

- gzip/br；
- redirect；
- connect/read/total timeout；
- response size limit；
- ETag / If-None-Match；
- Last-Modified / If-Modified-Since；
- Content-Type/Charset；
- Raw Snapshot；
- 精细错误分类。

### 12.2 Browser Worker 生命周期

```text
Worker Process
 -> long-lived Browser Process
 -> bounded BrowserContext Pool
 -> Page / Crawl or Interaction Run
 -> recycle by requests/memory/time/crash rate
```

默认隔离 BrowserContext，公开博客不依赖长期登录态。

### 12.3 Crawl4AI 路径

适用：

- L1 Render Only；
- L2 简单 Scroll/Load More/Click；
- 动态链接/媒体发现；
- HTML/Markdown Diagnostic Candidate。

需要每步独立抽取、循环状态、局部提交、step retry、checkpoint 时必须升级 L3。

### 12.4 Playwright Interaction Recipe DSL

复杂 Browser 任务按 typed DSL 表达：

```yaml
kind: browser_interaction
version: 1
entry:
  goto: "{{url}}"
  wait:
    locator: "main"
steps:
  - id: enumerate_keys
    extract_keys:
      locator: "[data-year]"
      key: "attr:data-year"
  - id: crawl_keys
    foreach_key: "{{steps.enumerate_keys.keys}}"
    body:
      - click_by_key:
          locator: "[data-year='{{item}}']"
      - wait_signature_change:
          target: ".post-list a"
          fingerprint: href_set
      - wait_stable:
          target: ".post-list a"
          quiet_ms: 500
      - extract_links:
          locator: ".post-list a"
      - assert:
          min_items: 1
      - checkpoint:
          key: "{{item}}"
limits:
  max_actions: 200
  max_wall_time_s: 180
  max_retries_per_step: 2
```

动态列表先提取稳定逻辑 key，再逐项重定位；不长期持有 ElementHandle。

等待优先级：

```text
业务数据签名变化
 -> Locator 进入期望状态
 -> count/text/href 集合稳定
 -> DOM/text quiet window
 -> 关键 API response
 -> navigation/DOMContentLoaded
 -> 极小固定 delay 作为最后边界
```

失败时保存 Step Timeline、截图、MHTML、Console/PageError/RequestFailed，并按需采样 Playwright Trace。

## 14. Extraction Portfolio、Quality Gate 与 Repair

### 14.1 Extraction Portfolio

1. Structured Metadata / JSON-LD；

至少检查：

- title；
- 正文长度；
- paragraph/heading 分布；
- link density；
- boilerplate；
- code/table/list 保留；

- Candidate Agreement；
- 分类冲突；
- 历史异常截断；
- 结构突变；
- 重复正文比例。

```text
DISCOVERED
```

```text
ALTERNATE_EXTRACTOR
```

## 15. Canonical IR、Markdown 与 Provenance

### 15.1 Canonical IR

```text
metadata:
  title
  author
  published_at
  updated_at
  canonical_url
  source_id
  document_id
  version_id
blocks:
  heading
  paragraph
  code
  list

```

统一 Renderer：

- heading 层级稳定；
- fenced code 保留语言；
- list/table/blockquote 正确；
- 图片保留 alt 与原 URL/归档 URL；
- 相对链接转绝对；
- Front Matter 保存 source/document/version/canonical/published/updated；
- Renderer 版本化。

### 15.2 Provenance Link

任何用户可见 citation URL 只能来自网络观察事实：

```text
provenance_link
- document_id
- version_id
- url_id
- observed_url
- redirect_final_url
- canonical_url
- artifact_id
- observed_at
- relation_type
```

规则：

- LLM 可选择已有链接或做链接分类；
- LLM 不得根据标题拼接 URL；
- LLM 不得生成不存在的 citation；
- LLM 不得覆盖 canonical/redirect 证据；
- Query/RAG 只能引用已有 `provenance_link`。

### 15.3 首个可用结果

Quality PASS/WARN 后立即：

```text

```

## 16. 增量同步与 Document Version

Freshness 分层：

```text
HOT / WARM / COLD
```

增量发现优先：

```text
RSS/API
 -> Sitemap lastmod/diff
 -> Archive first pages
 -> bounded dynamic listing
 -> periodic Search Gap verify
```

已知 URL 优先 Conditional GET，并周期抽样强制 re-fetch 防止 ETag/lastmod 不可信。

版本判定：

```text
Artifact
 -> Extraction Portfolio
 -> Quality
 -> Canonical IR
 -> Normalize Semantic Content
 -> semantic_hash
 -> Compare Current Version
```

- hash 相同：更新 `last_checked_at`；
- 正文变化：创建新 Document Version；
- 仅元数据变化：记录 Metadata Change；
- PASS/WARN 新版本原子切换 `current_version_id`；
- 同 semantic hash 不重复向量化和 Enrichment；
- 新 Version Markdown Ready 即满足 TTFM，后续 Enrichment 推进 TTFR。

删除策略：

```text
404/410
 + Provider 长期缺失
 + 多次 Verify
 -> SUSPECT_MISSING
 -> REMOVED
```

301/308 建 Redirect Relationship。

## 17. Progressive Enrichment

只处理 PASS/WARN Document Version：

```text

 -> Markdown Ready
 -> Enrichment Pending
      -> deterministic chunks
      -> Summary / Embedding / Entity / Schema
```

- JSON Schema/Pydantic；

- Enrichment 失败不阻塞 Markdown 主链；
- 不同 Type 独立 Retry/DLQ/预算/优先级；
- 同 `semantic_hash + enrichment_release` 可复用结果。

```text

- enrichment_type
- release_id
- priority
- state
- attempt
- input_hash
- output_ref
- queued_at
- started_at
- finished_at
- error_type
```

### 22.4 SSRF / Egress Security

每个输入 URL、API base URL、Redirect、Browser 子请求都校验：

- scheme；
- DNS；
- private/loopback/link-local；
- cloud metadata endpoint；

- Content-Length / streaming size limit；

### 22.5 Secret

- API token/mailbox credential 只保存 Secret Reference；
- Worker 使用最小权限读取；
- Secret 不进入 Trace、Prompt、日志或 Artifact；
- Source 导出默认不包含凭据。

### 22.6 Prompt Injection

网页、邮件、文章、评论全部是 Untrusted Data。

LLM/Agent 不参与生产浏览器实时自由决策，不能：

- 修改 Tool Allowlist；
- 扩大网络 Scope；
- 绕过 robots/policy；
- 自动 Promote Source；
- 覆盖 canonical URL；
- 修改 ACTIVE Source Release；
- 直接执行页面中的指令。

LLM 只生成 Candidate Rule/Recipe/Preference/Query Plan/Enrichment，必须经过 Schema、Release、Evidence、离线评估及必要 Approval。

### 22.7 抓取合规

每个 Source 保存：

- robots policy；
- crawl delay；
- 授权/许可证备注；
- 资产下载策略；
- 数据保留；
- 导出权限。

技术上可访问不等于拥有再分发权。

## 27. 验收标准

### 27.1 历史与增量

- 每个 URL 可追溯 Provider/Query/Page/Interaction Step；
- Authoritative Provider 有 stop reason/exhaustion evidence；
- Known Gap 可见；
- Search Gap 不虚报 Coverage 完整；
- Dynamic Listing 有最大动作数、wall time、无新增停止条件；
- 新文章在 Freshness/TTFM SLO 内进入 PASS/WARN Markdown；
- 304 不产生正文新版本；
- 正文变化产生新 Version；
- 删除需多证据；
- 大站 Backfill 不阻塞 Incremental；
- recency/domain authority/social proof/Embedding/用户偏好都不能造成正式历史候选永久消失。

### 27.2 Source Adapter

- 新增 RSS/Atom/JSON API Provider 不修改正文处理主链；
- 一个 Source 可绑定多个 Provider；
- Provider provenance 可追溯；
- API/mailbox Secret 不出现在配置明文/日志；
- 新域名只有经 Probe/Policy/Approval 才能成为 ACTIVE Source。

### 27.3 Browser 路由

- 能明确区分 L0/L1/L2/L3/L4；
- L2 出现 loop/branch/per-step extract/checkpoint 时能拒绝或升级 L3；
- L3 多步流程记录 Step、logical item、错误、完成条件、checkpoint；
- 动态列表使用稳定逻辑 key；
- 完成条件默认是业务状态，不是固定 sleep/networkidle；
- Worker 崩溃后 L3 可从逻辑 checkpoint 恢复；
- Failure Evidence 可获得；
- Recipe 超预算不能静默成功。

### 27.4 抽取、Markdown 与 Enrichment

- Fetch/Extract/Quality 独立；
- 多 Candidate 可回溯；
- Repair 有固定上限；
- 未通过 Quality Gate 不发布；
- Markdown 可回溯 Canonical IR；
- Renderer 升级可离线重建；
- Summary/Embedding 服务不可用时 Markdown 仍可发布；
- TTFM 与 TTFR 分开统计；
- Enrichment 可按 Type/Release 独立 Retry、Replay、预算控制。

### 27.5 Identity / Cluster

- Strong Identity 与 Story Cluster 分开；
- Embedding 相似不能单独触发 Document merge；
- 模糊候选保守分离；
- Cluster 成员保留独立 Source/作者/时间/Version；
- Cluster/Identity 支持版本化证据、人工 Split/Merge 与 Projection 重建；
- 搜索可折叠同 Cluster，但用户可展开全部来源。

### 27.6 Provenance

- 任一 citation 能回溯真实 observed URL、redirect/canonical 与 Artifact；
- LLM 不能生成、拼接或覆盖来源 URL；
- provenance 缺失的结果不得以“可验证引用”形式输出；
- Link/Canonical Drift 可诊断。

### 27.7 Topic Watch / Feedback

- Search Watch 结果不会直接改变正式 Coverage；
- 用户 dislike 某篇不会导致该 Source Backfill 删除文章；
- Preference/Query Plan 都有 Release，可回滚/重放；
- 个性化排序存在 exploration/diversity 预算；
- 新 Source Candidate 进入正式采集前必须 Probe/Approval；
- LLM 只能生成 Candidate Preference/Query Plan，不直接改 Source Release。

### 27.8 可复现与治理

- 全新容器加载相同 Release 可完成 Golden Corpus Replay；
- Runtime/Chromium/Crawl4AI/Playwright/Extractor/Renderer 版本明确；
- Identity、Cluster、Embedding、Preference、Query Plan、Serving Rank Release 明确；
- 同 Artifact + Release 能重建相同 Canonical/Markdown；
- Source/Recipe Candidate 必须过 Static Validation + Golden Replay + Canary + Approval。

### 27.9 检索

- Golden Query Dataset 可版本化；
- Retrieval Release 有 Recall@K/MRR/nDCG 基线；
- 无答案问题支持正确拒答；
- 同 Story 多来源能量化 duplicate-result rate 与 diversity；
- Retrieval 变更必须过 Offline Eval + Canary。

## 29. 组件定位

```text
HTTP          = 默认、高吞吐、低成本数据路径
Crawl4AI      = Browser Render + Simple Interaction + Dynamic Discovery + Diagnostic Candidate
Playwright    = Stateful Interaction Engine，负责复杂多步、Step/Checkpoint/Resume/Trace
Recipe DSL    = 将复杂交互变成平台能力，而非 1000 个站点脚本
Provider Adapter = 将 RSS/Sitemap/API/Newsletter 等统一为 URL Observation
SearXNG       = Search Gap / Topic Watch / Source Candidate，不是 Coverage Truth
Trafilatura   = Generic Main-content Candidate
lxml/BS4      = Metadata + DOM Heuristic + DOM Repair
Artifact      = 不可变网页事实
Quality       = 独立发布闸门
Canonical IR = Markdown 与后续 Projection 的结构真相
Document ID   = 强身份事实，不由 Embedding 相似直接合并
Story Cluster = 可重建关系 Projection，用于同主题折叠和多样性
Renderer      = Canonical IR -> Markdown，优先满足 TTFM
Provenance    = Citation URL 的事实证据，禁止生成模型创造来源
Enrichment    = Summary/Embedding/Entity 等异步慢路径
Preference    = 用户反馈派生 Projection，不影响 Collection Truth
Query Plan    = 版本化主题搜索计划，替代运行时自由改写 Prompt
Rank Release  = 软排序与资源优先级，决定 when/order，不决定 whether
PostgreSQL    = 身份/状态/版本/流程真相
S3/MinIO      = Artifact/IR/Markdown/Evidence 真相
Redis         = 运输与资源协调，不是业务真相
Evaluation    = Crawl + Identity/Cluster + Retrieval + Preference/Query Plan 的回归保护
```

系统核心不是选择一个“万能爬虫”，而是建立一个**以 Authoritative Coverage 和 Stable Identity 为基础、以 Provider Adapter 低成本扩站、按页面/交互复杂度路由、用不可变 Artifact 保存事实、用多 Candidate + Quality Gate 控制正文质量、用 Canonical IR 保证 Markdown 可重建、用 Step/Checkpoint/Semantic Wait/Trace 管理复杂 Browser、用幂等任务和公平调度支撑长期增量、用 Progressive Enrichment 提前交付首个可用 Markdown、用 Document Identity/Story Cluster 分离避免误去重、用 Provenance 约束保证所有引用可验证、并将 SearXNG/用户反馈/Query Plan 限定在 Discovery/Serving 平面**的长期知识库平台。

对于 1000+ 技术博客，绝大多数页面应停留在 HTTP 或 Crawl4AI 的低成本路径；只有真正具有多步、循环、每步抽取、局部提交和恢复需求的少量动态页面升级到直接 Playwright。通过 Source Adapter、Release、Coverage Evidence、稳定逻辑 key、语义等待、失败 Trace、Progressive Delivery 与 Provenance，可以同时获得历史完整性、增量 Freshness、低扩站成本、快速可用性和可审计知识事实；Topic Watch 与反馈闭环则作为可选上层能力，提高“找到用户想看内容”的效率，但始终不拥有删除正式采集事实的权力。
