# 博客知识库技术方案

## 1. 建设目标

建设一套面向 **1000+ 技术博客、工程博客、技术文档站和公开 Newsletter** 的长期采集与知识库平台，可平滑扩展到数千站点、百万到千万级文章。

平台必须同时满足：

1. **全历史回填**：尽可能完整发现每个已批准 Source 的历史文章，并能解释发现通道、覆盖率、缺口、截断与停止原因；
2. **持续增量同步**：发现新文章、正文修改、元数据变化、URL 迁移、重定向、删除与重发布；
3. **动态归档覆盖**：支持静态分页、Load More、无限追加、Virtual Scroll/窗口化渲染等归档形态；
4. **Markdown 稳定可重放**：保存不可变 Raw Artifact，经版本化 Cleaner、Extractor、Canonical IR、Renderer 生成最终 Markdown；
5. **技术内容保真**：代码块、表格、公式、Mermaid、列表、引用、脚注、图片说明不能被通用降噪算法静默删除；
6. **低成本扩站**：新增站点优先通过 Source Profile、Provider、Recipe、Traversal Policy 配置完成，不维护 1000 份独立爬虫脚本；
7. **Web 可运营**：支持站点接入、审批、Backfill、Incremental、Coverage、Frontier、Dynamic Archive、质量、成本、诊断、暂停、恢复、重跑、灰度与审计；
8. **任务可恢复**：Provider Run、Dynamic Archive Run、Task、Attempt、URL、Artifact、Candidate、Document、Version 全链路持久化，Worker/Runtime 崩溃可恢复；
9. **可搜索/RAG**：支持 BM25、向量和混合检索，并可回溯原文、版本、Source、抓取证据与处理 Release；
10. **主链不依赖 LLM**：LLM 仅用于可选 Repair/Enrichment，不参与 Coverage、URL 身份、正文存在性、版本真相、Freshness 或权限边界的最终判定。

### 1.1 核心 SLO

- **Coverage**：每个 Source 可查看 Provider Inventory、Completion Attestation、Known Gap、Backfill Stop Reason；
- **Dynamic Archive Coverage**：可查看归档模式、滚动/分页步骤、唯一条目增长、结束证据、预算耗尽与模式漂移；
- **Freshness**：新文章/更新从发布或发现到 PASS Markdown 的 P50/P95/P99 延迟；
- **TTFM**：URL 首次发现到首个可用 Markdown 的时间；
- **Extraction Quality**：标题、正文、代码、表格、列表、链接、图片说明、公式召回率与噪声率；
- **Protected Structure Recall**：受保护技术节点在 Candidate/IR 中的保留率；
- **Multilingual Retention**：中文、日文及中英混排正文保留率；
- **Reliability**：Task 成功率、Retry、DLQ、Queue Age、Lease Recovery；
- **Replayability**：相同 Raw Artifact + 相同 Release 得到相同派生结果；
- **Provider Integrity**：partial、cache hit、预算耗尽、浏览器滚到底不能被误报为完整枚举；
- **Validator Integrity**：业务 validator 必须绑定具体 Raw Artifact/body hash；
- **Browser Efficiency**：HTTP Fast Lane 命中率、Browser avoided、Browser 单文档/单新增 URL 成本；
- **Fairness**：大型 Backfill/Dynamic Archive 不得长期饿死 Incremental、Revalidation、Repair、小站；
- **Agentic Safety**：越界导航、Policy Deny、Prompt Injection、Secret 泄露可监控、可审计；
- **Agentic Progress**：Agent 循环、停滞、无新增 Observation 必须由平台硬终止，不能依赖模型自行纠错；
- **Recipe Stability**：Production Recipe 的 selector 命中率、歧义率、mutation survival、deterministic replay 成功率可量化。

## 2. 核心设计原则

1. **Coverage First**：先构建可解释 URL Inventory，再抓正文；
2. **Authoritative First**：官方 CMS/API、Sitemap、Feed、静态 Archive 优先；
3. **Observation Before Selection**：发现事实先落库，再 Normalize、Scope、Classify、Dedup；
4. **Successful Return != Provider Complete**：HTTP 200、非空结果、`success=true`、cache hit、浏览器正常退出都不能自动代表 Provider 完成；
5. **Completion Must Be Attested**：只有具备可验证结束语义的 Provider Adapter 才能声明完整；
6. **Runtime Result Is Evidence, Not Truth**：Crawl4AI/Playwright/Browser Use 负责执行，不拥有 Coverage、Version、Freshness、Markdown 真值；
7. **Dynamic DOM Is Derived Evidence**：Virtual Scroll 合并 HTML、滚动后 DOM 不能覆盖原始网络/初始 DOM Evidence；
8. **Stable Item Identity Before Text Dedup**：归档条目优先以规范化 URL/稳定 ID 去重，不以可见文本 hash 作为主键；
9. **Discovery / Revalidation / Fetch / Clean / Extract / Quality / Canonicalize / Projection 分离**；
10. **HTTP First, Browser Slow Lane**；
11. **Snapshot First**：Provider Evidence / Raw Artifact 先保存，再生成派生物；
12. **Candidate Portfolio, Not Single Extractor**；
13. **Protected Structures Are First-Class**；
14. **Language Assumptions Must Be Explicit**；
15. **Canonical IR First, Markdown as Projection**；
16. **Recipe, Not 1000 Site Scripts**；
17. **Persistent Frontier, Not In-Memory Traversal**；
18. **Semantic Checkpoint, Not Browser Session**：浏览器 session 是临时执行状态，恢复依赖平台持久 checkpoint；
19. **Idempotent + Recoverable**：幂等键、Lease、Fencing Token、Checkpoint、Inbox/Outbox；
20. **Fair by Default**：Incremental、Revalidation、Repair 预留容量；
21. **Bounded Concurrency Everywhere**；
22. **No Silent Degradation**：过滤、截断、partial、预算耗尽、cache fallback、归档早停、降级都有 typed reason；
23. **Correlate by Identity, Never by Position**；
24. **Config Is Capability**：高能力配置必须经过 Capability Firewall；
25. **Runtime Cache Is Disposable**；
26. **Derived Artifact Never Overwrites Evidence**；
27. **Weak Freshness Signal Cannot Close Truth**；
28. **Validator Must Bind To Artifact**；
29. **Same URL Does Not Imply Same Representation**：不同 locale/Cookie/UA/Proxy/session/Browser Profile 使用 `fetch_variant_key` 隔离；
30. **Offline Means No Network**：离线 Replay 由平台 Artifact + egress deny 保证；
31. **Explicit Runtime Config**：生产 Attempt 不依赖 Runtime 默认值；
32. **Agentic Repair Is Proposal, Not Truth**：Agent 只提出诊断、Observation、Recipe Candidate；
33. **Ephemeral Element Identity**：highlight index/CDP node id 只属于当前观测，Production Recipe 只能引用稳定 SelectorBundle；
34. **Agent Replay Is Diagnostic**：Browser Use history replay 不等于确定性 Recipe Replay，也不等于 Task Recovery；
35. **One Mutating Action, One State Boundary**：会改变 DOM/URL/target 的动作后重新采样；
36. **Web Content Is Untrusted Prompt Input**；
37. **Agentic Runtime Is Hermetic**：显式 Tool/Domain/IP/egress/Profile/Permission 边界；
38. **Soft Agent Heuristics Are Not Hard Limits**：模型内部 loop/planning/replan 提示仅作 advisory signal；硬停止由平台实现。

### 5.4 Capability Firewall

Dynamic Archive 额外限制：

- `container_selector`/`item_selector` 必须来自审批后的 SelectorBundle；

- Crawl4AI `VirtualScrollConfig` 的参数必须经 Config Compiler 二次 clamp；
- 网页内容或模型输出不能动态扩大上述权限。

## 6. 全历史 URL 发现与 Coverage

### 6.1 Provider 顺序

1. CMS/API；
2. Sitemap/Sitemap Index；
3. RSS/Atom；
4. Static Archive/Pagination/Tag/Category；
5. Dynamic Archive：Load More / Infinite Append / Virtual Replace；
6. 静态链接图；
7. Common Crawl Index；
8. Wayback；
9. Crawl4AI URL Seeder/Domain Mapping/Deep/Adaptive 作为补洞与加速。

任何单一 Provider 都不能自动证明“全历史完整”。Agentic Browser 只能产生 Observation 或提示潜在入口，不能成为 Completion Authority。

### 6.2 Observation 与 Inventory

每条发现先写：

```text
url_observation(
  observation_id, source_id, provider_id, provider_run_id,
  provider_step_id,
  observed_url, observed_at, provider_timestamp,
  provider_metadata, provider_evidence_uri
)
```

然后统一执行：

```text
Normalize -> Scope Check -> MIME Hint -> URL Identity -> Dedup -> Frontier Upsert
```

### 6.3 Provider Completion Attestation

Provider Run 保存 checkpoint/cursor/shard、items_seen、unique_urls、status、completion_type、stop_reason、truncated、budget_exhausted、known_gap、provider_release。

统一 completion type：

```text
ATTESTED_COMPLETE
HEURISTIC_EXHAUSTED
PARTIAL
FAILED
BLOCKED
```

只有 Adapter 的协议级结束条件满足时才允许 `ATTESTED_COMPLETE`。

HTTP 200、非空结果、达到 limit、cache hit、Deep Crawl 达到深度、Agent 暂时无新 URL、Virtual Scroll 正常返回、`scroll_count` 用尽、滚动几何暂时到底、LLM 报“完成”都不能证明完整。

### 6.4 Sitemap / Common Crawl / Wayback

- Sitemap Index 拆 durable shard；
- Sitemap 增量使用 Conditional GET，`lastmod` 仅是变化线索；
- Common Crawl/Wayback 固定 index/release、保存查询 Evidence、流式处理；
- Archive 出现不代表当前仍有效，Archive 缺失也不能证明文章从未存在。

### 6.5 DynamicArchiveProvider

动态归档统一分四种执行模式：

```text
STATIC_PAGINATION
LOAD_MORE
INFINITE_APPEND
VIRTUAL_REPLACE
```

Onboarding 先用小预算 Probe：比较初始/滚动后的稳定 article key 集合、DOM child count、scrollHeight、next link、network request/cursor，优先识别底层 JSON/API；若存在权威 API，晋升为 API Provider，避免长期依赖 Browser。

#### 6.5.1 运行策略

- `STATIC_PAGINATION`：HTTP/HTML 页码优先；
- `LOAD_MORE`：确定性 Browser Recipe 点击受控按钮；
- `INFINITE_APPEND`：Crawl4AI `scan_full_page` 或平台 Recipe，按 article identity 增量收集；
- `VIRTUAL_REPLACE`：Crawl4AI `VirtualScrollConfig` 可作为执行器，保存窗口被替换前的 Observation；
- `UNKNOWN`：进入有限 Probe/Recipe Studio，不能无限探索。

#### 6.5.2 Virtual Scroll 的平台边界

Crawl4AI 当前实现会比较滚动容器前后 `innerHTML`，把“无变化 / 追加 / 替换”分支处理；发生替换时保存旧窗口，最后按归一化 `innerText` 去重直接子元素并重写容器 HTML。

平台不能继承以下语义为真相：

1. 纯文本去重可能把“相同标题、不同 href”的文章合并；
2. `startsWith(previousHTML)` 会受随机属性、计数器、广告等 DOM 抖动影响；
3. 固定 `wait_after_scroll` 不能证明新数据已加载；
4. `scroll_count` 是预算，不是完整性证明；
5. 滚动几何到底不等于服务端 cursor 已耗尽；
6. 合并后的 `container.innerHTML` 是 Derived Artifact，不是原始页面快照；
7. Runtime 内 Virtual Scroll 出错后仍可能继续普通 crawl，因此 Runtime success 不能推进 Completion。

平台 URL 去重主键必须优先：

```text
normalized_article_url
> source item id / data-id
> title + published_at + author composite
> structural fingerprint
```

文本 hash 只作为弱辅助证据。

#### 6.5.3 Dynamic Archive Step Evidence

每一步保存：

```text
dynamic_archive_step(
  run_id, step_no, observed_at,
  scroll_top, client_height, scroll_height,
  item_count, unique_item_count, new_item_count,
  item_key_set_hash, first_item_key, last_item_key,
  dom_fingerprint, network_cursor_hint,
  end_marker_seen, wait_condition,
  dom_or_screenshot_artifact_id,
  stop_reason
)
```

典型 stop reason：

```text
END_MARKER
CURSOR_EXHAUSTED
SERVER_TOTAL_REACHED
NO_NEXT_PAGE
STABLE_NO_NEW_ITEMS
SCROLL_GEOMETRY_END
SCROLL_BUDGET_EXHAUSTED
WALL_TIME_EXHAUSTED
NETWORK_BUDGET_EXHAUSTED
CONTAINER_NOT_FOUND
SELECTOR_AMBIGUOUS
WAIT_TIMEOUT
VIRTUAL_SCROLL_RUNTIME_ERROR
POLICY_DENIED
```

`STABLE_NO_NEW_ITEMS` 与 `SCROLL_GEOMETRY_END` 默认只能形成 `HEURISTIC_EXHAUSTED`。

#### 6.5.4 持久化断点

不保存“浏览器 session 可继续”的假设，保存语义 checkpoint：

```text
last_unique_item_key
oldest_published_at_hint
unique_item_count
step_no
last_item_key_set_hash
last_cursor_hint
recipe_release
fetch_variant_key
```

崩溃后创建新 Attempt：若有 cursor/API 直接恢复 cursor；否则按确定性 Recipe 快速重放到 checkpoint 附近。

### 6.6 Coverage 页面

每 Source 维护：

- provider_inventory / provider_attestation；
- historical_time_range；
- observed/fetchable/article count；
- dynamic archive mode、unique item、oldest date、step、completion/stop reason；
- Sitemap/CMS/RSS/Archive/Common Crawl/Wayback URL 集合差异；
- known/unresolved gap；
- backfill_stop_reason；
- forced deep scan 漏洞发现数。

页面必须能回答“为什么认为完成/未完成”。

## 7. URL Identity、Canonical 与 Persistent Frontier

### 7.1 URL 三层身份

```text
observed_url   Provider 实际看到的 URL
normalized_url 平台规则归一化后的 URL
canonical_url  经多证据判定的文章主 URL
```

`rel=canonical` 不是绝对真相。Normalize 只做安全规则；query、path 大小写、www/apex、HTTP/HTTPS 合并必须 Source-specific。

### 7.2 去重

```text
exact URL
-> redirect/canonical alias
-> stable archive item id
-> raw body hash
-> semantic hash
-> SimHash/MinHash
```

近重复只建立关系，不静默删除版本。

### 7.3 Frontier

```text
url_id, source_id, normalized_url, canonical_url, fetch_variant_key,
state, priority, next_action_at, last_discovered_at,
last_fetch_at, last_verified_at, retry_count,
lease_owner, lease_until, fencing_token
```

状态覆盖 DISCOVERED、DUE_FOR_REVALIDATION、FETCH_REQUIRED、FETCHING、FETCHED、EXTRACT_PENDING、PASS、REPAIR、REVIEW、DELETED、BLOCKED、DEAD。

### 7.4 公平调度与 Backpressure

优先级：

```text
P0 incremental-hot
P1 revalidation
P2 new-source-backfill
P3 dynamic-archive-continuation
P4 historical-gap
P5 repair/replay
```

按 source/host/domain/workload Weighted Fair Queueing。Redis Lua 维护 host token bucket、source/domain/browser semaphore、dynamic-archive quota、agentic token/cost quota。

Queue Age、DB latency、S3 backlog、Browser 饱和、429/503、成本接近预算时，先暂停低优先级 historical discovery/agentic repair，保留 Incremental/Revalidation 容量。

## 8. Revalidation Engine 与增量同步

### 8.1 增量入口

CMS revision、Sitemap `lastmod`、RSS `updated`、Webhook、Archive 新链接、Dynamic Archive head scan、定时 Revalidation、强制完整刷新、人工重抓、Provider Reconcile。

### 8.2 Revalidation Ledger

保存 `last_fetch_at/last_verified_at/last_changed_at`、ETag/Last-Modified、raw/semantic hash、head fingerprint、validator strength、validator_artifact_id、validator_body_sha256、origin、binding state、validation method/result/reason、runtime cache status、consecutive_304、forced_refresh_due_at、false-negative、source trust score。

### 8.3 证据强度

- **STRONG**：CMS revision；使用绑定当前 authoritative Artifact 的 validator 得到标准 304；完整 GET 后 body hash 一致；
- **MEDIUM**：validator 变化、Sitemap/RSS 更新时间变化；
- **WEAK**：head fingerprint、长度、link graph、归档卡片、局部 metadata、Agent/LLM 判断未变化。

只有符合 Source Policy 的强证据才能推进 `last_verified_at`。

### 8.4 Validator Binding Invariant

1. 只有与完整网络响应一起得到的 validator 才能绑定该 Raw Artifact；
2. HEAD/弱校验得到的新 validator 只能记录 `UNBOUND_HINT`；
3. 304 只有在请求 validator 已绑定当前 authoritative Artifact/body hash 时才是 STRONG；
4. Runtime cache weak match 后更新的 validator 不得直接导入业务真相；
5. Artifact 被新版本替代后旧绑定进入历史或失效；
6. 定期完整抽样校验 false negative，并动态调整 trust score。

### 8.5 Dynamic Archive 增量高水位

保存：

```text
newest_known_article_key
newest_known_published_at
archive_head_fingerprint
recent_known_item_keys
last_incremental_archive_run
```

增量从归档顶部开始。出现连续 `K` 个已知稳定 item key，并且 Source 的时间/排序单调性政策满足时才 early stop。

防漏策略：

- 置顶文章单独识别，不把“第一条已知”当停止条件；
- 定期 forced deep archive scan；
- Sitemap/CMS/RSS 多 Provider Reconcile；
- 对历史位置插入、乱序严重的 Source 降低/关闭 aggressive early-stop；
- forced deep scan 若持续发现漏 URL，自动降低 Dynamic Archive trust。

Dynamic Archive 只发现 URL/迁移线索；已知文章正文变化仍由 Revalidation Engine 判断。

## 9. HTTP、Browser 与 Runtime Cache

### 9.1 HTTP Fast Lane

普通文章优先 `httpx/aiohttp`，记录 redirect、response headers、Content-Type、encoding、validator、原始字节。正文质量满足条件即不启 Browser。

### 9.2 Deterministic Browser Slow Lane

仅 HTTP 空壳、JS 渲染、有限交互、Shadow DOM/iframe、动态归档或 Source Recipe 指定时升级。生产默认使用长期 Browser Pool + **确定性 Recipe Executor**。

Dynamic Archive Browser 与 Article Fetch Browser 分池，避免大归档滚动拖垮正文 Freshness。

### 9.3 Agentic Browser Repair / Recipe Studio

只在确定性路径失败、Source onboarding 探索、长期 REPAIR/REVIEW 或 Operator 诊断时启用：

```text
HTTP / deterministic Browser failed
        |
        v
Agentic Browser Repair Sandbox
        |
        +--> BrowserState(DOM/AX/screenshot/URL)
        +--> bounded structured actions
        +--> Browser Gateway policy enforcement
        +--> Agentic Progress Guard
        +--> immutable trace/evidence
        |
        v
Selector Compiler + Recipe Compiler
        |
        v
Recipe Candidate
```

运行绑定 source/url/fetch_variant、Browser Use/Chromium/model/prompt/tool/security/observation/progress-guard release，并设置 max steps/actions/page/tab/wall-time/token/cost/artifact bytes 硬预算。

平台在 Agent Loop 外部维护不可被 prompt 修改的 `Agentic Progress Guard`，对重复动作、停滞状态、state revisit、连续无新 URL/Observation、wall-time/token/cost 做硬终止。

典型 typed reason：

```text
AGENT_ACTION_LOOP
AGENT_STATE_STAGNANT
NO_NEW_OBSERVATION_PROGRESS
REPEATED_STATE_CYCLE
PLANNING_STALL
MAX_STEPS
WALL_TIME_EXHAUSTED
TOKEN_BUDGET_EXHAUSTED
COST_BUDGET_EXHAUSTED
POLICY_DENIED
CROSS_SCOPE_BLOCKED
```

Browser Use 自带 loop/replan 提示只作 advisory evidence，不得覆盖平台 hard stop。

### 9.4 Selector Compiler 与 Recipe Promotion

Browser highlight index、CDP node id/backend node id 只在单次观测中有效。Agent evidence 编译为稳定 `selector_bundle`：

```text
semantic_role
accessible_name
stable_attributes / data_attributes
id_name_candidates[]
stable_text_anchor
css_candidates[] / xpath_candidates[]
ancestor_constraints[] / frame_scope
expected_cardinality
fallback_order[]
selector_fingerprint
fixture_match_rate
live_sample_match_rate
ambiguity_rate
mutation_survival_rate
selector_strategy_release
```

Production Recipe 只能引用 `selector_ref`。无法把临时元素引用编译成无歧义 selector 时返回 `UNCOMPILABLE_ELEMENT_REFERENCE`。

Promotion Gate：

```text
Agentic Evidence
 -> Selector Compiler
 -> Recipe Compiler
 -> Recipe Candidate
 -> Schema / Static / Security Validation
 -> Selector Ambiguity Validation
 -> Deterministic Fixture Replay

 -> Shadow
 -> Source Canary
 -> Human/Policy Approval

```

若仍需 LLM 实时决策，则不能晋升生产。

### 9.5 Runtime Cache Policy

业务层只暴露：

```text
AUTHORITATIVE_FETCH
VALIDATE_THEN_FETCH
REPLAY_FROM_ARTIFACT
RUNTIME_CACHE_WARMUP
DIAGNOSTIC_CACHE_READ
```

Crawl4AI `CacheMode`、legacy flags、Smart Cache 真实语义由 pinned release Contract Test 验证。Runtime cache 仅优化执行，不能推进 Coverage/Freshness/Version/validator 真相；Runtime cached Markdown/Extracted Content 永远不直接成为 canonical。

Runtime cache namespace 至少按 `source_id + fetch_variant_key + runtime_release` 隔离。

## 10. Raw Artifact、Extraction 与 Markdown

### 10.1 Raw Artifact

每次真实网络抓取生成不可变：

### 10.2 Protected Structure + Extraction Portfolio

```text

```

## 11. Document、Version、删除与迁移

- `Document` = 逻辑文章；`DocumentVersion` = 业务正文版本；`RawArtifact` = 抓取证据；
- raw hash 不变不创建新 Version；raw 变但 semantic hash 不变只更新证据/metadata；semantic hash 变才创建新 Version；
- 保存完整 redirect chain，旧 URL 建 alias；
- 单次 404/5xx 仅进入 TOMBSTONE_CANDIDATE，多次确认/provider reconcile 后才 DELETED_CONFIRMED；
- 相同正文出现在新 URL 时保留独立 Observation，再建立 relation；
- Archive 列表删除链接本身不是删除正文的充分证据。

### 12.1 Task / Attempt

### 12.3 Browser/Dynamic Archive 恢复语义


## 16. 安全与合规

### 16.1 SSRF / Browser 隔离

所有 URL Fetch 前解析 DNS；禁止 loopback/private/link-local/metadata；redirect 每跳重验；防 DNS rebinding；Approved Host/Path allowlist。

Agentic Browser 运行在独立非 root 容器/Pod，最小文件系统权限与 egress policy；临时 profile；禁下载/upload/file/evaluate/arbitrary CDP/clipboard；Browser Permission 最小化；Storage State 按 Source/fetch variant 隔离、加密、TTL。

### 16.2 Robots / Terms

默认遵守 robots、保存 snapshot/release；429/Retry-After 优先；登录、付费墙、明确禁止自动化的 Source 单独审批；CAPTCHA/付费墙不由 Agent 自动绕过。

Dynamic Archive 不得通过无限滚动或并发放大绕过 host rate limit；滚动触发的 XHR 同样纳入 Source/Host 配额。

### 16.3 Prompt Injection

DOM、AX、截图、隐藏文本、下载内容都是不可信输入。System task/Tool Policy/Source Scope/Secret Policy 来自版本化配置并与网页内容隔离；页面不能扩大 Tool、Domain、Secret、JS/CDP/File 权限。维护恶意 Fixture Corpus 做回归。

## 22. 最终推荐架构与不可破坏边界

最终采用：

> **PostgreSQL Truth Store + S3/MinIO Immutable Artifact + Redis Streams Durable Transport + Declarative Source/Profile + Multi-Provider Discovery + DynamicArchiveProvider + Persistent URL Inventory/Frontier + Persistent Archive Step/Checkpoint + Coverage Completion Attestation + Revalidation Engine + Validator-to-Artifact Binding + Fetch Variant Isolation + HTTP First / Deterministic Browser Slow Lane + Crawl4AI Runtime Service Plane + 可选 Hermetic Agentic Browser Repair / Recipe Studio + Agentic Progress Guard + Selector Compiler + Recipe Compiler + Deterministic Recipe Promotion Gate + Cache Policy Compiler + Runtime Contract Release Gate + Extraction Portfolio + Canonical IR + Deterministic Markdown + OpenSearch/pgvector + Web Admin。**

不可破坏边界：

- Provider 返回不是 Coverage 真相；
- **Virtual Scroll/scan_full_page 滚动结束不是历史完整性证明；**
- **Crawl4AI Virtual Scroll 的文本合并去重不能作为平台文章身份主键；**
- **Virtual Scroll 合成 HTML 是 Derived Artifact，不能覆盖初始 Raw Evidence；**
- **浏览器 session 不是 durable checkpoint；Dynamic Archive 恢复依赖持久语义 checkpoint；**
- **`scroll_count`/wall-time/network budget 耗尽必须 PARTIAL，不得伪装 COMPLETE；**
- Runtime cache 不是 Freshness、Version、Replay 真相；
- 同 URL 不等于同表示，cache 不跨 fetch variant 盲目复用；
- Runtime cached Markdown/Extracted Content 不是 canonical；
- weak freshness/head fingerprint/归档卡片不能证明正文未变；
- validator 必须绑定具体 Raw Artifact/body hash；
- Raw Artifact 不可变，所有清洗/抽取/Markdown 可重放；
- Browser 是昂贵慢路径，不是默认路径；
- LLM/Agentic Browser 只能提出诊断、Observation 或 Recipe Candidate；
- Browser highlight index/CDP node identity 不是 Production Selector；
- Browser history replay 不是 Recipe Replay，也不是 Task Recovery；
- 任何 DOM/URL/target 变化后重新采样；
- 模型内部 loop/planning/replan 等提示是 advisory，循环、停滞、无进展由平台 Agentic Progress Guard 强制终止；
- 网页内容是不可信 prompt 输入，不能扩大 Capability；
- Agentic Browser 必须显式 Tool allowlist、Source Scope、IP/私网阻断、容器 egress、临时 profile、最小权限；
- Agent extracted/final text 不是文章正文真相；
- Coverage、Version、Freshness、Validator Binding、Markdown 的最终真相始终在平台层。
