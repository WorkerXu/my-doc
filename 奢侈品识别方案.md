# 奢侈品识别方案

## 1. 目标与边界

系统目标不是“找最像的商品”，而是把雷小安、奢当家、腕表之家、小迈步、爱回收等来源的记录归一到**同一个官方商品变体（Official Variant）**。

第一阶段覆盖腕表与箱包，历史数据约 100 万–1000 万条。腕表已有部分品牌/系列/型号标准库；箱包主档不完整，因此系统必须同时支持 **Entity Linking** 与 **Entity Discovery**。

核心原则：

> **Precision >> Recall。宁可输出 UNKNOWN，也不能把不同官方变体错合并。**

只有定义官方变体的关键属性兼容时，才允许自动认定 `SAME_VARIANT`。系统不做真假鉴定；成色、价格、库存、卖家、单件序列号、保卡状态等属于 Offer / 单件属性，不定义官方商品变体。

机器成功识别后必须形成一致业务结果：

```text
Source Product 当前状态
+ Source → Canonical 当前识别关系
+ Immutable Recognition Record
+ Pending Review 任务/事件
```

这四个副作用必须原子、幂等、可重放，不能出现“模型判断正确但业务状态只写了一半”。

## 2. 核心实体、关系与标识符语义

```text
Brand
  └── Product Family / Series
       └── Product Model
            └── Canonical Variant
                 └── Source Product / Offer
```

关系至少包括：

```text
SAME_VARIANT
VARIANT_OF
SAME_MODEL
SAME_SERIES
VISUALLY_SIMILAR
UNKNOWN
```

只有 `SAME_VARIANT` 可以生成自动 Recognition。

Canonical Variant 状态：

```text
ACTIVE         已验证，可参与自动挂接
PROPOSED       新发现，等待证据/治理
SPLIT_PENDING  疑似一个 Canonical 混入多个 Variant，冻结新自动挂接
MERGE_PENDING  疑似多个 Canonical 实为同一 Variant，冻结相关实体新自动挂接
RETIRED        历史实体，不再接受新自动挂接
MERGED         已治理合并到唯一 surviving Canonical
SPLIT          已确认 one-to-many 拆分，仅保留历史身份与 lineage
TAINTED        关键事实污染，暂停自动挂接
```

`MERGED` 是 many-to-one，可 redirect 到唯一 survivor；`SPLIT` 是 one-to-many，旧 Canonical 不能自动 redirect 到任一 child，必须重新解析。

### 2.1 Identifier Namespace

统一采集：

```text
reference_full / style_code / mpn
gtin / ean / upc
merchant_sku
product_group_id / item_group_id
variant_dimension_keys / variant_dimension_values
barcode_symbology / payload / checksum
market
identifier_namespace / identifier_owner / identifier_scope
identifier_source / source_field_path / confidence
```

规则：

- 高可信完整 Reference / Style Code 精确一致：最强 Identity Anchor 之一。
- 官方品牌来源中的 `mpn` 经品牌规则/格式验证后可作为 Manufacturer-grade Identifier。
- 第三方商家 `sku` 默认属于 merchant namespace，不得直接升级为官方 Reference / Style Code。
- `productGroupID / item_group_id / inProductGroupWithID` 是父商品组/变体组关系标识，不是 Variant Identity Anchor。
- `ProductGroup.hasVariant / Product.isVariantOf / variesBy / variant_option` 是高价值 Variant Boundary Evidence。
- 高可信、校验通过的 GTIN/EAN/UPC：Strong Positive + Exact Retrieval Key。
- 不同 GTIN 默认 `POSSIBLE_CONFLICT`；只有品牌/市场规则证明该语境下 GTIN 与本系统 Variant 1:1 时才升级 Hard。
- Vintage 必须考虑旧编码、地区站点差异、包装变化与历史规则。

维护 `identifier_semantics_policy`，最小粒度：

```text
brand × market × source_group × field_path × identifier_type
```

策略声明 `MANUFACTURER_ID / MERCHANT_ID / GROUP_ID / INSTANCE_ID / UNKNOWN`，并声明是否允许 Exact Retrieval、Strong Positive、Hard Conflict、Auto Activation。

## 3. 标准 Schema 与 Hard Constraint

每个属性断言保存：

```text
raw_value
normalized_value
canonical_value_id
extractor / extractor_version
source_type / source_id / source_url
evidence_span / image_bbox
extraction_confidence
validation_status / validation_confidence
validation_record_id
fact_scope
effective_from / effective_to
observed_at / content_hash
market_scope / region_scope
```

**Extraction Confidence 与 Validation Confidence 必须分开。**“模型很确定自己抽到了 `blue`”不等于“`blue` 对这个商品确实正确”。同样，**“当前实物确实是 blue”也不等于“这个官方 Variant 的出厂规格就是 blue”**。Hard/Strong 的定义默认指 `OFFICIAL_VARIANT_SPEC` 语义；二手实物观察值必须先做 Item-State / Origin 判定。

### 3.1 腕表

| 字段 | 默认策略 |
|---|---|
| brand | Hard |
| series / family | Blocking + Strong；品牌规则可 Hard |
| subseries / model | Strong |
| official_reference_full | Hard；最强身份字段之一 |
| reference_base | Retrieval / Strong，默认不能代替 full |
| gtin/ean/upc | Strong；条件 Hard |
| case_diameter_mm | Hard |
| case_material | Hard |
| dial_color | Hard；仅官方 Variant Spec 语义 |
| dial_type | 定义独立变体时 Hard；仅官方 Variant Spec 语义 |
| bezel | 定义独立变体时 Hard；仅官方 Variant Spec 语义 |
| bracelet_or_strap | 条件 Hard；当前实物表带/表链不得直接当出厂规格 |
| caliber / movement | 代际/变体区分时 Hard，否则 Strong |
| functions | 变体区分时 Hard |
| edition / generation | Hard |
| serial_number | 单件属性 |
| condition / price | Offer 属性 |

Reference 保存 `raw / normalized / base / full / parts / brand_rule_version`。默认以 `reference_full` 为准；只有品牌规则明确证明后缀不定义 Variant 时才允许 base reference 参与自动合并。

### 3.2 箱包

| 字段 | 默认策略 |
|---|---|
| brand | Hard |
| family / series | Blocking + Strong |
| model / style | Strong |
| official_style_code | Hard；最强身份字段之一 |
| gtin/ean/upc | Strong；条件 Hard |
| official_size | Hard |
| material | Hard；指官方 Variant Spec |
| official_color | Hard；指官方 Variant Spec |
| hardware | Hard；指官方 Variant Spec，当前实物五金需 Origin Gate |
| pattern / print | Hard |
| edition / collaboration | Hard |
| season / year / generation | 官方由其区分时 Hard |
| serial / date_code | 单件/生产证据 |
| condition / price | Offer 属性 |

图片颜色不直接成为 Hard Constraint；灯光、白平衡、老化、修图会造成偏差，视觉颜色只做 Soft Evidence。

### 3.3 两级标准化

```text
material_group = ROSE_GOLD
material_brand_value = ROLEX_EVEROSE_GOLD

color_group = BLACK
color_brand_value = CHANEL_NOIR
```

通用层用于跨平台召回，品牌精确层用于 Variant 判定，避免把品牌专有语义压平。

## 4. Evidence、来源独立性、事实状态与时间版本

来源等级：

```text
T0  品牌官网、官方目录、官方标识体系
T1  已验证内部标准库、授权/专业数据库
T2  高质量专业平台、可信二手平台
T3  普通电商、聚合站、搜索网页
```

可信度按“来源 × 属性 × 市场/时间”定义，而不是整站一刀切。

### 4.1 来源独立性

维护 `source_group_id / syndication_group_id / content_fingerprint / image_hash_group_id / upstream_hint`。

多个 URL 不等于多个独立来源。复制同一 feed、相同/近重复图片、相同异常文案、相同字段错误不能增加 `independent_source_count`。

### 4.2 Evidence Family

```text
IDENTIFIER        Reference / Style Code / MPN / GTIN
STRUCTURED_ATTR   size / material / color / hardware / movement
VARIANT_GRAPH     ProductGroup / isVariantOf / variesBy
LEXICAL_TEXT      BM25 / token overlap
SEMANTIC_TEXT     text embedding / reranker
IMAGE_VISUAL      image embedding / patch feature / perceptual hash
OCR_TEXT          image → OCR → identifier/attribute
EXTERNAL_WEB      外部网页证据
TEMPORAL          year / generation / effective period
```

同一原始观测派生出的多个分数不是多个独立证据：同一标题的 BM25+Embedding 不算两票；同一图片的 pHash/SigLIP/DINO/VLM 不算多票；同一网页的 JSON-LD/DOM/摘要默认属于同一 evidence origin。

### 4.3 Fact Promotion Barrier

```text
OBSERVED      原始可追溯观测
DERIVED       规则/模型/聚类推导
REVIEWED_GOLD 人工确认标签
GOVERNED_FACT 主档治理确认事实
APPROVED_ALIAS 已批准别名/标识符映射
TAINTED       已知被污染
```

Recognition、Matcher 分数、Cluster membership、模型抽取/伪标签都是 DERIVED Artifact。未经 Review/Governance Promotion，不能直接进入 Exact Identity 索引、Hard Constraint 主档、官方 Alias、Identifier Semantics 或 Gold Training Set。

### 4.4 时间版本

Canonical 属性保存 `valid_from / valid_to / version / evidence_ids`。没有明确代际证据时，不跨年代自动合并。

### 4.5 Canonical Attribute Fact Arbitration

`attribute_fact` 是事实断言集合，不是“当前主档值”本身。仲裁主键至少为：

```text
canonical_variant_id
× attribute_id
× market_scope
× valid_time_scope
× variant_generation
```

每个属性定义：

```text
cardinality = SINGLE_VALUE / SET_VALUE / ORDERED_MULTI / RANGE
identity_role = HARD / STRONG / SOFT / OFFER_ONLY
normalization_level = GENERIC / BRAND_PRECISE
allows_regional_variation
allows_temporal_change
specificity_order / unit_policy / comparison_policy
```

Resolution 状态：

```text
RESOLVED
MULTI_VALID
CONFLICTED
UNKNOWN
STALE
```

固定规则：

1. 不使用 latest-write-wins。
2. 不使用简单 majority vote；转载/同 feed 去重。
3. Authority 按字段、品牌、市场、有效期和字段语义定义。
4. 同 scope 的治理级 SINGLE_VALUE Hard Attribute 高可信冲突 → `CONFLICTED`，停止依赖该字段 Auto-Match。
5. T2/T3、OCR/VLM 与已治理 T0/T1 冲突只触发 revalidation/governance，不能覆盖 Current Fact。
6. 保留 Generic + Brand-Precise 粒度，不让粗值覆盖精确值。
7. 缺失不是反证。
8. 多值属性按其集合/顺序语义比较。
9. 支撑 Evidence 撤回/TAINT → `STALE` 并重仲裁。
10. Resolution 保存 input assertions、source-independence snapshot、policy、scope、reason、confidence、supersedes lineage。
11. **Canonical Arbitration 只消费 `fact_scope=OFFICIAL_VARIANT_SPEC` 且通过 Validation/Promotion Gate 的断言。** `OBSERVED_ITEM_STATE / SERVICE_REPLACEMENT / AFTERMARKET_MODIFICATION` 即使事实正确，也不能因为“被多次观察到”而升级为 Canonical 出厂规格。
12. Search/Matching/Conflict 默认只消费 `RESOLVED/MULTI_VALID` Current Fact。
13. Identity-critical Resolution 变化必须通过 Catalog Publication Barrier 与 Search 同版本生效。

## 5. 属性抽取、Validation、OCR 与 VLM

```text
Raw Source Product
→ Schema Mapping
→ Deterministic Parsing / Dictionary
→ Barcode Decode
→ Text Attribute Extraction
→ Scene OCR
→ Document-like OCR/VLM（按需）
→ General VLM Fallback（少量困难样本）
→ Normalization / Ontology Mapping
→ Attribute Validation / Quality Check
→ Attribute Assertion
→ Item-State / Origin Classification
→ Canonical Attribute Arbitration（仅 Variant-Spec 路径）
→ Normalized Product Profile / Current Fact Projection
```

Extraction 回答“候选值是什么”，Validation 回答“该值是否真的适用于当前记录”，Item-State / Origin Classification 再回答“这个正确值描述的是官方 Variant 规格，还是这件二手实物当前状态”。三者不能合并成一个 confidence。

### 5.1 Barcode / OCR

条码使用 zxing-cpp 等确定性 decoder，经过 check digit、格式、品牌/市场校验后进入 Exact Retrieval。

PoC Scene OCR 基线：PP-OCRv6。OCR 输出必须先分类为：

```text
reference / style_code
gtin/ean/upc
serial_number
date_code
size
material_text
other_text
```

保卡整页、历史目录、复杂表格等 document-like 场景使用 PaddleOCR-VL-1.6 / PP-Structure 类能力作为 fallback。

### 5.2 General VLM

PoC 困难样本结构化抽取基线：Qwen3.5-4B。职责是产生可验证候选证据，不是最终身份判断。VLM 无权直接写 ACTIVE Canonical、Current Fact 或 `CERTAIN_MATCH`。

### 5.3 Attribute Validation Gate

每个 `(source_product, attribute, candidate_value)` 都生成独立 `attribute_validation_record`：

```text
VALIDATED_VALID
VALIDATED_INVALID
UNVERIFIED
NOT_APPLICABLE
SOURCE_CONFLICT
```

最小记录：

```text
source_product_id / source_version
attribute_id / candidate_value_id
product_type_path / taxonomy_version
validation_status / validation_confidence
validator_type / validator_version
profile_evidence_ids / independent_evidence_group_ids
rule_hits / contradiction_hits
scope = market / time / generation
circular_dependency_check
created_at
```

分层 Validator：

```text
L0 Schema / Deterministic
L1 Applicability / Cross-field
L2 Text/Profile Cross-check
L3 Cross-source / Official Consistency
L4 Multimodal Validator
L5 LLM/VLM Quality Assessor（长尾 fallback）
```

所有层允许 abstain。Applicability 与 Value Correctness 分开；Validation 不能使用由当前 assertion 自己或 descendant 推导出的 Canonical Fact 自证。

Hard Attribute 使用资格：

- `VALIDATED_VALID` 且 validator/source policy 已认证，才可能进入下一层身份资格判断。
- `VALIDATED_INVALID` 不进入 Arbitration eligible set。
- `UNVERIFIED` 只能用于 Soft Retrieval/提示。
- `NOT_APPLICABLE` 从该 Product Type 身份比较中排除。
- `SOURCE_CONFLICT` 触发 revalidation / UNKNOWN。

### 5.4 零/少标签 Validation 路线

冷启动顺序：确定性规则+Ontology+品牌知识 → 弱监督 Positive/Negative → cross-category few-shot validator → structured table validator → training-free LLM quality assessor。所有 challenger 只有在独立 Gold/Time-shift 上证明 False-Valid 风险下降后才进入 Hard Evidence 路径。

### 5.5 Validation Benchmark / Gate

按 brand/category/attribute、HARD/STRONG/SOFT、seen/unseen、current/vintage、text/image、applicable/not-applicable 分层。

指标：

```text
valid_precision / valid_recall
invalid_precision / invalid_recall
applicability_precision / recall
hard_attribute_false_valid_rate
hard_attribute_false_invalid_rate
unseen_category_validation_precision
source_conflict_detection_recall
abstain_rate
circular_validation_violation = 0
unverified_used_as_hard_evidence = 0
```

Hard Attribute Validator 的目标不是最大化 Accuracy，而是在可接受 abstention 下把 False-Valid 压到分配的 identity risk budget 内。

### 5.6 Official Variant Spec vs Observed Item State

这是奢侈品二手识别必须独立建模的一层。官方售后、维修、个性化和用户后配都会让**当前实物状态**与**该 SKU 的官方出厂 Variant 规格**发生合法或非法偏离；系统不做真假鉴定，因此不能把“当前组件不同”机械等价成“不是这个官方 Variant”。

每条可变化组件属性断言增加：

```text
fact_scope =
  OFFICIAL_VARIANT_SPEC
  OBSERVED_ITEM_STATE

component_origin =
  FACTORY_CONFIG
  AUTHORIZED_SERVICE_REPLACEMENT
  AFTERMARKET_OR_MODIFIED
  UNKNOWN_ORIGIN

origin_confidence
origin_evidence_ids
replaceability_class
```

`replaceability_class` 由 `brand × category × attribute × generation` 策略维护：

```text
IDENTITY_STABLE
SERVICE_REPLACEABLE
USER_REPLACEABLE
COSMETIC_OR_CONSUMABLE
UNKNOWN
```

典型高风险字段：腕表 `dial / hands / bezel / crown / bracelet_or_strap / crystal`，箱包 `hardware / removable_strap / charm / replaceable trim`。字段是否定义官方 Variant 与字段是否能在售后被更换，是两个不同维度。

固定规则：

1. **Canonical Fact 只描述官方 Variant Spec。** 当前实物图片、卖家文本、维修单、服务替换件等首先进入 `OBSERVED_ITEM_STATE`；没有独立的官方/治理证据时不得升级 `OFFICIAL_VARIANT_SPEC`。
2. **`VALIDATED_VALID` 只证明观察值正确，不证明它是出厂规格。** 例如当前腕表确实装皮带、当前包确实是某种五金，都仍需 Origin Gate。
3. `FACTORY_CONFIG` 只有在官方 catalog/archive/reference-specific mapping、可靠历史资料或治理证据能证明“该配置属于此 Variant 出厂规格”时成立；卖家自称“原装”不能单独升级。
4. `AUTHORIZED_SERVICE_REPLACEMENT` 说明部件可是真品/品牌售后件，但它仍是 post-sale item state，**不得重写 Canonical Variant Spec**。
5. `AFTERMARKET_OR_MODIFIED` 同样不生成新 Canonical；若已有 Strong Identity Anchor，可继续识别 underlying Variant，同时把改装/后配作为 Item-State Evidence 保存。
6. 对 `SERVICE_REPLACEABLE / USER_REPLACEABLE` 字段，Observed Item State 与 Canonical Spec 不一致默认形成 `ITEM_STATE_DIVERGENCE / POSSIBLE_COMPONENT_CHANGE`，而不是 Hard Conflict。
7. 只有当 Source Assertion 被验证为 `OFFICIAL_VARIANT_SPEC` 或足够高可信的 `FACTORY_CONFIG`，且该字段在对应 Variant policy 中为 Hard，才允许形成 Hard Conflict。
8. 对 `IDENTITY_STABLE` 字段，若经过 Validation + Origin Gate 的高可信 observation 与 Canonical Spec 冲突，可进入 Hard/Possible Conflict；Origin 不明时仍优先 UNKNOWN。
9. 当前实物组件恰好与另一个近邻 Variant 相似时，不能用它覆盖 Strong Reference/Style/GTIN；若缺少 Strong Anchor，则进入 `UNKNOWN_ITEM_STATE_DIVERGENCE`，而不是靠视觉强行选 Variant。
10. Item-State 不作为独立 Variant Discovery 证据：后换表带、维修盘面、更换五金、可拆肩带等不得单独触发新 Canonical。
11. 识别结果输出分离：`variant_identity_decision` 与 `item_configuration_assessment`。前者回答“官方 Variant 是谁”，后者回答“当前实物是否与官方配置存在可疑/已知偏离”；后者不是鉴真假结论。

`item_configuration_assessment` 至少保存：

```text
source_product_id / source_version
canonical_variant_id (optional)
component_origin_assessments
item_state_divergence_fields
supporting_evidence_ids
assessment_state = CLEAN / DIVERGED / POSSIBLE_REPLACEMENT / MODIFIED / UNKNOWN
policy_version / model_version
```

## 6. EvidenceProfile、Router 与缺模态 Route Policy

每条 Source Product 计算：

```text
identifier_quality = NONE / WEAK / STRONG
text_quality       = NONE / WEAK / STRONG
image_quality      = NONE / WEAK / STRONG
hard_attr_coverage = 0..1
conflict_state     = NONE / POSSIBLE / HARD
catalog_mode       = LINK / DISCOVERY
synthetic_evidence = true / false
brand_route_state    = AUTHORITATIVE / MULTI_CANDIDATE / UNKNOWN / CONFLICTING
category_route_state = AUTHORITATIVE / MULTI_CANDIDATE / UNKNOWN / CONFLICTING
routing_scope        = LEAF / ANCESTOR / MULTI_ROUTE / BROAD_FALLBACK
image_set_state      = CLEAN / PARTIAL / CONFLICTING / NO_IDENTITY_IMAGE / UNKNOWN
item_state_assessment = CLEAN / DIVERGED / POSSIBLE_REPLACEMENT / MODIFIED / UNKNOWN
```

路由策略保持：强 Identifier 可 Exact；无图不是负证据；仅视觉默认不能 CERTAIN_MATCH；文本/图片冲突、Hard Attr 不足、Item-State Divergence 且缺 Strong Anchor 时允许 UNKNOWN。

### 6.1 Router / Filter Safety

Brand/Category Router 只用于缩小候选空间和控制成本，不是身份事实源。

```text
HARD_FILTER     只有权威、可验证路由证据
MULTI_ROUTE     多个 plausible route 各保留 quota
ANCESTOR_ROUTE  leaf 不确定时退 taxonomy ancestor
BROAD_FALLBACK  路由未知/冲突时宽范围召回
```

Exact Identifier 永远绕过 Router；只有 T0/T1、历史认证结构化类别或已验证 Identifier→Category 映射可 Hard Filter；模型/VLM/OCR/merchant 分类只能 Multi-route/Ancestor/Broad。

## 7. Candidate Retrieval、Fusion 与 Open-world Guard

100 万–1000 万记录禁止 N²。

召回：Exact Identifier、Brand+Model、Brand+Series+Hard Attr、BM25、Text ANN、Image ANN、Image hash、Historical Alias、Discovery Neighbor。

PoC 初始 K：Exact≤20、BM25 30、Text ANN 50、Image ANN 每图30/总≤60、Attribute 30；union≤150，Cheap Rerank≈30，Expensive Matcher 10–20。

Gate：

```text
Recall@100 after fusion/truncation >= 99.5%
Exact-candidate survival rate = 100%
router_pre_filter_positive_recall >= 99.9%
router_post_filter_positive_recall >= 99.5%
```

### 7.1 Fusion / Search

不同通道 raw score 不直接相加；Exact 永不被 soft fusion 截断；零/少标签使用 RRF baseline；截断前保留各通道 quota；Exact∪RRF 后再 rerank；有 judgment 后比较 normalized/learned fusion。

生产基线 OpenSearch 3.8。Identity-critical Search Filter 只能消费已发布的 `RESOLVED/MULTI_VALID`、满足 Validation Gate 且属于 `OFFICIAL_VARIANT_SPEC` 的 Canonical 属性。

Image ANN 只消费通过 Image Set Identity/Utility Gate 的合格图或明确归属当前商品的 panel/region。

### 7.2 NIL / Route Recovery

CandidateSet 状态：`KNOWN_CANDIDATE / AMBIGUOUS_KNOWN / POSSIBLE_NIL / RETRIEVAL_FAILURE / ROUTING_AMBIGUOUS`。

进入 NIL/Discovery 前，只要缺 Strong Identifier 或 Router 非 AUTHORITATIVE，必须做 route-bypass。Item-State Divergence 不得作为 `POSSIBLE_NIL` 证据；只有 Router/Search/Publication 健康、bypass 后仍无安全已有候选，且不存在“可解释的组件变更”时，才进入新品链路。

---

## 8. Embedding、Visual Search 与 Image Set Safety

Text：Qwen3-Embedding-0.6B，先测 512d，再比较 256/384d；Qwen3-Reranker-0.6B 仅 Top-N。

Image：SigLIP2-B/16 384 baseline；DINOv3 ViT-B/16 challenger，生产前 Legal/Compliance Gate；Qwen3-VL-Embedding/Reranker 作为多模态 challenger。

每图独立向量。近邻 Variant Top-10～20 使用局部 patch/local descriptor 复核盘面、表圈、刻字、五金、走线、印花等；局部视觉仍属于 IMAGE_VISUAL，不是 Identity Anchor。

### 8.1 Image Set Identity / Utility Gate

一个 `Source Product` 的图片集合不能默认视为同一商品的多个独立视角。必须先做角色、item membership、shared-image reuse、collage regionization、quality 与 identity eligibility，再进入 Retrieval/OCR/VLM/Attribute Validation。

图片角色至少区分：PRODUCT_PRIMARY / PRODUCT_DETAIL / MODEL_LIFESTYLE / PACKAGING_OR_DOCUMENT / COLLAGE / ACCESSORY_OR_AFTERMARKET / DECORATIVE / OTHER_PRODUCT_SUSPECT / UNKNOWN。

固定规则：

- raw image set 不直接 `max_similarity`。
- 拼图必须 region 化。
- `CROSS_VARIANT_REUSE` 不能形成 SAME_VARIANT Positive 或 near-tie 决胜证据。
- 文档图可 OCR，但默认不进外观 ANN。
- 多图聚合使用 robust top-M / quality+utility weighting，并显式记录 support/contradict/shared counts。
- `image_set_state=CONFLICTING` 时视觉为 mandatory evidence 则 `UNKNOWN_IMAGE_SET_CONFLICT`。
- 多张图仍属于同一 IMAGE_VISUAL Evidence Family。
- 图片中观察到后换/维修组件时，只能生成 `OBSERVED_ITEM_STATE`，不得自动生成 Canonical Variant Spec。

## 9. Pair Matcher、Conflict Engine 与 Decision Policy

```text
Candidate Pair
→ Pre-Conflict
→ Cheap Deterministic Features
→ Structured/Text Matcher
→ Multimodal Difficult Pair（少量）
→ Local Visual（near-tie）
→ Post-Conflict
→ Calibration
→ Evidence-Family Risk Policy
→ Candidate-set/NIL/Ambiguity Guard
→ Decision
```

`CERTAIN_MATCH` 至少满足：

```text
NO HARD_CONFLICT
AND CandidateSetState == KNOWN_CANDIDATE
AND identity-critical Canonical Resolution 可服务
AND
(
  Strong Identity Anchor
  OR
  Calibrated Matcher >= tau_segment
  + >=2 个非重复 Evidence Family
  + Ambiguity Guard 通过
)
```

Conflict Engine 规则：

1. Hard Conflict 只允许使用已通过 Validation Gate、Origin/Fact-Scope Gate 的 Source Assertion 和已发布 Canonical Resolution。
2. `UNVERIFIED / SOURCE_CONFLICT` 不能被升级为 Hard Reject。
3. `OBSERVED_ITEM_STATE` 与 Canonical Spec 的可替换部件不一致 → `ITEM_STATE_DIVERGENCE / POSSIBLE_COMPONENT_CHANGE`，不是 Hard Conflict。
4. `OFFICIAL_VARIANT_SPEC` 或高可信 `FACTORY_CONFIG` 在 identity-critical Hard 字段上与 Canonical 冲突 → Hard/Possible Conflict。
5. Strong Identifier 已锁定 Variant、但当前实物存在可解释后换/维修组件时，可继续 Variant Linking，同时 Item-State Assessment 标记 divergence；图片/组件差异不得推翻 Strong Anchor。
6. 无 Strong Anchor 且关键视觉部件疑似已更换/改装时，输出 UNKNOWN，不使用当前组件把商品强制匹配到另一个近邻 Variant。

UNKNOWN 至少包括：AMBIGUOUS、POSSIBLE_NIL、ROUTING_AMBIGUOUS、INSUFFICIENT_EVIDENCE、SEARCH_FAILURE、DEPENDENCY_FAILURE、PUBLICATION_INCONSISTENT、CONFLICT、CATALOG_REPAIR、STALE_SOURCE_VERSION、COMMIT_CONFLICT、CANONICAL_FACT_CONFLICT、ATTRIBUTE_UNVERIFIED、IMAGE_SET_CONFLICT、**ITEM_STATE_DIVERGENCE**。

## 10. Entity Linking、Discovery 与 Canonical Health

Linking：Source Snapshot → Route/Validation/Image/Item-State Gate → Retrieval → Pair/Conflict/Calibration → CandidateSetAssessment → CERTAIN_MATCH → Recognition Commit Barrier。

Discovery：POSSIBLE_NIL → Route Recovery → Item-State Divergence Check → Official/Web Evidence → Strict Blocking → Clustering → PROPOSED → Novelty/Uniqueness → Attribute Validation + Required Variant-Spec Fact Check → ACTIVE/PROPOSED。

任何 `PROPOSED→ACTIVE` 必须有当前 publication 的 `canonical_novelty_assessment`；只有 `UNIQUE` 可自动激活。**OBSERVED_ITEM_STATE、SERVICE_REPLACEMENT、AFTERMARKET_MODIFICATION 不得作为“新品 Variant”证明。**

ACTIVE Canonical 持续检查 Hard Conflict、cannot-link、Manufacturer ID partition、attribute mode、review disagreement、temporal conflict、Canonical Fact Conflict。

Cluster detector / GNN / GraphCR / SuperPart 只能 Detect/Prioritize/Propose；Split/Merge Repair 必须经 Governance Approval 和原子 Publication。Merge 前所有 Variant-Spec Assertion 重新 Validation/Arbitration；Item-State facts 不迁入 Canonical Current Fact。

## 11. Web Evidence Agent 与 Official Web Catalog

仅触发内部无候选、POSSIBLE_NIL、新款/Vintage、型号疑似错误、关键属性冲突、near-tie、Canonical Fact Conflict。

优先级：品牌官网 → 官方目录/经销资料 → 专业数据库 → 高质量二手平台 → 通用搜索。

官方站优先解析 ProductGroup/Product、DOM、Embedded State、Identifier、Variant URL；所有结果形成版本化 Attribute Assertion / External Variant Graph。

Product Group ID、merchant SKU、单张图片、搜索/LLM 摘要、只有营销名无具体 Variant ID 的页面都不能单独激活 Variant 或形成 Current Hard Fact。Web Assertion 同样必须经过 Validation。

维修/售后页面属于 `SERVICE_CAPABILITY / COMPONENT_REPLACEABILITY` 证据，可用于维护 `replaceability_class` 和解释 Item-State Divergence；**它们不能说明某个具体 Source Product 确实做过维修**，具体实例仍需 item-level evidence。

## 12. 冷启动、Pseudo-label 与训练数据飞轮

0 labels：高可信 Reference/Style/GTIN、Hard Constraint、alias/ontology、pretrained Text/Image、确定性 Positive、Hard Negative、Attribute Validator 弱监督。

Pseudo-label 永远不能进入 Certification Gold、Canonical Fact 或 Attribute Arbitration eligible set。

约 10K reviewed pairs：Logistic/LightGBM + calibration；更多数据使用 compact cross encoder/domain contrastive；100K+ 且 Hard Negative 足够再评估 multimodal student/active learning/learned fusion。

Attribute Validation Labels、Pair Matching Labels、Image-role labels、Item-State/Origin labels 分开管理：

- “属性值观察正确” ≠ “它是官方出厂规格”。
- “当前部件是官方售后件” ≠ “这是原始出厂配置”。
- `SAME_VARIANT` ≠ “listing 中所有图片/组件都属于 factory config”。

## 13. Review、风险认证与 Reviewer Quality

三轨：TRAINING_REVIEW / CERTIFICATION_AUDIT / GOVERNANCE_REVIEW。

正式风险认证单位是最终 Recognition Decision，不是 candidate pair。Certification 概率抽样保存 inclusion probability/stratum，按真实流量权重汇总；正式报告同时给 i.i.d. 与 dependency-cluster-aware 风险上界，release 取最保守值。

Certification 默认双人独立盲审；标签允许 SAME_VARIANT / DIFFERENT_VARIANT / INSUFFICIENT_EVIDENCE / SOURCE_DATA_ERROR，分歧进入 adjudication。

独立控制集：

- Attribute Validation Set：Hard Attribute、NOT_APPLICABLE、SOURCE_CONFLICT、unseen category。
- Image Set Safety Set：wrong/shared/collage/document/aftermarket/duplicate/conflict。
- **Item-State / Factory-Spec Set**：同 Reference 后换表带、维修盘面/表冠/表链、未知来源组件、箱包更换五金/可拆肩带、卖家“原装/后配”描述、当前组件恰好接近另一 Variant 等。

Reviewer 必须能区分：

```text
OFFICIAL_VARIANT_SPEC
OBSERVED_ITEM_STATE
AUTHORIZED_SERVICE_REPLACEMENT
AFTERMARKET_OR_MODIFIED
UNKNOWN_ORIGIN
INSUFFICIENT_EVIDENCE
```

## 15. Incremental、CDC、Publication 与 Recognition Commit

DB Canonical/Attribute Resolution mutation 与 `catalog_outbox_event` 同事务；CDC/Outbox Relay → 幂等投影 → OpenSearch external version → refresh/checkpoint → publication watermark。

Auto-Match 请求入口 pin `ACTIVE publication_id`；Search hit 校验 Canonical status/version/Fact Resolution。Search projection 落后、混合 publication、旧 Resolution → `UNKNOWN_PUBLICATION_INCONSISTENT`。

Source 图片/文本变化生成新的 `source_version`；影响 Item-State/Origin、identity-eligible 图或 Hard Assertion 时，旧 Decision Snapshot 不得静默复用。

Recognition 推理阶段不持长事务；CERTAIN_MATCH 最终短 ACID transaction：

```text
idempotency intent
→ lock/CAS Source current row
→ validate source_version/content_hash/epoch
→ validate target Canonical + publication + fact-resolution ids
→ ensure single current link
→ immutable recognition_record
→ upsert current source_canonical_link
→ update Source state
→ exactly one Review task or outbox event
```

相同 key+相同 intent 返回第一次结果；相同 key+不同语义拒绝。Source/Canonical/Fact Resolution 在推理后变化则不提交。

## 16. Production Runtime Reliability

任一 mandatory stage 被跳过/timeout/熔断都会形成新 `route_execution_signature`；未经独立 benchmark + risk certification，不允许 CERTAIN_MATCH。

每请求使用 end-to-end deadline；每依赖唯一 retry owner；指数退避+jitter+retry budget；OpenSearch/Reranker/OCR/GPU/VLM/Web Agent 使用 bounded queue 与 circuit breaker。

Load shedding：P4 backfill/bulk re-validation → P3 Discovery/Web/Fact conflict enrichment → P2 near-tie expensive path → P1/P0 linking。

Attribute Validation / Image Gate / Item-State Origin Gate 若为当前 route 的 identity-critical mandatory stage，被 shed/超时时只能降低 Coverage，不能把未知 Origin 当作 Factory Config。

## 17. 容量、成本与性能

## 19. MVP → Production

### Phase 0：数据审计、Taxonomy 与 Gold

建立字段完整度、Alias/Ontology、Hard Conflict Matrix、Identifier 可用率、来源独立性、EvidenceProfile、Router benchmark、Leakage-safe Split、NIL/near-tie benchmark、三轨 Review。

同时建立：Attribute Semantics/Validation Policy、Image Set 小型 Gold、**Item-State/Factory-Spec Policy 与小型 Gold**。对腕表/箱包抽样统计当前 listing 中后换/维修/可拆部件、未知 Origin 和“官方规格+当前状态混写”的比例。

### Phase 1：确定性腕表 Linking + Hard Attribute / Origin Safety

Reference/GTIN、Exact Retrieval、Hard Conflict、Recognition Commit；先上线腕表 identity-critical 字段的 L0/L1/L2 Validation，并对 `dial / bezel / bracelet_or_strap / crown` 等建立最小 `replaceability_class + fact_scope` 规则。

先证明 **判断 Precision + Hard Attribute False-Valid Gate + Observed-vs-Spec 零污染 + Commit Integrity** 同时达标。

### Phase 2：Hybrid Text + Router/Filter Safety + Few-shot Validation

BM25、Qwen3-Embedding、RRF、Qwen3-Reranker、箱包、Calibration/NIL Guard；扩展箱包 size/material/color/hardware/pattern Validation，并对 hardware/removable strap 引入 Item-State Origin Gate。

### Phase 3：Image/OCR/Multimodal Validation + Image Set / Item-State Gate

zxing-cpp、PP-OCRv6、PaddleOCR-VL、SigLIP2/DINO challenger、局部视觉、Qwen3.5/Qwen3-VL。视觉可识别当前组件，但输出首先是 Item-State Assertion；只有独立证据证明 Factory Config 才能进入 Variant Spec。

### Phase 4：Discovery/Web/Canonical Repair

POSSIBLE_NIL、ProductGroup/Product parse、External Variant Graph、Novelty Gate、Cluster Health、Split/Merge Repair。Web/Repair 产生的新 assertion 必须重新 Validation→Fact Scope/Origin→Arbitration。

### Phase 5：Supervised Student + Controlled Continuous Learning

Review labels、Hard Negative、active learning、domain encoder、learned fusion、shadow/A-B/rollback；Attribute Validator、Router、Image Gate、Item-State/Origin Gate、Matcher 分别版本化/认证，不用统一模型 confidence 替代分层风险控制。

## 20. 正式开启自动识别 Gate

全部满足才扩大 Auto-Match：

1. `Precision@Auto-Match >= 99.9%`，`Recall@100 after fusion >= 99.5%`，Exact survival=100%。
2. Certification Audit 满足 sampling provenance 与 cluster-aware risk upper bound。
3. 所有 Hard Conflict 回归 0 自动错合并；Seen/Unseen/Time-shift/Vintage/缺图/缺型号/低质图分别达标。
4. Synthetic/Pseudo evidence 不能形成 Hard Fact/Identity Anchor/Certification Gold。
5. AMBIGUOUS/NIL/ROUTING_AMBIGUOUS/RETRIEVAL_FAILURE/PUBLICATION_INCONSISTENT/CATALOG_REPAIR/CANONICAL_FACT_CONFLICT 不得绕过 Guard。
6. Product Group ID、merchant SKU、Web JSON-LD/DOM 冲突等语义安全违规=0。
7. ACTIVE 模型/Router/Image Gate/Attribute Validator/Item-State Origin Policy lineage 完整率=100%。
8. `SPLIT_PENDING/SPLIT/MERGE_PENDING/TAINTED` Canonical 新 Auto-Match=0。
9. `PROPOSED→ACTIVE` 必须 novelty=UNIQUE 且 required Hard Fact 可服务。
10. Recognition Commit duplicate/partial/stale/multiple-current-link 违规=0。
11. Router 非权威导致 hard prune、false-NIL/new-canonical 违规=0。
12. Identity/Search/Hard Conflict 只消费已发布 Canonical Attribute Resolution。
13. Identity-critical Resolution `CONFLICTED/STALE` 时 CERTAIN_MATCH=0。
14. Arbitration 中 syndicated double-count/latest-write-wins/majority-vote Hard Fact 违规=0。
15. Hard Attribute Source Assertion 未达到 `VALIDATED_VALID`（或治理等价状态）却参与 Hard Positive/Hard Conflict/Identity Anchor/Exact Filter 的违规=0。
16. `UNVERIFIED / SOURCE_CONFLICT / VALIDATED_INVALID` 被提升为 identity-critical Current Fact 的违规=0。
17. Attribute Validator circular validation / self-confirmation 违规=0。
18. Hard Attribute Validator 在关键 slice 的 False-Valid 风险上界低于预分配 identity risk budget；样本不足则对应 slice UNKNOWN。
19. NOT_APPLICABLE 被当作 missing/invalid 并影响 Variant 判定的关键用例违规=0。
20. Attribute Validation policy/model/Gold/threshold 版本化且可回滚。
21. Identity ANN / visual rerank 使用 INELIGIBLE/NON_PRODUCT/CONFLICTING 图片违规=0。
22. CROSS_VARIANT_REUSE 共享图被当 SAME_VARIANT Positive/独立证据/near-tie 决胜证据违规=0。
23. `image_set_state=CONFLICTING` 且视觉 mandatory 时 CERTAIN_MATCH=0；强非视觉 Anchor 路径若继续，图片贡献必须为 0。
24. 拼图/多商品图片未经 region/item-membership 判定直接形成商品级 Identity Embedding 违规=0。
25. Image Gate/shared-image/image-set assessment 全部版本化，图片变化后不得复用失效视觉 Decision Snapshot。
26. **`OBSERVED_ITEM_STATE` 直接进入 Canonical Attribute Arbitration 或 Search Hard Fact 的违规=0。**
27. **`AUTHORIZED_SERVICE_REPLACEMENT / AFTERMARKET_OR_MODIFIED / UNKNOWN_ORIGIN` 被升级为 `FACTORY_CONFIG` 且无独立证据的违规=0。**
28. **`SERVICE_REPLACEABLE / USER_REPLACEABLE` 字段仅因当前实物与 Canonical Spec 不同就产生 Hard Conflict 的违规=0。**
29. **已有 Strong Identifier Anchor 时，可解释的后换/维修组件不得覆盖 Anchor 或触发新 Canonical；违规=0。**
30. **无 Strong Anchor 且 identity-critical 当前组件 Origin 不明/疑似变化时，必须允许 `UNKNOWN_ITEM_STATE_DIVERGENCE`，不得强制选择近邻 Variant。**
31. **Item-State/Origin policy、replaceability policy、Gold Set 与 assessment 全部版本化；品牌售后规则或 parser 变化后未经重认证不得沿用旧 Factory/Service 判定。**

任何指标退化时，优先降低 Coverage，不降低 Item-State Origin Gate、Image Set Gate、Attribute Validation、Hard Constraint、NIL、Publication 或 Commit Safety。

## 22. 最终生产原则

```text
官方知识 / 确定性标识
          ↓
Attribute Extraction
          ↓
Attribute Validation / Applicability
          ↓
Official-Spec vs Observed-Item-State / Component-Origin Gate
          ↓
Evidence Assertions + Source Independence
          ↓
Canonical Variant-Spec Fact Arbitration
          ↓
EvidenceProfile + Router/Filter Safety
          ↓
Image Set Identity / Utility Gate（有图时）
          ↓
Hybrid Retrieval + Exact Preserve
          ↓
结构化 + 文本 + 合格图片多证据
          ↓
Hard Conflict + Calibration
          ↓
Candidate-set / NIL / Ambiguity Guard
          ↓
Constraint-aware Graph Resolution
          ↓
CERTAIN_MATCH Decision
          ↓
Recognition Commit Barrier
          ↓
Current Link + Immutable Recognition + Pending Review
          ↓
Canonical Novelty / Health / Repair
          ↓
Independent Risk Audit
          ↓
Controlled Training + Immutable ML Lineage
```

固定原则：

1. **Identity first，Similarity second。**
2. **Extraction confidence ≠ fact correctness；Validated observation ≠ Official Variant Spec。**
3. **Attribute Applicability、Value Correctness、Fact Scope/Component Origin 是三个不同判断。**
4. **Canonical 只保存官方 Variant Spec；二手实物当前组件状态进入 Item-State 层。**
5. **官方售后替换件可以是真实/正品组件，但不因此成为原始出厂规格。**
6. **可替换部件的当前状态与 Canonical 不一致默认是 Item-State Divergence，不是 Hard Conflict。**
7. **Hard Conflict 优先于模型高分，但它只能建立在高可信、已验证且具备正确 Fact Scope 的属性上。**
8. **UNKNOWN / UNVERIFIED / UNKNOWN_ORIGIN 是合法生产输出。**
9. **Synthetic/Pseudo evidence 不能形成 Hard Fact / Identity Anchor / Certification Gold。**
10. **多张图片不是多份独立身份票；先做 image-to-item membership 与 utility。**
11. **跨 Variant 共用库存图、拼图未归属 panel、错传图、非商品图不得成为 SAME_VARIANT Positive。**
12. **仅视觉相似不能自动 SAME_VARIANT；视觉观察到的可替换组件首先是 Item-State Evidence。**
13. **必须显式允许 NIL；Top-1/Top-2 near-tie 必须 Abstain。**
14. **Exact Identifier 永远绕过非权威 Router，Exact 候选永不被 Soft Fusion 截断。**
15. **Brand/Category Router 是候选空间优化器，不是身份事实源。**
16. **训练 Review、Image Set Gold、Attribute Validation Gold、Item-State Origin Gold 与生产 Risk Certification 是不同数据资产。**
17. **Product Group ID 是关系标识，不是 Variant Identity；Merchant SKU 与 Manufacturer ID 分命名空间。**
18. **官网结构化数据是高价值 Variant-Spec Evidence；维修/售后资料是 component replaceability 证据，两者语义不能混用。**
19. **Canonical Current Fact 不是最近值/多数票，而是 OFFICIAL_VARIANT_SPEC Assertions 在明确 scope 下的版本化 Arbitration。**
20. **Search/Hard Conflict/Identity Filter 只消费已验证、已仲裁、已发布的 Variant-Spec Current Fact。**
21. **DB→Search 使用 Transactional Outbox + Idempotent Projection + Monotonic Version + Publication Barrier。**
22. **ACTIVE Canonical 不是永久真值：持续检查 over-merge、under-merge、Fact Conflict。**
23. **Entity Discovery 是新品证明问题；后换/维修/改装组件不得触发新 Canonical。**
24. **Cluster repair model 只能 Detect/Prioritize/Propose，不能直接修改 Canonical。**
25. **所有 ACTIVE 模型、Router、Image Gate、Attribute Validator、Item-State Origin/Replaceability Policy、Taxonomy 与数据集都是不可变、可追溯 Artifact。**
26. **timeout/过载/依赖故障形成的新 route 未认证时 fail closed 为 UNKNOWN。**
27. **模型 CERTAIN_MATCH 只是待提交 Decision；只有通过 Recognition Commit Barrier 后业务关系才生效。**
28. **任何复杂度只有在提高 Coverage@99.9% Precision、降低 False-Valid/False-Merge/False-Novel/Modified-item False-Nonmatch、提高事实/事务可靠性或降低总成本时才有价值。**
