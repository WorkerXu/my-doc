# 奢侈品识别方案

## 1. 目标与边界

系统目标不是“找最像的商品”，而是把雷小安、奢当家、腕表之家、小迈步、爱回收等来源的异构记录归一到**同一个官方商品变体（Official Variant）**，并产生可审核、可回放、可治理的 Recognition。

第一阶段只覆盖：

```text
IN_SCOPE_WATCH
IN_SCOPE_BAG
```

历史数据约 100 万–1000 万条。腕表已有部分品牌/系列/型号主档；箱包主档不完整，因此同时支持 Entity Linking 与 Entity Discovery。

核心原则：

> **Precision >> Recall。宁可 UNKNOWN / OUT_OF_SCOPE，也不能把不同官方 Variant 错合并。**

系统不做真假鉴定。成色、价格、库存、卖家、单件序列号、保卡状态属于 Offer / Physical Item Instance；维修换件、个性化、联名营销、附属物、商家 Bundle、Multipack、Lot、重复上架，以及业务范围外商品都不能被误当成新的官方 Variant。

每个 `CERTAIN_MATCH` 必须原子形成：

```text
Source Product 当前状态
+ Source → Canonical 当前识别关系
+ Immutable Recognition Record
+ Pending Business Review
```

四个副作用必须原子、幂等、可重放。

## 2. 核心实体、品牌角色、Source Composition、Physical Item 与 Identifier

### 2.1 Canonical Identity

```text
Brand / Brand Role
  └── Product Family / Series
       └── Product Model
            └── Canonical Variant
```

Canonical 关系至少包括：

```text
SAME_VARIANT
VARIANT_OF
SAME_MODEL
SAME_SERIES
VISUALLY_SIMILAR
UNKNOWN
```

只有 `SAME_VARIANT` 可进入普通 Canonical 聚类并生成默认自动 Recognition。

Canonical Variant 状态：

```text
ACTIVE
PROPOSED
SPLIT_PENDING
MERGE_PENDING
RETIRED
MERGED
SPLIT
TAINTED
```

`MERGED` 可 redirect 到唯一 survivor；`SPLIT` 是 one-to-many，旧 Canonical 必须重新解析。

### 2.2 Brand Role / Collaboration Semantics Gate

奢侈品不能把商品标题中出现的所有品牌词压成一个 `brand_id`。统一维护：

```text
canonical_brand_relation:
  brand_entity_id
  role
  confidence / source_evidence
  valid_from / valid_to

role =
  PRIMARY_PRODUCT_BRAND
  CO_PRIMARY_BRAND
  SUB_BRAND
  COLLABORATION_PARTNER
  ARTIST_OR_DESIGNER
  LICENSED_IP
  BRAND_OWNER_OR_MANUFACTURER
  UNKNOWN_ROLE
```

并单独维护：

```text
collaboration_program_id
collaboration_scope =
  PRODUCT_VARIANT_DEFINING
  COLLECTION_PROGRAM
  CAMPAIGN_OR_EDITORIAL
  ENDORSEMENT_OR_STYLING
  UNKNOWN
```

固定规则：

1. **Hard Brand Constraint 比较的是治理后的 `PRIMARY_PRODUCT_BRAND / CO_PRIMARY_BRAND` 身份集合，不是标题里所有品牌词。**
2. Collaboration Partner、Artist/Designer、Licensed IP 不能自动升级成 Primary Brand。
3. 来源漏写 collaborator 视为 missing，不形成 Brand Hard Conflict。
4. 来源只写 collaborator、联名简称或双方品牌但角色不清时，使用 multi-brand retrieval / role resolution，不直接 hard-prune。
5. 当官方 Catalog 明确把联名项目做成独立产品/Variant 边界时，`collaboration_program_id` 进入 Variant Identity；同 base model 的普通款与联名款不得合并。
6. `CAMPAIGN_OR_EDITORIAL / ENDORSEMENT_OR_STYLING` 不定义 Variant。品牌请艺术家拍摄广告、代言或做内容合作，不能单凭页面同时出现双方名称创建联名 Variant。
7. 联名是**有方向的关系**。若官方语义区分 “A by B” 与 “B by A”，不得把 `{A,B}` 当无序 brand set。
8. Identifier 仍绑定实际 namespace / issuer / brand owner；不能因为 collaborator 出现在商品名就把 GTIN/MPN/Reference 重新绑定到 collaborator namespace。
9. Official Collaboration 信息缺失时，不用“视觉像联名”自动补 Truth；图片/logo/VLM 只能产出候选 Evidence。

典型处理：

```text
Balenciaga Hacker Project with Gucci codes:
primary product brand = Balenciaga
collaboration partner = Gucci
collaboration program = Hacker Project

Louis Vuitton x Murakami:
primary product brand = Louis Vuitton
artist collaborator = Takashi Murakami
collaboration program = LV x Murakami

OMEGA X Swatch:
允许 co-brand/collaboration relation；
具体主品牌/identifier ownership 由官方产品页、SKU namespace 与治理策略决定，不能仅靠标题顺序判断。
```

### 2.3 Source Offer / Component / Physical Item

Source 侧不能假设“一条记录 = 一个商品 = 一件实物”。统一建模：

```text
Source Offer / Listing
   └── Source Component(s)
        └── 0..1 Primary Identity Target
              └── 0..1 Physical Item Instance（可未知）
                    └── Canonical Variant
```

组合关系：

```text
PRIMARY_COMPONENT_VARIANT
MULTIPACK_OF_VARIANT
ACCESSORY_OF_VARIANT
CONTAINS_VARIANT
```

实例关系：

```text
INSTANCE_OF_VARIANT
SAME_PHYSICAL_ITEM
RELIST_OF
POSSIBLE_SAME_PHYSICAL_ITEM
```

Physical Item 只用于实例追踪、Evidence 去重、Item-State/Customization timeline、训练/审计聚类；不得直接产生 Variant Identity。

### 2.4 Identifier Namespace

统一采集：

```text
reference_full / style_code / mpn
gtin / ean / upc
merchant_sku
product_group_id / item_group_id
serial_number / date_code / certificate_id / instance_identifier
made_to_order_gtin / made_to_order_variation
market
identifier_namespace / identifier_owner / identifier_scope
identifier_source / source_field_path / confidence
component_id / identifier_binding_scope
```

规则：

- 高可信完整 Reference / Style Code 是最强 Variant Anchor 之一。
- 官方 MPN 经品牌规则验证后可作为 Manufacturer-grade Identifier。
- Merchant SKU 默认属于 merchant namespace。
- Product Group ID 是 Group/Variant Graph 标识，不是 Variant Anchor。
- GTIN/EAN/UPC 是 Strong Positive + Exact Retrieval Key；GTIN 冲突是否 Hard 取决于品牌/市场规则。
- Serial/Certificate/Date Code 默认属于 Individual Item / Production Evidence，不是 Variant Identifier。
- Serial 必须绑定 `brand/manufacturer + identifier_namespace + identifier_type`；裸字符串不全局比较。
- GS1 Made-to-Order GTIN/MTO variation 与普通 GTIN、serial、内部 variant 是不同语义。

`identifier_semantics_policy` 最小粒度：

```text
brand_role × market × source_group × field_path × identifier_type × composition_state × customization_state
```

声明 `MANUFACTURER_ID / MERCHANT_ID / GROUP_ID / INSTANCE_ID / MTO_ID / UNKNOWN`，以及 Exact Retrieval、Strong Positive、Hard Conflict、Auto Activation、Instance Linking 权限。

### 2.5 Source Composition Semantics

```text
SINGLE_PRODUCT
SINGLE_PRIMARY_WITH_AUXILIARY
MERCHANT_DEFINED_BUNDLE
MANUFACTURER_DEFINED_SET
MERCHANT_MULTIPACK
MULTI_PRODUCT_LOT
ACCESSORY_ONLY
CONFLICTING_COMPOSITION
UNKNOWN_COMPOSITION
```

组件角色：

```text
PRIMARY_IDENTITY_TARGET
INCLUDED_AUXILIARY
MERCHANT_ADD_ON
MANUFACTURER_SET_COMPONENT
PACKAGING_OR_DOCUMENT
ACCESSORY_PRODUCT
OTHER_PRODUCT
UNKNOWN_COMPONENT
```

Merchant Bundle 可识别主组件，但整个 Listing 默认不产生 `SAME_VARIANT`；Manufacturer Set 只有官方 Set identity/Hard Facts 齐全时才可成为独立 Canonical；Multipack 数量属于 Offer；Lot/Accessory-only/Unknown Composition 不进入普通 SAME_VARIANT Linking/Discovery。

### 2.6 Physical Item / Relisting Independence Gate

同一二手实物可能反复上架或跨平台搬运。不同 Offer ID/URL 不自动等于不同实物，也不能增加独立证据数。

实例链接状态：

```text
CONFIRMED_SAME_INSTANCE
LIKELY_SAME_INSTANCE
UNKNOWN_INSTANCE_RELATION
CONFIRMED_DIFFERENT_INSTANCE
```

同一 `physical_item_id` 的多个 Offer 在 Activation、Weak Validation、Attribute Arbitration、Risk Audit 中最多算一个 Physical-Instance Evidence Group。实例误合并必须 fail-safe：最多减少独立证据、降低 Coverage，不能制造 Variant 决策。

### 2.7 Official Customization / Personalization Semantics Gate

```text
customization_state =
  NONE_STANDARD
  CATALOG_VARIANT_OPTION
  MANUFACTURER_MTO_PROGRAM
  POST_PURCHASE_PERSONALIZATION
  AFTERMARKET_PERSONALIZATION
  UNKNOWN_CUSTOMIZATION

customization_value_scope =
  VARIANT_DEFINING
  PROGRAM_LEVEL
  INSTANCE_SPECIFIC
  DECORATIVE_ONLY
  UNKNOWN
```

Catalog 有限选项且官方定义 Variant 边界时按普通 Variant；MTO Program 与客户最终组合分层；客户 initials、姓名、日期、自由刻字、patch/stripe 默认 Instance-specific；最终配置只有获得独立 manufacturer-grade Variant/Trade Item Identity 时才另建 Canonical；高基数 personalization 不允许造成 Canonical Explosion。

## 3. Product Scope / Product-Type Open-set Gate

第一阶段只做腕表与箱包，因此在 Router、NIL、Discovery 前必须证明输入属于当前 Scope：

```text
IN_SCOPE_WATCH
IN_SCOPE_BAG
IN_SCOPE_UNKNOWN_SUBTYPE
OUT_OF_SCOPE_KNOWN
OPEN_UNKNOWN
CONFLICTING_SCOPE
```

Closed-set Top-1 不能直接当 Scope Truth。父类可靠但 leaf 未知 → `IN_SCOPE_UNKNOWN_SUBTYPE + ANCESTOR_ROUTE`。`OUT_OF_SCOPE_KNOWN / OPEN_UNKNOWN / CONFLICTING_SCOPE` 不进入腕表/箱包 NIL/Discovery。

Scope Gate 与 Category Router 分开：前者决定“是否属于系统”，后者决定“在 in-scope 内去哪检索”。

## 4. 标准 Schema 与 Hard Constraint

每个属性断言保存：

```text
raw / normalized / canonical_value_id
extractor / extractor_version
source / evidence span / image bbox
extraction_confidence
validation_status / validation_confidence
fact_scope
market / region / valid time
component_id / component_binding_confidence
physical_item_id(optional)
customization_assessment_id(optional)
brand_role_resolution_id(optional)
```

**Extraction Confidence ≠ Validation Confidence；Validated Observation ≠ Official Variant Spec；Official Customization/Collaboration ≠ 必然独立 Variant。**

### 4.1 腕表

| 字段 | 默认策略 |
|---|---|
| primary/co-primary brand identity | Hard |
| collaboration_program | 官方定义独立 Variant 时 Hard；否则 Strong/Metadata |
| series/family | Blocking + Strong；品牌规则可 Hard |
| subseries/model | Strong |
| official_reference_full | Hard |
| reference_base | Retrieval/Strong，默认不能代替 full |
| gtin/ean/upc | Strong；条件 Hard |
| case_diameter_mm | Hard |
| case_material | Hard |
| dial_color/dial_type | 定义 Variant 时 Hard；仅 Official Spec |
| bezel | 定义 Variant 时 Hard |
| bracelet_or_strap | 条件 Hard；Item-State 不直接当 Factory Spec |
| caliber/movement | 代际区分时 Hard，否则 Strong |
| functions | 区分 Variant 时 Hard |
| edition/generation | Hard |
| serial / limited piece number | Physical Item |
| engraving / initials / personal date | Item Customization |

### 4.2 箱包

| 字段 | 默认策略 |
|---|---|
| primary/co-primary brand identity | Hard |
| collaboration_program | Product-level 联名时 Hard/Strong；Campaign-only 不参与 Identity |
| family/series | Blocking + Strong |
| model/style | Strong |
| official_style_code | Hard |
| gtin/ean/upc | Strong；条件 Hard |
| official_size | Hard |
| material / official_color / hardware | Hard；仅 Official Spec |
| pattern/print | 官方 Variant Spec 时 Hard |
| edition/collaboration | Hard；必须与 collaboration program/role 一致 |
| season/year/generation | 官方区分时 Hard |

| initials/hot-stamp/personalized stripe | Item Customization，除非官方最终配置有独立 Variant identity |

## 5. Evidence、来源独立性、事实状态与时间版本

来源等级：T0 品牌官方；T1 已验证主档/授权专业库；T2 高质量专业/二手平台；T3 普通电商/聚合/搜索。

可信度按“来源 × 属性 × 品牌角色 × 市场/时间 × Component × Physical Instance × Customization Scope”定义。

### 5.1 Evidence Independence

维护：

```text
source_group_id
syndication_group_id
content_fingerprint
image_hash_group_id
physical_item_group_id
upstream_hint
```

同 feed、转载、相同图、同一 physical item relist、同一官方联名/个性化页面复制都不能机械增加独立 Variant 证据数。

### 5.2 Evidence Family

```text
IDENTIFIER
BRAND_ROLE / COLLABORATION
STRUCTURED_ATTR
VARIANT_GRAPH
LEXICAL_TEXT / SEMANTIC_TEXT
IMAGE_VISUAL / OCR_TEXT
EXTERNAL_WEB / TEMPORAL / PRODUCT_SCOPE
ITEM_INSTANCE / CUSTOMIZATION
```

同一原始观测派生的多个分数不是多票。`ITEM_INSTANCE` 与非 Variant-defining `CUSTOMIZATION` 不作为 Variant 正向 Evidence Family；Brand Role 与同一标题中的 lexical/semantic signal 也不能被重复计票。

### 5.3 Fact Promotion Barrier

```text
OBSERVED / DERIVED / REVIEWED_GOLD / GOVERNED_FACT / APPROVED_ALIAS / TAINTED
```

Recognition、Matcher、Brand-role classifier、Cluster、Instance Link、Customization classifier 和 pseudo-label 都是 DERIVED；未经治理不得进入 Exact Variant Identity、Canonical Hard Fact、Brand Role Truth 或 Gold Training Set。

### 5.4 Canonical Attribute / Brand-role Arbitration

Canonical Current Fact 不使用 latest-write-wins 或简单 majority vote。所有 identity-critical Resolution 按 market/time/generation/source independence/version 仲裁：

```text
RESOLVED / MULTI_VALID / CONFLICTED / UNKNOWN / STALE
```

Search/Matching/Conflict 只消费已发布的 `RESOLVED/MULTI_VALID` Current Fact。Brand-role/collaboration relation 同样版本化；官方高可信 Primary Brand 与 Collaboration Role 发生无法解释冲突时 `CONFLICTED`，不能靠标题词频/模型分数自动选边。

## 6. 前处理流水线

```text
Raw Source Offer
→ Schema Mapping
→ Source Composition Detection
→ Component / Evidence Binding
→ Physical Item / Relist Assessment
→ Product Scope Open-set Gate
→ Brand Role / Collaboration Resolution
→ Deterministic Parsing / Barcode / OCR
→ Text / Image / VLM Extraction
→ Normalization / Ontology
→ Attribute Validation
→ Item-State / Origin Classification
→ Customization Semantics Gate
→ Canonical Arbitration（Official Variant Spec / Brand Role / Variant-defining Collaboration）
```

### 6.1 Barcode / OCR

条码经 deterministic decode + component binding + identifier semantics。Serial OCR 默认生成 Instance-ID Candidate；个性化刻字/姓名/日期默认 Customization Evidence；合作方 logo/name OCR 默认 Brand-role Candidate，不能直接覆盖 Primary Brand。

### 6.2 General VLM

PoC 困难样本结构化抽取基线：Qwen3.5-4B。只能产出候选 Evidence/Scope/Composition/Brand Role/Component/Instance/Customization 提示，无权直接写 Canonical Truth 或 `CERTAIN_MATCH`。

### 6.3 Attribute Validation Gate

```text
VALIDATED_VALID
VALIDATED_INVALID
UNVERIFIED
NOT_APPLICABLE
SOURCE_CONFLICT
```

L0 deterministic → L1 applicability/cross-field → L2 text/profile → L3 cross-source/official → L4 multimodal → L5 LLM/VLM fallback。所有层允许 abstain。Hard Attribute 只有 `VALIDATED_VALID` 且 validator/source policy 已认证才可进入身份链路。

### 6.4 Official Variant Spec vs Observed Item State

```text
fact_scope = OFFICIAL_VARIANT_SPEC / OBSERVED_ITEM_STATE
component_origin = FACTORY_CONFIG / AUTHORIZED_SERVICE_REPLACEMENT / AFTERMARKET_OR_MODIFIED / UNKNOWN_ORIGIN
replaceability_class = IDENTITY_STABLE / SERVICE_REPLACEABLE / USER_REPLACEABLE / COSMETIC_OR_CONSUMABLE / UNKNOWN
```

Canonical 只描述 Official Variant Spec；可替换组件差异默认 Item-State Divergence；Strong Identifier 已锁定 Variant 时可解释换件不得覆盖 Anchor。

## 7. EvidenceProfile、Route Policy 与缺模态

每条 Source Offer 计算：

```text
identifier_quality / text_quality / image_quality
composition_state / main_component_id
physical_item_link_state
product_scope_state
brand_role_state / collaboration_program_state
customization_state
hard_attr_coverage / conflict_state
brand_route_state / category_route_state / routing_scope
image_set_state / item_state_assessment
```

执行顺序：

```text
Composition
→ Component Binding
→ Physical Item/Relist
→ Product Scope
→ Brand Role/Collaboration
→ Customization Semantics
→ Router
→ Retrieval
```

Router 是 in-scope 后的候选空间优化器，不是身份事实源。Exact Identifier 可绕过非权威 Router，但不能绕过 Component、Scope、Brand Role、Composition、Customization、Fact Scope、Identifier Semantics 和 Conflict。

## 8. Candidate Retrieval、Fusion 与 Open-world Guard

召回通道：Exact Identifier、Primary/Co-brand + Model、Collaboration Program、Brand+Series+Hard Attr、BM25、Text ANN、Image ANN/hash、Historical Alias、Discovery Neighbor。

PoC 初始 K：Exact≤20、BM25 30、Text ANN 50、Image ANN 每图30/总≤60、Attribute/Brand-role 30；union≤150，Cheap Rerank≈30，Expensive Matcher 10–20。

Gate：

```text
Recall@100 >= 99.5%
Exact survival = 100%
Scope / Brand-role / Router pre-post filter recall 单独监控
```

### 8.1 Brand/Component/Customization-aware Retrieval

- Primary/co-primary Brand 可作为经治理 Hard Filter；Collaborator/Artist 只能作为 Collaboration Channel 或 soft route，除非官方 identity relation 已治理。
- 来源只写 collaborator 时保留 collaborator-driven candidate route，不把它当 Primary Brand exact filter。
- Product-level collaboration program 有独立 route；标准款与 collaboration program 候选不得因 base model 相同被强制合并。
- Query text 只由主 Identity Component + identity-eligible base/program attributes 生成；Bundle add-on、个人刻字、campaign text 不进入 Hard Filter。
- Image ANN 只使用通过 Composition/Scope/Image Gate 的图/region；个性化区域 low-weight/masked。
- Exact 候选永不被 Soft Fusion 截断；零/少标签用 RRF baseline。

### 8.2 NIL / Recovery

CandidateSet：

```text
KNOWN_CANDIDATE
AMBIGUOUS_KNOWN
POSSIBLE_NIL
RETRIEVAL_FAILURE
ROUTING_AMBIGUOUS
```

进入 NIL/Discovery 前完成 Scope Gate + Router bypass（必要时）+ Composition + Brand-role ambiguity + Item-State + Customization/MTO Recheck。Out-of-scope、Brand-role conflict、Campaign-only collaboration、Composition Unknown、可解释 Item-State/Customization、Search/Publication Failure 都不能直接解释成新品。

## 10. Pair Matcher、Conflict Engine 与 Decision Policy

```text
Candidate Pair
→ Pre-Conflict
→ Deterministic Features
→ Structured/Text Matcher
→ Multimodal Difficult Pair
→ Local Visual（near-tie）
→ Post-Conflict
→ Calibration
→ Evidence-Family Risk Policy
→ Candidate/NIL/Ambiguity/Scope/Brand-role/Composition/Customization Guard
→ Decision
```

`CERTAIN_MATCH` 至少满足：

```text
NO HARD_CONFLICT
AND product_scope in-scope
AND CandidateSetState == KNOWN_CANDIDATE
AND Brand Role/Collaboration Boundary 无未解决冲突
AND Composition 允许 SAME_VARIANT
AND Customization 不造成 Variant-boundary ambiguity
AND Canonical Hard Resolution 可服务
AND (
  Strong Identity Anchor
  OR calibrated_matcher >= tau_segment
     + >=2 non-duplicate Variant Evidence Families
     + Ambiguity Guard
)
```

Primary/Co-primary Brand 高可信不一致可 Hard；Collaboration Partner 缺失不算冲突；已治理的不同 `PRODUCT_VARIANT_DEFINING collaboration_program_id` 可形成 Hard/Strong Conflict；Campaign/Editorial collaborator 不进入 Variant Conflict。

`ITEM_INSTANCE`、非 Variant personalization、Campaign-only collaboration 不充当第二票。

## 11. Entity Linking、Discovery、Instance Lineage 与 Canonical Health

### 11.1 Linking

```text
Source Snapshot
→ Composition / Component Binding
→ Physical Item / Relist
→ Product Scope
→ Brand Role / Collaboration
→ Validation / Item-State / Customization / Router / Image Gate
→ Hybrid Retrieval
→ Pair / Conflict / Calibration
→ CandidateSetAssessment
→ SAME_VARIANT CERTAIN_MATCH
→ Recognition Commit Barrier
```

### 11.2 Discovery / Novelty

```text
POSSIBLE_NIL
→ Scope/Brand-role/Route Recovery
→ Composition / Item-State / Customization / Instance-Duplicate Recheck
→ Official/Web Evidence
→ Strict Blocking
→ Constraint-aware Clustering
→ PROPOSED
→ Novelty/Uniqueness + Required Hard Facts + Collaboration/Customization Boundary
→ ACTIVE or remain PROPOSED
```

新品前置：Scope in-scope；Composition 允许；Primary/co-primary Brand role 已可服务或 governance policy 允许；Campaign-only collaboration 不能触发新 Variant；官方 Product Collaboration 若有独立 Identifier/Variant boundary 才可形成新的 collaboration Canonical。

### 11.3 ACTIVE Canonical Health / Split / Merge

周期性检查 Hard Conflict、cannot-link、Manufacturer ID partition、Brand-role/Collaboration Boundary collision、Fact Conflict、review disagreement、temporal generation、Customization Boundary collision。治理级冲突立即 freeze。

GNN/GraphCR/SuperPart 等只能 Detect/Prioritize/Propose；Split/Merge 需 Governance + 原子 Publication。Merge 时重新 Validation/Brand-role/Collaboration/Customization Arbitration。

## 12. Web Evidence Agent 与 Official Web Catalog

优先级：品牌官网 → 官方目录/授权资料 → 专业数据库 → 高质量二手平台 → 通用搜索。

官方站解析 ProductGroup/Product、Identifier、Variant URL、Brand/Sub-brand、Collaboration Program、MTO/Personalization 页面，产出版本化 Evidence。

Brand Role 规则：

- 官方商品页/集合页可用于确认 Primary/Co-brand/Collaborator role，但仍需 product-level scope 与 identifier consistency。
- 官方新闻/广告同时出现两个品牌并不自动证明商品是 Product Collaboration。
- 对 “A x B / A by B / B by A” 保存方向与官方 program 名，不把品牌集合无序化。
- 多个页面复制同一联名新闻/collection feed 不增加独立 Evidence 数。

Web/Agent 无权直接修改 Canonical、Brand Role Truth、Current Fact 或 `CERTAIN_MATCH`。

## 14. Review、风险认证与 Review Orchestration

四轨：

```text
BUSINESS_CONFIRMATION_REVIEW
TRAINING_REVIEW
CERTIFICATION_AUDIT
GOVERNANCE_REVIEW
```

每个 `CERTAIN_MATCH` 都创建 Business Review。Training Review 可 Active Learning；Certification 从冻结版本最终 Decision 流按预定义概率抽样；Governance 处理 PROPOSED/Novelty/Merge/Split/Brand Role/Collaboration/Fact Conflict/Identifier 等。

### 14.1 Certification

正式 Certification 默认双人独立盲审；允许 SAME_VARIANT / DIFFERENT_VARIANT / INSUFFICIENT_EVIDENCE / SOURCE_DATA_ERROR；分歧 adjudication。

同时报告 i.i.d. 与 dependency-cluster-aware 风险上界，release 取最保守值。Business/Training priority queue 的 rejection rate 不能当生产 Precision。

### 14.2 Review Work Unit / Exposure Safety

每条 task 独立保存；相同 Physical Item/同证据模板可安全 batch 展示，但不得无条件 label fan-out。

按 model/route/source/Canonical family 维护：

```text
max_unreviewed_count
max_unreviewed_age
max_rejection_burst
min_recent_review_coverage
```

超阈值：`REVIEW_PRESSURE → AUTO_MATCH_THROTTLED → AUTO_MATCH_DISABLED/UNKNOWN`。Certification/Governance 保留最低 reviewer capacity；Training Review 过载时最先降配。

## 16. Incremental、CDC、Publication 与 Recognition Commit

Canonical/Brand-role/Collaboration/Attribute Resolution mutation 与 `catalog_outbox_event` 同事务；幂等 Search projection 使用 external version，refresh/checkpoint 后推进 publication watermark。

`CERTAIN_MATCH` 进入短 ACID：

```text

→ Source CAS
→ validate Source / Composition / Scope / Brand Role / Collaboration / Customization / Canonical / publication / fact versions
→ ensure single current link
→ immutable Recognition
→ current link
→ Source state
→ exactly one BUSINESS_CONFIRMATION_REVIEW task or outbox event
```

同 key+同 intent 返回第一次结果；同 key+不同语义拒绝；Source/Brand-role/Collaboration 状态在推理后变化则 stale/reprocess。

## 17. Production Runtime Reliability

Mandatory stage timeout/熔断/跳过形成新 route signature；未经单独认证只能 UNKNOWN。

每请求 end-to-end deadline；依赖唯一 retry owner；指数退避+jitter+retry budget；bounded queue+circuit breaker。

Load shedding：

```text
P5 optional training/backfill/re-embedding

P3 Discovery/Web/Scope/Brand-role/Composition/Customization enrichment
P2 near-tie expensive inference
P1/P0 Linking
```

Brand Role/Collaboration Gate 若是当前 route 的 identity-critical mandatory stage，过载时不能默认取标题第一个品牌。

## 18. 容量、成本与性能

10M 商品、平均 3 图、10M text + 30M image vectors、512d：FP16 导出约 40.96GB；OpenSearch FP32 完整向量约 81.92GB，不含 Lucene/HNSW、metadata、副本、shadow index。

PoC（1–2M）：1×L4 24GB、1×8 vCPU/64GB OpenSearch、0.5TB SSD。

10M 压测起点：3×8 vCPU/64GB OpenSearch、3×1TB usable storage、2×L4 24GB online GPU；历史 backfill 临时 4–8×L4。

额外统计 Brand-role/Collaboration resolution QPS/p95、ambiguous rate、multi-brand retrieval amplification、collaboration program candidate count，以及 Review/Governance 人工成本。

成本与 `Coverage @ 99.9% Precision`、`Cost per Confirmed Recognition`、`Review Hours per 1K Recognitions` 联合优化。

## 23. 最终生产原则

```text
Raw Source Offer
          ↓
Source Composition / Component Binding
          ↓
Physical Item / Relisting Independence
          ↓
Product Scope Open-set Gate
          ↓
Brand Role / Collaboration Semantics Gate
          ↓
Attribute Extraction + Validation
          ↓
Official-Spec vs Observed-Item-State / Origin
          ↓
Official Customization / MTO Semantics Gate
          ↓
Evidence Assertions + Source/Instance Independence
          ↓
Canonical Variant-Spec + Brand-role Fact Arbitration
          ↓
In-scope Router / Filter Safety
          ↓
Image Set Identity / Utility Gate
          ↓
Component/Brand/Customization-aware Hybrid Retrieval + Exact Preserve
          ↓
Structured + Text + Eligible Image Evidence
          ↓
Hard Conflict + Calibration
          ↓
Candidate-set / NIL / Ambiguity / Scope / Brand-role / Composition / Customization Guard
          ↓
Constraint-aware Graph Resolution
          ↓
SAME_VARIANT CERTAIN_MATCH
          ↓
Recognition Commit Barrier
          ↓
Current Link + Immutable Recognition + BUSINESS_CONFIRMATION_REVIEW
          ↓
Review Orchestration + Exposure Safety
          ↓
Canonical Novelty / Health / Repair
          ↓
Independent Certification Audit
          ↓
Controlled Training + Immutable Lineage
```

固定原则：

1. **Identity first，Similarity second。**
2. **Primary Brand、Co-brand、Collaborator、Artist/Designer、Sub-brand、Manufacturer/Brand Owner 必须分角色；标题出现多个品牌不等于多个 Primary Brand。**
3. **Product-level collaboration 与 Campaign/Editorial collaboration 必须分开；只有前者在官方定义 Variant 边界时进入 Identity。**
4. **联名关系可能有方向，不能把 `A by B` 与 `B by A` 压成无序集合。**
5. **Source Offer ≠ 一个商品；Offer ID ≠ Physical Item ID；Physical Item ID ≠ Variant ID。**
6. **Serial/Date Code/Certificate 默认是实例/生产证据，不是 Variant Reference。**
7. **官方个性化能力不等于每个客户组合都是独立 Variant。**
8. **Catalog Variant Option、MTO Program、客户最终配置、Post-purchase Personalization 分层。**
9. **第一阶段 Scope 只有腕表与箱包；Closed-set Top-1 不是 Scope Truth。**
10. **Merchant Bundle / Multipack / Lot 不能伪装 SAME_VARIANT；配件 Evidence 与主商品隔离。**
11. **Extraction confidence ≠ fact correctness；Validated Observation ≠ Official Variant Spec。**
12. **Canonical 只保存 Official Variant Spec；二手当前组件与 instance personalization 进入 Item-State。**
13. **Hard Conflict 只建立在 Validation、Fact Scope、Component Binding、Brand Role、Customization Scope 合格的证据上。**
14. **Synthetic/Pseudo evidence 不能形成 Hard Fact / Brand Role Truth / Identity Anchor / Certification Gold。**
