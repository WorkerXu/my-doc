# 奢侈品识别方案

## 1. 目标与边界

系统目标不是“找最像的商品”，而是把雷小安、奢当家、腕表之家、小迈步、爱回收等来源的异构记录归一到**同一个官方商品变体（Official Variant）**，并产生可审核、可回放、可治理的 Recognition。

第一阶段只覆盖：

```text
IN_SCOPE_WATCH
IN_SCOPE_BAG
```

历史数据约 100 万–1000 万条。腕表已有部分品牌/系列/型号主档；箱包主档不完整，因此同时支持 **Entity Linking** 与 **Entity Discovery**。

核心原则：

> **Precision >> Recall。宁可 UNKNOWN / OUT_OF_SCOPE，也不能把不同官方 Variant 错合并。**

系统不做真假鉴定。成色、价格、库存、卖家、单件序列号、保卡状态属于 Offer / Physical Item Instance；维修换件、个性化刻字/印花、附属物、商家 Bundle、Multipack、Lot、重复上架，以及业务范围外商品都不能被误当成新的官方 Variant。

机器成功识别后必须形成一致业务结果：

```text
Source Product 当前状态
+ Source → Canonical 当前识别关系
+ Immutable Recognition Record
+ Pending Review 任务/事件
```

四个副作用必须原子、幂等、可重放。

## 2. 核心实体、Source Composition、Physical Item 与 Identifier

### 2.1 Canonical Identity

```text
Brand
  └── Product Family / Series
       └── Product Model
            └── Canonical Variant
```

Canonical 关系：

```text
SAME_VARIANT
VARIANT_OF
SAME_MODEL
SAME_SERIES
VISUALLY_SIMILAR
UNKNOWN
```

只有 `SAME_VARIANT` 可以进入普通 Canonical 聚类并生成默认自动 Recognition。

Canonical Variant 状态：

```text
ACTIVE
PROPOSED
SPLIT_PENDING
MERGE_PENDING
RETIRED
MERGED
SPLIT
TAINTED
```

`MERGED` 可 redirect 到唯一 survivor；`SPLIT` 是 one-to-many，旧 Canonical 必须重新解析。

### 2.2 Source Offer / Component / Instance

Source 侧不能假设“一条记录 = 一个商品 = 一件实物”。统一建模：

```text
Source Offer / Listing
   └── Source Component(s)
        └── 0..1 Primary Identity Target
              └── 0..1 Physical Item Instance（可未知）
                    └── Canonical Variant
```

组合关系：

```text
PRIMARY_COMPONENT_VARIANT
MULTIPACK_OF_VARIANT
ACCESSORY_OF_VARIANT
CONTAINS_VARIANT
```

Physical Item 关系：

```text
INSTANCE_OF_VARIANT
SAME_PHYSICAL_ITEM
RELIST_OF
POSSIBLE_SAME_PHYSICAL_ITEM
```

Physical Item Instance 层只用于实例追踪、Evidence 去重、Item-State/Customization 时间线、训练/审计聚类；不得直接产生 Variant Identity。

### 2.3 Identifier Namespace

统一采集：

```text
reference_full / style_code / mpn
gtin / ean / upc
merchant_sku
product_group_id / item_group_id
variant_dimension_keys / variant_dimension_values
serial_number / date_code / certificate_id / instance_identifier
made_to_order_gtin / made_to_order_variation
barcode_symbology / payload / checksum
market
identifier_namespace / identifier_owner / identifier_scope
identifier_source / source_field_path / confidence
component_id / identifier_binding_scope
```

规则：

- 高可信完整 Reference / Style Code 是最强 Variant Identity Anchor 之一。
- 官方品牌 `mpn` 经品牌规则校验后可作为 Manufacturer-grade Identifier。
- merchant `sku` 默认属于 merchant namespace。
- Product Group ID 是 Group/Variant Graph 标识，不是 Variant Identity Anchor。
- 高可信 GTIN/EAN/UPC：Strong Positive + Exact Retrieval Key；不同 GTIN 是否 Hard 取决于品牌/市场语义。
- Serial/Certificate/Date Code 默认属于 Individual Item / Production Evidence，不是 Variant Identifier。
- 实例 serial 必须绑定 `brand/manufacturer + identifier_namespace + identifier_type`；不能按裸字符串全局比较。
- GS1 Made-to-Order GTIN / MTO variation 与普通 GTIN、内部 variant、serial 是不同语义；出现时必须先通过 Identifier Semantics Policy 决定其绑定层级。
- Vintage 考虑旧编码、地区差异、包装变化和历史规则。

维护：

```text
identifier_semantics_policy:
brand × market × source_group × field_path × identifier_type × composition_state × customization_state
```

声明 `MANUFACTURER_ID / MERCHANT_ID / GROUP_ID / INSTANCE_ID / MTO_ID / UNKNOWN`，以及 Exact Retrieval、Strong Positive、Hard Conflict、Auto Activation、Physical-Instance-Link 权限。

### 2.4 Source Composition Semantics

每个 Source Offer 生成：

```text
SINGLE_PRODUCT
SINGLE_PRIMARY_WITH_AUXILIARY
MERCHANT_DEFINED_BUNDLE
MANUFACTURER_DEFINED_SET
MERCHANT_MULTIPACK
MULTI_PRODUCT_LOT
ACCESSORY_ONLY
CONFLICTING_COMPOSITION
UNKNOWN_COMPOSITION
```

组件角色：

```text
PRIMARY_IDENTITY_TARGET
INCLUDED_AUXILIARY
MERCHANT_ADD_ON
MANUFACTURER_SET_COMPONENT
PACKAGING_OR_DOCUMENT
ACCESSORY_PRODUCT
OTHER_PRODUCT
UNKNOWN_COMPONENT
```

规则：

1. `SINGLE_PRODUCT`：正常一条 Source → 一个 Identity Target。
2. `SINGLE_PRIMARY_WITH_AUXILIARY`：盒、保卡、防尘袋、备用可拆件不改变主商品 Variant。
3. `MERCHANT_DEFINED_BUNDLE`：可识别主组件，但整个 Listing 默认不产生 SAME_VARIANT Recognition。
4. `MANUFACTURER_DEFINED_SET`：只有官方 Set identifier、Catalog 边界和必要 Hard Facts 齐全时才可成为独立 Canonical。
5. `MERCHANT_MULTIPACK`：数量是 Offer Composition，不是 Variant 属性。
6. `MULTI_PRODUCT_LOT`：没有唯一主商品时不做 SAME_VARIANT Auto-Match。
7. `ACCESSORY_ONLY`：独立配件不得挂到腕表/箱包 Canonical。
8. Composition 冲突/未知输出 `UNKNOWN_SOURCE_COMPOSITION`。

### 2.5 Physical Item / Relisting Independence Gate

二手奢侈品中，同一件实物可能修改标题、换图、换卖家、跨平台搬运或被重新上架，产生多个 Offer ID。不同 Offer ID/URL/平台记录不能自动视为独立实物，也不能自动增加独立证据数。

实例链接状态：

```text
CONFIRMED_SAME_INSTANCE
LIKELY_SAME_INSTANCE
UNKNOWN_INSTANCE_RELATION
CONFIRMED_DIFFERENT_INSTANCE
```

强到弱信号：平台显式 relist lineage → 治理过的品牌级 serial/instance identifier → GTIN+Serial/证书组合 → seller/time+稀有 item-state+图像 → 跨平台 serial/证件/独特刻痕。

固定规则：

- 实例聚类不能成为 SAME_VARIANT Anchor、Hard Conflict 或 Canonical mutation 依据。
- 同一 `physical_item_id` 的多个 Offer 在 activation、weak validation、Attribute Arbitration 独立支持中最多算一个 Physical-Instance Evidence Group。
- 裸 serial 不全局唯一；图片/标题相同单独也不能确认同一实物。
- 同一 Physical Item 的 Item-State/Customization 可随时间变化。
- 实例误合并必须 fail-safe：最多减少独立证据、降低 Coverage，不能制造 Variant 决策。
- Instance lineage 可撤销；拆分后重算 Evidence Independence、Training membership、Fact Arbitration、Risk Audit dependency。

### 2.6 Official Customization / Personalization Semantics Gate

奢侈品“定制/个性化”不能统一当成 Variant，也不能统一当成 Item State。至少区分：

```text
customization_state =
  NONE_STANDARD
  CATALOG_VARIANT_OPTION
  MANUFACTURER_MTO_PROGRAM
  POST_PURCHASE_PERSONALIZATION
  AFTERMARKET_PERSONALIZATION
  UNKNOWN_CUSTOMIZATION

customization_value_scope =
  VARIANT_DEFINING
  PROGRAM_LEVEL
  INSTANCE_SPECIFIC
  DECORATIVE_ONLY
  UNKNOWN
```

`customization_assessment` 至少保存：

```text
source_product_id / source_version / component_id
brand_id / canonical_candidate_id(optional)
customization_state
program_name / program_identifier / program_variant_identifier
selected_options / freeform_personalization
customization_value_scope
official_product_url / official_evidence_ids
identifier_semantics_record_ids
assessment_confidence
policy_version / model_version
```

固定规则：

1. **有限、品牌明确声明的 Catalog Variant Option**（如官方 size/color/material，且具有明确 Variant 边界）继续按普通 Variant 处理。
2. **Manufacturer Made-to-Order Program 与最终客户选择分两层。** 若品牌把“定制项目/配置族”作为独立可订购商品，并提供稳定产品页、Style/GTIN/MTO Identifier 或其他治理级 Catalog 边界，可建立 program-level Canonical；但客户具体 initials、日期、条纹、patch、自由文字等默认仍是 `INSTANCE_SPECIFIC`。
3. **Post-purchase personalization**（刻字、烫印、手绘、购买后换个性化部件等）只进入 Physical Item Configuration，不创建新 Canonical，不重写 Variant Hard Fact。
4. **客户最终 MTO 配置只有在品牌明确为该最终配置分配独立官方 Variant Identifier/Trade Item Identity 时，才可成为独立 Canonical Variant。** “官方允许选择”本身不够。
5. **高基数/自由文本个性化不得造成 Canonical Explosion。** initials、姓名、日期、手写信息、序号式刻字、自由配色/图案选择，不按组合笛卡尔积建 Variant。
6. 一个品牌可能同时存在 program-level product 与 instance-level personalization。例如某个官方定制系列本身可有独立产品层，但同一系列下客户选择的 initials/stripe/patch 不自动产生新的 Variant。
7. `POST_PURCHASE_PERSONALIZATION / AFTERMARKET_PERSONALIZATION / INSTANCE_SPECIFIC` 的视觉/文本差异只能作为 Item-State/Customization Evidence；不得形成 Variant Hard Conflict、NIL、新品 Discovery 或另一个 Variant 的正向身份票。
8. Strong Reference/Style/GTIN 已锁定基础 Variant/Program 时，个性化文字、刻字、颜色条纹、patch 等不能覆盖 Anchor；需单独输出 `item_customization_assessment`。
9. 缺 Strong Anchor 且个性化显著改变外观时，先尝试识别 base/program identity；若无法剥离个性化影响则 `UNKNOWN_CUSTOMIZATION_AMBIGUOUS`，而不是强制选最近 Variant。
10. 限量版“Edition 名称/官方 Edition Identifier”可定义 Variant；单件编号 `37/100` 默认属于 Instance Identifier，不因号码不同创建多个 Variant。
11. 第三方卖家写“custom / bespoke / personalized”不是官方 Variant 证据；必须由品牌 T0/T1 Catalog/Identifier 证明其层级。

## 3. Product Scope / Product-Type Open-set Gate

第一阶段只做腕表与箱包，因此在 Router、NIL、Entity Discovery 前必须证明输入属于当前业务 Scope。Closed-set Top-1 不能直接当 Scope Truth。

```text
IN_SCOPE_WATCH
IN_SCOPE_BAG
IN_SCOPE_UNKNOWN_SUBTYPE
OUT_OF_SCOPE_KNOWN
OPEN_UNKNOWN
CONFLICTING_SCOPE
```

规则：

- Identifier→Product-Type 已治理映射、T0/T1 Product Type 可作为权威 Scope Evidence。
- 模型分类、Embedding nearest category、VLM/OCR、低可信 merchant category 只能作为候选 Scope，默认允许 abstain。
- 父类可靠但 leaf 未知 → `IN_SCOPE_UNKNOWN_SUBTYPE + ANCESTOR_ROUTE`。
- `OUT_OF_SCOPE_KNOWN / OPEN_UNKNOWN / CONFLICTING_SCOPE` 不进入腕表/箱包 NIL/Discovery。
- Scope Gate 与 Category Router 分开版本化；前者决定是否属于系统，后者决定在 in-scope 内去哪检索。

## 4. 标准 Schema 与 Hard Constraint

每个属性断言保存：

```text
raw_value / normalized_value / canonical_value_id
extractor / extractor_version
source / evidence_span / image_bbox
extraction_confidence
validation_status / validation_confidence / validation_record_id
fact_scope
effective_from / effective_to / observed_at
market_scope / region_scope
component_id / component_binding_confidence
physical_item_id(optional)
customization_assessment_id(optional)
```

**Extraction Confidence ≠ Validation Confidence；Validated Observation ≠ Official Variant Spec；Official Customization ≠ 必然独立 Variant。** Hard/Strong 默认只消费 `OFFICIAL_VARIANT_SPEC` 且绑定正确 Component/Customization Scope。

### 4.1 腕表

| 字段 | 默认策略 |
|---|---|
| brand | Hard |
| series/family | Blocking + Strong；品牌规则可 Hard |
| subseries/model | Strong |
| official_reference_full | Hard |
| reference_base | Retrieval/Strong，默认不能代替 full |
| gtin/ean/upc | Strong；条件 Hard |
| case_diameter_mm | Hard |
| case_material | Hard |
| dial_color / dial_type | 定义 Variant 时 Hard；仅 Official Spec |
| bezel | 定义 Variant 时 Hard；仅 Official Spec |
| bracelet_or_strap | 条件 Hard；当前实物/个性化配置不能直接当 Factory Spec |
| caliber / movement | 代际/Variant 区分时 Hard，否则 Strong |
| functions | 区分 Variant 时 Hard |
| edition / generation | Hard |
| serial / limited-edition piece number | Physical Item 属性 |
| engraving / initials / personal date | Item Customization |
| condition / price | Offer/Item 属性 |

### 4.2 箱包

| 字段 | 默认策略 |
|---|---|
| brand | Hard |
| family/series | Blocking + Strong |
| model/style | Strong |
| official_style_code | Hard |
| gtin/ean/upc | Strong；条件 Hard |
| official_size | Hard |
| material / official_color / hardware | Hard；仅 Official Spec |
| pattern / print | Hard；官方 Catalog Variant Spec 才 Hard |
| edition / collaboration | Hard |

| condition / price | Offer/Item 属性 |

图片颜色只做 Soft Evidence；个性化颜色/图案不得覆盖官方 Variant 颜色/图案语义。

## 5. Evidence、来源独立性、事实状态与时间版本

来源等级：T0 品牌官方；T1 已验证主档/授权专业库；T2 高质量专业/二手平台；T3 普通电商/聚合/搜索。

可信度按“来源 × 属性 × 市场/时间 × Component × Instance Lineage × Customization Scope”定义。

### 5.1 Evidence Independence

至少维护：

```text
source_group_id
syndication_group_id
content_fingerprint
image_hash_group_id
physical_item_group_id
upstream_hint
```

多 URL、同 feed、转载文案、相同图、同一 physical item relist、同一 personalization 页面复制都不能机械增加独立 Variant 证据数。

### 5.2 Evidence Family

```text
IDENTIFIER / STRUCTURED_ATTR / VARIANT_GRAPH
LEXICAL_TEXT / SEMANTIC_TEXT / IMAGE_VISUAL
OCR_TEXT / EXTERNAL_WEB / TEMPORAL / PRODUCT_SCOPE
ITEM_INSTANCE / CUSTOMIZATION
```

`ITEM_INSTANCE` 和 `CUSTOMIZATION` 主要用于 provenance、去重、Item Configuration；除非 Customization Gate 已证明它是 `VARIANT_DEFINING`，否则不作为 Variant 正向 Evidence Family。

### 5.3 Fact Promotion Barrier

```text
OBSERVED / DERIVED / REVIEWED_GOLD / GOVERNED_FACT / APPROVED_ALIAS / TAINTED
```

Recognition、Matcher、Cluster、Instance Link、Customization classifier 和 pseudo-label 都是 DERIVED；未经治理不得进入 Exact Variant Identity、Canonical Hard Fact 或 Gold Training Set。

### 5.4 时间版本

Canonical 保存 Variant Spec 时间版本；Physical Item 保存 Item-State/Customization timeline。没有明确代际证据时不跨年代自动合并。

### 5.5 Canonical Attribute Fact Arbitration

仲裁主键：

```text
canonical_variant_id × attribute_id × market_scope × valid_time_scope × variant_generation
```

Resolution：`RESOLVED / MULTI_VALID / CONFLICTED / UNKNOWN / STALE`。

规则：不 latest-write-wins、不简单 majority vote；同 feed/转载/同实物先去重；Authority 按字段/品牌/市场/时间/Component/Fact Scope/Customization Scope 定义；Arbitration 只消费 `OFFICIAL_VARIANT_SPEC` 且通过 Validation/Promotion 的断言；Item-State、维修、instance-specific personalization 不进入 Canonical Current Fact。

## 6. Source Composition、Scope、Extraction、Validation、Item-State 与 Customization

完整前处理：

```text
Raw Source Offer
→ Schema Mapping
→ Source Composition Detection
→ Source Component / Evidence Binding
→ Physical Item / Relisting Assessment
→ Product Scope Open-set Gate
→ Deterministic Parsing / Barcode / OCR
→ Text / Image / VLM Attribute Extraction
→ Normalization / Ontology
→ Attribute Validation
→ Attribute Assertion
→ Item-State / Origin Classification
→ Customization / Personalization Semantics Gate
→ Canonical Arbitration（仅 Official Variant Spec / Variant-defining customization）
```

### 6.1 Composition Gate

Listing 级文本、图片、属性不能在 Composition 未确定前直接生成 Identity Embedding；Identity Evidence 必须绑定主组件或官方 Set；Bundle 主商品 Identifier 只证明主组件；Multipack 数量是 Offer Composition；未知/多商品 Lot/Accessory-only 不进入新品 Discovery。

### 6.2 Barcode / OCR

条码经 deterministic decode + component binding + identifier semantics。Serial OCR 默认生成 Instance-ID Candidate；个性化刻字/姓名/日期 OCR 默认生成 Customization/Item-State Evidence，不能误当 Reference/Style Code。

### 6.3 General VLM

PoC 困难样本结构化抽取基线：Qwen3.5-4B。只能产出候选 Evidence/Scope/Composition/Component/Instance/Customization 提示，无权直接写 Canonical、Truth 或 CERTAIN_MATCH。

### 6.4 Attribute Validation Gate

状态：`VALIDATED_VALID / VALIDATED_INVALID / UNVERIFIED / NOT_APPLICABLE / SOURCE_CONFLICT`。

分层：L0 deterministic → L1 applicability/cross-field → L2 text/profile → L3 cross-source/official → L4 multimodal → L5 LLM/VLM fallback。所有层允许 abstain。Hard Attribute 只有 `VALIDATED_VALID` 且来源/Validator policy 已认证才可进入下一层身份资格判断。

### 6.5 Official Variant Spec vs Observed Item State

```text
fact_scope = OFFICIAL_VARIANT_SPEC / OBSERVED_ITEM_STATE
component_origin = FACTORY_CONFIG / AUTHORIZED_SERVICE_REPLACEMENT / AFTERMARKET_OR_MODIFIED / UNKNOWN_ORIGIN
replaceability_class = IDENTITY_STABLE / SERVICE_REPLACEABLE / USER_REPLACEABLE / COSMETIC_OR_CONSUMABLE / UNKNOWN
```

Canonical 只描述 Official Variant Spec；VALIDATED_VALID 只证明观察值正确，不证明 Factory Config；可替换组件与 Canonical 不一致默认 Item-State Divergence；Strong Identifier 已锁定 Variant 时可解释换件不得覆盖 Anchor；无 Strong Anchor 且关键 Origin 不明时 UNKNOWN。

### 6.6 Customization Decision

Customization 与 Item-State 输出分离：

```text
variant_identity_decision
item_configuration_assessment
customization_assessment
```

`item_configuration_assessment` / `customization_assessment` 可以说明：官方 MTO 项目、刻字、烫印、个性化图案、售后/第三方改装等，但这些不是真假结论。

对于官方 MTO：先匹配 program/base trade item，再判断 final configuration 是否拥有独立 manufacturer-grade identifier；无法证明时保持 program/base Canonical + instance configuration，不为客户每个自由组合创建 Canonical。

## 7. EvidenceProfile、Scope、Router、Composition 与缺模态 Route Policy

每条 Source Offer 计算：

```text
identifier_quality / text_quality / image_quality
hard_attr_coverage / conflict_state / catalog_mode
composition_state / main_component_id
physical_item_link_state / physical_item_id(optional)
customization_state / customization_value_scope
product_scope_state / scope_evidence_level
brand_route_state / category_route_state / routing_scope
image_set_state
item_state_assessment
```

执行顺序：

```text
Composition
→ Component Binding
→ Physical Item/Relist
→ Product Scope
→ Customization Semantics
→ Router
→ Retrieval
```

Router 是 in-scope 后的候选空间优化器，不是身份事实源。Exact Manufacturer Identifier 绕过非权威 Router，但不能绕过 Component、Scope、Composition、Customization、Fact Scope、Identifier Semantics 和 Conflict。

## 8. Candidate Retrieval、Fusion 与 Open-world Guard

召回：Exact Identifier、Brand+Model、Brand+Series+Hard Attr、BM25、Text ANN、Image ANN/hash、Historical Alias、Discovery Neighbor。

PoC 初始 K：Exact≤20、BM25 30、Text ANN 50、Image ANN 每图30/总≤60、Attribute 30；union≤150，Cheap Rerank≈30，Expensive Matcher 10–20。

Gate：

```text
Recall@100 >= 99.5%
Exact survival = 100%
Scope / Router pre-post filter recall 单独监控
```

### 8.1 Component/Scope/Customization/Image-aware Retrieval

- Query text 只由主 Identity Component + 允许用于 identity 的 base/program attributes 生成。
- Bundle/add-on/accessory、实例刻字、initials、自由 personalization text 不进入主商品 hard filter。
- Image ANN 只使用通过 Composition、Scope、Image Gate 的图/region；个性化覆盖区域可作为 masked/low-weight region，避免其主导 base identity retrieval。
- Identity-critical Search Filter 只消费已验证、已仲裁、已发布 Current Fact。
- Exact 候选永不被 Soft Fusion 截断；零/少标签使用 RRF baseline。

### 8.2 NIL / Recovery

CandidateSet：`KNOWN_CANDIDATE / AMBIGUOUS_KNOWN / POSSIBLE_NIL / RETRIEVAL_FAILURE / ROUTING_AMBIGUOUS`。

进入 NIL/Discovery 前完成：

```text
Scope Gate
+ Router bypass（必要时）
+ Composition Gate
+ Item-State Divergence Check
+ Customization / MTO Recheck
```

Out-of-scope、Open Unknown、Composition Unknown、Lot、Accessory-only、Search/Publication Failure、可解释 customization divergence 都不得直接解释成新品。

同一 Physical Item relist 也不能分别创建多个 PROPOSED；Discovery pool 先按 instance/relist/duplicate evidence 保守去重。

## 9. Embedding、Visual Search 与 Image Set Safety

Text：Qwen3-Embedding-0.6B；Text Reranker：Qwen3-Reranker-0.6B。

Image：SigLIP2 baseline；DINOv3 challenger（Legal Gate）；Qwen3-VL Embedding/Reranker 只在困难路径验证收益。近邻 Variant 使用局部 patch/local descriptor shortlist rerank。

### 9.1 Image Set Identity / Utility Gate

图片角色：`PRODUCT_PRIMARY / PRODUCT_DETAIL / MODEL_LIFESTYLE / PACKAGING_OR_DOCUMENT / COLLAGE / ACCESSORY_OR_AFTERMARKET / DECORATIVE / OTHER_PRODUCT_SUSPECT / UNKNOWN`。

规则：raw image set 不直接 max；拼图 region 化；`CROSS_VARIANT_REUSE` 库存图不做 SAME_VARIANT Positive；文档图可 OCR 不做外观 ANN；Bundle 全景图必须分离主组件；同 Listing 多图仍属一个 IMAGE_VISUAL Family；同一 Physical Item relist 图片只增强 Instance Linking；合格图支持不同 Variant → visual UNKNOWN/置零。

个性化区域（engraving、initials、hot-stamp、stripe、patch、手绘等）默认不作为 Variant Hard Visual Feature；可用于 Physical Item/Customization Linking，但不能因为个性化一致/不一致决定 SAME_VARIANT。

## 10. Pair Matcher、Conflict Engine 与 Decision Policy

```text
Candidate Pair
→ Pre-Conflict
→ Deterministic Features
→ Structured/Text Matcher
→ Multimodal Difficult Pair
→ Local Visual（near-tie）
→ Post-Conflict
→ Calibration
→ Evidence-Family Risk Policy
→ Candidate/NIL/Ambiguity/Scope/Composition/Customization Guard
→ Decision
```

`CERTAIN_MATCH` 至少满足：

```text
NO HARD_CONFLICT
AND product_scope_state in scope
AND CandidateSetState == KNOWN_CANDIDATE
AND Composition 允许 SAME_VARIANT
AND Customization 不造成未解决 Variant-boundary ambiguity
AND Canonical Hard Resolution 可服务
AND (
  Strong Identity Anchor
  OR calibrated_matcher >= tau_segment
     + >=2 non-duplicate Variant Evidence Families
     + Ambiguity Guard
)
```

## 11. Entity Linking、Discovery、Instance Lineage 与 Canonical Health

### 11.1 Linking

```text
Source Snapshot
→ Composition + Component Binding
→ Physical Item / Relist
→ Product Scope
→ Validation / Item-State / Customization / Router / Image Gate
→ Hybrid Retrieval
→ Pair / Conflict / Calibration
→ CandidateSetAssessment
→ SAME_VARIANT CERTAIN_MATCH
→ Recognition Commit Barrier
```

### 11.2 Physical Item Lineage

Physical Item 用于 Evidence Independence、Item-State/Customization Timeline、Relisting suppression、Benchmark split、Risk dependency clustering、Incident sibling scan。Variant 未确定时实例 cluster 也可存在，但不得通过 membership 推导 Canonical。

### 11.3 Discovery / Novelty

```text
POSSIBLE_NIL
→ Scope Recheck + Route Recovery
→ Composition / Item-State / Customization / Instance-Duplicate Recheck
→ Official/Web Evidence
→ Strict Blocking
→ Constraint-aware Clustering
→ PROPOSED
→ Novelty/Uniqueness + Required Hard Facts + Customization Boundary
→ ACTIVE or remain PROPOSED
```

Discovery 前置：Scope in-scope；Composition 允许；维修/aftermarket/instance personalization 不当新品；官方 MTO program 与最终 customer configuration 分层；同一 Physical Item relist 不能生成多个独立 PROPOSED。

`PROPOSED → ACTIVE` 必须通过当前 publication 的 Novelty/Uniqueness Gate。Variant-unique Manufacturer ID / official external Variant ID 使用唯一 identity claim 防并发双 ACTIVE。

### 11.4 ACTIVE Canonical Health / Split / Merge

周期性检查 Hard Conflict、cannot-link、Manufacturer ID partitions、Fact Conflict、review disagreement、temporal generation、Customization Boundary collision。治理级冲突立即 freeze。

GNN/GraphCR/SuperPart 等只能 Detect/Prioritize/Propose；Split/Merge 需 Governance + 原子 Publication。Merge 时重新 Validation/Arbitration/Customization Scope 检查。

## 12. Web Evidence Agent 与 Official Web Catalog

优先级：品牌官网 → 官方目录/经销资料 → 专业数据库 → 高质量二手平台 → 通用搜索。

官方站解析 ProductGroup/Product、DOM、Embedded State、Identifier、Variant URL，以及 personalization/MTO program 页面，产出版本化 Assertions/Variant Graph/Customization Evidence。Web/Agent 无权直接修改 Canonical、Scope Truth、Customization Truth、Current Fact、Physical Item Truth 或 CERTAIN_MATCH。

品牌“personalizable/customizable”标签只说明提供个性化能力，不等于每个客户组合是独立 Variant；必须结合产品级 Identifier、官方可订购边界和 Identifier Semantics 判断。

通用搜索和二手平台重复页面先做 syndication/content/image/Physical-Instance dedupe；多个网页若追溯到同一实物或同一 personalization 页面，只算对应独立 Evidence Group。

## 14. Review、风险认证与 Reviewer Quality

三轨：`TRAINING_REVIEW / CERTIFICATION_AUDIT / GOVERNANCE_REVIEW`。

Certification 以最终 Recognition Decision 为单位，概率抽样保存 inclusion probability/stratum，并报告 i.i.d. 与 dependency-cluster-aware 风险上界，release 取最保守值。

Certification 默认双人独立盲审；允许 SAME_VARIANT / DIFFERENT_VARIANT / INSUFFICIENT_EVIDENCE / SOURCE_DATA_ERROR，分歧 adjudication。Reviewer 资格、指南、UI、Evidence Snapshot 全部版本化。

独立控制集包括：Pair、Attribute、Image Set、Item-State、Customization/MTO、Composition、Scope、Physical Item/Relisting。

Customization Control Set 至少覆盖：

- Cartier 类 purchase/post-purchase engraving：同一官方 Variant 不同 initials/date。
- Louis Vuitton 类普通 hot stamping：标准商品 + instance personalization。
- Louis Vuitton Mon Monogram 类官方 Made-to-Order program：program/base identity 与最终自由组合分层。
- 官方定制项目有独立产品页/价格但客户 initials/stripe/patch 不同。
- 卖家写 custom/bespoke 但无官方证据。
- 个性化区域改变整体视觉颜色/图案导致近邻 Variant 误检。
- 限量 Edition 名称相同但 piece number `x/N` 不同。

Risk dependency keys 至少包括 source/syndication、physical_item_group、canonical_variant、customization_program/config group、model/policy/publication/time bucket。高频个性化订单/同一 MTO program 不得虚增独立故障簇。

## 16. Incremental、CDC、Publication 与 Recognition Commit

Canonical/Attribute Resolution mutation 与 catalog outbox 同事务；幂等 Search 投影用 external version，refresh/checkpoint 后推进 publication watermark。

Source 文本、图片、category/bundle/component/instance identifier/relist/customization 信息变化生成新 `source_version`；影响 Composition、Scope、Physical Item、Customization、Item-State、Image eligibility 或 Hard Assertion 时旧 Decision Snapshot 失效。

Recognition Commit：推理阶段不持长事务，CERTAIN_MATCH 进入短 ACID：

```text
idempotency intent
→ Source CAS
→ validate Source / Composition / Scope / Customization / Canonical / publication / fact versions
→ ensure single current link
→ immutable Recognition
→ current link
→ Source state
→ one Review/outbox
```

Physical Item/Customization 更新与 Recognition 历史分离；若重算影响 Candidate/Fact/Certification，触发 reprocess/re-arbitration/re-certification，不原地改历史 Recognition。

## 17. Production Runtime Reliability

mandatory stage timeout/熔断/跳过形成新 route signature；未经单独认证只能 UNKNOWN。

每请求 end-to-end deadline；依赖唯一 retry owner；指数退避+jitter+retry budget；bounded queue+circuit breaker。

Load shedding：P4 backfill/bulk validation/instance-dedupe → P3 Discovery/Web/Scope/Composition/Customization enrichment → P2 near-tie expensive → P1/P0 Linking。

Instance/Customization Gate 不可用时可以降低 Evidence Independence/Discovery/Configuration 输出，但不能把未知关系当作 Variant Hard Evidence；依赖该 Gate 才能排除 personalization shortcut 的路径未经认证时必须 UNKNOWN。

## 18. 容量、成本与性能

10M 商品、平均3图、10M text + 30M image vectors、512d：FP16 导出约 40.96GB；OpenSearch FP32 完整向量约 81.92GB，不含索引/副本/shadow。

PoC（1–2M）：1×L4 24GB、1×8 vCPU/64GB OpenSearch、0.5TB SSD。

10M 压测起点：3×8 vCPU/64GB OpenSearch、3×1TB usable storage、2×L4 24GB online GPU；历史回填临时 4–8×L4。

单独统计：Physical Instance、Scope/Composition/Image/Validation、Customization classification 的 QPS/p95、fallback rate、review cost；成本与 `Coverage @ 99.9% Precision`、`Cost per Confirmed Recognition` 联合优化。

## 20. MVP → Production

### Phase 0：数据审计与 Gold

建立字段完整度、Ontology、Hard Conflict、Identifier、来源独立性、Router、NIL/near-tie、Review、Attribute、Image Set、Item-State、Composition、Scope、Physical Item，以及 **Customization/MTO Gold**。

### Phase 2：Hybrid Text + Router + Instance/Customization Expansion

BM25、Qwen3-Embedding/Reranker、箱包、Calibration/NIL；上线品牌级 Customization Semantics Policy。普通 hot stamp/engraving 从 identity text 中剥离或降权；official MTO program 先识别 program/base identity，再解析 customer configuration。

zxing-cpp、PP-OCRv6、PaddleOCR-VL、SigLIP2/DINO challenger、局部视觉、Qwen3.5/Qwen3-VL。OCR/VLM 需把 Reference 与 personalization text 分型；视觉局部需要避免把 initials/patch/stripe 当 Variant Hard Feature。

POSSIBLE_NIL、ProductGroup/Product、External Variant Graph、Novelty、Cluster Health、Split/Merge。Official Web Agent 同时抓取 personalization/MTO program 边界；Discovery 前必须排除 instance-specific customization 造成的 False NIL/False Novel。

Pair、Scope、Attribute、Image、Item-State、Composition、Physical-Instance、Customization 模型分别版本化/认证；Review feedback、Hard Negative、active learning、domain encoder、learned fusion、shadow/A-B/rollback。

## 21. 正式开启自动识别 Gate

全部满足才扩大 Auto-Match：

1. `Precision@Auto-Match >= 99.9%`，`Recall@100 >= 99.5%`，Exact survival=100%。
2. Certification Audit 满足 sampling provenance 与 cluster-aware risk upper bound。
3. Hard Conflict、Seen/Unseen/Time-shift/Vintage/缺图/缺型号/低质图达标。
4. Synthetic/Pseudo evidence 不形成 Hard Fact/Identity Anchor/Certification Gold。
5. AMBIGUOUS/NIL/ROUTING_AMBIGUOUS/PRODUCT_SCOPE/SOURCE_COMPOSITION/CUSTOMIZATION/RETRIEVAL_FAILURE/PUBLICATION/CATALOG_REPAIR/FACT_CONFLICT 不得绕过 Guard。
6. Product Group ID、merchant SKU、Web structured-data 语义违规=0。
7. ACTIVE 模型/Scope/Router/Composition/Image/Instance/Customization/Attribute/Item-State policy lineage=100%。
8. SPLIT/MERGE/TAINT 状态新 Auto-Match=0；repair partial publication CERTAIN_MATCH=0。
9. PROPOSED→ACTIVE 必须 novelty=UNIQUE，required Hard Facts 与 Customization Boundary 可服务。
10. Recognition Commit duplicate/partial/stale/multiple-current-link=0。
11. Router 非权威 hard prune / false NIL / false new canonical=0。
12. Identity/Search/Hard Conflict 只消费已发布 Canonical Resolution。
13. Hard Attribute UNVERIFIED/INVALID/SOURCE_CONFLICT 参与身份链路=0。
14. Image Gate/shared-image/collage 违规=0。
15. OBSERVED_ITEM_STATE/Service/Aftermarket 被当 Factory Spec=0。
16. Composition 未完成却假定 SINGLE_PRODUCT 并 Auto-Match=0。
17. Merchant Bundle/Multipack/Lot/Accessory-only SAME_VARIANT=0；Bundle accessory evidence leakage=0。
18. OUT_OF_SCOPE/OPEN_UNKNOWN/CONFLICTING_SCOPE 进入 SAME_VARIANT/Discovery=0。
19. Serial/Date Code/Certificate INSTANCE_ID 被当 Variant Reference=0。
20. 同一 physical item 的 relist 被计为多个独立激活/Arbitration 支持=0；同实例跨 split 泄漏=0。
21. Physical Item cluster 被用作 Variant Anchor/Hard Conflict/Canonical mutation=0。
22. **POST_PURCHASE_PERSONALIZATION / AFTERMARKET_PERSONALIZATION / INSTANCE_SPECIFIC 被创建成独立 Canonical Variant 的违规=0。**
23. **客户 initials/姓名/日期/自由刻字/自由 patch/stripe 直接进入 Variant Hard Conflict、Exact Filter、Variant Identity Embedding 文本的违规=0。**
24. **Manufacturer MTO Program 只有 program-level Catalog 边界而 final configuration 无独立官方 Variant Identifier 时，按每个 customer configuration 创建 Canonical 的违规=0。**
25. **官方 finite Catalog Variant Option 被错误降为纯 Item Personalization、导致不同官方 Variant 被合并的违规=0。**
26. **第三方卖家 `custom/bespoke/personalized` 声明未经 T0/T1 证明却改变 Canonical Variant 边界的违规=0。**
27. **限量版 piece number `x/N` 被当 Variant Identifier 的违规=0；Edition/official edition identifier 仍按品牌规则保留 Variant 语义。**
28. **Customization/MTO policy、program catalog evidence、Gold Set、模型与阈值必须版本化；品牌项目规则变化后未重认证的 customization path 不得继续 Auto-Match。**

指标退化时优先降低 Coverage，不通过“官方允许定制 = 每个组合都是 Variant”或“有个性化外观 = 新 SKU”的捷径提高自动识别率。

## 23. 最终生产原则

```text
Raw Source Offer
          ↓
Source Composition / Component Binding
          ↓
Physical Item / Relisting Independence
          ↓
Product Scope Open-set Gate
          ↓
Attribute Extraction + Validation
          ↓
Official-Spec vs Observed-Item-State / Origin
          ↓
Official Customization / MTO Semantics Gate
          ↓
Evidence Assertions + Source/Instance Independence
          ↓
Canonical Variant-Spec Fact Arbitration
          ↓
In-scope Router / Filter Safety
          ↓
Image Set Identity / Utility Gate
          ↓
Component/Customization-aware Hybrid Retrieval + Exact Preserve
          ↓
Structured + Text + Eligible Image Evidence
          ↓
Hard Conflict + Calibration
          ↓
Candidate-set / NIL / Ambiguity / Scope / Composition / Customization Guard
          ↓
Constraint-aware Graph Resolution
          ↓
SAME_VARIANT CERTAIN_MATCH
          ↓
Recognition Commit Barrier
          ↓
Current Link + Immutable Recognition + Pending Review
          ↓
Canonical Novelty / Health / Repair
          ↓
Independent Risk Audit
          ↓
Controlled Training + Immutable Lineage
```

固定原则：

1. **Identity first，Similarity second。**
2. **Source Offer ≠ 必然一个商品；Offer ID ≠ Physical Item ID；Physical Item ID ≠ Variant ID。**
3. **同一件实物的 relist/跨平台搬运不能伪装成多个独立 Variant 证据。**
4. **Serial/Date Code/Certificate 默认是实例/生产证据，不是官方 Variant Reference。**
5. **官方个性化能力不等于每个客户组合都是独立 Variant。**
6. **Catalog Variant Option、Manufacturer MTO Program、最终客户配置、Post-purchase Personalization 必须分层。**
7. **Manufacturer MTO program 可以有 program-level Canonical；final configuration 只有具备独立官方 Variant Identity 时才另建 Canonical。**
8. **initials、姓名、日期、自由刻字、patch/stripe 等高基数 personalization 默认属于 Physical Item Configuration。**
9. **第一阶段 Scope 只有腕表与箱包；Closed-set Top-1 不是 Scope Truth。**
10. **Merchant Bundle / Multipack / Lot 的组合关系不能伪装 SAME_VARIANT；附件/配件 Evidence 与主商品隔离。**
11. **Extraction confidence ≠ fact correctness；Validated Observation ≠ Official Variant Spec。**
12. **Canonical 只保存 Official Variant Spec；二手当前组件与 instance personalization 进入 Item-State/Customization 层。**
13. **官方维修替换件不自动成为 Factory Config；官方刻字/烫印也不自动成为 Variant Spec。**
14. **Hard Conflict 只建立在 Validation、正确 Fact Scope、Component Binding、Customization Scope 合格的证据上。**
15. **Synthetic/Pseudo evidence 不能形成 Hard Fact / Identity Anchor / Certification Gold。**
16. **多张图片不是多份独立身份票；同一实物的多次 Listing 也不是多份独立来源票。**
17. **必须显式允许 NIL；near-tie / customization ambiguity 必须 Abstain。**
18. **Exact Identifier 绕过非权威 Router，但不能绕过 Scope、Component、Composition、Customization 和 Identifier Semantics。**
19. **训练 Review、Scope/Composition/Image/Attribute/Item-State/Customization/Physical-Instance Gold、Risk Certification 是不同资产。**
20. **Product Group ID 是关系标识；Merchant SKU、Manufacturer ID、MTO ID、Instance ID 分命名空间。**
21. **Canonical Current Fact 是已验证 Official-Spec Assertions 的版本化 Arbitration，不是最近值/多数票/同一实物重复票/客户个性化票。**
22. **Search/Hard Conflict 只消费已验证、已仲裁、已发布 Current Fact。**
23. **DB→Search 使用 Transactional Outbox + Idempotent Projection + Monotonic Version + Publication Barrier。**
24. **ACTIVE Canonical 持续检查 over-merge、under-merge、Fact Conflict 与 Customization Boundary collision。**
25. **Entity Discovery 是新品证明问题，不是 relist、换件或 personalization 导致“没匹配上”的同义词。**
26. **Cluster/Instance/Customization Model 只能 Detect/Prioritize/Propose，不能直接修改 Canonical。**
27. **所有模型、Scope/Router/Composition/Image/Instance/Customization/Attribute/Item-State Policy 和数据集都不可变、可追溯。**
28. **依赖故障或 mandatory gate 缺失时 fail closed 为 UNKNOWN。**
29. **模型 CERTAIN_MATCH 只是待提交 Decision；Recognition Commit 后业务关系才生效。**
30. **任何复杂度只有在提高 Coverage@99.9% Precision、降低 False Merge/False Novel/False In-Scope/Composition Leakage/Instance Evidence Inflation/Customization Explosion，提高事务可靠性或降低总成本时才有价值。**
