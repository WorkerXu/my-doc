# 奢侈品识别方案

## 1. 目标与边界

系统目标不是“找最像的商品”，而是把雷小安、奢当家、腕表之家、小迈步、爱回收等来源的异构记录归一到**同一个官方商品变体（Official Variant）**，并产生可审核、可回放、可治理的 Recognition。

第一阶段只覆盖：

```text
IN_SCOPE_WATCH
IN_SCOPE_BAG
```

历史数据约 100 万–1000 万条。腕表已有部分品牌/系列/型号主档；箱包主档不完整，因此系统同时支持 **Entity Linking** 与 **Entity Discovery**。

核心原则：

> **Precision >> Recall。宁可 UNKNOWN / OUT_OF_SCOPE，也不能把不同官方 Variant 错合并。**

系统不做真假鉴定。成色、价格、库存、卖家、单件序列号、保卡状态属于 Offer / Physical Item Instance；维修换件、附属物、商家 Bundle、Multipack、Lot、重复上架，以及业务范围外商品都不能被误当成新的官方 Variant。

机器成功识别后必须形成一致业务结果：

```text
Source Product 当前状态
+ Source → Canonical 当前识别关系
+ Immutable Recognition Record
+ Pending Review 任务/事件
```

四个副作用必须原子、幂等、可重放。

## 2. 核心实体、Source Composition、Physical Item Instance 与 Identifier

### 2.1 Canonical Identity

```text
Brand
  └── Product Family / Series
       └── Product Model
            └── Canonical Variant
```

Canonical 关系：

```text
SAME_VARIANT
VARIANT_OF
SAME_MODEL
SAME_SERIES
VISUALLY_SIMILAR
UNKNOWN
```

只有 `SAME_VARIANT` 可以进入普通 Canonical 聚类并生成默认自动 Recognition。

Canonical Variant 状态：

```text
ACTIVE
PROPOSED
SPLIT_PENDING
MERGE_PENDING
RETIRED
MERGED
SPLIT
TAINTED
```

`MERGED` 可 redirect 到唯一 survivor；`SPLIT` 是 one-to-many，旧 Canonical 必须重新解析。

### 2.2 Source Offer / Component / Instance

Source 侧不能假设“一条记录 = 一个商品 = 一件实物”。统一建模：

```text
Source Offer / Listing
   └── Source Component(s)
        └── 0..1 Primary Identity Target
              └── 0..1 Physical Item Instance（可未知）
                    └── Canonical Variant
```

组合型 Offer 额外保存：

```text
PRIMARY_COMPONENT_VARIANT
MULTIPACK_OF_VARIANT
ACCESSORY_OF_VARIANT
CONTAINS_VARIANT
```

Physical Item 关系：

```text
INSTANCE_OF_VARIANT
SAME_PHYSICAL_ITEM
RELIST_OF
POSSIBLE_SAME_PHYSICAL_ITEM
```

**Physical Item Instance 层只用于实例追踪、Evidence 去重、Item-State 时间线、训练/审计聚类；不得直接产生 Variant Identity。**

### 2.3 Identifier Namespace

统一采集：

```text
reference_full / style_code / mpn
gtin / ean / upc
merchant_sku
product_group_id / item_group_id
variant_dimension_keys / variant_dimension_values
serial_number / date_code / certificate_id / instance_identifier
barcode_symbology / payload / checksum
market
identifier_namespace / identifier_owner / identifier_scope
identifier_source / source_field_path / confidence
component_id / identifier_binding_scope
```

规则：

- 高可信完整 Reference / Style Code 是最强 Variant Identity Anchor 之一。
- 官方品牌 `mpn` 经品牌规则校验后可作为 Manufacturer-grade Identifier。
- merchant `sku` 默认属于 merchant namespace。
- Product Group ID 是 Group/Variant Graph 标识，不是 Variant Identity Anchor。
- 高可信 GTIN/EAN/UPC：Strong Positive + Exact Retrieval Key；不同 GTIN 是否构成 Hard Conflict 取决于品牌/市场语义。
- Serial/Certificate/Date Code 默认属于 **Individual Item / Production Evidence**，不是 Variant Identifier。
- 实例 serial 不能只按裸字符串全局比较；必须绑定 `brand/manufacturer + identifier_namespace + identifier_type`。若采用 GS1 语义，单件唯一性按 GTIN + Serial 等正确粒度解释。
- Vintage 考虑旧编码、地区差异、包装变化和历史规则。

维护：

```text
identifier_semantics_policy:
brand × market × source_group × field_path × identifier_type × composition_state
```

声明 `MANUFACTURER_ID / MERCHANT_ID / GROUP_ID / INSTANCE_ID / UNKNOWN`，以及 Exact Retrieval、Strong Positive、Hard Conflict、Auto Activation、Physical-Instance-Link 权限。

### 2.4 Source Composition Semantics

每个 Source Offer 生成：

```text
SINGLE_PRODUCT
SINGLE_PRIMARY_WITH_AUXILIARY
MERCHANT_DEFINED_BUNDLE
MANUFACTURER_DEFINED_SET
MERCHANT_MULTIPACK
MULTI_PRODUCT_LOT
ACCESSORY_ONLY
CONFLICTING_COMPOSITION
UNKNOWN_COMPOSITION
```

组件角色：

```text
PRIMARY_IDENTITY_TARGET
INCLUDED_AUXILIARY
MERCHANT_ADD_ON
MANUFACTURER_SET_COMPONENT
PACKAGING_OR_DOCUMENT
ACCESSORY_PRODUCT
OTHER_PRODUCT
UNKNOWN_COMPONENT
```

固定语义：

1. `SINGLE_PRODUCT`：正常一条 Source → 一个 Identity Target。
2. `SINGLE_PRIMARY_WITH_AUXILIARY`：盒、保卡、防尘袋、备用可拆件等不改变主商品 Variant。
3. `MERCHANT_DEFINED_BUNDLE`：可识别主组件，但整个 Listing 默认不产生 SAME_VARIANT Recognition。
4. `MANUFACTURER_DEFINED_SET`：只有官方 Set identifier、Catalog 边界和必要 Hard Facts 齐全时才能成为独立 Canonical。
5. `MERCHANT_MULTIPACK`：数量是 Offer Composition，不是 Variant 属性。
6. `MULTI_PRODUCT_LOT`：没有唯一主商品时不做 SAME_VARIANT Auto-Match。
7. `ACCESSORY_ONLY`：独立配件不得挂到腕表/箱包 Canonical。
8. Composition 冲突/未知输出 `UNKNOWN_SOURCE_COMPOSITION`。

### 2.5 Physical Item Instance / Relisting Independence Gate

二手奢侈品中，同一件实物可能修改标题、换图、换卖家、跨平台搬运或被平台重新上架，产生多个不同 Offer ID。**不同 Source Offer ID、URL 或平台记录不能自动视为独立实物，也不能自动增加独立证据数。**

实例链接状态：

```text
CONFIRMED_SAME_INSTANCE
LIKELY_SAME_INSTANCE
UNKNOWN_INSTANCE_RELATION
CONFIRMED_DIFFERENT_INSTANCE
```

`physical_item_instance` 至少保存：

```text
physical_item_id
brand_id / canonical_variant_id(optional)
instance_identifier_namespace
normalized_instance_identifiers / hashed_instance_identifiers
first_seen_at / last_seen_at
instance_link_policy_version
status
```

`source_item_instance_link` 至少保存：

```text
source_product_id / source_version / component_id
physical_item_id
link_state / confidence
link_evidence_ids
platform_relist_parent_id / relist_chain_id
link_model_or_policy_version
created_at
```

实例链接信号按强到弱使用：

```text
A. 平台显式 relist lineage / old→new listing relation
B. 已治理的 brand-scoped Manufacturer Serial / official instance identifier
C. GTIN + Serial / official certificate-instance combination
D. 同一卖家 + 时间连续 + exact/near-duplicate image + 稀有 Item-State 特征
E. 跨平台 serial/certificate + 独特刻痕/维修特征/局部图像一致性
```

固定规则：

1. **实例聚类不得成为 SAME_VARIANT Identity Anchor。** `CONFIRMED_SAME_INSTANCE` 只能说明两个 Offer 很可能描述同一件实物；Variant 仍按 Official Spec/Identifier/Hard Facts 识别。
2. **实例聚类用于保守去重。** 同一 `physical_item_id` 的多个 Offer 在 `independent_source_count / Canonical activation / weak cross-source validation / Attribute Arbitration independent support` 中最多算一个 Physical-Instance Evidence Group。
3. **平台 relist 是最强实例 lineage 之一。** 明确 old→new listing 关系时，即使新 Listing ID 不同，也不能当成新独立实物证据。
4. **裸 serial 不全局唯一。** Serial 必须有正确品牌/namespace/产品语境；存在冲突或格式不确定时只生成 instance candidate，不做强链接。
5. **图片/标题相同不够。** exact/pHash/text copy 单独只能生成 `LIKELY_SAME_INSTANCE` 或 syndication hint，不能确认同一实物，因为品牌库存图、模板文案可能复用。
6. **Observed Item State 可随时间变化。** 同一 Physical Item 在维修、换带、磨损、配件变化后可出现不同图片/属性；实例时间线允许 state change，不要求所有观测完全一致。
7. **误把两个独立实例合成一个实例组时必须 fail-safe。** Instance cluster 只能减少独立证据、降低 Coverage；不得因此生成 NON_MATCH、Hard Conflict、Canonical Merge/Split 或 Variant Decision。
8. **同一实例的重复上架不能自证 Canonical。** 多次 relist、跨站搬运、多个 URL 即使文案不同，也不能满足“多个独立来源”激活门槛，除非存在真正独立的 Variant-level 官方/治理证据。
9. **实例 lineage 可撤销。** 新 serial、官方证明或高可信冲突证明两个 Offer 属于不同实物时，拆分 `physical_item_id`，并重算 independent evidence、训练 membership、风险审计 dependency keys；历史 link 不删除，使用 superseding event。

## 3. Product Scope / Product-Type Open-set Gate

第一阶段只做腕表与箱包，因此在 Router、NIL、Entity Discovery 之前必须先证明输入属于当前业务 Scope。Closed-set Top-1 不能直接当 Scope Truth。

Scope：

```text
IN_SCOPE_WATCH
IN_SCOPE_BAG
IN_SCOPE_UNKNOWN_SUBTYPE
OUT_OF_SCOPE_KNOWN
OPEN_UNKNOWN
CONFLICTING_SCOPE
```

规则：

- Identifier→Product-Type 已治理映射、T0/T1 Product Type 可作为权威 Scope Evidence。
- 模型分类、Embedding nearest category、VLM/OCR、低可信 merchant category 只能作为候选 Scope，默认允许 abstain。
- 父类可靠但 leaf 未知 → `IN_SCOPE_UNKNOWN_SUBTYPE + ANCESTOR_ROUTE`。
- `OUT_OF_SCOPE_KNOWN / OPEN_UNKNOWN / CONFLICTING_SCOPE` 不进入腕表/箱包 NIL/Discovery。
- Scope Gate 与 Category Router 分开版本化；前者决定是否属于系统，后者决定在 in-scope 内去哪检索。
- Open-set/OOD threshold 只用独立 holdout/时间窗选择，不用 certification set 调参；不以 AUROC 单指标直接上线。

## 4. 标准 Schema 与 Hard Constraint

每个属性断言保存：

```text
fact_scope
```

**Extraction Confidence ≠ Validation Confidence；Validated Observation ≠ Official Variant Spec。** Hard/Strong 默认只消费 `OFFICIAL_VARIANT_SPEC` 且绑定正确 Component。

## 5. Evidence、来源独立性、事实状态与时间版本

来源等级：T0 品牌官方；T1 已验证主档/授权专业库；T2 高质量专业/二手平台；T3 普通电商/聚合/搜索。

可信度按“来源 × 属性 × 市场/时间 × Component × Instance Lineage”定义。

### 5.1 Evidence Independence

至少维护：

```text
source_group_id
syndication_group_id
content_fingerprint
image_hash_group_id
physical_item_group_id
upstream_hint
```

独立性规则：

- 多 URL 不等于多来源。
- 同 feed、转载文案、相同图、同一 physical item 的 relist 都不能机械增加独立证据数。
- `physical_item_group_id` 是来源独立性的一个去重维度，不替代 `source_group/syndication/content/image`。
- Variant-level 官方事实与 Item-instance observation 分开计票；同一实物在多个平台重复出现不能压过一条真正独立 T0/T1 Official Spec。

### 5.2 Evidence Family

```text
IDENTIFIER / STRUCTURED_ATTR / VARIANT_GRAPH
LEXICAL_TEXT / SEMANTIC_TEXT / IMAGE_VISUAL
OCR_TEXT / EXTERNAL_WEB / TEMPORAL / PRODUCT_SCOPE
ITEM_INSTANCE
```

`ITEM_INSTANCE` 主要用于“这些 Offer 是否同一件实物”的 provenance/去重，不作为 Variant 正向 Evidence Family。

同一原始观测派生的多个分数不是多票；不同 Component 或同一 Physical Item 的多个 Listing 也不能机械相加支持同一 Variant。

### 5.3 Fact Promotion Barrier

```text
OBSERVED / DERIVED / REVIEWED_GOLD / GOVERNED_FACT / APPROVED_ALIAS / TAINTED
```

Recognition、Matcher、Cluster、Instance Link 模型输出和 pseudo-label 都是 DERIVED；未经治理不得进入 Exact Variant Identity、Canonical Hard Fact 或 Gold Training Set。

### 5.4 时间版本

Canonical 属性保存 `valid_from / valid_to / version / evidence_ids`；Physical Item 保存 Item-State timeline。没有明确代际证据时不跨年代自动合并 Variant。

### 5.5 Canonical Attribute Fact Arbitration

仲裁主键：

```text
canonical_variant_id × attribute_id × market_scope × valid_time_scope × variant_generation
```

Resolution：`RESOLVED / MULTI_VALID / CONFLICTED / UNKNOWN / STALE`。

规则：

- 不 latest-write-wins，不简单 majority vote。
- syndicated、copy、same-physical-item relist 先去重。
- Authority 按字段、品牌、市场、有效期、Component 和 Fact Scope 定义。
- 同 scope 治理级 Hard Attribute 冲突 → `CONFLICTED`，停止依赖该字段 Auto-Match。
- OCR/VLM/普通平台不能覆盖治理级 T0/T1。
- 缺失不是反证；多值按属性语义比较。
- 上游撤回/TAINT/Instance cluster 修订 → `STALE` 并重仲裁。
- Arbitration 只消费 `OFFICIAL_VARIANT_SPEC` 且通过 Validation/Promotion Gate 的断言；Item-State/同实例重复 Observation 不能被多数票提升成 Canonical Fact。
- Search/Matching/Conflict 只消费已发布 `RESOLVED/MULTI_VALID` Current Fact。

## 6. Source Composition、Scope、Extraction、Validation、OCR 与 Item-State

完整前处理：

```text
Raw Source Offer
→ Schema Mapping
→ Source Composition Detection
→ Source Component / Evidence Binding
→ Physical Item / Relisting Assessment
→ Product Scope Open-set Gate
→ Deterministic Parsing / Barcode / OCR
→ Text / Image / VLM Attribute Extraction
→ Normalization / Ontology
→ Attribute Validation
→ Attribute Assertion
→ Item-State / Origin Classification
→ Canonical Arbitration（仅 Official-Spec）
```

### 6.1 Composition Gate

- Listing 级文本、图片、属性不能在 Composition 未确定前直接生成商品级 Identity Embedding。
- Identity Evidence 必须绑定 Primary Identity Component 或官方 Set。
- Bundle 主商品 GTIN/MPN 只能证明主组件候选，不能证明整个 Listing=SAME_VARIANT。
- Manufacturer-defined Set Identifier 绑定 Set 本身。
- Multipack 数量是 Offer Composition。
- Composition 未知/多商品 Lot/Accessory-only 不进入新品 Discovery。

### 6.2 Barcode / OCR

条码使用 zxing-cpp 等确定性 decoder，并完成 `component_binding_scope` 与 identifier type 判别。证件、拼图、配件上的 Identifier 不自动绑定主商品。

Serial OCR 默认生成 Instance-ID Candidate；只有 identifier semantics policy 验证后才能用于 Physical Item Linking，不能升级成 Variant Reference。

### 6.3 General VLM

PoC 困难样本结构化抽取基线：Qwen3.5-4B。只能产出候选 Evidence/Scope/Composition/Component/Instance 提示，无权直接写 Canonical、Current Fact、Scope Truth、Composition Truth、Physical Item Truth 或 CERTAIN_MATCH。

### 6.4 Attribute Validation Gate

状态：

```text
VALIDATED_VALID
VALIDATED_INVALID
UNVERIFIED
NOT_APPLICABLE
SOURCE_CONFLICT
```

分层：L0 deterministic → L1 applicability/cross-field → L2 text/profile → L3 cross-source/official → L4 multimodal → L5 LLM/VLM fallback。所有层允许 abstain。

Hard Attribute 只有 `VALIDATED_VALID` 且来源/Validator policy 已认证才可进入身份链路。

### 6.5 Official Variant Spec vs Observed Item State

```text
fact_scope = OFFICIAL_VARIANT_SPEC / OBSERVED_ITEM_STATE
component_origin = FACTORY_CONFIG / AUTHORIZED_SERVICE_REPLACEMENT / AFTERMARKET_OR_MODIFIED / UNKNOWN_ORIGIN
replaceability_class = IDENTITY_STABLE / SERVICE_REPLACEABLE / USER_REPLACEABLE / COSMETIC_OR_CONSUMABLE / UNKNOWN
```

规则：

- Canonical 只描述 Official Variant Spec。
- VALIDATED_VALID 只证明观察值正确，不证明 Factory Config。
- 官方售后替换件仍是 post-sale Item State，不重写 Canonical。
- SERVICE/USER replaceable 字段与 Canonical 不一致默认是 Item-State Divergence，不是 Hard Conflict。
- Strong Identifier 已锁定 Variant 时，可解释换件不得覆盖 Anchor。
- 无 Strong Anchor 且关键组件 Origin 不明/疑似更换时 UNKNOWN。
- 同一 Physical Item 在多个 relist 上的 Item-State 可形成时间线，但这些 Observation 不因此变成多个独立 Official-Spec 证据。

输出分离：`variant_identity_decision` 与 `item_configuration_assessment`。

## 7. EvidenceProfile、Scope、Router、Composition 与缺模态 Route Policy

每条 Source Offer 计算：

```text
identifier_quality / text_quality / image_quality
hard_attr_coverage / conflict_state / catalog_mode
composition_state / main_component_id
physical_item_link_state / physical_item_id(optional)
product_scope_state / scope_evidence_level
brand_route_state / category_route_state / routing_scope
image_set_state
item_state_assessment
```

执行顺序：

```text
Composition → Component Binding → Physical Item/Relist → Product Scope → Router → Retrieval
```

Router 是 in-scope 后的候选空间优化器，不是身份事实源。Exact Manufacturer Identifier 绕过非权威 Router，但不能绕过 Component、Scope、Composition、Fact Scope 和 Conflict。

Scope-aware Route：

- `IN_SCOPE_WATCH / IN_SCOPE_BAG`：普通 Linking。
- `IN_SCOPE_UNKNOWN_SUBTYPE`：ancestor/multi-route/broad retrieval。
- `OUT_OF_SCOPE_KNOWN`：停止腕表/箱包 Linking/Discovery。
- `OPEN_UNKNOWN / CONFLICTING_SCOPE`：`UNKNOWN_PRODUCT_SCOPE`。

Composition-aware Route：

- `SINGLE_PRODUCT`：普通 Linking。
- `SINGLE_PRIMARY_WITH_AUXILIARY`：只对 primary component Linking。
- Merchant Bundle/Multipack：写独立关系，不默认 SAME_VARIANT。
- Multi-product Lot/Accessory-only/Unknown：不做 SAME_VARIANT Auto-Match。

## 8. Candidate Retrieval、Fusion 与 Open-world Guard

召回：Exact Identifier、Brand+Model、Brand+Series+Hard Attr、BM25、Text ANN、Image ANN/hash、Historical Alias、Discovery Neighbor。

PoC 初始 K：Exact≤20、BM25 30、Text ANN 50、Image ANN 每图30/总≤60、Attribute 30；union≤150，Cheap Rerank≈30，Expensive Matcher 10–20。

Gate：

```text
Recall@100 >= 99.5%
Exact survival = 100%
scope_in_scope_recall / scope_false_in_scope_rate 单独监控
Router pre/post-filter recall 单独监控
```

### 8.1 Component/Scope/Image-aware Retrieval

- Query text 只由主 Identity Component 生成。
- Bundle/add-on/accessory 属性不进入主商品 hard filter。
- Image ANN 只使用通过 Composition、Scope、Image Gate 的图/region。
- Identity-critical Search Filter 只消费已验证、已仲裁、已发布 Current Fact。
- Exact 候选永不被 Soft Fusion 截断；零/少标签使用 RRF baseline。

### 8.2 NIL / Recovery

CandidateSet：

```text
KNOWN_CANDIDATE
AMBIGUOUS_KNOWN
POSSIBLE_NIL
RETRIEVAL_FAILURE
ROUTING_AMBIGUOUS
```

进入 NIL/Discovery 前完成：

```text
Scope Gate
+ Router bypass（必要时）
+ Composition Gate
+ Item-State Divergence Check
```

以下状态不得解释成新品：Out-of-scope、Open Unknown、Composition Unknown、Multi-product Lot、Accessory-only、Search/Publication Failure。

Physical Item duplicate/relist 也不得因为“多个 Offer 都没链接到 Canonical”而分别创建多个 PROPOSED；Discovery pool 先按 `physical_item_group_id / relist lineage / duplicate Evidence` 做保守去重。

## 9. Embedding、Visual Search 与 Image Set Safety

Text：Qwen3-Embedding-0.6B；Text Reranker：Qwen3-Reranker-0.6B。

Image：SigLIP2 baseline；DINOv3 challenger（Legal Gate）；Qwen3-VL Embedding/Reranker 只在困难路径验证收益。近邻 Variant 使用局部 patch/local descriptor shortlist rerank。

### 9.1 Image Set Identity / Utility Gate

图片角色：

```text
PRODUCT_PRIMARY / PRODUCT_DETAIL / MODEL_LIFESTYLE
PACKAGING_OR_DOCUMENT / COLLAGE / ACCESSORY_OR_AFTERMARKET
DECORATIVE / OTHER_PRODUCT_SUSPECT / UNKNOWN
```

规则：

- raw image set 不直接 max；只对 identity-eligible 图做 robust aggregation。
- 拼图 region 化；无法确认 panel 归属时整图不进 Identity ANN。
- `CROSS_VARIANT_REUSE` 库存图不做 SAME_VARIANT Positive/near-tie 决胜。
- 文档图可 OCR Identifier，但不做商品外观 ANN。
- Bundle 全景图仅在主组件 region 可稳定分离时进入主商品 Identity。
- 同一 listing 多图仍属于一个 `IMAGE_VISUAL` Evidence Family。
- 同一 Physical Item 跨 relist 的相同/近重复图片只增强 Instance Linking，不增加 Variant 独立来源数。
- 合格图片分别支持不同 Variant → `UNKNOWN_IMAGE_SET_CONFLICT` 或视觉贡献置零。

## 10. Pair Matcher、Conflict Engine 与 Decision Policy

```text

→ Pre-Conflict
→ Deterministic Features
→ Structured/Text Matcher
→ Multimodal Difficult Pair
→ Local Visual（near-tie）
→ Post-Conflict
→ Calibration
→ Evidence-Family Risk Policy
→ Candidate/NIL/Ambiguity/Scope/Composition Guard
→ Decision
```

`CERTAIN_MATCH` 至少满足：

```text
NO HARD_CONFLICT
AND product_scope_state ∈ {IN_SCOPE_WATCH, IN_SCOPE_BAG, IN_SCOPE_UNKNOWN_SUBTYPE}
AND CandidateSetState == KNOWN_CANDIDATE
AND Composition 允许 SAME_VARIANT
AND Canonical Hard Resolution 可服务
AND (
  Strong Identity Anchor
```

## 11. Entity Linking、Discovery、Instance Lineage 与 Canonical Health

### 11.1 Linking

```text
Source Snapshot
→ Composition + Component Binding
→ Physical Item / Relist Assessment
→ Product Scope Gate
→ Router / Validation / Image / Item-State Gate
→ Hybrid Retrieval
→ Pair / Conflict / Calibration
→ CandidateSetAssessment
→ SAME_VARIANT CERTAIN_MATCH
→ Recognition Commit Barrier
```

Bundle/Multipack 主商品识别可写独立 Composition Relation，但默认不写 SAME_VARIANT Recognition。

### 11.2 Physical Item Lineage

Physical Item layer 维护“同一件实物在时间和平台上的 Offer lineage”，用途：

```text
Evidence Independence
Item-State Timeline
Relisting/Duplicate Suppression
Benchmark Split Isolation
Risk-Audit Dependency Clustering
Incident/Sibling Scan
```

如果 Variant 已确定，则多个 Offer 可以共享 `physical_item_id + canonical_variant_id`；如果 Variant 未确定，Physical Item cluster 仍可存在，但不得通过自身 membership 推导 Canonical。

### 11.3 Discovery / Novelty

```text
POSSIBLE_NIL
→ Scope Recheck + Route Recovery
→ Composition/Item-State/Instance-Duplicate Recheck
→ Official/Web Evidence
→ Strict Blocking
→ Constraint-aware Clustering
→ PROPOSED
→ Novelty/Uniqueness + Required Hard Facts
→ ACTIVE or remain PROPOSED
```

Discovery 前置：Scope 必须 in-scope；Composition 必须允许；Observed Item State/Service/Aftermarket 不可当新 Variant；同一 Physical Item 的 relist 不能生成多个独立 PROPOSED 或满足多源激活门槛。

任何 `PROPOSED → ACTIVE` 必须通过当前 publication 的 Novelty/Uniqueness Gate。Variant-unique Manufacturer ID / official external Variant ID 使用唯一 identity claim 防并发双 ACTIVE。

### 11.4 ACTIVE Canonical Health / Split / Merge

周期性/事件驱动检查 Hard Conflict、cannot-link、Manufacturer ID partitions、Fact Conflict、review disagreement、temporal generation。治理级冲突立即 freeze。

GNN/GraphCR/SuperPart 等只能 Detect/Prioritize/Propose；Split/Merge 需 Governance + 原子 Publication。Merge 时重新 Validation/Arbitration。

Physical Item cluster 冲突默认修复 Instance Lineage，不自动升级 Canonical Split/Merge；只有独立 Variant-level Hard Evidence 证明 Canonical 错误时才触发 Canonical Repair。

## 12. Web Evidence Agent 与 Official Web Catalog

优先级：品牌官网 → 官方目录/经销资料 → 专业数据库 → 高质量二手平台 → 通用搜索。

官方站解析 ProductGroup/Product、DOM、Embedded State、Identifier、Variant URL，产出版本化 Assertions/Variant Graph。Web/Agent 无权直接修改 Canonical、Scope Truth、Current Fact、Physical Item Truth 或 CERTAIN_MATCH。

平台/Feed 的 bundle/multipack/component/category/relist 字段都是 Evidence；字段缺失不能证明 Single Product、In-Scope 或 Independent Instance。

通用搜索和二手平台重复页面先做 syndication/content/image/Physical-Instance dedupe；多个网页若追溯到同一件实物，只算一个 item-instance group，不能伪造“多源一致”。

### 13.1 Training Leakage Guard for Relisting

- Pair/Attribute/Image/Instance 数据切分前按 `physical_item_group_id` 隔离；同一实物的多次 relist 不得跨 train/dev/test。

## 14. Review、风险认证与 Reviewer Quality

三轨：

```text
TRAINING_REVIEW
CERTIFICATION_AUDIT
GOVERNANCE_REVIEW
```

正式风险认证以最终 Recognition Decision 为单位，概率抽样保存 inclusion probability/stratum，并报告 i.i.d. 与 dependency-cluster-aware 风险上界，release 取最保守值。

### 14.1 Reviewer Quality

Certification 默认双人独立盲审；允许 `SAME_VARIANT / DIFFERENT_VARIANT / INSUFFICIENT_EVIDENCE / SOURCE_DATA_ERROR`，分歧 adjudication。Reviewer 资格、指南、UI、Evidence Snapshot 全部版本化。

独立控制集包括：Pair、Attribute Validation、Image Set、Item-State、Source Composition、Product Scope、Physical Item/Relisting。

Physical Item Control Set 覆盖：

- 同平台显式 relist、新 Listing ID。
- 同一件实物跨平台搬运。
- 同 Variant 不同实物但库存图/模板文案相同。
- Serial 相同字符串但不同品牌/不同 GTIN namespace。
- 维修/换带后同一实物外观变化。
- 多个 Offer 图片不同但独特刻痕/证件/serial 一致。

### 14.2 Cluster-aware Production Risk Certification

dependency keys 至少包括：

```text
source_group / syndication_group
physical_item_group_id
canonical_variant_id
parser/extractor/model/calibrator/policy version
route_execution_signature
catalog_publication_id
ingestion_batch / decision_time_bucket
```

固定规则：

- 原始审核条数 ≠ 有效独立样本数。
- “0 错误、约 2995 条”只作为近似独立 Bernoulli 时的 i.i.d. sanity bound，不单独作为上线证明。
- 正式报告 `n_raw / n_distinct_dependency_clusters / design_effect / effective_sample_size / record upper bound / cluster-aware upper bound`。
- 多个 relist 若属于同一 physical item，在 cluster-aware audit 中视为相关决策；仍保留其真实流量权重，但不能虚增独立故障簇数。
- Release 使用预先声明 cluster definitions 中最保守上界；关键 slice 单独通过。
- False Merge 发生后沿 source/physical-item/canonical/model/policy/publication dependency 做 sibling scan；系统性错误对应 slice kill switch/UNKNOWN 后重新认证。

## 16. Incremental、CDC、Publication 与 Recognition Commit

Canonical/Attribute Resolution mutation 与 catalog outbox 同事务；幂等 Search 投影使用 external version，refresh/checkpoint 后推进 publication watermark。

Source 文本、图片、category/bundle/component/instance identifier/relist lineage 变化都会生成新 `source_version`；影响 Composition、Scope、Component Binding、Physical Item link、Item-State、Image eligibility 或 Hard Assertion 时，旧 Decision Snapshot 失效。

Recognition Commit：推理阶段不持长事务，CERTAIN_MATCH 进入短 ACID：

```text
idempotency intent
→ Source CAS
→ validate Source / Composition / Scope / Canonical / publication / fact versions
→ ensure single current link
→ immutable Recognition
→ current link
→ Source state
→ one Review/outbox
```

Physical Item link 更新与 Recognition 分离：Instance dedupe 可异步重算 Evidence Independence，但任何重算都必须版本化；若重算影响 Candidate/Fact/Certification，触发 reprocess/re-arbitration/re-certification，不原地改历史 Recognition。

## 17. Production Runtime Reliability

mandatory stage timeout/熔断/跳过形成新 route signature；未经单独认证只能 UNKNOWN。

每请求 end-to-end deadline；依赖唯一 retry owner；指数退避+jitter+retry budget；bounded queue+circuit breaker。

Load shedding：P4 backfill/bulk validation/instance-dedupe → P3 Discovery/Web/Scope/Composition enrichment → P2 near-tie expensive → P1/P0 Linking。

Instance dedupe 不得成为在线 CERTAIN_MATCH 的硬依赖：Instance Gate 不可用时可以降低“多源独立性/Discovery/Activation”能力，但不能放松 Variant Hard Constraint，也不能把未知实例关系当成独立多源支持。

13. Hard Attribute UNVERIFIED/INVALID/SOURCE_CONFLICT 参与身份链路=0。
14. Image Gate/shared-image/collage 违规=0。
15. OBSERVED_ITEM_STATE/Service/Aftermarket 被当 Factory Spec=0。
16. Composition 未完成却假定 SINGLE_PRODUCT 并 Auto-Match=0。
17. Merchant Bundle / Multipack / Lot / Accessory-only SAME_VARIANT 违规=0。
18. Bundle accessory/add-on Evidence 污染主商品身份链路=0。
19. Manufacturer-defined Set Identifier 被误解释为单主组件 Identifier=0。
20. Bundle/Lot/Composition UNKNOWN 进入新品 Discovery=0。
21. OUT_OF_SCOPE/OPEN_UNKNOWN/CONFLICTING_SCOPE 进入腕表/箱包 SAME_VARIANT 或新品 Discovery=0。
22. closed-set Top-1 被直接提升为 Scope Truth=0。
23. Scope/Composition/Component Binding/Instance policy 与 Gold provenance 完整率=100%；Source 变化后旧 Decision Snapshot 不得提交。
24. **Serial/Date Code/Certificate 等 INSTANCE_ID 被直接当 Variant Reference/Style Code 的违规=0。**
25. **同一 `physical_item_id` 的多次 relist/跨平台 Offer 在 Canonical activation、weak cross-source validation、Attribute Arbitration 中被计为多个独立 Physical-Instance 支持的违规=0。**
26. **平台显式 relist old→new 已知时，新 Listing ID 被当作独立实物来源的违规=0。**
27. **Physical Item cluster membership 被用作 SAME_VARIANT Identity Anchor、Hard Conflict、NON_MATCH 或直接 Canonical mutation 的违规=0。**
28. **Pair/Attribute/Image/Instance 正式 benchmark 中同一 physical item 跨 split 泄漏=0。**
29. **Certification risk report 必须包含 physical_item_group dependency；高频 relist 不得虚增 distinct-cluster/effective sample size。**
30. **Instance lineage 拆分/纠错后，受影响 Evidence Independence、Training membership、Fact Arbitration、Risk Audit 必须完成重算或对应 slice fail closed。**

指标退化时优先降低 Coverage，不通过“不同 Listing ID 就是不同实物”“多个 relist 就是多源一致”或实例聚类捷径来提高自动识别率。

## 23. 最终生产原则

```text
Raw Source Offer
          ↓
Source Composition / Component Binding
          ↓
Physical Item / Relisting Independence Gate
          ↓
Product Scope Open-set Gate
          ↓
Attribute Extraction + Validation
          ↓
Official-Spec vs Observed-Item-State / Origin Gate
          ↓
Evidence Assertions + Source/Instance Independence
          ↓
Canonical Variant-Spec Fact Arbitration
          ↓
In-scope Router / Filter Safety
          ↓
Image Set Identity / Utility Gate
          ↓
Component-aware Hybrid Retrieval + Exact Preserve
          ↓
Structured + Text + Eligible Image Evidence
          ↓
Hard Conflict + Calibration
          ↓
Candidate-set / NIL / Ambiguity / Scope / Composition Guard
          ↓
Constraint-aware Graph Resolution
          ↓
SAME_VARIANT CERTAIN_MATCH
          ↓
Recognition Commit Barrier
          ↓
Current Link + Immutable Recognition + Pending Review
          ↓
Canonical Novelty / Health / Repair
          ↓
Independent Risk Audit
          ↓
Controlled Training + Immutable Lineage
```

固定原则：

1. **Identity first，Similarity second。**
2. **Source Offer ≠ 必然一个商品；Offer ID ≠ Physical Item ID；Physical Item ID ≠ Variant ID。**
3. **同一件实物的多次 relist/跨平台搬运不能伪装成多个独立 Variant 证据。**
4. **Serial/Date Code/Certificate 默认是实例/生产证据，不是官方 Variant Reference。**
5. **Physical Item Instance 层只做去重、状态时间线、训练/风险聚类；不能直接产生 SAME_VARIANT、Hard Conflict 或 Canonical mutation。**
6. **第一阶段 Scope 只有腕表与箱包；Scope 未证明前不强制吸收。**
7. **Closed-set Top-1 不是 Scope Truth；未知类必须允许 OUT_OF_SCOPE/OPEN_UNKNOWN/CONFLICTING。**
8. **Merchant Bundle / Multipack / Lot 的组合关系不能伪装 SAME_VARIANT。**
9. **附件、配件、其他商品 Evidence 与主商品 Identity Evidence 隔离。**
10. **Extraction confidence ≠ fact correctness；Validated Observation ≠ Official Variant Spec。**
11. **Canonical 只保存 Official Variant Spec；二手当前组件进入 Item-State。**
12. **官方维修替换件不自动成为 Factory Config。**
13. **Hard Conflict 只建立在 Validation、正确 Fact Scope、正确 Component Binding 的证据上。**
14. **Synthetic/Pseudo evidence 不能形成 Hard Fact / Identity Anchor / Certification Gold。**
15. **多张图片不是多份独立身份票；同一实物的多次 Listing 也不是多份独立来源票。**
16. **必须显式允许 NIL；near-tie 必须 Abstain。**
17. **Exact Identifier 绕过非权威 Router，但不能绕过 Scope、Component、Composition 和 Identifier Semantics。**
18. **Router 只负责 in-scope 后的候选空间优化。**
19. **训练 Review、Scope/Composition/Image/Attribute/Item-State/Physical-Instance Gold、Risk Certification 是不同资产。**
20. **Product Group ID 是关系标识，不是 Variant Identity；Merchant SKU、Manufacturer ID、Instance ID 分命名空间。**
21. **Canonical Current Fact 是已验证 Official-Spec Assertions 的版本化 Arbitration，不是最近值/多数票/同一实物重复票。**
22. **Search/Hard Conflict 只消费已验证、已仲裁、已发布 Current Fact。**
23. **DB→Search 使用 Transactional Outbox + Idempotent Projection + Monotonic Version + Publication Barrier。**
24. **ACTIVE Canonical 持续检查 over-merge、under-merge、Fact Conflict。**
25. **Entity Discovery 是新品证明问题，不是“多个 relist 都没匹配上”的同义词。**
26. **Cluster/Instance Repair Model 只能 Detect/Prioritize/Propose，不能直接修改 Canonical。**
27. **所有模型、Scope/Router/Composition/Image/Instance/Attribute/Item-State Policy 和数据集都不可变、可追溯。**
28. **依赖故障或 mandatory gate 缺失时 fail closed 为 UNKNOWN。**
29. **模型 CERTAIN_MATCH 只是待提交 Decision；Recognition Commit 后业务关系才生效。**
30. **任何复杂度只有在提高 Coverage@99.9% Precision、降低 False Merge/False Novel/False In-Scope/Composition Leakage/Instance Evidence Inflation、提高事务可靠性或降低总成本时才有价值。**
