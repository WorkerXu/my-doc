# 奢侈品识别方案

## 1. 目标与边界

系统目标不是“找最像的商品”，而是把雷小安、奢当家、腕表之家、小迈步、爱回收等来源的异构记录归一到**同一个官方商品变体（Official Variant）**，并产生可审核、可回放、可治理的 Recognition。

第一阶段只覆盖：

```text
IN_SCOPE_WATCH
IN_SCOPE_BAG
```

历史数据约 100 万–1000 万条。腕表已有部分品牌/系列/型号主档；箱包主档不完整，因此同时支持 Entity Linking 与 Entity Discovery。

核心原则：

> **Precision >> Recall。宁可 UNKNOWN / OUT_OF_SCOPE，也不能把不同官方 Variant 错合并。**

系统不做真假鉴定。成色、价格、库存、卖家、单件序列号、保卡状态属于 Offer / Physical Item；维修换件、个性化、联名营销、附属物、商家 Bundle、Multipack、Lot、重复上架，以及业务范围外商品都不能被误当成新的官方 Variant。

每个 `CERTAIN_MATCH` 必须原子形成：

```text
Source Product 当前状态
+ Source → Canonical 当前识别关系
+ Immutable Recognition Record
+ Pending Business Review
```

四个副作用必须原子、幂等、可重放。

## 2. 核心实体、品牌角色与 Identifier Identity Scope

### 2.1 Canonical Identity

```text
Brand / Brand Role
  └── Product Family / Series
       └── Product Model
            └── Canonical Variant
```

关系至少包括：

```text
SAME_VARIANT
VARIANT_OF
SAME_MODEL
SAME_SERIES
VISUALLY_SIMILAR
UNKNOWN
```

只有 `SAME_VARIANT` 可进入普通 Canonical 聚类并生成默认自动 Recognition。

Canonical 状态：`ACTIVE / PROPOSED / SPLIT_PENDING / MERGE_PENDING / RETIRED / MERGED / SPLIT / TAINTED`。

### 2.2 Brand Role / Collaboration Semantics

标题中出现多个品牌不能压成一个 `brand_id`。维护：

```text
PRIMARY_PRODUCT_BRAND
CO_PRIMARY_BRAND
SUB_BRAND
COLLABORATION_PARTNER
ARTIST_OR_DESIGNER
LICENSED_IP
BRAND_OWNER_OR_MANUFACTURER
UNKNOWN_ROLE
```

并维护 `collaboration_program_id` 与：

```text
PRODUCT_VARIANT_DEFINING
COLLECTION_PROGRAM
CAMPAIGN_OR_EDITORIAL
ENDORSEMENT_OR_STYLING
UNKNOWN
```

Hard Brand Constraint 比较治理后的 Primary/Co-primary 身份；漏写 collaborator 是 missing，不是 Hard Conflict；Campaign/Editorial 不定义 Variant；`A by B` 与 `B by A` 可有方向，不能无序化；Identifier namespace 不因 collaborator 名称改变。

### 2.3 Identifier Namespace 与 Identity Scope

统一采集：

```text
reference_raw / reference_normalized
style_code / mpn / gtin / ean / upc
merchant_sku / product_group_id / item_group_id
serial_number / date_code / certificate_id / instance_identifier
made_to_order_gtin / made_to_order_variation
market
identifier_namespace / identifier_owner / identifier_type
identifier_source / source_field_path
component_id / identifier_binding_scope
brand_rule_pack_version
```

每个 Identifier 必须显式赋予身份粒度：

```text
VARIANT_UNIQUE_VERIFIED
VARIANT_CANDIDATE
MODEL_OR_CASE
FAMILY_OR_GROUP
INSTANCE_ONLY
MERCHANT_ONLY
UNKNOWN_SCOPE
```

**字段名本身不能决定身份粒度。** `reference`、`style_code`、`mpn` 只有被当前 Brand Rule Pack 证明为 `VARIANT_UNIQUE_VERIFIED` 时，才能作为 Strong Variant Identity Anchor。

固定规则：

1. `VARIANT_UNIQUE_VERIFIED` exact + required Hard Attributes 无冲突，可进入 Strong Anchor。
2. `MODEL_OR_CASE` exact 只进入高优先召回/Blocking；仍必须比较 Variant-defining Hard Attributes。
3. `VARIANT_CANDIDATE` 在 Brand Pack 完成 collision audit 前不能单独 Auto-Match。
4. Merchant SKU 默认 `MERCHANT_ONLY`；Product Group ID 默认 `FAMILY_OR_GROUP`。
5. Serial/Certificate/Date Code 默认 `INSTANCE_ONLY`。
6. GTIN 默认 Strong Positive + Exact Retrieval Key；是否 `VARIANT_UNIQUE_VERIFIED` 仍按品牌/市场/Trade Item 语义治理。
7. 不根据编号位数、前后缀或社区经验推断官方含义；没有官方或内部治理证据时保持 `UNKNOWN_SCOPE`。
8. Vintage/地区站点/历史编号规则单独 versioned，不把当前规则倒推历史。

### 2.4 Brand Rule Pack + Identifier Collision Audit

`Brand Rule Pack` 是生产必须项，而不是离线说明文档。最小结构：

```text
brand_id
category
rule_pack_version
valid_from / valid_to
market_scope
official_catalog_surfaces
identifier_rules[]
variant_defining_attributes[]
normalization_rules[]
known_aliases[]
reference_collision_audit_id
```

每条 `identifier_rule`：

```text
identifier_type
source_surface / field_path
normalization
identity_scope
required_companion_attributes
exact_retrieval_allowed
strong_anchor_allowed
hard_conflict_allowed
collision_audit_status
source_evidence_ids
```

#### Collision Audit

对官方 Catalog Snapshot：

```text
Official Products
→ Normalize Identifier
→ Group by brand + market + identifier
→ Build Variant Hard Signature
→ Detect same-identifier / different-signature collisions
→ Assign Identifier Scope
```

Variant Hard Signature 至少包含本项目定义的所有 Variant-defining 属性；腕表通常为尺寸/材质/盘面/表圈/表链或表带/必要机芯代际，箱包通常为官方尺寸/材质/颜色/五金/图案/edition。

规则：

- 同 Identifier 映射到多个不同 Hard Signature → **绝不能**标记 `VARIANT_UNIQUE_VERIFIED`。
- 官方字段明确声明只标识 model/case/group → 直接按其语义，不需模型猜测。
- 只有官方语义明确，或覆盖充分的官方 Catalog collision audit + 历史回归均通过，才允许提升为 `VARIANT_UNIQUE_VERIFIED`。
- Rule Pack 变化必须 shadow replay；受影响 Recognition、Alias、Exact Index、Hard Negative 与训练数据可沿 lineage 重算。

#### 已验证初始品牌规则

**Rolex：公开 Reference 不能默认 Variant-unique。**

Rolex 官网存在多个 Datejust 41 官方配置页面，公开均显示 `Reference 126334`，但表盘与表链不同；官方 URL/配置键分别形如 `m126334-0033`、`m126334-0015` 等。因此：

```text
Rolex public Reference 126334 / 126234 类字段
→ MODEL_OR_CASE
→ Exact Retrieval 到 model/case bucket
→ dial + bracelet + other Variant Hard Attr 再决策
```

官方页面的 `m126334-xxxx` 保存为 `official_catalog_configuration_key`，可作为高价值官方 Catalog Key，但在没有品牌明确声明其长期身份语义前，不自动把 URL key 当公开 Variant Identifier。

**CHANEL：Style stem 与完整 Ref 必须分层。**

官方 CHANEL 25 Medium 同一 `AS5311` style stem 可出现：

```text
AS5311-B20304-U8389  Grained Calfskin / Dark Khaki
AS5311-B24037-U9373  Denim / Dark Blue
AS5311-B20304-94305  Grained Calfskin / Black
```

2.55 的 `A37586` 也在不同材质/颜色完整 Ref 中复用。因此：

```text
AS5311 / A37586 等 style stem → MODEL_OR_CASE / style-level retrieval
完整官方 Ref → VARIANT_CANDIDATE
```

完整 Ref 只有在官方 Catalog collision audit 证明同 scope 无 Variant Hard Signature 冲突后，才提升 `VARIANT_UNIQUE_VERIFIED`。

**Cartier：官方 REF 是高价值候选，但先做 collision audit。**

Cartier 官方 Santos 页面使用如 `WSSA0018 / WSSA0037 / WSSA0096` 等 REF，并分别描述不同具体配置。首版将官方 Cartier REF 标记 `VARIANT_CANDIDATE`；完成官方 Catalog 全量同 Ref collision scan 后再决定哪些系列可提升为 `VARIANT_UNIQUE_VERIFIED`，不跨品牌照搬 Rolex 或 CHANEL 规则。

PoC Brand Pack 优先级：

```text
P0 Rolex + CHANEL
P1 Cartier + Omega
P2 Louis Vuitton + Hermès
其余品牌按数据量/错误风险扩展
```

## 3. Source Offer、Composition、Physical Item 与 Customization

### 3.1 Source Offer / Component / Physical Item

```text
Source Offer / Listing
   └── Source Component(s)
        └── 0..1 Primary Identity Target
              └── 0..1 Physical Item Instance
                    └── Canonical Variant
```

Physical Item 只用于实例追踪、Evidence 去重、Item-State/Customization timeline、训练/审计聚类，不得直接产生 Variant Identity。

### 3.2 Source Composition

```text
SINGLE_PRODUCT
SINGLE_PRIMARY_WITH_AUXILIARY
MERCHANT_DEFINED_BUNDLE
MANUFACTURER_DEFINED_SET
MERCHANT_MULTIPACK
MULTI_PRODUCT_LOT
ACCESSORY_ONLY
CONFLICTING_COMPOSITION
UNKNOWN_COMPOSITION
```

Merchant Bundle 可识别主组件，但整个 Listing 默认不产生 SAME_VARIANT；Manufacturer Set 只有官方 Set identity/Hard Facts 齐全时才成为独立 Canonical；Multipack 数量属于 Offer；Lot/Accessory-only/Unknown 不进入普通 SAME_VARIANT Linking/Discovery。

### 3.3 Physical Item / Relisting Independence

同一实物可能反复上架或跨平台搬运。不同 Offer ID/URL 不自动增加独立证据数。同一 `physical_item_id` 的多个 Offer 在 Activation、Weak Validation、Fact Arbitration、Risk Audit 中最多算一个 Physical-Instance Evidence Group。实例误合并必须 fail-safe：最多降低 Coverage，不能制造 Variant 决策。

### 3.4 Official Customization / MTO

```text
NONE_STANDARD
CATALOG_VARIANT_OPTION
MANUFACTURER_MTO_PROGRAM
POST_PURCHASE_PERSONALIZATION
AFTERMARKET_PERSONALIZATION
UNKNOWN_CUSTOMIZATION
```

Catalog 有限选项且官方定义 Variant 边界时按 Variant；MTO Program 与客户最终组合分层；initials、姓名、日期、自由刻字、patch/stripe 默认 Instance-specific；最终配置只有获得独立 manufacturer-grade Variant/Trade Item Identity 时才另建 Canonical。

## 4. Product Scope / Open-set Gate

第一阶段只做腕表与箱包：

```text
IN_SCOPE_WATCH
IN_SCOPE_BAG
IN_SCOPE_UNKNOWN_SUBTYPE
OUT_OF_SCOPE_KNOWN
OPEN_UNKNOWN
CONFLICTING_SCOPE
```

Closed-set Top-1 不能当 Scope Truth。父类可靠但 leaf 未知 → `IN_SCOPE_UNKNOWN_SUBTYPE + ANCESTOR_ROUTE`。Out-of-scope/Open Unknown/Conflicting Scope 不进入腕表/箱包 NIL/Discovery。

## 5. Hard Constraint、Attribute Validation 与 Fact Arbitration

每个属性断言保存 extraction/validation、fact scope、market/time、component、physical item、customization、brand rule pack provenance。

### 5.1 腕表默认 Hard Schema

| 字段 | 默认策略 |
|---|---|
| primary/co-primary brand | Hard |
| official identifier | **由 Brand Rule Pack 决定 scope** |
| series/family | Blocking + Strong；品牌规则可 Hard |
| model/subseries | Strong |
| case diameter | Hard |
| case material | Hard |
| dial color/type | 定义 Variant 时 Hard；Official Spec |
| bezel | 定义 Variant 时 Hard |
| bracelet/strap | 条件 Hard；Item-State 不直接当 Factory Spec |
| caliber/movement | 代际区分时 Hard，否则 Strong |
| functions | Variant 区分时 Hard |
| edition/generation | Hard |
| serial/piece number | Physical Item |

### 5.2 箱包默认 Hard Schema

| 字段 | 默认策略 |
|---|---|
| primary/co-primary brand | Hard |
| official style/reference | **由 Brand Rule Pack 决定 scope** |
| family/series/model/style | Blocking + Strong |
| official size | Hard |
| material / official color / hardware | Hard；Official Spec |
| pattern/print | 官方 Variant Spec 时 Hard |
| edition/collaboration | Product-level 时 Hard/Strong |
| season/year/generation | 官方区分时 Hard |
| serial/date code | Physical Item/生产证据 |

### 5.3 Attribute Validation Gate

```text
VALIDATED_VALID
VALIDATED_INVALID
UNVERIFIED
NOT_APPLICABLE
SOURCE_CONFLICT
```

L0 deterministic → L1 applicability/cross-field → L2 text/profile → L3 cross-source/official → L4 multimodal → L5 LLM/VLM fallback。所有层允许 abstain。Hard Attribute 只有 `VALIDATED_VALID` 且 validator/source/Brand Pack policy 已认证才可进入身份链路。

### 5.4 Official Variant Spec vs Observed Item State

```text
OFFICIAL_VARIANT_SPEC
OBSERVED_ITEM_STATE
```

并保存 `FACTORY_CONFIG / AUTHORIZED_SERVICE_REPLACEMENT / AFTERMARKET_OR_MODIFIED / UNKNOWN_ORIGIN`。Canonical 只描述 Official Variant Spec；维修/可替换组件差异默认 Item-State Divergence，不直接覆盖 Variant Anchor。

### 5.5 Canonical Fact Arbitration

不使用 latest-write-wins 或简单多数票。按 market/time/generation/source independence/Brand Pack 仲裁为：

```text
RESOLVED / MULTI_VALID / CONFLICTED / UNKNOWN / STALE
```

Search/Matching/Conflict 只消费已发布的 `RESOLVED/MULTI_VALID` Current Fact。Brand-role、Collaboration、Identifier Scope 与 Attribute Resolution 同样版本化。


## 8. Candidate Retrieval、Fusion 与 Open-world Guard

召回通道：

```text
Verified Variant-Unique Identifier Exact
Model/Case/Style Identifier Bucket
Brand/Co-brand + Model
Collaboration Program
Brand + Series + Hard Attr
BM25
Text ANN
Image ANN / hash
Historical Alias
Discovery Neighbor
```

PoC 初始 K：Verified exact≤20、BM25 30、Text ANN 50、Image ANN 每图30/总≤60、Attribute/Brand-rule 30；union≤150，Cheap Rerank≈30，Expensive Matcher 10–20。

Gate：`Recall@100 >=99.5%`，Verified Exact survival=100%，Brand Pack/Scope/Router pre-post recall 分开监控。

### 8.1 Fusion

Raw score 不直接相加；Verified Exact 候选永不被 Soft Fusion 截断；零/少标签用 RRF baseline；各通道保留 minimum quota；有 judgment 后比较 normalized/learned fusion。

### 8.2 NIL / Recovery

CandidateSet：`KNOWN_CANDIDATE / AMBIGUOUS_KNOWN / POSSIBLE_NIL / RETRIEVAL_FAILURE / ROUTING_AMBIGUOUS`。

进入 NIL/Discovery 前完成 Scope + Brand Rule Pack + Router bypass + Composition + Brand-role + Item-State + Customization/MTO Recheck。一个 `MODEL_OR_CASE` Identifier 精确命中但 Variant Hard Attr 不足时，输出 UNKNOWN/补证据，**不得**把“同 Reference 下多个配置”误解释成唯一候选。

## 9. Embedding、Visual Search 与 Image Set Safety

Text baseline：Qwen3-Embedding-0.6B；Text Reranker：Qwen3-Reranker-0.6B。

Image baseline：SigLIP2；DINOv3 challenger（Legal Gate）；Qwen3-VL Embedding/Reranker 只在困难路径验证收益。近邻 Variant 用局部 patch/local descriptor shortlist rerank。

Raw image set 不直接 max；库存图跨 Variant 复用不做 Positive；文档图只做 OCR；同一实物 relist 图片不增加独立 Variant Evidence；个性化/collaboration motif 可辅助识别程序或实例，但不能单独证明 Variant。

## 10. Pair Matcher、Conflict Engine 与 Decision Policy

```text
Candidate Pair
→ Pre-Conflict
→ Deterministic Features
→ Structured/Text Matcher
→ Multimodal Difficult Pair
→ Local Visual（near-tie）
→ Post-Conflict
→ Calibration
→ Evidence-Family Risk Policy
→ Identifier Scope / Candidate / NIL / Ambiguity / Scope / Brand-role / Composition / Customization Guard
→ Decision
```

`CERTAIN_MATCH` 至少满足：

```text
NO HARD_CONFLICT
AND Scope in-scope
AND CandidateSetState == KNOWN_CANDIDATE
AND Brand/Collaboration/Composition/Customization Boundary 无未解决冲突
AND Canonical Hard Resolution 可服务

  Verified Variant-Unique Identity Anchor

```

## 11. Linking、Discovery 与 Canonical Health

### 11.1 Linking

```text
Source Snapshot
→ Composition / Component / Physical Item
→ Scope / Brand Role / Brand Rule Pack
→ Validation / Item-State / Customization / Router / Image Gate
→ Hybrid Retrieval
→ Pair / Conflict / Calibration
→ CandidateSetAssessment
→ SAME_VARIANT CERTAIN_MATCH
→ Recognition Commit Barrier
```

### 11.2 Discovery / Novelty

```text
POSSIBLE_NIL
→ Scope/BrandPack/Route Recovery
→ Composition/Item-State/Customization/Instance Duplicate Recheck
→ Official/Web Evidence
→ Strict Blocking
→ Constraint-aware Clustering
→ PROPOSED
→ Novelty + Required Hard Facts + Identifier Scope Audit
→ ACTIVE or remain PROPOSED
```

新 Canonical 激活前，任何准备作为 Variant Anchor 的新 Identifier 都必须有 Brand Rule Pack scope；`UNKNOWN_SCOPE` Identifier 不能因为“从未见过”就创建 Variant。

### 11.3 Canonical Health / Split / Merge

周期性检查 Hard Conflict、Cannot-Link、Manufacturer ID partition、Identifier Scope Collision、Brand-role/Collaboration Boundary、Fact Conflict、temporal generation、Customization Boundary。治理级冲突立即 freeze。

GNN/GraphCR/SuperPart 只能 Detect/Prioritize/Propose；Split/Merge 需 Governance + 原子 Publication。Brand Pack 发现新 same-Identifier multi-Variant collision 时，相关 Anchor 立即降级并触发 affected-recognition scan。

## 12. Web Evidence Agent 与 Official Catalog Ingestion

优先级：品牌官网 → 官方目录/授权资料 → 专业数据库 → 高质量二手平台 → 通用搜索。

官方站解析 ProductGroup/Product、Identifier、Variant URL/configuration key、Brand/Sub-brand、Collaboration、MTO 页面，产出版本化 Evidence。

Web/Agent 无权直接修改 Canonical 或 Identifier Scope Truth。Official Catalog crawler 的重要职责之一就是持续执行 Brand Pack Collision Audit，而不是只做新品搜索。

## 13. 冷启动、Pseudo-label 与训练数据飞轮

0 labels：Verified Identifier、Brand Rule Pack、Hard Constraint、Ontology、预训练 Text/Image、确定性 Positive/Hard Negative、Attribute/Composition/Scope/Instance/Customization rules。

Pseudo-label 永远不能进入 Certification Gold、Canonical Fact、Brand Rule Truth 或 Identifier Scope Truth。

训练资产分开：Pair Matching、Identifier Scope/Brand Rule、Brand Role、Attribute Validation、Image Role、Item-State、Customization、Composition、Scope、Physical Item labels。

约10K reviewed pairs：Logistic/LightGBM + Calibration；更多数据使用 compact Cross Encoder/domain contrastive；100K+ 再评估 multimodal student/active learning/learned fusion。

## 14. Review、风险认证与 Review Orchestration

四轨：

```text
BUSINESS_CONFIRMATION_REVIEW
TRAINING_REVIEW
CERTIFICATION_AUDIT
GOVERNANCE_REVIEW
```

每个 CERTAIN_MATCH 都创建 Business Review；Training 可 Active Learning；Certification 从冻结版本最终 Decision 流按预定义概率抽样；Governance 处理 PROPOSED/Novelty/Merge/Split/Brand Pack/Identifier Scope/Fact Conflict。

正式 Certification 默认双人独立盲审，并同时报告 i.i.d. 与 dependency-cluster-aware 风险上界，release 取最保守值。Business/Training priority rejection rate 不能当生产 Precision。

按 model/route/source/Canonical/Brand Pack 维护 `max_unreviewed_count / max_unreviewed_age / max_rejection_burst / min_recent_review_coverage`；超限 throttle/kill-switch。Certification/Governance 保留最低 reviewer capacity。

## 16. Incremental、CDC、Publication 与 Recognition Commit

Canonical/BrandPack/IdentifierScope/Attribute Resolution mutation 与 `catalog_outbox_event` 同事务；幂等 Search projection 使用 external version，refresh/checkpoint 后推进 publication watermark。

Auto-Match 请求 pin `ACTIVE publication_id`。Brand Pack/Identifier Scope 在推理后变化，旧 Decision Snapshot 必须 stale/reprocess。

`CERTAIN_MATCH` 短 ACID：

```text
idempotency intent
→ Source CAS
→ validate Source / Brand Pack / Identifier Scope / Composition / Scope / Brand Role / Customization / Canonical / publication / fact versions
→ ensure single current link
→ immutable Recognition
→ current link
→ Source state
→ exactly one BUSINESS_CONFIRMATION_REVIEW task/outbox
```

同 key+同 intent 返回第一次结果；同 key+不同语义拒绝。

## 17. Production Runtime Reliability

Mandatory stage timeout/熔断/跳过形成新 route signature；未经单独认证只能 UNKNOWN。

每请求 end-to-end deadline；每依赖唯一 retry owner；指数退避+jitter+retry budget；bounded queue+circuit breaker。

Load shedding：P5 training/backfill → P4 low-priority review/enrichment → P3 Discovery/Web/BrandPack/Scope/Composition → P2 near-tie expensive → P1/P0 Linking。

Brand Pack/Identifier Scope 若为当前 route 的 identity-critical mandatory stage，不能因过载默认“Reference exact = Variant exact”。

## 18. 容量、成本与性能

10M 商品、平均3图、10M text + 30M image vectors、512d：FP16 导出约40.96GB；OpenSearch FP32 完整向量约81.92GB，不含 Lucene/HNSW、metadata、副本、shadow index。

PoC（1–2M）：1×L4 24GB、1×8 vCPU/64GB OpenSearch、0.5TB SSD。

10M 压测起点：3×8 vCPU/64GB OpenSearch、3×1TB usable storage、2×L4 24GB online GPU；历史 backfill 临时4–8×L4。

新增统计：Brand Pack collision scan pages/sec、same-identifier collision rate、unknown-scope identifier rate、model/case bucket candidate amplification、official catalog freshness，以及 Review/Governance 人工成本。

成本与 `Coverage @ 99.9% Precision`、`Cost per Confirmed Recognition`、`Review Hours per 1K Recognitions` 联合优化。

## 21. 正式开启自动识别 Gate

全部满足才扩大 Auto-Match：

1. `Precision@Auto-Match >=99.9%`，`Recall@100 >=99.5%`，Verified Exact survival=100%。
2. Certification Audit 满足 sampling provenance 与 cluster-aware risk upper bound。
3. Hard Conflict、Seen/Unseen/Time-shift/Vintage/缺图/缺型号/低质图达标。
4. Synthetic/Pseudo evidence 不形成 Hard Fact/Identifier Scope Truth/Certification Gold。
5. AMBIGUOUS/NIL/IDENTIFIER_SCOPE/PRODUCT_SCOPE/BRAND_ROLE/COLLABORATION/SOURCE_COMPOSITION/CUSTOMIZATION/RETRIEVAL_FAILURE/PUBLICATION/CATALOG_REPAIR/FACT_CONFLICT 不得绕过 Guard。
6. Product Group ID、merchant SKU、Instance ID 语义违规=0。
7. ACTIVE 模型/BrandPack/Scope/Router/Composition/Image/Instance/Customization/Attribute/Item-State/Review policy lineage=100%。
8. PROPOSED→ACTIVE 必须 novelty=UNIQUE，required Hard Facts 与 Identifier Scope 可服务。
9. Recognition Commit duplicate/partial/stale/multiple-current-link=0。
10. Identity/Search/Hard Conflict 只消费已发布 Canonical Resolution 与当前 Brand Pack。
11. Hard Attribute UNVERIFIED/INVALID/SOURCE_CONFLICT 参与身份链路=0。
12. Bundle/Multipack/Lot/Accessory-only SAME_VARIANT=0；Out-of-scope 进入 SAME_VARIANT/Discovery=0。
13. 同一 physical item relist 被计为多个独立 Variant 证据=0。
14. POST_PURCHASE/AFTERMARKET/INSTANCE_SPECIFIC personalization 创建独立 Canonical=0。
15. Collaborator/Artist 被错误提升 Primary Brand=0；Product-level collaboration 与普通 base variant 错合并=0。
16. **任何 `MODEL_OR_CASE / VARIANT_CANDIDATE / UNKNOWN_SCOPE` Identifier exact 被当作单独 Strong Variant Anchor 的违规=0。**
17. **Rolex 公开 Reference-only 路径产生 SAME_VARIANT CERTAIN_MATCH 的违规=0，除非 Brand Pack 后续有新官方证据明确提升 scope。**
18. **同一 official Identifier 在同 market/time scope 对应多个不同 Variant Hard Signature 时，自动合并违规=0。**
19. **Brand Rule Pack 没有 official/governed evidence 或 collision-audit provenance 仍允许 Auto-Match 的违规=0。**
20. **Brand Pack rule 被新 collision 降级后，受影响 Recognition 未在 SLA 内 freeze/replay/re-certify 的违规=0。**
21. 每个 committed CERTAIN_MATCH 对应 Business Review task 完整率=100%；review exposure breach 后未 throttle/kill-switch=0。

指标退化时优先降低 Coverage，不通过“Reference 看起来很完整”“编号格式很像官方 SKU”来绕过 Brand Rule Pack。

## 23. 最终生产原则

```text
Raw Source Offer
→ Composition / Component / Physical Item
→ Product Scope / Brand Role
→ Brand Rule Pack / Identifier Scope
→ Extraction + Validation
→ Official Spec vs Item State / Customization
→ Evidence Independence + Canonical Arbitration
→ Router / Image Safety
→ Identifier-aware Hybrid Retrieval
→ Pair Matcher + Hard Conflict + Calibration
→ Candidate/NIL/Ambiguity/Identifier-Scope Guard
→ SAME_VARIANT CERTAIN_MATCH
→ Recognition Commit Barrier
→ Business Review / Exposure Safety
→ Canonical Novelty / Health / Repair
→ Independent Certification
→ Controlled Training + Immutable Lineage
```

固定原则：

1. **Identity first，Similarity second。**
2. **Identifier 的身份粒度由 Brand Rule Pack 决定，不由字段名或字符串格式决定。**
3. **只有 `VARIANT_UNIQUE_VERIFIED` Identifier 才能单独成为 Variant Strong Anchor。**
4. **同一 Identifier 映射多个不同 Hard Signature 时必须降级 scope，不能自动合并。**
5. **Rolex 类 public model/case Reference 只做 bucket retrieval；CHANEL 类 style stem 与 full Ref 分层治理。**
6. **不使用未经官方证据支持的编号位数/前缀/后缀语义。**
7. **Primary Brand、Co-brand、Collaborator、Artist、Manufacturer 分角色。**
8. **Source Offer ≠ 一个商品；Offer ID ≠ Physical Item ID；Physical Item ID ≠ Variant ID。**
9. **Catalog Variant Option、MTO Program、客户最终配置、Post-purchase Personalization 分层。**
10. **第一阶段 Scope 只有腕表/箱包；Closed-set Top-1 不是 Scope Truth。**
11. **Bundle/Multipack/Lot 不伪装 SAME_VARIANT；配件 Evidence 与主商品隔离。**
12. **Extraction confidence ≠ fact correctness；Validated Observation ≠ Official Variant Spec。**
13. **Hard Conflict 只建立在 Validation、Brand Pack、Fact Scope、Component、Brand Role、Customization Scope 合格的证据上。**
14. **Synthetic/Pseudo evidence 不能形成 Hard Fact / Identifier Scope Truth / Certification Gold。**
15. **多图、多 URL、同一实物多 Listing 都不是多份独立身份票。**
16. **必须显式允许 NIL、near-tie 与 identifier-scope ambiguity 并 Abstain。**
17. **Exact Identifier 绕过非权威 Router，但不能绕过 Brand Rule Pack 与 Identifier Scope。**
18. **每个 CERTAIN_MATCH 都保留 Pending Business Review；Review backlog 超安全暴露阈值时 throttle/kill-switch。**
19. **Canonical Current Fact、Brand Role、Identifier Scope 都是版本化、可回放、可发布的治理结果。**
20. **DB→Search 使用 Transactional Outbox + Idempotent Projection + Monotonic Version + Publication Barrier。**
21. **ACTIVE Canonical 持续检查 over-merge、under-merge、Fact Conflict 与 Identifier Scope Collision。**
22. **Entity Discovery 是新品证明问题，不是“Reference 没见过”的同义词。**
23. **所有模型、Brand Pack、Scope/Router/Composition/Image/Instance/Customization/Attribute/Review Policy 和数据集都不可变、可追溯。**
24. **依赖故障或 mandatory gate 缺失时 fail closed 为 UNKNOWN。**
25. **模型 CERTAIN_MATCH 只是待提交 Decision；Recognition Commit 后业务关系才生效。**
26. **任何复杂度只有在提高 Coverage@99.9% Precision、降低 False Merge/False Novel/Identifier Scope Error、提高事务可靠性或降低总成本时才有价值。**
