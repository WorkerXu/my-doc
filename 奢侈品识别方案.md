# 奢侈品识别方案

## 1. 目标与边界

系统目标不是“找最像的商品”，而是把雷小安、奢当家、腕表之家、小迈步、爱回收等来源的记录归一到**同一个官方商品变体（Official Variant）**。

第一阶段覆盖腕表与箱包，历史数据约 100 万–1000 万条。腕表已有部分品牌/系列/型号标准库；箱包主档不完整，因此系统同时支持 **Entity Linking** 与 **Entity Discovery**。

核心原则：

> **Precision >> Recall。宁可输出 UNKNOWN，也不能把不同官方变体错合并。**

系统不做真假鉴定。成色、价格、库存、卖家、单件序列号、保卡状态属于 Offer / 单件属性；官方维修、后换件、附属物和商家自组 Bundle 也不能被误当成新的官方 Variant。

机器成功识别后形成一致业务结果：

```text
Source Product 当前状态
+ Source → Canonical 当前识别关系
+ Immutable Recognition Record
+ Pending Review 任务/事件
```

四个副作用必须原子、幂等、可重放。

## 2. 核心实体、关系、Source Composition 与标识符语义

Canonical 身份层级：

```text
Brand
  └── Product Family / Series
       └── Product Model
            └── Canonical Variant
```

Source 侧不是默认一条记录等于一个商品。真实输入是：

```text
Source Offer / Listing
   └── Source Component(s)
        └── 0..1 Identity Target Component
```

Canonical 关系：

```text
SAME_VARIANT
VARIANT_OF
SAME_MODEL
SAME_SERIES
VISUALLY_SIMILAR
UNKNOWN
```

组合型 Offer 额外保存非等价关系：

```text
PRIMARY_COMPONENT_VARIANT
MULTIPACK_OF_VARIANT
ACCESSORY_OF_VARIANT
CONTAINS_VARIANT
```

只有 `SAME_VARIANT` 可以进入普通 Canonical 聚类并生成默认自动 Recognition；其他关系是 Offer Composition 关系，不能伪装成 SAME_VARIANT。

Canonical Variant 状态：

```text
ACTIVE
PROPOSED
SPLIT_PENDING
MERGE_PENDING
RETIRED
MERGED
SPLIT
TAINTED
```

`MERGED` 可 redirect 到唯一 survivor；`SPLIT` 是 one-to-many，旧 Canonical 必须重新解析。

### 2.1 Identifier Namespace

统一采集：

```text
reference_full / style_code / mpn
gtin / ean / upc
merchant_sku
product_group_id / item_group_id
variant_dimension_keys / variant_dimension_values
barcode_symbology / payload / checksum
market
identifier_namespace / identifier_owner / identifier_scope
identifier_source / source_field_path / confidence
component_id / identifier_binding_scope
```

规则：

- 高可信完整 Reference / Style Code：最强 Identity Anchor 之一。
- 官方品牌来源 `mpn` 经品牌规则校验后可作为 Manufacturer-grade Identifier。
- 第三方 merchant `sku` 默认属于 merchant namespace。
- `productGroupID / item_group_id` 是 Group 关系标识，不是 Variant Identity Anchor。
- ProductGroup/hasVariant/isVariantOf/variesBy 是 Variant Boundary Evidence。
- 高可信 GTIN/EAN/UPC：Strong Positive + Exact Retrieval Key；GTIN 冲突需结合品牌/市场规则解释。
- Vintage 考虑旧编码、地区差异、包装变化和历史规则。

维护：

```text
identifier_semantics_policy:
brand × market × source_group × field_path × identifier_type × composition_state
```

声明 `MANUFACTURER_ID / MERCHANT_ID / GROUP_ID / INSTANCE_ID / UNKNOWN`，以及 Exact Retrieval、Strong Positive、Hard Conflict、Auto Activation 权限。

### 2.2 Source Composition Semantics

每个 Source Offer 必须生成 `source_composition_assessment`：

```text
SINGLE_PRODUCT
SINGLE_PRIMARY_WITH_AUXILIARY
MERCHANT_DEFINED_BUNDLE
MANUFACTURER_DEFINED_SET
MERCHANT_MULTIPACK
MULTI_PRODUCT_LOT
ACCESSORY_ONLY
CONFLICTING_COMPOSITION
UNKNOWN_COMPOSITION
```

组件角色：

```text
PRIMARY_IDENTITY_TARGET
INCLUDED_AUXILIARY
MERCHANT_ADD_ON
MANUFACTURER_SET_COMPONENT
PACKAGING_OR_DOCUMENT
ACCESSORY_PRODUCT
OTHER_PRODUCT
UNKNOWN_COMPONENT
```

关键语义：

1. `SINGLE_PRODUCT`：正常一条 Source → 一个 Official Variant。
2. `SINGLE_PRIMARY_WITH_AUXILIARY`：主商品附带盒、保卡、防尘袋、可拆肩带、挂件、备用表带等；附属物属于 Offer，不改变主商品 Variant。
3. `MERCHANT_DEFINED_BUNDLE`：商家把主商品和其他不同商品组合销售。该 Listing **不等于**主商品的 Official Variant；可保存 `PRIMARY_COMPONENT_VARIANT`，但默认不产生 SAME_VARIANT Recognition。
4. `MANUFACTURER_DEFINED_SET`：制造商本身定义并销售的 Set/Bundle。只有存在官方 Set 标识、官方 Catalog 边界及必要 Hard Facts 时，才能作为独立 Canonical Product/Variant；不能自动拆成“主商品”。
5. `MERCHANT_MULTIPACK`：商家把多个相同商品组合销售，属于 Offer 数量语义；默认保存 `MULTIPACK_OF_VARIANT`，不等于单个 Official Variant。
6. `MULTI_PRODUCT_LOT`：多个不同商品且没有可证明的唯一主商品；不做 SAME_VARIANT Auto-Match。
7. `ACCESSORY_ONLY`：表带、盒、挂件、肩带等独立配件 Listing 不得因为品牌/系列名称接近而挂到腕表/箱包 Canonical。
8. `CONFLICTING/UNKNOWN`：合法 abstain，输出 `UNKNOWN_SOURCE_COMPOSITION`。

## 3. 标准 Schema 与 Hard Constraint

每个属性断言保存：

```text
raw_value / normalized_value / canonical_value_id
extractor / extractor_version
source / evidence_span / image_bbox
extraction_confidence
validation_status / validation_confidence / validation_record_id
fact_scope
effective_from / effective_to / observed_at
market_scope / region_scope
component_id / component_binding_confidence
```

**Extraction Confidence ≠ Validation Confidence；Validated Observation ≠ Official Variant Spec。** Hard/Strong 默认指 `OFFICIAL_VARIANT_SPEC`，并且断言必须绑定正确 Source Component。

### 3.1 腕表

| 字段 | 默认策略 |
|---|---|
| brand | Hard |
| series / family | Blocking + Strong；品牌规则可 Hard |
| subseries / model | Strong |
| official_reference_full | Hard |
| reference_base | Retrieval / Strong，默认不能代替 full |
| gtin/ean/upc | Strong；条件 Hard |
| case_diameter_mm | Hard |
| case_material | Hard |
| dial_color / dial_type | 定义 Variant 时 Hard；仅 Official Spec |
| bezel | 定义 Variant 时 Hard；仅 Official Spec |
| bracelet_or_strap | 条件 Hard；当前实物组件不能直接当 Factory Spec |
| caliber / movement | 代际/Variant 区分时 Hard，否则 Strong |
| functions | 区分 Variant 时 Hard |
| edition / generation | Hard |
| serial_number | 单件属性 |
| condition / price | Offer 属性 |

### 3.2 箱包

| 字段 | 默认策略 |
|---|---|
| brand | Hard |
| family / series | Blocking + Strong |
| model / style | Strong |
| official_style_code | Hard |
| gtin/ean/upc | Strong；条件 Hard |
| official_size | Hard |
| material / official_color / hardware | Hard；仅 Official Spec |
| pattern / print | Hard |
| edition / collaboration | Hard |
| season / year / generation | 官方区分时 Hard |
| serial / date_code | 单件/生产证据 |
| condition / price | Offer 属性 |

图片颜色只做 Soft Evidence。

### 3.3 两级标准化

```text
material_group = ROSE_GOLD
material_brand_value = ROLEX_EVEROSE_GOLD
color_group = BLACK
color_brand_value = CHANEL_NOIR
```

通用层用于召回，品牌精确层用于 Variant 判定。

## 4. Evidence、来源独立性、事实状态与时间版本

来源等级：T0 品牌官方；T1 已验证标准库/授权专业库；T2 高质量专业/二手平台；T3 普通电商/聚合/搜索。

可信度按“来源 × 属性 × 市场/时间 × Component”定义。

### 4.1 来源独立性

维护 `source_group_id / syndication_group_id / content_fingerprint / image_hash_group_id / upstream_hint`。复制 feed、重复图、相同异常文案不能增加独立来源数。

### 4.2 Evidence Family

```text
IDENTIFIER / STRUCTURED_ATTR / VARIANT_GRAPH
LEXICAL_TEXT / SEMANTIC_TEXT / IMAGE_VISUAL
OCR_TEXT / EXTERNAL_WEB / TEMPORAL
```

同一原始观测派生的多个分数不是多票；不同组件的证据也不能机械相加支持同一 Identity Target。

### 4.3 Fact Promotion Barrier

```text
OBSERVED / DERIVED / REVIEWED_GOLD / GOVERNED_FACT / APPROVED_ALIAS / TAINTED
```

Recognition、Matcher 分数、Cluster membership、模型抽取和 pseudo-label 都是 DERIVED；未经治理不得进入 Exact Identity、Canonical Hard Fact 或 Gold Training Set。

### 4.4 时间版本

Canonical 属性保存 `valid_from / valid_to / version / evidence_ids`。没有明确代际证据时不跨年代自动合并。

### 4.5 Canonical Attribute Fact Arbitration

仲裁主键：

```text
canonical_variant_id × attribute_id × market_scope × valid_time_scope × variant_generation
```

属性语义：`SINGLE_VALUE / SET_VALUE / ORDERED_MULTI / RANGE`，并定义 `identity_role / normalization_level / regional/temporal variation / comparison_policy`。

Resolution：`RESOLVED / MULTI_VALID / CONFLICTED / UNKNOWN / STALE`。

规则：

- 不 latest-write-wins，不简单 majority vote。
- syndicated/复制来源先去重。
- Authority 按字段、品牌、市场、有效期和字段语义定义。
- 同 scope 治理级 Hard Attribute 冲突 → `CONFLICTED`，停止依赖该字段 Auto-Match。
- 低可信 OCR/VLM/普通平台不能覆盖治理级 T0/T1。
- 缺失不是反证；多值按属性语义比较。
- 上游撤回/TAINT → `STALE` 并重仲裁。
- Arbitration 只消费 `OFFICIAL_VARIANT_SPEC` 且通过 Validation/Promotion Gate 的断言。
- Search/Matching/Conflict 只消费已发布的 `RESOLVED/MULTI_VALID` Current Fact。

## 5. Source Composition、属性抽取、Validation、OCR 与 VLM

完整前处理：

```text
Raw Source Offer
→ Schema Mapping
→ Source Composition Detection
→ Source Component / Evidence Binding
→ Deterministic Parsing / Dictionary
→ Barcode Decode
→ Text Attribute Extraction
→ Scene OCR
→ Document-like OCR/VLM（按需）
→ General VLM Fallback（少量）
→ Normalization / Ontology
→ Attribute Validation
→ Attribute Assertion
→ Item-State / Origin Classification
→ Canonical Arbitration（仅 Official-Spec）
```

### 5.1 Source Composition Gate

优先证据：平台结构化字段（bundle/multipack/set/component fields）→ Identifier 语义 → 标题/描述组件分段 → 图片/region membership → 规则/VLM fallback。

每个组件保存：

```text
source_component_id
component_role
brand/category candidate
identifier_ids
text_span_ids
image_region_ids
attribute_assertion_ids
component_confidence
```

固定规则：

1. **Listing 级文本、图片和属性不能在 Composition 未确定前直接生成商品级 Identity Embedding。**
2. 所有 Identity Evidence 必须绑定到 `PRIMARY_IDENTITY_TARGET` 或官方 Manufacturer Set 实体；`MERCHANT_ADD_ON / ACCESSORY_PRODUCT / OTHER_PRODUCT` 不能污染主商品 Hard Attribute、Text ANN、Image ANN、Reranker。
3. Google Merchant 语义中，商家自组 Bundle 的 GTIN/MPN/brand 可以指向**主商品**，而标题和图片描述**整个 Bundle**；因此 Exact Identifier 命中只能证明主组件候选，不能证明整个 Listing=`SAME_VARIANT`。
4. 制造商定义 Bundle/Set 的 GTIN/MPN/brand 指向 Bundle 本身；有官方 Set identity 时按 Set Canonical 处理，不能误当单件主商品 Identifier。
5. Merchant multipack 的数量是 Offer Composition，不是 Variant size/型号属性。
6. `is_bundle/multipack` 缺失不能证明 `SINGLE_PRODUCT`；弱来源只能提高/降低 composition confidence。
7. 主商品无法唯一确定时不强行选择：`UNKNOWN_SOURCE_COMPOSITION`。
8. Bundle/lot/composition 不确定不得进入 Entity Discovery 创建新品。
9. `SINGLE_PRIMARY_WITH_AUXILIARY` 中盒、证件、备用可拆件等只作为 Offer/Item-State Evidence；不会让 Listing 失去主商品 SAME_VARIANT 资格。
10. Composition Policy、detector、component binding 都版本化；Source 文本/图片/结构字段变化后必须重算。

### 5.2 Barcode / OCR

使用 zxing-cpp 等确定性 decoder；条码/Reference OCR 结果还必须完成 `component_binding_scope`。拼图、证件、配件上的 Identifier 不能自动绑定到主商品。

### 5.3 General VLM

PoC 困难样本结构化抽取基线：Qwen3.5-4B。只能产出候选 Evidence/Composition/Component 提示，无权直接写 Canonical、Current Fact、Composition Truth 或 CERTAIN_MATCH。

### 5.4 Attribute Validation Gate

状态：

```text
VALIDATED_VALID / VALIDATED_INVALID / UNVERIFIED / NOT_APPLICABLE / SOURCE_CONFLICT
```

Validation 保存 source/version、attribute/value、product type/taxonomy、component id、validator/version、independent evidence、market/time/generation、circular-dependency check。

分层：L0 deterministic → L1 applicability/cross-field → L2 text/profile → L3 cross-source/official → L4 multimodal → L5 LLM/VLM fallback。所有层允许 abstain。

Hard Attribute 只有 `VALIDATED_VALID` 且来源/Validator policy 已认证才可进入身份链路。

### 5.5 Official Variant Spec vs Observed Item State

可变化组件断言增加：

```text
fact_scope = OFFICIAL_VARIANT_SPEC / OBSERVED_ITEM_STATE
component_origin = FACTORY_CONFIG / AUTHORIZED_SERVICE_REPLACEMENT / AFTERMARKET_OR_MODIFIED / UNKNOWN_ORIGIN
replaceability_class = IDENTITY_STABLE / SERVICE_REPLACEABLE / USER_REPLACEABLE / COSMETIC_OR_CONSUMABLE / UNKNOWN
```

规则：

- Canonical 只描述 Official Variant Spec。
- VALIDATED_VALID 只证明观察值正确，不证明 Factory Config。
- 官方售后替换件仍是 post-sale item state，不重写 Canonical。
- SERVICE/USER replaceable 字段与 Canonical 不一致默认是 Item-State Divergence，不是 Hard Conflict。
- Strong Identifier 已锁定 Variant 时，可解释换件不得覆盖 Anchor。
- 无 Strong Anchor 且关键组件 Origin 不明/疑似更换时输出 UNKNOWN。
- 后换/维修/改装不触发新 Canonical。

输出分离：`variant_identity_decision` 与 `item_configuration_assessment`。

## 6. EvidenceProfile、Router、Composition 与缺模态 Route Policy

每条 Source Offer 计算：

```text
identifier_quality / text_quality / image_quality
hard_attr_coverage / conflict_state / catalog_mode
brand_route_state / category_route_state / routing_scope
composition_state / composition_confidence / main_component_id
image_set_state
item_state_assessment
```

### 6.1 Router / Filter Safety

Router 是候选空间优化器，不是身份事实源。

```text
HARD_FILTER / MULTI_ROUTE / ANCESTOR_ROUTE / BROAD_FALLBACK
```

Exact Identifier 永远绕过非权威 Router；模型/VLM/OCR/merchant 分类不得单独 hard-prune。

### 6.2 Composition-aware Route

- `SINGLE_PRODUCT`：普通 Linking。
- `SINGLE_PRIMARY_WITH_AUXILIARY`：只对 primary component Linking；auxiliary 不参与 Identity。
- `MERCHANT_DEFINED_BUNDLE`：可识别 primary component，但默认 relation=`PRIMARY_COMPONENT_VARIANT`，不生成 SAME_VARIANT Recognition。
- `MANUFACTURER_DEFINED_SET`：仅在官方 Set identity 已治理时走 Set Canonical；否则 UNKNOWN/PROPOSED Set governance。
- `MERCHANT_MULTIPACK`：关系=`MULTIPACK_OF_VARIANT`；不把数量写入 Official Variant 属性。
- `MULTI_PRODUCT_LOT / ACCESSORY_ONLY / UNKNOWN/CONFLICTING`：不做腕表/箱包 SAME_VARIANT Auto-Match。

## 7. Candidate Retrieval、Fusion 与 Open-world Guard

召回：Exact Identifier、Brand+Model、Brand+Series+Hard Attr、BM25、Text ANN、Image ANN/hash、Historical Alias、Discovery Neighbor。

PoC 初始 K：Exact≤20、BM25 30、Text ANN 50、Image ANN 每图30/总≤60、Attribute 30；union≤150，Cheap Rerank≈30，Expensive Matcher 10–20。

Gate：`Recall@100 >=99.5%`，Exact survival=100%，Router pre/post-filter recall 单独监控。

### 7.1 Component-aware Retrieval/Fusion

- Query text 只由 `PRIMARY_IDENTITY_TARGET` 的 text span + Listing 中已确认属于主组件的共享上下文生成。
- Bundle/add-on/accessory component 的属性不进入主商品 hard filter。
- Exact Identifier 必须携带 `identifier_binding_scope`；商家 Bundle 中主商品 GTIN 可召回主商品，但不会把 Bundle Listing升级 SAME_VARIANT。
- Manufacturer-defined Set Identifier 只能召回 Set Canonical。
- Image ANN 只使用 Composition+Image Gate 均确认属于 Identity Target 的图/region。
- Exact 候选永不被 Soft Fusion 截断；RRF 为零/少标签 baseline。

### 7.2 NIL / Route Recovery

CandidateSet：`KNOWN_CANDIDATE / AMBIGUOUS_KNOWN / POSSIBLE_NIL / RETRIEVAL_FAILURE / ROUTING_AMBIGUOUS`。

进入 NIL/Discovery 前必须完成：Router bypass（必要时）+ Composition Gate + Item-State Divergence Check。任何 Bundle/Lot/Composition 不确定均不能作为新品证据。

## 8. Embedding、Visual Search 与 Image Set Safety

Text：Qwen3-Embedding-0.6B；Text Reranker：Qwen3-Reranker-0.6B。

Image：SigLIP2 baseline；DINOv3 challenger（Legal Gate）；Qwen3-VL Embedding/Reranker 只在困难路径验证收益。

近邻 Variant 使用局部 patch/local descriptor shortlist rerank；局部视觉仍非 Identity Anchor。

### 8.1 Image Set Identity / Utility Gate

图片角色：PRODUCT_PRIMARY / PRODUCT_DETAIL / MODEL_LIFESTYLE / PACKAGING_OR_DOCUMENT / COLLAGE / ACCESSORY_OR_AFTERMARKET / DECORATIVE / OTHER_PRODUCT_SUSPECT / UNKNOWN。

Image Gate 与 Composition Gate 分工：

- Composition Gate 判断 Listing 包含哪些产品/组件、谁是 Identity Target。
- Image Gate 判断每张图/region 是否属于对应组件、是否适合 Identity/OCR/Validation。

规则：raw image set 不直接 max；拼图 region 化；CROSS_VARIANT_REUSE 不做 Positive；文档图不进外观 ANN；Bundle 全景图只有在主组件 region 可稳定分离时才进入主商品 Identity；多图仍属于同一 IMAGE_VISUAL Family。

→ Deterministic Features
→ Structured/Text Matcher
→ Multimodal Difficult Pair
→ Local Visual（near-tie）
→ Post-Conflict
→ Calibration

## 10. Entity Linking、Discovery 与 Canonical Health

### 10.1 Linking

```text
Source Snapshot
→ Composition Gate + Component Binding
→ Router / Validation / Image / Item-State Gate
→ Hybrid Retrieval
→ Pair / Conflict / Calibration
→ CandidateSetAssessment
→ SAME_VARIANT CERTAIN_MATCH
→ Recognition Commit Barrier
```

`MERCHANT_DEFINED_BUNDLE / MERCHANT_MULTIPACK` 的主商品识别结果可写独立 Composition Relation，但默认不写 SAME_VARIANT Recognition，不进入 Canonical cluster/training Positive。

### 10.2 Discovery / Novelty

```text
POSSIBLE_NIL
→ Route Recovery
→ Composition/Item-State Recheck
→ Official/Web Evidence
→ Strict Blocking
→ Constraint-aware Clustering
→ PROPOSED
→ Novelty/Uniqueness + Required Hard Facts
→ ACTIVE or remain PROPOSED
```

以下输入禁止直接生成新 Official Variant：Merchant Bundle、Merchant Multipack、Multi-product Lot、Accessory-only、Observed Item State、Service Replacement、Aftermarket Modification。

Manufacturer-defined Set 只有在官方 Set identifier/catalog 证明其本身是制造商产品实体时，才能进入独立 Canonical Discovery。

### 10.3 ACTIVE Canonical Health / Split / Merge

周期性/事件驱动检查 Hard Conflict、cannot-link、Manufacturer ID partitions、Fact Conflict、review disagreement、temporal generation。治理级冲突立即 freeze。

GNN/GraphCR/SuperPart 等只能 Detect/Prioritize/Propose；Split/Merge 需 Governance + 原子 Publication。Merge 时重新 Validation/Arbitration，不能让 survivor 字段覆盖另一边。

## 11. Web Evidence Agent 与 Official Web Catalog

优先级：品牌官网 → 官方目录/经销资料 → 专业数据库 → 高质量二手平台 → 通用搜索。

官方站解析 ProductGroup/Product、DOM、Embedded State、Identifier、Variant URL，产出版本化 Assertions/Variant Graph。

Web/Agent 无权直接修改 Canonical、裁决 Current Fact 或 CERTAIN_MATCH。

维修资料用于 component replaceability，不证明具体 Source 实例维修过。

若平台/Feed 暴露 `is_bundle / multipack / component` 等字段，作为高价值 Composition Evidence；其缺失不能单独证明 Single Product。Schema.org `isAccessoryOrSparePartFor` 可作为 accessory relation evidence，不作为身份锚点。

## 13. Review、风险认证与 Reviewer Quality

三轨：TRAINING_REVIEW / CERTIFICATION_AUDIT / GOVERNANCE_REVIEW。

正式风险认证以最终 Recognition Decision 为单位，概率抽样保存 inclusion probability/stratum，并报告 i.i.d. 与 dependency-cluster-aware 风险上界，release 取最保守值。

Certification 默认双人独立盲审；允许 SAME_VARIANT / DIFFERENT_VARIANT / INSUFFICIENT_EVIDENCE / SOURCE_DATA_ERROR，分歧 adjudication。

独立控制集包括：Attribute Validation、Image Set Safety、Item-State/Factory-Spec、**Source Composition**。

## 15. Incremental、CDC、Publication 与 Recognition Commit

Canonical/Attribute Resolution mutation 与 catalog outbox 同事务；幂等 Search 投影使用 external version，refresh/checkpoint 后推进 publication watermark。

Auto-Match 请求 pin `ACTIVE publication_id`。

Source 文本、图片、结构化 Bundle 字段变化都会生成新 `source_version`；影响 Composition、Component Binding、Item-State、Image eligibility 或 Hard Assertion 时旧 Decision Snapshot 失效。

Recognition Commit：推理阶段不持长事务，CERTAIN_MATCH 进入短 ACID：idempotency intent → Source CAS → validate Source/Canonical/publication/fact/composition versions → ensure single current link → immutable Recognition → current link → Source state → one Review/outbox。

如果推理后 `source_composition_assessment` 变化、main component 改变或 Composition 从 Single 变 Bundle/Lot，则不提交旧 SAME_VARIANT Decision，返回 stale/reprocess。

## 16. Production Runtime Reliability

mandatory stage timeout/熔断/跳过会形成新 route signature；未经单独认证只能 UNKNOWN。

每请求 end-to-end deadline；依赖唯一 retry owner；指数退避+jitter+retry budget；bounded queue+circuit breaker。

Load shedding：P4 backfill/bulk validation → P3 Discovery/Web/Composition enrichment → P2 near-tie expensive → P1/P0 Linking。

Composition Gate 若为该 Source 的 identity-critical mandatory stage，不能因过载直接假设 SINGLE_PRODUCT。

## 17. 容量、成本与性能

10M 商品、平均3图、10M text + 30M image vectors、512d：FP16 导出约40.96GB；OpenSearch FP32 完整向量约81.92GB，不含索引/副本/shadow。

PoC（1–2M）：1×L4 24GB、1×8 vCPU/64GB OpenSearch、0.5TB SSD。

10M 压测起点：3×8 vCPU/64GB OpenSearch、3×1TB usable storage、2×L4 24GB online GPU；历史回填临时4–8×L4。

单独统计：Composition detection QPS/p95、component segmentation rate、multi-product ratio、eligible identity component ratio、Bundle/Lot UNKNOWN rate、因 evidence isolation 减少的 ANN/VLM 计算量。

成本与 `Coverage @ 99.9% Precision`、`Cost per Confirmed Recognition` 联合优化。

## 20. 正式开启自动识别 Gate

全部满足才扩大 Auto-Match：

1. `Precision@Auto-Match >= 99.9%`，`Recall@100 >= 99.5%`，Exact survival=100%。
2. Certification Audit 满足 sampling provenance 与 cluster-aware risk upper bound。
3. Hard Conflict、Seen/Unseen/Time-shift/Vintage/缺图/缺型号/低质图达标。
4. Synthetic/Pseudo evidence 不形成 Hard Fact/Identity Anchor/Certification Gold。
5. AMBIGUOUS/NIL/ROUTING_AMBIGUOUS/SOURCE_COMPOSITION/RETRIEVAL_FAILURE/PUBLICATION/CATALOG_REPAIR/FACT_CONFLICT 不得绕过 Guard。
6. Product Group ID、merchant SKU、Web structured-data 语义违规=0。
7. ACTIVE 模型/Router/Composition Gate/Image Gate/Attribute Validator/Item-State Policy lineage=100%。
8. SPLIT/MERGE/TAINT 状态新 Auto-Match=0；repair partial publication CERTAIN_MATCH=0。
9. PROPOSED→ACTIVE 必须 novelty=UNIQUE，required Hard Facts 可服务。
10. Recognition Commit duplicate/partial/stale/multiple-current-link=0。
11. Router 非权威 hard prune / false NIL / false new canonical=0。
12. Identity/Search/Hard Conflict 只消费已发布 Canonical Resolution。
13. Hard Attribute UNVERIFIED/INVALID/SOURCE_CONFLICT 参与身份链路=0。
14. Image Gate/shared-image/collage 违规=0。
15. OBSERVED_ITEM_STATE/Service/Aftermarket 被当 Factory Spec=0。
16. **Composition 未完成却假定 SINGLE_PRODUCT 并 Auto-Match 的违规=0。**
17. **Merchant-defined Bundle 被写成 SAME_VARIANT 的违规=0；只允许独立的主组件关系。**
18. **Merchant Multipack 被写成单商品 SAME_VARIANT 的违规=0。**
19. **Multi-product Lot / Accessory-only 产生腕表或箱包 SAME_VARIANT Auto-Match 的违规=0。**
20. **Merchant Bundle 的 accessory/add-on 文本、属性、图片进入主商品 Hard/Strong Evidence 的违规=0。**
21. **Manufacturer-defined Set Identifier 被误解释为单个主组件 Identifier 的违规=0。**
22. **Merchant Bundle 主商品 Identifier 命中后，直接把整个 Listing 当 SAME_VARIANT 的违规=0。**
23. **Bundle/Lot/Composition UNKNOWN 被作为 POSSIBLE_NIL 进入新品 Discovery 的违规=0。**
24. **Composition/Component Binding policy、Gold、model/version provenance 完整率=100%；Source composition 变化后旧 Decision Snapshot 不得提交。**

指标退化时优先降低 Coverage，不通过“默认单商品”来保吞吐或召回。

## 22. 最终生产原则

```text
Raw Source Offer
          ↓
Source Composition / Component Binding
          ↓
Attribute Extraction + Validation
          ↓
Official-Spec vs Observed-Item-State / Origin Gate
          ↓
Evidence Assertions + Source Independence
          ↓
Canonical Variant-Spec Fact Arbitration
          ↓
Router / Filter Safety
          ↓
Image Set Identity / Utility Gate
          ↓
Component-aware Hybrid Retrieval + Exact Preserve
          ↓
Structured + Text + Eligible Image Evidence
          ↓
Hard Conflict + Calibration
          ↓
Candidate-set / NIL / Ambiguity / Composition Guard
          ↓
Constraint-aware Graph Resolution
          ↓
SAME_VARIANT CERTAIN_MATCH
          ↓
Recognition Commit Barrier
          ↓
Current Link + Immutable Recognition + Pending Review
          ↓
Canonical Novelty / Health / Repair
          ↓
Independent Risk Audit
          ↓
Controlled Training + Immutable Lineage
```

固定原则：

1. **Identity first，Similarity second。**
2. **Source Offer ≠ 必然一个商品；先判 Composition，再做 Variant Identity。**
3. **Merchant Bundle / Multipack / Lot 的组合关系不能伪装成 SAME_VARIANT。**
4. **商家 Bundle 的主商品 Identifier 可用于定位主组件，但不能证明整个 Listing 等于主商品 Variant。**
5. **制造商官方 Set 与商家自组 Bundle 必须分开；前者可能有独立官方身份，后者是 Offer Composition。**
6. **附件、配件、其他商品的文本/图片/属性必须与主商品 Identity Evidence 隔离。**
7. **Composition 不确定是合法 UNKNOWN；不得默认 SINGLE_PRODUCT。**
8. **Bundle/Lot/Accessory-only 不得因为没匹配上就进入新品 Discovery。**
9. **Extraction confidence ≠ fact correctness；Validated Observation ≠ Official Variant Spec。**
10. **Canonical 只保存 Official Variant Spec；二手当前组件进入 Item-State 层。**
11. **官方维修替换件不自动成为 Factory Config。**
12. **Hard Conflict 只建立在经过 Validation、正确 Fact Scope、正确 Component Binding 的证据上。**
13. **Synthetic/Pseudo evidence 不能形成 Hard Fact / Identity Anchor / Certification Gold。**
14. **多张图片不是多份独立身份票；先做 item/component membership 与 utility。**
15. **仅视觉相似不能自动 SAME_VARIANT。**
16. **必须显式允许 NIL；near-tie 必须 Abstain。**
17. **Exact Identifier 绕过非权威 Router，但不能绕过 Identifier Component/Composition Semantics。**
18. **训练 Review、Composition Gold、Image Gold、Attribute Gold、Item-State Gold、Risk Certification 是不同资产。**
19. **Product Group ID 是关系标识，不是 Variant Identity；Merchant SKU 与 Manufacturer ID 分命名空间。**
20. **Canonical Current Fact 是已验证 Official-Spec Assertions 的版本化 Arbitration，不是最近值/多数票。**
21. **Search/Hard Conflict 只消费已验证、已仲裁、已发布的 Current Fact。**
22. **DB→Search 使用 Transactional Outbox + Idempotent Projection + Monotonic Version + Publication Barrier。**
23. **ACTIVE Canonical 持续检查 over-merge、under-merge、Fact Conflict。**
24. **Entity Discovery 是新品证明问题，不是“没匹配上”的同义词。**
25. **Cluster Repair Model 只能 Detect/Prioritize/Propose，不能直接修改 Canonical。**
26. **所有模型、Router、Composition Gate、Image Gate、Attribute Validator、Item-State Policy 和数据集都不可变、可追溯。**
27. **依赖故障或 mandatory gate 缺失时 fail closed 为 UNKNOWN。**
28. **模型 CERTAIN_MATCH 只是待提交 Decision；Recognition Commit 后业务关系才生效。**
29. **任何复杂度只有在提高 Coverage@99.9% Precision、降低 False Merge/False Novel/Composition Leakage、提高事务可靠性或降低总成本时才有价值。**
