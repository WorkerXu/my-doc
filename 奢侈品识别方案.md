# 奢侈品识别方案

## 1. 目标与边界

系统目标不是“找最像的商品”，而是把雷小安、奢当家、腕表之家、小迈步、爱回收等来源的记录归一到**同一个官方商品变体（Official Variant）**。

第一阶段覆盖腕表与箱包，历史数据约 100 万–1000 万条。腕表已有部分品牌/系列/型号标准库；箱包主档不完整，因此系统必须同时支持 **Entity Linking** 与 **Entity Discovery**。

核心原则：

> **Precision >> Recall。宁可输出 UNKNOWN，也不能把不同官方变体错合并。**

只有定义官方变体的关键属性兼容时，才允许自动认定 `SAME_VARIANT`。系统不做真假鉴定；成色、价格、库存、卖家、单件序列号、保卡状态等属于 Offer / 单件属性，不定义官方商品变体。

机器成功识别后必须形成一致业务结果：

```text
Source Product 当前状态
+ Source → Canonical 当前识别关系
+ Immutable Recognition Record
+ Pending Review 任务/事件
```

这四个副作用必须原子、幂等、可重放，不能出现“模型判断正确但业务状态只写了一半”。

## 2. 核心实体、关系与标识符语义

```text
Brand
  └── Product Family / Series
       └── Product Model
            └── Canonical Variant
                 └── Source Product / Offer
```

关系至少包括：

```text
SAME_VARIANT
VARIANT_OF
SAME_MODEL
SAME_SERIES
VISUALLY_SIMILAR
UNKNOWN
```

只有 `SAME_VARIANT` 可以生成自动 Recognition。

Canonical Variant 状态：

```text
ACTIVE         已验证，可参与自动挂接
PROPOSED       新发现，等待证据/治理
SPLIT_PENDING  疑似一个 Canonical 混入多个 Variant，冻结新自动挂接
MERGE_PENDING  疑似多个 Canonical 实为同一 Variant，冻结相关实体新自动挂接
RETIRED        历史实体，不再接受新自动挂接
MERGED         已治理合并到唯一 surviving Canonical
SPLIT          已确认 one-to-many 拆分，仅保留历史身份与 lineage
TAINTED        关键事实污染，暂停自动挂接
```

`MERGED` 是 many-to-one，可 redirect 到唯一 survivor；`SPLIT` 是 one-to-many，旧 Canonical 不能自动 redirect 到任一 child，必须重新解析。

### 2.1 Identifier Namespace

统一采集：

```text
reference_full / style_code / mpn
gtin / ean / upc
merchant_sku
product_group_id / item_group_id
variant_dimension_keys / variant_dimension_values
barcode_symbology / payload / checksum
market
identifier_namespace / identifier_owner / identifier_scope
identifier_source / source_field_path / confidence
```

规则：

- 高可信完整 Reference / Style Code 精确一致：最强 Identity Anchor 之一。
- 官方品牌来源中的 `mpn` 经品牌规则/格式验证后可作为 Manufacturer-grade Identifier。
- 第三方商家 `sku` 默认属于 merchant namespace，不得直接升级为官方 Reference / Style Code。
- `productGroupID / item_group_id / inProductGroupWithID` 是父商品组/变体组关系标识，不是 Variant Identity Anchor。
- `ProductGroup.hasVariant / Product.isVariantOf / variesBy / variant_option` 是高价值 Variant Boundary Evidence。
- 高可信、校验通过的 GTIN/EAN/UPC：Strong Positive + Exact Retrieval Key。
- 不同 GTIN 默认 `POSSIBLE_CONFLICT`；只有品牌/市场规则证明该语境下 GTIN 与本系统 Variant 1:1 时才升级 Hard。
- Vintage 必须考虑旧编码、地区站点差异、包装变化与历史规则。

维护 `identifier_semantics_policy`，最小粒度：

```text
brand × market × source_group × field_path × identifier_type
```

策略声明 `MANUFACTURER_ID / MERCHANT_ID / GROUP_ID / INSTANCE_ID / UNKNOWN`，并声明是否允许 Exact Retrieval、Strong Positive、Hard Conflict、Auto Activation。

## 3. 标准 Schema 与 Hard Constraint

每个属性事实保存：

```text
raw_value
normalized_value
canonical_value_id
extractor / extractor_version
source_type / source_id / source_url
evidence_span / image_bbox
confidence / validation_status
effective_from / effective_to
observed_at / content_hash
```

`observed_at` 与有效期分离；新证据不覆盖旧事实，而用 version / supersedes 表达变化。只有双方属性都达到对应可信度门槛时才形成 Hard Conflict；低置信 OCR/VLM 冲突只能触发 `POSSIBLE_CONFLICT → UNKNOWN`。

### 3.1 腕表

| 字段 | 默认策略 |
|---|---|
| brand | Hard |
| series / family | Blocking + Strong；品牌规则可 Hard |
| subseries / model | Strong |
| official_reference_full | Hard；最强身份字段之一 |
| reference_base | Retrieval / Strong，默认不能代替 full |
| gtin/ean/upc | Strong；条件 Hard |
| case_diameter_mm | Hard |
| case_material | Hard |
| dial_color | Hard |
| dial_type | 定义独立变体时 Hard |
| bezel | 定义独立变体时 Hard |
| bracelet_or_strap | 条件 Hard；需识别后换件 |
| caliber / movement | 代际/变体区分时 Hard，否则 Strong |
| functions | 变体区分时 Hard |
| edition / generation | Hard |
| serial_number | 单件属性 |
| condition / price | Offer 属性 |

Reference 保存 `raw / normalized / base / full / parts / brand_rule_version`。默认以 `reference_full` 为准；只有品牌规则明确证明后缀不定义 Variant 时才允许 base reference 参与自动合并。

### 3.2 箱包

| 字段 | 默认策略 |
|---|---|
| brand | Hard |
| family / series | Blocking + Strong |
| model / style | Strong |
| official_style_code | Hard；最强身份字段之一 |
| gtin/ean/upc | Strong；条件 Hard |
| official_size | Hard |
| material | Hard |
| official_color | Hard |
| hardware | Hard |
| pattern / print | Hard |
| edition / collaboration | Hard |
| season / year / generation | 官方由其区分时 Hard |
| serial / date_code | 单件/生产证据 |
| condition / price | Offer 属性 |

图片颜色不直接成为 Hard Constraint；灯光、白平衡、老化、修图会造成偏差，视觉颜色只做 Soft Evidence。

### 3.3 两级标准化

```text
material_group = ROSE_GOLD
material_brand_value = ROLEX_EVEROSE_GOLD

color_group = BLACK
color_brand_value = CHANEL_NOIR
```

通用层用于跨平台召回，品牌精确层用于 Variant 判定，避免把品牌专有语义压平。

## 4. Evidence、来源独立性、事实状态与时间版本

来源等级：

```text
T0  品牌官网、官方目录、官方标识体系
T1  已验证内部标准库、授权/专业数据库
T2  高质量专业平台、可信二手平台
T3  普通电商、聚合站、搜索网页
```

可信度按“来源 × 属性”定义，而不是整站一刀切。

### 4.1 来源独立性

维护：

```text
source_group_id
syndication_group_id
content_fingerprint
image_hash_group_id
upstream_hint
```

多个 URL 不等于多个独立来源。复制同一 feed、相同/近重复图片、相同异常文案、相同字段错误不能增加 `independent_source_count`。

### 4.2 Evidence Family

```text
IDENTIFIER        Reference / Style Code / MPN / GTIN
STRUCTURED_ATTR   size / material / color / hardware / movement
VARIANT_GRAPH     ProductGroup / isVariantOf / variesBy
LEXICAL_TEXT      BM25 / token overlap
SEMANTIC_TEXT     text embedding / reranker
IMAGE_VISUAL      image embedding / patch feature / perceptual hash
OCR_TEXT          image → OCR → identifier/attribute
EXTERNAL_WEB      外部网页证据
TEMPORAL          year / generation / effective period
```

同一原始观测派生出的多个分数不是多个独立证据：同一标题的 BM25+Embedding 不算两票；同一图片的 pHash/SigLIP/DINO/VLM 不算多票；同一网页的 JSON-LD/DOM/摘要默认属于同一 evidence origin。

Student Matcher 可使用全部特征学习联合分布，但 `CERTAIN_MATCH` 风险策略不得把相关特征机械相加解释为多个独立支持。

### 4.3 Fact Promotion Barrier

```text
OBSERVED      原始可追溯观测
DERIVED       规则/模型/聚类推导
REVIEWED_GOLD 人工确认标签
GOVERNED_FACT 主档治理确认事实
APPROVED_ALIAS 已批准别名/标识符映射
TAINTED       已知被污染
```

`Recognition`、Matcher 分数、Cluster membership、模型抽取/伪标签都是 DERIVED Artifact。未经 Review/Governance Promotion，不能直接进入 Exact Identity 索引、Hard Constraint 主档、官方 Alias、Identifier Semantics 或 Gold Training Set。

任何 Exact Alias、Canonical Fact、Reviewed Gold Label 必须能沿 lineage 回溯到 OBSERVED/REVIEWED/GOVERNED 上游；DERIVED→DERIVED 不能完成事实晋升。

### 4.4 时间版本

Canonical 属性保存 `valid_from / valid_to / version / evidence_ids`。用于同名跨年份改款、Reference 规则变化、新旧机芯/五金/尺寸变化和 Vintage 回溯。没有明确代际证据时，不跨年代自动合并。

## 5. 属性抽取、OCR 与 VLM

```text
Raw Source Product
→ Schema Mapping
→ Deterministic Parsing / Dictionary
→ Barcode Decode
→ Text Attribute Extraction
→ Scene OCR
→ Document-like OCR/VLM（按需）
→ General VLM Fallback（少量困难样本）
→ Normalization / Ontology Mapping
→ Attribute Validation / Quality Check
→ Normalized Product Profile
```

优先级：规则/主档 → 条码 → 文本 → Scene OCR → 文档 OCR/VLM → General VLM → Quality Check。能用确定性方法解决的问题不交给大模型。

### 5.1 Barcode / OCR

条码先用 zxing-cpp 等确定性 decoder 解析 EAN/UPC/Code128/Data Matrix/QR，经 check digit、格式、品牌/市场校验后进入 Exact Retrieval。

PoC Scene OCR 基线：PP-OCRv6。OCR 输出分类：

```text
reference / style_code
gtin/ean/upc
serial_number
date_code
size
material_text
other_text
```

保卡整页、历史目录、复杂表格等 document-like 场景使用 PaddleOCR-VL-1.6 / PP-Structure 类能力作为 fallback。

### 5.2 General VLM

PoC 困难样本结构化抽取基线：Qwen3.5-4B。职责是产生**可验证候选证据**，不是最终身份判断。VLM 输出必须经过 ontology、品牌规则、主档、OCR/文本交叉验证；无权直接写 ACTIVE Canonical 或直接输出 `CERTAIN_MATCH`。

## 6. EvidenceProfile、Router 与缺模态 Route Policy

每条 Source Product 先计算：

```text
identifier_quality = NONE / WEAK / STRONG
text_quality       = NONE / WEAK / STRONG
image_quality      = NONE / WEAK / STRONG
hard_attr_coverage = 0..1
conflict_state     = NONE / POSSIBLE / HARD
catalog_mode       = LINK / DISCOVERY
synthetic_evidence = true / false

brand_route_state    = AUTHORITATIVE / MULTI_CANDIDATE / UNKNOWN / CONFLICTING
category_route_state = AUTHORITATIVE / MULTI_CANDIDATE / UNKNOWN / CONFLICTING
routing_scope        = LEAF / ANCESTOR / MULTI_ROUTE / BROAD_FALLBACK
```

| 场景 | 主要召回 | 自动判定上限 |
|---|---|---|
| 强 Reference/Style/GTIN + Hard Attr 无冲突 | Exact + 属性过滤 | 可 CERTAIN_MATCH |
| 文本强、无图片 | Exact/BM25/Text ANN/属性 | 可 CERTAIN_MATCH；无图不是负证据 |
| 图片强、文本弱、无可靠型号 | Image ANN + OCR + 视觉属性 + 少量 VLM | 默认不能仅视觉 CERTAIN_MATCH |
| 文本强 + 图片强 | 多路召回 + Rerank | 可 CERTAIN_MATCH |
| 型号疑似错误 | raw/normalized identifier 双路 + 非 identifier 召回 | 冲突时 UNKNOWN/NON_MATCH |
| 文本与图片冲突 | 模态独立保留 | POSSIBLE_CONFLICT → UNKNOWN |
| 无图无可靠型号、结构化属性较全 | BM25/Text ANN/Attribute | 只有经认证的高区分组合才自动，否则 UNKNOWN |
| 只有泛化标题、缺 Hard Attr | BM25/Text ANN | UNKNOWN |
| Vintage / 新款无 Canonical | Neighbor + Official/Web Evidence | PROPOSED |

Synthetic Evidence 不能形成 Hard Constraint、Identity Anchor 或官方事实；图→文本只可做 query expansion/候选提示；文本→图像默认不进入身份链路。

低质量图片在 Image ANN 前独立评估 blur、resolution、subject_area_ratio、occlusion、background_complexity、watermark、crop_type、color_cast，并降低视觉权重/候选配额。

### 6.1 Router / Filter Safety

Brand/Category Router 的作用是**缩小候选空间和控制成本**，不是身份事实源。路由错误若被当作 hard filter，会在 BM25/ANN 前删除正确 Canonical，随后被误解释为 NIL 或新品，因此路由必须分级：

```text
HARD_FILTER     只有权威、可验证路由证据
MULTI_ROUTE     多个 plausible brand/category route 各保留 quota
ANCESTOR_ROUTE  leaf 不确定时退到 taxonomy ancestor
BROAD_FALLBACK  路由未知/冲突时在更宽 scope 召回
```

固定规则：

1. **Exact Identifier Retrieval 永远绕过 Router。** Manufacturer-grade Reference/Style/MPN/GTIN lookup 不因预测 brand/category 不一致而被提前过滤；身份冲突在 Conflict Engine 决定。
2. 只有 T0/T1 或经过历史质量认证的结构化 brand/category、或已验证 Identifier→Brand/Category 映射，才允许作为 `HARD_FILTER`。
3. 模型分类、VLM 推断、OCR 猜测、低可信 merchant category、标题推断只能做 `MULTI_ROUTE/ANCESTOR_ROUTE/BROAD_FALLBACK`，不得单独 hard-prune。
4. Hierarchical category 预测 leaf 不稳定时优先退到上层 ancestor，而不是强选一个 leaf；多个高概率 sibling route 分别保留 minimum quota。
5. Brand/category 多证据冲突时保留各 plausible route，并把冲突作为 Pair/Conflict 特征；不能通过平均概率把一个真实 route 消失。
6. 图片可补充文本分类，但视觉分类只改变 route candidate 权重，不自动升级为权威品牌/品类事实。
7. 每次查询保存 `routing_decision`：候选 brand/category path、confidence、evidence source、filter mode、router/model version、pre/post-filter candidate counts、fallback reason。
8. OpenSearch efficient k-NN filtering 解决的是“在给定 filter 正确时如何高效检索”，**不能修复错误 filter 语义**；因此引擎 filter recall 与 Router semantic recall 必须分开评测。

## 7. Candidate Retrieval、Fusion 与 Open-world Guard

100 万–1000 万记录禁止 N²。

召回通道：

```text
Exact Full Reference / Style Code / Manufacturer MPN
Exact GTIN/EAN/UPC
Brand + normalized model/reference
Brand + series/model + Hard Attributes
BM25
Text ANN
Image ANN
Image exact/perceptual hash
Historical Canonical Alias
Unmatched Entity-Discovery Neighbors
```

PoC 初始 K：Exact≤20、BM25 30、Text ANN 50、Image ANN 每图30/总≤60、Attribute 30；union≤150，Cheap Rerank≈30，Expensive Matcher 10–20。最终由域内 benchmark 调参。

Retrieval Gate：

```text
Recall@100 after fusion/truncation >= 99.5%
Exact-candidate survival rate = 100%
router_pre_filter_positive_recall >= 99.9%
router_post_filter_positive_recall >= 99.5%
```

### 7.1 Fusion

- 不同通道 raw score 不直接相加。
- Exact/Identity 候选永不被 Soft Fusion 截断。
- 零/少标签阶段用 RRF 作为 Soft Retrieval 基线。
- 截断前保留各通道 minimum quota。
- Exact ∪ RRF 后再 Cheap Rerank。
- 有足够 judgment 后再比较 normalized weighted fusion / learned fusion。
- Fusion、quota、index、embedding、routing policy 全部版本化。

### 7.2 Search Engine

生产基线：OpenSearch 3.8，统一承载 Exact/filter、BM25、filtered k-NN、hybrid retrieval、RRF/score normalization、on-disk vector、quantization/rescore、versioned index/alias。

Milvus 只在 10M 真实压测证明 OpenSearch Recall/QPS/资源成本不满足时拆分；pgvector 适合小规模 PoC/内部工具。

过滤策略必须按 `filter_selectivity × K × latency × recall` 基准选择；post-filter 可能返回显著少于 K 的结果，不能将“返回少”误解释为 Catalog 没有候选。

### 7.3 NIL / None-of-the-Candidates

检索 Top-1 不等于正确 Canonical 一定存在。

`CandidateSetAssessment` 保存：

```text
best_candidate_id / best_score_calibrated
second_candidate_id / second_score_calibrated
score_margin / near_tie_count
candidate_set_state
none_of_candidates_score
nil_reason
retrieval_health_snapshot
routing_decision_id / route_bypass_assessment_id
policy_version
```

状态：

```text
KNOWN_CANDIDATE
AMBIGUOUS_KNOWN
POSSIBLE_NIL
RETRIEVAL_FAILURE
ROUTING_AMBIGUOUS
```

near-tie 且关键 Variant 属性缺失 → `UNKNOWN_AMBIGUOUS`；候选整体低且 Retrieval 健康 → 先进入 Route/Filter Recovery；搜索/索引/route 不健康 → `UNKNOWN_SEARCH_FAILURE`，不得误判新品。

### 7.4 Route/Filter Recovery Before NIL

任何会进入 `POSSIBLE_NIL → Discovery` 的请求，只要缺少 Strong Identifier 或 Router 不是 `AUTHORITATIVE`，必须先做一次 `route_bypass_assessment`：

```text
Current routed candidate set
→ Remove disputed model-inferred hard filters
→ Search taxonomy ancestor / plausible sibling routes
→ Broad BM25/Text ANN quota
→ Image ANN / exact hash when available
→ Compare recovered candidates against original set
```

规则：

1. 若 broad/ancestor/multi-route 搜索恢复出能安全匹配的已有 Canonical，重新进入 Pair/Conflict，不得创建新 Canonical。
2. 若恢复出高风险 near-tie 但证据不足，输出 `UNKNOWN_ROUTING_AMBIGUOUS`，不进入 Discovery。
3. 只有 Router、Search、Publication 均健康，且 bypass 后仍无安全已有候选时，才允许 `UNKNOWN_POSSIBLE_NIL`。
4. `canonical_novelty_assessment` 必须包含 route-bypass 结果；不能用同一错误 Router 再次证明 `UNIQUE`。
5. 生产监控区分 `false_nil_due_to_router`、`candidate_recovered_by_bypass`、`hard_filter_without_authoritative_evidence`。

## 8. Embedding、Visual Search 与局部复核

### 8.1 Text

PoC：Qwen3-Embedding-0.6B，先测 512d，再比较 256/384d。文本同时保存结构化稳定模板与原始标题/描述表示。

Text Reranker：Qwen3-Reranker-0.6B，仅对 Top-N 使用。

### 8.2 Image

语义/跨模态基线：SigLIP2-B/16 384；细粒度 challenger：DINOv3 ViT-B/16。DINOv3 使用自定义许可证，生产前必须 Legal/Compliance Gate；无法接受时测试 DINOv2/其他可商用方案。

每图独立保存向量，多图聚合使用 `max_similarity / topk_mean / front/detail similarity / image_quality_weight`。完全相同/近重复图片不能单独证明 `SAME_VARIANT`。

Qwen3-VL-Embedding-2B / Reranker-2B 作为多模态 challenger；只有显著提高 `Coverage @ 99.9% Precision` 且成本可接受才进入困难路径。

### 8.3 Local/Patch Visual Verify

全局向量负责高召回；盘面刻度、表圈、刻字、五金、走线、印花等近邻差异在 Top-10～20 shortlist 做局部复核：

```text
Global Image ANN
→ Region Selection
→ Patch / Local Descriptor
→ Local Rerank / Correspondence
→ local_visual_score / patch_match_coverage
→ Pair Decider + Ambiguity Guard
```

局部视觉仍属于 `IMAGE_VISUAL`，不得成为 Identity Anchor，也不能覆盖 Hard Conflict。

## 9. Pair Matcher、Conflict Engine 与 Decision Policy

```text
Candidate Pair
→ Pre-Conflict Check
→ Cheap Deterministic Features
→ Structured / Text Matcher
→ Multimodal Difficult-Pair Matcher（少量）
→ Local Visual Verify（near-tie）
→ Post-Conflict Check
→ Calibration
→ Evidence-Family Risk Policy
→ Candidate-set / NIL / Ambiguity Guard
→ Decision
```

### 9.1 CERTAIN_MATCH

至少满足：

```text
NO HARD_CONFLICT
AND CandidateSetState == KNOWN_CANDIDATE
AND
(
  Strong Identity Anchor
  OR
  Calibrated Matcher >= tau_segment
  + >=2 个非重复 Evidence Family 一致支持
  + Ambiguity Guard 通过
)
```

Strong Identity Anchor：高可信 full Reference / official Style Code / Manufacturer-grade MPN exact，或高可信 GTIN exact + Hard Attributes 无冲突。

`tau_segment`、`margin_segment` 按品牌/品类/来源/EvidenceProfile 独立认证，不使用 ANN raw score 或全局固定阈值。

### 9.2 Conflict Engine

Matcher 前后都执行：`HARD_CONFLICT / POSSIBLE_CONFLICT / NO_CONFLICT`。品牌不同；官方 36mm vs 41mm；Mini vs Medium；官方材质/颜色/五金冲突等属于典型 Hard。Validated GTIN 不同默认 Possible，只有品牌规则证明 1:1 才 Hard。任何模型高分都不能覆盖 Hard Conflict。

### 9.3 UNKNOWN Reason Code

至少包括：

```text
UNKNOWN_AMBIGUOUS
```

## 10. Entity Linking、Discovery 与 Canonical Health

### 10.1 Linking

```text
Source Snapshot
→ Route Policy / Filter Safety
→ Hybrid Retrieval
→ Pair / Conflict / Calibration
→ CandidateSetAssessment
→ CERTAIN_MATCH or reason-coded UNKNOWN
→ Recognition Commit Barrier（仅 CERTAIN_MATCH）
→ Current Source→Canonical Link + Immutable Recognition
→ Pending Review
```

最终身份判断与业务写入分层：推理结果只是待提交 Decision，不等于业务状态已经生效。

### 10.2 Discovery 与 Canonical Novelty / Uniqueness Gate

```text
POSSIBLE_NIL
→ Route/Filter Recovery
→ Official/Web Evidence
→ Strict Blocking
→ High-confidence Pair Edges
→ Constraint-aware Clustering
→ PROPOSED Canonical
→ Canonical Novelty / Uniqueness Gate（必须包含 bypass route）
→ ACTIVE or remain PROPOSED
```

`POSSIBLE_NIL` 只表示没有安全链接到已有 Canonical，不等于已经证明是新品。

任何 `PROPOSED → ACTIVE` 必须生成 `canonical_novelty_assessment`，在当前 pinned publication 上对 ACTIVE、PROPOSED、MERGED historical aliases、official external variant ids、governed Manufacturer IDs 做高召回去重。

Novelty 状态：`UNIQUE / DUPLICATE_SUSPECT / AMBIGUOUS_EXISTING / CONFLICTING_EXISTING / RETRIEVAL_UNHEALTHY`。只有 `UNIQUE` 可自动激活。无强 ID 且与已有 Canonical 高度近似、又缺少可区分 Hard Attribute 时保持 PROPOSED。

为防并发 Discovery 创建同一新品，对 variant-unique Manufacturer Identifier / official external Variant ID 建 `canonical_identity_claim` 唯一所有权；无强 ID Proposal 激活前必须在同一事务/锁语境重新执行 novelty check。

### 10.3 传递冲突

禁止 `Connected Component = Canonical Variant`。使用 `Union-Find / Cluster Graph + Cannot-Link + Cluster Signature + Anchor Validation`。合并前检查 cannot-link、Hard Attributes、时间版本、来源互斥、anchor；有冲突立即阻断 A=B、B=C 推导 A=C。

### 10.4 ACTIVE Cluster Health / Split Repair

ACTIVE Canonical 持续做周期性与事件驱动一致性检查：

```text
high_trust_hard_conflict_count
cannot_link_inside_cluster_count
manufacturer_identifier_partition_count
variant_attribute_mode_count
review_disagreement_rate
new_evidence_conflict_rate
temporal_generation_conflict
cluster_partition_score(optional)
```

治理级 Hard Conflict、不可兼容 Manufacturer ID 分区、confirmed cannot-link 穿过 cluster 时，立即 `SPLIT_PENDING` 并停止新 Auto-Match。GNN/graph classifier 只能检测/排序 repair candidate，不得直接修改 Canonical。

确认 Split 后：创建 N 个新 Canonical；所有 Source Product 从 ORIGINAL OBSERVED Evidence 重新解析；旧 Recognition 保留并由 superseding/invalidation event 更新 current pointer；跨 child Alias/Identifier 降级；旧 pseudo positive/训练 artifact 沿 lineage taint；repair 通过原子 publication 发布；旧 Canonical=`SPLIT`。

### 10.5 Duplicate Canonical / Merge Repair

系统同时防 under-merge：同一 Official Variant 被建成多个 Canonical。

Identity-critical collision（governed Manufacturer ID、official external Variant ID、variant-unique GTIN、reviewed SAME_VARIANT bridge）→ `MERGE_PENDING` 并冻结新挂接；Image/Text 高相似只生成治理候选。治理确认后选择唯一 survivor，旧 Canonical=`MERGED`；Alias/Identifier、冲突标签重新验证；所有状态与 Search tombstone/redirect 在同一 repair publication 生效。

## 13. Review、风险认证与 Reviewer Quality

### 13.1 三轨 Review

```text
TRAINING_REVIEW      Active Learning / Hard Negative / LIKELY / UNKNOWN / rare slices
CERTIFICATION_AUDIT 从真实最终 Recognition Decision 流概率抽样
GOVERNANCE_REVIEW   PROPOSED/Novelty/Merge/Split/Web/Identifier/主档治理
```

风险认证单位是最终 Recognition Decision，不是 candidate pair。Certification 样本记录 `inclusion_probability / stratum_key`；全局风险按真实生产流量权重汇总。Active Learning/Hard Negative 只能用于训练和诊断。

### 13.2 Calibration 与 Cluster-aware Certification

- 调参集与最终认证集分离。
- Record-level Auto-Match 计算单侧二项风险上界作为 i.i.d. sanity bound，但原始审核条数不等于有效独立样本数。
- 审计 dependency keys 至少保存 source/feed、Canonical、parser/extractor/identifier policy、model/calibrator/route、publication、ingestion batch/time bucket。
- 维护版本化 `audit_cluster_policy`，预先声明 source/feed、canonical、model+parser+policy、publication/time 等 cluster definitions。
- 正式报告给出 design-weighted error、i.i.d. upper bound、cluster-aware upper bound、`n_raw / n_distinct_clusters / design_effect / effective_sample_size`。
- Release 使用预先声明定义中的最保守上界；相关性信息不足则 `CERTIFICATION_INSUFFICIENT`。
- 任一确认 False Merge 都按 dependency keys 展开 sibling scan；系统性问题先 kill-switch/UNKNOWN，再修复与重认证。

```text
release_risk_upper_bound = max(
  iid_record_upper_bound,
  cluster_aware_upper_bounds,
  critical_slice_upper_bounds
)
```

### 13.3 Certification Label Quality

正式 `CERTIFICATION_AUDIT` 默认双人独立盲审，首轮不展示模型 score、Teacher/VLM 建议或另一 reviewer 标签。

标签：`SAME_VARIANT / DIFFERENT_VARIANT / INSUFFICIENT_EVIDENCE / SOURCE_DATA_ERROR`。分歧进入高级 reviewer/专家 adjudication；仍无法裁决的 `AUDIT_UNRESOLVED` 按潜在 false merge 保守处理或关闭对应 slice。

Reviewer 维护 brand/category qualification，定期插入 hidden control items。Guideline、UI、Evidence Snapshot、Qualification 全部版本化。Certification set 不参与同一版本调参。

## 15. Incremental、CDC、Catalog Publication 与 Recognition Commit

### 15.1 Catalog → Search Publication Barrier

历史初始化：

```text
Raw Import
→ Normalize / Extract / QC
→ Barcode/OCR
→ EvidenceProfile / Router
→ Batch Text/Image Embedding
→ Build Versioned OpenSearch Generation
→ Publication Parity Validation
→ Atomic Alias Publish
→ Linking / Recognition
```

增量 Canonical mutation：

```text
DB Transaction: mutation + catalog_outbox_event
→ CDC / Outbox Relay
→ Idempotent Projection Consumer
→ External-versioned OpenSearch Upsert/Tombstone
→ Refresh Visibility + Search Checkpoint
→ Advance Catalog Publication Watermark
```

Canonical/Alias/Identifier promotion、撤销、RETIRED/MERGED/SPLIT_PENDING/SPLIT/MERGE_PENDING/TAINTED 与 outbox event 在同一 DB transaction 提交。Indexer 用 `event_id` 幂等去重，用数据库单调 `mutation_version` 做 OpenSearch external version。删除/撤销生成 tombstone。

Auto-Match 请求入口 pin `ACTIVE publication_id`。Search hit 进入 Pair/Conflict 前校验 pinned publication；修复/撤销状态即使被旧索引召回，也必须在 Identity Gate 丢弃。

`search_apply_checkpoint < publication.mutation_watermark`、refresh 未确认、projection parity 失败、混合 publication → `UNKNOWN_PUBLICATION_INCONSISTENT`。

### 15.2 Recognition Commit Barrier

推理、OCR、检索、Rerank 不持有数据库长事务。在线链路先在事务外形成不可变 `RecognitionDecisionSnapshot`，绑定 idempotency key、Source Version、candidate Canonical/version、publication、模型/策略/route/routing 与 decision fingerprint。

只有 `CERTAIN_MATCH` 进入短 ACID transaction：

```text
BEGIN
  Insert/lookup recognition_commit_intent(idempotency_key)
  Lock/CAS source_product current row
  Validate source_version/content_hash/recognition_epoch unchanged
  Validate target Canonical still linkable under authoritative state/publication
  Ensure no conflicting current Source→Canonical link
  Insert immutable recognition_record
  Upsert current source_canonical_link
  Update source_product recognition state/current_recognition_id
  Insert exactly one Pending Review task or recognition_outbox_event
COMMIT
```

相同 key + 相同 intent 返回第一次结果；相同 key + 不同语义参数拒绝。Source 变化 → `UNKNOWN_STALE_SOURCE_VERSION`；目标 Canonical 冻结/修复/撤销或 publication 不一致 → 不提交。跨系统副作用用 Outbox + idempotent consumer。

Source 内容更新生成新的 `source_version / recognition_epoch`，旧 Recognition 保留历史，current state 转 `REPROCESS_REQUIRED`。Review Reject/Correction、Split/Merge/Reprocess 通过 superseding/invalidation event 改 current pointer，不原地修改历史 Recognition。

## 16. Production Runtime Reliability

### 16.1 Fail-closed

Route Policy 定义 mandatory/optional stage。任一 mandatory stage 被跳过、timeout、熔断都会改变 `route_execution_signature`；未经该 degraded route 独立 benchmark + risk certification，不允许 CERTAIN_MATCH，只能 UNKNOWN 或异步重试。

### 16.2 Deadline / Retry / Queue / Circuit Breaker

- 每条请求入口生成绝对 deadline 并沿 OpenSearch、Reranker、OCR、GPU/VLM 传播。
- Expensive stage 开始前检查剩余预算；mandatory stage 无法完成 → `UNKNOWN_DEPENDENCY_FAILURE`。
- 每个依赖只有一个 retry owner；只重试 transient error；指数退避+jitter+max attempts+retry budget，受原 deadline 约束。
- OpenSearch、Reranker、OCR、GPU/VLM、Web Agent 分别配置 `max_inflight / max_pending / queue_deadline / circuit threshold / half-open budget`。
- 队列有界；没有足够 deadline 的请求直接 shed/UNKNOWN。

### 16.3 Load Shedding

```text
P0 Strong Identifier 在线 Linking
P1 普通 Hybrid Linking
P2 Near-tie Local Visual / Difficult Pair
P3 Route-bypass / Entity Discovery / Web Evidence / Novelty Scan
P4 历史 backfill / re-embedding / periodic Canonical dedupe/repair scan
```

过载优先停止 P4→P3→P2。未认证简化 route 只能降低 Coverage，不能降低 Identity Safety。Route-bypass 若因过载无法执行，则不能把原结果升级为 POSSIBLE_NIL/新品，只能 UNKNOWN。

定期故障注入：timeout、OpenSearch partial failure、GPU unavailable、queue overload、retry storm、CDC lag、重复/乱序事件、refresh lag、publication rollback、Split/Merge partial publish、Recognition commit crash/response loss/concurrent retry，以及错误 Brand/Category Router/过窄 filter 导致正例被提前删除。

## 17. 容量、成本与性能

## 20. 正式开启自动识别 Gate

全部满足才扩大 Auto-Match：

1. 主要品类/来源 `Precision@Auto-Match >= 99.9%`。
2. `Recall@100 after fusion/truncation >= 99.5%`，Exact/官方标识符 survival=100%。
3. 正式 Certification Audit 满足概率抽样 provenance、distinct dependency cluster coverage，且 `release_risk_upper_bound <= target_false_merge_risk`。
4. 所有 Hard Conflict 回归 0 自动错合并；Seen/Strict Unseen/Time-shift、Vintage、缺图、缺型号、低质图分别达标。
5. Image-only 路径不得无额外身份/结构证据产生 CERTAIN_MATCH；Synthetic/Pseudo evidence 不得成为 Hard Fact / Identity Anchor / Certification Gold。
6. AMBIGUOUS/NIL/ROUTING_AMBIGUOUS/RETRIEVAL_FAILURE/PUBLICATION_INCONSISTENT/CATALOG_REPAIR 不得绕过 Guard。
7. Product Group ID 作为 Variant Identity Anchor 违规=0；未认证 merchant SKU 作为官方 Reference 违规=0；Official Web JSON-LD/DOM 未解决冲突时自动 ACTIVE=0。
8. 所有 ACTIVE 模型/Router/Policy lineage 完整率=100%；tainted upstream 在 SLA 内触发 kill-switch/re-certification。
9. `SPLIT_PENDING / SPLIT / MERGE_PENDING / TAINTED` Canonical 新增 Auto-Match=0；Split/Merge partial publication 下 CERTAIN_MATCH=0。
10. `PROPOSED → ACTIVE` 必须有同 publication 的 `canonical_novelty_assessment` 且 `novelty_state=UNIQUE`；variant-unique ID 不得双 ACTIVE。
11. 一个 committed Recognition intent 只能产生一次业务副作用；partial commit、stale source、多 current link、duplicate review task 均为 0。
12. **Exact Identifier 被 Router/Category Filter 提前删除的违规=0。**
13. **任何模型/VLM/OCR/低可信 merchant 推断的 brand/category 单独作为 hard filter 的违规=0。**
14. **Router 非 AUTHORITATIVE 且请求将进入 NIL/Discovery 时，缺少 `route_bypass_assessment` 的违规=0。**
15. **Route-bypass 恢复出可安全链接的已有 Canonical 后仍创建 PROPOSED/ACTIVE 新主档的违规=0。**
16. **Brand/category 冲突被强制单一路由、未保留 plausible route quota 的违规=0。**
17. **Router/filter policy、taxonomy version、router model version、routing decision provenance 完整率=100%。**
18. `CERTIFICATION_INSUFFICIENT` 不得当作 PASS；任一认证 False Merge 若显示为系统性 dependency-cluster 问题，相关 slice 立即 kill-switch/UNKNOWN 并重新认证。

任何指标退化时，优先降低 Coverage，不放宽 Identity Safety，也不允许通过更激进的 brand/category hard filter 换取延迟或成本。

## 22. 最终生产原则

```text
官方知识 / 标准化 / 确定性标识
          ↓
EvidenceProfile + Router/Filter Safety
          ↓
Hybrid Retrieval + Exact Preserve
          ↓
结构化 + 文本 + 图片多证据
          ↓
Hard Conflict + Calibration
          ↓
Candidate-set / NIL / Ambiguity Guard
          ↓
Route-bypass Verification before NIL/Discovery
          ↓
Constraint-aware Graph Resolution
          ↓
CERTAIN_MATCH Decision
          ↓
Recognition Commit Barrier
          ↓
Current Link + Immutable Recognition + Pending Review
          ↓
Canonical Novelty / Health / Repair
          ↓
Independent + Cluster-aware Risk Audit
          ↓
Controlled Training + Immutable ML Lineage
```

固定原则：

1. **Identity first，Similarity second。**
2. **Hard Conflict 优先于任何模型高分。**
3. **UNKNOWN 是合法且必要的生产输出。**
4. **缺模态不能靠生成模态伪装成完整证据；Synthetic/Pseudo evidence 不能形成 Hard Fact / Identity Anchor / Certification Gold。**
5. **仅视觉相似不能自动 SAME_VARIANT；全局视觉负责召回，局部视觉只验证 near-tie。**
6. **必须显式允许 NIL；Top-1/Top-2 near-tie 必须 Abstain。**
7. **Exact Identifier 永远绕过非权威 Router，Exact 候选永不被 Soft Fusion 截断。**
8. **Brand/Category Router 是候选空间优化器，不是身份事实源；模型/VLM/OCR/低可信 merchant 分类不得单独 hard-prune。**
9. **路由不确定时使用 multi-route / ancestor / broad fallback；NIL/Discovery 前必须做 route-bypass verification。**
10. **Router semantic recall 与 Search engine filtered-ANN recall 分开评测；不能把错误 filter 当成 Catalog 不存在候选。**
11. **训练 Review 与风险 Certification 分流；正式风险用 cluster-aware 上界，不用 raw audit count 冒充 effective sample size。**
12. **Product Group ID 是关系标识，不是 Variant Identity；Merchant SKU 与 Manufacturer ID 分命名空间。**
13. **官网结构化数据是高价值 Evidence，不是无条件 Canonical Truth。**
14. **DB→Search 使用 Transactional Outbox + Idempotent Projection + Monotonic Version + Publication Barrier。**
15. **ACTIVE Canonical 不是永久真值：持续检查 over-merge 与 under-merge。**
16. **Entity Discovery 是新品证明问题；`POSSIBLE_NIL` 不能直接推出新 Canonical，任何 `PROPOSED → ACTIVE` 必须通过 Novelty/Uniqueness Gate。**
17. **Cluster Detector/Repair Classifier/Graph Partitioning 只能检测、排序、提问和生成候选，不能直接修改 Canonical。**
18. **每一个 ACTIVE 模型、Router、Taxonomy、Policy 和训练数据集都是不可变、可哈希、可追溯 Artifact。**
19. **timeout/过载/依赖故障形成的新 route 未认证时 fail closed 为 UNKNOWN。**
20. **模型的 CERTAIN_MATCH 只是待提交 Decision；只有通过 Recognition Commit Barrier 后业务关系才生效。**
21. **Recognition Commit 必须满足显式 idempotency intent、Source Version CAS、Canonical 可挂接性再验证、单一 current link、Immutable Recognition、Pending Review/Outbox 原子提交。**
22. **Source 更新、Review Reject、Split/Merge、Reprocess 通过 superseding/invalidation event 改 current pointer，不修改历史 Recognition。**
23. **任何认证 False Merge 都必须按 dependency cluster 做 sibling scan/incident triage；系统性错误先 kill-switch/UNKNOWN，再修复和重认证。**
24. **任何复杂度只有在提高 Coverage@99.9% Precision、提高事务/运行可靠性、降低 Router False-NIL、降低 Catalog fragmentation、降低治理成本或降低总成本时才有价值。**
