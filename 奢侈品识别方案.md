# 奢侈品识别方案

## 1. 目标与边界

系统目标不是“找最像的商品”，而是把雷小安、奢当家、腕表之家、小迈步、爱回收等来源的记录归一到**同一个官方商品变体（Official Variant）**。

第一阶段只覆盖：

```text
IN_SCOPE_WATCH
IN_SCOPE_BAG
```

历史数据约 100 万–1000 万条。腕表已有部分品牌/系列/型号标准库；箱包主档不完整，因此系统同时支持 **Entity Linking** 与 **Entity Discovery**。

核心原则：

> **Precision >> Recall。宁可输出 UNKNOWN / OUT_OF_SCOPE，也不能把不同官方变体错合并。**

系统不做真假鉴定。成色、价格、库存、卖家、单件序列号、保卡状态属于 Offer / 单件属性；官方维修、后换件、附属物、商家自组 Bundle、Multipack、Lot，以及业务范围外商品都不能被误当成新的腕表/箱包 Official Variant。

机器成功识别后形成一致业务结果：

```text
Source Product 当前状态
+ Source → Canonical 当前识别关系
+ Immutable Recognition Record
+ Pending Review 任务/事件
```

四个副作用必须原子、幂等、可重放。

## 2. 核心实体、关系、Source Composition 与标识符语义

Canonical 身份层级：

```text
Brand
  └── Product Family / Series
       └── Product Model
            └── Canonical Variant
```

Source 侧真实输入是：

```text
Source Offer / Listing
   └── Source Component(s)
        └── 0..1 Identity Target Component
```

Canonical 关系：

```text
SAME_VARIANT
VARIANT_OF
SAME_MODEL
SAME_SERIES
VISUALLY_SIMILAR
UNKNOWN
```

组合型 Offer 额外保存：

```text
PRIMARY_COMPONENT_VARIANT
MULTIPACK_OF_VARIANT
ACCESSORY_OF_VARIANT
CONTAINS_VARIANT
```

只有 `SAME_VARIANT` 可以进入普通 Canonical 聚类并生成默认自动 Recognition；其他关系不能伪装成 SAME_VARIANT。

Canonical Variant 状态：

```text
ACTIVE
PROPOSED
SPLIT_PENDING
MERGE_PENDING
RETIRED
MERGED
SPLIT
TAINTED
```

`MERGED` 可 redirect 到唯一 survivor；`SPLIT` 是 one-to-many，旧 Canonical 必须重新解析。

### 2.1 Identifier Namespace

统一采集：

```text
reference_full / style_code / mpn
gtin / ean / upc
merchant_sku
product_group_id / item_group_id
variant_dimension_keys / variant_dimension_values
barcode_symbology / payload / checksum
market
identifier_namespace / identifier_owner / identifier_scope
identifier_source / source_field_path / confidence
component_id / identifier_binding_scope
```

规则：

- 高可信完整 Reference / Style Code 是最强 Identity Anchor 之一。
- 官方品牌来源 `mpn` 经品牌规则校验后可作为 Manufacturer-grade Identifier。
- 第三方 merchant `sku` 默认属于 merchant namespace。
- `productGroupID / item_group_id` 是 Group 关系标识，不是 Variant Identity Anchor。
- ProductGroup / hasVariant / isVariantOf / variesBy 是 Variant Boundary Evidence。
- 高可信 GTIN/EAN/UPC：Strong Positive + Exact Retrieval Key；GTIN 冲突结合品牌/市场规则解释。
- Vintage 考虑旧编码、地区差异、包装变化和历史规则。

维护：

```text
identifier_semantics_policy:
brand × market × source_group × field_path × identifier_type × composition_state
```

声明 `MANUFACTURER_ID / MERCHANT_ID / GROUP_ID / INSTANCE_ID / UNKNOWN`，以及 Exact Retrieval、Strong Positive、Hard Conflict、Auto Activation 权限。

### 2.2 Source Composition Semantics

每个 Source Offer 生成：

```text
SINGLE_PRODUCT
SINGLE_PRIMARY_WITH_AUXILIARY
MERCHANT_DEFINED_BUNDLE
MANUFACTURER_DEFINED_SET
MERCHANT_MULTIPACK
MULTI_PRODUCT_LOT
ACCESSORY_ONLY
CONFLICTING_COMPOSITION
UNKNOWN_COMPOSITION
```

组件角色：

```text
PRIMARY_IDENTITY_TARGET
INCLUDED_AUXILIARY
MERCHANT_ADD_ON
MANUFACTURER_SET_COMPONENT
PACKAGING_OR_DOCUMENT
ACCESSORY_PRODUCT
OTHER_PRODUCT
UNKNOWN_COMPONENT
```

固定语义：

1. `SINGLE_PRODUCT`：正常一条 Source → 一个 Official Variant。
2. `SINGLE_PRIMARY_WITH_AUXILIARY`：盒、保卡、防尘袋、备用可拆件等不改变主商品 Variant。
3. `MERCHANT_DEFINED_BUNDLE`：可识别主组件，但整个 Listing 默认不产生 SAME_VARIANT Recognition。
4. `MANUFACTURER_DEFINED_SET`：只有官方 Set identifier、Catalog 边界和必要 Hard Facts 齐全时，才能成为独立 Canonical Product/Variant。
5. `MERCHANT_MULTIPACK`：数量是 Offer Composition，不是 Official Variant 属性。
6. `MULTI_PRODUCT_LOT`：没有唯一主商品时不做 SAME_VARIANT Auto-Match。
7. `ACCESSORY_ONLY`：独立配件不得挂到腕表/箱包 Canonical。
8. `CONFLICTING/UNKNOWN`：输出 `UNKNOWN_SOURCE_COMPOSITION`。

## 3. Product Scope / Product-Type Open-set Gate

第一阶段只做腕表与箱包，因此**在 Router、NIL 和 Entity Discovery 之前必须先证明输入属于当前业务 Scope**。Closed-set 分类器总会给一个已知类别最高分，不能把“最高分类分数”当成“属于腕表/箱包”的事实。

Scope Gate 对 `PRIMARY_IDENTITY_TARGET` 或官方 Manufacturer Set 实体计算：

```text
IN_SCOPE_WATCH
IN_SCOPE_BAG
IN_SCOPE_UNKNOWN_SUBTYPE
OUT_OF_SCOPE_KNOWN
OPEN_UNKNOWN
CONFLICTING_SCOPE
```

含义：

- `IN_SCOPE_WATCH / IN_SCOPE_BAG`：顶层业务类别已可靠确认。
- `IN_SCOPE_UNKNOWN_SUBTYPE`：能证明属于腕表或箱包父类，但当前 taxonomy 中没有可靠 leaf/subtype；允许在父类下继续 broad/ancestor route。
- `OUT_OF_SCOPE_KNOWN`：可确认属于当前不处理的类别，例如珠宝、鞋服、香水、眼镜、家居、非目标独立配件等；保留 Source 数据，但不做腕表/箱包 SAME_VARIANT/NIL/Discovery。
- `OPEN_UNKNOWN`：无法证明属于任何当前已知顶层业务类别。
- `CONFLICTING_SCOPE`：权威或高可信证据对顶层 Product Type 冲突。

### 3.1 Scope Evidence Hierarchy

优先级：

```text
已治理 Manufacturer Identifier → 已验证 Identifier→Product-Type Mapping
→ T0/T1 结构化 Product Type / Taxonomy
→ Source Composition + Component Role
→ 标题/结构化属性
→ Image Product-Type Evidence
→ Hierarchical Classifier / VLM fallback
```

固定规则：

1. **Exact Manufacturer-grade Identifier 命中已存在的 in-scope Canonical，本身可成为强 Scope Evidence**，但仍不能绕过 Component Binding、Composition、Hard Conflict 和权威冲突。
2. 只有 T0/T1、已治理 Identifier Mapping、或经过历史认证的结构化 Product-Type 字段可直接形成权威 `IN_SCOPE_* / OUT_OF_SCOPE_KNOWN`。
3. 模型分类、Embedding nearest category、VLM/OCR 猜测、低可信 merchant category 只能输出候选 Scope 或 `OPEN_UNKNOWN`，默认不能单独把未知商品硬塞进 watch/bag。
4. 不稳定 leaf 不等于 out-of-scope：如果父类可靠属于腕表/箱包，使用 `IN_SCOPE_UNKNOWN_SUBTYPE + ANCESTOR_ROUTE`。
5. 顶层 Scope 冲突不做分数平均；输出 `CONFLICTING_SCOPE`，补证据或治理。
6. `OUT_OF_SCOPE_KNOWN / OPEN_UNKNOWN / CONFLICTING_SCOPE` 不进入当前阶段 `POSSIBLE_NIL → New Canonical Discovery`。
7. Scope Gate 与 Category Router 分开版本化：Scope 决定“是否属于当前系统”，Router 决定“在已确认 Scope 内去哪里检索”。

### 3.2 Open-set / OOD Model Policy

Open-set/OOD 模型只作为 Scope Evidence 的一层，不能取代确定性规则。

- 不使用 closed-set softmax Top-1 直接判断 in-scope。
- 不把 AUROC 高视为可直接上线；阈值必须在独立 holdout 上选择，并在 source/time-shift 上重新验证。
- 不设一个全局固定 OOD threshold；至少按 input modality、source/domain 和 scope policy version 认证。
- 可将 Amazon ANS/ODIST 类 open-world 方法作为文本 OOD challenger；多模态 Scope challenger 只有在邻近奢侈品类别挑战集上证明降低 false-in-scope 才上线。
- 模型输出必须允许 abstain。

## 4. 标准 Schema 与 Hard Constraint

每个属性断言保存：

```text

extractor / extractor_version

extraction_confidence
validation_status / validation_confidence / validation_record_id
fact_scope
effective_from / effective_to / observed_at
market_scope / region_scope
```

**Extraction Confidence ≠ Validation Confidence；Validated Observation ≠ Official Variant Spec。** Hard/Strong 默认指 `OFFICIAL_VARIANT_SPEC`，并绑定正确 Source Component。

## 5. Evidence、来源独立性、事实状态与时间版本

来源等级：T0 品牌官方；T1 已验证标准库/授权专业库；T2 高质量专业/二手平台；T3 普通电商/聚合/搜索。

可信度按“来源 × 属性 × 市场/时间 × Component”定义。

### 5.1 来源独立性

维护 `source_group_id / syndication_group_id / content_fingerprint / image_hash_group_id / upstream_hint`。复制 feed、重复图、相同异常文案不能增加独立来源数。

### 5.2 Evidence Family

```text
IDENTIFIER / STRUCTURED_ATTR / VARIANT_GRAPH
LEXICAL_TEXT / SEMANTIC_TEXT / IMAGE_VISUAL
OCR_TEXT / EXTERNAL_WEB / TEMPORAL / PRODUCT_SCOPE
```

同一原始观测派生的多个分数不是多票；不同组件证据也不能机械相加支持同一 Identity Target。

### 5.3 Fact Promotion Barrier

```text
OBSERVED / DERIVED / REVIEWED_GOLD / GOVERNED_FACT / APPROVED_ALIAS / TAINTED
```

Recognition、Matcher 分数、Cluster membership、模型抽取和 pseudo-label 都是 DERIVED；未经治理不得进入 Exact Identity、Canonical Hard Fact 或 Gold Training Set。

### 5.4 时间版本

Canonical 属性保存 `valid_from / valid_to / version / evidence_ids`。没有明确代际证据时不跨年代自动合并。

### 5.5 Canonical Attribute Fact Arbitration

仲裁主键：

```text
canonical_variant_id × attribute_id × market_scope × valid_time_scope × variant_generation
```

属性语义：`SINGLE_VALUE / SET_VALUE / ORDERED_MULTI / RANGE`，并定义 `identity_role / normalization_level / regional/temporal variation / comparison_policy`。

Resolution：`RESOLVED / MULTI_VALID / CONFLICTED / UNKNOWN / STALE`。

规则：

- 不 latest-write-wins，不简单 majority vote。
- syndicated/复制来源先去重。
- Authority 按字段、品牌、市场、有效期和字段语义定义。
- 同 scope 治理级 Hard Attribute 冲突 → `CONFLICTED`，停止依赖该字段 Auto-Match。
- 低可信 OCR/VLM/普通平台不能覆盖治理级 T0/T1。
- 缺失不是反证；多值按属性语义比较。
- 上游撤回/TAINT → `STALE` 并重仲裁。
- Arbitration 只消费 `OFFICIAL_VARIANT_SPEC` 且通过 Validation/Promotion Gate 的断言。
- Search/Matching/Conflict 只消费已发布的 `RESOLVED/MULTI_VALID` Current Fact。

## 6. Source Composition、Scope、属性抽取、Validation、OCR 与 VLM

完整前处理：

```text
Raw Source Offer
→ Schema Mapping
→ Source Composition Detection
→ Source Component / Evidence Binding
→ Product Scope Open-set Gate
→ Deterministic Parsing / Dictionary
→ Barcode Decode
→ Text Attribute Extraction
→ Scene OCR
→ Document-like OCR/VLM（按需）
→ General VLM Fallback（少量）
→ Normalization / Ontology
→ Attribute Validation
→ Attribute Assertion
→ Item-State / Origin Classification
→ Canonical Arbitration（仅 Official-Spec）
```

### 6.1 Source Composition Gate

优先证据：平台结构化字段 → Identifier 语义 → 标题/描述组件分段 → 图片/region membership → 规则/VLM fallback。

固定规则：

1. Listing 级文本、图片和属性不能在 Composition 未确定前直接生成商品级 Identity Embedding。
2. Identity Evidence 必须绑定 `PRIMARY_IDENTITY_TARGET` 或官方 Set；add-on/accessory/other product 不能污染主商品 Hard/Text/Image/Reranker。
3. 商家 Bundle 主商品 GTIN/MPN 只能证明主组件候选，不能证明整个 Listing=SAME_VARIANT。
4. Manufacturer-defined Set Identifier 绑定 Set 自身。
5. Multipack 数量是 Offer Composition。
6. `is_bundle/multipack` 缺失不能证明 `SINGLE_PRODUCT`。
7. 主商品无法唯一确定 → `UNKNOWN_SOURCE_COMPOSITION`。
8. Bundle/Lot/Composition 不确定不得进入 Entity Discovery。
9. Composition Policy、detector、component binding 全部版本化。

### 6.2 Barcode / OCR

使用 zxing-cpp 等确定性 decoder；条码/Reference OCR 还必须完成 `component_binding_scope`。证件、拼图、配件上的 Identifier 不能自动绑定到主商品。

### 6.3 General VLM

PoC 困难样本结构化抽取基线：Qwen3.5-4B。只能产出候选 Evidence/Scope/Composition/Component 提示，无权直接写 Canonical、Current Fact、Scope Truth、Composition Truth 或 CERTAIN_MATCH。

### 6.4 Attribute Validation Gate

状态：

```text
VALIDATED_VALID / VALIDATED_INVALID / UNVERIFIED / NOT_APPLICABLE / SOURCE_CONFLICT
```

Validation 保存 source/version、attribute/value、product type/taxonomy、component id、validator/version、independent evidence、market/time/generation、circular-dependency check。

分层：L0 deterministic → L1 applicability/cross-field → L2 text/profile → L3 cross-source/official → L4 multimodal → L5 LLM/VLM fallback。所有层允许 abstain。

Hard Attribute 只有 `VALIDATED_VALID` 且来源/Validator policy 已认证才可进入身份链路。

### 6.5 Official Variant Spec vs Observed Item State

可变化组件断言增加：

```text
fact_scope = OFFICIAL_VARIANT_SPEC / OBSERVED_ITEM_STATE
component_origin = FACTORY_CONFIG / AUTHORIZED_SERVICE_REPLACEMENT / AFTERMARKET_OR_MODIFIED / UNKNOWN_ORIGIN
replaceability_class = IDENTITY_STABLE / SERVICE_REPLACEABLE / USER_REPLACEABLE / COSMETIC_OR_CONSUMABLE / UNKNOWN
```

规则：

- Canonical 只描述 Official Variant Spec。
- VALIDATED_VALID 只证明观察值正确，不证明 Factory Config。
- 官方售后替换件仍是 post-sale item state，不重写 Canonical。
- SERVICE/USER replaceable 字段与 Canonical 不一致默认是 Item-State Divergence，不是 Hard Conflict。
- Strong Identifier 已锁定 Variant 时，可解释换件不得覆盖 Anchor。
- 无 Strong Anchor 且关键组件 Origin 不明/疑似更换时输出 UNKNOWN。
- 后换/维修/改装不触发新 Canonical。

输出分离：`variant_identity_decision` 与 `item_configuration_assessment`。

## 7. EvidenceProfile、Scope、Router、Composition 与缺模态 Route Policy

每条 Source Offer 计算：

```text
identifier_quality / text_quality / image_quality
hard_attr_coverage / conflict_state / catalog_mode
composition_state / composition_confidence / main_component_id
product_scope_state / product_scope_confidence / scope_evidence_level
brand_route_state / category_route_state / routing_scope
image_set_state
item_state_assessment
```

执行顺序：

```text
Composition → Component Binding → Product Scope → Router → Retrieval
```

### 7.1 Router / Filter Safety

Router 是**已确认 in-scope 后**的候选空间优化器，不是身份事实源，也不是 Scope 判定器。

```text
HARD_FILTER / MULTI_ROUTE / ANCESTOR_ROUTE / BROAD_FALLBACK
```

Exact Identifier 永远绕过非权威 Router；模型/VLM/OCR/merchant 分类不得单独 hard-prune。

### 7.2 Scope-aware Route

- `IN_SCOPE_WATCH / IN_SCOPE_BAG`：进入普通 Linking。
- `IN_SCOPE_UNKNOWN_SUBTYPE`：保留在已知父类，走 ancestor/multi-route/broad retrieval；不强迫预测具体 leaf。
- `OUT_OF_SCOPE_KNOWN`：停止腕表/箱包 Linking 和 Discovery；可保留到未来品类扩展队列。
- `OPEN_UNKNOWN / CONFLICTING_SCOPE`：输出 `UNKNOWN_PRODUCT_SCOPE`，不得解释为 NIL。

### 7.3 Composition-aware Route

- `SINGLE_PRODUCT`：普通 Linking。
- `SINGLE_PRIMARY_WITH_AUXILIARY`：只对 primary component Linking。
- `MERCHANT_DEFINED_BUNDLE`：默认 relation=`PRIMARY_COMPONENT_VARIANT`，不生成 SAME_VARIANT Recognition。
- `MANUFACTURER_DEFINED_SET`：仅官方 Set identity 已治理时走 Set Canonical。
- `MERCHANT_MULTIPACK`：relation=`MULTIPACK_OF_VARIANT`。
- `MULTI_PRODUCT_LOT / ACCESSORY_ONLY / UNKNOWN/CONFLICTING`：不做腕表/箱包 SAME_VARIANT Auto-Match。

## 8. Candidate Retrieval、Fusion 与 Open-world Guard

召回：Exact Identifier、Brand+Model、Brand+Series+Hard Attr、BM25、Text ANN、Image ANN/hash、Historical Alias、Discovery Neighbor。

PoC 初始 K：Exact≤20、BM25 30、Text ANN 50、Image ANN 每图30/总≤60、Attribute 30；union≤150，Cheap Rerank≈30，Expensive Matcher 10–20。

Gate：

```text
Recall@100 >= 99.5%
Exact survival = 100%
scope_in_scope_recall / scope_false_in_scope_rate 单独监控
Router pre/post-filter recall 单独监控
```

### 8.1 Component/Scope-aware Retrieval

- Query text 只由主 Identity Component 证据生成。
- out-of-scope/unknown Scope 不进入 watch/bag ANN/BM25 identity retrieval，除非走显式 Scope Recheck。
- Exact Manufacturer Identifier 命中 in-scope Canonical 可作为 Scope Recheck 强证据。
- Bundle/add-on/accessory 属性不进入主商品 hard filter。
- Image ANN 只使用同时通过 Composition、Scope 和 Image Gate 的图/region。
- Exact 候选永不被 Soft Fusion 截断；RRF 为零/少标签 baseline。

### 8.2 NIL / Scope / Route Recovery

CandidateSet：

```text
KNOWN_CANDIDATE
AMBIGUOUS_KNOWN
POSSIBLE_NIL
RETRIEVAL_FAILURE
ROUTING_AMBIGUOUS
```

进入 NIL/Discovery 前必须完成：

```text
Scope Gate
+ Router bypass（必要时）
+ Composition Gate
+ Item-State Divergence Check
```

只有 `IN_SCOPE_WATCH / IN_SCOPE_BAG / IN_SCOPE_UNKNOWN_SUBTYPE` 才能进入 `POSSIBLE_NIL`。

以下状态不得被解释成新品：

```text
OUT_OF_SCOPE_KNOWN
OPEN_UNKNOWN
CONFLICTING_SCOPE
UNKNOWN_SOURCE_COMPOSITION
MULTI_PRODUCT_LOT
ACCESSORY_ONLY
```

## 9. Embedding、Visual Search 与 Image Set Safety

Text：Qwen3-Embedding-0.6B；Text Reranker：Qwen3-Reranker-0.6B。

Image：SigLIP2 baseline；DINOv3 challenger（Legal Gate）；Qwen3-VL Embedding/Reranker 只在困难路径验证收益。

近邻 Variant 使用局部 patch/local descriptor shortlist rerank；局部视觉仍非 Identity Anchor。

### 9.1 Image Set Identity / Utility Gate

图片角色：

```text
PRODUCT_PRIMARY / PRODUCT_DETAIL / MODEL_LIFESTYLE
PACKAGING_OR_DOCUMENT / COLLAGE / ACCESSORY_OR_AFTERMARKET
DECORATIVE / OTHER_PRODUCT_SUSPECT / UNKNOWN
```

规则：raw image set 不直接 max；拼图 region 化；CROSS_VARIANT_REUSE 不做 Positive；文档图不进外观 ANN；Bundle 全景图仅在主组件 region 可稳定分离时进入主商品 Identity；多图仍属于同一 IMAGE_VISUAL Family。

## 10. Pair Matcher、Conflict Engine 与 Decision Policy

```text
Candidate Pair
→ Pre-Conflict
→ Deterministic Features
→ Structured/Text Matcher
→ Multimodal Difficult Pair
→ Local Visual（near-tie）
→ Post-Conflict
→ Calibration
→ Evidence-Family Risk Policy
→ Candidate/NIL/Ambiguity/Scope/Composition Guard
→ Decision
```

`CERTAIN_MATCH` 至少满足：

```text
NO HARD_CONFLICT
```

## 11. Entity Linking、Discovery 与 Canonical Health

### 11.1 Linking

```text
Source Snapshot
→ Composition + Component Binding
→ Product Scope Gate
→ Router / Validation / Image / Item-State Gate
→ Hybrid Retrieval
→ Pair / Conflict / Calibration
→ CandidateSetAssessment
→ SAME_VARIANT CERTAIN_MATCH
→ Recognition Commit Barrier
```

Bundle/Multipack 主商品识别结果可写独立 Composition Relation，但默认不写 SAME_VARIANT Recognition。

### 11.2 Discovery / Novelty

```text
POSSIBLE_NIL
→ Scope Recheck + Route Recovery
→ Composition/Item-State Recheck
→ Official/Web Evidence
→ Strict Blocking
→ Constraint-aware Clustering
→ PROPOSED
→ Novelty/Uniqueness + Required Hard Facts
→ ACTIVE or remain PROPOSED
```

Discovery 前置不变量：

```text
product_scope_state ∈ {IN_SCOPE_WATCH, IN_SCOPE_BAG, IN_SCOPE_UNKNOWN_SUBTYPE}
```

以下输入禁止直接生成新 Official Variant：

- `OUT_OF_SCOPE_KNOWN / OPEN_UNKNOWN / CONFLICTING_SCOPE`。
- Merchant Bundle / Multipack / Multi-product Lot / Accessory-only。
- Observed Item State / Service Replacement / Aftermarket Modification。

Manufacturer-defined Set 只有官方 Set identifier/catalog 证明其本身是制造商产品实体且属于当前 Scope 时，才能进入独立 Canonical Discovery。

任何 `PROPOSED → ACTIVE` 必须通过当前 publication 的 Novelty/Uniqueness Gate。Variant-unique Manufacturer ID / official external Variant ID 使用唯一 identity claim 防并发双 ACTIVE。

### 11.3 ACTIVE Canonical Health / Split / Merge

周期性/事件驱动检查 Hard Conflict、cannot-link、Manufacturer ID partitions、Fact Conflict、review disagreement、temporal generation。治理级冲突立即 freeze。

GNN/GraphCR/SuperPart 等只能 Detect/Prioritize/Propose；Split/Merge 需 Governance + 原子 Publication。Merge 时重新 Validation/Arbitration。

## 16. Incremental、CDC、Publication 与 Recognition Commit

Canonical/Attribute Resolution mutation 与 catalog outbox 同事务；幂等 Search 投影使用 external version，refresh/checkpoint 后推进 publication watermark。

Auto-Match 请求 pin `ACTIVE publication_id`。

Source 文本、图片、结构化 category/bundle/component 字段变化都会生成新 `source_version`；影响 Composition、Scope、Component Binding、Item-State、Image eligibility 或 Hard Assertion 时旧 Decision Snapshot 失效。

Recognition Commit：推理阶段不持长事务，CERTAIN_MATCH 进入短 ACID：

```text
idempotency intent
→ Source CAS
→ validate Source / Composition / Scope / Canonical / publication / fact versions
→ ensure single current link
→ immutable Recognition
→ current link
→ Source state
→ one Review/outbox
```

如果推理后 `source_scope_assessment` 变化，或 Scope 从 in-scope 变为 out-of-scope/unknown/conflicting，则不提交旧 SAME_VARIANT Decision，返回 stale/reprocess。

## 17. Production Runtime Reliability

mandatory stage timeout/熔断/跳过会形成新 route signature；未经单独认证只能 UNKNOWN。

每请求 end-to-end deadline；依赖唯一 retry owner；指数退避+jitter+retry budget；bounded queue+circuit breaker。

Load shedding：P4 backfill/bulk validation → P3 Discovery/Web/Scope/Composition enrichment → P2 near-tie expensive → P1/P0 Linking。

**Scope Gate 是 identity-critical mandatory stage 时，不得因过载直接假定 IN_SCOPE_WATCH/IN_SCOPE_BAG。**

## 21. 正式开启自动识别 Gate

全部满足才扩大 Auto-Match：

1. `Precision@Auto-Match >= 99.9%`，`Recall@100 >= 99.5%`，Exact survival=100%。
2. Certification Audit 满足 sampling provenance 与 cluster-aware risk upper bound。
3. Hard Conflict、Seen/Unseen/Time-shift/Vintage/缺图/缺型号/低质图达标。
4. Synthetic/Pseudo evidence 不形成 Hard Fact/Identity Anchor/Certification Gold。
5. AMBIGUOUS/NIL/ROUTING_AMBIGUOUS/PRODUCT_SCOPE/SOURCE_COMPOSITION/RETRIEVAL_FAILURE/PUBLICATION/CATALOG_REPAIR/FACT_CONFLICT 不得绕过 Guard。
6. Product Group ID、merchant SKU、Web structured-data 语义违规=0。
7. ACTIVE 模型/Scope Gate/Router/Composition Gate/Image Gate/Attribute Validator/Item-State Policy lineage=100%。
8. SPLIT/MERGE/TAINT 状态新 Auto-Match=0；repair partial publication CERTAIN_MATCH=0。
9. PROPOSED→ACTIVE 必须 novelty=UNIQUE，required Hard Facts 可服务。
10. Recognition Commit duplicate/partial/stale/multiple-current-link=0。
11. Router 非权威 hard prune / false NIL / false new canonical=0。
12. Identity/Search/Hard Conflict 只消费已发布 Canonical Resolution。
13. Hard Attribute UNVERIFIED/INVALID/SOURCE_CONFLICT 参与身份链路=0。
14. Image Gate/shared-image/collage 违规=0。
15. OBSERVED_ITEM_STATE/Service/Aftermarket 被当 Factory Spec=0。
16. Composition 未完成却假定 SINGLE_PRODUCT 并 Auto-Match=0。
17. Merchant Bundle / Multipack / Lot / Accessory-only SAME_VARIANT 违规=0。
18. Bundle accessory/add-on Evidence 污染主商品身份链路=0。
19. Manufacturer-defined Set Identifier 被误解释为单主组件 Identifier=0。
20. Bundle/Lot/Composition UNKNOWN 进入新品 Discovery=0。
21. **`OUT_OF_SCOPE_KNOWN` 进入腕表/箱包 SAME_VARIANT Auto-Match=0。**
22. **`OUT_OF_SCOPE_KNOWN / OPEN_UNKNOWN / CONFLICTING_SCOPE` 被作为 POSSIBLE_NIL 进入新品 Discovery=0。**
23. **closed-set classifier Top-1 被直接提升为 Product Scope Truth 的违规=0。**
24. **真实 in-scope、taxonomy leaf 未知的商品被错误判成 OUT_OF_SCOPE，而不是 `IN_SCOPE_UNKNOWN_SUBTYPE` 的关键 slice 必须单独达标。**
25. **Scope OOD/open-set threshold 只能由独立 holdout/时间窗选择；同一 certification set 调 threshold 的违规=0。**
26. **Scope/Composition/Component Binding policy、Gold、model/version provenance 完整率=100%；Source scope/composition 变化后旧 Decision Snapshot 不得提交。**

指标退化时优先降低 Coverage，不通过“默认是腕表/箱包”“默认单商品”或强制 closed-set Top-1 来保吞吐/召回。

固定原则：

1. **Identity first，Similarity second。**
2. **Source Offer ≠ 必然一个商品；先判 Composition，再做 Variant Identity。**
3. **第一阶段业务 Scope 只有腕表与箱包；Scope 未证明前不能把任何 Source 强制吸进这两个类别。**
4. **Closed-set Top-1 不是 Product Scope Truth；未知类必须允许 OUT_OF_SCOPE / OPEN_UNKNOWN / CONFLICTING。**
5. **已知父类下的新 subtype 可留在 `IN_SCOPE_UNKNOWN_SUBTYPE`，不强制 leaf，也不误判 out-of-scope。**
6. **Out-of-scope / Open-unknown 不是 NIL；不得借“没匹配到”进入腕表/箱包新品 Discovery。**
7. **Merchant Bundle / Multipack / Lot 的组合关系不能伪装成 SAME_VARIANT。**
8. **商家 Bundle 主商品 Identifier 可定位主组件，但不能证明整个 Listing 等于主商品 Variant。**
9. **制造商官方 Set 与商家自组 Bundle 分开；前者可能有独立官方身份。**
10. **附件、配件、其他商品的 Evidence 与主商品 Identity Evidence 隔离。**
11. **Composition 不确定是合法 UNKNOWN；不得默认 SINGLE_PRODUCT。**
12. **Extraction confidence ≠ fact correctness；Validated Observation ≠ Official Variant Spec。**
13. **Canonical 只保存 Official Variant Spec；二手当前组件进入 Item-State 层。**
14. **官方维修替换件不自动成为 Factory Config。**
15. **Hard Conflict 只建立在经过 Validation、正确 Fact Scope、正确 Component Binding 的证据上。**
16. **Synthetic/Pseudo evidence 不能形成 Hard Fact / Identity Anchor / Certification Gold。**
17. **多张图片不是多份独立身份票；先做 component membership 与 utility。**
18. **仅视觉相似不能自动 SAME_VARIANT。**
19. **必须显式允许 NIL；near-tie 必须 Abstain。**
20. **Exact Identifier 绕过非权威 Router，但不能绕过 Scope、Component 与 Composition Semantics。**
21. **Router 只负责已确认 in-scope 后的候选空间优化；Scope Gate 决定是否进入当前系统。**
22. **训练 Review、Scope Gold、Composition Gold、Image Gold、Attribute Gold、Item-State Gold、Risk Certification 是不同资产。**
23. **Product Group ID 是关系标识，不是 Variant Identity；Merchant SKU 与 Manufacturer ID 分命名空间。**
24. **Canonical Current Fact 是已验证 Official-Spec Assertions 的版本化 Arbitration，不是最近值/多数票。**
25. **Search/Hard Conflict 只消费已验证、已仲裁、已发布的 Current Fact。**
26. **DB→Search 使用 Transactional Outbox + Idempotent Projection + Monotonic Version + Publication Barrier。**
27. **ACTIVE Canonical 持续检查 over-merge、under-merge、Fact Conflict。**
28. **Entity Discovery 是新品证明问题，不是“没匹配上”的同义词。**
29. **Cluster Repair Model 只能 Detect/Prioritize/Propose，不能直接修改 Canonical。**
30. **所有模型、Scope Gate、Router、Composition Gate、Image Gate、Attribute Validator、Item-State Policy 和数据集都不可变、可追溯。**
31. **依赖故障或 mandatory gate 缺失时 fail closed 为 UNKNOWN。**
32. **模型 CERTAIN_MATCH 只是待提交 Decision；Recognition Commit 后业务关系才生效。**
33. **任何复杂度只有在提高 Coverage@99.9% Precision、降低 False Merge/False Novel/False In-Scope/Composition Leakage、提高事务可靠性或降低总成本时才有价值。**
