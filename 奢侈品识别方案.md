# 奢侈品识别方案

## 1. 目标与边界

系统目标不是“找最像的商品”，而是把雷小安、奢当家、腕表之家、小迈步、爱回收等来源的记录归一到**同一个官方商品变体（Official Variant）**。

第一阶段覆盖腕表与箱包，历史数据约 100 万–1000 万条。腕表已有部分品牌/系列/型号标准库；箱包主档不完整，因此系统必须同时支持 **Entity Linking** 与 **Entity Discovery**。

核心原则：

> **Precision >> Recall。宁可输出 UNKNOWN，也不能把不同官方变体错合并。**

只有定义官方变体的关键属性兼容时，才允许自动认定 `SAME_VARIANT`。系统不做真假鉴定；成色、价格、库存、卖家、单件序列号、保卡状态等属于 Offer / 单件属性，不定义官方商品变体。

机器成功识别后必须形成一致业务结果：

```text
Source Product 当前状态
+ Source → Canonical 当前识别关系
+ Immutable Recognition Record
+ Pending Review 任务/事件
```

这四个副作用必须原子、幂等、可重放，不能出现“模型判断正确但业务状态只写了一半”。

## 2. 核心实体、关系与标识符语义

```text
Brand
  └── Product Family / Series
       └── Product Model
            └── Canonical Variant
                 └── Source Product / Offer
```

关系至少包括：

```text
SAME_VARIANT
VARIANT_OF
SAME_MODEL
SAME_SERIES
VISUALLY_SIMILAR
UNKNOWN
```

只有 `SAME_VARIANT` 可以生成自动 Recognition。

Canonical Variant 状态：

```text
ACTIVE         已验证，可参与自动挂接
PROPOSED       新发现，等待证据/治理
SPLIT_PENDING  疑似一个 Canonical 混入多个 Variant，冻结新自动挂接
MERGE_PENDING  疑似多个 Canonical 实为同一 Variant，冻结相关实体新自动挂接
RETIRED        历史实体，不再接受新自动挂接
MERGED         已治理合并到唯一 surviving Canonical
SPLIT          已确认 one-to-many 拆分，仅保留历史身份与 lineage
TAINTED        关键事实污染，暂停自动挂接
```

`MERGED` 是 many-to-one，可 redirect 到唯一 survivor；`SPLIT` 是 one-to-many，旧 Canonical 不能自动 redirect 到任一 child，必须重新解析。

### 2.1 Identifier Namespace

统一采集：

```text
reference_full / style_code / mpn
gtin / ean / upc
merchant_sku
product_group_id / item_group_id
variant_dimension_keys / variant_dimension_values
barcode_symbology / payload / checksum
market
identifier_namespace / identifier_owner / identifier_scope
identifier_source / source_field_path / confidence
```

规则：

- 高可信完整 Reference / Style Code 精确一致：最强 Identity Anchor 之一。
- 官方品牌来源中的 `mpn` 经品牌规则/格式验证后可作为 Manufacturer-grade Identifier。
- 第三方商家 `sku` 默认属于 merchant namespace，不得直接升级为官方 Reference / Style Code。
- `productGroupID / item_group_id / inProductGroupWithID` 是父商品组/变体组关系标识，不是 Variant Identity Anchor。
- `ProductGroup.hasVariant / Product.isVariantOf / variesBy / variant_option` 是高价值 Variant Boundary Evidence。
- 高可信、校验通过的 GTIN/EAN/UPC：Strong Positive + Exact Retrieval Key。
- 不同 GTIN 默认 `POSSIBLE_CONFLICT`；只有品牌/市场规则证明该语境下 GTIN 与本系统 Variant 1:1 时才升级 Hard。
- Vintage 必须考虑旧编码、地区站点差异、包装变化与历史规则。

维护 `identifier_semantics_policy`，最小粒度：

```text
brand × market × source_group × field_path × identifier_type
```

策略声明 `MANUFACTURER_ID / MERCHANT_ID / GROUP_ID / INSTANCE_ID / UNKNOWN`，并声明是否允许 Exact Retrieval、Strong Positive、Hard Conflict、Auto Activation。

## 3. 标准 Schema 与 Hard Constraint

每个属性事实保存：

```text
raw_value
normalized_value
canonical_value_id
extractor / extractor_version
source_type / source_id / source_url
evidence_span / image_bbox
extraction_confidence
validation_status / validation_confidence
validation_record_id
effective_from / effective_to
observed_at / content_hash
market_scope / region_scope
```

**Extraction Confidence 与 Validation Confidence 必须分开。**“模型很确定自己抽到了 `blue`”不等于“`blue` 对这个商品确实正确”。只有经过相应属性验证策略、且达到身份用途门槛的断言，才有资格成为 Hard/Strong Evidence。

### 3.1 腕表

| 字段 | 默认策略 |
|---|---|
| brand | Hard |
| series / family | Blocking + Strong；品牌规则可 Hard |
| subseries / model | Strong |
| official_reference_full | Hard；最强身份字段之一 |
| reference_base | Retrieval / Strong，默认不能代替 full |
| gtin/ean/upc | Strong；条件 Hard |
| case_diameter_mm | Hard |
| case_material | Hard |
| dial_color | Hard |
| dial_type | 定义独立变体时 Hard |
| bezel | 定义独立变体时 Hard |
| bracelet_or_strap | 条件 Hard；需识别后换件 |
| caliber / movement | 代际/变体区分时 Hard，否则 Strong |
| functions | 变体区分时 Hard |
| edition / generation | Hard |
| serial_number | 单件属性 |
| condition / price | Offer 属性 |

Reference 保存 `raw / normalized / base / full / parts / brand_rule_version`。默认以 `reference_full` 为准；只有品牌规则明确证明后缀不定义 Variant 时才允许 base reference 参与自动合并。

### 3.2 箱包

| 字段 | 默认策略 |
|---|---|
| brand | Hard |
| family / series | Blocking + Strong |
| model / style | Strong |
| official_style_code | Hard；最强身份字段之一 |
| gtin/ean/upc | Strong；条件 Hard |
| official_size | Hard |
| material | Hard |
| official_color | Hard |
| hardware | Hard |
| pattern / print | Hard |
| edition / collaboration | Hard |
| season / year / generation | 官方由其区分时 Hard |
| serial / date_code | 单件/生产证据 |
| condition / price | Offer 属性 |

图片颜色不直接成为 Hard Constraint；灯光、白平衡、老化、修图会造成偏差，视觉颜色只做 Soft Evidence。

### 3.3 两级标准化

```text
material_group = ROSE_GOLD
material_brand_value = ROLEX_EVEROSE_GOLD

color_group = BLACK
color_brand_value = CHANEL_NOIR
```

通用层用于跨平台召回，品牌精确层用于 Variant 判定，避免把品牌专有语义压平。

## 4. Evidence、来源独立性、事实状态与时间版本

来源等级：

```text
T0  品牌官网、官方目录、官方标识体系
T1  已验证内部标准库、授权/专业数据库
T2  高质量专业平台、可信二手平台
T3  普通电商、聚合站、搜索网页
```

可信度按“来源 × 属性 × 市场/时间”定义，而不是整站一刀切。

### 4.1 来源独立性

维护 `source_group_id / syndication_group_id / content_fingerprint / image_hash_group_id / upstream_hint`。

多个 URL 不等于多个独立来源。复制同一 feed、相同/近重复图片、相同异常文案、相同字段错误不能增加 `independent_source_count`。

### 4.2 Evidence Family

```text
IDENTIFIER        Reference / Style Code / MPN / GTIN
STRUCTURED_ATTR   size / material / color / hardware / movement
VARIANT_GRAPH     ProductGroup / isVariantOf / variesBy
LEXICAL_TEXT      BM25 / token overlap
SEMANTIC_TEXT     text embedding / reranker
IMAGE_VISUAL      image embedding / patch feature / perceptual hash
OCR_TEXT          image → OCR → identifier/attribute
EXTERNAL_WEB      外部网页证据
TEMPORAL          year / generation / effective period
```

同一原始观测派生出的多个分数不是多个独立证据：同一标题的 BM25+Embedding 不算两票；同一图片的 pHash/SigLIP/DINO/VLM 不算多票；同一网页的 JSON-LD/DOM/摘要默认属于同一 evidence origin。

### 4.3 Fact Promotion Barrier

```text
OBSERVED      原始可追溯观测
DERIVED       规则/模型/聚类推导
REVIEWED_GOLD 人工确认标签
GOVERNED_FACT 主档治理确认事实
APPROVED_ALIAS 已批准别名/标识符映射
TAINTED       已知被污染
```

Recognition、Matcher 分数、Cluster membership、模型抽取/伪标签都是 DERIVED Artifact。未经 Review/Governance Promotion，不能直接进入 Exact Identity 索引、Hard Constraint 主档、官方 Alias、Identifier Semantics 或 Gold Training Set。

### 4.4 时间版本

Canonical 属性保存 `valid_from / valid_to / version / evidence_ids`。没有明确代际证据时，不跨年代自动合并。

### 4.5 Canonical Attribute Fact Arbitration

`attribute_fact` 是事实断言集合，不是“当前主档值”本身。仲裁主键至少为：

```text
canonical_variant_id
× attribute_id
× market_scope
× valid_time_scope
× variant_generation
```

每个属性定义：

```text
cardinality = SINGLE_VALUE / SET_VALUE / ORDERED_MULTI / RANGE
identity_role = HARD / STRONG / SOFT / OFFER_ONLY
normalization_level = GENERIC / BRAND_PRECISE
allows_regional_variation
allows_temporal_change
specificity_order / unit_policy / comparison_policy
```

Resolution 状态：

```text
RESOLVED
MULTI_VALID
CONFLICTED
UNKNOWN
STALE
```

固定规则：

1. 不使用 latest-write-wins。
2. 不使用简单 majority vote；转载/同 feed 去重。
3. Authority 按字段、品牌、市场、有效期和字段语义定义。
4. 同 scope 的治理级 SINGLE_VALUE Hard Attribute 高可信冲突 → `CONFLICTED`，停止依赖该字段 Auto-Match。
5. T2/T3、OCR/VLM 与已治理 T0/T1 冲突只触发 revalidation/governance，不能覆盖 Current Fact。
6. 保留 Generic + Brand-Precise 粒度，不让粗值覆盖精确值。
7. 缺失不是反证。
8. 多值属性按其集合/顺序语义比较。
9. 支撑 Evidence 撤回/TAINT → `STALE` 并重仲裁。
10. Resolution 保存 input assertions、source-independence snapshot、policy、scope、reason、confidence、supersedes lineage。
11. Search/Matching/Conflict 默认只消费 `RESOLVED/MULTI_VALID` Current Fact。
12. Identity-critical Resolution 变化必须通过 Catalog Publication Barrier 与 Search 同版本生效。

## 5. 属性抽取、Validation、OCR 与 VLM

```text
Raw Source Product
→ Schema Mapping
→ Deterministic Parsing / Dictionary
→ Barcode Decode
→ Text Attribute Extraction
→ Scene OCR
→ Document-like OCR/VLM（按需）
→ General VLM Fallback（少量困难样本）
→ Normalization / Ontology Mapping
→ Attribute Validation / Quality Check
→ Attribute Assertion
→ Canonical Attribute Arbitration（Canonical 路径）
→ Normalized Product Profile / Current Fact Projection
```

Extraction 和 Validation 是两个不同任务：Extraction 回答“候选值是什么”，Validation 回答“该值是否适用于这个商品、是否与商品 profile 一致、是否足以用于身份判断”。

### 5.1 Barcode / OCR

条码使用 zxing-cpp 等确定性 decoder，经过 check digit、格式、品牌/市场校验后进入 Exact Retrieval。

PoC Scene OCR 基线：PP-OCRv6。OCR 输出必须先分类为：

```text
reference / style_code
gtin/ean/upc
serial_number
date_code
size
material_text
other_text
```

保卡整页、历史目录、复杂表格等 document-like 场景使用 PaddleOCR-VL-1.6 / PP-Structure 类能力作为 fallback。

### 5.2 General VLM

PoC 困难样本结构化抽取基线：Qwen3.5-4B。职责是产生可验证候选证据，不是最终身份判断。VLM 无权直接写 ACTIVE Canonical、Current Fact 或 `CERTAIN_MATCH`。

### 5.3 Attribute Validation Gate

每个 `(source_product, attribute, candidate_value)` 都必须生成独立 `attribute_validation_record`，状态固定为：

```text
VALIDATED_VALID       有充分证据支持值正确且适用于该商品
VALIDATED_INVALID     有充分证据证明值错误/错配
UNVERIFIED            证据不足，既不能证明正确也不能证明错误
NOT_APPLICABLE        该属性对当前 Product Type / Variant 语义不适用
SOURCE_CONFLICT       同一来源内部或可见页面之间存在未解决冲突
```

最小记录：

```text
source_product_id / source_version
attribute_id / candidate_value_id
product_type_path / taxonomy_version
validation_status
validation_confidence
validator_type / validator_version
profile_evidence_ids
independent_evidence_group_ids
rule_hits / contradiction_hits
scope = market / time / generation
circular_dependency_check
created_at
```

#### 5.3.1 分层 Validator

按成本与确定性执行：

```text
L0 Schema / Deterministic Validator
  类型、单位、枚举、正则、check digit、数值范围、品牌编码规则

L1 Applicability / Cross-field Validator
  Product Type 是否允许该属性；属性之间是否存在不可能组合

L2 Text/Profile Cross-check
  candidate attribute value vs title/description/structured profile
  输出 support / contradiction / missing，而不是只给相似度

L3 Cross-source / Official Consistency
  与真正独立的 T0/T1 Evidence、官网可见字段、历史 scope 做交叉验证

L4 Multimodal Validator
  对颜色、材质、盘面、五金、图案等视觉可观察属性做辅助验证

L5 LLM/VLM Quality Assessor
  仅用于长尾、不熟悉属性、复杂文本和冲突解释；默认不能单独把 Hard Attribute 升级为 VALIDATED_VALID
```

所有层都允许 abstain。Validator 不能为了覆盖率强制二分类。

#### 5.3.2 Applicability 与 Value Correctness 分开

先判断：

```text
Is attribute applicable to this product type / variant?
```

再判断：

```text
If applicable, is candidate value correct?
```

例如箱包的 `movement` 应为 `NOT_APPLICABLE`，而不是把空值/错误值混成 INVALID；腕表没有 `hardware_color` 也不能按箱包 Schema 验证。Taxonomy/Router 不确定时 applicability 只能 `UNVERIFIED` 或按多个 plausible type 路径验证，不能用预测 leaf 强行判错。

#### 5.3.3 Circularity / Confirmation-bias Guard

Validation 不能使用由当前断言自己或其 descendant 推导出的 Canonical Fact 来证明自己正确。

```text
Assertion A
→ Model/Rule
→ Canonical Resolution R
→ 再用 R 验证 A
```

这种闭环禁止作为独立支持。`circular_dependency_check` 必须沿 Business/ML Lineage 检查 validator Evidence 是否独立于待验证 assertion。Teacher 输出、同源转载、同一网页的 JSON-LD/DOM、同一图片的 OCR/VLM 也不能伪装成多份独立证据。

#### 5.3.4 Hard Attribute 使用资格

对于 `identity_role=HARD` 的字段：

- `VALIDATED_VALID` 且 validator/source policy 已在对应 brand/category/attribute slice 认证，才允许参与 Hard Positive / Hard Conflict。
- `VALIDATED_INVALID` 不进入 Attribute Arbitration eligible set，可作为 source-quality/error Evidence。
- `UNVERIFIED` 只能用于 Soft Retrieval/提示；不能成为 Hard Conflict、Identity Anchor 或 Exact Filter。
- `NOT_APPLICABLE` 从该 Product Type 的身份比较中排除。
- `SOURCE_CONFLICT` 直接触发 revalidation / UNKNOWN；不能选一边继续 Auto-Match。

对 Hard Attribute 的 validator threshold 按**下游 False Merge 风险预算**设置，不用统一 `0.5`/`0.8` 分数。

### 5.4 零/少标签 Validation 路线

冷启动顺序：

1. **确定性规则 + Ontology + 品牌知识**：先覆盖 Reference、尺寸单位、枚举、GTIN、明显不可能组合。
2. **弱监督 Positive/Negative**：使用高可信重复出现的有效 attribute-value 模式作为 Positive；用同类型内明显错配的 value replacement、Hard Negative 生成 Negative。该方式与 AutoKnow 的 Catalog cleaning 思路一致。
3. **Few-shot Cross-category Validator**：MetaBridge 类方法作为跨品类少标签基线/challenger，重点评测未见 category 的 uncertainty，而不是直接全量上线。
4. **Structured Table Validator**：当积累 Reviewed Data 后，以 Tab-Cleaner 类结构化 catalog pretrain/fine-tune 为主 challenger；同时做 attribute applicability 与 value validation。
5. **Training-free LLM Quality Assessor**：EMNLP 2025 的 auto-prompt cascade 可用于数以千计的长尾 category-attribute 组合，作为无标签 quality-assessment challenger；只有在独立 Gold/Time-shift 上认证后才可提高 Evidence 权重，且不能单独形成 Hard Fact。

### 5.5 Validation Benchmark / Gate

Gold Set 必须按：

```text
brand / category / attribute
HARD / STRONG / SOFT
seen category / unseen category
clean / noisy source
current / vintage
text-only / image-assisted
applicable / not-applicable
```

分层。

核心指标：

```text
valid_precision / valid_recall
invalid_precision / invalid_recall
applicability_precision / recall
PR-AUC
abstain_rate
hard_attribute_false_valid_rate
hard_attribute_false_invalid_rate
unseen_category_validation_precision
source_conflict_detection_recall
circular_validation_violation = 0
unverified_used_as_hard_evidence = 0
```

**Precision-first Gate：Hard Attribute Validator 的目标不是最大化总体 Accuracy，而是在可接受 abstention 下把 False-Valid 压到其分配的 identity risk budget 内。**

## 6. EvidenceProfile、Router 与缺模态 Route Policy

每条 Source Product 计算：

```text
identifier_quality = NONE / WEAK / STRONG
text_quality       = NONE / WEAK / STRONG
image_quality      = NONE / WEAK / STRONG
hard_attr_coverage = 0..1
conflict_state     = NONE / POSSIBLE / HARD
catalog_mode       = LINK / DISCOVERY
synthetic_evidence = true / false
brand_route_state    = AUTHORITATIVE / MULTI_CANDIDATE / UNKNOWN / CONFLICTING
category_route_state = AUTHORITATIVE / MULTI_CANDIDATE / UNKNOWN / CONFLICTING
routing_scope        = LEAF / ANCESTOR / MULTI_ROUTE / BROAD_FALLBACK
```

| 场景 | 主要召回 | 自动判定上限 |
|---|---|---|
| 强 Reference/Style/GTIN + Hard Attr 无冲突 | Exact + 属性过滤 | 可 CERTAIN_MATCH |
| 文本强、无图片 | Exact/BM25/Text ANN/属性 | 可 CERTAIN_MATCH；无图不是负证据 |
| 图片强、文本弱、无可靠型号 | Image ANN + OCR + 视觉属性 + 少量 VLM | 默认不能仅视觉 CERTAIN_MATCH |
| 文本强 + 图片强 | 多路召回 + Rerank | 可 CERTAIN_MATCH |
| 型号疑似错误 | raw/normalized identifier 双路 + 非 identifier 召回 | 冲突时 UNKNOWN/NON_MATCH |
| 文本与图片冲突 | 模态独立保留 | POSSIBLE_CONFLICT → UNKNOWN |
| 无图无可靠型号、结构化属性较全 | BM25/Text ANN/Attribute | 只有经认证的高区分组合才自动，否则 UNKNOWN |
| 只有泛化标题、缺 Hard Attr | BM25/Text ANN | UNKNOWN |
| Vintage / 新款无 Canonical | Neighbor + Official/Web Evidence | PROPOSED |

### 6.1 Router / Filter Safety

Brand/Category Router 只用于缩小候选空间和控制成本，不是身份事实源。

```text
HARD_FILTER     只有权威、可验证路由证据
MULTI_ROUTE     多个 plausible route 各保留 quota
ANCESTOR_ROUTE  leaf 不确定时退到 taxonomy ancestor
BROAD_FALLBACK  路由未知/冲突时宽范围召回
```

规则：Exact Identifier 永远绕过 Router；只有 T0/T1、历史认证结构化类别或已验证 Identifier→Category 映射可 Hard Filter；模型/VLM/OCR/merchant 分类只能 Multi-route/Ancestor/Broad；leaf 不稳定退 ancestor；多个 sibling route 保留 quota；图片只补充 route 权重。

Amazon 2024 的 hierarchical classification 结果说明层级标签本身、长尾 class imbalance 和短文本歧义需要显式建模；因此 Router benchmark 必须分别看 ancestor/leaf recall，而不能只看 flat accuracy。

## 7. Candidate Retrieval、Fusion 与 Open-world Guard

100 万–1000 万记录禁止 N²。

召回：Exact Identifier、Brand+Model、Brand+Series+Hard Attr、BM25、Text ANN、Image ANN、Image hash、Historical Alias、Discovery Neighbor。

PoC 初始 K：Exact≤20、BM25 30、Text ANN 50、Image ANN 每图30/总≤60、Attribute 30；union≤150，Cheap Rerank≈30，Expensive Matcher 10–20。

Gate：

```text
Recall@100 after fusion/truncation >= 99.5%
Exact-candidate survival rate = 100%
router_pre_filter_positive_recall >= 99.9%
router_post_filter_positive_recall >= 99.5%
```

### 7.1 Fusion / Search

不同通道 raw score 不直接相加；Exact 永不被 soft fusion 截断；零/少标签使用 RRF baseline；截断前保留各通道 quota；Exact∪RRF 后再 rerank；有 judgment 后比较 normalized/learned fusion。

生产基线 OpenSearch 3.8。Milvus 仅在 10M 实测 OpenSearch Recall/QPS/成本不达标时拆分。Identity-critical Search Filter 只能消费已发布的 `RESOLVED/MULTI_VALID` 且满足 Validation Gate 的 Canonical 属性。

### 7.2 NIL / Route Recovery

CandidateSet 状态：`KNOWN_CANDIDATE / AMBIGUOUS_KNOWN / POSSIBLE_NIL / RETRIEVAL_FAILURE / ROUTING_AMBIGUOUS`。

进入 NIL/Discovery 前，只要缺 Strong Identifier 或 Router 非 AUTHORITATIVE，必须做 route-bypass：去掉模型推断 hard filter，搜索 ancestor/sibling/broad BM25/Text ANN/Image ANN。只有 Router/Search/Publication 健康且 bypass 仍无安全已有候选，才允许 `UNKNOWN_POSSIBLE_NIL`。

## 8. Embedding、Visual Search 与局部复核

Text：Qwen3-Embedding-0.6B，先测 512d，再比较 256/384d；Qwen3-Reranker-0.6B 仅 Top-N。

Image：SigLIP2-B/16 384 baseline；DINOv3 ViT-B/16 challenger，生产前 Legal/Compliance Gate；Qwen3-VL-Embedding/Reranker 作为多模态 challenger。

每图独立向量，多图用 max/top-k/front/detail/quality aggregation。完全相同图片不能单独证明 SAME_VARIANT。

近邻 Variant Top-10～20 使用局部 patch/local descriptor 复核盘面、表圈、刻字、五金、走线、印花等；局部视觉仍属于 IMAGE_VISUAL，不是 Identity Anchor。

## 9. Pair Matcher、Conflict Engine 与 Decision Policy

```text
Candidate Pair
→ Pre-Conflict
→ Cheap Deterministic Features
→ Structured/Text Matcher
→ Multimodal Difficult Pair（少量）
→ Local Visual（near-tie）
→ Post-Conflict
→ Calibration
→ Evidence-Family Risk Policy
→ Candidate-set/NIL/Ambiguity Guard
→ Decision
```

`CERTAIN_MATCH` 至少满足：

```text
NO HARD_CONFLICT
AND CandidateSetState == KNOWN_CANDIDATE
AND identity-critical Canonical Resolution 可服务
AND
(
  Strong Identity Anchor
  OR
  Calibrated Matcher >= tau_segment
  + >=2 个非重复 Evidence Family
  + Ambiguity Guard 通过
)
```

Hard Conflict 的属性比较只允许使用**已通过 Validation Gate 的 Source Assertion**和已发布 Canonical Resolution。`UNVERIFIED/SOURCE_CONFLICT` 不能被升级成 Hard Reject。

UNKNOWN 至少包括：AMBIGUOUS、POSSIBLE_NIL、ROUTING_AMBIGUOUS、INSUFFICIENT_EVIDENCE、SEARCH_FAILURE、DEPENDENCY_FAILURE、PUBLICATION_INCONSISTENT、CONFLICT、CATALOG_REPAIR、STALE_SOURCE_VERSION、COMMIT_CONFLICT、CANONICAL_FACT_CONFLICT、ATTRIBUTE_UNVERIFIED。

## 10. Entity Linking、Discovery 与 Canonical Health

Linking：Source Snapshot → Route/Validation → Retrieval → Pair/Conflict/Calibration → CandidateSetAssessment → CERTAIN_MATCH → Recognition Commit Barrier。

Discovery：POSSIBLE_NIL → Route Recovery → Official/Web Evidence → Strict Blocking → Clustering → PROPOSED → Novelty/Uniqueness → Attribute Validation + Arbitration + Required Hard Fact Check → ACTIVE/PROPOSED。

任何 `PROPOSED→ACTIVE` 必须有当前 publication 的 `canonical_novelty_assessment`；只有 `UNIQUE` 可自动激活。Variant-unique Manufacturer ID / official external Variant ID 使用唯一 identity claim 防止并发双 ACTIVE。

ACTIVE Canonical 持续检查 Hard Conflict、cannot-link、Manufacturer ID partition、attribute mode、review disagreement、temporal conflict、Canonical Fact Conflict。Identity-critical conflict 立即冻结 Auto-Match。

Cluster detector / GNN / GraphCR / SuperPart 只能 Detect/Prioritize/Propose；Repair 采用：

```text
Detect & Freeze
→ Immutable Repair Graph Snapshot
→ Graph-based Repair Triage
→ Cluster-aware Active Evidence Query
→ Governed Must-Link/Cannot-Link
→ Constrained Partition Proposal
→ Governance Approval
→ Atomic Repair Publication
```

模型无权直接 Split/Merge Canonical。Merge 前所有 Attribute Assertion 必须重新 Validation/Arbitration，不能简单选 survivor 字段覆盖另一侧。

## 11. Web Evidence Agent 与 Official Web Catalog

仅触发内部无候选、POSSIBLE_NIL、新款/Vintage、型号疑似错误、关键属性冲突、near-tie、Canonical Fact Conflict。

优先级：品牌官网 → 官方目录/经销资料 → 专业数据库 → 高质量二手平台 → 通用搜索。

官方站优先解析 `ProductGroup/Product`、DOM、Embedded State、Identifier、Variant URL；所有结果形成版本化 Attribute Assertion / External Variant Graph。

Product Group ID、merchant SKU、单张图片、搜索/LLM 摘要、只有营销名无具体 Variant ID 的页面都不能单独激活 Variant 或形成 Current Hard Fact。Web Assertion 同样必须经过 Attribute Validation Gate。

## 12. 冷启动、Pseudo-label 与训练数据飞轮

0 labels：高可信 Reference/Style/GTIN、Hard Constraint、alias/ontology、pretrained Text/Image、确定性 Positive、Hard Negative、Attribute Validator 弱监督。

Pseudo-label 记录 origin、teacher/policy、source decision、EvidenceProfile、confidence/uncertainty、selection policy、upstream artifacts。Pseudo-label 永远不能进入 Certification Gold、Canonical Fact 或 Attribute Arbitration eligible set。

约 10K reviewed pairs：Logistic/LightGBM + calibration；更多数据使用 compact cross encoder/domain contrastive；100K+ 且 Hard Negative 足够再评估 multimodal student/active learning/learned fusion。

Attribute Validation Labels 与 Pair Matching Labels 分开管理；“这个属性值正确”不自动等于“这两个商品 SAME_VARIANT”，反之亦然。

## 13. Review、风险认证与 Reviewer Quality

三轨：

```text
TRAINING_REVIEW
CERTIFICATION_AUDIT
GOVERNANCE_REVIEW
```

正式风险认证单位是最终 Recognition Decision，不是 candidate pair。Certification 概率抽样保存 inclusion probability/stratum，按真实流量权重汇总。

调参集与最终认证集分离；正式报告同时给 i.i.d. 与 dependency-cluster-aware 风险上界，release 取最保守值。确认 False Merge 后按 dependency key 做 sibling scan。

Certification 默认双人独立盲审；标签允许 SAME_VARIANT / DIFFERENT_VARIANT / INSUFFICIENT_EVIDENCE / SOURCE_DATA_ERROR，分歧进入 adjudication。Reviewer 资格、指南、UI、Evidence Snapshot 全部版本化。

Attribute Validation 另建 attribute-level review/control set，尤其覆盖 Hard Attribute、NOT_APPLICABLE、SOURCE_CONFLICT 和 unseen category；不能用 Pair Gold 自动替代。

## 15. Incremental、CDC、Publication 与 Recognition Commit

DB Canonical/Attribute Resolution mutation 与 `catalog_outbox_event` 同事务；CDC/Outbox Relay → 幂等投影 → OpenSearch external version → refresh/checkpoint → publication watermark。

Auto-Match 请求入口 pin `ACTIVE publication_id`；Search hit 必须校验 Canonical status/version/Fact Resolution。Search projection 落后、混合 publication、旧 Resolution → `UNKNOWN_PUBLICATION_INCONSISTENT`。

Recognition 推理阶段不持长事务；CERTAIN_MATCH 最终短 ACID transaction：

```text
idempotency intent
→ lock/CAS Source current row
→ validate source_version/content_hash/epoch
→ validate target Canonical + publication + fact-resolution ids
→ ensure single current link
→ immutable recognition_record
→ upsert current source_canonical_link
→ update Source state
→ exactly one Review task or outbox event
```

相同 key+相同 intent 返回第一次结果；相同 key+不同语义拒绝。Source/Canonical/Fact Resolution 在推理后变化则不提交。跨系统副作用用 Outbox + idempotent consumer。

## 16. Production Runtime Reliability

任一 mandatory stage 被跳过/timeout/熔断都会形成新 `route_execution_signature`；未经独立 benchmark + risk certification，不允许 CERTAIN_MATCH。

每请求使用 end-to-end deadline；每依赖唯一 retry owner；指数退避+jitter+retry budget；OpenSearch/Reranker/OCR/GPU/VLM/Web Agent 使用 bounded queue 与 circuit breaker。

Load shedding 顺序：P4 backfill/bulk re-validation → P3 Discovery/Web/Fact conflict enrichment → P2 near-tie expensive path → P1/P0 linking。Attribute Validation mandatory stage 被 shed 时，Hard Assertion 不能自动降级为“默认有效”。

### Phase 0：数据审计、Taxonomy 与 Validation Gold

建立字段完整度、Alias/Ontology、Hard Conflict Matrix、Identifier 可用率、来源独立性、EvidenceProfile、Router benchmark、Leakage-safe Split、NIL/near-tie benchmark、三轨 Review。

同时为腕表/箱包建立：

- `attribute_semantics_policy`。
- `attribute_validation_policy`。
- Attribute applicability + value correctness Gold Set。
- 首批规则型 Positive/Negative/Hard Negative。
- 当前主档 Hard Attribute 噪声与 validation coverage 审计。

### Phase 1：确定性腕表 Linking + Hard Attribute Validation

Reference/GTIN、Exact Retrieval、Hard Conflict、Recognition Commit；先上线腕表 identity-critical 字段的 L0/L1/L2 Validation（Reference/尺寸/材质/盘面/表圈/代际），再进入 Arbitration/Search Projection。

先证明 **判断 Precision + Hard Attribute False-Valid Gate + Commit Integrity** 同时达标。

### Phase 2：Hybrid Text + Router/Filter Safety + Few-shot Validation

BM25、Qwen3-Embedding、RRF、Qwen3-Reranker、箱包、Calibration/NIL Guard；扩展箱包 size/material/color/hardware/pattern 的 Validation。

MetaBridge 类 cross-category few-shot validator、Tab-Cleaner 类 structured validator 作为 challenger，用 unseen-category validation set 决定是否上线。

### Phase 3：Image/OCR/Multimodal Validation

zxing-cpp、PP-OCRv6、PaddleOCR-VL、SigLIP2/DINO challenger、局部视觉、Qwen3.5/Qwen3-VL。视觉不仅用于 extraction，也可做 visual-observable attribute validation；但不能单独提升 Hard Fact。

无标签 LLM auto-prompt quality assessor 只处理长尾属性/复杂规则，并受独立 Validation Gold/Time-shift Gate。

### Phase 4：Discovery/Web/Canonical Repair

POSSIBLE_NIL、ProductGroup/Product parse、External Variant Graph、Novelty Gate、Cluster Health、Split/Merge Repair。所有 Web/Repair 产生的新 assertion 必须重新 Validation→Arbitration。

### Phase 5：Supervised Student + Controlled Continuous Learning

Review labels、Hard Negative、active learning、domain encoder、learned fusion、shadow/A-B/rollback；Attribute Validator、Router、Matcher 分别训练/版本化/认证，不用一个统一模型置信度替代三层风险控制。

## 20. 正式开启自动识别 Gate

全部满足才扩大 Auto-Match：

1. `Precision@Auto-Match >= 99.9%`，`Recall@100 after fusion >= 99.5%`，Exact survival=100%。
2. Certification Audit 满足 sampling provenance 与 cluster-aware risk upper bound。
3. 所有 Hard Conflict 回归 0 自动错合并；Seen/Unseen/Time-shift/Vintage/缺图/缺型号/低质图分别达标。
4. Synthetic/Pseudo evidence 不能形成 Hard Fact/Identity Anchor/Certification Gold。
5. AMBIGUOUS/NIL/ROUTING_AMBIGUOUS/RETRIEVAL_FAILURE/PUBLICATION_INCONSISTENT/CATALOG_REPAIR/CANONICAL_FACT_CONFLICT 不得绕过 Guard。
6. Product Group ID、merchant SKU、Web JSON-LD/DOM 冲突等语义安全违规=0。
7. ACTIVE 模型/Router/Attribute Validator/Policy lineage 完整率=100%。
8. `SPLIT_PENDING/SPLIT/MERGE_PENDING/TAINTED` Canonical 新 Auto-Match=0。
9. `PROPOSED→ACTIVE` 必须 novelty=UNIQUE 且 required Hard Fact 可服务。
10. Recognition Commit duplicate/partial/stale/multiple-current-link 违规=0。
11. Router 非权威导致 hard prune、false-NIL/new-canonical 违规=0。
12. Identity/Search/Hard Conflict 只消费已发布 Canonical Attribute Resolution。
13. Identity-critical Resolution `CONFLICTED/STALE` 时 CERTAIN_MATCH=0。
14. Arbitration 中 syndicated double-count/latest-write-wins/majority-vote Hard Fact 违规=0。
15. **Hard Attribute Source Assertion 未达到 `VALIDATED_VALID`（或治理等价状态）却参与 Hard Positive、Hard Conflict、Identity Anchor 或 Exact Filter 的违规=0。**
16. **`UNVERIFIED / SOURCE_CONFLICT / VALIDATED_INVALID` Attribute Assertion 被提升为 identity-critical Current Fact 的违规=0。**
17. **Attribute Validator 的 circular validation / self-confirmation 违规=0。**
18. **Hard Attribute Validator 在 brand/category/attribute 关键 slice 的 False-Valid 风险上界必须低于其预分配 identity risk budget；样本不足则对应 slice 保持 UNKNOWN。**
19. **NOT_APPLICABLE 被当作 missing/invalid 并影响 Variant 判定的关键用例违规=0。**
20. **Attribute Validation policy/model/Gold Set/threshold 均版本化且可回滚；Validator 漂移或上游 parser 变更后未经重认证不得继续沿用旧 Hard eligibility。**

任何指标退化时，优先降低 Coverage，不降低 Attribute Validation、Hard Constraint、NIL、Publication 或 Commit Safety。

## 22. 最终生产原则

```text
官方知识 / 确定性标识
          ↓
Attribute Extraction
          ↓
Attribute Validation / Applicability Gate
          ↓
Evidence Assertions + Source Independence
          ↓
Canonical Attribute Fact Arbitration
          ↓
EvidenceProfile + Router/Filter Safety
          ↓
Hybrid Retrieval + Exact Preserve
          ↓
结构化 + 文本 + 图片多证据
          ↓
Hard Conflict + Calibration
          ↓
Candidate-set / NIL / Ambiguity Guard
          ↓
Constraint-aware Graph Resolution
          ↓
CERTAIN_MATCH Decision
          ↓
Recognition Commit Barrier
          ↓
Current Link + Immutable Recognition + Pending Review
          ↓
Canonical Novelty / Health / Repair
          ↓
Independent Risk Audit
          ↓
Controlled Training + Immutable ML Lineage
```

固定原则：

1. **Identity first，Similarity second。**
2. **Extraction confidence ≠ fact correctness；identity-critical Attribute 必须单独 Validation。**
3. **Attribute Applicability 与 Value Correctness 分开判断；NOT_APPLICABLE 不是 INVALID。**
4. **Hard Conflict 优先于任何模型高分，但 Hard Conflict 本身也只能建立在高可信、已验证属性上。**
5. **UNKNOWN / UNVERIFIED 是合法且必要的生产输出。**
6. **Synthetic/Pseudo evidence 不能形成 Hard Fact / Identity Anchor / Certification Gold。**
7. **Attribute Validation 允许 abstain；不能为了覆盖率把未验证值强制转为 valid/invalid。**
8. **Validator 不能通过 Canonical Current Fact 自证自己的上游 assertion；所有 Hard Validation Evidence 必须通过 circular-lineage check。**
9. **仅视觉相似不能自动 SAME_VARIANT；视觉可以辅助 Router/Attribute Validation/near-tie 复核。**
10. **必须显式允许 NIL；Top-1/Top-2 near-tie 必须 Abstain。**
11. **Exact Identifier 永远绕过非权威 Router，Exact 候选永不被 Soft Fusion 截断。**
12. **Brand/Category Router 是候选空间优化器，不是身份事实源。**
13. **训练 Review、Attribute Validation Gold 与生产 Risk Certification 是不同数据资产。**
14. **Product Group ID 是关系标识，不是 Variant Identity；Merchant SKU 与 Manufacturer ID 分命名空间。**
15. **官网结构化数据是高价值 Evidence，不是无条件 Canonical Truth；同样要经过 Validation。**
16. **Canonical Current Fact 不是最近值/多数票，而是已验证 Assertions 在明确 scope 下的版本化 Arbitration。**
17. **Search/Hard Conflict/Identity Filter 只消费已验证、已仲裁、已发布的 Current Fact。**
18. **DB→Search 使用 Transactional Outbox + Idempotent Projection + Monotonic Version + Publication Barrier。**
19. **ACTIVE Canonical 不是永久真值：持续检查 over-merge、under-merge、Fact Conflict。**
20. **Entity Discovery 是新品证明问题；PROPOSED→ACTIVE 必须 Novelty/Uniqueness + Required Fact Gate。**
21. **Cluster repair model 只能 Detect/Prioritize/Propose，不能直接修改 Canonical。**
22. **所有 ACTIVE 模型、Router、Attribute Validator、Taxonomy、Validation/Arbitration Policy 与数据集都是不可变、可哈希、可追溯 Artifact。**
23. **timeout/过载/依赖故障形成的新 route 未认证时 fail closed 为 UNKNOWN。**
24. **模型 CERTAIN_MATCH 只是待提交 Decision；只有通过 Recognition Commit Barrier 后业务关系才生效。**
25. **任何复杂度只有在提高 Coverage@99.9% Precision、降低 False-Valid/False-Merge、提高事实/事务可靠性或降低总成本时才有价值。**
