# 奢侈品识别方案

## 1. 目标与边界

系统目标不是“找最像的商品”，而是把雷小安、奢当家、腕表之家、小迈步、爱回收等来源的记录归一到**同一个官方商品变体（Official Variant）**。

第一阶段覆盖腕表与箱包，历史数据约 100 万–1000 万条。腕表已有部分品牌/系列/型号标准库；箱包主档不完整，因此系统必须同时支持 **Entity Linking** 与 **Entity Discovery**。

核心原则：

> **Precision >> Recall。宁可输出 UNKNOWN，也不能把不同官方变体错合并。**

只有会定义官方变体的关键属性兼容时，才允许自动认定 `SAME_VARIANT`。系统不做真假鉴定；成色、价格、库存、卖家、单件序列号、保卡状态等属于 Offer / 单件属性，不定义官方商品变体。

机器成功识别后必须形成一致的业务结果：

```text
Source Product 当前状态
+ Source → Canonical 当前识别关系
+ Immutable Recognition Record
+ Pending Review 任务/事件
```

这四个副作用必须原子、幂等、可重放，不能出现“模型判断正确但业务状态只写了一半”。

## 2. 核心实体、关系与标识符语义

统一实体层级：

```text
Brand
  └── Product Family / Series
       └── Product Model
            └── Canonical Variant
                 └── Source Product / Offer
```

关系至少包括：

```text
SAME_VARIANT
VARIANT_OF
SAME_MODEL
SAME_SERIES
VISUALLY_SIMILAR
UNKNOWN
```

只有 `SAME_VARIANT` 可以生成自动 Recognition。

Canonical Variant 状态：

```text
ACTIVE         已验证，可参与自动挂接
PROPOSED       新发现，等待证据/治理
SPLIT_PENDING  疑似一个 Canonical 混入多个 Variant，冻结新自动挂接
MERGE_PENDING  疑似多个 Canonical 实为同一 Variant，冻结相关实体新自动挂接
RETIRED        历史实体，不再接受新自动挂接
MERGED         已治理合并到唯一 surviving Canonical
SPLIT          已确认 one-to-many 拆分，仅保留历史身份与 lineage
TAINTED        关键事实污染，暂停自动挂接
```

`MERGED` 是 many-to-one，可 redirect 到唯一 survivor；`SPLIT` 是 one-to-many，旧 Canonical 不能自动 redirect 到任一 child，必须重新解析。

### 2.1 Identifier Namespace

统一采集：

```text
reference_full / style_code / mpn
gtin / ean / upc
merchant_sku
product_group_id / item_group_id
variant_dimension_keys / variant_dimension_values
barcode_symbology / payload / checksum
market
identifier_namespace / identifier_owner / identifier_scope
identifier_source / source_field_path / confidence
```

规则：

- 高可信完整 Reference / Style Code 精确一致：最强 Identity Anchor 之一。
- 官方品牌来源中的 `mpn` 经品牌规则/格式验证后可作为 Manufacturer-grade Identifier。
- 第三方商家 `sku` 默认属于 merchant namespace，不得直接升级为官方 Reference / Style Code。
- `productGroupID / item_group_id / inProductGroupWithID` 是父商品组/变体组关系标识，不是 Variant Identity Anchor。
- `ProductGroup.hasVariant / Product.isVariantOf / variesBy / variant_option` 是高价值 Variant Boundary Evidence。
- 高可信、校验通过的 GTIN/EAN/UPC：Strong Positive + Exact Retrieval Key。
- 不同 GTIN 默认 `POSSIBLE_CONFLICT`；只有品牌/市场规则证明该语境下 GTIN 与本系统 Variant 1:1 时才升级 Hard。
- Vintage 必须考虑旧编码、地区站点差异、包装变化与历史规则。

维护 `identifier_semantics_policy`，最小粒度：

```text
brand × market × source_group × field_path × identifier_type
```

策略声明：

```text
MANUFACTURER_ID / MERCHANT_ID / GROUP_ID / INSTANCE_ID / UNKNOWN
```

并声明是否允许 Exact Retrieval、Strong Positive、Hard Conflict、Auto Activation。

## 3. 标准 Schema 与 Hard Constraint

每个属性事实保存：

```text
raw_value
normalized_value
canonical_value_id
extractor / extractor_version
source_type / source_id / source_url
evidence_span / image_bbox
confidence / validation_status
effective_from / effective_to
observed_at / content_hash
```

`observed_at` 与有效期分离；新证据不覆盖旧事实，而用 version / supersedes 表达变化。只有双方属性都达到对应可信度门槛时才形成 Hard Conflict；低置信 OCR/VLM 冲突只能触发 `POSSIBLE_CONFLICT → UNKNOWN`。

### 3.1 腕表

| 字段 | 默认策略 |
|---|---|
| brand | Hard |
| series / family | Blocking + Strong；品牌规则可 Hard |
| subseries / model | Strong |
| official_reference_full | Hard；最强身份字段之一 |
| reference_base | Retrieval / Strong，默认不能代替 full |
| gtin/ean/upc | Strong；条件 Hard |
| case_diameter_mm | Hard |
| case_material | Hard |
| dial_color | Hard |
| dial_type | 定义独立变体时 Hard |
| bezel | 定义独立变体时 Hard |
| bracelet_or_strap | 条件 Hard；需识别后换件 |
| caliber / movement | 代际/变体区分时 Hard，否则 Strong |
| functions | 变体区分时 Hard |
| edition / generation | Hard |
| serial_number | 单件属性 |
| condition / price | Offer 属性 |

Reference 保存 `raw / normalized / base / full / parts / brand_rule_version`。默认以 `reference_full` 为准；只有品牌规则明确证明后缀不定义 Variant 时才允许 base reference 参与自动合并。

### 3.2 箱包

| 字段 | 默认策略 |
|---|---|
| brand | Hard |
| family / series | Blocking + Strong |
| model / style | Strong |
| official_style_code | Hard；最强身份字段之一 |
| gtin/ean/upc | Strong；条件 Hard |
| official_size | Hard |
| material | Hard |
| official_color | Hard |
| hardware | Hard |
| pattern / print | Hard |
| edition / collaboration | Hard |
| season / year / generation | 官方由其区分时 Hard |
| serial / date_code | 单件/生产证据 |
| condition / price | Offer 属性 |

图片颜色不直接成为 Hard Constraint；灯光、白平衡、老化、修图会造成偏差，视觉颜色只做 Soft Evidence。

### 3.3 两级标准化

```text
material_group = ROSE_GOLD
material_brand_value = ROLEX_EVEROSE_GOLD

color_group = BLACK
color_brand_value = CHANEL_NOIR
```

通用层用于跨平台召回，品牌精确层用于 Variant 判定，避免把品牌专有语义压平。

## 4. Evidence、来源独立性、事实状态与时间版本

来源等级：

```text
T0  品牌官网、官方目录、官方标识体系
T1  已验证内部标准库、授权/专业数据库
T2  高质量专业平台、可信二手平台
T3  普通电商、聚合站、搜索网页
```

可信度按“来源 × 属性”定义，而不是整站一刀切。

### 4.1 来源独立性

维护：

```text
source_group_id
syndication_group_id
content_fingerprint
image_hash_group_id
upstream_hint
```

多个 URL 不等于多个独立来源。复制同一 feed、相同/近重复图片、相同异常文案、相同字段错误不能增加 `independent_source_count`。

### 4.2 Evidence Family

至少定义：

```text
IDENTIFIER        Reference / Style Code / MPN / GTIN
STRUCTURED_ATTR   size / material / color / hardware / movement
VARIANT_GRAPH     ProductGroup / isVariantOf / variesBy
LEXICAL_TEXT      BM25 / token overlap
SEMANTIC_TEXT     text embedding / reranker
IMAGE_VISUAL      image embedding / patch feature / perceptual hash
OCR_TEXT          image → OCR → identifier/attribute
EXTERNAL_WEB      外部网页证据
TEMPORAL          year / generation / effective period
```

同一原始观测派生出的多个分数不是多个独立证据：同一标题的 BM25+Embedding 不算两票；同一图片的 pHash/SigLIP/DINO/VLM 不算多票；同一网页的 JSON-LD/DOM/摘要默认属于同一 evidence origin。

Student Matcher 可使用全部特征学习联合分布，但 `CERTAIN_MATCH` 风险策略不得把相关特征机械相加解释为多个独立支持。

### 4.3 Fact Promotion Barrier

事实状态：

```text
OBSERVED      原始可追溯观测
DERIVED       规则/模型/聚类推导
REVIEWED_GOLD 人工确认标签
GOVERNED_FACT 主档治理确认事实
APPROVED_ALIAS 已批准别名/标识符映射
TAINTED       已知被污染
```

`Recognition`、Matcher 分数、Cluster membership、模型抽取/伪标签都是 DERIVED Artifact。未经 Review/Governance Promotion，不能直接进入 Exact Identity 索引、Hard Constraint 主档、官方 Alias、Identifier Semantics 或 Gold Training Set。

任何 Exact Alias、Canonical Fact、Reviewed Gold Label 必须能沿 lineage 回溯到 OBSERVED/REVIEWED/GOVERNED 上游；DERIVED→DERIVED 不能完成事实晋升。

### 4.4 时间版本

Canonical 属性保存 `valid_from / valid_to / version / evidence_ids`。用于同名跨年份改款、Reference 规则变化、新旧机芯/五金/尺寸变化和 Vintage 回溯。没有明确代际证据时，不跨年代自动合并。

## 5. 属性抽取、OCR 与 VLM

```text
Raw Source Product
→ Schema Mapping
→ Deterministic Parsing / Dictionary
→ Barcode Decode
→ Text Attribute Extraction
→ Scene OCR
→ Document-like OCR/VLM（按需）
→ General VLM Fallback（少量困难样本）
→ Normalization / Ontology Mapping
→ Attribute Validation / Quality Check
→ Normalized Product Profile
```

优先级：规则/主档 → 条码 → 文本 → Scene OCR → 文档 OCR/VLM → General VLM → Quality Check。能用确定性方法解决的问题不交给大模型。

### 5.1 Barcode / OCR

条码先用 zxing-cpp 等确定性 decoder 解析 EAN/UPC/Code128/Data Matrix/QR，经 check digit、格式、品牌/市场校验后进入 Exact Retrieval。

PoC Scene OCR 基线：PP-OCRv6。OCR 输出分类：

```text
reference / style_code
gtin/ean/upc
serial_number
date_code
size
material_text
other_text
```

保卡整页、历史目录、复杂表格等 document-like 场景使用 PaddleOCR-VL-1.6 / PP-Structure 类能力作为 fallback。

### 5.2 General VLM

PoC 困难样本结构化抽取基线：Qwen3.5-4B。职责是产生**可验证候选证据**，不是最终身份判断。

VLM 输出必须经过 ontology、品牌规则、主档、OCR/文本交叉验证；无权直接写 ACTIVE Canonical 或直接输出 `CERTAIN_MATCH`。

## 6. EvidenceProfile 与缺模态 Route Policy

每条 Source Product 先计算：

```text
identifier_quality = NONE / WEAK / STRONG
text_quality       = NONE / WEAK / STRONG
image_quality      = NONE / WEAK / STRONG
hard_attr_coverage = 0..1
conflict_state     = NONE / POSSIBLE / HARD
catalog_mode       = LINK / DISCOVERY
synthetic_evidence = true / false
```

| 场景 | 主要召回 | 自动判定上限 |
|---|---|---|
| 强 Reference/Style/GTIN + Hard Attr 无冲突 | Exact + 属性过滤 | 可 CERTAIN_MATCH |
| 文本强、无图片 | Exact/BM25/Text ANN/属性 | 可 CERTAIN_MATCH；无图不是负证据 |
| 图片强、文本弱、无可靠型号 | Image ANN + OCR + 视觉属性 + 少量 VLM | 默认不能仅视觉 CERTAIN_MATCH |
| 文本强 + 图片强 | 多路召回 + Rerank | 可 CERTAIN_MATCH |
| 型号疑似错误 | raw/normalized identifier 双路 + 非 identifier 召回 | 冲突时 UNKNOWN/NON_MATCH |
| 文本与图片冲突 | 模态独立保留 | POSSIBLE_CONFLICT → UNKNOWN |
| 无图无可靠型号、结构化属性较全 | BM25/Text ANN/Attribute | 只有经认证的高区分组合才自动，否则 UNKNOWN |
| 只有泛化标题、缺 Hard Attr | BM25/Text ANN | UNKNOWN |
| Vintage / 新款无 Canonical | Neighbor + Official/Web Evidence | PROPOSED |

Synthetic Evidence 不能形成 Hard Constraint、Identity Anchor 或官方事实；图→文本只可做 query expansion/候选提示；文本→图像默认不进入身份链路。

低质量图片在 Image ANN 前独立评估 blur、resolution、subject_area_ratio、occlusion、background_complexity、watermark、crop_type、color_cast，并降低视觉权重/候选配额。

## 7. Candidate Retrieval、Fusion 与 Open-world Guard

100 万–1000 万记录禁止 N²。

召回通道：

```text
Exact Full Reference / Style Code / Manufacturer MPN
Exact GTIN/EAN/UPC
Brand + normalized model/reference
Brand + series/model + Hard Attributes
BM25
Text ANN
Image ANN
Image exact/perceptual hash
Historical Canonical Alias
Unmatched Entity-Discovery Neighbors
```

默认按 `category`，通常再按 `brand_id` 过滤。

PoC 初始 K：Exact≤20、BM25 30、Text ANN 50、Image ANN 每图30/总≤60、Attribute 30；union≤150，Cheap Rerank≈30，Expensive Matcher 10–20。最终由域内 benchmark 调参。

Retrieval Gate：

```text
Recall@100 after fusion/truncation >= 99.5%
Exact-candidate survival rate = 100%
```

### 7.1 Fusion

- 不同通道 raw score 不直接相加。
- Exact/Identity 候选永不被 Soft Fusion 截断。
- 零/少标签阶段用 RRF 作为 Soft Retrieval 基线。
- 截断前保留各通道 minimum quota。
- Exact ∪ RRF 后再 Cheap Rerank。
- 有足够 judgment 后再比较 normalized weighted fusion / learned fusion。
- Fusion、quota、index、embedding 全部版本化。

### 7.2 Search Engine

生产基线：OpenSearch 3.8，统一承载 Exact/filter、BM25、filtered k-NN、hybrid retrieval、RRF/score normalization、on-disk vector、quantization/rescore、versioned index/alias。

Milvus 只在 10M 真实压测证明 OpenSearch Recall/QPS/资源成本不满足时拆分；pgvector 适合小规模 PoC/内部工具。

### 7.3 NIL / None-of-the-Candidates

检索 Top-1 不等于正确 Canonical 一定存在。

`CandidateSetAssessment` 保存：

```text
best_candidate_id / best_score_calibrated
second_candidate_id / second_score_calibrated
score_margin / near_tie_count
candidate_set_state
none_of_candidates_score
nil_reason
retrieval_health_snapshot
policy_version
```

状态：

```text
KNOWN_CANDIDATE
AMBIGUOUS_KNOWN
POSSIBLE_NIL
RETRIEVAL_FAILURE
```

near-tie 且关键 Variant 属性缺失 → `UNKNOWN_AMBIGUOUS`；候选整体低且 Retrieval 健康 → `UNKNOWN_POSSIBLE_NIL`；搜索/索引/route 不健康 → `UNKNOWN_SEARCH_FAILURE`，不得误判新品。

## 8. Embedding、Visual Search 与局部复核

### 8.1 Text

PoC：Qwen3-Embedding-0.6B，先测 512d，再比较 256/384d。文本同时保存结构化稳定模板与原始标题/描述表示。

Text Reranker：Qwen3-Reranker-0.6B，仅对 Top-N 使用。

### 8.2 Image

语义/跨模态基线：SigLIP2-B/16 384；细粒度 challenger：DINOv3 ViT-B/16。DINOv3 使用自定义许可证，生产前必须 Legal/Compliance Gate；无法接受时测试 DINOv2/其他可商用方案。

每图独立保存向量，多图聚合使用 `max_similarity / topk_mean / front/detail similarity / image_quality_weight`。完全相同/近重复图片不能单独证明 `SAME_VARIANT`。

Qwen3-VL-Embedding-2B / Reranker-2B 作为多模态 challenger；只有显著提高 `Coverage @ 99.9% Precision` 且成本可接受才进入困难路径。

### 8.3 Local/Patch Visual Verify

全局向量负责高召回；盘面刻度、表圈、刻字、五金、走线、印花等近邻差异在 Top-10～20 shortlist 做局部复核：

```text
Global Image ANN
→ Region Selection
→ Patch / Local Descriptor
→ Local Rerank / Correspondence
→ local_visual_score / patch_match_coverage
→ Pair Decider + Ambiguity Guard
```

LOCORE 类 list-wise local reranker 作为 challenger。局部视觉仍属于 `IMAGE_VISUAL`，不得成为 Identity Anchor，也不能覆盖 Hard Conflict。

## 9. Pair Matcher、Conflict Engine 与 Decision Policy

```text
Candidate Pair
→ Pre-Conflict Check
→ Cheap Deterministic Features
→ Structured / Text Matcher
→ Multimodal Difficult-Pair Matcher（少量）
→ Local Visual Verify（near-tie）
→ Post-Conflict Check
→ Calibration
→ Evidence-Family Risk Policy
→ Candidate-set / NIL / Ambiguity Guard
→ Decision
```

### 9.1 CERTAIN_MATCH

至少满足：

```text
NO HARD_CONFLICT
AND CandidateSetState == KNOWN_CANDIDATE
AND
(
  Strong Identity Anchor
  OR
  Calibrated Matcher >= tau_segment
  + >=2 个非重复 Evidence Family 一致支持
  + Ambiguity Guard 通过
)
```

Strong Identity Anchor：高可信 full Reference / official Style Code / Manufacturer-grade MPN exact，或高可信 GTIN exact + Hard Attributes 无冲突。

`tau_segment`、`margin_segment` 按品牌/品类/来源/EvidenceProfile 独立认证，不使用 ANN raw score 或全局固定阈值。

### 9.2 Conflict Engine

Matcher 前后都执行：

```text
HARD_CONFLICT
POSSIBLE_CONFLICT
NO_CONFLICT
```

典型：品牌不同；官方 36mm vs 41mm；Mini vs Medium；官方材质/颜色/五金冲突。Validated GTIN 不同默认 Possible，只有品牌规则证明 1:1 才 Hard。任何模型高分都不能覆盖 Hard Conflict。

### 9.3 UNKNOWN Reason Code

至少包括：

```text
UNKNOWN_AMBIGUOUS
UNKNOWN_POSSIBLE_NIL
UNKNOWN_INSUFFICIENT_EVIDENCE
UNKNOWN_SEARCH_FAILURE
UNKNOWN_DEPENDENCY_FAILURE
UNKNOWN_PUBLICATION_INCONSISTENT
UNKNOWN_CONFLICT
UNKNOWN_CATALOG_REPAIR
UNKNOWN_STALE_SOURCE_VERSION
UNKNOWN_COMMIT_CONFLICT
```

## 10. Entity Linking、Discovery 与 Canonical Health

### 10.1 Linking

```text
Source Snapshot
→ Hybrid Retrieval
→ Pair / Conflict / Calibration
→ CandidateSetAssessment
→ CERTAIN_MATCH or reason-coded UNKNOWN
→ Recognition Commit Barrier（仅 CERTAIN_MATCH）
→ Current Source→Canonical Link + Immutable Recognition
→ Pending Review
```

最终身份判断与最终业务写入分层：**推理结果只是待提交 Decision，不等于业务状态已经生效。**

### 10.2 Discovery 与 Canonical Novelty / Uniqueness Gate

只有 `UNKNOWN_POSSIBLE_NIL` 且输入证据达到最低质量要求时进入发现池：

```text
POSSIBLE_NIL
→ Official/Web Evidence
→ Strict Blocking
→ High-confidence Pair Edges
→ Constraint-aware Clustering
→ PROPOSED Canonical
→ Canonical Novelty / Uniqueness Gate
→ ACTIVE or remain PROPOSED
```

`POSSIBLE_NIL` 只表示没有安全链接到已有 Canonical，不等于已经证明是新品。

任何 `PROPOSED → ACTIVE` 必须生成 `canonical_novelty_assessment`，在当前 pinned publication 上对 ACTIVE、PROPOSED、MERGED historical aliases、official external variant ids、governed Manufacturer IDs 做高召回去重。

Novelty 状态：

```text
UNIQUE
DUPLICATE_SUSPECT
AMBIGUOUS_EXISTING
CONFLICTING_EXISTING
RETRIEVAL_UNHEALTHY
```

只有 `UNIQUE` 可自动激活。无强 ID 且与已有 Canonical 高度近似、又缺少可区分 Hard Attribute 时保持 PROPOSED。

为防两个 Discovery Worker 并发创建同一新品，对已证明 variant-unique 的 Manufacturer Identifier / official external Variant ID 建 `canonical_identity_claim` 唯一所有权；无强 ID Proposal 在激活提交前必须在同一事务/锁语境重新执行 novelty check，避免 TOCTOU 双 ACTIVE。

### 10.3 传递冲突

禁止 `Connected Component = Canonical Variant`。

使用：

```text
Union-Find / Cluster Graph
+ Cannot-Link
+ Cluster Signature
+ Anchor Validation
```

合并前检查 cannot-link、Hard Attributes、时间版本、来源互斥、anchor；有冲突立即阻断 A=B、B=C 推导 A=C。

### 10.4 ACTIVE Cluster Health / Repair Triage / Split Repair

ACTIVE Canonical 持续做周期性与事件驱动一致性检查：

```text
high_trust_hard_conflict_count
cannot_link_inside_cluster_count
manufacturer_identifier_partition_count
variant_attribute_mode_count
review_disagreement_rate
new_evidence_conflict_rate
temporal_generation_conflict
cluster_partition_score(optional)
health_state
```

治理级 Hard Conflict、不可兼容 Manufacturer ID 分区、confirmed cannot-link 穿过当前 cluster 时，立即进入 `SPLIT_PENDING` 并停止新 Auto-Match。高可信规则触发冻结不等待 ML detector。

Cluster Repair 固定拆成四层：

```text
Detect / Freeze
→ Repair Graph Snapshot + Triage
→ Active Evidence Query / Governed Diagnosis
→ Constrained Partition Proposal
→ Governance Approval
→ Atomic Repair Publication
```

GNN/graph classifier 只预测 cluster 是否可能需要分区并排序检查优先级，不得直接拆分 Canonical。Partition 必须满足 confirmed cannot-link、governed Manufacturer Identifier、Hard Attributes、时间版本以及 reviewed must-link；关键边未解决时保持 `SPLIT_PENDING`，不为恢复 Coverage 强制拆分。

确认 Split 后：创建 N 个新 Canonical；所有 Source Product 从 ORIGINAL OBSERVED Evidence 重新解析；旧 Recognition 保留并由新事件 supersede/invalidate；跨 child Alias/Identifier 降级；旧共簇产生的 pseudo positive/训练 artifact 沿 lineage taint；repair 通过原子 publication 发布；旧 Canonical 状态=`SPLIT`。

### 10.5 Duplicate Canonical / Merge Repair

系统同时防 under-merge：同一 Official Variant 被建成多个 Canonical。

高优先信号：相同 governed Manufacturer-grade Identifier、official external Variant ID、认证为 variant-unique 的 GTIN、reviewed SAME_VARIANT bridge、持续集中在相同 Canonical pair 的 near-tie。

Identity-critical collision → `MERGE_PENDING` 并冻结新挂接；只有 Image/Text 高相似只生成治理候选。治理确认后选择唯一 survivor，旧 Canonical=`MERGED`；Alias/Identifier、冲突标签重新验证；所有状态与 Search tombstone/redirect 在同一 repair publication 生效。

## 13. Review、风险认证与 Reviewer Quality

### 13.1 三轨 Review

```text
TRAINING_REVIEW
  Active Learning / Hard Negative / LIKELY / UNKNOWN / rare slices

CERTIFICATION_AUDIT
  从真实最终 Recognition Decision 流按预定义 probability sampling 抽样

GOVERNANCE_REVIEW
  PROPOSED/Novelty/Merge/Split / Web 冲突 / Identifier semantics / 主档治理
```

风险认证单位是最终 Recognition Decision，不是 candidate pair。Certification 样本记录 `inclusion_probability / stratum_key`；全局风险按真实生产流量权重汇总。Active Learning/Hard Negative 默认只能用于训练和诊断。

Repair Active Learning 属于 `GOVERNANCE_REVIEW`，目标是降低 cluster repair 的人工诊断成本；其非均匀选择样本不能直接用于全局 Precision 风险估计。

### 13.2 Calibration 与 Certification 分开

- 调参集与最终认证集分离。
- Record-level Auto-Match 仍计算单侧二项风险上界作为 i.i.d. sanity bound。
- “0 错误、95% 单侧、约 2995 个样本将上界压到约 0.1%”**只在样本可近似独立 Bernoulli 时成立**，不得直接作为正式上线证明。
- 主要 brand/category/source/EvidenceProfile/CandidateState 做 slice-level 认证。
- KNOWN/AMBIGUOUS/NIL 分开评估。
- 分布漂移后重新校准/认证。

### 13.3 Cluster-aware Production Risk Certification

线上 False Merge 往往不是独立散点，而会因同一 feed、Canonical、parser/normalizer、模型/校准器、policy、publication 或时间批次产生相关错误。正式风险证明必须同时保留“按记录估计总体错误率”和“按故障域处理相关性”两层。

每条 `CERTIFICATION_AUDIT` 样本除 `inclusion_probability / stratum_key` 外，至少保存以下 dependency keys：

```text
source_group_id / syndication_group_id
canonical_variant_id
parser_version / extractor_version / identifier_semantics_policy_version
model_version / calibrator_version / route_execution_signature
catalog_publication_id
ingestion_batch_id / decision_time_bucket
```

固定规则：

1. **原始审核条数不等于有效独立样本数。** 抽样设计应限制同一 dependency cluster 反复占满审计额度，并保证关键来源、Canonical、模型/规则版本、publication 与时间窗具有足够独立 cluster 覆盖；但这种 cluster diversification 不能被解释成“样本已经独立”。
2. 维护版本化 `audit_cluster_policy`，预先声明正式认证要评估的 cluster definitions。至少对 `source/feed`、`canonical`、`model+parser+policy`、`publication/time` 分别做相关性敏感度分析；不得事后挑选最有利的定义。
3. 正式报告同时给出：design-weighted record-level False Merge estimate、raw i.i.d. upper bound、cluster-aware upper bound、`n_raw / n_distinct_clusters / design_effect / effective_sample_size`。首版可用 survey-style design effect / adjusted effective sample size 的保守单侧区间；样本少、比例接近 0 或相关性高时，用针对 clustered binary proportion 的更准确区间作为 challenger。
4. 当不同 cluster 定义给出不同上界时，Release Gate 使用**预先声明定义中的最大/最保守上界**；critical slice 上界仍需单独通过，不能被全局流量平均稀释。
5. **0 error 也不能反推 independence。** 若没有足够错误样本估计 ICC/design effect，使用历史已认证窗口、压力/回放实验或预先规定的保守 design effect 做 sensitivity；缺少可信相关性假设或 distinct-cluster coverage 时状态为 `CERTIFICATION_INSUFFICIENT`，不是 PASS。
6. 对一个被确认的 False Merge，不只修这条记录：立即以其 dependency keys 展开 sibling scan / incident triage。若证据显示为 parser、source feed、policy、publication 或 Canonical 级系统性错误，对相应 cluster/slice 执行 kill switch 或降为 UNKNOWN，直到修复并重新认证。
7. 除 record-level False Merge per Million 外，监控错误集中度：`max_false_merge_burst_size / affected_dependency_cluster_count / single_cluster_audit_share / cluster_error_concentration`。大量错误来自一个共同根因时，不能因为“总体样本量大”弱化风险判断。

推荐审计状态：

```text
CERTIFICATION_PASS
CERTIFICATION_FAIL
CERTIFICATION_INSUFFICIENT
CERTIFICATION_REQUIRES_INCIDENT_REVIEW
```

正式 Auto-Match 放量使用：

```text
release_risk_upper_bound = max(
  iid_record_upper_bound,
  cluster_aware_upper_bounds,
  critical_slice_upper_bounds
)
```

只有 `release_risk_upper_bound <= target_false_merge_risk` 且 distinct-cluster coverage 达到预设门槛时，当前冻结版本才允许扩大 Coverage。

### 13.4 Certification Label Quality

正式 `CERTIFICATION_AUDIT` 默认双人独立盲审：首轮不展示模型 score、置信解释、Teacher/VLM 建议或另一 reviewer 标签。

标签：

```text
SAME_VARIANT
DIFFERENT_VARIANT
INSUFFICIENT_EVIDENCE
SOURCE_DATA_ERROR
```

分歧或不确定进入高级 reviewer/专家 adjudication；仍无法裁决的 `AUDIT_UNRESOLVED` 不计作正确匹配，首版按 potential false merge 纳入保守风险上界或关闭对应 slice。

Reviewer 维护 brand/category qualification，定期插入 hidden control items。Guideline、UI、Evidence Snapshot、Qualification 全部版本化。Certification set 不参与同一版本 threshold/model/policy 选择。

## 15. Incremental、CDC、Catalog Publication 与 Recognition Commit

### 15.1 Catalog → Search Publication Barrier

历史初始化：

```text
Raw Import
→ Normalize / Extract / QC
→ Barcode/OCR
→ EvidenceProfile / Route
→ Batch Text/Image Embedding
→ Build Versioned OpenSearch Generation
→ Publication Parity Validation
→ Atomic Alias Publish
→ Linking / Recognition
```

增量 Canonical mutation：

```text
DB Transaction: mutation + catalog_outbox_event
→ CDC / Outbox Relay
→ Idempotent Projection Consumer
→ External-versioned OpenSearch Upsert/Tombstone
→ Refresh Visibility + Search Checkpoint
→ Advance Catalog Publication Watermark
```

Canonical/Alias/Identifier promotion、撤销、RETIRED/MERGED/SPLIT_PENDING/SPLIT/MERGE_PENDING/TAINTED 与 outbox event 在同一 DB transaction 提交。Indexer 用 `event_id` 幂等去重，用数据库单调 `mutation_version` 做 OpenSearch external version。删除/撤销必须生成 tombstone。

Auto-Match 请求入口 pin 一个 `ACTIVE publication_id`。Search hit 进入 Pair/Conflict 前校验 pinned publication；修复/撤销状态即使被旧索引召回，也必须在 Identity Gate 丢弃。

`search_apply_checkpoint < publication.mutation_watermark`、refresh 未确认、projection parity 失败、混合 publication → `UNKNOWN_PUBLICATION_INCONSISTENT`。

消息系统的“exactly once”不等于 DB→OpenSearch 原子提交；目标是：

> **事务性发出 + 幂等投影 + 单调版本 + 可验证 publication。**

### 15.2 Recognition Commit Barrier

模型推理、OCR、检索、Rerank 不持有数据库长事务。在线链路先在事务外形成不可变 `RecognitionDecisionSnapshot`，绑定 idempotency key、Source Version、candidate Canonical/version、publication、模型/策略/route 与 decision fingerprint。

只有 `CERTAIN_MATCH` 进入短 ACID transaction：

```text
BEGIN
  Insert/lookup recognition_commit_intent(idempotency_key)
  Lock/CAS source_product current row
  Validate source_version/content_hash/recognition_epoch unchanged
  Validate target Canonical still linkable under authoritative state/publication
  Ensure no conflicting current Source→Canonical link
  Insert immutable recognition_record
  Upsert current source_canonical_link
  Update source_product recognition state/current_recognition_id
  Insert exactly one Pending Review task or recognition_outbox_event
COMMIT
```

相同 key + 相同 intent 返回第一次结果；相同 key + 不同语义参数拒绝。推理期间 Source 变化 → `UNKNOWN_STALE_SOURCE_VERSION`；目标 Canonical 冻结/修复/撤销或 publication 不一致 → 不提交。跨系统副作用统一用 Outbox + idempotent consumer。

### 15.3 Source 更新、Review 纠错与重新识别

Source 内容更新生成新的 `source_version / recognition_epoch`，旧 Recognition 保留历史，current state 转 `REPROCESS_REQUIRED`。Review Reject/Correction、Split/Merge/Reprocess 通过 superseding/invalidation event 改 current pointer，不原地修改历史 Recognition。

## 16. Production Runtime Reliability

### 16.1 Fail-closed

Route Policy 定义 mandatory/optional stage。任一 mandatory stage 被跳过、timeout、熔断都会改变 `route_execution_signature`；未经该 degraded route 独立 benchmark + risk certification，不允许 CERTAIN_MATCH，只能 UNKNOWN 或异步重试。

### 16.2 Deadline / Retry / Queue / Circuit Breaker

- 每条请求入口生成绝对 deadline 并沿 OpenSearch、Reranker、OCR、GPU/VLM 传播。
- Expensive stage 开始前检查剩余预算；mandatory stage 无法完成 → `UNKNOWN_DEPENDENCY_FAILURE`。
- 每个依赖只有一个 retry owner；只重试 transient error；指数退避+jitter+max attempts+retry budget，受原 deadline 约束。
- OpenSearch、Reranker、OCR、GPU/VLM、Web Agent 分别配置 `max_inflight / max_pending / queue_deadline / circuit threshold / half-open budget`。
- 队列有界；没有足够 deadline 的请求直接 shed/UNKNOWN。

### 16.3 Load Shedding

```text
P0 Strong Identifier 在线 Linking
P1 普通 Hybrid Linking
P2 Near-tie Local Visual / Difficult Pair
P3 Entity Discovery / Web Evidence / Novelty Scan
P4 历史 backfill / re-embedding / periodic Canonical dedupe/repair scan
```

过载优先停止 P4→P3→P2。未认证简化 route 只能降低 Coverage，不能降低 Identity Safety。

定期故障注入：timeout、OpenSearch partial failure、GPU unavailable、queue overload、retry storm、CDC lag、重复/乱序事件、refresh lag、publication rollback、Split/Merge partial publish，以及 Recognition commit 过程中 crash/response loss/concurrent retry。

## 17. 容量、成本与性能

### 17.1 10M 向量容量

假设 10M 商品、平均3张可用图、10M text + 30M image vectors、512d。

模型导出 FP16 数组约：

```text
40M × 512 × 2B = 40.96GB
```

OpenSearch on-disk 完整 float 向量按 FP32：

```text
Text   20.48GB
Images 61.44GB
完整向量磁盘基线 ≈ 81.92GB / active vector set
```

不含 Lucene segment、HNSW/量化索引、倒排、doc values、metadata、translog、merge 临时空间、副本、shadow index。

HNSW 量化内存参考：

```text
HNSWBytes ≈ 1.1 × (dimension × bits / 8 + 8 × m) × vector_count
```

512d、m=16、40M vectors：32x/1-bit 约8.45GB，16x/2-bit 约11.26GB（仅 HNSW 图量级）。

### 17.2 资源档位

PoC（1–2M）：1×L4 24GB、1×8 vCPU/64GB OpenSearch、0.5TB SSD/block storage。

10M 生产压测起点：

```text
3 × 8 vCPU / 64GB OpenSearch data/search nodes
3 × 1TB usable storage, replica=1，可容纳 active+shadow
2 × L4 24GB online GPU（HA 时）
历史 backfill 临时扩 4–8 × L4/同级 GPU
```

公有云核心 compute+block storage 量级约 PoC $1k/月、10M 起点约 $3k/月；仅作立项量级，采购时按实际区域重算，另计 DB、原图、快照、日志、网络、备份。

成本与 `Coverage @ 99.9% Precision`、`Cost per Confirmed Recognition` 联合优化。

同时定义 `audit_cluster_policy`：明确 source/feed、Canonical、model/parser/policy、publication/time 等 dependency cluster；设定关键 slice 的最小独立 cluster 覆盖、单 cluster 最大审计占比和正式风险上界计算方式。

### Phase 1：确定性腕表 Linking + Recognition Commit

Reference/GTIN lookup、Exact Retrieval、Hard Conflict、Recognition/Review；实现 Decision Snapshot、idempotency、Source Version CAS、单一 current pointer、Immutable Recognition + Pending Review 原子 transaction、outbox/idempotent consumer 与故障测试。

Phase 1 先证明**判断 Precision、Commit Integrity 与 Cluster-aware Certification**同时达标，再扩大覆盖率。

### Phase 2：Hybrid Text + Route Policy + Pair Matcher

BM25、Qwen3-Embedding-0.6B、RRF、Qwen3-Reranker-0.6B、箱包、Calibration、Candidate-set/NIL/Ambiguity Guard。

### Phase 3：Image / Barcode / OCR / Multimodal

zxing-cpp、PP-OCRv6、PaddleOCR-VL、SigLIP2、DINOv3 challenger、局部 patch rerank、Qwen3.5-4B、Qwen3-VL challenger。

### Phase 4：Open-world Discovery + Official Web Evidence + Canonical Repair

POSSIBLE_NIL、constraint-aware clustering、ProductGroup/Product parse、Identifier Semantics、External Variant Graph、Catalog Activation Gate；上线 Canonical Novelty Scan、Cluster Health、Canonical-to-Canonical duplicate scan 与 Governed Split/Merge Repair。

### Phase 5：Supervised Student + Controlled Continuous Learning

Review labels、Hard Negative、NIL/near-tie mining、active learning、domain encoder、learned fusion、selective risk control、shadow/A-B/rollback；上线前必须具备完整 ML lineage 与 taint propagation。每次 model/parser/policy 大版本改变后，cluster-aware risk certification 重新从冻结版本真实流量执行。

## 20. 正式开启自动识别 Gate

全部满足才扩大 Auto-Match：

1. 主要品类/来源 `Precision@Auto-Match >= 99.9%`。
2. `Recall@100 after fusion/truncation >= 99.5%`。
3. Exact/官方标识符候选 survival = 100%。
4. 正式 Certification Audit 同时满足概率抽样 provenance、预设 distinct dependency cluster coverage，并且 `release_risk_upper_bound <= target_false_merge_risk`；**raw sample count 或 2995 条 i.i.d. 参考值本身不能作为通过条件**。
5. 所有 Hard Conflict 回归 0 自动错合并。
6. Seen/Strict Unseen/Time-shift、Vintage、缺图、缺型号、脏型号、低质图、文本图像冲突分别达标。
7. Image-only 路径不得无额外身份/结构证据产生 CERTAIN_MATCH。
8. Synthetic/Pseudo evidence 不得成为 Hard Fact / Identity Anchor / Certification Gold。
9. AMBIGUOUS/NIL/RETRIEVAL_FAILURE/PUBLICATION_INCONSISTENT/CATALOG_REPAIR 不得绕过 Guard。
10. 新 SKU challenge set forced Known-Link / near-tie 错误挂接=0。
11. Final certification split leakage=0。
12. 每个 brand/source/category/EvidenceProfile/CandidateState 有阈值或 kill switch。
13. 模型、规则、ontology、index、fusion、route、candidate/runtime/publication policy 可回滚。
14. Recognition 可重放完整 Evidence、CandidateSetAssessment、publication、dependency health、immutable model hash、training lineage 和 commit intent。
15. Source/model/route/retrieval drift 超阈值自动 UNKNOWN 或关闭 Auto-Match。
16. Product Group ID 作为 Variant Identity Anchor 违规=0；未认证 merchant SKU 作为官方 Reference 违规=0。
17. Official Web JSON-LD/DOM 未解决冲突时自动 ACTIVE=0。
18. 正式 Precision 证明来自冻结版本真实 CERTAIN_MATCH 流的概率审计；Certification label 同版本调参复用=0。
19. Reviewer blind double-review / qualification / adjudication provenance 完整。
20. mandatory stage timeout/熔断且 degraded route 未认证时 CERTAIN_MATCH=0；Catalog/Search publication 不一致时 CERTAIN_MATCH=0。
21. 所有 ACTIVE 模型 lineage 完整率=100%；tainted upstream 能在 SLA 内触发 kill-switch/re-certification。
22. Teacher/Pseudo-label 模型必须在独立 sealed human/time-shift set 上认证。
23. `SPLIT_PENDING / SPLIT / MERGE_PENDING / TAINTED` Canonical 新增 Auto-Match=0；Split/Merge Repair partial publication 下 CERTAIN_MATCH=0。
24. ACTIVE Canonical 内治理级 Hard Conflict/confirmed cannot-link 在 SLA 内 freeze/repair。
25. `PROPOSED → ACTIVE` 必须有同 publication 的 `canonical_novelty_assessment` 且 `novelty_state=UNIQUE`。
26. variant-unique governed Manufacturer Identifier / official Variant ID 不得同时属于多个非 MERGED ACTIVE Canonical；并发 Discovery 不得产生双 ACTIVE identity claim。
27. 一个 committed Recognition intent 只能产生一次业务副作用；partial commit、stale source、多 current link、相同 idempotency key 不同 intent、post-commit duplicate review 均为 0。
28. GNN/GraphCR/SuperPart/repair classifier 只能 Detect/Prioritize/Propose，不得直接 Split/Merge Canonical；未解决关键 repair query 不得强制发布。
29. Repair Active Learning 的非均匀治理样本不得替代 CERTIFICATION_AUDIT。
30. `audit_cluster_policy` 必须版本化且在审计前冻结；正式报告至少覆盖 source/feed、Canonical、model/parser/policy、publication/time 四类 cluster sensitivity，不允许事后选最有利 cluster 定义。
31. `CERTIFICATION_INSUFFICIENT` 不得被当作 PASS；0-error 但有效样本量/独立 cluster 数不足时必须继续审计或降低 Coverage。
32. 任一认证 False Merge 若显示为系统性 dependency-cluster 问题，相关 source/model/parser/policy/publication/Canonical slice 必须立即 kill-switch 或降为 UNKNOWN，修复并重新认证后才能恢复。

任何指标退化时，优先降低 Coverage，不放宽 Identity Safety，也不允许用 raw audit 数量掩盖错误相关性、部分提交、重复副作用或未经治理的 Cluster Repair。

## 22. 最终生产原则

```text
官方知识 / 标准化 / 确定性标识
          ↓
EvidenceProfile / Route Policy
          ↓
Hybrid Retrieval + Exact Preserve
          ↓
结构化 + 文本 + 图片多证据
          ↓
Hard Conflict + Calibration
          ↓
Candidate-set / NIL / Ambiguity Guard
          ↓
Constraint-aware Graph Resolution
          ↓
CERTAIN_MATCH Decision
          ↓
Recognition Commit Barrier
          ↓
Current Link + Immutable Recognition + Pending Review
          ↓
Canonical Novelty / Health / Repair Triage
          ↓
Governed Split/Merge + Atomic Publication
          ↓
Independent + Cluster-aware Risk Audit
          ↓
Controlled Training + Immutable ML Lineage
```

固定原则：

1. **Identity first，Similarity second。**
2. **Hard Conflict 优先于任何模型高分。**
3. **UNKNOWN 是合法且必要的生产输出。**
4. **缺模态不能靠生成模态伪装成完整证据。**
5. **Synthetic/Pseudo evidence 不能形成 Hard Fact / Identity Anchor / Certification Gold。**
6. **仅视觉相似不能自动 SAME_VARIANT；全局视觉负责召回，局部视觉只验证 near-tie。**
7. **必须显式允许 NIL；Top-1/Top-2 near-tie 必须 Abstain。**
8. **Exact 候选永不被 Soft Fusion 截断。**
9. **训练 Review 与风险 Certification 分流。**
10. **Product Group ID 是关系标识，不是 Variant Identity；Merchant SKU 与 Manufacturer ID 分命名空间。**
11. **官网结构化数据是高价值 Evidence，不是无条件 Canonical Truth。**
12. **DB→Search 使用 Transactional Outbox + Idempotent Projection + Monotonic Version + Publication Barrier。**
13. **ACTIVE Canonical 不是永久真值：持续检查 over-merge 与 under-merge。**
14. **Entity Discovery 是新品证明问题；`POSSIBLE_NIL` 不能直接推出新 Canonical。**
15. **任何 `PROPOSED → ACTIVE` 必须通过 Novelty/Uniqueness Gate。**
16. **Cluster Detector、Repair Classifier、Active Learning 与 Graph Partitioning 只能检测、排序、提问和生成候选；不能直接修改 Canonical。**
17. **Cluster Repair 必须满足 confirmed must-link/cannot-link、Hard Constraint 与 Governance Approval 后才能发布。**
18. **每一个 ACTIVE 模型和训练数据集都是不可变、可哈希、可追溯 Artifact。**
19. **timeout/过载/依赖故障形成的新 route 未认证时 fail closed 为 UNKNOWN。**
20. **模型的 CERTAIN_MATCH 只是待提交 Decision；只有通过 Recognition Commit Barrier 后业务关系才生效。**
21. **Recognition Commit 必须满足显式 idempotency intent、Source Version CAS、Canonical 可挂接性再验证、单一 current link、Immutable Recognition、Pending Review/Outbox 原子提交。**
22. **Source 更新、Review Reject、Split/Merge、Reprocess 通过 superseding/invalidation event 改 current pointer，不修改历史 Recognition。**
23. **正式 99.9% Precision 认证不能把所有审核记录默认视为独立 Bernoulli；必须按真实故障域做 cluster-aware 风险上界与 distinct-cluster coverage。**
24. **raw audit count 不是 effective sample size；0-error 也不能证明 independence。相关性信息不足时宁可 `CERTIFICATION_INSUFFICIENT`，不能虚高放量。**
25. **任何认证 False Merge 都必须按 dependency cluster 做 sibling scan/incident triage；系统性错误先 kill-switch/UNKNOWN，再修复和重认证。**
26. **任何复杂度只有在提高 Coverage@99.9% Precision、提高事务/运行可靠性、降低 Catalog fragmentation、降低治理成本或降低总成本时才有价值。**
