# 奢侈品识别方案

## 1. 目标与边界

系统目标不是“找最像的商品”，而是把雷小安、奢当家、腕表之家、小迈步、爱回收等来源的异构记录归一到**同一个官方商品变体（Official Variant）**，并产生可审核、可回放、可治理的 Recognition。

第一阶段只覆盖：

```text
IN_SCOPE_WATCH
IN_SCOPE_BAG
```

历史数据约 100 万–1000 万条。腕表已有部分品牌/系列/型号主档；箱包主档不完整，因此系统同时支持 Entity Linking 与 Entity Discovery。

核心原则：

> **Precision >> Recall。宁可 UNKNOWN / OUT_OF_SCOPE，也不能把不同官方 Variant 错合并。**

系统不做真假鉴定。成色、价格、库存、卖家、单件序列号、保卡状态属于 Offer / Physical Item；维修换件、个性化、联名营销、附属物、商家 Bundle、Multipack、Lot、重复上架，以及业务范围外商品都不能被误当成新的官方 Variant。

每个 `CERTAIN_MATCH` 必须原子形成：

```text
Source Product 当前状态
+ Source → Canonical 当前识别关系
+ Immutable Recognition Record
+ Pending Business Review
```

四个副作用必须原子、幂等、可重放。

## 2. Canonical Identity、品牌角色与 Identifier Identity Scope

### 2.1 Canonical Identity

```text
Brand / Brand Role
  └── Product Family / Series
       └── Product Model
            └── Canonical Variant
```

关系至少包括：

```text
SAME_VARIANT
VARIANT_OF
SAME_MODEL
SAME_SERIES
VISUALLY_SIMILAR
UNKNOWN
```

只有 `SAME_VARIANT` 可进入普通 Canonical 聚类并生成默认自动 Recognition。

Canonical 状态：

```text
ACTIVE
PROPOSED
SPLIT_PENDING
MERGE_PENDING
RETIRED
MERGED
SPLIT
TAINTED
```

`MERGED` redirect 到唯一 survivor；`SPLIT` 是 one-to-many，旧 Canonical 必须重新解析而不是简单 redirect。

### 2.2 Brand Role / Collaboration Semantics

标题中出现多个品牌不能压成一个 `brand_id`。维护：

```text
PRIMARY_PRODUCT_BRAND
CO_PRIMARY_BRAND
SUB_BRAND
COLLABORATION_PARTNER
ARTIST_OR_DESIGNER
LICENSED_IP
BRAND_OWNER_OR_MANUFACTURER
UNKNOWN_ROLE
```

并维护：

```text
collaboration_program_id
collaboration_scope =
  PRODUCT_VARIANT_DEFINING
  COLLECTION_PROGRAM
  CAMPAIGN_OR_EDITORIAL
  ENDORSEMENT_OR_STYLING
  UNKNOWN
```

固定规则：

1. Hard Brand Constraint 比较治理后的 Primary/Co-primary 身份，而不是标题里所有品牌词。
2. 来源漏写 collaborator 是 missing，不形成 Hard Conflict。
3. Collaboration Partner、Artist、Licensed IP 不自动升级为 Primary Brand。
4. Campaign/Editorial/Endorsement 不定义 Variant。
5. 官方 Product-level collaboration 只有在确实形成独立 Variant boundary 时才进入 Identity。
6. `A by B` 与 `B by A` 允许具有方向，不能压成无序 brand set。
7. GTIN/MPN/Reference namespace 不因 collaborator 名称改变。
8. 图片/logo/VLM 只能产生 Brand-role / Collaboration Candidate Evidence，不能直接写 Truth。

### 2.3 Identifier Namespace 与 Identity Scope

统一采集：

```text
reference_raw / reference_normalized
style_code / mpn / gtin / ean / upc
merchant_sku / product_group_id / item_group_id
serial_number / date_code / certificate_id / instance_identifier
made_to_order_gtin / made_to_order_variation
official_catalog_configuration_key
market
identifier_namespace / identifier_owner / identifier_type
identifier_source / source_field_path
component_id / identifier_binding_scope
brand_rule_pack_version
```

每个 Identifier 必须显式赋予身份粒度：

```text
VARIANT_UNIQUE_VERIFIED
VARIANT_CANDIDATE
MODEL_OR_CASE
FAMILY_OR_GROUP
INSTANCE_ONLY
MERCHANT_ONLY
UNKNOWN_SCOPE
```

**字段名、编号长度、前后缀或“看起来像官方编号”都不能决定身份粒度。**

固定规则：

1. `VARIANT_UNIQUE_VERIFIED` exact + required Hard Attributes 无冲突，可进入 Strong Variant Anchor。
2. `MODEL_OR_CASE` exact 只进入高优先召回/Blocking，仍必须比较 Variant-defining Hard Attributes。
3. `VARIANT_CANDIDATE` 在 Brand Rule Pack collision audit 完成前不能单独 Auto-Match。
4. Merchant SKU 默认 `MERCHANT_ONLY`；Product Group ID 默认 `FAMILY_OR_GROUP`。
5. Serial/Certificate/Date Code 默认 `INSTANCE_ONLY`。
6. GTIN 默认 Strong Positive + Exact Retrieval Key；是否 Variant-unique 仍按品牌/市场/Trade Item 语义治理。
7. Vintage/地区站点/历史编号规则独立版本化，不把当前规则倒推历史。

### 2.4 Brand Rule Pack 与 Identifier Collision Audit

`Brand Rule Pack` 是生产必须 Artifact：

```text
brand_id
category
rule_pack_version
valid_from / valid_to
market_scope
official_catalog_surfaces
identifier_rules[]
variant_defining_attributes[]
normalization_rules[]
known_aliases[]
reference_collision_audit_id
```

每条 identifier rule 至少保存：

```text
identifier_type
source_surface / field_path
normalization
identity_scope
required_companion_attributes
exact_retrieval_allowed
strong_anchor_allowed
hard_conflict_allowed
collision_audit_status
source_evidence_ids
```

Collision Audit：

```text
Official Catalog Snapshot
→ Normalize Identifier
→ Group by brand + market + identifier
→ Build Variant Hard Signature
→ Detect same-identifier / different-signature collisions
→ Assign Identifier Scope
```

Variant Hard Signature 至少包含本项目定义的所有 Variant-defining 属性。

规则：

- 同 Identifier 映射到多个不同 Hard Signature → **绝不能**标记 `VARIANT_UNIQUE_VERIFIED`。
- 官方字段明确声明只标识 model/case/group → 直接按其语义治理。
- 只有官方语义明确，或覆盖充分的官方 Catalog collision audit + 历史回归均通过，才允许提升为 `VARIANT_UNIQUE_VERIFIED`。
- Rule Pack 变化必须 shadow replay；受影响 Recognition、Alias、Exact Index、Hard Negative 与训练数据沿 lineage 重算。

已验证的初始品牌规则：

**Rolex**：公开 `Reference 126334 / 126234` 等不能默认 Variant-unique；同一公开 Reference 存在不同官方表盘/表链配置，因此按 `MODEL_OR_CASE` 进入 bucket retrieval。`m126334-xxxx` 类官方配置键保留为高价值 Catalog Key，但在品牌未明确声明长期身份语义前不自动提升为公开 Variant Identifier。

**CHANEL**：`AS5311 / A37586` 等 style stem 在不同完整 Ref、材质、颜色中复用，因此 stem 按 `MODEL_OR_CASE`；完整官方 Ref 初始为 `VARIANT_CANDIDATE`，经 collision audit 后才可提升。

**Cartier**：`WSSA0018 / WSSA0037 / WSSA0096` 等官方 REF 是高价值候选，但仍先做品牌内 collision audit，不跨品牌照搬 Rolex/CHANEL 规则。

PoC Brand Pack 优先级：

```text
P0 Rolex + CHANEL
P1 Cartier + Omega
P2 Louis Vuitton + Hermès
其余品牌按数据量 × 错合并风险扩展
```

## 3. Source Offer、Composition、Physical Item 与 Customization

### 3.1 Source Offer / Component / Physical Item

```text
Source Offer / Listing
   └── Source Component(s)
        └── 0..1 Primary Identity Target
              └── 0..1 Physical Item Instance
                    └── Canonical Variant
```

Physical Item 只用于实例追踪、Evidence 去重、Item-State/Customization timeline、训练/审计聚类，不得直接产生 Variant Identity。

### 3.2 Source Composition

```text
SINGLE_PRODUCT
SINGLE_PRIMARY_WITH_AUXILIARY
MERCHANT_DEFINED_BUNDLE
MANUFACTURER_DEFINED_SET
MERCHANT_MULTIPACK
MULTI_PRODUCT_LOT
ACCESSORY_ONLY
CONFLICTING_COMPOSITION
UNKNOWN_COMPOSITION
```

组件角色：

```text
PRIMARY_IDENTITY_TARGET
INCLUDED_AUXILIARY
MERCHANT_ADD_ON
MANUFACTURER_SET_COMPONENT
PACKAGING_OR_DOCUMENT
ACCESSORY_PRODUCT
OTHER_PRODUCT
UNKNOWN_COMPONENT
```

Merchant Bundle 可识别主组件，但整个 Listing 默认不产生 `SAME_VARIANT`；Manufacturer Set 只有官方 Set identity 与 Hard Facts 齐全时才成为独立 Canonical；Multipack 数量属于 Offer；Lot/Accessory-only/Unknown 不进入普通 SAME_VARIANT Linking/Discovery。

### 3.3 Physical Item / Relisting Independence

不同 Offer ID/URL 不自动等于不同实物。同一 `physical_item_id` 的多个 Offer 在 Activation、Weak Validation、Attribute Arbitration、Risk Audit 中最多算一个 Physical-Instance Evidence Group。

实例链接状态：

```text
CONFIRMED_SAME_INSTANCE
LIKELY_SAME_INSTANCE
UNKNOWN_INSTANCE_RELATION
CONFIRMED_DIFFERENT_INSTANCE
```

实例误合并必须 fail-safe：最多减少独立证据、降低 Coverage，不能制造 Variant 决策。

### 3.4 Official Customization / MTO

```text
customization_state =
  NONE_STANDARD
  CATALOG_VARIANT_OPTION
  MANUFACTURER_MTO_PROGRAM
  POST_PURCHASE_PERSONALIZATION
  AFTERMARKET_PERSONALIZATION
  UNKNOWN_CUSTOMIZATION
```

Catalog 有限选项且官方定义 Variant 边界时按普通 Variant；MTO Program 与客户最终组合分层；initials、姓名、日期、自由刻字、patch/stripe 默认 Instance-specific；最终配置只有获得独立 manufacturer-grade Variant/Trade Item Identity 时才另建 Canonical。高基数 personalization 不允许造成 Canonical Explosion。

## 4. Product Scope / Open-set Gate

第一阶段只做腕表与箱包：

```text
IN_SCOPE_WATCH
IN_SCOPE_BAG
IN_SCOPE_UNKNOWN_SUBTYPE
OUT_OF_SCOPE_KNOWN
OPEN_UNKNOWN
CONFLICTING_SCOPE
```

Closed-set Top-1 不能直接当 Scope Truth。父类可靠但 leaf 未知 → `IN_SCOPE_UNKNOWN_SUBTYPE + ANCESTOR_ROUTE`。`OUT_OF_SCOPE_KNOWN / OPEN_UNKNOWN / CONFLICTING_SCOPE` 不进入腕表/箱包 NIL/Discovery。

Scope Gate 与 Category Router 分开：前者决定“是否属于系统”，后者只优化 in-scope 检索空间。

## 5. Hard Constraint、Attribute Validation 与 Fact Arbitration

每个属性断言保存：

```text
raw / normalized / canonical_value_id
extractor / extractor_version
source / evidence span / image bbox
extraction_confidence
validation_status / validation_confidence
fact_scope
market / region / valid time
component_id / component_binding_confidence
physical_item_id(optional)
customization_assessment_id(optional)
brand_role_resolution_id(optional)
brand_rule_pack_version
```

**Extraction Confidence ≠ Validation Confidence；Validated Observation ≠ Official Variant Spec。**

### 5.1 腕表默认 Hard Schema

| 字段 | 默认策略 |
|---|---|
| primary/co-primary brand | Hard |
| official identifier | 由 Brand Rule Pack 决定 scope |
| series/family | Blocking + Strong；品牌规则可 Hard |
| model/subseries | Strong |
| case diameter | Hard |
| case material | Hard |
| dial color/type | 定义 Variant 时 Hard；仅 Official Spec |
| bezel | 定义 Variant 时 Hard |
| bracelet/strap | 条件 Hard；Item-State 不直接当 Factory Spec |
| caliber/movement | 代际区分时 Hard，否则 Strong |
| functions | Variant 区分时 Hard |
| edition/generation | Hard |
| serial / piece number | Physical Item |

### 5.2 箱包默认 Hard Schema

| 字段 | 默认策略 |
|---|---|
| primary/co-primary brand | Hard |
| official style/reference | 由 Brand Rule Pack 决定 scope |
| family/series/model/style | Blocking + Strong |
| official size | Hard |
| material / official color / hardware | Hard；仅 Official Spec |
| pattern/print | 官方 Variant Spec 时 Hard |
| edition/collaboration | Product-level 时 Hard/Strong |
| season/year/generation | 官方区分时 Hard |
| serial/date code | Physical Item/生产证据 |

图片颜色只做 Soft Evidence，不能把光线/白平衡/后期造成的颜色差异升级为 Hard Conflict。

### 5.3 Attribute Validation Gate

```text
VALIDATED_VALID
VALIDATED_INVALID
UNVERIFIED
NOT_APPLICABLE
SOURCE_CONFLICT
```

L0 deterministic → L1 applicability/cross-field → L2 text/profile → L3 cross-source/official → L4 multimodal → L5 LLM/VLM fallback。所有层允许 abstain。Hard Attribute 只有 `VALIDATED_VALID` 且 validator/source/Brand Pack policy 已认证才可进入身份链路。

### 5.4 Official Variant Spec vs Observed Item State

```text
fact_scope = OFFICIAL_VARIANT_SPEC / OBSERVED_ITEM_STATE
component_origin = FACTORY_CONFIG / AUTHORIZED_SERVICE_REPLACEMENT / AFTERMARKET_OR_MODIFIED / UNKNOWN_ORIGIN
replaceability_class = IDENTITY_STABLE / SERVICE_REPLACEABLE / USER_REPLACEABLE / COSMETIC_OR_CONSUMABLE / UNKNOWN
```

Canonical 只描述 Official Variant Spec；维修、换件、当前二手状态默认进入 Item-State。Strong Identifier 已锁定 Variant 时，可解释换件不得覆盖 Anchor。

### 5.5 Canonical Fact Arbitration

不使用 latest-write-wins 或简单多数票。按 market/time/generation/source independence/Brand Pack 仲裁：

```text
RESOLVED
MULTI_VALID
CONFLICTED
UNKNOWN
STALE
```

Search/Matching/Conflict 只消费已发布的 `RESOLVED/MULTI_VALID` Current Fact。Brand-role、Collaboration、Identifier Scope 与 Attribute Resolution 同样版本化。

## 7. Evidence、独立性、EvidenceProfile 与 Route Policy

### 7.1 Evidence Independence

维护：

```text
source_group_id
syndication_group_id
content_fingerprint
image_hash_group_id
physical_item_group_id
upstream_hint
```

同 feed、转载、相同库存图、同一 physical item relist、同一官方页面复制都不能机械增加独立 Variant 证据数。

Evidence Family：

```text
IDENTIFIER
BRAND_ROLE / COLLABORATION
STRUCTURED_ATTR
VARIANT_GRAPH
LEXICAL_TEXT / SEMANTIC_TEXT
IMAGE_VISUAL / OCR_TEXT
EXTERNAL_WEB / TEMPORAL / PRODUCT_SCOPE
ITEM_INSTANCE / CUSTOMIZATION
```

同一原始观测派生的多个分数不是多票。`ITEM_INSTANCE` 与非 Variant-defining `CUSTOMIZATION` 不作为 Variant 正向 Evidence Family。

### 7.2 Fact Promotion Barrier

```text
OBSERVED
DERIVED
REVIEWED_GOLD
GOVERNED_FACT
APPROVED_ALIAS
TAINTED
```

Recognition、Matcher、Cluster、Instance Link、VLM、Pseudo-label 均是 DERIVED；未经治理不得进入 Exact Variant Identity、Canonical Hard Fact、Brand Role Truth、Identifier Scope Truth 或 Gold Training Set。

### 7.3 EvidenceProfile

每条 Source Offer 保存：

```text
identifier_quality / identifier_identity_scope
brand_rule_pack_version
text_quality / image_quality
composition_state / main_component_id
physical_item_link_state
product_scope_state
brand_role_state / collaboration_state
customization_state
hard_attr_coverage / conflict_state
brand_route_state / category_route_state / routing_scope
image_set_state / item_state_assessment
```

执行顺序：

```text
Composition → Component → Instance → Scope → Brand Role
→ Brand Rule Pack → Customization → Router → Retrieval
```

Router 只优化 in-scope 候选空间。Exact Identifier 可绕过非权威 Router，但**不能绕过 Identifier Identity Scope、Brand Pack、Scope、Component、Composition、Customization 和 Conflict**。

## 8. Candidate Retrieval、Fusion 与 Open-world Guard

召回通道：

```text
Verified Variant-Unique Identifier Exact
Model/Case/Style Identifier Bucket
Primary/Co-brand + Model
Collaboration Program
Brand + Series + Hard Attr
BM25
Text ANN
Image ANN / perceptual hash
Historical Alias
Discovery Neighbor
```

PoC 初始 K：

```text
Verified exact <= 20
BM25 = 30
Text ANN = 50
Image ANN = 30 / eligible image, union <= 60
Attribute / Brand-rule = 30
All-channel union <= 150
Cheap Rerank ≈ 30
Expensive Matcher = 10–20
```

Gate：

```text
Recall@100 >= 99.5%
Verified Exact survival = 100%
Scope / BrandPack / Router pre-post recall 单独监控
```

### 8.1 Fusion

Raw score 不直接相加。零/少标签阶段用 RRF baseline；各通道保留 minimum quota；Verified Exact 永不被 Soft Fusion 截断。有足够 Judgment 后再比较 normalized / learned fusion。

### 8.2 Identity Text Projection

Text/BM25/Multimodal query 只消费身份相关文本：

```text
Primary Identity Component
+ brand/model/series
+ identifier
+ variant-defining attributes
+ governed collaboration program
```

默认剔除：价格、成色、卖家话术、物流、售后、个人刻字、Campaign/Editorial、与主组件无关的配件文本。训练多模态模型时也使用同一套 identity-text projection，避免非视觉或非身份 token 污染图文对齐。

### 8.3 NIL / Recovery

CandidateSet：

```text
KNOWN_CANDIDATE
AMBIGUOUS_KNOWN
POSSIBLE_NIL
RETRIEVAL_FAILURE
ROUTING_AMBIGUOUS
```

进入 NIL/Discovery 前完成 Scope + Brand Rule Pack + Router bypass + Composition + Brand-role + Item-State + Customization/MTO Recheck。

一个 `MODEL_OR_CASE` Identifier 精确命中但 Variant Hard Attr 不足时，输出 UNKNOWN/补证据，**不得**把“同 Reference 下多个配置”误解释成唯一候选。

## 9. Vector Index Policy：千万级 ANN 的成本、召回与量化

OpenSearch 3.8.x 作为当前 PoC/生产候选基线。向量索引不能再用“raw vector bytes ≈ RAM”估算；必须把**量化码、HNSW/FAISS 图、full-precision rescore 向量、Lucene metadata、JVM/native cache、副本、shadow index、merge/reindex 峰值**分别计量。

### 9.1 向量规模下界

按 10M 商品、平均 3 图、512d：

```text
10M text vectors + 30M image vectors = 40M vectors
FP32 raw payload ≈ 81.92 GB
FP16 export payload ≈ 40.96 GB
```

这只是 raw payload 下界，**不是集群 RAM 需求**。

其中图片向量约占 raw FP32 payload 61.44GB，是成本优化第一优先级。

### 9.2 推荐分层

**Text ANN：Latency-first**

- 先保留 `in_memory + 1x` 作为 recall/latency reference。
- PoC 同时测试 4x/8x compression challenger；只有 `Recall@100` 与 hardest-variant strata 都达标才允许替换 reference。
- 若内存压力仍高，再测试 `on_disk`，不能直接用低成本配置上线。

**Image ANN：Cost-first + Rescore**

- 30M 图片向量优先测试 `on_disk + 16x / 32x compression`。
- Quantized ANN 只负责 first-stage shortlist；随后使用 full-precision vector two-phase rescore。
- OpenSearch 默认 on-disk 32x compression；当前默认 rescore oversample 为 2.0；16x 默认 oversample 为 3.0。它们仅作为 PoC 起点，不作为最终参数。
- 若量化使关键视图/近似 Variant 召回跌破 Gate，则降低 compression 或提高 oversample/`ef_search`，绝不通过放宽 Matching Precision 补偿 Retrieval 丢失。

### 9.3 Vector Retrieval I/O

默认 ANN Search 不把 embedding 放回 `_source` 响应。

```text
只需要 id/score → _source=false 或最小字段
需要 metadata → _source.excludes vector fields
确实需要向量给下游 client-side rerank → docvalue_fields
```

OpenSearch 3.7 起支持直接从 `docvalue_fields` 取 `knn_vector`，适合大 K、需要返回向量的 rerank/后处理路径；不需要向量时不应为了“可能有用”把向量传回客户端。

### 9.4 ANN Benchmark Matrix

每次模型/维度/Index Engine/压缩变更必须跑：

```text
mode = in_memory / on_disk
compression = 1x / 4x / 8x / 16x / 32x (按兼容性选择)
ef_search
oversample_factor
vector_dimension
engine
k
filter selectivity
route / category / brand
```

指标：

```text
Recall@K / Candidate Recall@100
Recall delta vs 1x reference
Verified Exact survival
P50 / P95 / P99 latency
QPS at target concurrency
index.store.size
native/JVM memory
page-cache / disk read
index build time / reindex time
merge peak
replica + shadow index amplification
Cost per 1K retrievals
```

必须单独报告 Rolex same-Reference、CHANEL same-style-stem、同款不同颜色/尺寸/盘面、低质图、局部图、Vintage/New SKU 等 hardest strata。任何 compression profile 未通过同一上线 Gate，都只能留在 shadow。

### 9.5 Production Capacity Rule

生产硬件不再写成固定“3 台 64GB = 足够”。容量计算顺序：

```text
真实 vector/index benchmark
→ target QPS + P99 SLO
→ replica / AZ requirement
→ reindex/shadow headroom
→ failover N-1
→ 30-day growth
→ node count / RAM / SSD / GPU
```

PoC（1–2M）可从 `1×L4 24GB + 1×8 vCPU/64GB OpenSearch + 0.5TB SSD` 起跑，但它只是测量起点，不是 Production sizing 结论。

## 10. Image Embedding、Multi-view Visual Profile 与 Image Set Safety

### 10.1 Encoder 角色

```text
Bulk image retrieval baseline: SigLIP2
Dense/local challenger: DINOv3（Legal Gate）
Difficult multimodal challenger: Qwen3-VL Embedding/Reranker
```

SigLIP2 适合 bulk retrieval baseline，因为具备 image-text alignment、multilingual 与 dense/localization 能力。DINOv3 的高质量 dense features 适合近邻 Variant 的局部差异 challenger，但使用前必须通过其自定义商业 License 的 Legal Gate。Qwen3-VL Embedding/Reranker 只验证 top-N 困难路径收益，不承担 30M 图片全量在线主召回，除非领域 benchmark 同时证明 Recall、Latency、Cost 优于 baseline。

### 10.2 Image Role Gate

图片先分类：

```text
PRODUCT_PRIMARY
PRODUCT_DETAIL
MODEL_LIFESTYLE
PACKAGING_OR_DOCUMENT
COLLAGE
ACCESSORY_OR_AFTERMARKET
DECORATIVE
OTHER_PRODUCT_SUSPECT
UNKNOWN
```

只有 identity-eligible product image/region 进入 Image ANN。文档图只做 OCR；配件/售后件/个性化区域低权或隔离；`OTHER_PRODUCT_SUSPECT / UNKNOWN` 不直接参与正向身份证据。

### 10.3 Product-level Multi-view Retrieval

**Raw image set 不做 max similarity 决策。**

每个 eligible image 保留独立 embedding，同时构造商品级 `Visual Evidence Profile`：

```text
per_view_top1_score
per_view_topk_candidates
matched_view_roles
agreement_candidate_count
cross_view_score_distribution
shared_stock_image_penalty
relist_independence_group
local_detail_consistency
image_text_alignment_score
```

流程：

```text
Eligible Query Images
→ per-image ANN
→ union by Canonical Variant
→ view-aware candidate aggregation
→ candidate-level visual feature vector
→ Pair Matcher
```

多视图的价值是补足“正面/背面/局部”视角缺失，而不是增加票数。多个图片只有在来源独立、角色有效且确实提供不同视角时才增加视觉信息量。

单图商品仍可参与 Image Retrieval，但在缺 Strong Identifier、缺 Hard Attributes 的场景下，单图视觉相似不能单独升级为 `CERTAIN_MATCH`；系统应降低视觉 confidence 或 UNKNOWN，而不是制造补票。

### 10.4 Local Visual Safety

局部 patch / dense descriptor 只用于：

```text
near-tie discriminator
hard-negative evidence
variant-detail confirmation
```

**不得成为独立 Positive Evidence Family 或 Variant Anchor。**

原因是 logo、搭扣、纹理、表圈、monogram、同系列壳型等局部视觉模式会跨 Variant 重复。局部高相似必须同时满足：

```text
Global visual / multimodal candidate already plausible
AND no Hard Conflict
AND component/image role valid
AND identity-text / structured evidence not contradictory
```

如果 local match 强但 global/structured evidence 冲突，默认产生 `LOCAL_VISUAL_TRAP / UNKNOWN_CONFLICT`，而不是提高 match score。

### 10.5 Shared Image / Stock Image Safety

- 同一库存图跨多个 Variant 复用时，不作为 Variant Positive。
- 同一 physical item relist 的多张/多站图片不增加独立 Variant Evidence。
- perceptual hash / image reuse cluster 用于去重和风险特征，而不是直接 SAME_VARIANT。
- collaboration logo/artist motif 只能辅助 Collaboration Program 识别，不能单独证明 Primary Brand 或 Variant。

```text

→ Pre-Conflict
→ Deterministic Features
→ Structured/Text Matcher
→ Multi-view Visual Features
→ Multimodal Difficult Pair
→ Local Visual（near-tie only）
→ Post-Conflict
→ Calibration
→ Evidence-Family Risk Policy
```

```text

~10K reviewed pairs: Logistic / LightGBM + calibration
更多标签: compact Cross Encoder / domain contrastive
100K+: evaluate multimodal student / learned fusion
```

```text

AND Scope in-scope
AND CandidateSetState == KNOWN_CANDIDATE

```

```text

UNKNOWN
CERTAIN_NON_MATCH
```

## 23. 最终生产原则

```text
Raw Source Offer
→ Composition / Component / Physical Item
→ Product Scope / Brand Role
→ Brand Rule Pack / Identifier Scope
→ Extraction + Validation
→ Official Spec vs Item State / Customization
→ Evidence Independence + Canonical Arbitration
→ Router / Image Role Safety
→ Identifier-aware Hybrid Retrieval
→ Quantized ANN + Full-precision Rescore（where certified）
→ Multi-view Product Visual Evidence
→ Pair Matcher + Hard Conflict + Calibration
→ Candidate/NIL/Ambiguity/Identifier-Scope Guard
→ Constraint-aware Entity Resolution
→ SAME_VARIANT CERTAIN_MATCH
→ Recognition Commit Barrier
→ Business Review / Exposure Safety
→ Canonical Novelty / Health / Repair
→ Independent Certification
→ Controlled Training + Immutable Lineage
```

固定原则：

1. **Identity first，Similarity second。**
2. **Identifier 的身份粒度由 Brand Rule Pack 决定，不由字段名或字符串格式决定。**
3. **只有 `VARIANT_UNIQUE_VERIFIED` Identifier 才能单独成为 Variant Strong Anchor。**
4. **同一 Identifier 映射多个不同 Hard Signature 时必须降级 scope，不能自动合并。**
5. **Rolex 类 public model/case Reference 只做 bucket retrieval；CHANEL 类 style stem 与 full Ref 分层治理。**
6. **不使用未经官方证据支持的编号位数/前缀/后缀语义。**
7. **Primary Brand、Co-brand、Collaborator、Artist、Manufacturer 分角色。**
8. **Source Offer ≠ 一个商品；Offer ID ≠ Physical Item ID；Physical Item ID ≠ Variant ID。**
9. **Catalog Variant Option、MTO Program、客户最终配置、Post-purchase Personalization 分层。**
10. **第一阶段 Scope 只有腕表/箱包；Closed-set Top-1 不是 Scope Truth。**
11. **Bundle/Multipack/Lot 不伪装 SAME_VARIANT；配件 Evidence 与主商品隔离。**
12. **Extraction confidence ≠ fact correctness；Validated Observation ≠ Official Variant Spec。**
13. **Hard Conflict 只建立在 Validation、Brand Pack、Fact Scope、Component、Brand Role、Customization Scope 合格的证据上。**
14. **Synthetic/Pseudo evidence 不能形成 Hard Fact / Identifier Scope Truth / Certification Gold。**
15. **多图、多 URL、同一实物多 Listing 都不是多份独立身份票。**
16. **多视图用于补足视角信息，不是机械投票；Raw image set 不做 max similarity 决策。**
17. **局部 patch/dense visual 只做 near-tie discriminator/hard-negative evidence，不能成为独立 Variant Anchor。**
18. **图文对齐与 identity-text projection 用于抑制 logo/纹理/搭扣等低层视觉捷径。**
19. **Vector compression 只能降低基础设施成本，不能以牺牲 Candidate Recall Gate 为代价。**
20. **图片向量优先 on-disk + quantization + full-precision rescore PoC；Text ANN 保留 1x reference，所有压缩配置经同一 Gold Set 认证。**
21. **Raw vector bytes 只是容量下界，不等于 RAM；Production sizing 必须基于真实索引、QPS、P99、N-1、replica/shadow benchmark。**
22. **必须显式允许 NIL、near-tie 与 identifier-scope ambiguity 并 Abstain。**
23. **Exact Identifier 绕过非权威 Router，但不能绕过 Brand Rule Pack 与 Identifier Scope。**
24. **每个 CERTAIN_MATCH 都保留 Pending Business Review；Review backlog 超安全暴露阈值时 throttle/kill-switch。**
25. **Canonical Current Fact、Brand Role、Identifier Scope、Vector Index Profile 都是版本化、可回放、可发布的治理结果。**
26. **DB→Search 使用 Transactional Outbox + Idempotent Projection + Monotonic Version + Publication Barrier。**
27. **ACTIVE Canonical 持续检查 over-merge、under-merge、Fact Conflict、Identifier Scope Collision 与 visual inconsistency。**
28. **Entity Discovery 是新品证明问题，不是“Reference 没见过”或“图片没搜到”的同义词。**
29. **所有模型、Brand Pack、Scope/Router/Composition/Image/Vector/Instance/Customization/Attribute/Review Policy 和数据集都不可变、可追溯。**
30. **依赖故障或 mandatory gate 缺失时 fail closed 为 UNKNOWN。**
31. **模型 CERTAIN_MATCH 只是待提交 Decision；Recognition Commit 后业务关系才生效。**
32. **任何复杂度只有在提高 Coverage@99.9% Precision、降低 False Merge/False Novel/Identifier Scope Error/Visual Shortcut Error、提高事务可靠性或降低总成本时才有价值。**
